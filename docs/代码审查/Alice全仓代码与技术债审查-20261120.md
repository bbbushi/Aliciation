## 2. 源码确认的问题

### P1

#### F01 搜索密钥缺少供应商归属

**触发与影响。** 用户在 SearXNG 设置下填写它的凭据，之后切换到 Brave 并保留已保存值。SearXNG 的请求根本不用该字段，切换后的 Brave 请求却会发出该值。SearXNG 所在服务为私有时，这会把为另一个服务填写的凭据交给 Brave。用户还可能一直误以为 SearXNG 在进行鉴权。

**调用链。** 设置对两家均展示同一个密钥字段及状态。空值不发更新，服务只在写入非空值或明确清除时改变公共 `provider_key`。搜索配置复制同一个字段，SearXNG 只发送表单与 Accept，Brave 把旧值用作订阅凭据。参见 `web/discovery.js:700–723,737,1357–1369`，`alice/discovery.py:875–911,2115–2123`，`alice/discovery_sources.py:683–725`。

**方向与验收。** 先以实际支持范围限制 SearXNG 控件及保存语义，按连接器身份绑定凭据，切换时确认新归属。既有无归属条目需明确迁移或重新确认，避免把全量键覆盖当作切换。用独立档案及低权限测试凭据从正常设置切换，确认界面要求新供应商的凭据、可清除，回执和采集均不回显值。置信度高。

#### F02 Lab 元数据接口带出模型审查理由

**触发与影响。** 使用带引文的改写等触发已启用的变换审查。审查供应商返回的理由可能包含原文片段。该自由文本在元数据授权下也可从 Lab 的请求投影读到，长度限制只限制显示字数。默认元数据采集已足以形成这类记录。

**调用链。** `grounding.decisions` 允许 500 字自由文本。`loop` 把理由截取 200 字交给 `reply_processed`，其通用限长仍保存该值。`context_requests` 将整条后处理数据聚合，Lab 的 `context` 未列在正文主题表里，仪表盘亦可展开原始投影。参见 `alice/config.py:90–118`，`alice/grounding.py:52–77`，`alice/loop.py:867–906`，`alice/context_observer/observer.py:134–139,389–391`，`alice/observation.py:174–178`，`alice/lab_observation.py:13–35`，`addons/alice_lab/web/lab.js:649–659`。

**方向与验收。** 元数据 DTO 只返回宿主枚举、布尔值、计数和明确允许的字段。若保留自由理由，沿正文分级和配额读取，旧事件也按当前投影清洗。用无敏感内容的真人改写样本与真实审查回执，核对元数据仅显示操作及结果，单独正文授权才展示允许的详情。置信度高，理由是否恰好含原文取决于供应商回执。

#### F03 来源许可复核未覆盖下一次物理调用与部分流式片段

**触发与影响。** 本轮已含外部来源，首次非流式模型尝试失败并进入内部重试。若来源在退避期间失效，下一次仍可能提交旧输入。另一个边界是 GUI 显式关闭默认三栏回复、且本轮无其他缓冲条件时，外部来源不足以触发增量缓冲，后置核验之前已有文本和推理片段可能到达浏览器。

**调用链。** 主循环在逻辑模型调用前、回执后及存储前检查 `packet_ids`，但 `chat(..., retry=…)` 的条件缺少来源许可。`llm.chat` 循环复用冻结参数，内部准入回调服务于后台模型计费。GUI `buffered` 条件缺 `packet_ids`。默认 GUI 三栏路径关闭直接增量和推理回调，QQ 发送还做独立 `sending` 复核，因此这两道改进分别缩小了显示和 QQ 投递的窗口。参见 `alice/loop.py:742–845,994–1014`，`alice/llm.py:109–163`，`alice/channels.py:509–516`。

**方向与验收。** 用实际依赖决定缓冲与派发准入。短期对带依赖的调用收紧内部重试。长期在每次物理派发和最终发布前回宿主核准。用许可明确的公开材料，在真实响应中对照到期时点、已派发尝试和界面阶段。分别核对默认 GUI、关闭三栏的 GUI 以及 QQ，保留已完成与未知结果的原有区分。置信度高，当前没有晚到或费用的现场记录。

#### F04 CLI 普通对话的第一条轮次写入失败

**触发与影响。** 按 README 进入 `python -m alice` 的交互聊天，完成人格准备后发送普通文字。新 UUID 对应的请求从未接单，用户行插入和渠道行更新处于同一事务，无法形成有效轮次。有渠道表时更新零行触发错误。无表时更新语句本身失败。既有资料是否曾由 CLI 写入与本次路径无关。

**调用链。** CLI 直接打开 Store，执行 `cmd_chat` → `run_chat` → `chat_turn(request_id=uuid…)`。`chat_turn_steps` 在模型派发前添用户行。`Store.add_turn` 要求已存在相同请求的空位。GUI 通过 `ChatService.send` → `ChannelCoordinator.accept_locked` 接单。参见 `README.md:39–49`，`alice/cli.py:95–111,214–229,252–257`，`alice/loop.py:369–381,1204–1212`，`alice/store.py:243–278`，`alice/channels.py:375–386`。

**方向与验收。** 若保留终端对话，走同一公共准入和持久化协议并沿用 CLI 输入、退出、独占语义。若退出产品，明确调整命令与文档。用已获准的真实隔离档案，从 CLI 发送第一条，再通过 GUI 查同一轮和跨次切换。CLI 的备份、查看、维护子命令各有入口。置信度高。

#### F05 compact 可跨过最旧合格往返并推进提取游标

**触发与影响。** 手动 compact，或开启自动 compact，且保护线和游标之间的合格积压超过查询窗口的 200 个往返。查询先取近端最多 200 个合格往返，再从结果末尾求这一窗口的“最旧”批次。若有 250 个合格待处理往返，在查询层就缺最早 50 个。提交推进 `compact_cursor`，同时推进 `extract_cursor`，普通后续续跑不再选中这些更早轮次，可能跳过尚未提取的记忆。原始轮次仍在库中。

**调用链。** `compact_span` 在 `context_history_rounds` 的倒序窗口之外无法看到更早积压。筛游标发生在取回之后。提交记录本次覆盖并前进两个游标。参见 `alice/maintenance.py:268–283,420–454`，`alice/store.py:374–401`。自动 compact 默认关闭见 `alice/config.py:194–221`。本次独立核对了 Astra 原 F02。

**方向与验收。** 在 SQL 中先限定 epoch、受众、游标和保护线，再从游标后最旧端有界取下一批。确认已有跳读的各代资料如何核对和修复，避免直接回拨游标造成重复提取。用已有长期记录的合法隔离档案先预览，再核对首次实际批次的首尾 ID、覆盖与提取游标。置信度高，当前资料是否有积压未知。

### P2

#### F06 工具正文先累积，旧 recall 超限才由下一次调用拒绝

**触发与影响。** legacy 默认装配下，长来源或多条共享证据的见闻经 `recall` 返回。若再有多轮搜索，完整工具报文继续留在输入。首个模型尝试可以成功，后续在宿主估算超限时不再请求模型，而保存宿主提示为回复。部分取用及绑定已发生。在 indexed 的有界 `recall_sources`，超限被丢弃的外部条目也已占依赖和 `recalled` 记录，可能把用户原文变为受源约束的投影，影响失效后历史或普通往返资格。

**调用链。** `MemoryContext` 只在 indexed 构造，逐工具余额只传给其分支及人格注册表。legacy `recall` 不传 `max_tokens/max_chars`。`tool_recall` 每项重复序列化 `source_block`，外部条目先写保护并更新依赖，之后才判断预算，实际进入回执的条目才 `bump_use`。搜索附着按来源数量与范围裁剪，无动态上下文余额，`loop` 追加整个结果后才运行总守卫。参见 `alice/loop.py:66–105,426–428,742–745,948–993`，`alice/retrieval.py:375–413`，`alice/discovery_memory.py:87–103,556–577`，`alice/dialogue_search.py:483–529`。

**方向与验收。** 让所有大正文工具统一取当前估算余额，包含完整工具请求、schema、回执包装、输出预留和前面回执。建立输出候选后先准入，再事务化绑定实际可暴露来源，最后返回正文和记录使用。以有效证据身份及版本去重。用真实公开长材料、共享来源及连续查找，分别核对两种装配的余额、省略结果、使用计数和历史。`reply_reserve_tokens` 是宿主估算预留，模型 `usage` 是独立回执，字符配额另算。置信度高。

#### F07 外部记忆的后备查询绕开本轮来源范围

**触发与影响。** 普通聊天没有显式回顾许可，也没有该来源在本轮，库中已有允许当前渠道读取的正式外部见闻或观点。`recall` 或 `recall_sources` 的后备查询仍可能选中这条资料并挂到该轮。在搜索已阻断、为空或被取消的同渠道回执下，`attach_locked` 也无条件放开后续外部召回。影响是原本限制为“只用本轮已知来源”的回退失效，还可能多计来源分享并使更多原文受来源期限约束。来源本身的渠道、到期与依赖有效性校验仍在。

**调用链。** `ChatService` 从 `select_for_chat_locked` 取得 `source_explicit`。`search_memories` 按许可校验 `allowed_source_packet_ids`。并入的 `memory_rows(purpose='chat')` 只校验当前渠道及正式证据，随后的候选循环再取证据时未检查是否都在原已知集合。搜索附着末端直接赋值 `True`。参见 `alice/service.py:1312–1343`，`alice/discovery.py:1085–1118`，`alice/retrieval.py:341–390`，`alice/store.py:474–499`，`alice/observation_memory.py:83–122`，`alice/dialogue_search.py:483–515`。

**方向与验收。** 在所有候选的最终准入点执行同一主题/许可策略，来源集合按回执实际许可控制。用正式见闻分别核对普通聊、显式回顾、有实读材料和无结果的正常搜索，记录哪些现有证据进入当前轮。置信度高。

#### F08 已撤下的外部来源仍可出现在留存调用快照

**触发与影响。** 用户开正文采集，一次请求实际输入含外部材料，之后撤销该来源或让材料到期。只要快照仍在留存窗口，持当前有效正文授权仍能从调用快照读取当时的材料，即使聊天和来源业务投影已收回。旧观测设计明确把来源失效后的正文列为不可读，当前独立 Lab 文档描述留存和短时授权，尚欠这两条策略如何相交的定义。

**调用链。** `freeze_final` 收录 `messages`，按请求和 hash 存放。`context_body/context_call` 查调用归属、留存、摘要，没有复核当前来源集合。来源撤销清包、清依赖记忆及会话附件，当前清理未覆盖冻结正文。参见 `alice/context_observer/observer.py:212–243`，`alice/observation.py:193–262`，`alice/context_observation.py:350–385`，`alice/discovery_memory.py:419–447`，`docs/设计文档/上下文组装优化/上下文观测插件-架构与施工设计-v1-20261107.md:104`。

**方向与验收。** 建议沿请求或快照显式绑定依赖，当前来源不合格时拒绝相关正文并保留明确缺口。已有无法证明依赖的快照如何处理、共享 hash 何时实删，需要先定数据策略。用无隐私的真实公开来源观测一轮，再由设置撤销来源，核对历史与 Lab 里只显示经过授权的剩余内容和缺口。置信度高，关于旧快照的处置仍需裁定。

#### F09 日常实例撤销后，已有 Lab 正文留在打开的窗口

**触发与影响。** Lab 已显示正文，用户在 Alice 主窗口点撤销并留着 Lab 页。服务会拒绝后续读取，当前页没有接收撤销或定期复核的机制，只在本地到期计时、相关查询报错或显式断开时清理。有的读取操作只报错也未重置页面。用户会误以为撤销已使仍打开的观测窗口停止显示。

**调用链。** Alice grant 撤销清除内存票，服务在读前、读后都验票。Lab 清除 `observations/body-result` 等集中在 `connect`，时钟只按最初的到期设定。`load` 和 iframe 处理失效，正文表单复用通用 `perform`，异步结果写入前也没有像 iframe 一样再比对连接身份。参见 `alice/lab_observation.py:69–100`，`addons/alice_lab/web/lab.js:738–778,780–825,844–860,936–943`，`addons/alice_lab/README.md:33`。

**方向与验收。** 由 Lab 代理和页面共用连接代际，在所有失效、切换、重进和待返回响应路径清理。选择有界复核或明确推送机制，使已显示内容的清理符合产品承诺。真人分别验撤销、到期、两标签切换、断开、慢回执。服务拒绝新请求与页面清除已呈现文字应分别记录。置信度高。

#### F10 Lab 上下文概览让同一连接的两个请求争用独占锁

**触发与影响。** 打开 Lab「上下文」页。浏览器同时查询请求列表和读取状态，代理任一请求持锁时另一个立即 409。如果列表先占锁，状态失败被吞掉，持有正文授权的用户可看到“未授权”。如果状态先占锁，整个页面读取失败。核心返回 `busy` 投影时也会被概览当空记录。其他模块的普通快照已显式检查 `status`。

**调用链。** `paintContext` 用 `Promise.all` 发送两个 `/api`。`Handler.do_POST` 用 `acquire(blocking=False)` 串行所有动作。概览直接读取 `requests.requests || []`，`status?.can_read_body` 为假即作未授权。参见 `addons/alice_lab/web/lab.js:613–627,738–763,875–886`，`addons/alice_lab/server.py:308–340`。

**方向与验收。** 在同连接上串行这两次读取，或合并一次只读投影。分别呈现失效、忙、未采集和正文未授权，保留 iframe 的独立查询检查。用元数据及正文两种授权连续打开概览和完整观测窗口，前台聊天繁忙时核对提示，避免误报空数据或未授权。置信度高，409 分支是否发生取决于调度重叠。

#### F11 主网页源遮罩没有取消旧逐句队列

**触发与影响。** 来源或协作回复已经拿到完整回执，但尚在逐句显示，历史同步也已标记该轮为来源绑定。此时设置变更、任务撤回或本地到期遮罩可清掉已显示文本，仍在队列的回调随后又画回旧正文。连接中断分支也只检查并可能移除节点，未结束当轮的旧正文/推理队列。历史同步能重新纠正部分情况，纠正依赖一次成功的同步。

**调用链。** `done` 的 `revealSync` 排后续 timer。`alice:sources-changed` → `invalidateSourceDisplays` 以及本地到期都走 `redactSourceNode`，它只换内容和移除 `<details>`。下一次 `revealStep` 按 `shown/pending` 重画。`send` 的 SSE `error` 有清队列，传输异常的 `catch` 未走同一分支。参见 `web/app.js:526–552,584–621,2723–2792,2838–2859,2973–2995`，`web/discovery.js:1173–1176`。桌面气泡对已有历史另用 `speech.set(..., masked:true)`，应单独验收。

**方向与验收。** 遮罩、失联、代际切换、节点移除统一使旧队列失效，只有同一代的当前可信历史能恢复显示。用真实无敏感来源形成长回复，在揭示过程撤回、过期或断开页面连接。确认占位不会被旧定时器盖掉，原请求同步后只显示一条。置信度高。

#### F12 安装人格失败时配置装配模式可能已经落盘

**触发与影响。** 在原文候选的安装步骤切换 `full/registry`，之后归档准备、文件或 SQLite 提交失败。配置修订号和内存装配模式先变，原人格可能还在或等待恢复。重开设置会读到新模式，原候选及可重试资格却仍以旧安装结果为准。若失败发生在归档前，归档恢复记录还无法解释该模式变动。

**调用链。** `apply` 按 token、预览版本、会话、当前人格与配置修订核对，在排空后再核对。随后 `replace_persona_mode` 原子改 TOML、发布内存配置，之后才 `_archive_locked`／`commit_import_plan`。人格事务日志记录候选、旧新人格 SHA、库标记与阶段。在模式先行落盘、日志尚未建成的失败路径没有共同恢复决定。参见 `alice/service.py:1149–1183,1186–1228`，`alice/config_edit.py:140–157`，`alice/persona_transaction.py:254–309`，`alice/persona_reset.py:84–164`。

**方向与验收。** 明确配置、人设文件、库标记和归档的提交所有者。可按操作日志记录旧/新模式及修订与恢复步骤，校验外部修改。成功回执和可重试语义共用操作身份。分别在新原稿归档与编辑保留会话两个正常入口，使用独立档案验证受控失败、重新读取、重放和现有候选档案。置信度高。

#### F13 邀请可能把宿主兜底回复记为已展开

**触发与影响。** 用户在 GUI 接受真实邀请，模型工具成功获取展开材料，下一轮因上下文预算退出或回复格式失败。宿主仍保存一条兜底回复，之后可能把邀请置为 `expanded`。用户没收到展开内容，状态却显示已完成。异常导致没有助手行时不会走这一提交分支。

**调用链。** `contact_reply` 先记录 `accepted` 和原请求，`ThoughtSession` 载入材料后向 `invitation_expanded` 加入 ID。主循环超限或格式拒绝也生成助手行。后续仅凭 `growth_valid` 与该助手行的请求身份即可 `commit_expansion`，没有检查该答复是否真的发布了展开。参见 `alice/autonomy_v2/services.py:476–485`，`alice/thought_workspace.py:721–741`，`alice/loop.py:742–745,849–852,1008–1064`，`alice/autonomy_v2/adapters.py:811–843`。

**方向与验收。** 分开接受、材料已载入、内容已交付三个事实。仅持明确成功的答复回执提交展开。失败保留有界的可核对状态，用户再次要求时重新核准。真人核对正常接受、额度不足和材料在途失效三条路径，主动联系次数仍只计实际送达。置信度高。

#### F14 模型可用搜索 `limit` 替换用户的每次结果设置

**触发与影响。** 用户在联网额度里设置每次对话搜索返回 0 或更少材料，搜索许可和其他额度仍有效。模型工具显式请求正数 `limit` 时，服务器用它替换用户设置。网络、读取和数量仍受其他上限，但这项用户额度本身失效。设 0 也可能触发网络读取。

**调用链。** UI 将 `chat_search_results` 作为可为 0 或不限的每次额度。工具 schema 接受 `limit`，`SearchSession.execute` 用模型给的值优先，后面仅和 `chat_material_limit/chat_dependency_limit` 取小，实际读取循环以计算出的 `wanted` 截止。参见 `web/discovery.js:255–256`，`alice/capabilities/commands.json:103–130`，`alice/dialogue_search.py:248–263,313–331,366–380`。

**方向与验收。** 定义用户结果数为服务端上界，模型只在其内收紧，同时把 0 和不限的含义同步到注册表与界面。真实环境用少量公开结果分别核对 0、1、不限以及模型要求单篇的动作，核对真实读取次数及回执。置信度高。

#### F15 发现页快捷开启仍要求旧后台模型许可

**触发与影响。** 内容访问关闭，沿用 `allow_paid=false`、旧日模型额度为正的来源默认值。用户只想开启内容访问和网页搜索，在发现页点「开启发现」会被要求同意后台模型使用或改日额度。打开联网设置直接保存可以开启，核心聊天搜索只检查内容访问、对话搜索和渠道许可。两个正常入口给出不同授权要求。

**调用链。** `toggleEnabled` 对旧 `daily_models/allow_paid` 无条件前置拦截。同一脚本设置提交将这一规则限制于旧调度版本，核心状态已明确是 `lifecycle-v1`。核心旧发现计时器只做清理和维护，三模式调度另归思想侧。参见 `web/discovery.js:588–596,621–628,1363–1369`，`alice/discovery.py:35–48,431–445,714–722,1148–1178`。

**方向与验收。** 两个入口使用宿主当前的同一设置许可规则，保留旧字段映射和实际付费闸门。以全新档案关闭探索模型许可，分别从发现页和联网设置启用内容访问，验证前台查找可用、后台权限仍由思想设置控制。置信度高。

#### F16 隔离 Lab 聊天遗漏 P1 未绑定或未入队的提示

**触发与影响。** 在开启 P1 的源码隔离实例授权下轮核查，之后许可过期或在途配置变动。正常聊天可继续并保存，核查未绑定。主服务已生成告警，但 Lab 只显示普通回复，测试者容易将该轮当作已随 P1 提交。核查入队失败时也存在相同提示缺失。

**调用链。** `ChatService._send_steps` 将捕获异常和入队异常的提示放在 `events`。普通 SSE 会逐条发送 `meta`，新 Lab 私有 `lab_chat` 只投影 `evaluation_warning` 这个顶层字段，核心回复未设置它。Lab 页面也只读 `reply` 和该不存在的字段，提交时已消掉本地 `armed`。参见 `alice/service.py:1302–1311,1362–1382`，`alice/server.py:932–948`，`alice/desktop_host.py:173–185`，`addons/alice_lab/web/lab.js:945–957`。

**方向与验收。** 让 Lab 读取实际的核查接纳/失败回执，至少用结构化状态或明确的 `events` 告警。聊天保存和核查提交分别确认，避免失败时自动重发任一动作。真人以有效和过期许可分别完成聊天，再在真实核查列表对照记录。置信度高。

## 5. 边界核对和待验证风险

- **回环与凭据。** 核心 `server.run` 限回环，GUI 检查 Host/Origin、意图与 JSON，QQ 机器端有独立凭据和所有者，Lab grant/open 使用 GUI 意图，read 是回环代理的独立 Bearer。票摘要绑定本实例 scope，重签、撤销、归档和过期可使旧票失效，读取前后都复核。Lab 页启动 key 从 URL fragment 取出后移除，不与 Alice 授权码混用。读取投影的正常路径只查资料，忙时返回状态，不执行模型、flush、维护或增加记忆使用计数。正文授权签发会启用有限的新请求采集，这项副作用发生在签发。正在完成的单次采集以请求起点的政策冻结，待裁定撤销是否还需打断已经许可的留存。参见 `alice/server.py:223–277,477–494,966–969`，`alice/lab_observation.py:53–100`，`alice/service.py:500–521,676–715,1192`，`alice/context_observation.py:151–172`，`addons/alice_lab/web/lab.js:1–4`。
