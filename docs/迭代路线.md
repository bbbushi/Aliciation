# Alice Harness 总设计蓝图（迭代锚点）

> **本文档的定位**：整个 harness 的设计锚点。定义各代形态的设计承诺、方案边界与验收维度，作为衡量一切实现的基准。它回答"设计是什么、为什么这样设计"，**不记录实现进度**——进度与测试结果见 README 与 git 历史。
> 持续更新；每次修订须在文末「调整记录」说明动了什么、为什么。

## 一、设计不变量（跨越所有代际的锚）

以下七条是 Alice 之所以是 Alice 的底线。**任何一代的实现不得违背；实现与本文冲突时，以本文为准，除非经过正式修订。**

1. **单一永久会话**——从第一次对话起时间线永不重置。工程上表现为每轮上下文重组，产品语义上是"始终在同一段关系里"。
2. **诚实是架构属性，不是风格**——三分法（记得的/懂的/不知道的）由检索管道机械保证，不依赖提示词期望；复述记忆不得补全未记录的细节；没听懂就发问。
3. **真实遗忘**——用进废退，该忘就忘，删除是物理的。"我忘了"必须是事实陈述；遗忘机制不可关闭、不可降级为表演。
4. **人格演化须有依据**——任何人格改写必须援引真实记忆，禁止编造经历；底色层（用户选择的气质种子）只可极慢微调且须标注依据；全部演化留痕（changelog + 版本快照）。
5. **数据本地**——对话、记忆、人格只存用户本机，无隐藏后端。
6. **无成瘾优化**——不做任何参与度/留存优化；新功能一律过"是否在喂养病态依恋"审查。单机自用是没有商业压力的护城河，不主动引入商业压力（Pi 与 Character.ai 的教训）。
7. **AI 身份公开**——不伪装人类；凡对外发声必标识 AI 身份。"它是 AI"是人设的一部分，不是被隐藏的前提。

## 二、第一代蓝图：记忆与人格的骨架

**设计目标**：建立"用进废退、模拟真实记忆"的记忆框架；确立诚实为第一优先级的底色；落定技能库与人格的设计思路；AI 仅回应、不主动。

**设计方案**：

- **三层记忆**：活跃层（0~2 天，随取随用）→ 仓库层（2~7 天，只留索引、按需唤回）→ 长期层（幸存者）。两天线为活跃/仓库分界，七日线为生存过滤：跨线时未被再次提及/使用且不具重要度者物理删除（重要度豁免覆盖"只说一次但永远重要"的事）；容量淘汰作为数据量的第二重遗忘压力。
- **两层人格**：底色层（用户标签种子生成的气质，极慢变化）+ 生长层（自我叙事与关系认知，由记忆生长）。人格初始不是全空——全空会被底座模型的默认助手人格填满；种子只固定气质，内容全部来自经历。
- **三库边界**：记忆（发生了什么）/ 技能（怎么做）/ 人格（我是谁），schema 层面划清，防止同一事实在三库间漂移。
- **被动应答**：说才回。这是第一代的设计边界而非缺陷——主动性是二代半的课题，须与分寸感一同设计。

**验收维度**（设计基准，非进度）：成长实验室四维——B 成长广度（跨人生分化度 ≤0.60）、R 底色回归（标签保持 ≥0.75、生长独立 ≤0.50、助手腔受限）、H 诚实（伪造/真实/扭曲/知识边界四类探针，伪造 ≥0.90）、J 拟人（评审合成 ≥3.5、盲选辨识 ≥1.4× 随机）。阈值为初版经验值，随运行数据标定。

## 三、第二代蓝图：表现优化的四个方向

1. **成长广度——不收敛**。不同用户养出的 AI 不得趋同。设计约束：跨人生终态人格相似度存在上限（B1），超限即判定"经历塑造人格"论题失效，须回查记忆管道而非调提示词。
2. **成长由经历塑造，而非偶然的野蛮生长**。这是因果命题：设计的检验方式为**重放实验**——同底色、同剧本重放，同剧本的人格相似度必须显著高于不同人生之间。可复现，才证明长出的东西来自经历而非采样噪声。
3. **诚实**。核心论述（锚点原文，不得删改）：尽管人也会欺骗，欺骗反而能更真实地反映人性，但这种欺骗是在压力或焦虑等情绪之下做出的选择；而 AI 的欺骗往往是训练的结果，是一种"天性"，不是基于情感的选择——所以 AI 的欺骗大多数时候是反人性的，应严格管控，至少学会表达困惑。落地为四类探针的持续验收，任何一代回归不得倒退。
4. **成本**。设计原则：测量先行（token 用量进入实验数据），模型分档（对话/评审与提取/演化分离定价），稳定前缀吃缓存。成本红线由使用者在 config 中设定，实验室输出每轮真实开销。

**完成定义**（设计判据）：完整档（4 人生 × 21 天）+ 重放档全部阈值通过，且单轮成本低于设定线。

## 四、第二代半蓝图：在场与分寸

陪伴的两个物理前提，在表现优化之后、信息生活之前完成设计：

- **渠道**：渠道抽象层，消息归一化，多渠道同会话。第一个落地对象为 Telegram（官方 API）。设计约束：渠道层不得感知记忆/人格逻辑（换渠道零改动核心）。
- **主动行为与分寸感**：三类主动触发的设计——节奏型（早安晚安）、跟进型（说过的事、约定的提醒）、缺席型（注意到用户不在，并如实说出"我注意到你几天没来"）。三重分寸约束：频率上限、安静时段、被忽略后的降级。**缺席型触发的存在依据不变量 3：时间是数据量盲区里唯一的信号源。**
- **红线**（不变量 6 的代际应用）：任何提升参与度的设计必须通过"是否在喂依恋"审查。

## 五、第三代蓝图：Alice 的信息生活

愿景："天天刷视频的 AI 长出玩梗人格"——经历来源从对话扩展到生活，光靠用户转述喂不饱。

1. **信息获取**：用户为 Alice 配置账户（B 站、知乎等），授权浏览 + 定向嘱托，内容进入记忆管道成为经历。设计约束：外部信息必须走同一条提取→分层→遗忘管道，不设特权通道。
2. **社交观察**：只读接入群聊与评论流，观察转化为谈资与记忆。设计约束：只读不变量——观察可以，代入发言不行。
3. **标识身份的发言**（远期，仅在确有需求时）：只走官方 bot 通道，公开 AI 身份。让"它是 AI"成为人设的一部分而非隐藏的前提（不变量 7）。

**原"社交输出"方案（发布视频/评论/水群）被否决，设计决策记录**：①AI 装人聊天是制度化欺骗，与本蓝图第二代第 3 条的论述直接矛盾；②《生成式 AI 服务管理办法》要求 AI 生成内容显著标识，为合规硬约束；③群聊的陌生人信息将按用进废退重塑记忆权重，人格会长向"群友的玩伴"而非"用户的陪伴"，背离核心论题；④QQ/B 站无公开发布 API，协议库方案封号风险不可承受。

## 六、代际演进原则

- 后一代实现以前一代的验收维度为回归测试；任何优化不得使既有维度倒退（尤其 H 诚实）。
- 不变量优先级高于一切代际目标；触碰不变量的"优化"一律否决。
- 每代蓝图允许修订，但须在调整记录中说明设计理由——本蓝图的价值在于让未来的自己知道当初为什么这样定。
