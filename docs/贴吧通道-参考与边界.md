# 贴吧通道：参考与边界

2026-10-31。实现为免费、匿名、只读发现能力；前轮已在实际 GUI 跑通主帖搜索、正文读取、整理与资料卡保存。本轮新增每个兴趣的优先吧、保存前的显式吧名检测，以及可选首页一级回帖。新代码 CLI 已确认候选软排序、20 条回帖读取及吧名检测，实际 GUI 已完成未保存兴趣草稿的吧名检测；新设置保存、评论资料卡、撤销及聊天带入仍待人工验收。以下是第三方项目作者的公开实现，不是百度官方稳定 API 承诺。

## 实现范围

- 搜索一次 `GET https://tieba.baidu.com/mo/q/search/multsearch`：`word` 为本轮已批准查询，`rn` 为用户配置结果数；固定 `st=1&needbrand=1&sug_type=2&pn=1&come_from=search&subapp_type=pc&_client_type=20`。只取明确为 `thread` 的卡片，按数字 `tid` 构造 `/p/<tid>` 引用。每个兴趣的 `preferred_forums` 为空时不设优先吧；填写后，按 `card.data.forum_name` 或 `forum_info.forum_name` 将当前返回页中匹配的候选排在前面，其他吧候选保留作后备。读取不到合适材料时，在用户候选读取额度内继续尝试后备；不保证目标吧出现在当前关键词结果页，不属于完整吧内检索或吧列表浏览。搜索摘要只用于候选发现，不作为已读正文。
- 新增优先吧前，用户显式点击“检测吧名”：每个名字一次 `GET https://tieba.baidu.com/mg/f/getFrsData?kw=<吧名>&pn=1&rn=1`，核实 `data.forum.id/name` 和 `data.thread_list` 中可确认的公开帖子。`ready` 表示名字一致且本次有公开帖，`empty` 表示确认吧但本次无公开帖，`mismatch` 表示返回吧名不符，`unverified` 表示本次未能确认；失败不等于证明该吧不存在。新增名字只有出现在当前会话、同一配置版本、最近已完成检测的准确 `ready` 结果中才可保存，已有且未改的名字不强制重测。检测独立受监督、可取消，计入共享网络与响应量额度；不调用模型、不保存兴趣、不自动开始寻找，总开关关闭时也可显式检测。检测成功不承诺稍后的关键词搜索一定命中该吧或有合适内容。
- 阅读一次 `GET https://tieba.baidu.com/mg/p/getPbData?kz=<tid>&format=json&pn=1&rn=<数量>`。正文 `data.forum.name` 与候选归属均存在时须一致；无法确认归属时如实标注，不推断为优先吧。`tieba_read_replies` 默认 `false`，以 `rn=1` 读取唯一且明确 `floor=1` 的主帖文字。用户明确开启后，请求 `rn=tieba_reply_limit+1`，从顶层 `post_list` 读取主帖及最多该数量的 `floor>1` 一级回帖；主帖与每楼分开标记，来源范围说明实际取得的回帖数。返回的帖子 ID 若存在，必须与请求一致；楼层 `id` 是回帖 ID，不拿它比较线程 ID。
- `tieba_reply_limit` 为用户可调正整数，默认 20，不另设业务封顶；仍受可准确表示的整数、单页实际返回、响应与文字额度约束，不能把请求数写成已读数。只读首页，跳过媒体文字空壳，不递归读取 `sub_post_list`，不取楼中楼、图片、视频或作者画像。缺失明确一楼仍拒绝；一楼存在但只有媒体时，获准回帖可独立作为讨论材料，主帖明确标注没有可读文字、媒体未理解，不把回复归给楼主或冒充主帖正文。
- 无账号、Cookie、签名、浏览器 UA 伪装、分页、重试、HTML 回退或写操作。GET、JSON 解码、地址约束、响应字节、取消和额度由调用方注入的 `fetch_json(url)` 负责。正文最终长度仍由来源层控制，模块没有另设业务额度。
- 状态码格式错误或结构缺失报告 `tieba_response`；明确非零 API 状态或错误状态报告 `tieba_api_error`；控制元数据明确要求验证码时报告 `verification_required` 并停止。空结果须有合法空 `card_list`；缺主帖报告 `unreadable`，主帖及本次获准回帖均无可读文字时报告 `tieba_no_text`，文字不足现有阅读要求报告 `tieba_short_text`，不以搜索摘要补正文。不返回平台原始错误消息、验证材料或响应原文。
- 搜索向调用方提供固定计数：`received` 为完整卡片数，`unsupported` 为非帖子卡，`duplicates` 为重复的合格帖子，`accepted` 为唯一合格候选数，`rejected` 为字段或地址不合规数，`returned` 为按用户结果数截取后实际返回数。正常响应遍历完整列表后再截取；关键结构错误仍立即失败，此时计数只反映失败前已处理部分。计数不包含查询、标题或正文，也不覆盖调用方已有的平台、渠道和阶段字段。
- 关闭回帖或减少允许读取的回帖数时，撤销不再符合评论范围的旧来源及依赖引用；不把已经取得的评论视为永久授权。更改兴趣的优先吧仅影响后续候选顺序；只改优先吧或原样保存，保留兴趣内容版本、现有合法卡片与待讨论绑定，不撤销历史公开证据。主题、概要、启用或外发许可实变仍沿用原有失效规则，已经失效的旧卡不自动恢复。新设置只提供可配置能力，不替用户填写优先吧或自动开启回帖。

## 字段依据与有意收紧

1. [FACT 固定 commit 的搜索参数与直接请求](https://github.com/muchuan77/FACT/blob/65647a6510f0cdbf6ce41c2ec5722ea74ab590f3/fact_crawler/crawler/platform_search/tieba.py#L213)及[请求实现](https://github.com/muchuan77/FACT/blob/65647a6510f0cdbf6ce41c2ec5722ea74ab590f3/fact_crawler/crawler/platform_search/tieba.py#L1357)没有显式账号 Cookie 或签名，但使用浏览器 UA。因此只证明存在该匿名代码路线，不证明 Alice 自报 UA 可用。
2. [FACT 的 getPbData 地址](https://github.com/muchuan77/FACT/blob/65647a6510f0cdbf6ce41c2ec5722ea74ab590f3/fact_crawler/crawler/platform_search/tieba.py#L622)、[floor/content 解析](https://github.com/muchuan77/FACT/blob/65647a6510f0cdbf6ce41c2ec5722ea74ab590f3/fact_crawler/crawler/platform_search/tieba.py#L772)及[errno 检查](https://github.com/muchuan77/FACT/blob/65647a6510f0cdbf6ce41c2ec5722ea74ab590f3/fact_crawler/crawler/platform_search/tieba.py#L899)提供协议形状；Alice 不采用其缺楼层时补号、首个可读楼层当主帖、失败时回退 HTML 的处理。默认不读回帖时使用 `rn=1`；开启后请求用户选定数量加主帖，仍要求明确且唯一的 `floor=1`，不将前端整理出的 `mainFloor` 当作未经核实的服务端替代字段。
3. 2026 年 8 月公开的 [getPbData 读取实现](https://github.com/liuxiaZzz/dys-reputation-board-community/blob/6b70ba1ece6c95e4a5493fa0a8a5d2cb8ba424ef/scripts/lib/tieba.mjs#L76-L94)明确使用 [`type=0` 的 `text` 作为正文](https://github.com/liuxiaZzz/dys-reputation-board-community/blob/6b70ba1ece6c95e4a5493fa0a8a5d2cb8ba424ef/scripts/lib/tieba.mjs#L26-L32)。[较早的解析器](https://github.com/DeathSea/defanive2MCPostOfflineVersion/blob/079e0fc138b210d9d37b261097aa82ce101b024f/mcd2/tieba.py#L114-L122)还将 `type=1` 作为带文字标签的链接；[WhiteSevs 的类型声明](https://github.com/WhiteSevs/TamperMonkeyScript/blob/001a81cd36a29dab9ab5aabbdcbdf0e49574ae77/scripts-vite/%E3%80%90%E7%A7%BB%E5%8A%A8%E7%AB%AF%E3%80%91%E7%99%BE%E5%BA%A6%E7%B3%BB%E4%BC%98%E5%8C%96/src/main/tieba/types/TiebaPostApiType.ts#L1)只列 `type=1`，不能据此排除 `type=0`。Alice 接受这两种片段的 `text`，不读取链接目标字段或访问目标；兼容 FACT 的字符串内容及无类型 `text/c` 片段，不将图片 URL、表情名或未知媒体补成正文。仅借鉴响应字段，不引入参考项目的 Cookie、重试或浏览器会话。
4. [近期作者的匿名 HTML 拒绝记录](https://github.com/adj18311/qq-bridge-plus/blob/291a897377fb3c9e9d24d0f24f047171a377a321/src/tieba-lib.js#L6)及[小程序空壳记录](https://github.com/adj18311/qq-bridge-plus/blob/291a897377fb3c9e9d24d0f24f047171a377a321/src/tieba-lib.js#L94)说明 HTTP 200 不等于取得帖文。这是作者环境中的观察，不能泛化为所有匿名访问都失败，也不能用它承诺本原生接口一定成功。
5. [MediaCrawler 固定实现](https://github.com/NanmiCoder/MediaCrawler/blob/68d9ef1c1da22eab75940dfd7cec259907006538/media_platform/tieba/help.py#L129-L144)同时接受 `cardInfo` 或 `cardStyle` 明确等于 `thread` 的卡片。Alice 保留这一兼容性，不把其他卡片类型或搜索摘要当作已读帖子。
6. [MediaCrawler 的 `forum_name` 读取](https://github.com/NanmiCoder/MediaCrawler/blob/68d9ef1c1da22eab75940dfd7cec259907006538/media_platform/tieba/help.py#L124)和 [xGoose 的吧名/吧 ID 字段](https://github.com/xGoose-dev/xgoose/blob/a702d0126ed911500e4354b47ce03f7654375eed/apps/chrome/skills/tieba.xgs.js#L434)支持候选归属识别。后者的筛选仅覆盖 `current_api_page`，不能据此声称有服务端吧内查询；Alice 采用这些字段做软排序，保留其他吧后备，不采用全局吧白名单。
7. [社区读取器的 `pn/rn`、`floor/id/content` 和页数](https://github.com/liuxiaZzz/dys-reputation-board-community/blob/6b70ba1ece6c95e4a5493fa0a8a5d2cb8ba424ef/scripts/lib/tieba.mjs#L76)及 [WhiteSevs 的 `page` 元数据声明](https://github.com/WhiteSevs/TamperMonkeyScript/blob/001a81cd36a29dab9ab5aabbdcbdf0e49574ae77/scripts-vite/%E3%80%90%E7%A7%BB%E5%8A%A8%E7%AB%AF%E3%80%91%E7%99%BE%E5%BA%A6%E7%B3%BB%E4%BC%98%E5%8C%96/src/main/tieba/api/TiebaPostApi.ts#L180)说明 `rn` 是每页请求数量，未提供稳定的服务端上限承诺。参考项目自己的 10/20/30 默认值不作为 Alice 强制上限；`only_post` 含义未证实，本轮不引入该参数。
8. [TiebaSpider 的楼中楼解析](https://github.com/bubumua/TiebaSpider/blob/7dc29f8ee215861bf18e940cc236e64eae869af1/src/GetPosts.py#L113)显示 `sub_post_list` 可嵌在楼层对象中；本实现仅处理顶层 `post_list`。`data.forum.name/id` 另见 [TiebaApi 字段线索](https://github.com/bakasnow/TiebaApi/blob/5b723c2322c2c294fc7434876dd00cfcbb6594f7/TiebaApi/TiebaWebApi/TiebaWebHuiFu.cs#L129)，但该项目空值分支有明显错误，不能照搬；本轮真实响应另行确认该归属字段。
9. [社区读取器的 getFrsData 请求](https://github.com/liuxiaZzz/dys-reputation-board-community/blob/6b70ba1ece6c95e4a5493fa0a8a5d2cb8ba424ef/scripts/lib/tieba.mjs#L49)提供 `kw/pn/rn` 和 `data.thread_list` 的公开实现；[TiebaApi 的状态与字段读取](https://github.com/bakasnow/TiebaApi/blob/5b723c2322c2c294fc7434876dd00cfcbb6594f7/TiebaApi/TiebaWebApi/TiebaWebZhuTi.cs#L131)在 `errno=0` 后校验 `forum/thread_list`，读取吧 `id/name` 与帖 `tid/title`。尚无经本轮验证的“不存在吧专用错误码”，因此 Alice 只报告当前检测状态，不把拒绝、结构错误或空列表宣称为不存在；线程标题只用于确认结构，不在检测结果中展示或保存帖子内容。

## 前轮主帖真实观察（有限确认，保留历史）

- 用户授权的真实 `multsearch` 请求返回 `no=0`，共 11 张卡片，包含 `thread`、`forum`、`hot_topic`。这确认了本轮请求取得搜索卡片；非帖子卡片应计入 `unsupported`，不是读取失败。
- 第一个候选的 `getPbData` 返回明确的一楼，但内容仅有 `type=3` 图片；第二个候选文字过短。这些内容不能用搜索摘要、图片或回复补齐，现分别提示 `tieba_no_text` 与 `tieba_short_text`。
- 本轮响应中的 `thread.title` 缺失是有效形状；实现允许其缺失，若 `post.title` 存在则独立核对类型，否则保留候选标题。修正 `type=0` 漏读后，实际工作进程对帖子 `11148114920` 成功取得 524 字符主帖节选；搜索诊断为收到 11 张卡片、7 条合格帖子、4 条非帖子卡、按本次请求返回 5 条候选。
- 实际 GUI 随后完成另一轮寻找：收到 21 条结果，20 条帖子候选、1 条不支持的类型，保存 1 张[手柄按键体验资料卡的原始帖子](https://tieba.baidu.com/p/10807476494)（本机时间 2026-10-31 01:27:03）。页面明确显示主帖文字节选、不含回复，并保留 Alice 的暂时判断及不确定性。本机现仅贴吧开启，知乎及第三方搜索许可、B站、维基百科关闭；未调整用户兴趣、模型授权或额度。

第三方搜索只在用户选择并配置该服务后用于发现同平台帖子；源站拒绝读取时，搜索摘要仍不能进入已读资料。登录或人工验证会话不在本次实现中。

## 2026-10-31 优先吧、吧名检测与一级回帖增量

最初两个有限 GET 确认了协议形状：关键词“游戏”取得 26 张卡片且帖子有 `forum_name`；帖子 `10807476494` 的 `pn=1,rn=21` 响应为 HTTP 200/API 码 0，包含 `forum.name/id`、首页标记及第 1—8 楼。这仅是字段确认。随后最终软优先实现通过独立只读 worker 做了下列真实 CLI 诊断，无登录、重试、模型调用、活库写入或配置保存：

| 操作 | 实际结果 |
|---|---|
| 搜索“游戏”，兴趣优先吧为 `steam` | 收到 24 张卡，20 条合格候选、4 条非帖子卡、0 条拒绝，返回 20 条；前 3 条属于 `steam`，其后保留 `bilibili`、`ps5` 等吧的候选作为后备 |
| 读取 `11148114920`，允许 20 条首页回帖 | 取得 `steam` 主帖及 20 条一级回帖，共 1992 字符，`tieba_page=1`、`coverage=forum_thread_excerpt` |
| 检测 `steam` | 返回 `ready`、实际吧名 `steam`、吧 ID `707597`、1 条公开帖；首次因本机固定路径表未加入检测入口而在网络请求前停止，补齐后本次成功 |

上述每个成功操作均为网络 1 次、模型 0 次，不代表主进程保存新兴趣或生成评论资料卡已经验收。服务随后经正常 GUI 退出后重启，新页面在 **02:26:03** 对未保存兴趣草稿中的 `steam` 显示“已确认，取得公开帖子”、实际吧名与帖子数 1，并提示可以保存；随后取消编辑、清除草稿并关闭临时页，没有保存示例兴趣、发起寻找或聊天。此项确认了真实 GUI→受监督检测→结果展示，未覆盖保存与评论卡片全链路。

产品默认不读回帖；现场用户已经自行开启回帖、设置数量为 200，并保存了自己的兴趣与优先吧，本次诊断保留这些现有设置。前轮 GUI 的 21→20→1 主帖成功记录继续保留为历史，不改称读过评论；新设置保存、后备读取、范围撤销、异常与聊天使用仍按实施报告的人工剧本验收。
