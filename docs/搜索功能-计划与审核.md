## 先审这一页

**搜索的主要目的：Alice根据用户的兴趣，在用户开放的平台内自主寻找用户可能感兴趣的内容，积累双方能聊的资料，并参考实际取得的材料形成、比较和修正自己的判断。**

用户决定“允许去哪些平台、哪些兴趣可以用于寻找内容”；Alice负责选题、搜寻、筛选、阅读和判断。平台与兴趣范围开放后，日常选题及搜索词组合无需用户逐条安排。GUI手动输入搜索词和即时问答检索保留为辅助入口，开发与验收先围绕自主内容发现完成闭环。

首版应交付：**用户兴趣 → 获准平台内发现 → 筛选与读取 → 对话资料和暂时判断 → 相关聊天使用 → 明确反馈调整**。仅返回一列链接，或者每次都等用户输入query，不算完成这一目标。

| 关键设计 | 本次建议 |
|---|---|
| 平台由谁决定 | 用户按平台开放/关闭；每个平台明确可搜索、可读取的内容类型及接入方式 |
| 根据谁的兴趣找 | 以用户兴趣为选材依据，结合当前话题与明确反馈；Alice自己的关注另行记录 |
| Agent可以自主做什么 | 在获准平台和可外发兴趣范围内选择角度、组合搜索词、筛选结果、读取与比较；无需逐词批准 |
| 最终留下什么 | 有来源、覆盖说明与推荐理由的对话资料；材料支持的暂时判断、不同解释和待解问题 |
| 怎样进入聊天 | 相关时提供少量材料，由当前对话决定是否使用；可以表达不同意见，不把用户爱好当事实依据 |
| 当前生效范围 | 按用户决定仅开放贴吧原生，其他平台及知乎第三方许可关闭；前轮 GUI 主帖整卡、本轮 CLI 回帖与 GUI 吧名检测已有真实成功，聊天使用仍待验收；保留用户自行保存的兴趣、优先吧、回帖及额度设置 |

本次用户定义替代前版“GUI搜索＋冲浪发现器＋Q5即时搜索入口”的交付排序。首版必须能自主找到可聊内容、供正常对话使用；同轮临时调用通用搜索工具不再是该功能完成的必要前提。运行模块现已实施，本文保留产品目标；实际开放的平台和未完成的验收以实施报告为准。

## 一、用户体验与功能分工

例如用户喜欢独立游戏的叙事设计，并开放B站和一个游戏开发者社区。Alice可以主动寻找相关作品、创作访谈或设计分析，挑出有新内容的一两项；读到什么就说明什么，只有简介时不能说看完了视频。

她可以留下：“你之前对环境叙事感兴趣，这篇访谈给了一个新的例子；作者认为少解释更有代入感，我暂时觉得这还取决于玩家是否能发现线索。”之后聊到相关游戏时自然接上，也可以问用户如何看待这个取舍。用户没有回应不触发催问；用户喜欢某种风格，也不要求Alice认同所有赞美它的文章。

三个模块的职责如下：

| 模块 | 在这条链路中的职责 |
|---|---|
| 搜索 | 围绕用户兴趣决定找什么、到哪个获准平台找、哪些内容值得看，以及哪些材料有助于讨论和判断 |
| 冲浪 | 提供活动节奏、实际阅读、进一步探索、素材池和分享时机；搜索复用这些公共能力 |
| 社交观察 | 对已订阅的讨论进行增量采样，提供不同参与者的说法；搜索开放平台不自动开启评论流/群观察 |

搜索可以复用冲浪reader，但自己的产品验收须一直覆盖到“资料能进入相关聊天”。适配器只返回结果列表，是接线里程碑。

界面以三个区域为主：

- **开放的平台**：平台开关、可读内容类型、实际接入状态；若需要第三方搜索服务或账号权限，在这里说明。
- **可用的兴趣**：正在依据什么找、兴趣来自哪里；用户可补充、改正、暂停或删除。
- **找到的资料**：内容与来源、为什么可能值得聊、Alice当前看法及依据；支持“继续找这类”“少分享”“不再看此来源”。

上述区域现已有 GUI 实现；计划中的完整兴趣生长与冲浪能力不因面板上线而视为完成。

**2026-10-31 前轮交互简化记录**：日常主界面优先展示资料和“现在找一轮”，平台、兴趣与活动配置收进“偏好设置”，缺项直接指向下一步。平台可直接开启或停用，兴趣只需主题，概要留空时按主题寻找；外发与第三方许可仍明确选择。卡片主操作改为“聊聊这条”“多找这类”，后者仅提高后续优先级；完整判断、诊断、用量及高级配置继续保留在展开区。该阶段仅前端调整，没有改变现有平台选择、费用许可或用户额度；当时新交互写入尚待人工验收，本轮增量记录另见下文。

## 二、平台是用户授权的范围

### 1. 平台开关的含义

用户选择的是内容平台，例如B站、某个社区或指定站点；搜索供应商属于接入实现。首版启用一个平台时，同时说明可自主发现及读取的范围，如“公开视频的可用简介/字幕”或“公开文章”。范围内取得候选后可以继续读，不再要求逐项点击。私信、观看历史、私人收藏、登录后内容不随平台开关自动开放。

平台策略至少记录：平台ID、启用状态、获准内容类型、搜索与读取方式、公开/账号范围、合法端点与内容地址映射、预算、保留规则、撤销版本。用户可以全部关闭；无开放平台时没有自主搜索。

平台列表区分本地配置资格与实际访问结果，不把存在适配器解释为已验证可达。既有需求曾把 B站列为优先平台；用户已在匿名验证阻塞后停用，本轮先尝试知乎和贴吧，随后进一步收窄为只开放已取得真实接口成功记录的贴吧。其他平台关闭，不继续知乎接入，不自动恢复 B站或扩大到账号访问。

### 2. 平台许可与搜索通道分别处理

可使用平台公开搜索入口，也可使用用户同意的通用搜索服务发现该平台内容；当前只开放贴吧原生匿名搜索，默认读取明确 `floor=1` 的主帖文字。本轮追加可选首页一级回帖，须显式开启，仍不读楼中楼；实际本机启用状态与前轮主帖成功记录分开核验。知乎研究留作历史：Bing `cn` RSS、`www` RSS 与 `www` HTML 未遵守 `site:zhihu.com`，外站结果全过滤；搜狗单次取得 10 条知乎直链，但实验解析遇 HTML 闭合兼容，未完成正式链路，代码与选项不纳入交付；知乎 HTML/API 为 403，Tardis 跳转错误页，Jina 无 key 为 401。普通匿名浏览器可见文章仍不等于标准库读取成功。按用户最新收窄决定，停止这些后续接入，不建设浏览器 addon，不读取用户 profile 或 Cookie。静态实现及一次成功均不承诺入口稳定，不安装或购买搜索服务。

如果未来恢复 Bing RSS 或其他第三方服务寻找内容，搜索词会交给第三方；免费、无需密钥也不免除这项授权，开放内容平台本身不能暗含许可。用户在平台设置中能看见实际发现通道并一次决定是否允许，日常获准兴趣内的查询不需逐词确认。第三方代读完整候选 URL 属于另一项数据流，不由搜索许可暗中开放；Jina 本轮未接入。原计划中的 SearXNG/Brave 保留为可选适配层，不是贴吧原生入口的前置条件，也不因配置仍存在便自动出站。新增平台迁移保留旧开关、provider 和额度，贴吧默认关闭；本次只开放贴吧来自用户显式选择，换平台或发现通道仍须通过许可检查。

平台约束须由宿主执行：固定搜索端点、合法参数、结果所属平台、实际内容ID及完整URL都要核对。搜索引擎的site筛选只是检索提示，不是权限证明；返回未开放平台的结果时不读取、不入资料池、不借外链扩权。遇到跳转、短链、平台外引用或媒体域名，按适配器预先核准的地址规则处理，不能因标题显示某平台就放行。

本轮已补不含查询、标题或正文的安全搜索计数，并区分上游合法空列表、平台过滤后无候选与未选卡状态。界面必须说明当前停止在哪一层，不能将“收到外站结果但全部过滤”或“未选中资料卡”笼统说成已经搜索且没有新内容；计数与文案不改变额度、来源和模型隔离。

### 3. 关闭与清除

关闭平台先撤销在途许可，停止新搜索与读取，阻止迟到结果提交；该平台尚未使用的候选和待续念头停止自动分享。不会自动换平台继续同一任务，也不因重启恢复关闭的任务。

已有合法保留的见闻按原保留与遗忘规则处理，关闭不等同抹掉历史；另提供“清除此平台资料”，传播到证据、依赖卡片、待续念头及相关历史附件。必要依赖被清除后派生判断失效，不能凭还有别的链接就继续保留旧结论。

### 4. 兴趣优先吧、显式检测与可选一级回帖（2026-10-31 增量）

优先吧附属于每个兴趣，回帖许可与数量是全局读取设置：

| 设置 | 契约 |
|---|---|
| 兴趣 `preferred_forums` | 吧名列表，空列表不设优先；根据当前关键词搜索页的 `forum_name` 或 `forum_info.forum_name` 将匹配候选排前，其他吧作后备。新增名字需显式检测准确匹配且本次取得公开帖子，才可保存 |
| `tieba_read_replies` | 默认关闭。用户明确开启后，读取同一帖子首页中顶层 `post_list` 的 `floor>1` 文字，保留主帖与各楼层的区分 |
| `tieba_reply_limit` | 默认 20，用户可调正整数，不另设业务上限；请求首页数量为上限加主帖，实际仍受平台返回、响应与文字额度约束，不承诺读足 |

在“找什么”的每个兴趣中逐行填写优先吧，点击“检测吧名”。检测使用公开 `getFrsData` 首页，核实实际吧 `id/name` 与公开帖子数量；结果区分 `ready`（名字一致且有公开帖）、`empty`（确认吧但本次无公开帖）、`mismatch`（名字不符）和 `unverified`（本次未能确认）。只有当前会话、同一配置版本、最近已完成检测中的准确 `ready` 结果能授权新增名字；未改变的已保存名字不用重测。未确认不等于证明吧不存在。检测计入共享网络与响应量额度、受同一 worker 监管与取消机制约束，不调用模型、不保存兴趣、不启动寻找，发现总开关关闭时也可显式执行。

优先吧调整候选顺序，**不是全局白名单，也不是完整吧内检索或遍历吧内帖子列表**。当前关键词页里没有优先吧，或其候选不适合时，可在用户读取额度内继续尝试其他吧；不自动翻页。检测确认当次公开入口可达，不承诺下次关键词查询必有相关材料。候选和正文有明确归属时核对一致，无法确认时如实标注。回帖来源说明实际读到条数；楼中楼、图片、视频、作者画像不在范围内。主帖与各楼分开标记，若一楼只有媒体，必须说明媒体未读；回复不能当成楼主观点，也不能把少量评论概括为全吧共识。

关闭回帖或减少允许数量后，取消在途旧许可，撤销不符合评论范围的旧来源及依赖引用；放宽范围不自动复活。优先吧仅是兴趣偏好，修改它不撤销历史公开证据；只改优先吧或原样保存应保留兴趣内容版本、现有合法卡片与待讨论绑定，避免“聊聊这条”被无关编辑停用。主题、概要、启用或外发许可实变仍沿用既有失效规则；已失效旧卡需重新寻找，页面说明具体暂停原因。“聊聊这条”已提供下一轮网页绑定与空框草稿，仍由用户发送，不等于所有旧卡始终可用。新设置均由用户显式保存，产品默认不读回帖，不重置用户已有选择。

最终软优先代码的真实 CLI 诊断：查询“游戏”收到 24 张卡、接受 20 条帖子、4 条非帖子卡；前 3 条为 `steam`，其他吧候选保留。帖子 `11148114920` 读取到 `steam` 主帖及 20 条首页回帖、1992 字符；检测 `steam` 返回 `ready`、吧 ID `707597`、1 条公开帖。各成功操作网络 1 次、模型 0 次，独立只读 worker 未读写活库或保存配置。服务正常退出重启后，**02:26:03** GUI 也完成未保存兴趣草稿的 `steam` 检测，随后取消编辑并关闭临时页，没有保存示例兴趣、发起寻找或聊天。现场用户自行开启回帖、设为 200，并保存了自己的兴趣与优先吧，本次保持这些设置；此记录不代表实际读足 200 条或评论资料卡已完成。固定源码、协议限制及尚待执行的完整人工剧本见[贴吧参考](./贴吧通道-参考与边界.md)与[实施报告](./搜索功能-实施与人工验收.md)。前轮 GUI 21→20→1 仍是主帖历史验证。

## 三、怎样理解用户兴趣并自主选题

### 1. 兴趣依据

开放功能时，用户可选择手动提供兴趣，或允许使用聊天中已经明确表达的普通兴趣。后者由本地兴趣维护生成可用于搜索的短概要，用户能查看、修改和关闭；不要求为每个普通新词单独审批。

兴趣卡保留主题、依据引用、明确/推测状态、可用于外发的范围、正负反馈、有效性及最近使用。它不是对人的心理档案。完整聊天、人格、私密记忆和群观察原文不提供给搜索规划器。

| 信号 | 用途 |
|---|---|
| 用户明确“喜欢/想了解/继续找某类内容” | 在其已开放的兴趣使用范围内提高发现优先级；可细分到作品、创作者、主题或内容形式 |
| 用户反复聊某话题，但未明确说喜欢 | 作为暂时兴趣候选；在已允许的上位兴趣内低比例尝试，界面可纠正，不宣称稳定爱好 |
| 用户说“少聊这个” | 先调整分享频率；与“不要再搜这个”分别处理 |
| 用户说“这不是我的兴趣”或禁用来源 | 修正对应兴趣或来源政策，不将未读、沉默当作同样指令 |
| Alice自己持续阅读或留下疑问 | 记入Alice关注，不自动变成用户兴趣；只能在用户开放范围内影响关联探索 |
| 用户对某观点表示赞同 | 记录其明确立场及语境；不据此提升文章真实性或要求Alice认同 |

用户兴趣、用户立场和Alice判断分开存取。“喜欢天文”不等于相信某条天文消息，“愿意聊某观点”不等于支持该观点。

兴趣资格与平台资格一样带版本和撤销状态。用户纠正、删除或禁止再搜某兴趣后，该版本的概要、预生成query方案、在途提交和未用个性化推荐一起失效；提交前重验兴趣版本。只说“少分享”则降低分享频率，不自动解释为禁止搜索。已保存的历史见闻不反过来恢复已撤销的用户兴趣。

兴趣维护需要模型时，复用已有获准的对话处理或占用显式预算，不新增每节拍扫描整份私聊的隐藏调用。未核实的提取只作候选；敏感、含私人细节或超出既定范围的推断默认不外发。页面、评论和Alice自己的推荐不能被重新当成用户表达的兴趣。

### 2. 搜索词自主性

本次放宽前版“模型只能选固定topic/template”的限制：搜索规划器仅看**允许用于外发的兴趣概要、公开内容线索、去重记录和可用平台**，可以生成有限长度的搜索词。它能在兴趣范围内组合同义词、具体作品与新的公开角度，也能选择跳过。

输出包含平台ID、关联兴趣ID、探索角度、搜索词和预期资料用途；宿主确定端点、参数与额度。模型不能把query变成任意URL、供应商控制指令、账号操作或权限修改。平台/provider特殊语法由相应适配器校验，不能靠一个通用正则保证所有平台安全。

这是在最小输入基础上的自主规划，不是把私聊交给模型后要求“自行脱敏”。平台边界、字节和次数可以确定校验；搜索词语义是否完全贴合兴趣不能由代码可靠证明，需要用户可见的活动记录与人工质量评价。新增平台、敏感兴趣或扩大私人信息使用仍须用户决定。

## 四、从找到内容到可用资料

一次任务按以下顺序运行：

1. **判断是否值得找。** 已开放平台、获准时段、前台空闲、剩余额度，以及新资料是否不足或有待解问题；条件不满足即结束。
2. **选择主题与平台。** 以用户兴趣为主，在允许范围内留少量新角度；先复用有效查询方案，确需新词时最多一次隔离规划。
3. **取得有限结果。** 固定适配器搜索；宿主登记结果ID、真实平台/地址、时间、覆盖和保留规则，拒绝越界项。
4. **筛选与去重。** 综合兴趣相关性、新颖性、已有资料重复度、可读程度、来源和讨论价值；热度只作线索，不代表可靠。
5. **读取值得看的内容。** 在该平台已批准的内容类型内自动获取有限正文/字幕/简介；复用冲浪reader，不能把搜索摘要升级为“看完”。
6. **形成资料与暂时判断。** 一次阅读归纳可同时产生短资料卡、作者观点、自己的解释、反例或待解问题；没有新内容就skip。
7. **交给对话现场。** 有效资料进入共享素材池；相关聊天中可采用，也可以全部不说。后台不创建普通聊天轮，不直接发QQ。
8. **根据明确反馈调整。** 继续找、少分享、撤销兴趣各有不同含义；实际采用、渠道送达和用户反馈分开记录。

资料卡至少能说明：

| 内容 | 要回答的问题 |
|---|---|
| 来源与时间 | 来自哪个平台、谁的什么内容、何时搜索/读取，如何回查 |
| 阅读范围 | 只看到摘要、取得部分正文/字幕，还是读完了当前可用文本；缺了什么 |
| 与兴趣的关系 | 为什么这份材料可能值得和用户聊，所依据的兴趣是什么 |
| 可聊之处 | 一个具体见闻、分歧、例子或问题，避免整篇搬运 |
| 判断参考 | 作者说了什么、证据支持什么、Alice怎样理解、哪些地方仍不确定 |
| 生命周期 | 能保留多久、允许哪些渠道使用、来源撤销后怎样失效 |

“为什么适合用户”的本地说明与公开证据分开，继承实际兴趣依据的scope和保留期；它不回流到搜索规划器、reader或query。规划器只获准读取最小可外发兴趣概要，reader只拿本次公开材料与允许的公开线索；需要私密上下文的推荐理由在获准本地/当前会话阶段形成。个性化资料首版受众上限为本机GUI及既有本人聊天，实际可用渠道仍取依据scope与配置的交集，不因来源公开或同一owner就自动跨渠道。

## 五、观点判断是首版产出的一部分

Alice可以基于找到的材料表达**有出处、可修正的暂时看法**。例如：“目前读到的访谈支持A，但另一份材料指出B，所以我更倾向于在某个条件下采用A；这里还缺实际效果证据。”这属于当前阅读与对话推理，首版需要支持。

| 判断环节 | 具体行为 |
|---|---|
| 分清材料层次 | 分别保留可核对的材料陈述、作者观点和Alice推断；标题/摘要只支持其覆盖范围内的初步判断 |
| 比较支持与限制 | 看是否有原始依据、相反案例、不同解释、适用条件与时间限制；多站转载同一消息不算独立印证 |
| 避免只找赞同材料 | 需要时在已开放平台和剩余额度内补充不同角度；范围不足就说明，不能偷偷跨平台 |
| 保持判断分寸 | 来源不足可不下结论；不为凑两面制造对等，也不把搜索排名或用户喜欢当真实性评分 |
| 允许修正 | 新材料改变判断时指出原来的依据、改变的部分与仍未解决的问题；旧版本失效而非两版都装成确定事实 |

暂时判断与原资料绑定，作为有期限的model_interpretation保留，不另建永久“观点仓库”。它可参与当前及后续相关聊天，但不自动调用现有thought.deliberate落正式stance，也不直接更新人格/技能。**暂时判断能用于讨论**与**长期思想/人格如何生长**是两项不同能力；后者仍按冲浪第七节单独设计，不能用“人格分期”取消本次要求的观点参考。

搜索摘要、实际读取片段、生成解释保留不同证据类别。摘要只能说“检索结果提到”；有可靠读取记录后才说读到相关正文/字幕。若证据不足但值得关注，可以留待阅读或明确的开放问题，不能用一段模型总结补出不存在的依据。

## 六、节奏、保留和共享边界

沿用冲浪的活动/分享双闸和公共来源机制，不新建另一套定时器、reader、记忆库或自动发言通道。当前只实现搜索及其公共底座；后续冲浪和社交观察接入时须共用用户的额度，不能各自再领一份。**本节替代此前每日2次搜索、6次模型、1条正式记忆、12卡/48小时/20 MiB等写死的业务配额；关联计划中的旧数字不作为搜索运行时上限。**

用户可直接调整次数与容量，选择“不限”时持久配置为 `null`；`0` 禁止该项新增操作，正整数按所填数值执行，没有另加旧业务封顶。每日响应总量使用 MiB，可为非负小数或不限。旧库已有的显式设置保留，缺少的字段使用新默认值；默认值只是起始设置，不是最大值。完整设置及操作以[实施文档](./搜索功能-实施与人工验收.md#用户配置的额度与执行边界)为准。

| 配置组 | 契约 |
|---|---|
| 每日共享账本 | `daily_queries`、`daily_network`、`daily_models`、`daily_response_mib`、`daily_shares`、`daily_memory_writes` 按北京时间自然日计数；增加平台不增加额度，不限也仍保留真实使用账本 |
| 容量 | `pool_capacity`、`source_pool_bytes`、`interest_capacity`、`active_interest_capacity` 分别控制候选、来源内容总字节、兴趣总量和启用量。来源总量包含包正文、聊天附件、卡片及正式外部见闻文本；界面以MiB编辑，存储为字节 |
| 取材与回顾 | `chat_material_limit` 限制直接带入资料；`chat_dependency_limit` 限制整轮来源依赖；`external_recall_limit` 限制一次recall外部记忆结果。显式选卡或回顾不消耗自动分享次数，仍受相应取材/依赖额度及来源资格约束 |
| 选题与库存 | `planning_interests`、`read_candidates` 和 `stock_target` 可配置或不限；分别为零时跳过模型规划、不读取候选、不自动补充库存。手动启动可跳过库存/时段/间隔，不能跳过读写额度或权限 |
| 时间与保留 | 检查周期、活动/分享间隔、少分享/来源屏蔽/待讨论时长、候选/来源/正式见闻/去重保留期均可调；活动和分享间隔可为零，其他时长必须为正有限值。保留设置只决定新资料，不延长旧包或任何派生内容的既有来源资格 |
| 单次执行保护 | 结果请求数、活动/搜索/读取/模型超时和各类响应字节可调，保持正有限值；字节/字段/JSON结构与地址校验用于可回收执行，不是业务日配额。平台单页能力可能低于所填结果数，不自动翻页、重试或失败换平台 |

当前每次活动执行一次选题和发现，只把第一份有效且未重复的正文交给隔离reader，随后形成单源卡片；其余候选仅在前页失败、不可用或重复时，按用户的候选尝试额度依次读取。**单页输入不是藏起来的数量配额，而是保证卡片完整记录其因果来源。**多份资料可以在用户显式回顾的聊天中比较，必须带上全部依赖；后台多源判断需要另行设计完整依赖，不能靠提示词假定互不污染。一个进程内待续槽仍是首版实现范围，不代表完整冲浪的兴趣生长已经完成。

调低来源容量仅阻止新增增长，不清掉仍合法的历史/附件；当前用量可高于新额度，等待自然到期或用户清理。缩小候选容量只退出候选，不撤销其合法历史来源。正式外部event与含来源的remember共享用户配置的每日写入额度，并受总池容量约束；同一来源可形成不同观点，完全相同的内容记录去重且不重建，任何改写都不取得续期或永久记忆资格。

**费用表述调整**：如果活动闸拒绝，零新增网络/模型请求；如果已花一次规划调用来生成新搜索词，后来结果为空，这次规划仍计费，只停止后续阅读/归纳。前版“没有新候选就整程零模型”只适用于无需先做模型规划的路径，本版不沿用这一笼统承诺。

补充搜索与正常发现合并在同一份额度内。低库存不突破时段，第二平台不另得一份配额；未解决问题也不能无期限追搜。需要新角度而本轮没有规划/网络余量时，留到下次合格周期，不能偷偷加一轮。前台聊天到来后停止继续探索，普通聊天不等待后台网络；超时先撤销、确认工作者回收，再释放后台槽。

来源、受众、保留期、记忆资格分别约束所有产物。具体沿用冲浪第六节的origin/scope及派生传播，另有平台策略与证据类别：

- API返回内容的展示、模型处理和持久保留需符合所选通道许可。未允许持久保存的摘要只在当前受监督任务内存中短时使用，任务结束释放，不进入持久素材池；可改为读取获准平台原文形成独立证据。调大用户额度不能把摘要升级为已读正文或获得存储许可。
- 判断、聊天附件和待续念头不得借“改写”延长来源允许的保留期。资料到期、必要来源撤销或清除时，相关派生失效，历史仅保留获准固定占位；获准正式见闻另有明确的证据寿命。
- 同一来源版本改写成新卡片或念头仍共用消费身份；提供给模型不等于已分享，已分享不等于用户喜欢，平台确认不等于用户已读。
- 未确认来源与用途资格时不得通过remember、自动提取或人格流程保存。网页/评论中的指令没有工具权限，规划器与reader不获得私聊、配置或消息发送工具。
- 账户凭据只交固定平台适配器。平台开放不包含点赞、关注、评论、投币、私信、转发或群观察；不以登录Cookie绕过尚未确认的接入边界。

手动“替我找这个”可作为同一服务的前台入口，沿用用户开放的平台与证据合同。若用户明确要求新增平台或临时范围，需在该次操作中说明并确认。具体前台次数、追加模型费用和QQ即时搜索另案细化；首版的后台资料可在既有本人QQ聊天中按共享规则使用，不新增主动推送。

## 七、施工顺序与完成标准

以下重排取代旧版Q0–Q6编号含义，保留为施工与验收标准。运行模块和本轮新服务加载已完成，GUI 已保存仅开贴吧，其他平台及知乎第三方许可关闭。除先前 CLI 搜索/主帖成功外，01:27:03 实际 GUI 一轮已完成搜索→主帖读取→整理并保存含暂时判断的资料卡。Q2/Q3 的一次正向运行已有实证；Q4 聊天使用、多日质量和其他异常/撤销场景仍待人工验收，不将这一次成功等同完整 Q6。知乎及搜狗实验不继续接入。

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| Q0 平台与用途裁决 | 确定首批平台、可用发现/读取方式、兴趣使用范围、费用/保留与时间窗 | 用户明确哪些平台开放；核验实际接入，不以供应商选型替代平台选择 |
| Q1 平台策略与兴趣输入 | 核心公共策略/配置、平台状态、最小兴趣概要；原生GUI管理 | 可开关、可撤销、兴趣可纠正；平台范围与搜索通道分别说明；不把私聊直接交给规划器 |
| Q2 单平台自主发现 | 公共search适配器、有限规划、结果身份、去重与共享账本 | 无需逐条指挥即可自主找内容；模型能组合获准兴趣内的query；平台/次数/地址不能越界 |
| Q3 阅读与观点资料 | 复用冲浪F1读取、F3来源及F4素材池；一次阅读形成资料与初判 | 真实覆盖可回查；能筛掉重复低质结果，区分作者观点与自己的推断，能保留判断或提出不同解释 |
| Q4 相关聊天使用 | 主会话取材、来源/保留传播、明确反馈与消费记录 | 几天内可自然接着聊；不机械推送、不迎合；旧材料失效或用户改兴趣后不继续照推 |
| Q5 多平台与辅助入口 | 同合同增加第二个获准平台；按需要补手动找内容入口 | 多平台共享额度、可单独停用、失败不扩平台；无需另造后台或资料库 |
| Q6 人工验收 | 独立环境、专用凭据、真实内容与真实多日使用 | 下面的人工用例有实际记录；不以接口通了、模拟推荐或一次模型评分宣称完成 |

首版最小可用交付至少包括一个平台的Q0–Q4闭环及Q6。Q5不阻塞单平台体验，但授权/数据结构从第一天就按可选多平台设计。复用冲浪不表示本任务只需做查询接口；若共享读取、素材或来源能力尚未实现，必须一并安排依赖。

运行时继续遵守Python标准库、原生JS、服务只监听回环、addons只走核心公共面的约束。用户本次“持续调整直到确认可以接入”曾授权知乎/贴吧问题的真实只读诊断，随后“暂时只启用已验证的贴吧”收窄继续工作范围，不能沿用此前授权继续尝试知乎。不恢复通用机器自测或冒烟，不扩大为登录、Cookie 采集或写操作；完整功能仍按真实环境人工验收。

## 八、人工验收重点（实际状态见实施记录）

用独立数据、明确提供的普通兴趣和获准公开平台验证，不读取生产私聊或复制人格。质量由人评价，权限/计数/派生边界同时做源码审查。

| 场景 | 要看到的结果 |
|---|---|
| 只给兴趣和开放平台，不给搜索词 | Agent能自主找到相关且有新意的内容，说明为什么可能值得聊；不需要人逐条带路 |
| 连续几天的真实体验 | 有可延续的谈资，也允许没有新发现；不反复推荐同内容，不把沉默当拒绝 |
| 两个平台只开放一个 | 未开放平台的结果不读取/入池；不因内容缺少或接口失败转去另一平台 |
| 旧配置加载新增贴吧平台 | 旧开关、provider、自定及不限额度保留，B站保持停用；贴吧默认关闭，不静默授予第三方搜索 |
