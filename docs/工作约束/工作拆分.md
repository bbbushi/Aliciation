## 一、底层架构（A 线）

**在做什么**：把"上下文怎么组装、人格怎么推演、记忆怎么沉淀"从能跑，变成看得见、说得清、改得动。

**先看**：[设计思路.md](../设计思路.md) 第 2、4 节，`alice/retrieval.py:84` 的 `build_system_prompt`，跑一次 `python3 tests/pressure/demo.py`（看现在一次对话长什么样）。

| 编号 | 做什么 | 做完的样子 | 手感 |
|---|---|---|---|
| **A1** | 记录每轮上下文的分段开销：宪法 / 人格 / 长期 / 仓库索引 / 活跃 / 近期原文 | 任意一轮能出一张分段表，知道"每轮固定开销"是多少 | 两三天 |
| **A2** | 按 A1 的数据调组装顺序与裁剪，让稳定前缀真正吃到缓存 | 连续的轮次里不变段落一字不变，缓存命中占比有数 | 两三天 |
| **A3** | 校准记忆提取的提示词与"再提及"判定 | 抽 50 条看：不编、废话少、漏记少，同一段对话重跑结果稳定 | 一周左右 |
| **A4** | 量仓库索引的实际大小，看 recall 命中后模型到底有没有用上 | 索引不超过 1k token；召回了却被忽略的比例有数 | 两三天 |
| **A5** | 理顺人格演化的输入与留痕：changelog 能不能指回某条记忆 | 实验室 R1 ≥ 0.75、R2 ≤ 0.50 稳定两次；每条改动追得到出处 | 两三天 |
| **A6** | 成本归因：token 花在对话、提取、演化、评审各是多少 | 一张 ¥/天 的归因表，超了能看见 | 半天到一天 |
| **A7** | 技能注入对话（先放着）：什么时候该想起某个技能 | 注入后拟人度不降、成本增量可控 | 一周以上 |

**容易和别处搭界**：B 的探针要读记忆和人格的真值；C 要展示记忆和人格。接口没到位时先做，数字标"未测"。

## 二、测试验证（B 线）

**在做什么**：让"成长得好不好"变成能复现、能比较、能回头看的东西，而不是一份报告里的感觉。

**先看**：`tests/pressure/README.md`，[设计-监测仪v2.md](./harness研究/待动工模块/设计-监测仪v2.md)，跑一次 `python3 tests/pressure/demo.py`（零成本，能看到一份完整报告长什么样）。真机用 `launch.py`（浏览器里点开始、直接聊、点着记判定）或 `session.py`（终端逐轮回车）。

| 编号 | 做什么 | 做完的样子 | 手感 |
|---|---|---|---|
| **B1** | 每次实验留下元数据：commit、模型、价格表、参数、随机性来源 | 同一份代码跑两次，四个维度的差别在容差内；报告页眉自己写清这次是什么 | 两三天 |
| **B2** | 阈值标定：四个维度的线现在是拍的，用多次运行的分布定 | 一张阈值表，每项说清分布、分位点、怎么定的 | 两三天 |
| **B3** | 监测仪 v2 第一期：诚实度证据链（主张抽取→检索→裁定→警报） | 每条警报点开能看到"她说了什么、库里有什么"；抽 30 轮看裁定准不准；旧的三张绝对分卡下线 | 一周以上 |
| **B4** | 第二、三期：冻结底色做对照的漂移测量；用户盲评 | 样本太少只显示备注不画趋势；评审和人对得上才显示数字 | 一周以上 |
| **B5** | 横向对比：演化触发方式、模型档位、提示词版本 | 一个对照结论，一套能复用的报告模板 | 两三天 |
| **B6** | 把人工压测变成有部署、有留档、可复盘的流程；`tests/pressure/launch.py` 是浏览器启动器（点开始即部署、直接聊、点轮次记判定、出报告，改代码可重新部署） | 换一类压力只加一份 TOML 用例；每次真机跑完能直接看到最差级、无据让步率和测后新增记忆 | 两三天 |
| **B7** | 实验数据治理：归档规范、离线重分析、两次运行的指标并排看 | 任意两次运行能摆在一起比 | 半天到一天 |

**容易和别处搭界**：指标怎么算，以这边为准；A 改了组装，这边的基线要跟着重跑一次，数字才能从"未测"变成数。

## 三、产品功能（C 线）

**在做什么**：让它能被用、被看见——界面、记忆和人格的可见性、工具层，再往"信息生活"走。

**先看**：`alice/service.py` 的接口面，`web/app.js`，`tests/pressure/deploy.py` 里服务是怎么起的（复制副本、随机端口、走 HTTP）。

| 编号 | 做什么 | 做完的样子 | 手感 |
|---|---|---|---|
| **C1** | 界面信息架构：会话 / 记忆 / 人格 / 监测四块；手机上（393×852）走一遍 | 四个区都能到，本地首屏不卡，手机上点得着 | 两三天 |
| **C2** | 记忆可视化：三层时间轴 + 墓碑区，回答"这条为什么被忘了" | 界面上就能看到哪天过期、最后被用是什么时候，不用开命令行 | 两三天 |
| **C3** | 人格时间线：v0 到最新版的差异，底色和生长分色 | 任一历史版本能翻出来看，旁边配着当时的改动理由 | 两三天 |
| **C4** | 工具层：注册、描述、只读标记、超时与失败回传 | 加一个工具只改一个文件加一条注册；只读的工具干不出写的事 | 两三天 |
| **C5** | 信息获取（远期第一件）：只读接入 B 站 / 知乎，定向嘱托；抓来的东西走同一条记忆管道 | 抓来的内容在记忆里和聊出来的同构、能溯源；不打扰、不超速 | 一周以上 |
| **C6** | 社交观察（远期第二件）：只读群聊与评论流，观察变成谈资 | 代码里根本没有写接口；观察来的记忆带来源 | 一周以上 |
| **C7** | 主动行为与分寸：活动周期、三类触发、频率上限、安静时段、被忽略就降级 | 一周模拟里缺席型触发不超量；不该说话的时候一次 API 都不花 | 一周以上 |

**容易和别处搭界**：工具的注册长什么样，以这边为准，C5/C6 直接用；监测那块显示什么字段，听 B3 的，字段没定时先用假数据把界面搭出来。

## 四、信息收集（D 线）

**在做什么**：持续供给能用的参考，不是阅读量。

**先看**：`docs/harness研究/参考设计/通用设计理念.md`，`参考设计/论文导读/README.md`。

| 编号 | 做什么 | 做完的样子 | 手感 |
|---|---|---|---|
| **D1** | 按缺口补论文：记忆压缩与遗忘、人格的纵向一致性、评估方法、陪伴与拟人、工具使用、主动 agent | 每篇三行：能不能用、为什么、派给哪个编号 | 持续 |
| **D2** | 同类 harness 对标：已有的 pi / Claude Code / SWE-agent / OpenClaw / Cortico，再补记忆类项目 | 一张机制对比表，能说清"我们的三层哪里不一样、代价是什么" | 两三天 |
| **D3** | 插件市场扫一遍：Claude Code 插件、MCP servers、DSH / ZCode 生态 | 清单：能直接用的、要改的、得自己写的，各自挂到 C 的编号上 | 一天以内 |
| **D4** | 维护一张参考索引：主题 → 结论 → 编号 → 出处 | 下次查同一件事，半小时内能翻到，不重复读 | 持续 |
| **D5** | 术语对齐：诚实、遗忘、人格、分寸、在场 | 各份文档说的是同一件事 | 半天以内 |

**容易和别处搭界**：结论晚到不影响别人开工；但落不到编号的调研，基本等于没读。

## 五、几处交界

四条方向碰到一起的地方不多，就这几处：**指标口径、监测事件的字段、记忆管道的入口、工具注册的样子、参考索引的格式**。

不是规矩，只是提醒——动手改这几处之前，跟用得上的人说一声，省得两边各改各的。

还有一句经验：**改进不用等测量，写数字要等。** 改完可以先落地，自己确认行为对；要写"提升了 30%"，得先有能复现的尺子，没有就先写"未测"。
