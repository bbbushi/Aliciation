# 工作区约定

> 管边界与协作机制,不管工作内容(内容见 [工作拆分.md](./工作拆分.md),分工见 AGENTS.md)。
> 性质同工作拆分:是说明书不是制度,有分歧说一声就行。

## 一、四个工作区

| 工作区 | 目录 | 归属 | 内容 |
|---|---|---|---|
| **核心(harness 本体)** | `alice/`、`web/` | ZCode | 底层设计与默认界面;唯一被依赖的一层 |
| **测试工作区** | `tests/` | DSH | 面向人工测试的 SDK:剧本执行、部署、数据回收、记录辅助 |
| **附加功能区** | `addons/` | 按功能定 | 核心之外的附加物(QQ入口、桌宠等),只经 service 接口接入 |
| **资料存储区** | `docs/`、`tools/` | 共用 | 调研、观察、规范、出图脚本;零运行时耦合 |

## 二、依赖规则(全部指向核心,单向)

1. `alice/` 不 import 任何其他工作区;`web/` 只通过 HTTP/SSE 调 `server.py`,不 import `alice` 内部。
2. 测试区与 addons 区**只经公共面**使用核心,公共面现为:
   - `alice/service.py` 的 `ChatService(cfg, db_path, client)`(可注入假模型/临时库);
   - `alice/server.py` 的本地 HTTP API：聊天 SSE、状态、历史、设置、监测兼容查询及 `/api/chat/activity` 均要求本机 GUI 来源与意图校验；模型配置、关闭服务、P1及只读 `/api/observer/*` 同样为 GUI 专用。`/api/metrics` 不再产生检测仪数据；观察器公共方法为 `ChatService.observer_snapshot/observer_list/observer_detail`，忙时返回 busy，不触发检索使用或维护；
   - 2026-10-29 用户批准的 QQ 接入走 `/api/channels/v1/`（状态、提交、查询原请求、发送回执），使用单独凭据、固定所有者、会话身份与请求身份；仅用于本人私聊文字，不获得历史/管理/P1权限。Python `ChatService.send` 保留原阻塞用法；HTTP 历史保留原字段并增加消息 ID、来源和分页。协议与恢复约束见 [QQ实施与人工验收](../QQ接入-实施与人工验收.md)。旧人工SDK的匿名HTTP不能继续调用GUI入口，也不能伪造浏览器头绕过；其配置/数据路径与接口适配仍由DSH负责；
   - CLI 命令(`python -m alice …`)；人工 SDK/addons 不直接读内部 Store/SQL 活库，取证使用公共只读投影。

3. addons 需要核心**新增能力**时(如事件流入、动作流出),走架构侧(ZCode)评审落进核心,不在 addon 里绕洞。
4. 资料区无依赖;`tools/` 脚本可读仓库任何内容,但不被任何运行时代码引用。

## 三、数据与检出隔离

- `user/data/`(Alice 的记忆)与 `user/config.toml` 属于**所在检出**,整目录 `user/` 不入 git、不跨区共享;动过在 AGENTS.md「当前」记一句。
- 两棒同时在改代码时用 **git worktree** 各自检出(如 `../Aliciation-arch`、`../Aliciation-test`),各自分支,合回 main 走正常提交/合并——项目结构不因协作而拆分。
- worktree 的前提:当前未入库的改动先各自入库,否则新检出里没有这些文件。

## 四、协作约定

- 提交只暂存自己碰的路径(不用 `git add -A`);每棒收工更新 AGENTS.md「当前」(整节替换,≤5 行)。
- 测试策略:只保留真实环境人工测试(冒烟与机器自测已取消);`tests/growth/`、`tests/smoke*.py` 由 DSH 在测试工作区清理时移除,其余人不代删。
- 文档修订:涉及蓝图(迭代路线)的结论走其自身修订流程;观察与设计文档各自独立,新证据追加而非改写原文。
