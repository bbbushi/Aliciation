# GUI 功能三件：真实环境人工验收

日期：2026-10-29。以下步骤供项目所有者手工执行；开发期间**尚未执行**。不要对正在使用的 `D:\alice\data`、`config.toml` 或 8800 服务做故障操作。记录版本、模型与人工观察；不要把 API Key、完整配置或私人对话上传到报告。

## 准备隔离副本

在 PowerShell 中从 `D:\alice` 建新目录，只复制本期代码和示例配置，不复制 `data/`。目录名须不存在：

```powershell
$case = "D:\alice-gui-accept-$(Get-Date -Format yyyyMMdd-HHmmss)"
New-Item -ItemType Directory -Path $case | Out-Null
Copy-Item -LiteralPath D:\alice\alice -Destination $case -Recurse
Copy-Item -LiteralPath D:\alice\web -Destination $case -Recurse
Copy-Item -LiteralPath D:\alice\config.example.toml -Destination (Join-Path $case 'config.toml')
```

在副本的 `config.toml` 把空 `api_key` 填为非空占位值以便服务启动；请勿复制主会话数据。副本使用原工作区的虚拟环境解释器，运行前确认 8899 未被其他进程占用：

```powershell
Set-Location $case
& D:\alice\.venv\Scripts\python.exe -m alice serve --port 8899 --no-open
```

另开浏览器访问 `http://127.0.0.1:8899`，在设置中填入专用测试 Key；以下点击“测试候选连接”“验证并保存”、生成底色和发送消息都会向真实供应商发起请求，可能产生费用。建议使用可撤销的测试 Key。副本配置也含 Key，始终留在本机并妥善处理。

## 逐项记录

### A. 关闭服务

1. 先完成一轮真实对话，再在设置中点“关闭 Alice 服务…”，选择取消。确认页面仍可继续聊天，8899 仍监听。
2. 再点关闭并确认。确认页面先显示等待、最后明确显示成功或失败；成功后用 `Get-NetTCPConnection -LocalPort 8899 -State Listen -ErrorAction SilentlyContinue` 和任务管理器确认该副本服务进程无残留。关标签页本身不应结束仍在运行的服务。退出页重启命令应包含副本项目目录、本次解释器（此处为 `D:\alice\.venv\Scripts\python.exe`）、配置绝对路径和 8899 端口；若以自定义 `--config` 启动，按页面命令重启后仍应使用该文件。
3. 重启副本，检查历史回复、人格和记忆；重复试验时在一个标签发起较长真实回复，另一个标签确认关闭。应等当前轮完整结束，关闭后的新 API 请求明确拒绝，最后不留进程。
4. 可再做断开 SSE 的人工场景：回复期间关掉聊天标签，在另一标签关闭服务；核对原轮最终结果已落盘，不因网络写回失败额外发起同一轮模型调用。
5. 若可在隔离副本用可撤销测试 Key 安全制造退出前提取失败，记录“服务已关闭但整理未完成”提示，确认原始对话仍在；不要在主会话断网或撤销主 Key。
6. 在副本服务运行时再尝试同端口启动一次，确认第二个进程因端口占用直接退出，不先修改副本的会话数据或发起维护模型调用。

### B. 移除检测仪并保留思考深度

1. 欢迎页、聊天页和设置里检查：没有“监测”按钮、侧栏、token 曲线、人格偏移/诚实度/人机感卡片或添加入口。
2. 在未到记忆提取/人格演化阈值的隔离会话发一轮简单真实消息；从供应商用量或请求记录核对没有评审型廉价模型调用。工具、提取和其他正常后台调用须按用途单独识别，不能误当评审。
3. 设置思考深度为 off、on，各发一轮并人工观察请求/回复；刷新页面和重启副本后，设置值仍正确且可继续切换。

### C. 模型配置立即生效

1. 在副本 `config.toml` 的非 `[llm]` 区域加独特注释和未知字段，`[llm]` 现有配置项旁也加注释。打开设置确认供应商、URL、两模型可见，Key 只显示“已配置/来源”，没有原文或尾号。保留密钥模式下输入框禁用；选择替换后才能输入。
2. 以有效测试 Key 选择预设或自定义并点击“测试候选连接”。核对其两个模型的普通非流式探测结果；返回主对话发消息，确认测试动作本身没有切换生产配置。随后“验证并保存”，不重启即发新轮，核对其使用新模型/接口。
3. 输入错误 Key 分别点击测试和保存，应得到可理解的令牌错误；旧的有效配置仍能聊天，磁盘配置也未被错误 Key 覆盖。不要把供应商原始错误、完整 URL 查询或 Key 写入验收记录。
4. 人工令一轮回复保持在途时，在另一标签保存另一组有效配置；核对在途轮完整使用旧客户端/模型，随后轮使用新配置。注意保存本身会做候选探测，探测请求不属于生产轮。
5. 保存后人工查看副本 TOML：非目标字段、未知字段、注释均保留，特殊字符 Key 仍可被正常读取。设置打开后从编辑器修改副本文件，再点保存，应提示冲突并保留编辑器改动。用只读/权限受限副本尝试写入失败，核对旧配置仍有效、无残留临时文件。
