## 2. 审查耗时与用量优化

### 2.1 现状与实际代价

已实现的生产审查包括：显式带引文改写的角色/条件核对、非空记忆候选的全字段准入、前情生成后的来源审查，以及用户明确概括前情时的回答核对。审查缺项或异常时保留原句/原文，或不写入候选，不反复请求直到模型给出“通过”。

| 真人样本 | 场景 | 全轮耗时 | 额外调用/用量 |
| --- | --- | --- | --- |
| T14 | 显式改写及角色核对 | 4.840秒 | 一次回答审查，usage 480/259 |
| T16 第二次请求 | 已有前情卡复用，尚无回答核对 | 2.465秒 | 前情生成调用0 |
| T17 | 新跨度摘录生成及审查 | 26.758秒 | 两次前情调用，usage 1556/3800 |
| T18 | 已有前情卡复用，加回答核对 | 26.209秒 | 一次回答审查，usage 1009/3955 |

usage 两个数分别为已记录的 prompt/completion token 数；耗时是全轮耗时，不是首字延迟。各轮材料和请求不同，这不是严格 A/B 对照。现有记录不足以把26秒精确拆成主回答、审查、供应商排队和传输等部分；completion 也不能直接等同于可见正文或断言全部是思考 token。

### 2.2 具体缺口

1. 各调用已有用途和部分 usage，但缺少统一的逐调用开始/结束、耗时与失败阶段记录。
2. 通用 `llm.chat` 中，现有思考模式控制位于提供 tools 的分支。生产 JSON 审查不提供 tools，不能假定它已受同一开关控制；需要核对当前供应商实际支持的参数。
3. 审查模型、思考/输出配置与角色判断任务尚未分别优化。
4. 缺少同一验收语义下的可比较成本基线，不能仅根据单个慢样本就替换模型或删除审查。

### 2.3 建议施工内容

**第一步：补可归因的观测。** 给模型调用记录统一用途，例如主回答、提取、提取审查、前情摘录、前情审查、改写审查、前情回答审查。记录耗时、调用次数、实际 usage、成功/失败、是否回退、策略和模型指纹。默认不另存完整聊天 prompt；供应商未返回的数据记未知，不记零。

**第二步：做独立的审查调用配置。** 在核实实际接口后，为审查单独选择合适的推理与输出设置；保留严格 JSON、有限理由、一次调用、预算检查及失败保护。配置必须允许恢复现行行为，不把审查设置悄悄扩散至主聊天和人格演化。参数支持未核实前不写死供应商专有字段。

**第三步：减少不必要工作。** 已有卡片复用不重生成；空候选不发准入审查；继续保持只有明确任务才触发回答核对。先优化任务规模和模型设置，再评估是否需要审查缓存。缓存若引入，必须绑定完整请求、候选、规则、模型和实际来源版本/渠道/代际；相似文本不等于相同条件，缓存不是绕过撤回检查的理由。

### 2.4 不应采取的捷径

不能先流出未经检查的草稿再事后纠正；不能因为“查过一次”就跳过新版本来源核对；也不以删掉角色/条件审查换取表面速度。已有结构校验可直接拒绝格式错误，但不能仅凭关键词替代语义判断。

### 2.5 验收与收益

用真实使用中的同类任务比较分调用记录、总耗时和正确性，观察中位数与较慢样本，而非单轮快就宣布优化成功。主回答与审查都要可解释；失败仍按既有保护返回；不得多派工、重发副作用请求或漏掉计费尝试。尚未建立基线前，不承诺“降到几秒”。

涉及：[grounding.py](../../../alice/grounding.py)、[llm.py](../../../alice/llm.py)、[loop.py](../../../alice/loop.py)、[extraction.py](../../../alice/extraction.py)、[context_recap.py](../../../alice/context_recap.py)。估计复杂度：先补观测较小，接口/模型调优中等；这不是工期估算。

## 3. 人格 P1b：近位表达提醒

### 3.1 已有基础与缺失部分

P1a 已经按请求固定人格快照、渲染风格/情境/样本，并标注样本不是记忆。普通演化不能覆盖用户选定的表达偏好。P1b 是额外的短提醒，目的在长上下文、工具交互和正式任务之后提高表达参考的可用性；目前没有 `expression_anchor` 配置和对应的近位装配机制。

它解决的是参考是否容易被当前生成使用，不替代导入真实性审查，不要求 Alice 每轮宣布人格、堆口癖或表现捐赠人的私人生活。长期表达偏好本来就应持续保留；即使未来关闭额外提醒，也不能一并关闭用户选定的习惯。

### 3.2 拟交付内容

按原设计提供默认关闭的 `[persona] expression_anchor`。开启时，从本请求同一份人格快照中选择精简气质、关键边界和一条完整表达样本，初始工程预算约500中文字符，记录人格版本/选中样本/长度/开关状态。

模型再次请求（含工具回执后）时重建或替换这一段，保持一份，不越调用越多。用户改过表达后，后续请求必须使用新版本，不恢复旧语气。提醒本身不授予工具许可，样本内容继续作为引用资料，任意捐赠原文不能提升为宿主指令。

### 3.3 依赖与取舍

原设计要求先确认 P0 导入质量，再比较近位提醒。P0 安装链和人工定点修订有证据，但新增成品前提审查仍有未验部分，不能写成“整个 P0 已全过”。可以先完成 P1b 代码并保持关闭；效果比较前回收相关导入质量证据，不把重新清库或重装人格当默认步骤。

首版使用固定选择顺序，不新增每轮情绪分类或风格打分模型调用，不先建复杂语义检索器。表达任务已经变正式时，允许克制玩笑；离开办事场景后自然回到日常习惯，不追求每条文字都像同一种台词。

### 3.4 真人验收

在同一人格版本下比较开关前后：长对话、一次正式改写、几轮工具交互、澄清失实自述后回到日常话题。分别看表达自然度、任务条件保留、虚构经历以及提醒是否重复堆积。若只增加口癖或降低任务清晰度，保持关闭；不能把导入修订和提醒同时启用后的全部改善归给提醒。

长期稳定性作为日常观察，不阻塞代码建设，也不要求用户逐轮为口吻打分。依据：[人格设计第6.2节](人格连续性与表达稳定-架构优化设计-v1.md)。估计复杂度：小至中，效果不确定性高于接线难度。

## 4. 人格气质与情境微调：候选审议

### 4.1 不能与现有 P2 混称完成

现有普通演化只接受“生长 · 自我叙事”和“生长 · 与用户的关系”两节补丁，并核对旧内容摘要与版本化证据。GUI 的“编辑说话习惯”是用户显式修改风格、情境、样本的入口。这两条路径都不能代表“模型提出其他气质微调建议”的审议流程已实现。

例如，经多次实际对话后，Alice 可以建议在用户做技术任务时减少玩笑；这不等于可以因“最近都在办事”永久删除用户喜欢的日常表达，也不能据一次短回复推断用户讨厌整个性格。

### 4.2 拟补齐的机制

候选应包含：候选ID、目标条目、旧版本、建议新内容、理由、实际证据ID/版本、可能影响及是否触及用户选定偏好。状态至少区分待审、已应用、拒绝和因版本变化失效，不能只写一份新的完整人格文件。

宿主审议应检查证据确实存在、可进入人格、非压力来源、未被撤回，以及修改是否落在允许范围。保留原证据而不让模型通过删掉引用摆脱约束；候选完成时若用户已经修改人格，旧候选失效。

必须先分清“用户选定表达”和“其他可演化气质”的边界，再决定后者可自动应用的白名单。边界尚不清楚的首版可先只保留候选。修改用户选定表达仍走明确修订；表达样本不从最近回复自动采纳，避免把一次错误自述训练成长期习惯。原设计要求初期新增/替换样本经人工确认，并保留真实对话或适配生成标记。

### 4.3 审计、恢复与失败行为

每次应用记录旧新条目、理由、实际证据版本及所采用规则。候选提交失败保留旧人格；中断恢复不能重跑模型或覆盖后来的人类编辑；证据失效时停止采用相应派生内容。可复用现有 P2 快照、摘要比对与依据投影，但需明确新候选格式和字段权限，不能直接放宽现有两节白名单。

### 4.4 真人验收

用真实反复形成的相处习惯产生候选，验证建议可见、不会自动覆盖固定表达；再观察用户明确修订、证据失效、旧版本候选到达和压力事件的处理。先做少量有明确成败条件的样本，不用主观“像不像”替代写入权限检查。

依据：[人格设计第7节](人格连续性与表达稳定-架构优化设计-v1.md)、[persona_growth.py](../../../alice/persona_growth.py)。估计复杂度：中，主要难点是审议边界与证据生命周期。

## 5. 网络 N09：从知道线索到定向重读

### 5.1 为什么需要

既有网络链能按关键词检索和读取，但真实验收曾命中相关列表而非用户指定的单条目。即使工具上限收尾正确，也不能说读到了目标页。N09 的目标是：知道某条历史来源的名称/URL时，能在当前许可下准确重读目标，而非每次重新搜索近似关键词。

C1 普通记忆引用和 history_load 不是网络读取工具；前情里的本地ID或 URL也不证明已经重新读取。C3 只为这类适配留了方向，尚无完整 N09 操作、权限、定位、预算和迁移契约。

### 5.2 拟分成两层

**线索层：** 必要时保留有来源身份的名称/URL、历史版本及范围说明，让 Alice 能发现可申请重读的线索。正文因普通遗忘/容量移除，不意味着它必须永久保留；用户明确删除或撤回时，线索自身也应服从对应策略，不能另外藏一份“永久索引”。

**读取层：** 模型提议目标，宿主校验当前平台/渠道/用途/期限和网络许可，定位真实页面，再进入现有受控读取链。只有成功回执才能说本轮读过。过去有过许可不等于今天仍可读，有 URL不等于可访问所有跳转或本机路径。

### 5.3 必须完成的契约

- 目标引用怎样生成、绑定哪条来源、是否随请求失效，避免用任意字符串当读取权限。
- 如何确认读的是指定回答/文章/条目，而不是同站列表、登录页或另一项内容。
- 复用当前共享额度、读取预算、取消与尝试账本，不通过“定向”另开免费通道。
- 同 URL内容变化、范围变化、旧版本失效如何记录；新读取不能无条件继承旧正文的事实资格。
- 找不到、被拒、需登录、返回范围不全时如实失败；若另行搜索替代目标，应明确说是候选，不冒充原目标命中。
- 进入前情/记忆/观点后的派生内容继续绑定实际来源版本和受众，不能自动恢复已遗忘的观点或扩大 QQ 权限。

### 5.4 实施与验收建议

先选择一个当前已有且已授权的平台与内容类型完成整条路径，再逐类接入其他平台。首版先做到“正确定位、正确回执、沿用预算和来源链”，不同时扩展任意 URL抓取器。

真人验证已知目标准确命中、同名/相关列表不混淆、权限撤回、内容变更、读取失败/额度不足和跨渠道限制。不能以“工具返回了东西”判整项通过。

依据：[上下文设计第3.2与11节](模型参与上下文组装-架构优化设计-v1.md)、[网络验收记录](../网络层/网络接入与见闻成长-人工验收记录-20261102.md)。估计复杂度：中至大，定位适配和来源生命周期比增加工具名称更重要。

## 6. worker P2：协作报告的来源契约与上下文适配

本节的“P2”属于协作者调度，不是第4节的人格 P2。

### 6.1 已有什么、还缺什么

已有 DSH/Claude 任务能力，以及受限的任务引用、公开消息读取、GUI 单次无工具总结和依赖机制。它们不等于 worker 报告、产物正文能像普通记忆一样在所有上下文中流转。

完整 P2 来源契约仍待设计：任务报告如何成为可校验的材料，怎样进入模型、记忆、历史和其他渠道，撤回怎样传播。协作正文适配应归入这份契约，避免在 C3 里另做一套兼容标准。`worker_artifacts.py` 等保留模块也不能凭文件存在就称已接线；文件ID导入、产物下载和跨任务来源转发不能在没有实际契约时宣称已开放。

### 6.2 拟议材料身份

任务材料至少需要 task/artifact/evidence 标识、版本、会话代际、渠道、用途、保留许可、必要来源依赖和宿主取得方式。区分宿主执行事实（状态、时间、实际文件收取）与 worker 的内容主张（结论、分析、声称引用的资料）。

worker 自报 URL与引文不能相互自证，任务材料不能伪造成网页包。需要联网核实的内容走宿主认可的读取路径，或先形成可信的证据接口；同源重抓不是独立佐证。可以允许有清楚标签的分析建议，不能因此把建议直接升级为正式见闻或用户认可。

### 6.3 传播与撤回是主要工程量

正文暴露前登记实际依赖；模型说“我没用这段”不能解除本轮依赖。回答、历史再展开、回忆、提取、思辨、人格/技能维护、观察器和 QQ 取用要按同一来源范围处理。默认 GUI 限定不能因“总结过一次”变成全渠道可用。

明确撤回、输入许可取消和必要证据失效，应传播到派生内容。任务归档、普通文件清理、停止执行和撤销正文许可要分开，不能互相代替；无法确认停止也不能写成已停止。工作目录读取许可与操作系统沙箱也不是一回事。

### 6.4 建议施工顺序

1. 明确任务材料/报告/产物与网页材料的共同字段和差异，冻结最小来源契约。
2. 只做一个 GUI 任务的一种有界材料读取与分析，保留状态/未知费用等诚实语义。
3. 接入派生依赖与撤回，再讨论记忆准入；跨任务转发、下载和 QQ 扩展各自独立验收。
4. 最后将获准材料映射到统一目录/按需展开，不能反过来先给一个“万能上下文ID”再补权限。

N09 与本项可以共享来源/版本/范围原则，但不要求相互等待全部实现，也不能把两类材料强行合成网页格式。

### 6.5 真人验收

任务材料含恶意指令时不改变权限；混合多个来源后派生依赖完整；生成期间撤回后不发布；GUI 材料不能泄漏到 QQ；整理/重启不重发旧任务、不退还已用额度或复活过期许可。结果状态正常不代表报告正确，生成一个文件也不代表文件已收取或内容已核实。

依据：[协作者开发方案第9.2节](../Agent协作者调度/协作者调度-开发方案-v1.md)、[来源契约评审](../Agent协作者调度/协作者调度-架构评审-2026-11-01.md)。估计复杂度：大，涉及多个消费路径。

## 7. 已写但未验：需要保留的验收债务

这部分主要是补证据，不应统称“功能没做”，也不要求现在重新跑完整套测试。

| 模块 | 已有证据 | 仍待回收的关键边界 |
| --- | --- | --- |
| P0 导入 | 安装链、原始样本回收、定点修订 | 新增成品前提审查的代表性真实样本；失败与恢复，不能靠人工修订冒充自动审查通过 |
| P2 表达编辑 | 三节正常显示、取消未保存 | 真正保存、旧版本冲突、会话切换、快照和恢复；不覆盖关系/观点/聊天 |
| P2 人格演化 | 分节、白名单、依据版本和恢复代码已写 | 实际演化、依据失效投影、中断后恢复、后来用户编辑不被覆盖 |
| C1 目录/读取 | 定向搜索展开、先验来源辨别 | 自主判断是否读取、超预算、正文版本变化、渠道隔离、异常发布 |
| C2 工作集 | 保留→跨轮注入→释放→下轮空集 | TTL耗尽、容量、重复保留不续期、跨渠道、重启清空及撤回；早期部分返回码审计不足 |
| C3 旧原文 | 查到原文、失效旧ref拒绝 | 翻页、极限预算、资格变更、提供商兼容及长期历史规模 |
| 前情/回答审查 | 摘录生成、审查、复用、当前定位、#1/#13范围对照 | 错误候选拒绝、审查失败、复杂条件、流式异常、来源在I/O期间失效 |
| 提取准入 | 真实候选审查/入库审计；改写样本未再产生假约定 | 真正错误候选被拒、审查失败不推进游标、格式错误审计、原子写入中断 |

前情曾出现过真实的 `review_rejected`，因此不能说完全没有拒绝路径证据；它不替代记忆提取准入自身的拒绝验收。不同模块的拒绝是不同路径。

按新改动涉及的部分回收少量真人样本；不为达到提取阈值而补无意义消息。正常收尾提取确会新增记忆，需先备份并核对最终提交；出现错误保留原文及审计，可候审而不伪造通过。长期人格稳定性继续自然观察，不阻塞未施工模块推进。

## 8. 建议实施顺序与每段的完成条件

| 顺序 | 工作包 | 具体交付 | 可结束该段的条件 |
| --- | --- | --- | --- |
| 0 | 发布范围和证据收口 | 核对实际PR差异、已提交/未提交和未验项 | PR正文对应真实范围，未把未验写成完成 |
| 1 | 性能观测 | 分调用耗时/usage/结果/回退记录 | 能解释一轮等待由哪些阶段组成，未知不冒充零 |
| 2 | 审查开销优化 | 经接口核实的配置、小规模真实比较和恢复开关 | 正确性保护保留、成本变化有同类样本支撑 |
| 3 | P1b 默认关闭接线 | 同快照、单份提醒、预算/元数据/开关 | 编译及接线完整；效果独立人验，未有效则保持关闭 |
| 4 | 气质候选审议 | 类型边界、候选状态、证据/版本/审计 | 不越权修改固定表达，陈旧候选不覆盖新编辑 |
| 5 | N09 最小定向重读 | 一个已有平台/类型的定位→读取→来源回执 | 真正读到目标，额度/许可/失败路径有证据 |
| 6 | worker P2 最小来源链 | 一种GUI任务材料、依赖传播、撤回及受限分析 | 各消费路径保持范围，先过撤回/渠道边界再扩展 |

这是建议顺序，不是新的硬依赖清单。P1b与气质候选可先做默认关闭的施工；N09和worker契约可以先统一必要字段。不能用“等长期稳定性证明”冻结所有后续开发，也不应把多个新机制同时打开后无法归因地验收。

不要在本报告中换算为“还剩几条消息”或“几天完工”：代码施工、真实故障样本和长期使用证据是不同工作量。每个工作包分别给出范围与验收脚本，集中测试只覆盖该包，不无限追加同题。

## 9. 项目相关遗留项与发布边界

以下与本报告主题有关，但不是本批已承诺完成的五项施工。

### 9.1 Claude 直调与完整 PR

现行约定已经允许 Claude 直调与其他改动一样，经验收/共存检查后通过 PR 合入 `main`；不因包含 Claude 而强制拆分，`main`仍禁止直接推送。政策放开不代表真实权限质询、跨CLI能力和所有异常边界已验。

当前工作树仍有未提交的Claude/worker修复、部分UI和资料重排。PR只包含已提交内容；编写完整 `ytq → main` PR必须核对实际差异，不能只看最新一次35文件打包。是否补齐未提交修复、分批提交或拆成审阅单元，应按真实依赖决定，不能把它们自动夹入新的人格功能提交。

### 9.2 名册发现

[本机 agent 盘点 v1.1](../Agent协作者调度/名册发现-本机agent盘点设计-v1.md)仍为设计，尚未静态发现/选定探测/GUI报告接线。发现、执行探测、adapter核验、注册、启用必须分别记录；候选不等于可用工人，报告读取不自动推进注册或授权。其旧头部仍写“不合main”，已落后于新的AGENTS规则，应在实施时同步有效约束，不能照旧头部恢复已撤销的分支限制。

### 9.3 其他独立验收与文档债务

网络运输/额度/恢复的剩余固定边界，GUI/QQ共存、知乎候选等既有待验项继续保留；本轮人格验收不能替代它们。分屏浮窗、头像/动画和蓝图实验室维度也未因本批测试自动验收。

部分记录因目录重排已经迁移，AGENTS历史条目仍引用旧路径；引用修订与当前状态索引需要单独整理，不将历史失败或旧设计文本全部改写成今天通过。报告提供当前入口，不反复追加过长的常驻交接。

## 10. 推进时保持的约束

- 核心仍用标准库，GUI保持原生JS，不引入框架/构建链来完成上述机制。
- 本机 `user/`配置、记忆和人格不入代码提交；涉及真实数据时先备份、记录差异，避免双实例写库。
- 能力变化同步宪法存在事实；候选、索引、已读正文、模型理解、当前授权分别记录。
- 静态检查不等于真人验收，模型审查也不等于事实认证。沿用仅真实环境人工测试的策略，不重建机器自测或自动评分验收。
- 来源撤回和渠道限制从目录、展开、生成到发布都有效；不因为资料被移出下一轮装配就解除本轮已暴露依赖。
- 原始人格是表达与成长材料。任何优化都不能以风格为理由认领捐赠人经历，也不能以真实性为由自动抹掉用户选定的整套说话习惯。
