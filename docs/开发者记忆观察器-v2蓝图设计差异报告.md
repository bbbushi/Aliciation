## 3. 源码可证明的边界

- `alice/retrieval.py:120` 的 `tool_recall` 对命中调用 `bump_use`；`alice/store.py:226` 写使用次数/时间，`alice/consolidation.py` 用提及+使用判断存活，`memory_score` 用其淘汰排序。评审调用 recall 会改变被测对象，禁止复用其副作用入口。`Store.search_memories` 是纯读，但未命中可能只是中文词面匹配/范围/top-k 漏检。
- `alice/store.py` 的 turns.id 是**当前数据库内**稳定消息 ID，不能说完全没有 ID；`ChatService.history` 未暴露它，服务重置新库可复用数字。没有永久会话 UUID、轮次组合、工具/系统输入、生成参数或 evidence revision；观察器 scope 只在进程内，不可复用为跨重启引用。
- `persona.seed_from_tags/install_persona/evolve` 仅覆盖旧人格时保存旧全文；`thought.deliberate` 可直接改正文。v0.3 导入写包装正文后 `_digest_persona` 再改写并插入收养观点；历史首文件可能已含许多变化。人格版本计数不等于内容版本；没有可靠冻结底色就应显示“未建立参照”。
- `loop.chat_turn` 在保存助手消息后执行提取，`service.send` 再执行演化/思辨/技能；在 done 后检索当前库可能找回本轮回复刚生成的记忆，形成自证循环。P1必须区分回复前已存在的证据与事后新证据，不能仅用 created_at 排除（提取时间字段来自批末消息）。
- `loop.chat_turn` 只返 reply，工具转录/实际上下文临时存在；可选 usage_out 未被 service.send 使用。旧 turn_metrics 不是完整用量账，也不是v2裁定历史。`alice/metrics.py`虽还含旧judge_turn函数，当前send未调用；不能因文件存在就称监测仍启用。
- `expire_memory` 删除正文留墓碑；把证据引文、模型理由或对照全文永久复制到新评审表，会绕过遗忘。引用型方案需要失效处理，不能同时承诺“永远完整回放”和“正文真实删除”。现有对话/人格保留政策不因此自动改变。
- 原锁贯穿回复与watcher；把额外网络评审塞入send会拖延SSE done，释放锁后直接共享Store/热更新client又会破坏所有权。后台执行、取消、退出排空与配置代次必须先定契约。观察器继续沿原锁非阻塞读取。

## 4. 指标解释与人工校准的调整

P1三类锚点（合成说明，非用户数据，假设给定候选集非空且完整可复核）：证据“我一般23点睡”与主张“你说通常23点睡”可判支持；候选证据只含“喜欢茶”与主张“你每晚23点睡”判该候选集未支持；证据明确“我现在不喝咖啡”与同时间范围主张“你现在每天喝咖啡”才可判相悖。真实检索零命中统一为 `evidence_insufficient`，不当U或负分，不进入S/(S+U+C)。跨时间、对象含混或证据集合自相矛盾先标待人工核对；执行失败/正文过期不是第三类或负分。模型解释必须指向具体span，指向不在候选证据中的内容直接判运行结果无效。聚合同时披露无证据/无效样本数及排除导致的选择偏差。

抽取覆盖率与裁定准确率分开校准：人手标出完整回复中的应核查主张，核对模型漏抽/错抽；再由不看模型标签的人判检索证据关系，记录分歧和复核。若规则门控，额外抽查被跳过的回复，不能只在命中的容易样本上估计质量。20–30条仅作为试标起点；验收集不混入rubric锚点，按会话/回复分组，避免同一轮多条相关主张冒充独立样本。

模型结果与人工标签保留各自来源，人工纠正不覆写原结构化类别、引用和有限理由码（自由生成理由不持久保存）；指标注明使用哪一版结果。模型/rubric/检索器/参照变更、校准案例失效或范围缩减使相应校准过期，停止当前数字展示到重新核验；旧数字仅可标历史且不可复核。即使一致率超过75%，也不证明“诚实”“人格成长”或“关系质量”的测量效度；还须核对漏检、逐类错误、样本分布和稳定性。

P2/P3须披露样本数、独立回复数、时间范围、对照构造、随机顺序、评委身份类别、平局/无法判断/顺序敏感数、排除规则及不确定性。单用户、主动选择样本只能解释为该用户在该任务的偏好；不能称 Arena 排名或图灵测试通过率，也不能把刻意较差参考形成的胜率包装成进步。

## 5. 文献核查的使用限度

本地参考中的“权威方法全都不用单轮评分”“成对普遍显著优于绝对”“盲评是唯一金标准”均不作为本设计事实前提。采用文献中的具体方法建议，不把摘要结论直接外推到 Alice 的中文长期陪伴数据。75%、20–30条和成本倍数均为原草案提议，不是论文给出的通用门槛。

本轮独立核查了一手文献，以下是对**引用用途**的修正，不改写本地参考的历史原文：

| 引用 | 核查结果 / 本项目可采用的内容 |
|---|---|
| [MT-Bench §4.2、§5](https://arxiv.org/html/2306.05685v4) | 文中同时研究single与pairwise；首轮无平局设置表5两者与人工一致率均为85%，后续还因可扩展/简单采用single。不能据此宣称成对在任何任务都更好；保留其偏差检查建议 |
| [Prometheus](https://arxiv.org/html/2310.08491v2) | 使用rubric/参考材料的1–5分评价本身就是绝对评分。它支持明确标准与材料，不证明“加入三例就可靠”；不恢复v1是项目基于缺乏证据/校准的决定，而非论文禁止所有绝对分 |
| [SimpleQA §2.4、§4](https://arxiv.org/html/2411.04368v1) | 作者未正式研究grader性能，人工检查三类各100条发现2处分歧；calibration章节主要是被评模型置信度与准确度。不能用它为75%上线线背书 |
| [HaluEval §3.2.1](https://arxiv.org/html/2305.11747v3) | 主要相关实验是单回答是否含幻觉的二分类；本项目三分类为自己的设计，须独立验证，不把文献名称当有效性证明 |
| [2024图灵测试](https://arxiv.org/abs/2405.08007)、[2025图灵测试](https://arxiv.org/abs/2503.23674) | 2024为二人交互协议，摘要GPT-4被判人类54%、真人67%；不是本地参考写的三人局或表现相同。2025的三方协议和persona条件也不能证明Alice的长期关系质量 |
| [PersonaChat 原文](https://aclanthology.org/P18-1205.pdf) | 本地参考所链1801.07249是其他领域论文；PersonaChat为1801.07243。原文下一话语预测F1不能直接改称“回复与人格事实重合的persona F1” |
| [位置偏差研究](https://aclanthology.org/2025.ijcnlp-long.18/) | 交换顺序是偏差检查/缓解，不保证两次之后正确；同一案例两次评审不是两个独立样本 |

20–30条一致率的区间会很宽；多个主张来自同一回复又存在相关性。报告区间时应说明独立性假设与分组方法，可参考[NIST 二项比例区间说明](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。本轮没有Alice标注数据，不生成任何一致率或实际置信区间。

不是所有参考目录论文都已逐页核验；未核验文献只保留为线索，不承担本次准入或效度结论。
