# QQ 接入：实施与人工验收

2026-10-29；基线 `trial/windows-v0.2-20261028 / ac4d392367c47bf8d357c4b1973923f3d3183373`。用户已明确批准[方案](QQ接入-方案与审核.md)并授权开工，随后选择官方扫码接入。本文记录本轮实现；既有观察器、P1及其他未提交工作继续保留，不将它们列作本轮成果。

## 给使用者的说明

QQ现在作为同一位所有者的另一个入口来设计：它与网页共用对话、记忆和人格。第一版只接本人私聊文字，不回应群聊和陌生人，不主动发消息；图片、语音、文件和结构化引用会明确提示不支持。模型、人格、记忆重置、P1费用许可仍在本地网页管理。

首次连接以扫码为首选。使用腾讯官方组件取得机器人凭据，凭据只写本机；它不是个人QQ号自动登录。扫码组件公开提供第三方调用说明，但许可标记仍为UNLICENSED，因此仅引用官方包，不复制或打包分发源码。依据见[调研补充](QQ接入-参考项目调研.md#10-开工后补充扫码组件的使用说明2026-10-29)。

**代码、配置示例与操作说明不等于真实接入已完成。** 本轮未操作真实QQ账号、未发消息、未调用模型、未启停现有Alice、未读写真实 `user/`。真实扫码和下面的人工验收尚待用户执行。服务仍仅绑定回环，QQ桥主动连接官方平台，无需公网端口。

## 实现边界

- 核心新增 `alice/channels.py`：专用令牌、固定所有者、持久请求身份、会话代际、状态查询、发送回执和关闭排空。QQ桥只调用公开HTTP，不访问记忆库或模型密钥。
- `store.py/loop.py/service.py` 将用户/助手原文与对应请求分阶段原子关联。重复事件使用已有结果；进程重启后的未完成生成标为中断，不自动再次调用模型。工具或记忆副作用不回滚。
- GUI与QQ共用一个处理槽，忙时网页保留输入；QQ桥有界等待。重置、人格变更、模型配置发布与处理槽互斥，避免旧任务落入新会话。现有P1绑定保留，QQ不传evaluation_id。
- 本地网页增加QQ来源/发送状态、按消息ID合并历史、可见页刷新。P1本页许可在请求明确接受后才消费，忙拒绝不会丢失许可。
- 发送完成、平台确认、发送结果未知是不同状态。只发送最终正文，不发送模型思考、检索或维护详情。不承诺平台送达/已读，也不承诺模型供应商收费恰好一次。
- 目前平台文档的5分钟/60分钟被动窗口有冲突，按5分钟保守截止；过期回复留本地，不自动转为主动消息。

## 公共接口与兼容

### 网页连接入口（后续用户授权）

用户随后要求把接入放到网页，已追加欢迎页/顶栏的“连接QQ”入口与设置中的连接卡片。用户点击后在页面扫码、确认本人，再单独开始聊天；页面可查看状态、取消扫码及停止本页面管理的连接。打开设置本身不发起平台授权或模型调用。更新代码后需重新启动Alice以加载新增后端，后续网页启用连接不需要复制配置或为此再次重启。

同源GUI管理端点为 `/api/connectors/qq`，使用独立意图头、严格字段和当前操作身份；只允许固定扫码/配对/确认/启动/取消/停止动作。核心标准库宿主仅启动固定的公开连接器命令，通过有界JSON行通信，不导入addon代码，不接受用户指定程序、参数路径或网络目标。QQ平台SDK与扫码实现仍在addon，聊天继续使用原渠道API。

二维码在页面本地绘制，不调用外部二维码图片服务，不向网页提供AppSecret或机器令牌。待确认凭据只存短期内存；保存身份与开启聊天分开。可信子进程提供固定身份和令牌摘要，核心在当前会话与配置版本有效时保留其他配置并发布渠道设置。网页不会自动安装依赖、覆盖原连接、自动开机登录或接管终端启动的桥。关闭Alice会收尾本服务管理的连接器进程，已落盘但无法确认的发送仍按unknown恢复。

新增人工验收项（均待执行）：首次页面扫码/过期/取消；无身份时配对；确认后仍未开聊；使用已有连接；多标签页过期确认；实际端口与默认8800不同；缺Node或依赖提示；终端已有实例拒绝；停止/服务关闭/网络半开；保存连接不改变模型与其他配置；页面不出现密钥或授权链接。

### 聊天渠道

机器接口位于 `/api/channels/v1/`，要求专用Bearer凭据、回环Host、JSON，拒绝浏览器Origin/Fetch-Site/GUI意图头，不允许任意目标或管理字段。POST请求上限16KiB，文本上限12000 UTF-8字节。

| 接口 | 用途 |
|---|---|
| GET status | 当前会话、是否就绪/忙碌/关闭，不含人格、历史和密钥 |
| POST requests | 登记并处理所有者文字；新请求202，已存在返回原状态 |
| GET requests/{id} | 只查询此渠道自己的原请求及最终回复 |
| POST deliveries | 登记固定分段的发送状态，不触发发送或模型 |

**2026-10-30搜索来源联动：** 请求结果新增可选 `reply_hash`／`delivery_allowed`；前者是生成事务保存的原始回复hash，后者只是当前资格快照。ready仅登记固定hash，不授予发送权限；桥每次实际派发及明确401／429重试都重新提交sending，由核心检查全部必要来源的期限和QQ范围。来源失效返回409 `source_unavailable`，仅停止未发尾段。已发生的真实终态不依赖当前显示正文，仍可按原hash落账；确认终态必须提供有效平台消息ID，已有ID不得变更。端点及协议v1不变，详细兼容边界见[协议第5.3节补充](QQ接入-方案与审核.md)。

状态不可确认返回503，不能解释为没有处理；忙返回409，不能据此生成新请求ID。旧HTTP聊天/管理入口现在按GUI来源和意图校验，不能通过伪造Origin接入。Python公开 `ChatService.send` 的阻塞调用方式保持；新增可选身份参数与非阻塞方式。HTTP历史增加消息ID/来源与游标，原有字段保留。

**旧人工SDK兼容限制必须显式处理：** `tests/pressure/deploy.py` 仍使用匿名HTTP、旧data/config布局，已有适配工作由DSH负责；本轮不把它伪装成浏览器来绕过新边界，也不新增机器管理权限。旧启动器会收到明确GUI专用错误，不能继续作为这版QQ验收入口。人工QQ验收应使用独立检出/副本中的网页和桥；`--config`只更换模型配置文件，不隔离数据目录。

首次启动新代码会增量创建渠道请求/来源/发送状态表与独立session_epoch（即使QQ关闭，本地网页也使用请求身份）；不迁移现有对话正文、记忆/人格或P1数据。新会话归档换epoch，旧桥消息不能投到新会话。回退前停桥并关闭渠道，新表可保留，旧代码不能继续负责QQ恢复。

来源联动进一步给旧 `channel_requests` 表增量添加可空reply_hash列。旧记录先从已有一致delivery登记补齐，再取尚存的原始附件／普通正文；来源附件已清且无可信旧hash时不从占位推断。此联动需更新后的核心与桥配套，不能仅更新一端便宣称具备逐次撤权检查；已在途平台请求仍无法撤回。

## 操作与故障处理

QQ桥的安装、扫码、配对、前台运行与Windows启停步骤见 [addons/qq/README.md](../addons/qq/README.md)。默认渠道关闭，真实凭据只在用户操作时保存到 `user/qq/`，状态/日志落 `user/data/` 对应子目录；不使用旧根目录data。

模型配置仍在网页保存，在途轮结束后发布新配置，桥无需重启。网页首次启用QQ会受控发布渠道配置；手工修改QQ凭据/所有者/机器令牌仍须先停桥、排空并按说明重启，不能只修改文件就当撤销已生效。关闭Alice不会自动重启；QQ桥停止提交并保留未发送/未知记录。

重置前先暂停桥、核对未发送和未知结果；已经交给QQ平台的消息无法撤回。发送超时不要直接重发问题：先看网页是否已有答案、QQ是否已收到。本版不提供QQ远程补发命令，未发出的原答案在本机网页查看；结果未知不会自动重发。SDK在收到响应头后取消自身计时，极端情况下等待响应正文可能延长停桥时间，因此不承诺固定秒数内退出。

## 2026-11-01 补充：首次使用安装入口

用户反馈其他电脑提示“QQ 连接依赖尚未安装”，随后授权增加首次使用安装功能。源码不附带安装后的组件；现在从网页的“连接 QQ”面板即可开始准备：

1. 缺少 QQ 组件时，点击“安装 QQ 组件”，页面显示安装状态；完成后直接继续扫码。
2. 缺少或需要更新 Node.js 时，页面提供[官方下载入口](https://nodejs.org/en/download)，要求 22.19 或更新版本，并保留安装程序中的 npm 组件。安装后点“重新检测”；仍未找到时重启 Alice。
3. 下载或写入失败后，按提示处理并重试。关闭面板不会中断安装，关闭 Alice 则结束本服务的安装任务。

安装、扫码、确认身份、开始聊天分别由用户点击。打开页面或刷新状态不会自动下载；安装完成也不表示 QQ 已连接。升级到本版仍需重启 Alice 加载代码，此后安装 QQ 组件成功不需要再次重启服务。此次不改群聊范围。

实现沿用同源 `/api/connectors/qq`，新增固定 `install` 与 `recheck` 动作及 `setup` 状态。浏览器不能传命令、安装目录、软件包或下载地址。安装使用项目锁定版本，遵循 [`npm ci` 的固定安装行为](https://docs.npmjs.com/cli/v11/commands/npm-ci/)，禁用安装脚本；不复制、改编或随源码打包扫码组件。安装期间阻止启动 QQ，已有 QQ 进程使用组件时阻止安装。详情与终端备用方式见 [QQ 使用说明](../addons/qq/README.md)。

### 2026-11-01 人工反馈：安装完成后仍被判定缺组件

Mac 使用者反馈网页安装数秒后失败；手动执行 `npm ci --ignore-scripts --no-audit --no-fund` 返回 `added 4 packages in 2s`，随后网页重新检测仍显示需要安装。已静态确认原因：固定版本 `qrcode-terminal@0.12.0` 在包清单里写的入口是 `./lib/main`，实际文件为 `lib/main.js`。旧检查直接判断无扩展名路径是否存在，没有采用 Node 的文件名补全规则，因而在完整安装后仍报缺失。该错误也影响 Windows，并非 Mac 专有问题。

修复为检查该固定版本的真实入口。已通过终端安装的使用者更新并重启 Alice 后，点击“重新检测”即可重新判断，无需先删除组件。安装失败另外提供具体环节及受限排查编号，区分准备目录、启动程序、下载安装和结果检查；安装工具错误仅在内存中有界分类，不保存或显示原始日志。Mac / Linux 终端说明已补入 addon README。

证据范围：用户提供了旧版失败截图与 Mac 终端安装成功输出；修复后的网页检测、扫码和收发仍待该使用者人工确认。本轮未在日常副本安装、启动 QQ 或执行机器自测。
