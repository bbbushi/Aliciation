## 参考元素 → Alice 适配

| 参考原则 | 本次决定 |
| --- | --- |
| 主任务稳定、辅助入口收敛 | 单一对话始终是主区；216px 导航放人格、QQ、设置，开发者工具默认折叠。没有多会话、项目、终端或文件树。 |
| 正文、状态、工具分层 | 760px 阅读列，用户浅色气泡，Alice 无框正文；思考/工具继续沿用现有真实事件，诊断在观察器与 P1 面板查看。 |
| 语义颜色和组件 | 暖白背景 `#f8f9f6`、深青文字 `#25392f`、青绿操作色 `#315e4a`；灰绿导航、轻边框，警告和危险分色且保留文字。 |
| 输入区稳定 | 多行输入自适应高度，与消息滚动区分离；Enter 发送、Shift+Enter 换行，中文输入法组合期间不发送。 |
| 信息按需展开 | 记忆概览、开发工具、人格正文/高级源码、工具详情逐层进入；不把缺失、占位或无变化包装成已知状态。 |
| 浏览器可访问性 | 系统中文无衬线字体；等宽仅代码/源码。可见焦点、语义按钮、跳转输入框、抽屉/弹窗焦点与背景隔离、减少动画偏好。 |

布局使用统一 CSS 变量、组件边框和圆角，间距以 4/8px 节奏组织；正文优先中文可读性，不模拟全屏等宽终端。桌面开发面板与聊天分栏；900px 以下导航变抽屉，开发面板上下排列并各自滚动；短屏保留各区最小高度并允许外层纵向滚动。设置采用“对话与模型 / QQ 连接 / 服务”分区，危险动作不与一般配置混排。P1 下一轮许可或授权未知状态同时出现在输入区上方，可直接返回核查面板；折叠导航不会隐藏付费提示。

## 文件与兼容范围

- `web/index.html`：导航、欢迎/空态、聊天框架、设置分区、标签与语义属性。
- `web/style.css`：统一视觉变量及欢迎、聊天、弹窗、QQ、观察器、P1 的布局和响应式样式。
- `web/app.js`：导航和分区接线、最新消息跟随、输入高度与 IME、启动失败重试、标签键盘操作、弹窗焦点管理。修改时保留该文件原有未提交的 QQ 自然分条文案。
- 本文：参考证据、入口映射、验收与回滚说明。观察器、P1、QQ 继续复用原模块及后端，不改变核心接口。

原生 HTML/CSS/JS，无构建链、框架、外部字体、CDN 或新增运行依赖。现代桌面/手机浏览器为目标；`inert`、动态视口与焦点行为须在实际浏览器人工确认。原界面没有暗色主题，本次保持浅色，不增加主题切换。

聊天继续以 `textContent` 显示纯文本：Markdown 标记、代码、链接原文可阅读和复制，不执行 HTML/脚本，不把 URL 自动变为可点击链接。人格文档沿用受限、先转义的排版，不引入新的富文本解析器。超长内容换行或在所属源码容器内滚动。该限制是现有表达契约，不应把“未提供语法高亮/自动链接”误记为新增缺陷。

本轮不读取、上传、替换真实 `user/` 数据，不为展示自动连接 QQ、发送消息或调用模型。不重启现有服务；若资源缓存需刷新页面，先完成在途回复并保存需要保留的草稿。刷新会按既有规则丢失本页临时观察记录和 P1 待绑定状态。

## 真实环境人工验收清单

每项记录“通过 / 未通过 / 未执行”、浏览器与窗口尺寸、脱敏证据和复现步骤。下列均为待执行剧本，不是通过声明。

### A. 启动、欢迎与人格

- [ ] 正常启动、服务不可达、恢复后重试：正在连接/失败/重试入口清楚，不出现空白死页；恢复不自动发聊天或启用 QQ。
- [ ] 无历史时欢迎页、已有底色、已初始化但无可见消息的聊天空态分别正确；有消息后空态消失，数据未加载完不误报“空”。
- [ ] 用鼠标和键盘选择 2–4 个标签、切换导入、取消预览；焦点和选中态清楚。仅在测试者点击实际生成时调用模型。
- [ ] 粘贴、选择文件、拖放人格文档及非法格式提示可用；长文/表格预览不溢出。人格查看、下载、替换、重置原确认仍在，取消不修改状态。

### B. 聊天、历史与发送恢复

- [ ] 加载已有较长历史、手动同步、后台恢复、QQ 来源记录：顺序、角色、状态和身份仍正确，不重复插入；初次载入落在最新消息。
- [ ] 向上阅读旧消息时，流式回复/工具更新/同步不抢滚动；“回到最新消息”可见且点击后恢复跟随。长文尾部和输入区不互相遮挡。
- [ ] 单行、多行、空白、很长中文、英文连续串、emoji、Markdown/代码/URL/HTML 字符原文：可阅读复制，无横向整页溢出、脚本执行或自动危险链接。
- [ ] Enter 发送、Shift+Enter 换行；拼音/日文等输入法候选确认 Enter 不发送；textarea 增高达到上限后内部滚动，手机软键盘不挡输入和发送。
- [ ] 真实回复的等待、生成、思考、工具执行、完成、工具失败与服务忙碌提示可辨；没有将占位或缺失数据渲染为成功。
- [ ] 快速重复点击发送/按 Enter 不产生重复轮；发送失败时原草稿和提示仍可恢复。
- [ ] 在专用环境人工制造发送回包不确定/SSE 断线：同文重试沿用原请求身份，刷新记录可找回原轮；“允许作为新一轮发送”仍需显式选择，不自动付费重发。
- [ ] 多标签/QQ 忙碌、会话身份变化、服务重连情况下，聊天状态、旧记录和连接文案一致，旧会话数据不混入新身份。

### C. 导航、设置、密钥与退出

- [ ] 所有旧入口通过上表可达；开发工具默认折叠但可展开，切回聊天不创建新会话；记忆概览显示真实计数或明确尚未读取。
- [ ] 设置三个分区切换不误保存；打开窗口只读取状态。当前思考深度、供应商、两模型、Base URL 与服务配置一致。
- [ ] API Key 不回显；保留模式禁用输入，替换模式为密码框；关闭/重开不泄露新输入。截图/日志不含密钥、完整配置或私人会话。
- [ ] 测试候选连接、验证并保存的费用说明可见；成功、错误凭据、忙碌、配置冲突均显示原结果。候选测试本身不切换配置，失败不覆盖有效配置。
- [ ] “关闭服务”只在服务分区；取消确认保持可用；测试者确认后显示等待及完成/失败结果，重启命令可读且无布局截断。

### D. QQ 独立步骤与投递

- [ ] 未连接、扫码等待、二维码过期/失败、配对等待、本人确认、已保存未启用、运行、暂停、取消/错误各状态的说明和可用按钮匹配真实后台状态。
- [ ] 扫码/配对后必须勾选本人确认再保存；保存不会自动接收聊天，随后明确点击开始才启用。取消、暂停、刷新以及关闭弹窗各自保持原语义。
- [ ] 切换操作或会话后旧二维码/配对结果不重新生效；网页没有渠道密钥、凭据或可编辑的任意目标/程序路径。
- [ ] 用专用 QQ 人工发送一轮，查看自然分条计划/投递中/完成/部分失败或未知提示；UI 未隐藏已知状态，也未因重开面板触发重投。算法、间隔、账本的验收仍按原 QQ 自然分条剧本执行。

### E. 观察器与人格阅读

- [ ] 打开、自动/手动刷新、忙碌、断线、恢复、清空、关闭：保持只读、最后快照与未知间隔文案；关闭清空行为与原约定一致，不调用模型。
- [ ] 变化/进度、记忆与观点、人格/思想、历史、墓碑、技能全部可达；筛选、检索、首页/下一页、详情/下一段仍工作，切换视图不留错误旧内容。
- [ ] 人格真实内容、缺失、占位、无变化、截断和失败状态各自明确；摘录来自原文；目录、全文折叠、全展开/全收起、高级源码和变更对照均可操作。
