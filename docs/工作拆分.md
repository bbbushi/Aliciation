# Alice 工作拆分：四条分支，一条主干

> **给谁看**：打算接手其中一个方向的人（也供替人轮班的 agent 读）。
> **回答三件事**：这块的活是什么、做到什么叫完成、什么时候必须和别人合并。
> 不回答进度——进度看 `AGENTS.md` 的「当前」和 git log。

## 一、怎么用（人话版）

1. **一个方向 = 一个分支。** A / B / C / D 各有自己的目标、清单、完成标准，**可以独立开工，不必等其他分支**。分支内部按自己的节奏迭代，长期不合主干也没关系——只要不碰主干。
2. **主干只有两样东西**：设计不变量（[迭代路线.md](./迭代路线.md) 第一节）和五张接口（见 §七）。不碰主干，分支怎么跑都行。
3. **合并只发生在三处**：改接口、改共用文件、每两周一次对齐。其余时间不需要开会，也不需要互相等。
4. **编号就是通用语。** `A3` 就是 `A3`，写进提交、写进周报、写进交接都用它。任务做完标「完成」；只有数字还没量到的标「**待测**」——待测不等于没做完。
5. **三条给新人的纪律**：不编数字（没有尺子就写"未测"）；不绕过记忆管道（外部内容一律走提取→分层→遗忘）；不动别人的目录（见 §八）。

## 三、A 线 · 底层架构

**目标**：把"上下文怎么组装、人格怎么推演、记忆怎么沉淀"从**能跑**变成**可观测、可归因、可优化**。
**分支边界**：只动 `alice/` 的组装与推演逻辑；页面归 C，指标口径归 B。

**上手三件事**：读 [设计思路.md](../设计思路.md) 第 2、4 节 → 读 `alice/retrieval.py:84` 的 `build_system_prompt` → 跑 `python3 tests/growth/test_offline.py`（零成本，确认环境）。

| 编号 | 任务 | 做法 | 做完的标准 | 量级 | 接口依赖 |
|---|---|---|---|---|---|
| **A1** | 上下文分段可观测 | 在 `build_messages` 出口记录每段 token：宪法 / 人格 / 长期 / 仓库索引 / 活跃 / 近期原文 | 任意一轮能出分段表；给出"每轮固定开销"基线（绝对值 + 占比） | M | — |
| **A2** | 缓存友好的组装 | 依 A1 数据调序与裁剪：稳定前缀不动、易变段靠后（时间戳现只贴末条） | 连续 10 轮 `cached_tokens` 占比达标；轮间不变段落字节级一致 | M | A1 的数据 |
| **A3** | 记忆提取质量 | 校准 `alice/extraction.py` 的提示词与"再提及"判定；抽查 50 条分类：准确 / 添油加醋 / 废话 / 漏记 | 编造 = 0；废话率与漏记率有基线；同对话重跑提取结果稳定 | L | — |
| **A4** | 仓库层与 recall 实效 | 测 `warehouse_index` 实际 token；测 recall 命中后模型是否真的引用 | 索引 ≤ 1k token；召回内容被引用率有数据（可借实验室 H2 侧测） | M | A1 |
| **A5** | 人格推演可审计 | 检查 evolve 输入（当前人格 + 期间新记忆）、changelog 能否指回源记忆、底色护栏是否守住 | 实验室 R1 ≥ 0.75、R2 ≤ 0.50、B3 ≥ 3 稳定两次；每条 changelog 可溯到记忆 id | M | A3 的质量 |
| **A6** | 成本归因与红线 | usage 归因到环节（对话 / 提取 / 演化 / 评审）；config 设成本红线 | ¥/天 归因表；超线告警而非静默 | S | A1 |

**与别的线的接缝**：给 B 提供记忆/人格真值（H2、R 维探针的数据源）；给 C 提供记忆与人格的读取接口。B 的尺子没到位时先做、结果标「待测」。

## 七、主干：五张接口与合并规则

**接口（定义一次，改动要通告，但不必等对方做完）**

| 接口 | 内容 | 定义方 | 消费方 |
|---|---|---|---|
| 指标口径 | B/R/H/J 的公式、探针类型、样本单位 | B2 | A、C、报告 |
| 事件 schema | `kind / turn_ref / evidence_refs / verdict / judge_model / prompt_version` | B3 | C2、C3 |
| 记忆管道 | 写入 → 提取 → 分层 → 检索的唯一入口 | A3、A4 | B3 取证、C5 抓取内容入库 |
| 工具注册 | 名称 / 描述 / 权限 / 超时 / 失败回传 | C4 | C5、C6 |
| 参考索引 | 主题 → 结论 → 编号 → 来源 | D4 | 四条线 |

**什么时候必须"合并"**（即对外通知、双方各跑一次自验）

1. **改接口**：口径、schema、管道、注册契约、索引格式变更 → 先发一句通告，再动手；
2. **改共用文件**：`alice/store.py`、`alice/retrieval.py`、`alice/service.py` → 提交描述写清动了哪块；
3. **A 改组装 → B 补基线**：数字类结论从「待测」转正前，必须有复现基线；
4. **每两周一次对齐会**（半小时）：接口变没变、阈值要不要重定、D 的结论该派给谁。

**合并方式**：一人一分支，按接口契约合并；分支偏离主干超过两周，先合并再继续——避免"大爆炸式合并"。

**纪律一句话**：**改进不等测量，声明等测量。** 改动能随时落地并自验行为；凡是要写成"提升 X%"的数字，必须有可复现的尺子，否则标「待测」。

## 八、人员与节奏

- **一人一线**为宜（A 架构 / B 测试数据 / C 前端与工具 / D 研究）；一人多线时按"先进先出"取编号，不跨线同时开工。
- **建议开工顺序**（只排优先级，不设准入）：A 线 A1 → A4 → A6；B 线 B1 → B2 → B3；C 线 C1 → C4；D 线 D3 → D1。
- **目录分工降低冲突**：A 碰 `alice/` 组装层；B 碰 `tests/`、`alice/metrics.py`；C 碰 `web/`、`alice/server.py`、`alice/service.py`；D 只碰 `docs/harness研究/`。
- **交接**：做完一块写三行——做了什么、下一块从哪开始、哪里脆。写进 `AGENTS.md`「当前」，不新建交接文档。

## 九、本期不做

多渠道（Telegram / 微信）、语音多模态、以 AI 身份公开发言、技能注入对话（A7 推迟）、绕过活动周期的主动打扰。这些在 [迭代路线.md](./迭代路线.md) 里有位置，但不进当前拆分——四条分支都要有人真正跑起来，比铺开更多方向重要。
