# Alice 工作拆分（四条线）

> 定位：这份文档回答"**这块要做什么、做到什么叫完成**"。它不记录进度——进度在 `AGENTS.md`「当前」、git log，以及 `docs/harness研究/参考索引.md`。

## 〇、怎么用

1. **任务编号稳定**：`A3`、`B5` 一旦分配不改号。合并就写 `A3→并入 A1`，废弃就划掉，不要删号（编号是交接时的唯一指代）。
2. **状态不写在这里**。每棒开工读 `AGENTS.md`「当前」，收工把它整节替换；做完的任务在 commit message 里带编号（`A1: 上下文分段可观测`）。
3. **调研必须落到编号**。D 线的产出如果落不到某个 A/B/C 任务上，就不入库——否则文档会变成一堆没人用的阅读笔记。

## 一、总体判断

四条线不平级：

- **D 是输入**，A 是地基，**B 是裁判**，C 是出口。
- 只有一条硬判据：**任何改动要么被 B 测到，要么不算完成**。所以 B1（可复现的环境）优先于所有"优化"——没有可比性，优化就是感觉。

## 八、轮值约定

一棒 = **一个任务编号**，产出三件套：

1. 代码 / 文档改动（提交信息带编号）；
2. `AGENTS.md`「当前」整节替换（≤5 行，写清"下一棒从哪开始"）；
3. 若涉及调研，`参考索引.md` 加一行。

跨线并行时按目录分棒（见上表），避免同文件对撞；同一棒内不跨线，保持"做完一块、可验证一块"。
