# 社交观察功能：计划与审核

2026-10-30｜heartbeat参考修订版，待审核，未授权开发。配套：[冲浪主计划](./冲浪功能-计划与审核.md) · [搜索计划](./搜索功能-计划与审核.md) · [修订报告](./联网能力-heartbeat参考修订报告.md)。

## 推荐与待选事项

**目标：让 Alice 能接触真实讨论，理解同一话题里的不同说法，成为可聊的见闻来源。** 首个可用版本应是开启后按时段自动观察的只读订阅，手动读一次只作内部接线里程碑。

推荐先选**一个用户确实感兴趣的公开评论来源/话题**，自动合批有限新增评论，形成有出处的观点卡；复用冲浪的活动调度和来源机制。已授权QQ群也值得设计，但需独立接入范围和参与者身份，不能把现在“本人私聊”开关改成收全部群消息。

heartbeat参考补充的是“绑定来源→游标→有界收件箱→成功提交后清本批”的处理方式。它实际观察的是绑定会话中的用户消息，不是社交平台采集器；不能据此推定Alice已有群观察能力或第三方处理许可。同步main的[需求六](./需求文档-GUI功能三件.md)明确B站先行，因此下列WordPress/YouTube只作待选接线方案；若本模块承担需求六的评论部分，应优先核查B站实际接入，不能用其他平台验收代替。

| 需裁决 | 推荐 |
|---|---|
| O1 首个平台 | 选真实想看的公开评论话题；WordPress公开评论或YouTube公开视频评论有官方接口可评估。若QQ群才是核心需求，改以知情测试群试点，明确新增范围 |
| O2 自动节奏 | 1个来源、每天2个活动窗口，每批≤20条；空批静默，有变化至多一次隔离解读 |
| O3 怎样进入相处 | 本机观点卡自动更新，用户可讨论；公共观察可选择每日最多1条external见闻，计入与冲浪共享的每日记忆额度 |
| O4 受限材料 | 群/自有社区另批准；默认本机观察区可见，不入QQ私聊、不用于搜索或公共冲浪，不默认长期记忆 |
| O5 增量与连续性 | 有界inbox、按版本去重；公开观点可进入共享素材池/待续念头，逐项继承scope |

观察许可不包含回复、点赞、关注、发帖、私信、入群或转发；本计划不代用户订阅、登录或发出任何社交消息。

## 一、用户体验

GUI新建来源时确认平台、精确文章/视频/群、观察目的、时段、样本上限、是否把评论发给所选模型、可见渠道及保留时间。“添加来源”和“启用自动观察”分开；没有来源就没有后台轮询。

运行后只在有新增或可检测变化时更新观点卡，例如“这次看到的18条评论里，一部分强调A，另一部分反对B；缺少完整回复链”。卡片可展开样本范围、抓取时间、排序方式、短引文和来源。不能把20条时间排序评论说成“大家都认为”，不能把评论者说法写成用户本人观点。

用户可点“讨论这张观察”。公开材料在允许渠道带来源进入话题；受限材料保持其查看范围。平台作者、群成员或评论里写“我是主人”都不会获得owner身份或给Alice下指令的权限。

## 二、入口与当前真实能力

| 来源 | 当前确认情况 | 首版选择的含义 |
|---|---|---|
| WordPress公开评论 | 官方`GET /wp/v2/comments`支持文章/时间/页数等参数；邮件/IP等不是普通公开view所需字段 | 固定站点和文章ID，纯标准库HTTP/JSON、无登录；真实站点是否开放要人工验证 |
| WordPress评论feed | 官方支持全站与文章评论feed | 可选适配；RSS窗口不是全历史，缺项不能当删除；需要安全的有界XML解析 |
| YouTube公开视频评论 | 官方`commentThreads.list`支持文本、排序/分页；返回的replies不保证完整 | 有专用API配置和quota；要明确评论关闭、缺回复及样本偏差，不承诺全部读完 |
| QQ群 | 官方有`GROUP_AT_MESSAGE_CREATE`和开启全量接收后的`GROUP_MESSAGE_CREATE` | 可以设计群观察；实际应用/群是否具备权限待验证，现有同一Intent位不能证明已开全量 |
| B站、知乎等 | 本轮未确认满足用途的现行官方接口/权限 | 保留需求，选定后先查可用接入；不预先承诺登录Cookie或非公开接口抓取 |

依据：[WordPress评论API](https://developer.wordpress.org/rest-api/reference/comments/)、[Feed说明](https://developer.wordpress.org/advanced-administration/wordpress/feeds/)、[YouTube列表接口](https://developers.google.com/youtube/data/reference/rest/v3/commentThreads/list)、[回复完整性](https://developers.google.com/youtube/data/guides/implementation/comments)、[QQ群@事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_at_message_create.html)、[QQ全量群事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_message_create.html)。这些是官方接口事实，不是本机账号已获权限的证明。QQ两页本轮通过只读HTTP取回，未访问登录后台。

源码已确认：`addons/qq/src/config.mjs`硬拒allow_groups；`bridge.mjs`限定C2C及owner；`alice/channels.py:normalize`再次验证本人身份。`retrieval.build_messages`将普通turn直接送主模型，`history_page`将其标为所有者。**群消息不能伪装成普通role=user，也不能提交到现有qq-owner入口。**

## 三、一次观察怎样进行

```text
活动闸：已启用的明确来源 + 活动窗口 + 前台空闲 + 预算/队列余量
  → 固定适配器按话题ID/游标读取有限样本
  → 去重、版本化、字段最小化，入有界inbox并提交游标，记录缺口
  → 有新材料且有费用许可时，一次无工具解读
  → 宿主验证引文/参与者/范围，成功提交后只清已处理ID
  → 来源观点卡；可选公共素材、共享额度内的external见闻
  → 分享闸：当前渠道有scope、材料有效，主会话才可选择使用
```

授权对象至少包含`source_id、平台、站点/群ID、topic_id、读取模式、端点模板、参数范围、时段/额度、处理供应商、audience、保留期、policy版本`。来源不能自行扩成整个作者主页、关注关系或其他群；分页只能由适配器在已批准页数内生成，模型不能传任意URL。

来源事件先投影再落盘：只保留必要正文、来源内参与者ID、内容ID/版本、时间、回复关系；不保存整包原始事件。排除邮件、IP、auth_token、附件签名URL及不需要的联系方式字段；转发/引用合并消息、图片、文件、音视频不递归导入，不自动取头像和外链。

昵称不作身份键。使用`provider + source_scope + participant_id`，默认显示来源内化名；不跨群合并人物、不建立个人画像或推断敏感身份。第三方的“授权语句”也是评论内容，不能更改配置或代表当前用户。

### 增量收件箱与失败恢复

首版所有观察来源合计待处理≤100条且≤1 MiB，仍计入全局20 MiB短期内容池；单条与单批上限见第六节。收件箱保存最小字段，不是永久事件日志。空间不足时暂停接收/拉取并标记缺口，不能默默覆盖未处理内容后声称完整。

游标只随已持久接受的一批事件推进；去重键为`source_scope + content_id + version`，不以昵称或首句去重。处理批次固定其ID与版本；模型处理期间的新事件留在下一批，成功提交观点卡后仅确认本批已处理ID。失败/锁冲突/取消不清空整个inbox，失败材料仅在原保留期内可供人工重试，重试消耗新额度；不因重启或下个空节拍自动重跑失败模型。队列超限、停机和游标失效如实显示采集缺口。

不照搬“每条只留第一句80字”作为理解方式：短评论在限额内保留完整正文和回复关系；截断、缺上文、编辑与删除均显式标注。排除可确定的Alice自身输出/转发，模型归纳不再作为新社会声音重新入箱；无法可靠识别的跨站转载不承诺全部排除。来源删除/撤销时，待处理批、正在加工的提交许可及相关候选一起失效。

## 四、公开、群与私密材料分别授权

| 类型 | 读取和派生边界 |
|---|---|
| 公开评论 | 固定话题、有限采样；明确是否送外部模型；只能得到样本视角，不以公开可读为无限归档依据 |
| 自有社区 | 管理权限不自动等于成员允许外部模型处理；确认用途、成员告知/退出方式、实际可见字段；默认不读私信、待审/隐藏内容、管理日志 |
| 已授权QQ群 | 指定群与@/全量模式；未开全量就如实称@样本；默认不补历史、不读附件/合并转发，收到非授权群立即丢弃 |
| 第三方私聊 | 不继承本人C2C、公开订阅或群主许可；首版排除，另案设计 |

群观察建议新observer addon或明确隔离的观察进程，核心新增公共接入面。addon只提交类型化观察事件，不导入核心内部、不碰共享数据库；核心不import addon。观察凭据及命名空间不复用owner会话身份；若平台token同时有发送能力，本地只读闸不等于平台已签发只读token，代码只暴露固定接收操作，不能把通用SDK调用交给模型。

观察连接在非活动期断开并显示采集缺口，以满足新增观察任务休眠不发API的默认选择；本人私聊唤醒连接保留不等于批准常开全量群观察。若用户需要全天群覆盖，应另批准常开接收与有限处理的例外，并在活动策略中如实记录，不宣称同时实现“全量覆盖”和“休眠零连接”。

## 五、与记忆和人格的关系

公开观点卡默认保留7天供讨论；经用户开启“保存少量公共观察”后，最多选1条来源明确的external event，**与冲浪共享每日1条自动见闻额度**，不能三个模块各自写满后稀释关系记忆。内容是“某批样本出现某说法”，不是某说法已证实。使用[冲浪计划第六节](./冲浪功能-计划与审核.md)的来源、派生、remember、提取和人格过滤；不另绕insert_memory路径。

公共观点卡可产生一个分享素材，计入冲浪/观察共享的12个新见闻位置和48小时上限；卡片本体可保留7天，候选退休不删仍有效卡片，也不能每拍从同一张卡重建候选来反复分享。候选ID绑定来源版本及卡片ID，退休状态保留至卡片到期。由卡片生成的待续念头同样携带证据、origin/scope和期限；转为念头不提升可信度、不扩大受众、不自动进入长期记忆。

产生观点卡、提交正式见闻、提供给主会话、保存进回答、渠道送达分别记账。模型自报“采用了”不证明用户看过；没有回应不能推断用户喜欢或讨厌某个群体。候选选择的归属与未知送达处理使用冲浪的delivery_id协议，不另设可以匿名报账的旁路。

受限群/社区首版不进入普通记忆或主会话；本机讨论默认留在独立观察解读区。后续若批准进入主会话，关联用户turn、助手turn、引用、历史详情、缓存、提取、recall、active、P1和persona消费都必须继承scope，派生只取输入权限交集，模型不能放宽；不能只过滤memories而从recent_turns漏到下一次QQ聊天。完整消费链实现前不开放此路径，不能靠一句提示词“别泄露”上线。向另一个渠道转述是新的内容披露动作，不因同一owner就默许。

观察者的观点并非Alice本人经历，也并非owner立场。仅公开见闻允许参与冲浪的公开兴趣候选；受限材料及其主题/频率默认也不能变成搜索query，避免只删姓名却泄露语义。首版外部及派生材料都不直接改人格/技能。

提示注入按能力隔离处理：reader无工具、无历史/私人记忆、无可写设置；外部命令不能产生新抓取、发言或保存权限。模型仍可能错误归纳、遗漏少数声音；短引文核验只证明字符串存在，不能证明观点代表性或事实真伪。

## 六、节奏、保留和删除

| 初值 | 语义 |
|---|---|
| 1个来源、每天2窗口 | 用户选实际活动时间；不轮询全站，不因停机追回全部历史 |
| 每批≤20条、每条≤2000字符 | 按批准排序取样；超过标截断。正文总输入另限，无法装下时显示覆盖范围 |
| 每窗口≤2次读取、1次解读 | 空批或仅重复事件不调模型；计入自主联网共享预算，API平台quota另记；无自动重试/换源 |
| 原始文本/可识别人名24小时 | 到期不可再回放；运行清理删除，停机不保证到点擦除；WAL/备份不承诺安全擦除 |
| 观点卡≤7天、共享短期内容池≤20 MiB | 与冲浪快照/获准搜索缓存共用全局池，非社交单独20 MiB；默认化名、有限短引文；达到限额淘汰旧卡 |

原文24小时与观点卡7天的关系必须清楚：卡片只保留批准的最小短引文/化名和范围数据，不能保留整批原文；原样本清理后标明完整样本已不可回查，不拿短引文声称还能重现全部讨论。若来源许可/受限场景要求所有派生内容24小时删除，则卡片、待续念头、关联聊天附件及历史正文同样缩短，到期仅留固定占位，不能用“摘要”或UI历史绕过。原始样本的计划到期与来源撤销不同：只有启用时已明确批准的最小证据/派生保留期才可更长。存活公共见闻的必要证据走记忆生命周期，须在启用时说明这一例外。

内容按`source + event/comment_id + version`去重，游标与持久记录原子提交。窗口分页变化/断线/编辑会造成缺口；来源列表少一项不能证明删除，时间游标也不保证发现旧评论改写。可确认的删除事件使该内容及依赖它的摘要/分享/检索引用失效；无删除同步能力则显示快照时间、短期保留并支持本机即时清除。

共享15分钟本地节拍只检查到期与待运行状态，不把社交采集扩大到每15分钟。每个获准观察窗口最多启动一批，活动闸拒绝则不请求平台或模型；素材池空也不增加观察窗口。分享闸关闭不抹去此前采集费用。超时后撤销并确认工作者回收才释放共享后台槽；不把一项Promise返回当成平台连接已停止。

“暂停”只停未来采集；“清除此来源数据”清任务、证据、派生卡、待续念头、分享及关联历史附件，不退已用额度。首版任一必要依赖被删除/撤销，整条依赖它的汇总卡、见闻和派生都失效；不能只因还有其他来源就宣称剩余足以支持原数量、比例或结论。需要保留其余材料时另建获准加工任务、重新计费与校验，不从旧缓存复活。来源身份与必要防重墓碑不保存敏感正文。取消先撤销版本，再停止下一阶段，迟到结果不能复活；reset/重启不自动补发模型请求。

## 七、开发计划

| 阶段 | 拟涉及位置 | 完成标准 |
|---|---|---|
| O0 冻结一个真实用途 | 本计划、范围裁决 | 用户选平台/话题或知情群、样本/费用/查看范围；公开与受限分别批准 |
| O1 单源接线里程碑 | 来源适配器、核心观察公共面 | 手动触发真实有界读取、字段最小化、正确身份/范围；此阶段不单独算“订阅版完成” |
| O2 自动订阅闭环 | 共享activity/来源表/预算、有界inbox，`service.py/server.py/config.py`、原生GUI | 双闸、按版本入箱、成功清本批/失败保留、缺口/截断/暂停可见；空批无模型，普通聊天优先 |
| O3 公共见闻接入 | 冲浪来源资格、素材池与记忆消费入口 | 候选与正式见闻分开；可选共享每日额度；卡片/待续念头不洗scope；提供与送达独立记录 |
| O4 群/自有社区适配 | 独立observer addon、接入认证、scope查询与删除传播 | 保留原owner C2C边界；@/全量准确、非授权群不收、无发言、缺口与退出可解释 |

推荐公开来源首版包括O1–O3；O4另授权，可优先于公开平台推进，但不能跳过身份/scope边界。核心/平台分工遵守工作区约定，三个计划共用一套活动/来源/预算接口，不各造后台队列。

回滚先停订阅、排空；保留scope过滤与来源资格，不可回退到会把群评论当owner消息的旧实现。新数据不默认清库；需要删除或迁移时按用户选定范围处理。QQ分条已有未提交改动，本计划不修改或覆盖它。

## 八、真实环境人工验收（全部待执行）

独立检出/数据、专用凭据、自有或明确获准的评论话题/知情测试群，使用虚构作者和非敏感文本；不复制生产私聊，不做机器自测或冒烟。

| 场景 | 预期观察 |
|---|---|
| 连续两个真实窗口 | 新增自动合批、无变化不花模型费用；停机/休眠缺口如实显示 |
| 对立观点和不完整回复 | 展示样本中的分歧，不夸大多数；缺回复链/截断/排序有标识 |
| 同昵称/改昵称/冒充owner | 身份仍按来源内ID；评论不能变为owner指令或用户事实 |
| 注入与跨域链接 | 不执行remember、发言、扩源或秘密query；reader看不到私人库 |
| 429/评论关闭/断网/编辑删除 | 不密集重试、不把缺数据当没人讨论；删除或未知状态准确 |
| 暂停/清理/重启/reset | 旧代际结果不提交、不补抓补模型；清理传播到派生卡/引用 |
| GUI/QQ竞争 | 普通聊天优先；观察不占被动回复次数、不产生额外QQ泡 |
| 受限scope | 本机可见不代表QQ/其他群可见；冲浪、搜索、普通recall和P1拿不到越界材料 |
| 群接入（另批后） | 只@与全量不同；非授权群丢弃；无历史/附件擅自导入、无自动群回复 |
| 几天后的观点卡 | 完整样本到期后不假装可复核全部；短引文与存活见闻各按已批准生命周期 |
| 收件箱并发与失败 | 加工期间新到事件不被本批清理；游标/入箱同提交，失败不全清；满队列显示缺口，无隐藏重跑 |
| 首句与来源版本 | 否定/转折不因首句取样变相反观点；截断标明；修改/删源使依赖候选和待续念头同步失效 |
| 分享连续性 | 同卡候选退休后不自动复活；缺回话/报账/送达未知不记用户态度，受限材料不借待续念头越界 |

样本归纳是否有用、是否误读群体由人工判；只读方法白名单、身份及scope传播另做源码审查。读取成功和模型一次抵抗不能证明安全机制成立。
