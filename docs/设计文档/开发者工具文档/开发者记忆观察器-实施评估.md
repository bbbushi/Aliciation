## 结论与范围

最小闭环可按局部功能实施，无需架构裁决：在聊天旁增加可关闭的开发者只读面板，通过现有 ChatService 所有权及同一 RLock 获取有界快照。锁忙时立即返回 busy，浏览器继续显示最后一次成功快照；空闲后刷新。这里没有读取在途半轮，也不改变写者、事务、提取与演化调度。

交付：三层记忆分页检索与详情、观点与技能的实际记录、删除墓碑、当前人格与既有历史快照、观察期间变化、触发进度、自动/手动刷新。变化是两次观测之间的净差异，不能重建期间多次改写或短暂新增后删除的完整顺序。首次打开建立基线；未记录的信息显示未知。没有额外模型调用、打分、编辑、强制提取、重置、导出或新的永久副本。

完整事件溯源、精确来源轮次、流式生成期间读取最新半轮、跨进程一致性、修复首次思辨及持续维护调度均需架构裁决，本期不是必要依赖，不实施。若用户以后需要上述能力，应另提交裁决报告，不能将本面板宣称为完整事件流。

## 源码地图与实际数据流

| 路径 | 实际行为及保存位置 | 观察结论 |
|---|---|---|
| `loop.chat_turn` → `extraction.extract_pending` | 回复落盘后取 extract_cursor 后最多 80 条消息，按用户消息数判断阈值；逐条插入 memories，最后写游标；created_at 是批次最后消息时间 | 对话、候选、持久记忆不同；没有候选表或确切入库时间；游标不代表原子成功批次 |
| `retrieval.tool_remember` | 以默认 active 层直接写入 salience=1 的重要记忆 | 无来源类型/turn ID 列，不能据层级推断一定来自 remember |
| `retrieval.tool_recall` | 命中后 bump_use，更新 use_count/last_used_at | 观察绝不能复用 recall；再次提及由提取器 bump_mention |
| `consolidation.run/run_if_due` | 活跃转仓库、按年龄/使用/重要性/压力晋升或删除，长期超额按权重删除；last_consolidate_at | 服务只在 prepare 维护，send 不维护；到期不等于后台会立即执行 |
| `Store.expire_memory` | 删除正文，同时保存 memory_tombstones 的 memory_id/title/expired_at/reason | 墓碑是真实存储记录，可分页；不补造已删除正文 |
| `persona.seed_from_tags/install_persona/evolve` | persona.md；覆盖前 history/vNNN_日期.md 存旧正文；meta persona_version；CHANGELOG.md | 文件名版本是写入前快照的保存编号，不能当成对应内容版本或精确发生时间 |
| `thought.deliberate` | stance 写长期层；理由/出处标题/不确定/未决均在 content 文本，修订另建 ID 并将旧条写墓碑；思想节写 persona.md | 不是结构化来源 ID 链；思想更新不增加 persona_version，也不保存旧人格快照 |
| `skills.distill` | skills 含 source_titles 文本及计数；写 last_distill_at | 当前对话未消费技能，不能声称其已影响行为 |
| `service.send/_watchers_due` | 同一锁内聊天与提取，随后演化→思辨→技能；SSE done 在其后 | 只能在锁空闲时获取一致的进程内快照；不把 busy 解释为某个具体后台任务 |

## 字段与能力矩阵

| 对象 | 可直接展示 | 只能观察差异 / 未记录 |
|---|---|---|
| memories | id、created_at、layer、title、content、keywords、salience、mention_count、use_count、last_used_at、promoted_at、kind、pressure | 无 updated_at、来源轮次、提取候选、统一 revision；内容/标记/计数/迁层只能比较快照 |
| tombstones | id、memory_id、title、expired_at、reason | 无旧正文；reason 是原存储文本，不追加推理 |
| persona | 当前原文、meta 版本/种子/演化时间、既有快照与 changelog | 思辨可能只改正文；日志包含模型给出的变更说明，不是独立事实判断；历史不完整 |
| stance / skills | 原文中的出处标题、曾以为；技能 source_titles | 不验证或自动链接为唯一来源，不推定因果；技能删除无墓碑 |
| 进度 | extract_cursor、其后首 80 消息内用户数及总待处理数；时间锚点后现存记忆数；配置阈值；维护时间及规则 | 无持久任务状态、失败原因/重试计划；达到门槛仅是条件，非执行承诺 |

首次思辨退用 last_evolve_at；演化先行可能重置首次思辨计数。演化最多 100 条、思辨最多 60 条；补提取的旧时间和已删除材料影响计数。面板按当前真实算法展示，并给出这些限制，不修复 A01—A10，也不展示虚构百分比。

## 访问、刷新与边界方案

新增 `ChatService.observer_*` 公共只读入口及 `alice/observation.py` 纯读取辅助；所有 DB/人格读取仅在原 `_lock.acquire(blocking=False)` 成功后进行，finally 释放；失败返回 busy、不访问 Store。不新建数据库连接，不执行 Store 初始化，不调用 recall、维护、watcher 或 LLM。新增路由 `/api/observer/*` 使用现有 Host/Origin/X-Alice-Intent 校验，响应 no-store；只白名单列，不返回 config、turns 正文或原始 DB。

列表采用 ID 键集分页，每页 25 条，查询最多 200 字；同一筛选固定首屏 ID 上界，刷新重新开始，避免插入引起 offset 重复。详情正文每次 8000 字，当前人格快照前 64000 字、changelog 尾部 16000 字。历史列表按固定文件名键集分页、禁止任意路径；人格文件详情超过 4 MiB 明确拒绝，仍可读取有界快照。SQL 扫描在持锁期间临时设置 1 秒 progress handler 预算并在 finally 清除（不是整个 HTTP 的硬超时；文件读取与浏览器调度另计）。读取错误返回固定文案，不泄露路径或提供者原文。

快照带进程/会话随机观察身份与采样时间；归档重置时更换身份，即使新库从 ID 1 开始也不混合。身份仅在服务内存，不是新持久版本协议；跨进程写入依旧不受此锁覆盖，外部 CLI 同时写不在一致性保证内。

各列表页、详情段和总览是独立的持锁采样，不是一份跨请求冻结数据库。分页上界只排除之后的新 ID；正在发生的迁层/删除仍可改变筛选结果，需按列表采样时间理解并刷新重查。浏览器不会把翻页和筛选结果拿来推断全库差异。

浏览器串行请求，面板开启且自动刷新时每 5 秒尝试；本页 SSE done/error 后也请求刷新。锁忙不会排队；空闲且连接正常时通常下一次 5 秒轮询加请求耗时可见，长轮次/断线/后台页调度无有限最大延迟。快照时间、busy、断线、退出、暂停自动刷新都明确显示。打开时若尚无成功快照且锁忙，显示等待首次快照。关闭面板停止轮询并中止请求，清空临时数据；不抢输入焦点。

差异跟踪限定最近最多 2000 个存活 ID；列表仍可逐页查看全部。快照说明覆盖范围及截断；新进入跟踪窗口不直接声称新增，离开窗口不直接声称删除；删除以墓碑记录为证。字段指纹用来比较内容，过长文本的比较范围须披露；正文按需读取。当前人格以有界原文作前后差异，同时提供原文对照与既有历史。只保留相邻基线与最近 100 条摘要，不缓存已删除记忆正文、不写 localStorage/文件。清空/关闭/身份变化/重载清除旧基线；网络中断时保留最后有效快照并标注未知间隔。文本只走 textContent，绝不执行记忆内 HTML。

## 落地与静态复核（2026-10-29）

已按上述局部方案实现。聊天页“观察”入口在 `web/index.html`，独立脚本 `web/observer.js`；`app.js` 仅接入回复终态/连接失败通知与关闭服务时清理。`style.css` 为侧栏独立滚动，小屏改上下分区。没有增加编辑或触发模型的按钮。

| HTTP 入口 | 参数 | 内容 |
|---|---|---|
| `/api/observer/snapshot` | `scope`（首次可省略） | 2000 个 ID 指纹、分层数量、人格有界原文、变更日志尾部、真实触发进度 |

## 人格 / 思想分块阅读调整（2026-10-29）

标签模板常见底色两节、生长三节，v0.3 可再有“我的来历”，自定义导入还有其他章节；思想写入可能调整小节顺序。展示必须按收到的标题和原顺序分块，保留序言、重复标题、未知章节和未形成占位文案，不能固定成三类、按标题去重或把思想里的出处/不确定性误变为经过验证的数据字段。没有章节标题的正文仍可完整阅读。
