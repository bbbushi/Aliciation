# 监测仪 v2 架构变更裁决报告

2026-10-29；基线 `ac4d392`。**当前状态：用户已批准先实施推荐的 A1 + R1，本版代码已落地；费用默认 0，未调用评审模型，真实环境人工验收待执行。**

第 1–7 节保留审批时的方案及取舍；实际接口、限制和人工验收以 [P1 实施说明](./P1记忆主张核查-实施与人工验收.md)为准。P2/P3、永久证据正文副本、自动周期评审、真实数据迁移和新费用启用不在本次执行范围。

本报告依据实际[蓝图建议](../wiki/harness研究/设计蓝图/设计-监测仪v2.md)及[逐项差异报告](./开发者记忆观察器-v2蓝图设计差异报告.md)。用户允许批判性调整设计，仍要求涉及架构的部分先报后做。已独立完成的界面语义调整不依赖本报告批准。

## 1. 建议批准什么

推荐 **A1：默认关闭、手动单次选择的 P1 证据核查实验**。从“核查下一轮自然回复”开始，不自动逐轮评审、不做历史证据回填、不生成对抗题。先建立记录/身份/保留/人工试标基础，再启用抽取与三分类；未校准只给带证据的实验性建议，不显示总体质量分。原观察器持续只读，打开它不启用实验，也不增加模型调用。

| 选择 | 可得能力 | 代价与边界 |
|---|---|---|
| A0 保持当前观察器 | 当前存储、差异、进度；本轮界面说明 | 零新增评审调用，无新schema；不能称已完成v2证据裁定 |
| **A1 手动P1（推荐）** | 用户选定下一轮的记忆主张核查、纯读检索、证据引用、独立人工标签、校准前置 | 新数据库身份/评估表/任务生命周期；每次通常1次抽取，若有主张再1次批量裁定；需要费用许可 |
| A2 按蓝图自动在线全套 | 周期P1、P2对照、P3偏好、可能用量卡 | 更高费用、采样偏差、更多记录与后台任务；须分别批准频率、基线、生成方式和预算，不建议一次性启动 |

批准 A1 不等于批准 A2，也不意味着批准保存完整证据副本、恢复 Token 卡或改变真实遗忘政策。

## 2. 为什么不能只补一个 UI

1. `turns.id`、`memories.id` 只在当前 DB 内稳定；observer scope 每次启动随机变化（`service.py:81`）。记录跨重启/归档要有持久数据库身份，消息引用与请求身份不能混用。
2. `retrieval.tool_recall` 会 `bump_use`（`retrieval.py:120`）；评审若走该入口会改变存活和淘汰。必须在 service 所有权下使用无副作用的证据读取契约。
3. 助手落盘→提取→演化/思辨/技能→done（`loop.py:182`、`service.py:273`）。done 后拿当前记忆去裁定，可能用刚从回复抽出的记忆为回复自证；单靠 created_at 不能分辨，因为它不统一表示入库时刻。
4. 旧 `turn_metrics` 只有 module/value/detail/ts（`store.py:53`），无证据/版本/校准状态。把新数据塞成 JSON detail 并不能避免新公共协议与保留语义，仍应明示为架构变化。
5. 当前 `_lock` 包住网络对话与watcher；额外评审若塞入send会拖延回复终态。锁外线程不能直接操作共享Store或复用会热更新/关闭的client。退出gate只计HTTP连接，不会自动管理新增任务（`server.py`的`_ShutdownGate`）。
6. 保存证据正文、完整评审prompt或自由理由会留下新的永久记忆副本；现有墓碑只保留标题/原因，不能默认扩大保留范围。

这些是状态所有权与语义依赖，不是改几个文件的问题；不捆绑修复全部历史审查项。

## 3. P1 的推荐时序与公共契约（拟议）

### 3.1 只核查明确选定的未来一轮

用户主动选择“核查下一轮”，看到模型用途、最多调用数、预算和证据保留规则后开启一次。选择产生一次性动作ID，明确绑定该页面随后提交的聊天请求（拟议为 `/api/chat` 的可选字段），不能被另一标签页先到的普通send消费；重复提交同一核查动作不重复计费。初期只接受本服务中的一个待核查轮次，不建无人值守常驻采样器。不使用当前模型姓名/Key来推断用户已同意新的费用；具体评审模型通过已配置的非秘密名称展示，凭据仍不回传。

这里的幂等只约束评估任务及调用额度，不承诺修复现有主聊天请求重发/恢复协议。资格清单只排除本轮新生成记忆自证，不能证明旧记忆没有来自过往模型的错误或自证，因此始终只裁定对给定存储记录的关系。

```text
用户单次开启 → service 记录一次性选择/预算
  → 下一个 send 取得原锁
    → 捕获回复前的证据资格清单（ID、完整内容校验值、范围、时间）
    → 正常 chat_turn；取得实际 assistant turn ID（不靠时间/相邻消息猜）
    → 正常提取与 watcher；登记任务、释放原锁；正常 SSE done
  → 评审专用工作者：抽取 → 持锁只读检索 → 锁外裁定
    → 再持锁核验数据库身份、消息/证据hash、任务状态、预算
    → 提交结果或标失效；前端按需读取
```

资格清单持久记录ID/hash与范围，不存记忆正文。检索只取该轮前清单中**仍存活且校验一致**的记录；回复后新写入、被改写或删除的条目不能替补为当时证据。首期仅核查“对存活记忆记录的可核查主张”；通用知识、感受、捐赠背景、语义不明的来历不强塞进同一判准，标超出范围。收养观点须保留“继承、未经自己经历检验”的性质。

**零命中统一记 `evidence_insufficient`，不记U、不进入支持比例。** U只表示非空、未截断且可复核的返回候选集没有提供支持，不能解释为全库不存在依据；若候选相互冲突、对象/时间不清或资格清单已变化，标待人工核对/不可判。每次检索记录查询派生版本、范围、阈值、top-k、返回顺序及完整性；查询由回复span确定性派生，避免额外持久保存一份可能含敏感内容的自由查询文本。原资格范围中的记录删除/改写后，首期保守地让相关检索结果整体失效，不能仅靠正向evidence_links仍存在来声称检索可复核。未命中/失效/超界数量与分母一起展示；排除缺证样本会产生选择偏差，支持比例不是全部主张的表现。

捕获、检索和输入均设条数/字符/时间上限；超过上限明确 `incomplete`，不得静默截断后以“没有依据”打负面标签或纳入支持比例。建议从最多2000个记忆条目、每个完整正文最多16000字符、每次最多10条主张、每主张最多5条证据开始人工观察资源消耗；这是待验证的工程上限，不是复用观察器前缀hash冒充全文hash。超长记录跳过时报告数量，受影响主张不产可汇总裁定；清单资源不足可拒绝该次核查，真实聊天仍继续。

更小替代方案是手动核查“已完成回复与**审查时**当前记录的一致性”，不捕获轮前资格清单；它能省事前挂钩，但不能检验当时是否有据，也不能排除本轮提取自证。可以作为明确命名的离线材料审阅，**不推荐替代本期P1指标**。没有轮前清单的历史回复不回填为同质量样本。

### 3.2 任务状态、锁与客户端

拟议状态：`armed → captured → queued → extracting → retrieving → judging → completed`；终止分支为 `skipped_no_claims / incomplete / failed / cancelled / interrupted / evidence_unavailable`。`evidence_insufficient` 是claim级状态；所有主张均无足够证据时run标incomplete。取消、失败、预算不足不计“未支持”。关闭后不能自动恢复费用；重启将未完成任务标 interrupted，用户手动决定是否重新发起。

所有读写和提交仍经 `ChatService._lock`；网络等待不持此锁。专用工作者不拥有Store连接，不直接调用内部写者；用Service方法领取只读材料与提交状态。每实例最多1个评审工作者、最多1个待执行任务，满额拒绝而非无限排队；与用户聊天争用供应商限额仍可能增加网络延迟，人工验收后再考虑放宽。

每个任务绑定配置代次/非秘密模型说明，使用独立client。配置热更新不关闭在途评审client，也不让一项任务混用新旧模型；密钥只在运行时内存中交给client，记录不含Key/环境变量值/完整配置。评审输入视为不可信数据，无工具权限；不执行原文中的指令、URL或代码。模型给出的证据ID必须属于本次候选集，span必须落在确切原文内，否则结果无效。

评审显式设请求超时、输出上限、输入字符上限，关闭SDK/外层的隐式重试；手动重试创建新的attempt并扣预算，不重复覆盖旧结果。当前 `llm.chat` 最多3次尝试，不能不加区分地复用并声称一次调用。计费开始后取消可能仍产生费用，无法保证撤销已送达供应商的处理。

**每个网络dispatch之前**须在原锁内原子预留并登记调用额度/attempt，抽取与裁定分别经过门闩；不能到提交结果时才查预算。崩溃、超时或结果未确认记已尝试/unknown，不自动退还额度并重发；提交后补实际usage。重复action ID返回已有任务或未知状态，不再发第二次请求。货币预留只有具备可靠价格与token上界时才能承诺，否则只执行明确的调用次数额度。

退出：先拒绝新任务、取消未发送任务，纳入既有server所有者的排空流程；等待在途client结束后清临时材料和关闭client，最后关闭Store。不能关闭Store后让线程提交，也不以daemon线程丢弃记录。若供应商/SDK不能在预定等待内结束，服务保持“正在收尾/待人工处理”，不能谎称已安全退出；具体超时取值由实现与人工故障验收确定。

重置/归档：撤销一次性选择与旧dataset任务，阻止旧结果跨入新库。归档中的既有记录仍归旧dataset，不能用新scope/同数字ID继续引用。已经发给供应商的文本不能远程撤回；本机临时文本在在途请求结束后丢弃，不留调试日志副本。

### 3.3 拟议接口

| 公共面 | 含义与约束 |
|---|---|
| `POST /api/evaluations/arm` | 同源、明确意图、幂等用户动作ID；绑定当前dataset、选定下一轮、模型/预算。不是打开观察器时自动发起 |
| `GET /api/evaluations`、`GET /api/evaluations/<id>` | 摘要与分页明细；每次核验证据仍可用。旧v1指标不混入 |
| `POST /api/evaluations/<id>/cancel` | 取消未开始/阻止新阶段；已发生调用仍计费 |
| `POST /api/evaluations/<id>/labels` | 人工标签独立保存，带标注版本/是否已看模型结果/备注权限；不覆写模型裁定 |
| `POST /api/evaluations/calibrations` | 明确人工核验后的准入记录，包含适用模型/rubric/检索版本和数据范围；不能模型自批 |

这些仅为拟议接口名和语义，当前不存在；批准后再锁定参数、错误码、分页和兼容细节。原 `/api/observer/*`、`/api/history`、SSE语义不删除；如需新增turn ID字段采用兼容的可选字段，不能从旧SSE虚构补全。下一轮捕获、chat_turn返回ID与任务提交需要一起设计，不能用“最后一条消息”代替返回实际ID。

## 4. 拟议数据模型与保留策略

推荐在原SQLite由同一Service管理新增独立评估表，不引入新数据库进程或事件总线：

| 对象 | 最小字段/职责 |
|---|---|
| dataset identity | 持久UUID、schema版本；新库生成新身份，归档不复用；observer scope仍是临时GUI身份 |
| evaluation_runs | run/action ID、dataset、assistant turn ID+hash、选择时间/证据截点、范围完整性、状态、用途、模型/参数摘要、rubric与检索版本、attempt/预算/实际usage可用性、开始/结束时间 |
| evaluation_claims | run、claim序号、原助手正文span、主张类型、裁定类别或不可判状态；不额外复制主张原文 |
| evidence_inventory / retrieval_attempts | 回复前有界资格ID/hash清单、清单hash；由claim span派生查询的版本/hash、层/阈值/top-k、返回候选ID/hash/顺序、截断/未命中/失效状态；不存查询或证据正文 |
| evidence_links | run/claim、对象类型+ID、完整hash、字段/span、检索排序/阈值、资格截点、availability；不存记忆正文 |
| human_labels | 案例ID、标注ID/版本、独立类别、是否揭盲、时间、分歧/复核状态；首期不保存可夹带证据正文的自由备注 |
| calibration_records | 独立数据集引用、模型/rubric/检索版本组合、三类分布、混淆矩阵与不确定性、人工判定的准入用途/范围/日期；不把样本条数当效度证书 |

任务/claim/evidence集合提交用原Service锁下的显式事务；失败不能留下“完成但无证据”的部分记录。现有Store逐操作提交问题不在本期全量整改，但新表不能复制该问题。schema版本、提交事务与原消息记录的边界必须明确，进程中断后只标未完成，不自动重发付费请求。

### 推荐 R1：引用型、与存活性联动

- 持久化受控类别、有限理由代码、记录ID/hash/span/参数，不保存完整prompt、证据正文、自由生成理由或检索结果副本。原回复已在turns中，主张只存引用；`unsupported`等模型标签永远与人工标签分栏。
- 证据在读取/聚合/任务提交时验证存活与hash；删除或改写后标 unavailable，UI不从已删除内容或另一个归档恢复，历史比例排除该样本并披露排除数与统计时点。必要的删除联动清理由服务原删除路径触发，这是待裁决的保留契约，不偷偷改变memories的寿命。
- 原始模型理由只可作为在途校验材料，运行结束丢弃；若以后要展示解释，可用存活证据span和有限理由代码拼出事实说明。禁止以自由理由永久保存被遗忘内容的转述。
- hash只能检查相同内容，不能恢复正文，不保证匿名性；存活性丧失后不承诺完整重放。用户如要求固定不可变历史比例，须另裁决证据保留与统计语义，不能默认缓存旧分数掩盖失效。
- 评审送出的本机材料会经过配置的模型供应商；本机不保留不代表供应商立即删除，需在开启时说明这一边界。观察器本身仍不向供应商发数据。

### 替代 R2：审计保留期

经用户另行批准，才能保存有期限的完整审计包；必须定义期限、删除联动、归档/导出权限、敏感内容处理与用户彻底删除。它改变当前“新增副本不得规避遗忘”的边界，还需决定是否正式修订迭代路线的不变量。**本报告不推荐也不默认选择R2。**

## 5. 校准、P2/P3与费用

### P1校准在前

先写版本化rubric与合成锚点，人工试标20–30条寻找歧义，再准备独立、分层的验证材料；人工流程执行真实模型核查，不能用机器自测或模型自评分替代。覆盖无主张、漏抽、未命中、矛盾记忆、时间限定、收养观点、捐赠背景、超长/截断、证据失效。分别核查抽取、检索与裁定，不用一个总体一致率遮掉前两步漏检。

75%不是已验证准入门槛。应由用途与误报/漏报成本确定，并报告每类混淆、样本分母、人工分歧、独立回复数与区间；在数据足够之前只展示逐案实验性建议。所有汇总明确“受检且证据仍有效的记忆主张”，不是整体诚实度。模型/rubric/检索配置变化后先标校准过期，不直接拼接历史曲线。校准样本的回复/证据失效、资格范围缩减也使其校准记录与准入许可过期；旧混淆矩阵只能标历史且不可复核，当前须重算有效样本并由人重新确认，不能沿用已失去样本支持的旧许可。

### P2 人格对照（不随P1自动批准）

先定义冻结对象：未来标签种子完成后，或v0.3消化成功/回落完成后的**完整已安装人格**，记录内容hash、创建时点、来源类型和消化状态。既有会话若用户指定当前/历史文件，只称“指定时点参照”，不能补称v0。完整人格可能含由记忆派生文本；新增永久冻结副本也需保留许可，R1下优先仅引用仍存在且hash一致的已有人格文件，缺失/改写即参照不可用。若必须新建不可变全文基线，应另批准其保留边界，不能借P1默认获得权限。

真实历史回复无当时完整上下文，不能称精确重放。推荐同一时点、同一模型和参数的两个受控生成，仅替换指定人格材料，均无写工具、不进入主会话；两序评审同一对，只记一个样本，顺序矛盾单列。名称是“指定条件下的成对偏好”，不把偏离50%当人格漂移。即使保持同一记忆输入，也不是“回到最初她”，因为当前共同经历会影响两版；报告必须披露这一限制。

### P3 人工偏好（独立选择）

用户主动触发，不每日自动提醒。真实回复已经看过，隐藏左右来源只能算部分盲法，记录“是否认出”；更强盲法可比较未见过的两版、统一模型/上下文/长度条件，另需两次生成预算。参考不能故意造弱；允许平局/无法判断。结果只代表该用户对该对候选的偏好，不称人机感客观分数；明确双方都是AI，不隐瞒本体。

### 成本模型与建议控制

设抽取的首次尝试数为 E、有主张后批量裁定的首次尝试数为 J、P2对数为 P、P3对照生成的首次尝试数为 B、人工允许的所有额外尝试为 R；不把重试重复计入E/J/P/B。蓝图原构造的调用数为 `E + J + 3P + B + R`；本报告推荐P2双生成改为 `E + J + 4P + B + R`，未见双候选P3则每案2次生成。该式假设每案正常走完；实际失败/提前停止按已dispatch记录计费，不补算未发送阶段。无主张只使该次J=0，不使E=0。若规则预筛没调用，必须记 skipped_unchecked，不能记“已确认无主张”。

金额需要按每次输入/输出token、模型档位和当时价格计算。缺失usage记unknown，不能算0；重试/失败可能收费。不读取真实Key或猜供应商价格，本报告不提供人民币估价；v1已停，当前新增评审基线是0调用，“1.5–2倍”不成立为可用预算。

建议A1先采用**单次许可最多2次网络请求（抽取+批量裁定）、自动重试0、并发1、排队1**；每次开始前显示上限。另需用户指定日调用额度与是否启用货币预算。严格金额上限需要已验证价格与输入token上界/预留计算，单靠字符上限不能保证；缺失价格时不声称硬金额封顶，达到调用额度即停止。未获费用许可前运行额度为0。Token卡不随账本基础自动恢复，若另要展示也只能展示明确用途/采样范围的实测值与缺失。

所有破坏性/故障/重置/超额场景仅在完整隔离副本，保持标准库/原生JS，无新增依赖，不执行冒烟或机器自测。

## 8. 用户裁决与实施结果

用户回复“先进行这一版的修改，若有问题我再要求你按照什么样的标准回退”，批准先实施推荐的 A1 + R1。未给出日费用额度，故默认保持 0；后续由 GUI 明确许可并逐次授权。没有执行回退，也不预设自动回退标准。

- 已落地持久数据库身份、独立评估表、下一轮资格清单、实际助手消息绑定、专用工作者及同源 HTTP/GUI。一次性 `action_id` 只作授权幂等键，聊天使用返回的 `run.id`；普通聊天不消费其他页面选择。
- R1 只存引用/hash/span/有限类别与元数据。原资格范围变化即停止回放；不复制正文、不改变遗忘计数。记录未完成/超限/缺证状态，不把它们当负面裁定。
- 生命周期采用更小的容量：总计最多一个待绑定或执行任务，无额外排队位；每次最多 2 请求、零自动重试。预留即记已尝试，取消不能保证已预留的调用免收费。配置变更、重启、重置与退出均有显式失效路径。
- 校准只检验候选集内的裁定一致性；每个独立回复固定取序号最小的已裁定主张。漏抽与漏召回须另由人工检查，20–100 个样本及所填阈值不构成整体效度认证。本版不输出总体质量指标。
- 实现和独立静态复审已完成；语法/接口/生命周期/差异静态检查不能代替真实环境验收。未操作 `user/`、启停服务或发起模型调用；详见 [实施与人工验收](./P1记忆主张核查-实施与人工验收.md)。

## 9. 使用反馈后的记录交互调整

用户随后要求改善任务记录的使用方式，并明确选择“删除核查记录”。此授权仅清理单次 P1 记录，不删除聊天、记忆或已消耗额度。实现新增同源单条删除入口，未结束任务终止与内容清理在同一事务完成；不新增存储架构或 schema 迁移。保留必要的幂等墓碑和调用账本，避免删除后同一授权重复计费；相关校准永久失效，不因剩余样本仍够数而自行恢复准入。

日常入口改为“查看结果”，直接展示建议；独立标注另选“先自行判断”，仍记录真实揭示状态。卡片以时间、中文状态与下一步为主，技术字段和高级标注折叠；全部/进行中/已结束筛选配合单条删除。具体边界及新增人工验收见 [P1 实施说明](./P1记忆主张核查-实施与人工验收.md)。未替用户批量删除或实际调用删除接口。
