# Alice v0.4 设计：思想层认识论结构化（观点的生命周期）

> 依据：用户 2026-10-30 构想（观点字段结构化 + 先入为主的可进化观点）；承接 [v0.2 思想层](./架构设计-Alice-v0.2.md)与 [v0.3 底色捐赠](./架构设计-Alice-v0.3-底色捐赠.md)；格式参考 bili-humanism 手账的数据层强制字段（见 [参考](../../wiki/harness研究/参考设计/参考-dsh-bili-humanism.md)）。
> 状态：**已实施（P0，2026-10-30 推 ytq b5ccbde；设计稿 v1）**——schema/生命周期/verifications/轻门控/兼容全部落地，离线八项验收通过（见八节状态表）。P1（对话中即时先验）与 P2（搜索/问答型证据）待做。
> 北极星承接：把隐式的训练先验显式化——**显式的先入为主，比假装没观点更诚实**。

## 一、动机（现行 stance 的四个缺口）

1. **去语境化**：claim 是悬空命题（"边界感很重要"），无处境锚点——不可被相似处境再唤起，易概括化；
2. **解释来源不可审计**：不知道观点从哪来（用户说的？自己推的？捐赠的？经历消化的？）；
3. **隐藏先验**：底座对未入库话题自带训练先验——不可见、不可审计、不可修订；思想层不收编它们，它们照样在起作用；
4. **观点与行为断裂**：没有"这会怎样改变下次回应"，观点不改变回应方式就是装饰品。

## 二、观点 schema（数据层强制）

| 字段 | 含义 | 买到了什么 |
|---|---|---|
| claim | 主张（≤24字） | 不变 |
| **encounter** | 什么处境下形成的 | 检索锚点；处境限定优先于概括 |
| **facts** | 处境中发生了什么（原因） | 事实层，与解释分离 |
| **interp** | 解释 + **来源四值枚举：用户 / 推断 / 捐赠 / 经历** | 解释的可审计来源——用户解释且她认可的 / 自己推测的（推理链即据）/ 捐赠收养的（v0.3）/ 经历消化的（v0.2） |
| **missing** | 没看见的与不确定 | 盲区，不止置信度 |
| **next_response** | 会怎样改变下次回应 | 行为承诺——观点→行为的闭环挂钩 |
| evidence | 可追溯依据 | 不变（A01 逐字校验） |
| **maturity** | 状态：先验 / 验证 | 成熟度显式化 |

**分层要求**：思辨消化与重要观点全 schema；轻量先验强制四项（claim / 来源 / 可追溯 evidence / missing），其余可选。**防通胀：按处境触发形成，不批量预生成**。

## 三、生命周期（状态机）

```
先验（prior）──第一次相关经历──► 验证（verified）──新论据（P2 门控）──► 修订（曾以为）/ 退役（墓碑）
   │                                            ▲
   └────────── 经历证伪 ── 轻门控直接修订 ────────┘
```

- **先验形成三条路径**：对话中即时形成（遭遇新话题）、搜索形成（依赖需求四）、询问用户形成（用户回答即 user_view 证据）；
- **先验→验证**：思辨时携带在库先验（含 encounter 与 next_response），对每条给出裁决——证实 → 状态翻为"验证"；**证伪 → 轻门控直接修订**（事件本身就是新证据，只过 A01 出处校验，不过"新论据差集"门控）——先验被现实打磨是成熟，不是翻案，不丢人；
- **验证→修订**：P2 修订门控照常（需新论据差集）；
- 捐赠收养的观点天然是**先验**（"尚未经自己的经历检验"标注的正式化）。

## 四、next_response 行为闭环

思辨时做**兑现检查**：相似处境再现（触发思辨的事件与某先验的 encounter 相关），把旧观点的 next_response 带进 prompt，问三选一：兑现 / 未兑现 / 无从判断。兑现 → 观点加强；未兑现 → 裂缝本身是认知材料（写进 missing）。被压测时她守的不只是命题，是一种回应方式。

## 五、A01 校验的推广（不是放松）

证据类型枚举：**{事件记忆、网络材料、用户话语、演绎}**。每条证据仍须可追溯：记忆标题（现有逐字校验）/ 来源与摘要 / 对话轮次 / 推理链说明。"禁止无中生有"不变——先入为主 ≠ 无中生有，**先验的据是推理链，推断字段本身就是**。素材≠指令红线延伸到网络证据。

## 六、实施落点

- `store`：stance content 格式扩展——`遭遇：/事实：/解释：{来源}——{说明}/不确定：/下次回应：/出处：/状态：` 行式字段（无需改表结构）；
- `thought.py`：DELIBERATE_PROMPT 新 schema + `verifications` 输出（先验裁决+兑现检查）+ 先验验证/证伪路径 + `_render_stances` 渲染状态与下次回应；
- `persona.py`：捐赠收养的 stance 内容改新格式（状态：先验）；
- 兼容：旧格式 stance（v0.2/v0.3）不迁移，渲染与解析容错（无状态行视为成熟）。

**实施细节**（超出设计稿的部分，以代码为准）：

- schema 以行式字段存 stance content（`遭遇：/事实：/解释：{来源}——{说明}/不确定：/下次回应：/出处：/状态：`），不改表结构；
- 证伪为**两段式**：先标记（状态：证伪、下次回应改为证伪说明），同批 replaces 后继接走"曾以为"脉络（墓碑记"先验被经历证伪并修订"）；无人接棒则收尾扫除（墓碑留教训与依据）；
- `store.update_memory_content` 新增（先验→验证的原位状态迁移，不做删除重建）；
- `_render_stances` 渲染成熟度标记（先验·未验证/验证）与下次回应简注；旧格式视为成熟；
- 配套分寸机制（同期落地）：宪法"诚实≠透明"条款、分寸元先验（`_ensure_meta_prior`）、提取器行为-反应配对事件——设计哲学 v1.3。
