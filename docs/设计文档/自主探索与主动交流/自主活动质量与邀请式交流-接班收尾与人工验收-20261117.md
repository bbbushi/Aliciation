## 1. 本轮修正

| 位置 | 实际改动 | 原问题的影响 |
| --- | --- | --- |
| 进展回执 | 先检查幂等回执；结束状态随回执一起保存；执行账本按真实 substantive_progress 记值，首条执行晚于收尾落库时也读取真实值 | 原实现任意收尾都将账本标为有进展，等待状态仅出现在返回对象，重读会丢失 |
| 后台循环 | 成功提交 activity_finish 后结束当前窗口，不再付费生成一句收尾；回执缺失仍保守补记 | 原实现提交收尾后仍能继续模型循环和工具操作 |
| 等待 | source/material 都可映射 waiting_source；WAIT 必须有条件；无关新来源包不再机械解锁所有 waiting_source | 原反向字典把同一状态对应的两种等待类型折叠错了；新包不等于相关证据 |
| 依据与限窗 | 旧 AI 原话只计工作版本，不计用户外部依据；无问题 ID 的自由兴趣/迭代也按同一外部材料限窗；显式关联沿用目标真实问题族 | 防止通过回读自己、空任务、子问题获得不受限的重复推演 |
| 发呆 | 修正公共服务的计数参数；显式任务清除发呆；面板休息请求让正在运行的窗口在下一边界让位；请求时长不超过设置 | 原独立服务调用签名不匹配；显式任务可能被发呆计时挡住 |
| 邀请准备/投递 | 核对当前会话、引用版本、可用来源和单一待回应邀请；失效的待发邀请转撤销；相同主题/问题不能新建重复意图绕过冷却 | 原实现仅在准备阶段限制待回应数量，准备的多条邀请仍可能依次投递 |
| 延期再邀 | 后台索引提供最多 5 条可重新判断的意图；contact_propose 增加 intent_ref，重新准备沿用原意图 | 原只有新建意图入口，延期后无法由模型复用原意图重新发起 |
| 接受/展开 | 真实 channel_requests 核对当前用户轮、请求、渠道和会话；正文载入和最终落库均绑定本次请求；接受后把依赖接入现有来源校验 | 只检查某个 user 轮次存在不足以证明它属于当前请求；正文依赖不能丢失 |
| 撤销/计次 | 结束意图同时撤销未发和待回应尝试；已实际投递无论之后撤销与否均计次数；超时不将已关闭意图复活 | 撤销不能退回实际投递额度或造成幽灵邀请 |
| 来源保护 | 来源衍生的邀请本身也绑定来源许可；正文展开前再次核对引用 | 邀请虽然简短，也可能包含来源衍生标题 |
| 迁移 | 计划绑定实际内容/版本指纹，变化后需重新准备；执行核对会话与合同；保留旧 message 原文，仅改状态 | 原随机计划 ID 不绑定当前对象，且迁移清空旧正文，不符合保留历史原则 |
| 公共接口 | 修正 ForegroundAssembler 仓库接线、枚举和值对象构造；配置门面校验修订号并更新修订；快照含分数 | 骨架与具体适配的字段/参数未完全对齐 |
| 可观测性 | 疑问详情显示等待、依据版本、族窗口余量；探索详情显示完整结束回执；已采纳观点列表仅显示当前版 | 人工验收需要能看到实际回执，不仅看自然语言总结 |
| 时间边界 | 当前进程窗口同时检查单调时间与墙钟截止 | 补系统睡眠后单调时钟可能停走的边界；不宣称已解释首夜全部超时 |

## 2. 当前使用入口

在“设置 → 思想与探索”操作：

1. 主区切换清醒/睡眠，或让 Alice 休息一会儿。清醒不等于一定调用模型，还要满足时段、权限、额度和可推进条件。
2. 配置内设置发呆时长、同依据推演窗口、邀请等待和再邀间隔；三个工作模式的时长与工具权限保持独立。权重只读，没有用户基础偏好。
3. 展开“调度与权重详情”看实际分数；查看疑问详情看等待条件和窗口余量；查看探索记录详情看执行和结束回执。
4. 展开“邀请与联系意图”看每次尝试。面板仅提供稍后/拒绝；接受通过真实聊天自然语言完成，不用面板伪造一个用户轮次。
5. 旧待发全文停留在历史区域。需要继续使用时，先“准备旧联系迁移”，核对计划后“执行迁移”。之后还要由 Alice 重新准备简短邀请，不立即投递旧正文。

未回复的邀请到期不发催办。后台索引只有主题和状态；正文在真实接受后载入。用户明确主动问起某个主题时，正常回答路径保留，不强迫再次邀请。

## 3. 数据与降级

**资料容器格式 v1 和自主活动业务合同 autonomy-v2 是两件事。** 新表为加性 v2_ 表，现有备份会保留整个数据库，新代码不用把 profile-maintenance/updater 的格式声明伪装为 v2。迁移计划中的 data_format 已改为真实容器格式 1。

旧核心可以读取旧表，但不能理解 waiting_permission/budget、当前观点指针和邀请状态。不能因为 SQLite 可以打开就声称原地降级行为兼容。本批仅按向前升级交付，不支持旧包继续使用已经迁移/写入新合同的同一份资料。若回退，正常退出后用既有维护流程恢复升级前备份，再运行对应旧包。实际恢复和中断撤销仍沿用此前暂缓状态，本轮未执行。

迁移是面板显式操作，不在启动时批量重写资料。原 memory/turn/question ID 与来源依赖不删除，旧联系全文保留供历史回看；失效来源仍受原清理机制处理。

## 4. 人工验收顺序

所有行当前为“待真人”，用户之前通过的 v1 睡眠两项不自动算作 v2 回归通过。

| 顺序 | 真人操作 | 观察与取证 |
| --- | --- | --- |
| A | 正常备份、安装新包，打开思想面板 | 版本 0.1.11；人格/历史保留；清醒与权限不自动放大 |
| B | 睡眠时先不操作，再发普通问候及明确任务 | 自动工作不启动；前台正常响应，显式任务不被发呆挡住 |
| C | 清醒并允许有限额度，进入发呆 | 显示计时；模型/工具调用不增长；发消息可响应；到期只重新判断 |
| D | 允许同一材料上的实际推演；观察窗口余量 | 写入/润色不冒充新依据；达到窗口数后不再自由换题/空任务逃逸；详情可查回执 |
| E | 阶段成果还有用户反馈缺口，再发无关问候 | 保持 waiting_user；新观点或无关消息不自动重开。相关反馈后由模型明确更新 |
| F | 修订同题已有观点 | 当前版移动、旧 ID/历史保留；思想列表和普通上下文不重复注入旧版 |
| G | Alice 准备并实际投递邀请 | 只有一句邀请；实际投递才计一次；同时至多一个待回应；未接受看不到正文 |
| H | 自然语言接受，之后检查实际记录 | contact_reply 绑定本次真实消息；正文材料载入；展开回执绑定该请求的真实 assistant 轮；不另计主动联系 |
| I | 分别测试没空、明确拒绝、无回复超时 | 不继续展开或催办；拒绝结束意图；超时静默延期；下一合适机会重判，不到点机械重发 |
| J | 面板结束一个待回应意图；更新一次相关材料版本 | 邀请撤销；原投递额度仍占用；失效旧引用不能展开，须重新准备 |
| K | 准备旧联系迁移，中途改变对象后执行 | 旧计划失效；重新核对后执行；旧正文仍可回看、不自动投递 |
| L | 正常退出重开，再检查待回应/超时/当前观点 | 不重放未知网络结果或重复投递；期限和版本可追溯 |
| M | 系统睡眠/唤醒、慢网络与连接中断 | 边界超时停止下一步；在途调用仍可能晚返回，不冒充可立即杀死；记录墙钟/实际调用次数 |

建议逐项提供时间、运行 ID/邀请 ID、面板回执与真实聊天表现。不要只用 Alice 的文字自报判定宿主行为已通过。

## 5. 静态检查及明确边界

本轮进行了 compileall、原生 JS 语法、JSON 解析、模块导入、类型注解解析、数据类调用签名 AST 核对与 diff 空白检查。没有实例化业务服务、运行临时 Store 行为测试或调模型。上一棒设计记录中提到的 14 项开发验证是上一棒所做，不作为本轮或真人验收通过证据。

后台等待事项采用保守路径：等待状态不被任意新资料机械唤醒，相关性在正常前台/后台模型已得到相关材料后由显式 thought_update 决定，不额外增加一个固定审核模型调用。聊天内“现在聊”按钮不是本批依赖，接受用自然语言；面板稍后/拒绝入口已接。

ForegroundAssembler 是可用的公共业务投影；当前 ThoughtSession.initial 仍保留既有索引装配入口，以避免同时改动两条前情/观点选取路径。两者都只提供邀请索引，正文必须通过接受路径。不声称已经统一到唯一装配函数。
