# 联网搜索：主开关 + 分步设置向导

2026-11-24，用户提议「联网搜索页要么也按照这种方式修改？」（与 2026-11-22 的[思想与探索](./思想与探索-主开关与分步设置向导-实施与人工验收-20261122.md)同一方式），核对后施工。设置部分改为：主开关即时生效、首次开启走分步向导、已配置过直接开启、「更改设置」重开向导；分类导航、底部保存条与脏草稿机制移除。

## 实施

- **主开关 = `settings.enabled`**（文案沿用「允许内容访问」——它在后端同时管聊天查找、自动带出资料和手动寻找，比「联网搜索」准确）。拨动即生效：设置卡上的开关与「内容发现」面板的开启/暂停链接共用 `toggleEnabled()`。开=清醒、关=睡眠那套按钮没有对应物，这里原本就只有一个 `enabled`。
- **首启判定 = `settings_archived`**（`alice/discovery.py` 快照新增只读字段）。**不能照搬思想页的「键是否存在」**：发现配置行初始化时就以出厂默认落库，平台开关、兴趣保存、迁移都会抬版本号。规则是：
  - 档案首次加载且没有 `discovery_settings_saved` 时，用合并默认值后的配置作一次旧档案判定。出厂配置记为未完成，已有自定义配置记为已配置。
  - 向导最后一步提交时带 `configured: true`，后端在保存配置的同一事务内写完成标记。
  - 平台开关、兴趣和平台访问方式仍可即时保存，向导完成状态独立记录。
- **向导**（`web/discovery.js`）：旧的五个分类原样成为五步，顺序不变——使用与安排 → 平台与兴趣 → 费用与额度 → 资料与使用 → 网络与访问。面板内呈现，复用开始引导的进度点（`AliceUI.wizardProgress`）与 `.wizard-actions` 按钮组。每步一页；上一步/跳过都把当前步恢复到**进入这一步时的值**（进入时记下该步控件的快照），只有「继续」确认过的修改会带到后面。
- **三流**：未配置拨 ON → 首启向导，最后一步「保存并开启」一次提交完整设置；已配置拨 ON → 直接写 `enabled`，提示按上次的设置开启（模型许可不满足时改为落到「费用与额度」那一步）；「更改设置」→ 编辑态向导（预填当前值），最后一步「保存设置」，**不动开关现状**。放弃、关窗、切到别的分区都不保存设置。
- **深链落步**：这页原有大量「去改某项」的入口（「选择平台」「查看额度」「调整费用与额度」「设置回帖阅读」、校验失败的字段…）。现在带目标的入口一律打开编辑态向导并落到目标所在的步骤；保存时若某一步的值有问题，会跳回那一步并聚焦到字段。

## 与思想页的三处不同（都是这页的结构决定的）

1. **平台与兴趣是即时保存的，不进设置草稿**——它们各有独立的接口（`platform` / `interest`），兴趣还是列表式增删改。所以向导中途放弃时，已在「平台与兴趣」里保存的平台和兴趣会保留（放弃提示里写明了）。它们抬高的版本号由前端跟上，不算外部冲突。
2. **没配置过也能进向导**：思想页在无留档时隐藏「更改设置」，入口只有拨开关；这里「更改设置」同样隐藏，但上面的深链会打开编辑态向导——否则「内容发现」面板上的引导按钮就没有去处。
3. **主开关沿用本页原有的开关样式**，没有换成思想页的滑动 toggle。

## 兼容边界（未改）

发现设置的 API 只增不改：快照多一个 `settings_archived`，`settings` 动作多一个可选的 `configured`。`desktop_host`、`tests/`、`lab`、`autonomy_v2`、TUI 均未触碰（全仓核对过，没有模块依赖被移除的界面元素）。旧档案：配置偏离过默认 → 视为已配置，直接开启。

## 验证

- 静态：`node --check web/discovery.js`、`python -m compileall alice/discovery.py` 通过。
- 首启判定离线核对：用与初始化迁移同构的归并逻辑确认「全新档案（含迁移与落盘往返）== 出厂默认 → 未配置」；仅拨开开关、旧版改过额度 → 已配置。
- 隔离实例全流程（`user/` 副本起 8821，真实档案零改动；副本预先把自主活动改为睡眠、发现配置重置为默认）：
  1. 未配置初始态：开关 OFF、「更改设置」隐藏、向导收起；分类导航/保存条/保存按钮均已不存在；
  2. 拨 ON → 第 1/5 步，进度点与标题聚焦正常；
  3. 五步走完：第 2 步开平台、加兴趣即时保存（版本号 2→4，未造成误判冲突）→「保存并开启」→ 开关 ON、`settings_archived` 真、标记落库、未改动的项保持默认；
  4. 上一步/跳过的还原：第 3 步改 18 后上一步 → 回到 120；跳过的第 4 步值不变；
  5. 关 → 暂停；开 → 直接按档案开启，不进向导；
  6. 更改设置 → 预填正确，保存后开关保持开启；
  7. 放弃：改 99 后放弃 → 未入库；关窗：改 77 后直接关设置弹窗 → 未入库、向导收起；
  8. 深链：「调整费用与额度」落第 3/5 步；面板「平台与兴趣」落第 2/5 步；
  9. 校验：选 SearXNG 不填地址 → 保存被拦在本步；第 4 步填换算不足 1 字节的值 → 到第 5 步保存时跳回第 4 步并聚焦；
  10. 冲突：向导打开期间外部抬版本号 → 最后一步保存变灰、说明出现、修改保留；
  11. 全程零 JS 报错。

## 验证中发现并修掉的问题

1. **编辑态保存把开关关掉了**——保存前开着，保存后变成关。原因是最后一步把开关值写死成了「关」。改为：首次开启才打开开关，编辑态保持现状。
2. **冲突时按钮变灰却没有解释**——旧界面的草稿提示被移除后没补上。加了说明行。
3. **校验失败的原因一闪而过**——提示写在页首状态行，而那一行每轮轮询都会刷新（实测 8 秒后被刷成「等待下一次合格活动」）。向导内另加一条不会被冲掉的提示行。
4. 小窗口模式下向导容器本应不限高，但基础规则带了 id 选择器压过了覆盖规则（当时没出问题只是碰巧）。提高覆盖规则的优先级。
5. 清理：轨道主题样式表里针对旧导航/保存条的规则、「从聊天中整理兴趣」说明里对「底部设置保存」的指代。
6. 首启向导内开启平台后放弃，下次拨开关误走直启。原判断每次都比较当前配置与出厂默认值，平台即时保存也会改变比较结果。现在只在档案首次加载时推断旧配置，之后以持久化的向导完成状态为准。

## 待真人验收

1. 你自己的档案：发现配置是出厂默认、没有兴趣，所以会被判为「未配置」——第一次拨开关应进向导；
2. 首次开启逐步填写、即时保存的平台与兴趣、保存后「内容发现」面板的引导提示是否衔接顺畅；
3. 「更改设置」改值后的实际行为；关→开的直启提示；
4. 深链落步的手感：从面板的引导按钮进来、改完走到最后一步保存，是否嫌路长；
5. 桌面 App 与窄屏下的滚动和按钮可达性；轨道投影环页面内逐步操作。
