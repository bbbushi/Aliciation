## 2. 思想与成果合同

主要界面仍是“未解决的疑问”和“已采纳的思辨”。已解决、关闭的问题可展开历史，不作为每轮常驻材料。旧观点未被批量改写。

| 模型命令 | 实际作用 |
| --- | --- |
| `thought_search` | 检索疑问和观点索引，返回真实引用 |
| `thought_load` | 展开疑问进展或观点正文 |
| `thought_record` | 轻量收纳疑问；精确重复返回已有记录 |
| `thought_update` | 保存进展与下一步，等待用户/资料、搁置、关闭或重新打开 |
| `thought_resolve` | 原子关联结论与问题；可保存 stance、知识事件，或不保存长期成果；支持部分解决 |
| `contact_propose` | 保存反馈、询问或分享意图，返回尚未送达的真实状态 |
| `contact_update` | 读取意图，并由 Alice 判断准备、采用到当前回应或取消 |

观点修订使用已展开的真实观点引用和理由；保存修订关系，不要求为解释纠错伪造新增事实。新思辨标为先验/尚未独立验证，当前采纳不等于事实已证实。

普通记忆、见闻和思想保留实际依赖。涉及外部来源的思想正文、联系内容和探索检查点纳入来源容量计量；来源失效时立即停止投影，空闲清理再去除失效副本。归档前清理新表中的临时外部正文。

## 3. 探索执行

后台使用当前聊天模型及人格投影，可使用本机记忆、历史、思想、按需人格读取和已开放的搜索。这里的工具都是现有能力层实际暴露的工具，没有扩展任意程序执行或任意联系人范围。

没有用户发言时，探索上下文以自主运行状态与实际资料组装，不创建虚构的用户轮次。Alice 可以返回没有值得继续的事情。没有新增材料且没有活跃问题时，自由好奇机会最多每六小时重新考虑一次。

候选按最近被提供的时间轮换，避免只展示新问题；实际选题仍由 Alice 决定。等待用户的问题在新增用户材料后可以重新提供以供判断，不由宿主认定用户已经回答。

在每次模型调用、工具步骤和提交边界检查前台活动、会话、材料、人格/配置与问题版本。I/O 不持有数据库长写锁。检查点保存可恢复的显式行动与回执，不保存原始思维链。

暂停后继续提供新鲜索引，旧工具调用没有回执的部分不直接重放。在途模型/外部工具遇到进程中断时标为结果未知。未知状态没有自动继续入口；可以查实际记录，再显式开始新的探索。

探索检查点正文最多 120000 字符，非运行中的旧正文保留最近 30 次且最长七天，事件最多 2000 条；问题和成果关系另行持久化。观测 SDK 的上下文正文沿用原有滚动留存。保留期以外的运行不能承诺从完整旧正文恢复。

## 4. 主动交流与实际渠道

| 方式 | 首版行为 |
| --- | --- |
| 下次聊天提起 | 提供少量待联系索引。Alice 读取后结合当前目的决定采用或取消；采用结果关联实际已保存的回复，标记为材料已采用，不声称用户已读 |
| 站内主动消息 | 服务空闲且设置允许时，原子写入独立 assistant 消息与联系回执；网页已有历史轮询会同步，无需创建假用户回合 |
| QQ 主动投递 | **未接入**，状态明确返回不可用；现有 QQ 被动回复资格不当作主动发送资格 |
| 系统/浏览器通知、应用退出期间运行 | **未接入**；关闭页面后仍运行的服务可写入站内历史，但不承诺弹出通知；服务退出后不运行 |

每条消息有稳定联系身份；数据库事务保证站内不重复插入。用户或问题出现新变化后，待发消息转为需要 Alice 重判。真正的外部通知将来需要相应适配器与投递协议，不能复用站内成功来宣称已经实现。

站内主动消息有独立来源标记，进入历史时仍是 Alice 发言。上下文可保留独立主动发言；提取时标明不是用户要求或承诺。普通 compact/历史检索的完整往返合同仍只覆盖真实请求，独立主动发言不伪装成一个已压缩用户往返。

## 5. 设置与首版默认值

新增设置保存在当前本机数据库 meta 中，带会话身份与配置修订号。没有修改用户配置文件。重置会话不自动迁移旧探索与待发消息。

| 配置 | 首版默认 |
| --- | --- |
| 空闲自主探索、允许探索模型、允许外部读取、主动联系 | 全部关闭 |
| 联系方式 | 下次聊天提起 |
| 每日后台模型调用预约上限 | 12 |
| 单次探索窗口 | 4 次模型、12 步工具、180 秒；在途调用在检查点让位 |
| 开始前空闲、运行间隔 | 120 秒、1800 秒 |
| 探索时段、可联系时段 | 北京时间 09:00–22:00，各自设置；起止相同表示全天 |
| 主动联系 | 每日 2 次，冷却 3600 秒 |
| 活跃疑问容量 | 500 条；接近上限时由 Alice/用户合并或关闭，不自动伪称解决 |

数值是首版可调初始值，未经真人校准。每日模型数是预约账本，调用结果未知仍占用；不是精确费用金额。允许探索模型后，维护/内容发现后台调用共用额外模型上限，原有平台及发现额度继续适用。前台普通回复不计入这个后台额度。

自动探索关闭时仍可显式运行一轮，但需要允许使用模型，并遵守同一额度。新模型循环不增加每轮聊天的固定审查请求。

## 6. 公共接口与观测

- `ChatService.thoughts("status")`：只读快照，不启动模型、恢复任务或投递消息。
- `GET /api/thoughts`：本机 GUI 意图 `thoughts`，返回设置、双区索引、运行、联系和事件。
- `POST /api/thoughts`：同源 JSON，`action`、`session_epoch` 及操作字段。支持 `settings / record / question / run / resume / pause / cancel / contact_cancel / detail`。
- 设置写入带 `revision`；问题修改带 `id/version`；恢复运行带 `run_id`；读取详情不调用模型。
- 忙碌、会话改变、修订冲突和无效参数分别返回真实状态，不自动重发付费运行。

观测器按探索 request ID 记录真实模型输入与工具参数；思想页面提供工具回执检查点和元数据事件。正文留存不足会失去展开能力，不把未留存伪装成没有发生。

5. 探索过程中发送真实用户消息，观察前台能否响应，后台不开始新步骤；明确暂停后不自动继续；再显式继续，对照账本检查没有重放未知操作。
6. 让 Alice 对已有思辨形成有理由的修正，先展开原观点。确认修订关系、原始依据和当前未验证状态；“采纳办法”没有被记成“办法已经有效”。
7. 开启空闲自主探索，设置可承担额度，观察没有用户新输入也能推进或选择不推进。等待用户的信息缺口不能变成周期性催办。
8. 另行开放所需平台及外部探索，观察实际搜索、读取和来源依赖。撤回来源后，新思想投影和检查点正文停止可用。
9. 开启主动联系、选择下次聊天。让 Alice 提出值得稍后谈的实际进展，下一次对话可以采用、延后或取消；只开页面不伪造用户消息。
10. 选择站内主动消息，保持服务运行。对照联系 ID、独立消息 ID 与历史回执；用户未回复时不反复换措辞重问同一问题。
11. 在消息待发时补充答案或改变相关条件，观察转入重判，由 Alice 决定取消或更新。更改时段、频率和联系开关后核对实际送达。
12. 重启后检查正常暂停与结果未知的区别；换会话后旧任务和消息不进入新会话。对照 `next_chat / gui / qq` 能力状态，QQ 不可用不得被说成已经通知。

长期价值、选题质量、风格和联系频率需要持续真人观察，不能在短轮次内宣称稳定通过。原有未通过的人格与互动问题继续保留。
