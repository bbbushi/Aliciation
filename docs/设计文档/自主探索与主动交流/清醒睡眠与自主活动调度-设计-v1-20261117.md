# 清醒、睡眠与自主活动调度 v1

2026-11-17。依据用户确认实施；先完成本设计，再修改代码。真实行为只做人工验收。

## 1. 目标与约定

Alice 有清醒和睡眠两个运行状态。睡眠时不自主探索、反省或主动投递消息，用户发起的聊天和显式任务照常处理，处理后仍是睡眠。清醒且空闲时，在兴趣探索、问题思考、自我迭代三种模式之间动态选择。状态是运行许可，不表示模型在两次调用之间持续思考。

用户设置状态、清醒时段、三种模式单段最长时长、各模式可使用的工具组，以及共享模型/工具/时间预算。**不提供基础偏好或模式权重配置**。模式时长为上限，可以提前完成；设为 0 暂停该模式，不强迫填满窗口。时长不替代模型调用额度。

## 2. 状态与兼容

`wake_state=awake/sleeping` 是显式状态；现有 `enabled` 仅为旧接口兼容别名，读取派生、写入同步，冲突拒绝。旧资料无新字段时由旧 enabled 推导，不自动开启费用或工具。清醒时段继续使用 window_start/end（北京时间，起止相同为全天）；请求清醒但时段外的有效状态为睡眠。

运行进度另行显示：待机、前台忙碌、等待空闲/间隔、等待模型许可/额度、模式关闭、排队、执行中。排队不等于执行。切换睡眠时排队的自动任务暂停，在途调用不能强杀；返回后先保存真实回执，再停止新的行动。用户显式运行/继续一轮可在睡眠中完成该任务，不改变清醒状态，也不据此开放主动投递。

三模式共用现有后台执行位，不建立三个 Agent。旧发现模块的自主选题、自动读后反省由此统一入口接管，保留手动发现与聊天搜索。定时清理等无模型维护继续；睡眠时自动 compact/tidy/反省等待，显式维护任务仍可执行。应用退出不运行，不增加开机唤醒服务。

## 3. 内容与权重

事项仍以思想层疑问为主，可由 `thought_record/update` 提供轻量调度元数据：activity（interest/problem/iteration）、importance（0–3）、urgency（0–3）、due_at（Unix 秒，0 表示无期限）、schedule_reason（短理由）。模型判断内容价值；宿主只校验类型、范围、引用、等待状态和实际许可，不从文本猜“重要”“紧急”。元数据是 Alice 的评估，不是已证实事实。

默认归属：interest/exploration 来源→兴趣，review→自我迭代，其他→问题。已有条目没有元数据时采用同样规则，默认 importance=1、urgency=0。用户明确任务按事项加优先级，不转成长期模式偏好。等待用户/资料的事项在材料更新前不入候选；进入候选仅表示可重新判断，不表示用户已经回答。

三模式共同起点为 1。每个模式内容分数取其最值得推进事项的分数，不把重复堆积问题变成权重优势：`1 + 2*importance + 2*urgency + 截止接近度(0/3/6) + 用户委托(4)`。临近期限定义为未来 24 小时加 3、1 小时内或已到期加 6；等待条件仍优先。

历史补偿按真正开展活动记录：执行过的模式债额归零、其他模式加 1（上限 6），上一执行模式再乘 0.55；最终权重为 `(内容分数 + 债额) * 最近执行系数`。普通情况按权重抽样；明确临近期限/当前可推进用户委托优先于普通抽样，仍保留同级轮换。高价值进展可抵消最近执行降权，允许连续推进。

模式内优先最高分事项，相同分数先选较久未考虑的事项。没有事项时，兴趣探索可以基于实际兴趣目录或每六小时一次的自由选题机会；自我迭代在新增对话/记忆后可提出改进问题。问题思考无疑问不启动。兴趣和自我迭代仅用弱起点，不由宿主替其编造任务。

只有有效模型结果/实际非拒绝工具行动才记轮换补偿；选中后因权限、前台活动、资料版本等未开展则不算执行。没有新输入也没有保存进展时，同模式冷却六小时；有实际写入进展则按通常间隔可重选。等待不通过反复改写同一结论制造新工作。

选择快照保存每种模式分数、入选事项、选择理由、实际工具列表、开始/截止时间、是否计入轮换、冷却与结束原因。页面读取不抽样、不更新补偿、不调用模型。

## 4. 权限、预算与执行

每模式 `seconds` 为 0–86400；`tools` 允许 memory/history/persona/sources/search 五个固定读取组。思想记录工具保留用于登记进展与联系意图；不因此开放任意执行、改写代码或修改自身权限。默认本地读取组开启；兴趣模式含 search 候选，仍需全局 allow_external 和现有平台授权同时允许。用户可为其他模式开放搜索。

实际暴露工具为模式允许组与现有能力/权限的交集；未暴露工具调用由统一能力校验拒绝。全局每日模型额度与单轮模型/工具步骤额度沿用，三模式不分别重置；单段实际时限为 min(run_seconds, 模式 seconds)，恢复是新窗口，累计实际调用仍记录在原运行。前台任务优先。

后台搜索继续要求内容发现总许可与逐平台许可；失败文字明确当前后台条件，不再把 GUI 后台拒绝解释成 QQ 缺许可。自我迭代用现有观点/疑问记录可执行的调整，不获得编辑系统规则的工具。

## 5. 上下文与结果

后台上下文增加当前有效状态、所选模式、目标引用、调度评估、实际工具和本窗口预算。给出该模式的简短目标。兴趣目录为索引；正文按需读取。表达策略可以直接形成；用户动机、历史事件、实际试错次数依据真实记录。区分观察、解释和拟尝试调整，产出是可追溯摘要而不是原始思维链。

模式时限内仍走现有模型工具循环/检查点。已完成、部分进展、等待用户、等待资料、无值得保留内容分别如实记录。主动交流另受联系许可/时段/频率控制，清醒不等于必须发消息。

## 6. 存储与公共面

新增 `thought_agenda`（疑问调度元数据）、`autonomous_activity_runs`（模式、选择快照、输入戳、时限）和 `autonomous_activity_executions`（每个实际执行窗口的轮换与进展回执）三张可选扩展表，随思想层 schema 创建。恢复窗口实际执行后才新增轮换记录，不覆盖原执行历史。原表/原字段不改，旧程序可继续读取原资料，旧版不会执行新调度。属于格式 v1 的加性扩展；备份按原整库合同包含新表，部署不修改格式主版本或跨文件协议。回退旧版本会失去本版睡眠与模式语义，应先停用自动活动，不承诺行为兼容。

沿用 `ChatService.thoughts` 与 GUI `/api/thoughts`，设置仍携带会话与修订号。快照新增 lifecycle/scheduler；运行列表及详情增加 activity/selection。模型侧只扩展既有 thought_record/update 参数，注册表与 SDK 同源；宪法只增加必要运行事实，不加入设置教程。

## 7. 界面与验收

思想与探索主页显示有效清醒/睡眠、当前执行或等待原因、明确的切换按钮。时长与工具选择收在设置，权重与选择理由收在调度详情；不把大量数值铺到主页面。保存与立即状态切换均保留修订冲突保护，不覆盖未保存草稿。

人工验收：睡眠闲置无自主调用/消息；睡眠可聊天和显式任务且不自动清醒；清醒三模式按内容选取；执行后权重变化、未执行不变；紧急问题提升但等待用户不空转；每模式时长/零时长/工具权限实际生效；额度耗尽与排队明确；清醒时段边界、前台让位、睡眠中途暂停、重启恢复和旧数据迁移；关闭模式不自动重放未知结果。真实模型探索质量、长期公平性与人格表现仍需持续人工观察。
