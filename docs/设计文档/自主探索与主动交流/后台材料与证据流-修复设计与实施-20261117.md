# 后台材料与证据流修复

2026-11-17。根据晚间真实记录评估施工。只改变后续运行合同，不删除旧来源、修订旧观点或伪造真实经验。

## 设计

1. **目录、任务摘要、旧正文分开。** 疑问/观点目录只签发引用与检查资格，不将所有候选的依赖并入本次正文阅读集。thought_load默认task：只读原始任务题目与调度状态，旧进展/推测/出处正文须显式full。full才绑定完整旧依据；旧出处仍存原问题、始终检查其资格。新任务不再因目录吸入无关来源；已有问题与观点的历史出处和保存许可继续核对，包括未展开的旧依据。旧题若本来带不可保存来源，成果仍可能被拒，不能由模型自由声明“此段不依赖来源”来解除，也不自动修订旧库依赖。
2. **目标锚点。** 宿主固定本窗口的原问题与来源类型，作为task_anchor随运行材料提供；材料使用说明不是任务目标。“零候选”“受限未返回”“未读”“不可保存”分开处理，阻塞以条件和下一步收尾，不据此宣布原目标不存在。模型是否正确理解目标仍需真实复验，宿主不以关键词猜测语义。
3. **证据按真实载入对象解析。** 精确引用不接受附注；memory须来自本轮实际loaded映射，history须实际loaded且版本仍有效，拆为user_message与historical_ai_speech两个真实轮次。自身观点可作为self_view参考，不充外部新证据。旧AI原话/观点不会自己解锁等待。
4. **真实动作回执。** 后台每次工具返回宿主绑定的action_receipt.ref（调用ID），收尾只接受本窗口真实成功回执；错误/被拦/未读不能冒充成功取证。无须用函数名或人工拼写动作描述猜ID。
5. **记录与活动自述。** 记忆展开提示按说话者和原始资格使用；历史AI自述可作表达样例，真实“在做/做过什么”取当前运行账本。任务材料明确提供当前窗口事实，不把语言风格限制为必须从真实经历生长。

现有许可、每日模型预算、工具组、来源保存资格和字符限制不放宽；资料库不迁移。已有被污染的观点只标为待用户审阅，不自动改写删除。代码完成后静态检查与构建，真实读/写/候选不占依赖等待新包复验；不新增机器行为自测。

## 实施完成情况

- thought_workspace：expose只有full绑定旧正文依赖，view_index不绑定正文；引用有效性仍检查版本/会话/来源，自己的观点修订退仓不自动视为失效；任务摘要默认不提供旧progress/reason/basis正文。状态提交回执返回目录，避免成功更新时又隐式展开旧推演。
- history证据由本轮loaded+issued及完整版本核对后拆分为用户/AI两个轮次；memory使用原样loaded映射，拒绝附注污染或伪造ID。self_view仅为推演参考，和historical_ai_speech均不作为新的外部证据解除等待。
- StoreEvidence核对真实版本、说话者、渠道与资格；比较新证据使用类型+ID+版本，避免记忆ID与对话ID相同被误认为同一项。
- 后台每次工具回执含action_receipt，搜索的外部不可信标记保留；动作核验支持此前带固定前导的JSON搜索回执，仍拒绝失败/被阻塞的动作成功声明。
- activity_finish写入等待时保留模型提供的next_step，避免收尾只改状态却丢失解除阻塞后的执行步骤。
- 目标与材料使用采用本窗口短说明、结构化原目标和结果身份；没有增加宪法长禁令。引用合同与thought_load参数同步能力JSON注册表v6。

## 必须保留的边界

目录不占正文阅读额度，不意味着旧资料的来源关系被删除。已有受限问题在保存成果时继续合并原题出处；旧题带memory_eligible=0时仍可能拒绝成果。真正的修复是后续新题不会被所有未读候选提前带入无关依赖，当前任务能够在不展开旧推演时腾出正文阅读空间。自动判定历史哪些依赖“其实无关”并删除，属于另一个需要可审阅证据的整理动作，本轮不做。

“保留目标”目前由宿主固定原问题题目、提供明确输入状态与短工作约定实现，不能宣称宿主已验证模型每条结论在语义上都正确；需真实任务观察。原有memory17、memory16没有删除或重写，旧自述是否事实/策略是否有效仍按原记录身份处理。

## 真人复验顺序

1. 新自动窗口仅列目录/读取task摘要时，确认packet_ids不再因所有候选变成8/8；在同一真实任务中查询新资料，检查真实返回/拦截原因。
2. 显式full旧推演时，完整旧来源依然绑定；受限或过期资料不因新路径绕过保存资格。旧问题保存仍可能拒绝，此时应准确说明而不改成“不存在/无需完成”。
3. 实际history_load成功后，用原样history ref提交activity_finish；确认不再报“来源须在本窗口真实读取”，用户与AI两种身份仍分开。原样stance/ref可作参考，不增加外部证据。
4. 使用工具返回的action_receipt.ref作为action_refs；函数名、检索任务ID、错误回执不能冒充成功取证。
5. 用户要求查素材人物时，确认仍围绕人物故事推进；人格材料使用边界不应被推成该人物不存在。普通活动自述取真实运行记录，不拿历史“卡带”发言当已经发生的活动或效果证明。
6. 既有清醒/睡眠/发呆/预算、前台历史读取、观点修订与邀请路径共存。

上述行为尚未在0.1.14真实验收；只做compileall、模块导入、JSON/注册表解析、数据类调用签名AST与类型注解静态核对、diff空白和打包检查。没有临时Store行为自测、假模型、模拟消息或真实模型调用。本轮未访问user/或桌面实际资料，未修改开关、额度、记忆与迁移，未启停App/服务。
