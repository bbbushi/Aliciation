## 实施范围

| 部分 | 实现 |
| --- | --- |
| 状态 | 显式清醒/睡眠、清醒时段与有效状态；旧 enabled 兼容映射；前台聊天不修改状态 |
| 活动 | 兴趣探索、问题思考、自我迭代；共用原后台执行位和探索工具循环 |
| 权重 | 内容价值/紧迫性/截止时间/用户委托加分，执行历史补偿、最近模式降权、按权重选择；不提供用户基础偏好 |
| 事项 | thought_record/update 可附活动、importance/urgency、due_at、schedule_reason；thought_load 与 GUI 详情返回评估 |
| 时间与工具 | 三模式各自时长和五组读取工具许可；窗口取单轮时间与模式时间较小值，共享每日模型、单轮模型和工具步骤上限 |
| 实际执行回执 | 有效的无工具文字回复或非拒绝工具结果才计一次轮换；恢复窗口独立记录；提出调用但未执行不算完成 |
| 等待 | 等待用户/资料的事项有新材料后才重新提供；同输入无进展冷却六小时；仅遇拒绝而未开展的窗口不改变轮换并等待条件变化或冷却 |
| 反馈 | 主页状态与切换；配置内三模式时长/工具；折叠调度详情、模式运行记录和真实工具列表；额度满时不把排队说成运行 |
| 共存 | 旧发现计时器只做无模型清理，选题统一调度；手动发现、聊天搜索保留；自动维护在睡眠等待，显式维护可执行 |
| 出处 | 调度理由沿用原问题依据，外部派生理由计来源容量，来源失效/归档清理理由；选择与轮换账本只保留 ID 和数值 |

## 文件与公共面

- 新增 `alice/activity.py`：状态、候选、内容评分、动态权重、调度存储；不执行模型或联网。
- `alice/autonomy.py`：实际调度/执行、时限与模式工具投影、睡眠阻止自动投递、运行详情。
- `alice/thought_workspace.py`：三张加性表、设置兼容、事项调度评估与来源清理。
- `alice/discovery.py`、`alice/dialogue_search.py`、`alice/discovery_memory.py`：统一自主入口、拒绝解释、来源容量。
- `alice/maintenance.py`：睡眠时自动任务等待，显式任务仍处理；调用和提交边界检查状态。
- `web/thoughts.js/css`、`web/discovery.js`：状态、配置、详情与旧入口反馈同步。
- 能力注册表 v3：扩展既有 thought_record/update 的业务参数；宪法 v5：必要清醒睡眠自我事实。没有新增任意执行或管理权限工具。

沿用 GUI `/api/thoughts` 与 `ChatService.thoughts`。设置保存携带 session_epoch/revision；新字段 wake_state 与 activities（固定三种模式，各含 seconds/tools）。weights 不是可写配置字段。旧 enabled 与 wake_state 同时写入且冲突则拒绝；旧资料只读取映射，不在本轮后台改写用户资料。

读取状态不会随机选择、更新轮换、恢复任务或调用模型。清醒时段起止相同为全天。睡眠时“现在探索一轮”和具体问题的显式探索属于用户任务；完成后仍保持睡眠，主动投递仍等待。

默认三模式时长为 180/180/120 秒；默认单轮总时长沿用 180 秒。默认允许本地记忆、历史、人格材料及已有来源读取；兴趣探索还列入搜索候选，但全局外部许可和平台实际许可继续验权，默认不新增开放。思想记录工具始终可用于留进度。

被拒绝的工具调用不计入轮换，但模型调用仍消耗实际预算。达到窗口上限后保留检查点；自动下一次按内容重新选题，不再无条件优先恢复最旧暂停运行。显式继续沿用原任务和模式并取得新窗口，原执行记录保留。

## 人工验收步骤（未明确通过的部分继续待验）

1. 使用新源码服务或安装含本改动的新包。进入“设置 → 思想与探索”，核对原资料清醒映射、费用与许可；界面载入不应新增模型执行。
2. 切换睡眠，等待超过原空闲/间隔；观察探索、旧内容发现、自动维护无新增模型调用，站内没有自动投递。非模型清理可以继续。
3. 睡眠时正常发消息，再显式探索某问题；确认可处理，结束后仍睡眠且不自行开展其他活动。显式维护与手动发现同样保留原许可检查。
4. 清醒时段内设清醒，开放模型许可并设置小额预算；观察首个活动选择，详情有三模式权重、选择理由、目标 ID、实际工具及时限。
5. 完成有效窗口后刷新：实际执行模式补偿归零，其他增加，上一模式有降权；仅排队/拒绝/前台中断而未开展不应记完成。
6. 让 Alice 为具体问题登记较高价值、紧迫性和真实截止时间，检查 thought_load/页面详情与权重一致；改为 waiting_user 后，没有新用户材料不再调度该事项。
7. 对兴趣和自我迭代分别使用新的真实兴趣/交流材料，观察是否围绕本模式开展工作；没有进展和新输入时等待，不反复改写同一未知。
8. 设置一种模式时长为 0，确认不再自动选择；设置短窗口检查边界停止与记录。模型在途可能超出截止，应显示暂停及实际已发请求，不能声称强杀或退款。
9. 关闭某模式的搜索或历史读取，确认工具清单没有对应命令。旧检查点属于历史，不自动重放。全局外部许可开但发现总开关关时，回执应正确说明后台搜索依赖。
10. 额度用尽后手动排队，确认“额度已用完”、无额外调用；继续旧运行时，旧窗口回执保留，未实际执行的新窗口不先记账。
11. 执行中发消息或设睡眠，检查让位、真实回执与待发消息；时段外显示睡眠，用户请求不自动改清醒设置。
12. 修改时长不保存，再用主页切换状态，确认只保存状态、其他草稿保留；多窗口修订冲突拒绝。关闭设置再打开、重启后状态/配置/记录正确。
