## 3. 需要处理的问题

### A. 旧来源依赖占满，实际形成推进阻塞

Q12、Q9的运行basis都携带同一组8个旧来源，已占满8/8。里面既有“客套話”“闲聊”，也有明显不贴当前题目的“閃電十一人系列角色列表”“习近平”“李登輝”“弗兰斯·米歇尔·彭宁”。8份均memory_eligible=0、未撤销、有效期约3天。

实际搜索回执不同于“没搜到”：

- Q12：received=3、readable=1，但returned=0，1份因source_dependency_limit未给模型。
- Q9第一次搜索确实零候选；第二次received=20、readable=2，但returned=0，2份同样被依赖上限拦住。
- 两个thought_resolve都返回“来源当前不允许保存成果，疑问保持不变”。拒绝保存是资格约束生效，不能改成放宽许可来掩盖。

因此并非主要缺少思考时长，而是旧依赖既占新阅读位置，又使本轮成果受不可保存资格约束。等待“额度恢复”也不精确：这是每请求依赖集合上限，不是日模型额度，下一轮带同一组来源仍可能卡住。

优先方向：区分出处保留关系与本轮实际阅读集合，按具体任务装配最小充分材料；保留真实衍生关系及许可，不能直接删依赖伪装为独立结论。

### B. 没读到/没命中被推成可以放弃原目标

Q12在thought_resolve中写“外部是查不到，内部是从没聊过”，然后从人格材料“示例是说法参考而非设定”推出“考不出原型不构成缺口”，将“她是谁/故事与性格成因”改成“用户为什么挑这几句”，准备搁置。

这两步都证据不足：

1. 外部材料实际上有可读候选，只是没有获准返回；内部搜索未命中也不能证明从未聊过。
2. 人格材料不作为Alice自身经历，并不意味着素材人物没有原作；也不改变用户明确提出的了解人物故事的目标。

本次观点保存被拒，但该判断仍进入activity_finish摘要，问题也转为waiting_source。应保留原任务目标，把障碍写为“缺哪些来源/如何解除”，而不是因一条路径堵塞重新定义目标使其失去必要性。

### C. 历史自述成为策略依据，存在回流风险

memory:16正确记录的是“AI说自己在翻旧卡带目录”。新观点memory:17把这句当作“我这边有具体动作、给对方接话把手”的样本，并建议以后用“我正在做什么”接话。

历史发言可以作为措辞样例，但不能据此证明真做过该活动，更不能证明这种策略有效；当时用户回应也缺失。本次观点自己注明“尚未验证”是积极因素，但“长段他接不住”“没有具体东西”的归因仍超出少量样本。

合适的后续约束不是禁止个性表达，而是实际活动自述从真实运行状态取得；假设和措辞样例继续保留其身份，不升级为亲历或有效性证据。否则容易把之前的无依据活动自述发展成新的表达习惯。

### D. 历史引用已读成功，结束回执却不支持它

Q3 history_load真实loaded，但activity_finish共提交4次才成功：先因引用自有stance拒绝，再两次报“来源须在本窗口真实读取”，最后删除历史引用等才成功。Q9也重交了一次。

除模型把说明文字拼进ref、用函数名描述代替真实动作ID的问题外，代码本身也有接口缺口：ThoughtSession._resolve_evidence只支持memory引用和当前packet ID，没有history分支。即使是本轮真实loaded的history引用，也会落到“不在packet_ids”的拒绝路径。错误信息把“不支持此引用类型”误报成“未读”，诱使模型继续改写重交。

后续应支持由宿主从已载入历史引用拆分真实user/assistant轮，保留原说话者，明确AI历史发言不等于外部事实；动作引用采用宿主签发的真实回执标识。保持真实性校验，但让符合约定的证据有可成功提交的路径。

## 4. 处理优先顺序

1. 任务材料与来源依赖分层，解除“旧目录占满→新正文不可用”的阻塞。
2. 补历史证据/动作回执的合同与可操作错误，减少无效重交。
3. 保留原用户目标，区分无候选、被额度拦截、未读、不允许保存；这些状态不能推出“不存在/无需完成”。
4. 对历史AI自述保留归属，活动表述读取真实当前状态；观点仍按待验证策略使用。

不建议先增加长篇宪法禁令或只提高模型日额度。当前已出现多种能正确等待的行为，主要缺口在材料、证据与任务状态如何传递。
