# 历史读取额度与发呆详情修复

2026-11-17。依据[清醒机制真实观察](./清醒机制-真实运行观察-20261117.md)中复现的两项失败。修复在源码完成，0.1.13本机包已生成；不修改真实资料、权限或额度，不替用户完成真人验收。

## 1. 历史搜索与正文展开

原 HistoryContext.execute 共用 self.calls，两次 history_search 即用尽 history_calls=2，随后即使取得真实引用也无法 history_load。实际观察中批量读和单条重试均失败。

现在分别维护 search_calls/load_calls，各自由原 history_calls 配置限额，calls 继续记录实际进入执行的合计次数。默认2表示最多2次搜索和2次展开（每次展开仍最多2个往返）；0同时禁止两类调用。不新增配置项，旧配置可直接加载，但**旧“合计2次”语义调整为“每阶段2次”**，总调用数可能比旧版多。没有提高每日后台模型次数、单轮模型/工具次数、允许读取的渠道或旧对话窗口，也没有扩大总字符与token预算。

回执提供 budget.search_calls_remaining 与 budget.load_calls_remaining；阶段耗尽保留 history_call_limit 错误码并附 stage 与明确提示。耗尽搜索不等于无法读已有引用；耗尽读取说明不要改成单条反复重试。观测metadata同时保留总数与分项数。

搜索和展开仍共用history_max_chars及当前剩余token空间，预算提示本身也计入完整回执尺寸。超限仍回滚本次新签发引用与分页游标；未完整交付的正文不加入loaded。旧引用/失效、请求绑定、来源与角色归属规则保持原路径。

修改文件：alice/context_history.py、alice/config.py、config.example.toml。能力注册表版本升5，同步两条命令的一句话概要；工具参数与执行路由没有变化。宪法已有历史读取自我事实仍准确，无需追加工具教程。

## 2. 发呆详情

新发呆记录basis带真实epoch；不需要迁移旧库。详情先核对当前epoch与活动类型，再为真正的无调用idle记录提供计时详情：

- run ID必须是idle_前缀、活动账本类型idle、没有关联问题且模型/工具计数均为0。
- 返回开始时间、截止时间、休息原因和设定秒数，messages为空、finish_receipt为空。
- 不返回checkpoint或其他正文，不将普通探索伪装成发呆以跳过来源资格检查。
- 老版basis={}的真实发呆记录也可读取；无需改写历史记录。
- 普通工作记录仍走valid_basis，来源失效时仍不可返回材料正文。

修改文件：alice/activity.py、alice/autonomy.py。沿用公开thoughts detail动作与前端查看记录入口，不新加绕过接口或模型工具。
