# 思想层疑问管理、自主探索与主动交流：设计 v1

## 1. 目标与已确认方向

让 Alice 在用户没有主动发言时，也能延续自己的关注：回顾记忆、提出疑问、使用已获准工具探索、形成或修正看法，并在合适时机主动交流。

用户已基本认可的方向：

1. 思想层分为两个主要区块：**已得到认同和采纳的思辨、未解决的疑问**。已采纳指 Alice 当前认可，不要求每条经用户批准，也不表示绝对正确。
2. 问题可以来自用户委托、对话未解、记忆关联、观点复核、行为复盘、兴趣与自由联想，以及探索中的新发现。
3. 分别判断问题何时收纳、何时探索，以及成果是否值得保留。一个重要性分数不能包办这些决定。
4. 未解疑问反向参与当前回答。依据不足时，Alice 可以查证、给出有限回答、说明未知或询问用户。
5. 成果按性质进入见闻或思想层；同一次探索可以产生两类成果，通过引用关联。
6. Alice 可以因旧问题有进展、需要用户信息或想分享兴趣而主动联系用户。
7. 自主探索、主动联系和消息送达分别管理；一次设置允许的范围内，不逐条要求用户重新批准。

以下关于状态、数据结构、调度、默认值、观测和分期的内容，是使上述方向可实施的建议。具体预算和频率留给真人使用校准，不在本稿宣称已经验证。

## 3. 总体组织与职责

```text
对话 / 记忆 / 已有观点 / 兴趣 / 探索发现
                    ↓
              发现与收纳问题
                    ↓
思想层：未解疑问 ←→ 相关问题参与前台回答
                    ↓
          选题 → 读取 → 工具 → 判断下一步
                    ↓
          阶段成果 / 暂停条件 / 新问题
              ↙                 ↘
      见闻、已采纳思辨          主动交流意图
                                  ↓
                         调度 → 送达 → 用户回应
                                  ↓
                       更新疑问与继续探索
```

从职责上区分：

- **领域部分**：问题与思想的含义、探索步骤、成果关系，以及对话上下文选取。Alice 在这里选择问题、工具、下一步和表达。
- **应用部分**：任务调度、权限与额度、事务提交、暂停恢复、消息投递及只读观测。模型提出意图，宿主给出真实执行回执。
- **适配部分**：现有模型、检索、平台读取、渠道通知等实际连接。继续通过已有公共面和能力层接入。

实现初期可以继续由 `ChatService` 组合这些职责，不要求先完成全仓分层重构。问题仓库、调度和连续性属于核心；插件提供具体阅读或通知能力，不另建一套思想库和永久会话。

## 4. 思想层的两个区块

### 4.1 已采纳的思辨

存储 Alice 当前认可的看法，包括主张、形成背景、依据与推断、适用范围、仍存疑处，以及后续修订关系。与行为有关时，可以记录打算怎样改变回应。

“我决定少追问”是采纳了一种办法；“这已经改善交流”需要后续实际材料。两者分别记录。用户意见可以影响 Alice 的看法，但用户表达、Alice 的解释和 Alice 的采纳保持归属。

当前偏好、审美和表达方式可以直接形成，不要求编造亲历来证明。需要来源的是声称发生过的事件、已经执行的行动及其他事实依据。

### 4.2 未解决的疑问

存储值得延续的问题及其进展。可以尚未开始、正在探索、等待资料、等待用户、暂时搁置或部分解决。

问题解决后退出活跃疑问列表，保留简短的问题历史和成果引用。历史记录不作为第三个常驻思想区块，也不随每轮聊天装入上下文。

知识答案可以进入见闻而没有对应新观点。思想层保留“这个问题如何结束、成果在哪里”的关系，不为了填满已采纳区块制造立场。

出现反例、新资料或用户纠正时，可以重新打开原问题并增加版本，关联旧成果的复核。重新打开不抹掉当时为什么认为已解决，也不重新制造一组无关联的问题。

## 5. 问题来源与收纳时机

| 来源 | 例子 | 主要收纳时机 |
| --- | --- | --- |
| 用户委托 | “有空帮我研究两种记忆方案” | 当时记录要求、范围与明确期限 |
| 对话未解 | 某个解释停留在猜测 | Alice 明确意识到缺口时轻量记录；也可在对话告一段落后发现 |
| 记忆关联或冲突 | 两次偏好表达不同 | 空闲回顾或记忆整理时比较相关记录 |
| 观点复核 | 旧看法遇到反例 | 出现新材料或相关疑问时 |
| 行为复盘 | 已记录少催问，却仍反复催问 | 真实互动留下偏差线索后 |
| 兴趣与自由联想 | 想了解停顿如何改变亲近感 | 空闲探索或交流中自然出现时 |
| 探索衍生 | 新资料引出子问题 | 步骤完成时记录，并关联父问题 |

人格材料可以影响关注方向。背景设定作为材料引用，兴趣可以从现在形成，资料中的故事不转换为 Alice 自己经历过的事情。

### 5.1 收纳规则

明确问题及时收纳，潜在问题批量发现。发现过程可以输出零个问题；时间到、空闲或跑完一次任务均不要求制造疑问。

收纳只需要说清“想弄明白什么、为什么值得继续、线索在哪里”。自由好奇允许没有外部来源，如实标为本次自主提出；问题内声称的历史事实仍保留实际出处。

重复疑问合并线索；表面相似但对象、条件不同的问题可关联而不强行合并。父问题不能无限生成同义子问题，新增分支应说明新增缺口。

普通回复路径不增加一次专门的问题审查模型调用。主模型可在需要时使用记录能力；批量发现复用空闲回顾、compact 后思辨等自然节点，并记录已处理的材料版本，避免同批材料被多套任务重复消化。

### 5.2 问题表述

保留未确定部分。例如，“用户为什么总逃避我的关心”已经预设动机；可以改为“这几次追问得到什么反馈，提问方式是否妨碍了话题转移”。

问题不是事实证据。被多次检索、引用、浓缩后，仍应保持疑问或假设的性质。

## 6. 探索机会与选题优先级

### 6.1 先判断能否推进

宿主先给出满足硬条件的候选：当前允许后台运行、有资源预算、相关来源可用。有没有值得尝试的下一步，由 Alice 判断。前台活跃时不开始新的探索步骤。候选轮换只提供公平查看的机会，不代替 Alice 的语义选题。

等待用户的问题，只有收到相关信息或出现独立可推进的分支时重新激活；等待资料的问题在新资料到来后重看。普通定时检查只检查元数据，不为同一个缺口反复付费思考。

### 6.2 再选择当前问题

Alice 根据以下因素选择，并留下简短理由：

| 因素 | 判断内容 |
| --- | --- |
| 时效 | 用户明确期限、资料时效、错过后是否失去意义 |
| 影响 | 是否正在造成错误回应，或阻塞其他探索与用户委托 |
| 可推进性 | 是否有新线索、可用工具和明确下一步 |
| 兴趣 | Alice 是否仍关注，能否延续已有探索方向 |
| 成本 | 本次需要的时间、模型、网络与其他工具资源 |

不采用一个模型自报数字作为永久排序依据。宿主提供期限、实际成本、失败次数和资格；Alice 判断语义价值与兴趣。

用户明确委托通常优先，重复影响交流的错误也应及时处理；同时给自由兴趣保留可用机会。具体配额在人工使用后确定。等待时间增加重新考虑的机会，不使失去意义的问题必然执行。

探索过程允许改选或停止，但要说明原因。没有新进展时记录“等待什么再继续”，而不是在每次空闲窗口重试同一条路。

## 7. 有界、可恢复的探索循环

每次探索围绕一个主问题，按需读取相关记忆、观点、人格材料和既有探索记录：

1. 确认本次要推进的具体缺口。
2. 选择读取、工具调用、比较资料、形成看法或等待信息。
3. 取得真实结果，更新阶段进展和剩余问题。
4. 判断继续、部分解决、解决、搁置或提出交流意图。
5. 在检查点保存可恢复记录。

同一个 Alice 使用自己的表达习惯、记忆和已采纳思辨。探索使用独立任务上下文，不伪造用户消息，不通过合成用户输入调用聊天发送接口。

保存的是来源、行动、回执、阶段结论、缺口和下一步摘要，不要求保存模型原始思维链。恢复读取这些显式工作记录。

### 7.1 工具与预算

复用能力层注册表、必要业务参数及宿主权限核准。后台身份不会扩大工具权限；无法在后台完成的交互步骤转为等待用户。已有许可范围内正常调用，不逐次要求用户批准。

每次运行有模型调用、工具步骤、时间和费用上限；预算耗尽可以暂停，不要求硬凑结论。模型、网络和主动投递分别记账，并纳入共享总预算，不因新模块多出一份隐形额度。

### 7.2 中断与恢复

模型或工具调用前后、写入前设置检查点。前台到来后暂停开始新步骤；在途调用若不能取消，就等待回执并核对后续处理，不宣称已经瞬间停止。

数据库短事务与 I/O 分离。提交前核对会话 epoch、材料版本、问题版本、实际权限和已产生的新对话；无关新消息不必使全部研究作废，改变前提的新信息则需重新评估。

进程重启后恢复已完成的检查点。结果不明的付费调用或外部动作标记为未知，不自动当作从未执行而重试。探索运行、成果提交和消息投递各自防重复。

## 8. 成果、价值与生命周期

### 8.1 什么算解决

| 问题类型 | 合适的结束依据 |
| --- | --- |
| 事实问题 | 资料足够支持目标范围内的回答，剩余不确定性已说明 |
| 观点问题 | 形成当前认可的立场，理由、反例及修订条件可见 |
| 行为问题 | 形成可采用办法；实际效果另由后续互动判断 |
| 开放问题 | 记录阶段认识，未解部分仍可延续 |

收集到材料、模型说“想明白了”、查不到结果都不自动等于问题解决。问题也可以因不再相关、重复或暂不可解而退出活跃队列，并保留对应理由。

### 8.2 四个不同决定

| 决定 | 主要问题 |
| --- | --- |
| 收纳 | 这个疑问是否值得以后继续？ |
| 探索 | 现在研究它是否合适且能有进展？ |
| 保留 | 新成果是否值得进入见闻或已采纳思辨？ |
| 联系 | 是否值得现在告诉或询问用户？ |

这些决定分别记录简短理由，不强制生成四套长评估报告，也不增加固定的多模型评审流水线。

### 8.3 成果价值

将**依据状况**与**保留价值**分开：依据很充分的常识未必值得单独长期保存；尚有不确定性的个人思辨也可能有持续价值。

保留价值关注：新增或纠正了什么、会改变哪些判断或行为、是否有持续兴趣与审美意义、能否推动后续问题，以及保存成本。不要仅以是否直接服务用户衡量价值。

成果可以只留下结论和出处，也可以不进入长期库。没有长期成果的探索仍可保留简短结束原因，避免重复做同样的无效工作。

### 8.4 去向与修订

- **见闻**：从材料与工具实际获得的有据发现，保留出处、获取时间及既有资格。
- **已采纳思辨**：Alice 当前认可的解释、看法或策略，区分依据与推断，保留范围及未知。
- **未解疑问**：仍值得继续的缺口，关联已有阶段成果。

同次探索可以产生多类产物，通过引用关联，减少重复正文。成果持久化与问题状态更新在同一受控提交中完成，避免问题先被标成解决而成果丢失。

对旧观点的更新既可能来自新证据，也可能来自发现旧推理有误。后者记录解释修正，不伪装成新增事实。接入现有 stance 修订门控时，需要专门核对这一差异，不能悄悄绕过或原封不动套用。

长期复评关注：是否帮助解决新问题、改变真实选择、遇到反例或被更新资料取代。自动装入上下文、反复读取和自己复述不能算独立验证，也不刷新“用户再次确认”的时间。

来源撤回、失效或删除沿用既有依赖规则，派生问题和成果同步重新核对。审计引用不能成为永久保留失效正文的另一条通道。

## 9. 疑问反向参与对话与按需装配

当前话题涉及未解疑问时，提供少量相关问题的标题、状态、已知与未知摘要及引用；需要时再展开正文。问题总表、探索日志和所有新成果不常驻注入。

正常回答中发现依据不足时，按实际缺口选择：

| 条件 | 处理方式 |
| --- | --- |
| 记忆或工具能补足 | 在已有权限内先查证 |
| 已知部分足够回应 | 给出有限回答，说明相关未知 |
| 缺用户才能提供的关键内容 | 提出具体澄清问题 |
| 当前不能解决但值得延续 | 如实说明，并记录疑问 |

判断参考具体线索，如未载入、资料冲突、缺少执行回执或记录只支持部分结论。不把模型自评置信度当成可靠事实判定器，也不因此要求每轮额外审查。

当前偏好、语气、幽默和设想可以直接表达；声称过去发生过什么、用户答应过什么、自己实际做过什么时，按相应来源处理。

用户补充相关信息后更新原问题及其版本，不另外复制一条。匹配不确定时保留待关联线索，不能把用户换话题强行解释成回答旧问题。

例：记录只有“周末爬山”，没有具体日期，则提供“提过周末爬山，日期未确认”。后续没有确认前，不因摘要或新一轮生成而变成“明天确定去爬山”。

## 10. 主动交流

### 10.1 三类联系动机

| 动机 | 联系内容 |
| --- | --- |
| 反馈进展 | 之前共同讨论的问题出现了值得分享的新认识或修正 |
| 请求信息 | 某个具体问题需要用户提供信息，如当前偏好或要求 |
| 兴趣分享 | Alice 自己遇到有趣、想继续共同讨论的内容 |

主动联系是交流邀请，不自动产生用户义务。围绕实际讨论了解喜好；一次场景回答保留场景，不扩大成永久用户画像。

### 10.2 联系意图与送达分开

Alice 提出“想联系谁、为什么、关联什么问题、想说或想问什么、何时仍有意义”。核心只支持既有单一用户范围，不从探索内容获得任意联系人能力。

应用按配置安排两种方式：

- **下次见面提起**：用户进入下一次实际交流时，作为可选话题材料；用户已有紧迫任务时延后。只打开页面不伪造用户发言。
- **主动通知**：通过已启用且确实支持该能力的渠道送达，无需用户先打开页面。

不同渠道能力分别显示。网页聊天支持展示不等于操作系统通知可用；QQ 对话通道存在也不等于支持无请求的主动投递。本稿提出扩展，不声称当前已有。

若需要先邀请进入较长讨论，可以发对话请求；简短、有内容的发现可以直接分享，不统一增加“方便聊聊吗”的空前导。表达沿用 Alice 的人格习惯。

### 10.3 送达前核对与回执

宿主在送达前核对最新对话标识、问题及成果版本、用户设置、渠道资格和时效。前提发生变化时交回 Alice 判断用户是否已回答、内容是否仍有意义，再更新或撤销待发项；宿主不自行解释用户动机或裁定消息价值。

会话 epoch 或原始受众资格不符的消息不迁往新会话或另一渠道。外部资料派生内容按现有共享许可与来源条件处理。

维护稳定消息标识与渠道回执。区分：意图已记录、已排队、渠道已接受、已展示或送达、用户已回应。平台不能提供已读信息时不声称用户已读。

外部渠道不支持幂等且结果不明时，显示“送达未知”，不盲目重发；不能在缺少协议支持时承诺绝对只送一次。站内历史按稳定标识只登记一次。

采用持久化待发记录：联系意图与投递任务在受控事务中登记，实际外部发送在事务外执行，再登记回执。消息可以过期或取消；进入发送后的不确定结果按实际协议处理，不以回滚本地记录假装外部动作没有发生。

### 10.4 用户未回复

请求信息后进入等待状态，其他不依赖该信息的探索可以继续。用户未回复不转换为拒绝、同意、承诺或待催办事项，也不自动生成重复追问。

用户明确约定的提醒按约定处理，与一般好奇提问区分。用户取消、拒绝某类联系或更改偏好后，更新相关意图。已进入外部渠道的消息无法假装撤回成功。

### 10.5 永久会话中的主动消息

主动消息沿用 Alice 的发言身份，并记录主动来源、原联系意图、问题/成果引用、渠道和实际投递状态。不创建虚构的用户回合来凑成往返；待发内容也不作为已经对用户说过的话进入历史。

现有历史选择、compact、记忆提取、轮次统计与多渠道同步需要识别独立的主动发言及连续 AI 发言。用户后续回复通过实际关联继续，不能把主动提问误记成用户要求，把用户未回复误记成已经承诺。

前台正在生成回复时，先延后主动投递或把相关成果交给该次正常回应，避免两条通道同时开口。同一内容通过多渠道呈现时保留统一身份，按用户选择的送达策略处理，不默认为每个渠道各发一遍。

## 11. 数据结构建议：轻记录，按需展开

以下是逻辑结构，不要求把全部字段暴露给模型或复制到每轮上下文。继续使用当前本机数据库，新增结构采用增量迁移。

| 记录 | 最小内容 | 宿主维护的辅助信息 |
| --- | --- | --- |
| 疑问 | 标题或问题、来源类型、值得继续的原因、实际引用（可空） | ID、epoch、版本、状态、创建与更新时间、父子/合并关系、等待条件 |
| 探索运行 | 问题引用、本次目标、已做动作摘要、阶段结果、下一步 | run/step ID、工具与模型回执、预算、状态、检查点、输入版本 |
| 成果关联 | 问题引用、结论及去向、保留或不保留的理由 | 实际 memory/stance ID 和版本、依赖关系、提交身份 |
| 联系意图 | 动机、关联问题或成果、消息内容或沟通目标 | ID、受众、方式、时效、状态、版本 |
| 投递记录 | 联系意图引用、实际消息引用 | 渠道、幂等标识、尝试与回执、未知或失败原因 |

引用使用实际对象类型、ID、版本及必要的范围信息。标题用于展示，不能单靠标题定位更新。宿主填充 epoch、时间和执行身份；模型引用已提供的真实对象，不自行编造数据库身份。

疑问示例：

```json
{
  "question": "为什么我记录了少催问，之后仍反复追问同一件事？",
  "origin": "self_review",
  "reason": "实际回应与已采纳的调整方向不一致",
  "source_refs": [
    {"type": "turn", "id": 152, "version": "实际版本摘要"}
  ],
  "requested_by_user": false
}
```

示例身份只解释格式，不对应本次新增数据。具体表名、索引及 API 参数在施工前冻结；模型填写内容字段，执行状态与回执由宿主更新。

### 11.1 状态建议

- 疑问：`open / exploring / waiting_user / waiting_source / paused / resolved / closed`。部分解决保留 `open` 或等待状态，并关联已有成果；`closed` 记录重复、不再相关等原因。
- 运行：`queued / running / paused / completed / failed / unknown / cancelled / stale`。未知执行结果不能直接转成可重试。
- 联系：`draft / queued / pending_next_chat / sending / delivered / unknown / expired / cancelled`。用户回应另存关联，不与技术送达混为同一状态。

状态迁移带预期版本。多个探索或前台同时更新同一问题时，冲突返回重新核对，不能用最后写入覆盖用户新信息。

## 12. 能力入口、配置与现有流程接入

### 12.1 模型入口建议

优先复用现有记忆读取和实际工具，只补齐必要业务能力：问题记录/更新、问题检索/展开、成果提交、联系意图提出。可以按最终注册表约定拆成少量命令，本稿不固定命令名。

命令与一句话概要、必要业务参数供模型使用；完整执行协议、内部参数及权限判断留在能力层 JSON 和宿主。新增能力时同步 `alice/capabilities/commands.json` 与必要自我事实，宪法不重复接口教程。

读问题不隐含开启后台任务；记录问题不等于任务完成；提出联系意图不等于已经发送。回执明确各自结果。

### 12.2 设置建议

| 设置 | 作用 |
| --- | --- |
| 自主探索开关 | 是否在空闲时运行探索；与内容发现单独设置 |
| 探索范围与额度 | 本机读取、已获准外部工具、模型和资源预算 |
| 运行窗口 | 后台运行时段；独立于允许联系的时段 |
| 主动联系开关与类型 | 是否允许进展反馈、请求信息、兴趣分享 |
| 联系方式与时段 | 下次见面、获准渠道通知、免打扰时间 |
| 联系频率与冷却 | 控制实际打扰，不以探索成果数量代替 |
| 人工控制 | 暂停/继续问题、关闭问题、撤销待发意图、查看与调整关注方向 |

建议首版新增自动执行与外部主动通知默认关闭，不迁移解释为“旧内容发现已开，所以新能力也开”。用户显式启用相应范围后正常运行，无需每条重新审批。

首版建议单个探索运行；步数、时间、每日调用及联系频率均有上限。数值在预算设置和真人试用时确定，不把任意固定数字当作已验收参数。关闭自动执行仍可保留已有思想与疑问，并支持显式选题运行。

### 12.3 与维护、发现及退出的协调

在现有核心内形成统一后台运行许可和预算核准，逐步接入维护、内容发现、思辨和新探索。首版可以使用共享租约，不要求一次重写所有执行器；租约覆盖所有会启动付费调用的旧入口才算共存完成。

前台优先，紧迫的上下文维护有运行机会，自主兴趣也获得可用份额。明确处理旧 watchers、compact 后思辨、启动/退出回调与新问题发现的去重，避免同一材料在多条路径重复付费。

应用退出后不宣称仍在思考或定时联系。重启按检查点和原许可恢复；过时通知合并或失效，不补发离线期间积压的每条消息。

## 13. 观测器与界面

思想层界面展示两个主要区块。未解疑问可查看状态、进展、等待什么和成果关联；已采纳思辨可查看依据、适用范围及修订历史。提供“为什么现在探索它”的简短说明，不展示模型原始思维链。

新增后台运行记录与主动交流队列，并沿用只读观测原则。查询状态不触发模型、检索计数、任务恢复或消息发送。

至少能够关联以下事件：

1. 问题发现、记录、合并或未收纳及简短原因。
2. 选题、等待、跳过与采用的实际条件。
3. 探索每步的模型输入、已装配材料、工具调用及实际回执。
4. 暂停、恢复、版本冲突、失效及资源消费。
5. 成果候选、实际提交的见闻/观点身份，以及未保留原因。
6. 前台请求实际使用了哪些疑问、未知摘要或成果。
7. 联系意图、投递前重核、渠道回执及是否重复。

上下文正文沿用现有观测留存和资格规则，记录捕获状态及缺失原因，不另建无限正文副本。观察到“材料已注入”仅证明可见，不证明 Alice 已稳定采纳或改变行为。

## 14. 分期建议与真实环境人工验收

### A：问题仓库与前台关联

接通疑问记录、去重、检索与按需装配，关联既有 stance 和见闻。暂不要求自动探索或主动通知。

人工观察：明确疑问能持久化；同题能补线索；未知不变成事实；用户补充能更新旧题；普通表达不被强制查证；没有新增问题时不制造条目。

### B：本机自主探索与成果回流

接通空闲选题、本机资料读取、有界步骤、暂停恢复及成果提交。背景运行独立设置，与维护共用实际预算和许可。

人工观察：无用户输入也能推进真实选题；用户发言时及时让出新步骤；重启不重复记账；无进展会等待；观点采纳和行为效果分别记录；结果可以不入长期库。

### C：获准外部工具探索

复用现有检索与读取能力、来源资格和成本账本。没有外部许可时仍能进行本机探索。

人工观察：实际调用与许可一致；遇到受阻方法能判断其他获准路径或搁置；原始来源、派生结论和未知关系可追溯；失败不会自动循环消耗。

### D：主动交流

先接通“下次见面提起”，再逐渠道接通真正的主动通知。用户明确允许的范围内自动送达。

人工观察：旧问题有新进展能自然带回交流；必要提问与兴趣分享能发起；用户不答不会变成催办；用户已回答或内容过时时待发项能失效；送达未知不伪报成功、不盲重发；跨渠道和新会话不误投。

### E：长期价值与表达效果

在相同人格、模型和预算条件下，分别观察仅记录疑问、开启探索、开启主动联系的表现。保留实验条件和实际输入，不以短期主观印象宣称稳定改善。

重点看：问题是否真正推进、成果是否有新增价值、是否减少无据确定回答、是否改变重复互动毛病、兴趣是否形成持续方向、联系是否有内容且频率合适、额外费用是否可理解。

遵守工作区当前约定：只做真实环境人工行为验收，不新增冒烟、假模型或机器行为自测；静态结构与语法检查不能替代真人验收。各期独立记录部分通过和未通过，不等全部完工再发现问题。

## 15. 补充结论与下一步

在已讨论方向上，建议补齐以下工程合同，而不是继续扩写每轮宪法：

1. **问题与成果的关联和修订**：解决不丢出处，采纳不等于证实，错误解释可以被修正。
2. **后台共存与可恢复性**：前台优先、共享预算、检查点，以及结果未知时的真实状态。
3. **送达合同**：不同渠道的实际能力、回执、时效和重复处理，不把保存当作通知完成。
4. **价值的后续观察**：不以自身反复引用证明正确或重要，不把每个发现都变成通知。
5. **用户控制与对照条件**：探索和联系分别开关，暂停与撤销有明确效果，便于分阶段人工验收。
