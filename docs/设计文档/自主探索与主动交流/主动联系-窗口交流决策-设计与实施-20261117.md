# 主动联系：窗口交流决策

## 目标与范围

背景：Alice 已能保存疑问、形成观点和投递邀请，但真实记录中没有联系意图，也没有 contact_propose 调用。仅把主动联系作为可选工具，无法区分“没有值得说的事”和“没有考虑是否值得说”。

每个有效自主工作窗口在原有 activity_finish 中一并提交交流决定：invite（现在邀请）、later（留待以后）、none（无需联系），并给出简短理由。沿用原模型轮次，不新增审核模型或固定反思调用，不设置最低联系频率。发呆不是工作窗口，不生成交流任务。

## 数据与执行

- 交流决定是独立的窗口回执：run_id、会话、选择、理由、执行结果、意图与邀请 ID、阻塞原因、资料依据、时间。理由是简短结果说明，不保存原始思维链。
- invite/later 关联已登记的问题或观点，或沿用本轮取得的稳定 intent_ref；正文保持在原资料中。新意图须有 motive、topic 和内容引用；已有意图沿用 ID 与版本。已拒绝的话题不自动以新 ID 重建。
- later 保存意图，不排队发送邀请。invite 先记录意图，再检查投递条件；当前可投递时准备一句简短邀请，否则保留意图与阻塞回执，后续工作窗口重新判断。不开启额外的定时模型评审任务。
- 后台不再单独调用 contact_propose，改用窗口结束的一次提交，避免早先准备的邀请与最终决定冲突。前台 contact_propose 保持原能力。
- 窗口结果和交流决定在同一事务提交。重复结束调用复用原回执。引用失效或参数错误时整次回滚，不能只记录“已结束”却丢失联系意图。
- 直接输出最终答复、中断或异常，没有提交交流决定时由宿主补记 unknown（未完成判断）；不伪造 none，不付费追问。若同一 run 恢复，允许真实提交在同一事务替换这组宿主占位回执；明确提交过的交流决定保持幂等。旧版本窗口无记录，保持未记录。

## 权限与投递

交流价值由 Alice 判断，宿主处理权限与可达条件：总开关、清醒/休息状态、主动邀请许可、已有待回应邀请、来源有效性，以及正常模式下的时段、次数、冷却。当前临时测试策略继续跳过额度/时段/间隔；只保留总开关与工具/主动邀请权限，原设置值不覆盖。

想联系但权限关闭时可以记录意图，不创建待发送邀请。后续开启许可后仍由 Alice 重新判断，不能自动倾倒积压正文。已有 prepared 邀请仍在真正投递时再次检查宿主条件；页面同时展示当时决策与当前投递阻塞。

一次只等待一个邀请的回复。邀请仅问是否方便，不带成果正文；接受绑定真实用户消息后才载入正文并回复；未回应或没空收住，明确拒绝关闭话题。这套语义与测试放宽额度无关。

## 观测与人工验收

思想与探索面板增加折叠的交流决策历史；运行详情包含本窗口交流回执。展示“无需联系”“意图保留”“邀请已准备”“未完成判断”，并单独展示阻塞原因；不增加设置项。来源失效后隐去资料衍生的理由。

真人在真实配置中检查：① none 不产生邀请；② later 留下稳定意图，下一窗口可沿用；③ invite 可投递时只收到短邀请；④ 许可关闭/等待回复时保留意图并显示阻塞，不发正文；⑤ 接受/没空/拒绝/静默仍按原协议；⑥ 返回最终文本或中断时显示未完成判断；⑦ 重复提交没有重复邀请，来源失效后不继续发送。
