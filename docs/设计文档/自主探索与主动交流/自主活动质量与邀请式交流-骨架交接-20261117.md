## 2. 已固定的类型合同

- 生命周期 `WakeState` 为 awake/sleeping；`ActivityMode` 为 interest/problem/iteration/idle。调度结果 mode=None 表示被条件阻塞，不能与主动发呆混为一谈。
- `Question` 有 scope、版本、family_id、模式、状态、依据版本、下一步及等待条件；waiting_user/source/permission/budget 分别表达缺口。
- `MaterialVersion` 区分 external_material_version 与 working_revision。EvidenceRef 是带类型、版本与内容指纹的引用，旧 AI 发言有独立类型，不直接成为亲历或独立验证。
- `ProgressReport` 是模型可提供的结果说明；`ProgressReceipt` 是宿主核对后的实际回执，分别记录 actual_execution/substantive_progress 与剩余问题族窗口。
- 自由兴趣窗口尚无具体问题时，activity_finish 的 question_id 可为 None；由宿主注入的 run_id/family_id 承接依据与窗口记账，不要求为收尾先造一个疑问。
- `ModePolicy` 只含模式、时长、工具组；`Tuning` 不含基础偏好或可写权重。2 个同依据窗口、600 秒邀请等待、86400 秒重邀是设计建议初值；idle 的 300 秒建议值由后续配置适配设置，不在本轮自动写入。
- `ClockSnapshot` 同时保留墙钟、单调计时与 clock_epoch，避免跨进程复用单调时间；实际休眠/在途语义仍须实现并观测。
- `ViewRevision` 有稳定 view_id、revision、current/candidate/historical、原 memory_id、上一版及变更理由；`OutcomeDraft` 的 remaining 与 next_status 分离。
- `ContactIntent` 保留主题和展开内容引用，`InvitationAttempt` 单独保留每次邀请、实际投递/回复/展开身份和期限。准备时不能预填实际送达时间。
- `ContactReply` 只接业务决定；当前真实用户消息由 `ExecutionContext.user_turn_id` 绑定，不能让模型用工具参数自报一个用户同意。
- `InvitationIndex` 不含正文或展开引用；`ExpansionMaterial` 仅供已经接受且绑定本次请求后装配。用户主动明确请求主题的原有回答路径保留。
- `ForegroundProjection` / `ActivitySnapshot` 供后续上下文与公共 API 投影使用；不是已经实现的 HTTP JSON 格式。`MigrationPlan` 是待审阅的迁移计划，不自动执行。

数据类不进行组合校验。接班者须实现 idle 工具列表为空、等待状态对应 wait_condition、邀请状态/期限一致、有限数值与真实引用等校验；不能把类型提示当作已经完成的安全或业务检查。

## 3. 业务类与方法对应

| 类 | 方法 | 应补实现 |
| --- | --- | --- |
| ProgressService | link_family / classify / finish | 显式关联问题族；区分外部依据和自写；有限推演；一次实际收尾回执 |
| WaitingService | apply_outcome_wait / reconsider | 部分成果保留等待，只有相关真实条件变化才解除 |
| ActivityScheduler | scores / choose / enter_idle / reconsider_idle | 四模式分数、条件等待、零调用发呆计时与前台让位 |
| ViewService | commit_outcome / current_for_context | 当前指针与历史事务、阶段成果状态、传统及按需装配投影 |
| InvitationService | prepare / deliver / reply / expire / reconsider / commit_expansion | 简短邀请、实际送达、用户绑定、静默超时、下次重判、真实展开回执 |
| ForegroundAssembler | project | 少量相关等待、当前观点、一个邀请索引；接受后按需加载正文 |
| AutonomyV2 | configure / snapshot / activity_finish / contact_reply / prepare_migration / apply_migration | 未来统一入口与迁移协调；未被 ChatService 实例化 |

`ProgressService.finish` 和 `AutonomyV2.activity_finish` 分别是业务实现与应用路由层，不是两套独立工具。contact_reply 同理。未来 JSON 命令只路由到统一门面，再由其调用相应服务。

## 4. 适配器与事务责任

待实现的 ActivityRepository、ViewRepository、InvitationRepository 和 HostPort 必须共用同一 Store/宿主锁及事务单元；多个 Python 对象不意味着可以分开提交。

至少保证：

1. 阶段成果、观点版本/当前指针和问题的后续等待状态一致提交。
2. 邀请实际写入、主动联系额度与 attempt 状态/期限原子提交；重试用稳定 attempt ID 返回原回执。
3. 接受只绑定真实前台用户消息和本次主题；引用、会话、渠道、版本和来源均核对。
4. 展开关联实际 assistant_turn_id；生成计划、调用返回、保存回复分开，未知结果不重放。
5. 窗口计数按问题族、真实依据和真实执行窗口幂等处理；记录更新不自动重置。
6. snapshot、scores、迁移准备只读，不随机选择、不更新冷却、不恢复任务、不调模型。

仓库协议的方法没有 SQLite 实现，HostPort 的交付方法也没有消息写入实现。需要错误类型、查询限制、序列化与事件字段时，可补到适配层，保持现有核心依赖方向；不要从核心导入 addons 或测试代码。

## 5. 与现有代码的接线清单

施工顺序沿用 v2 设计，建议按以下接口逐项接入：

- `thought_workspace.py`：替换 partial→open；把现有成功写入等同 progress 的规则拆开。thought_resolve 构造 OutcomeDraft，由服务与共享事务提交。
- `activity.py` / `autonomy.py`：接入外部依据版本、问题族窗口与 idle；保留实际执行轮换计数，不能将 progress 布尔值换名后继续复用同一逻辑。
- 观点保存及 `context_memory.py` / `thought.py` / `retrieval.py`：补当前版投影与旧版按需读取，尤其核对传统长期全文路径。
- `loop.py`：构造宿主绑定的 ExecutionContext；在当前模型调用中判断邀请回应相关性，避免额外固定审查轮；用户接受后才取得 ExpansionMaterial。
- 原 `contact_propose/contact_update`、`_deliver_locked`、`contact_incorporated`：迁移到先邀请路径。不能保留旧全文投递/直接采用入口作为旁路。
- `service.py` / `server.py`：沿用公开 thoughts API 的会话、意图与修订校验。ActivitySnapshot 等需显式转换成 JSON；本轮未增加新端点。
- `web/thoughts.js/css`：补发呆/等待、邀请卡片、详情与时长设置；不改主聊天或 Orbit 的进行中样式。前端具体实现未在本轮预埋。
- `commands.json` / `constitution.json`：**只有实际实现并接线后**才注册 activity_finish/contact_reply，扩展 thought_resolve 参数及必要自我事实；本轮没有增减实际能力，故未改注册表或宪法，避免模型看到不可执行工具。
- 数据库/备份与桌面版本：实现扩展存储及迁移准备，再核对格式与降级合同。本轮没有 schema、用户资料迁移或重打包。

## 6. 给接班 AI 的实施要求

1. 先读最新 AGENTS.md 和 v2 设计，不覆盖另一棒修改；v1 代码仍在工作区，部分未提交，不以 git HEAD 代替当前源码。
2. 先补等待与进展，再做 idle、观点、邀请，最后接 API/前端和打包。所有占位抛错必须在接线前实现。
3. 如果调整类名或拆分方法，同步本交接文档与调用关系；字段语义优先于文件划分。这里固定的是业务合同，不要求为了保留空类而制造重复架构。
4. 不让模型修改实际权限、接收者身份、调用额度或真实回执；这些由宿主注入。模型只提出业务决定与理由。
5. 保留旧资料真实 ID、原文和来源依赖。不要启动时批量付费重写观点，不把旧 AI 叙述当新用户证据，不因保存被拒就放宽许可。
6. 只进行项目允许的静态检查和真实人工验收；不新增机器自测、假模型对话或伪造 GUI 请求。最终按 v2 验收表逐项记录，区分代码完成、已部署与真人通过。
