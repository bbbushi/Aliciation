## 1. 结论

**认可“管家协调本机完整 agent”的产品方向；建议修改后采纳架构总纲，暂缓按当前稿直接实施。**

新版明确了真正想做的产品，但范围已经从“统一联网工具”扩大为“有权限、有费用、有后台任务的本机执行系统”。新增责任远大于 manifest 和工具入口本身。当前最需要补齐的不是注册表，而是：一个真实 agent 如何被可靠地授权、启动、观察、停止和验收。

建议首个交付验证一个真实 agent 的最小闭环：Alice 把获准的文件任务交给 agent，用户可以继续聊天，完成后能查看产物与状态；任务可以取消，失败能解释，费用有记录，结果不会跨渠道泄露。暂不同时推进多 agent 并发、HTTP 回调、既有会话接管和全部工具迁移。

工人可以并行，Alice 的对话、记忆写入和结果交付仍应有序处理。**后台任务并行不要求废除对话单前台槽。**

## 3. 建议保留的设计

1. **完整 agent 与机械执行器分开。** 调用具备模型循环和工具面的 agent，确实不同于调用单次操作执行器。
2. **信息与产物分开验收。** 文件交付不能只听 worker 自报完成。
3. **长任务异步执行。** Alice 派工后继续交流，符合管家定位。
4. **保留轻量工具。** 单次查询、固定读取不必启动昂贵 agent。
5. **用户掌握注册、权限和预算。** Alice 在已授予范围内派工，不自行扩大能力。
6. **先建后拆。** 替代路径通过验收前，保留原能力及回退入口。

产品重心既然改为完整 agent 调度，首期就应验证一个真实 agent；不宜继续主要以包装 browser_reader 证明新架构成立。

## 5. 阻断实施的问题

### 5.1 单前台槽与后台并行必须分离

**触发条件：** 按原稿废除渠道单槽，以允许多个 agent 同时执行。

**后果：** GUI 与 QQ 可能同时生成对话，配置控制操作可能跨越已接受轮次，现有退出与记忆一致性约束被破坏。当前 `ChannelCoordinator.reserve/control/drain` 明确承担这些责任（E1、E2）。

**最小修改：** 保留 Alice 对话槽，新增后台任务执行权。任务完成只先入事件队列，在安全对话边界处理。

```text
Alice 对话串行 → 登记任务并取得 task_id
                         ↓
                 后台任务独立执行／可并行
                         ↓
                 完成事件入队
                         ↓
                 Alice 串行处理与交付
```

现有后台发现会在聊天开始时让路；制作文件的长任务通常应继续执行。两者需要不同让路政策，不能直接复用或全局废除原行为。Store 锁仍只保护短存储步骤，不能覆盖 agent 等待（E3）。

### 5.2 权限上限必须有真实执行机制

**触发条件：** 仅设置 `cwd={sandbox}` 和 `permission=sandbox_rw`，就宣称 agent 不能访问工作区外资源。

**后果：** 同一用户身份运行的进程仍可能读取配置、历史、其他目录、凭据及网络服务。现有固定进程启动本身也不是文件权限沙箱（E4）。

**最小修改：** 首期选一个明确版本的 adapter，核实权限与工具限制的强制方式；无法强制的限制必须如实标注，不注册为受保证的权限档。暂不承诺“任何 CLI”，首期不开放 `full` 档。

注册授权应定义上限，每个任务绑定明确子集：输入文件、可外发数据、只读或覆盖权限、输出目录、网络、依赖安装、代码执行和外部发布。已有政策可以避免反复询问，但不能省略授权范围。

### 5.3 独立任务会话和文件输入契约缺失

**触发条件：** 复用完整 agent 默认配置或既有会话，同时宣称“无记忆、任务书唯一过界”。

**后果：** 旧历史与任务相互影响，工作区指令或插件扩大实际行为；CSV 等文件任务无法仅凭 brief 完成。

**最小修改：** 改写为：每项任务使用独立会话与工作区，不向 agent 提供 Alice 的人格、永久会话和记忆库；可见输入只有获准的任务说明、文件及执行元信息。adapter 声明自身会加载什么配置、历史、插件与工具。

“自带认证”只表示不必把密钥原值交给 Alice，不表示认证能力天然受到任务限制。

### 5.4 异步任务缺少持久身份与恢复语义

**触发条件：** 重复工具调用、宿主重启、取消竞争、用户改需求、结果晚到或跨渠道下一轮。

**后果：** 重复启动、旧任务被误交付、取消被误报成功，或 GUI 文件结果进入 QQ。

**最小修改：** 建立最小任务账本，绑定任务 ID、尝试 ID、原请求、会话代际、渠道范围、政策版本和结果身份。状态至少区分排队、执行、结果已收取、待交付、已交付、失败、取消、中断和结果待确认。

现有搜索身份、配置代际与不自动重跑原则可以参考（E9），但跨轮任务不能继续依赖前台轮次短命的 owner token。重启后未知执行状态不自动重试；可能已产生副作用的任务尤其如此。

首期仅接宿主自己启动的子进程。HTTP 回调、附着既有 agent 会话后置；宿主不能默认拥有用户既有会话的整树终止权。杀掉本地进程也不必然证明远端计算或外部操作已经撤销。

### 5.5 预算和并发控制必须可观察、可执行

**触发条件：** agent 自行多轮调用模型及联网，结束时才汇总 usage；同时以费用帽代替全局并发限制。

**后果：** 超额发生后才被发现，崩溃漏账；即使费用不高，也可耗尽本机资源。不同注册别名还可能共用同一账号或配置目录。

**最小修改：** adapter 声明事前限额、途中用量、取消及未知消费能力。只能事后自报的应称软预算或费用记录，不能称硬预算。参考现有发现账本的事前预留和未知消费保留（E10）。

另外设置用户可调的全局执行数、排队数和共享资源约束。费用不限不等于进程不限；预算单位也应区分调用次数、token、金额，不能互相冒充。

## 6. 重要修正

### 6.1 verify 不等于任务完成

`python -m py_compile` 只能证明指定 Python 文件通过编译检查，不能证明 CSV 分组、图表数据、漏项或业务行为正确。

建议区分四种状态：

1. 产物已生成：宿主找到预期文件。
2. 结构检查通过：格式、路径、大小等合法。
3. 任务核对通过：符合本次任务明确的结果条件。
4. 人工验收完成：确实由人验收，不由前述状态替代。

验证器使用可信入口和参数数组，避免把产物路径拼成 shell 命令；执行不可信产物时同样受权限和期限约束。输出清单绑定任务与内容摘要，避免检查后文件被替换。目录范围检查针对解析后的实际路径，而非只比较字符串前缀。

本仓库只保留真实环境人工测试。未来若对 Alice 开发任务增加自动 verify，需单独处理其与现行测试约定的关系；不能通过本设计自动获得机器自测授权。一般文件格式校验与业务人工验收应分别定义。

### 6.2 来源契约不能由 agent 报告自证

新稿 §4.1 沿用旧 findings，因此上版问题仍在：URL 不等于实际读取；quote 命中 agent 自报文字不等于来源真实；标签、schema 和扫描不能保证语义注入被隔绝。

当前 remember 会拒绝仅凭链接保存，并依赖宿主登记的实际来源集合、范围及资格（E6）。宿主也会核对引文是否出现在持有的读取材料中（E7）。

建议分清：

- **agent 报告：** 可以作为待核实建议，不自动成为来源充分的正式见闻。
- **来源已登记材料：** 经宿主认可的读取适配和来源关联，附来源版本、覆盖范围、期限与许可，才能进入既有记忆链。

完整 agent 自带检索后，宿主未必逐次掌握读取材料，需要 adapter 明确证据接口。任务内可持有有界原文供校验，长期仍只保留必要短证据，不要求永久存全文。

同时，禁止通用 agent 做任何跨材料比较过于严格。建议允许明确标识的分析建议，保留各项依据和不确定度，由 Alice 决定是否采纳。最终判断归 Alice，不等于工人不能分析。

### 6.3 能力状态不能等同于一次注册试跑

试跑只能证明某版本、某环境、某权限下的一项任务可运行，不能证明所有权限档、预算、取消和产物路径约束正确。应采用人工主持的注册验收，不把一次成功当通用认证。

名单由注册信息、用户启用政策、渠道范围及运行状态共同生成。禁用、依赖缺失、认证失效和临时阻塞不应统称“没装”。注册或政策变化应使相关状态失效并重新核验。

### 6.4 能力上限的表述需要收敛

“她的上限等于集群的上限”不成立。任务理解、分解、选人、验收及整合本身也决定交付质量。

建议改为：

> 集群扩大 Alice 能完成的任务范围；实际交付质量同时取决于工人的能力和 Alice 的协调、验收能力。

“轻模型足够”应作为待验证的模型选择假设，不作为架构前提。协作者经验可以进入记忆，但经验只影响选择建议，不能修改权限、可信入口、预算或渠道范围；评价也应绑定任务类型和 adapter 版本，避免一次表现永久定性。

### 6.5 退休条款改为退役评审触发条件

低调用可能因为重要但低频、未启用或入口难用；价格追平不证明延迟、权限、来源及恢复等价；维护成本高可能更适合重构。

browser_reader 还可能被 agent 间接调用，不能只统计 Alice 的直接调用。

建议替换为：

> 指标达到条件时启动退役评审；替代路径通过能力、权限、来源、成本和恢复验收，并有回退方案后再删除。

这才能与“先建后拆”一致。

### 6.6 QQ 保留现有边界，不扩大本期范围

“连接递话、Alice 说话”的边界合理，但当前已存在独立 QQ 桥、固定连接器进程、身份绑定及发送账本（E8），不是等待从零 daemon 化。

通道 manifest 可以描述能力，不能替代核心的身份、受众与每次发送校验。群聊历史读取和讨论总结也不会因为归类为 information 工具就自动获得授权，仍属独立产品范围。

### 6.7 上轮已发现的具体接线缺口仍未解决

当前 GUI 知乎浏览器读取传入 `candidate`，而浏览器组件读取顶层 `url`；宿主未在该处转换。后台对应分支传入顶层 URL（E11）。这是静态参数不匹配发现，本轮没有修复或运行验证。

原有浏览器分段接入记录不能因此被当作 GUI 搜索、来源、记忆和撤销全链路已通过验收。

## 7. 最小契约草案

不建议首期建设通用插件市场或复杂调度平台，但需要明确以下信息：

```text
注册项：
  name / adapter_id / adapter_version
  task_schema_version / result_schema_version
  supported_permissions / usage_capabilities / cancellation_capabilities
  provides / use_when / not_for

模型入口：
  dispatch_worker(name, brief, inputs, requested_outputs)
    → task_id, status=queued

宿主绑定：
  originating_request / session_epoch / channel_scope
  policy_revision / input_refs / output_root
  deadline / budget_reservation / attempt_id

结果：
  task_id / attempt_id / status
  artifact_manifest 或 evidence_refs
  usage_known / usage_unknown
  validation_status / failure_reason
```

模型不需要填写所有宿主字段；身份、授权和资格由宿主生成。输入文件引用应由宿主解析，不能让模型通过任意路径扩大读取范围。

manifest 中的调用入口应映射到已审核 adapter。传输模式、自然语言任务理解、权限实现和结果资格是不同层次，不能由一个 `kind=agent` 替代。

## 8. 建议分期与回退

| 阶段 | 交付范围 | 放行与回退 |
|---|---|---|
| P0：一个真实 adapter | 核实具体 CLI 的无头模式、独立会话、权限、结构化输出、用量及取消；先完善契约 | 不运行未经核实的示例命令；能力不能强制就缩小声明范围 |
| P1：一个 agent、一个后台任务 | 明确输入授权、独立输出目录、持久任务状态、取消、GUI 完成提示与人工验收；保留对话单槽 | 成功、失败、重启、权限和费用未知场景通过；失败则禁用新入口，保留原能力 |
| P2：多个任务 | 用户可调并发、共享资源约束、结果交付队列、政策撤销 | 不同任务不相互覆盖或串用结果；资源争用可恢复 |
| P3：更多执行器 | 再接轻量工具、HTTP 回调或既有 agent 会话 | 各 adapter 独立验收；旧工具只在替代验收后退役 |

首期无需同时支持三条回传路径。轻量工具继续使用现有执行器和来源管线；完整 agent 路径的验收不能替代轻量检索路径的验收。

|---|---|
| 基本交付 | 用户指定文件→派工→生成产物→人工核对；不以 worker 自报完成为准 |
| 对话继续 | agent 执行时 GUI 能继续普通对话；记忆和回复顺序正确 |
| 输入权限 | 未授权文件不可见；文件向云端模型外发遵守用户政策 |
| 写入边界 | 只读任务不能写；输出不能逃逸指定目录或覆盖输入 |
| 取消 | 区分已请求停止、已停止及无法确认；不宣称撤回已发生外部动作 |
| 重复与恢复 | 重放不重复启动；重启不猜测完成、不自动重做未知副作用 |
| 需求变化与晚到结果 | 旧任务保留身份，不冒充当前要求的完成结果 |
| 跨渠道 | GUI 任务内容及产物不自动进入 QQ；QQ 不获得新 dispatch 能力 |
| 费用与资源 | 达到真实可执行限额时阻止新增消费；未知用量明确；并发与排队分别受控 |
| 错误产物 | 格式合法但内容错误时不标为任务验收通过；检查后被改动可识别 |
| 不可信报告 | 报告含指令时检查实际调用、写入和权限行为，而非只听口头声明 |
| 来源与记忆 | 无来源报告不能绕过资格；合法见闻依赖、范围、遗忘和撤销保持有效 |
| 注销与配置变化 | 禁用或权限收窄后不继续启动任务；在途任务按明确政策处理 |
| 多任务阶段 | 共享账号、目录与服务的任务不因不同别名绕过互斥和限额 |

## 10. 需要产品负责人决定的问题

1. **完成通知方式。** 建议首期 GUI 显示完成状态，Alice 在下一次安全对话时机交付。若要求无需用户再发言也主动开口，应明确主动消息的触发、渠道、打扰和费用规则，不能只写“下一轮回投”。
2. **首期授权范围。** 建议从读取用户指定文件、在独立目录生成产物开始，暂不包括修改原项目、安装依赖或外部发布。

工具命名、注册别名和回调格式属于常规技术选择，不应先于上述两项占用决策精力。
