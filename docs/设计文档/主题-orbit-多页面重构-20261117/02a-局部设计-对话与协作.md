## 〇、全组总则（结构壳的统一接口约定）

甲组全部页面共用以下四条处置规则，样式/动效/集成施工部门按此执行（每页条目只写增量）：

- **R1 隐藏/视觉类** → 写入 `web/theme-orbit.css` 的 `html[data-theme="orbit"]` 段。主题段天然 scoped，不波及 room/legacy/minimal。
- **R2 改写/结构类**（改文字、去属性、搬节点）→ 由 `web/orbit.js` 运行时执行并登记**还原表**（切回其他主题按记录还原），沿用 minimal「移动原节点保留 ID/事件/草稿」先例。**不直接改 index.html 静态文案**（轮次 3 裁定 1 已统一裁定）。对会被宿主 JS 重绘/改写的节点（evaluations.js 重绘、worker-tasks.js 933 行空态改写），由 orbit.js 以 **MutationObserver 重应用**替身与结构（轮次 3 裁定 2 授权），切主题清理。
- **R3 红线**：`#msgs` 内部与 revealStates/revealSync 的 DOM 结构、顺序、节奏不动；气泡样式契约不动；所有被收纳节点保留原 id 与事件绑定。
- **R4 动态构建窗**（S3/S4/S5/S6 的窗体、toast、boot 条由 JS 运行时注入，静态 HTML 无节点）→ **不搬移、不重建**，仅 R1 主题化，并由 orbit.js 在其根节点挂 `data-orbit-surface` 标记供样式/动效选择器使用。（v2 注：S2 不属此类——minimal 门控下其窗在 orbit 不会安装，S2 改由 orbit.js 自建，见裁定 4 与 S2 条目。）
