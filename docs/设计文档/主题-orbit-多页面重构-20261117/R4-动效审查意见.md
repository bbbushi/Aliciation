## 二、逐条问题

### P1-1（维度 A/D）两稿 OB 对勾描画时长冲突：04a 260ms vs 04b 240ms
- **证据**：04a §4.3「**260ms** `--orbit-ease`」且第五节降级总表 #13「OB 对勾描画 | 260ms dashoffset 一次性」；04b M-18「✓ 一次性描画 **240ms**（stroke-dashoffset，同 M-04 mark）」与第九节总表「M-18 | 静态 ✓ 直接显示」。03b §七.8 只给「一次性 ✓ 描画 + 淡入」未给数值，故两稿各自立数。这正是轮次 7 第 7 条要求 R4 先行核对的冲突项。
- **修改建议**：统一取 **240ms**——04b 的值有 demos-audit.js:25「首次完成 240ms」recipe 支撑，且与 M-04 结果回执对勾（240ms）同参，全主题对勾一族一值。04a 修订 §4.3、总表 #13、4.4 片段三处。

### P1-2（维度 A）04a `data-motion=off` 降级选择器结构性失配
- **证据**：04a §1.6 片段 L105：`html[data-motion=off] html[data-theme=orbit] .is-entering { … }`。`data-motion` 与 `data-theme` 同在 `<html>` 元素上（04b M-01 片段的同元素写法 `html[data-theme=orbit][data-motion=off]` 才是可匹配形式）；后代组合器要求后一个 html 嵌套在前一个之内，**永不命中**。该片段标注"落码并列展开"，但给出的结构本身就是错形，照抄即门禁静默失效——reduce 有 @media 兜底，data-motion=off 路径没有第二道保险。
- **修改建议**：04a 全稿统一为同元素形式 `html[data-theme=orbit][data-motion=off] …`，并在红线自查清单第 4 条加一句"data-motion=off 分支须与 reduce 分支选择器前缀同形，禁止后代组合器"。

### P1-3（维度 C/E）M-02 tip 控制器：pointermove 无差别清除鼠标意图计时
- **证据**：04b M-02 ⑤ 片段：`['pointerup','pointermove','pointercancel'].forEach(t => icon.addEventListener(t, () => clearTimeout(hold)))`。`pointermove` 对鼠标同样触发——悬停后 350ms 内指针微动 1px（真实用户常态）即取消 pending 的 show，**悬停揭示这条第一高价值动效面对多数鼠标用户失效**。且 ① 自述的取消条件是"移动 >8px 或抬起取消"（触屏长按语境），代码既无 `pointerType` 区分也无 8px 阈值，实现与自己的规格说明相悖。
- **修改建议**：move 取消仅对触屏生效并带阈值：`pointermove` 回调内 `if (e.pointerType !== 'touch') return; if (起点距 < 8px) return; clearTimeout(hold)`；`pointerup/pointercancel` 保留全局（抬起取消对两型都正确）。鼠标的"移出即收回"已由 `pointerleave` 承担，无需 move 参与。

### P1-4（维度 E/F）M-10 步体切换无重入防护，连点步点存在竞态
- **证据**：04b M-10 ⑤ `switchStep()` 用裸 `setTimeout(…, 120)` 两层（步体 + 副行换字），无取消、无纪元号。用户 120ms 内连点下一个步点（M-09 步点全程可点，`pointer-events:none` 只罩旧步体）时：第一个 pending timeout 会把第二个请求的 `fromEl`（即刚显示的新步体）置 hidden，出现"点了 B 却停在 A/B 之间闪切"；②自引 animate 技能"可中断、从当前画面继续"，但草稿用的固定延时路径恰恰不可中断。
- **修改建议**：模块级 `let stepSeq = 0`；`switchStep` 入口 `const seq = ++stepSeq;`，两处 setTimeout 回调首行 `if (seq !== stepSeq) return;`。三行改动，语义与 reduce/键盘直切分支不冲突。顺带把副行换字的 120ms 与步体退场共用同一 seq 判断。

### P1-5（维度 G）关机进度图形：03c 明确交办动效部门，两稿均未承接
- **证据**：03c §一（L84）：「`#shutdown-screen` …**进度图形归动效部门**（`#shutdown-state` aria-live 文本兜底样式…）」。04a 边界自述"组件微交互归动效 B，本稿不越界"，04b 十二节交接表 5 行均无 shutdown/M11 进度图形；两稿正文与不做清单亦无此名目。这是当前唯一一处"上游点名交办、下游无人认领"的动效面。
- **修改建议**：04b 补 M-20 一行（或并入 M-19）：关机进度 = **M-04 忙碌弧线规格复用**（不确定进度，不补间、不表演进度，与 `#qq-setup-progress` 同一"真实进度不表演"立场）+ `#shutdown-state` aria-live 文本为语义主通道；reduce 弧线停帧改静态「…」；窗壳按 M10 例外同参。一句话规格即可闭合交接表。

### P2-1（维度 F）M-09 指示条动画 width + 常驻 will-change，违反本部门纪律
- **证据**：04b M-09 ⑤：`transition: transform …, width var(--orbit-dur)` 且 `.orbit-step-indicator { … will-change: transform; }` 常驻。04a §六.1 明令"禁动画 width/height（layout 属性）"、§六.3 明令"常驻选择器一律不写 will-change"。（所引 pickerCSS 先例确实也动画 width，属先例自身的不严谨。）
- **修改建议**：width 改 `scaleX`（`transform-origin: left`，与 translateX 同帧合成，demos-motion.js L66–70 的 scaleX 结论正是为此）；删常驻 will-change（16×2px 微元素无提升收益）。若集成坚持 width 方案，须在 06 记录登记为"绝对定位微元素豁免"，不得默认推广。

### P2-2（维度 A/D）04a §4.3 行文与片段自相矛盾（对勾"同帧启动" vs 120ms delay）
- **证据**：04a §4.3 正文「对勾描画与旧步体退场**同帧启动**，各 260/120ms，互不等待」；4.4 片段 `animation: orbit-check-draw 260ms var(--orbit-ease) **120ms** backwards;`（注释"与步体退场同帧起"）。120ms delay 实为等旧步体退场结束后才起，与"同帧"相反。
- **修改建议**：二选一并统一：同帧启动则删 delay；若刻意让对勾在新步体浮现时才描（避免读者注意力被拉回旧侧），则正文改为"与**新步体入场同帧**启动（delay 120ms）"。随 P1-1 一并修订。

### P2-3（维度 A）合并总表须钉死两处易被错误统一的语义差
- **证据**：① **S9 启动点 = 连接进行中，允许 2.4s 循环**（04b M-15 `infinite`，理由"活着不是催促、条随完成消失"）；**徽标 = 完成态提示，一次性双波后永久静止**（轮次 7 第 4 条）。两者 reduce 侧同为"停帧留静态点"，正常侧节奏相反——合并时若按"脉冲"一名统一即违背裁定。② toast danger 竖条 2400ms 在 04b 为一次性（M-08 注释"一次性；播完静止"），与徽标同协议，应一并写入合并表。
- **修改建议**：轮次 7 第 7 条的合并总表增两列：「节奏（一次性/循环）」「永久静止判据（animationend 置 done）」，并把 M-03 的 quiet 分支 CSS 拆分、M-15/M-08 的 `data-motion=off` 分支列入 06 集成核对清单（轮次 7 第 6 条现只收了 toast 过桥与指示条节点两项）。

### P2-4（维度 B）04b M-11 两处行段引用不精确（机制描述正确）
- **证据**：「revealStep 每句经 renderTurnBubbles(container, shown) 整轮重渲（**2886**）」——app.js 2886 是 done 分支 `revealSync(…)` 调用点；render 回调传入在 2864，执行点在 revealStep 的 `st.render(txt, st.shown)`（2786）。revealDelay 2764–2767、首句 0ms 2794、revealSync 2802–2819、沉默 2889、revealStates 2724 起均与实文件精确吻合，仅此一处行号张冠李戴。
- **修改建议**：改为「（render 回调传入 2864，逐句执行 2786）」。不影响 M-11 结论——"整轮重渲 ⇒ 气泡级 animation 会随每句重播"的机制判断与源码一致。

### P2-5（维度 E）"焦点回归时机不变"的读法应在 05 备案
- **证据**：轮次 6 第 5 条裁定原文"焦点回归时机不变"；04a §3.2 第 2 步把焦点回归提前到**请求帧**（t=0），并论证"close() 的原生回焦落在已聚焦元素上 = 无操作"。严格字读下原生时机是 close() 时刻（本例 t=120ms），04a 提前了 120ms。这个提前是**正确的**：退场期窗体 inert，若焦点留在窗内 120ms 将出现"焦点悬在不可交互内容上"的可达性洞。
- **修改建议**：不改设计，改记录——05 轮次 7 补一行："焦点回归时机不变＝回归目标与可达性不变；退场动画期焦点提前至请求帧，避免 inert 窗内焦点悬空"。同时把 reduce 分支 `d.close()` 直关（原生回焦）与此说明并列，两条路径焦点目标一致。

### P2-6（维度 D）M-04 与 M-06 片段同选择器异属性表，层叠互覆
- **证据**：M-04 ⑤ 与 M-06 ⑤ 均写 `html[data-theme=orbit] .orbit-window .btn { transition: … }`，属性清单不同（前者含 transform/background-color/color，后者仅 opacity/border-color）。同特异性后者优先，集成若按稿顺序堆放，M-06 会砍掉 M-04 的按压/底色过渡。
- **修改建议**：两稿合并为单一 `.orbit-window .btn` 过渡声明（五属性一表），04b 内部先合并再交 06；这也是合并总表落地时的机械核对项。

### P2-7（维度 G）"该动而未动"三项，列为可选 P2 / 不做清单补登
- **证据与建议**（find-animation-opportunities 视角，均不阻塞）：
  1. **P1 页内 `#chat-new-attempt` 出现**：M-03 双落点去重管住了 dock 徽标，页内提示行本身零动效——属罕见+理解型，允许一次性 180ms 淡入（reduce 即时）。可做可不做；不做则建议在 M-11 约束段补一句"页内状态行入场零动画（与沉默占位同则）"以免集成自行加戏。
  2. **`#chat-refresh` 同步进行态**：同步行只有图标三态（hover），点击后的"进行中"无微观。03b §七.6 已给 P2/P3 主按钮 180ms 边框过渡先例，同参即可；不做的理由也成立（文字状态已反馈），倾向不做，建议明登不做清单。
  3. **回底按钮出现**：03a 4.3 低档 .70 只定义静态档，出现/消失现为即隐即现。属低频导航面，180ms 淡入收益边际，登记为"不做（现状即隐）"即可。
