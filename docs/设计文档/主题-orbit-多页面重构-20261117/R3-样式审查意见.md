## ② 逐条问题清单

### P1（修订后集成，缺一会产生可见缺陷或未定义行为）

**P1-1 [A/令牌登记] 三个已裁定采纳的真令牌未登记进 03a 8.1 令牌块。**
证据：05 轮次 5 第 4 条已裁定 `--orbit-win-head-h`/`--orbit-step-dot`/`--orbit-float-offset`「全部采纳入令牌表」，03c 1.9 CSS 已引用（`min-height: var(--orbit-win-head-h)`、`width: var(--orbit-step-dot)`、`bottom: calc(100% + var(--orbit-float-offset))`）；但 03a 8.1 的 `html[data-theme=orbit]` 变量块没有这三个变量。照稿集成则窗头高度、步点直径、浮层偏距全部落到未定义值（窗头 `min-height` 失效塌陷）。
建议：03a 8.1 令牌块追加三行：`--orbit-win-head-h: 52px; --orbit-step-dot: 8px; --orbit-float-offset: 8px;`，并在 1.4 圆角表或 1.1 色彩表补白衬底功能色登记注记（见 P2-9，现状已有无需落码）。

**P1-2 [B/结构壳] 03b 双列区依赖的包装节点未在任何结构壳/还原表登记，`#discovery` 平铺子节点直接套两列 grid 会棋盘化。**
证据：03b 2.4 对 `#discovery` 直接设 `display:grid; grid-template-columns:300px minmax(0,1fr); grid-template-rows:auto minmax(0,1fr)`；但 discovery.js 实际产出是平铺直系子节点（`.discovery-header`→status→sharing-warning→bound→`.discovery-overview`→`.discovery-results`，discovery.js:8–24/130），无「双列容器」层——grid 自动放置会把 header/status 等逐个填进 2×2 格。03b 3.4 的 `#orbit-page-thoughts .orbit-body` 与 `.orbit-drawer-stack` 同样在 02b 结构壳表（158–161 行仅页面壳/替身/运行记录抽屉三项）中不存在。0.4 的「给语言不给盲选择器」只覆盖了 `.orbit-card`，未覆盖这些布局承重节点。
建议：03b 增补一节「orbit.js 新建包装节点登记表」：P2 双列容器（建议名 `.orbit-body`，与 P3 同名同构）、`.orbit-drawer-stack`、`.orbit-entry-row`、`.orbit-count`（改挂既有 `#discovery-card-count`，见 P2-6）、`.orbit-state-chip`、`.orbit-empty-sigil`、`.orbit-lived-note`、`.orbit-doc-chip`——逐项注明「新建节点/挂标记类、MutationObserver 重应用、还原表条目号」，与 02b/02c 还原表对齐。

**P1-3 [G/跨稿冲突] S5 权限质询卡双稿双值：03b（right 16px / bottom 88px / 宽 340px）vs 03c（right 24px / bottom 96px / 宽 min(360px,…))。**
证据：03b 1.1/1.4 与 03c 5.4 各自写了同一节点（`.claude-gate-panel` / `[data-orbit-surface="gate"]`）的定位与宽度，数值不同。这正是 03b §九预警的「dock 让位值若跨组复用须登记」的失控实例——本轮 dock 让位常量已散落 84（toast）/88（03b gate）/94（03b #app）/96（03b OB、03c gate/M10）四处。
建议：S5 以 S 族属主 03c 为准；03b 1.4 删除 gate CSS 块、1.1 入场位一行改为「规格见 03c 5.4」。同时在 03a 1.3 增距令牌 `--orbit-dock-clear: 96px`（dock 顶 68 + 缓冲 28），03b `#app` 底让位注释改为 `calc(var(--orbit-dock-clear) - 2px)` 或 94px 注明「dock-clear 96 − 页边距 2」的推导，toast 84 改注「dock-clear − 12」。

**P1-4 [C/S1] S1 确认框换肤不完整且与 03a 区分规则冲突。**
证据：(a) 03c 5.1 承诺标题「确认操作」`--fs-section/600`、按钮行右对齐 ghost/primary、tight 档，但 5.9 CSS 只有容器与 `#action-confirm-message`，无 h2/按钮行规则；且 S1 不在 `.orbit-window` 内，1.9 的 `.orbit-window .btn` 三型皮对它不生效，按钮保持原 `.btn`（2px 边、`--card` 底、min-height 38px ≠ tight ctl 32px）。(b) S1 是原生 `<dialog>`，`.action-confirm::backdrop { background:#000a }`（style.css:143）照常全屏压暗，与 03a 五节区分规则 2「只有召唤窗有 ::backdrop 压暗；小浮层不产生全屏变暗」直接冲突，两稿均未处置。
建议：5.9 补 `[data-orbit-surface="confirm"] h2 { margin:0 0 var(--sp-3); font:600 var(--fs-section)/1.5 var(--font); }`、`[data-orbit-surface="confirm"] .action-confirm-buttons { justify-content:flex-end; gap:var(--sp-2); }` 与按钮皮（或声明 S1 按钮沿用全局 `.btn` 经令牌自动换肤、豁免 tight 控件高——二选一并写明）；补 `[data-orbit-surface="confirm"]::backdrop { background:transparent; }`，或在 03a 五节规则 2 加注「S1 原生 dialog 既有 backdrop 豁免」。

**P1-5 [D/可访问性] 55% 低档对比度独立验算不达标：有效对比 ≈2.7:1，低于非文字组件 3:1 线，03a 自报「≈4.3:1」不成立。**
证据：`--orbit-faint #8298b8` 以 55% alpha 合成于 `#0d1624` 底得 ≈`#4d5d75`，相对亮度 ≈0.108，对底（亮度 ≈0.0079）对比 = 0.158/0.058 ≈ **2.7:1**。来源行图标、「回到最新消息」、「继续加载会话记录」是功能的唯一入口（收纳红线：不可变得不可发现），须过 3:1。触屏兜底 .75 验算 ≈4.0:1 达标；`--muted` 验算 8.4:1、`--orbit-faint` 全亮 6.2:1、`--ink` 13.9:1、`--on-accent` 9.5:1 均与声称吻合（这三对通过）。
建议：03a 4.3 低档由 .55 提至 **.7**（验算 ≈3.65:1），或改为「纯装饰元素 .55、功能入口图标 .7」双档；同步修 4.3 表、8.2 `.orbit-icon[data-idle=low]`、03b `.orbit-source-icon/#chat-latest`、03c 六节「55% 淡化档」表述与粗验值；07 验收清单补「55% 元素须逐个判类：装饰/功能」。

**P1-6 [D/可访问性] M10 无标题窗头的 aria 方案机制错误：「dialog 继承 aside 的 aria-label」不成立。**
证据：03c 1.2 称「窗名经 dialog 继承 aside 的 aria-label="DSH 协作会话"」。aria-label 不随 DOM 包含关系继承：`aside#worker-tasks`（index.html:184）搬入 `<dialog id="orbit-win-workers">` 后，dialog 自身无可访问名称，读屏只报「对话框」。轮次 5 裁定 6 以 aria-label 为无标题红线的替代物，替代物本身失效则裁定落空。
建议：03c 1.2 改为「orbit.js 创建 `#orbit-win-workers` 时把 `aria-label="DSH 协作会话"` 复制到 dialog 元素（aside 原 label 保留；还原表含 dialog 移除，无还原负担）」；同法核 M8（`#orbit-window-observer` 建 dialog 时补 `aria-label="记忆观察器"`，其可见标题由 `.orbit-win-title` 承接）。

**P1-7 [C/装饰承接] `chat::before` 眉标（01 / conversation）的「移动不是删除」无任何承接。**
证据：03a 六节承诺 orbit 下「CSS 隐藏 + 装饰本体收进 P1 空态旁与 dock 悬停卡」；03b 承接了 ASCII 签名落点（`.orbit-empty-sigil`）但两稿 CSS 均无 `html[data-theme=orbit] .chat::before { content:none }`——现状眉标（style.css:363，absolute top:-10px、底色 `var(--bg)`）会继续渲染并压在 P1 直角壳上缘与页影上；眉标本体的 dock 悬停卡落点亦无样式与登记。
建议：03b 1.4 补 `html[data-theme=orbit] .chat::before { content: none; }`；03a 3.1 dock 结构契约或 03b 空态节补一句「眉标文本随 dock「对话」图标 `.orbit-tip` 呈现（orbit.js 组装 tip 文案，装饰不计字）」，登记还原表。

**P1-8 [A/S9] `#boot-status` 换肤有布局缺陷：未重置 `.boot-status` 的 `inset: 0`。**
证据：style.css:25 `.boot-status { position:fixed; inset:0; display:grid; place-content:center }`；03c 5.9 只设 `top:16px; left:50%; translate:-50% 0`——`right:0; bottom:0` 残留，高度 auto 且 top/bottom 同设时元素纵向拉伸至视口底，999px 圆角胶囊变成贯通全屏的竖带。
建议：5.9 首行改 `inset: 16px auto auto;`（或补 `right:auto; bottom:auto;`），并把 `display:grid; place-content:center` 改 `display:inline-flex; align-items:center`（避免 place-content 对单行文本的居中残留差异）。

**P1-9 [G/机制登记] M1/M2–M7 壳适配机制跨稿不一致：02b「仅 orbit 域 CSS 重皮肤」/02c「theme-orbit.css 重排 `.modal-card.settings-card`」vs 03c「orbit.js 运行时追加 `orbit-window orbit-window--md` + 还原表登记」。**
证据：02b:232（M1 无需搬移、仅 CSS 重皮肤）、02c:73（由 theme-orbit.css 重排）与 03c §1.1 表（追加类）是两套互斥实现：若集成按 02x 纯 CSS 走，03c 的 `.orbit-window--md/--sm` 宽度档、细轨、窗头 sticky、`.orbit-win-*` 全部落空。且 02a 的自建壳均无修饰类（M9 `orbit-window` 无 `--md`、S2 `orbit-win-memory` 无 `--sm`），03c 宽度档依赖的修饰类在壳清单里不存在。
建议：钉死以 03c 机制为准并在三处落一句话：03c §1.1 表加注「`--md/--sm` 由 orbit.js 于搬移时追加，02a/02c 结构壳类名不改，还原表登记去类」；02b:232 与 02c:73 的「仅 CSS 重皮肤/重排」措辞改为「皮由 `.orbit-window` 族承担（追加类机制见 03c）」；02a M9/S2 壳行加注同句。
