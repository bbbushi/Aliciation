## 〇、核对义务结论（先行，四项全给出）

### 0.1 observer.js 重绘行为 → **M8 视图容器可容器级搬移（R1 移交义务，结论：可行）**

核对 `web/observer.js`（882 行）全部 DOM 操作：

- 所有取节点均按 ID（`el("obs-…")`）；对视图**容器本身**只有 `classList.toggle("hidden")` 类操作（如 `obs-detail`、`obs-detail-reading-tools`，以及 changeView 797–803 行的视图切换），**从未对任何 `#obs-*` section 做替换、移动或按兄弟位置插入**（R2c 独立复核：innerHTML/insertAdjacentHTML/remove/insertBefore 全文零命中）。
- 重绘全部发生在**固定 ID 的内部内容容器**里：`obs-progress`、`obs-changes`、`obs-list`、`obs-persona-sections`、`obs-persona-toc`、`obs-persona-diff/compare`、`obs-changelog`、`obs-traces-list`、`obs-detail-reading/text` 等使用 `replaceChildren()`/`appendChild()` 填充。
- 结论：**整 `aside#observer` 节点容器级搬移安全**（`obs-detail` 是 aside 内兄弟 section，随整节点自然随迁）。orbit.js 搬移整节点即保留全部 ID 与既有监听；禁止拆散或重建内部节点。
- 补充核对（P2-06，observer.js:796–809 changeView 实况）：`obs-search` 表单**仅在 history 视图隐藏**（:803），墓碑/技能视图现状**显示**检索表单；memories 限定的只是层级/类型两个 select（:801–802）。检索对墓碑/技能数据端是否消费 query 未能确证——**处置改为保留检索表单不隐藏**（撤回 v1 的 CSS 隐藏兜底），列表类时刻预算补计检索行（见 M8 清单），不产生功能收窄、不依赖未确证行为。

### 0.2 claude-settings.js 动态构建 section 的时机 → **M7 搬移时机 = orbit 主题初始化即可，且只能搬移不能重建**

核对 `web/claude-settings.js`（177 行，IIFE）：

- 构建时机：**脚本加载即执行**（script 标签在 body 尾、DOM 已就绪，无 DOMContentLoaded 等待）——`#claude-settings` section（一次性 `innerHTML`）与导航按钮（`data-settings="claude"`，`after()` 插在 workers 按钮后）在 app.js 绑定 `data-settings` 点击监听（app.js 3112 行）**之前**已存在，故监听有效。
- 结论：orbit 主题初始化时该节点已在 DOM，**随 settings-nav / settings-body 一并搬移即可**；该模块对节点全部按 ID 引用并持有 `window.AliceClaudeSettings` 闭包引用，**重建节点会断链**，只能搬移原节点。
- 连带机制约束（重要，登记给施工）：`AliceClaudeSettings.open()` 内部执行 `$("settings-btn").click()`——**原导航 `#settings-btn`、`#qq-btn`（openQQSettings 依赖）等按钮节点必须保留在 DOM（视觉隐藏），dock 图标以 click() 代理**，不得删除节点。焦点与可达性约定见 0.5。

### 0.3 service 动态分区在 settings-nav 的注册方式 → **现树无注册源，是白名单预留键**

- app.js `selectSettings()` 的白名单为 `["general","appearance","discovery","thoughts","qq","workers","claude","service"]`（app.js 3102 行）；全 `web/` 目录检索后，**不存在任何 `data-settings="service"` 按钮或 `data-settings-section="service"` 元素**——"service" 是预留键，当前无动态注册来源，P4 与窗内步点均**不需要**为它保留位置；将来若出现，带 `data-settings` 属性的按钮会被 `selectSettings` 自动同步 `aria-pressed`（该函数是全局 querySelectorAll，非静态列表）。
- 实际的动态注册只有两处：**thoughts.js** 在 `.settings-nav` 运行时插入「思想与探索」按钮（自带监听，调 `AliceUI.selectSettings("thoughts")`）；**claude-settings.js** 插入 Claude 按钮（见 0.2）。
- 关键推论：app.js 3112 行的点击绑定是**加载时一次性逐个绑定**（非事件委托）——orbit.js **新建**的按钮（P4 hub 导航）不会被自动绑定，须 orbit.js 自行 `addEventListener` 并调用 `window.AliceUI.openSettings(key)`；而**搬移**原 settings-nav 按钮节点则监听保留，可直接作窗内步点。

### 0.4 M5「连接详情」同屏超帽的解决方案 → **错步呈现 + 静态文案具名折叠收纳（复算见 M5 节）**

「连接详情」折叠（summary 4 字）从确认步**错步移出**：仅在准备/扫码/配对/启用四步可达（它承载机器人编号、连接方式与资料保存说明，属于"连接态"信息，与"确认身份"决策无依赖）。同时把 QQ 区全部静态长文案收纳进「连接说明」（4）与「使用限制」（5）两个具名折叠，同样在确认步隐藏。改写后逐时刻清单与复算见第四节 M5：最重时刻=确认步 **37/40**，帽内；「连接详情」全文一字未删。错步显隐的监听机制（P2-10 修正）：**MutationObserver 监听四个步骤盒（`qq-setup` / `qq-qr-box` / `qq-pair-box` / `qq-confirm-box`），`attributeFilter:["class"]`（hidden 是 class 不是属性），任一步可见即切换「连接详情/连接说明/使用限制」折叠的显隐类**；qq.js 禁改。

### 0.5 隐藏节点的统一约定与焦点回路（P2-07 登记）

- **隐藏方式统一约定**：所有"保节点视觉隐藏"（原 nav 按钮、分区标题、步点文字、被收纳 hint 原句）一律用 **clip 式视觉隐藏**（不 `display:none`，保 aria-labelledby 引用、焦点落点与 click() 代理），并配 `tabindex="-1"` 使其**退出 Tab 序**——键盘用户不会 Tab 进不可见按钮，click() 代理（`.click()` 对 tabindex 无碍）不受影响。
- **焦点回归接管**：app.js 关闭 observer 时 `focus(observer-btn)`（或 nav-toggle）——目标已被视觉隐藏，focus 可能落 body；**orbit.js 在关窗/关面板后接管焦点，聚焦 dock 对应图标**（dock 图标始终可聚焦）。`#observer-btn` 的 `aria-expanded`（observer.js:815/823 维护）与 dock 工具簇图标 `aria-expanded` 由 orbit.js 同步；`#qq-btn` 的 `aria-controls="qq-settings"` 因分区节点 ID 不变继续有效。
- **developer-nav.open 置位**（app.js 3204）：orbit 下无功能副作用，登记即可。
- 验收登记：请主代理在 07-人工验收清单加「键盘走查：Tab 不落入隐藏节点、关窗后焦点回 dock 图标」条目。
