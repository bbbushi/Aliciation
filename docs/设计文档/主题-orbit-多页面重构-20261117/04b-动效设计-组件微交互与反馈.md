## 〇、总则：判断门、参数与通用纪律

### 0.1 基准参数（03a 1.6 定稿，全稿引用不另立）

`--orbit-ease: cubic-bezier(.2,.7,.2,1)`；常规过渡 `--orbit-dur: 180ms`；门禁降级 `--orbit-dur-quick: 125ms`；R3 P1-3 增补 `--orbit-dock-clear: 96px`（toast 位与 S5 位均由它推导）。

### 0.2 每项动效过四道判断门（UISkill：find-animation-opportunities，`addons/ui-skills-lab/demos-audit.js:21–27`）

四门依次为**频率 → 用途 → 时长预算 → 功能**；键盘触发或每天 100+ 次的操作**第一门即拒绝动画**（demos-audit.js:23「快捷命令」候选即被拒案例）；「首次完成」类罕见反馈允许 240ms（demos-audit.js:25 recipe）。本稿各项的判定结论写入各条「UISkill 出处」行；被四门拒绝的机会在 M-11（句级动画）与第九节显式登记为「不做」。

### 0.3 通用纪律（UISkill：review-animations，`demos-audit.js:38–40` 规则段）

禁 `transition: all`（仅列具体属性）；入场起点 `scale(.97)+opacity:0` 禁 `scale(0)`；每条 transform 动画必须有 reduce 分支；触发式浮层的 origin 靠近触发器。属性面只动 **transform / opacity / box-shadow / border-color / color**——不动画布局属性（UISkill：animation-performance，`demos-motion.js:60–79`：width 推挤布局、scaleX 保留布局的并排结论）。

### 0.4 键盘与高频路径零等待（UISkill：remove-animations `demos-audit.js:36`；improve-animations finding #1 `demos-audit.js:30`）

所有键盘触发（`keydown` 或 `click && detail===0`，判别式沿用 `demos-motion.js:22` 的 `keyboard()` 先例）**跳过位移与缩放，直接终态**；结果类反馈优先用**文字本身**说明发生了什么（emil-design-eng「按钮宽度保持稳定；文字变化就是结果反馈」`demos-motion.js:177`）。

## 一、悬停揭示（高价值动效面一）

### M-01 图标三态过渡：idle .70 → hover/focus 全亮

- **① 触发与状态源**：纯 CSS——`:hover` / `:focus-visible`；idle 档位由 03a 8.2 的 `data-idle`（mid .8 / low **.70**，R3 P1-5 修订值）与 03b 的 `.orbit-icon-entry`（.8）、`.orbit-source-icon`/`#chat-latest`（低档）承载；active 态由 `aria-current="page"`（dock）与 `aria-pressed`（步点）驱动。悬停/聚焦/激活只改 color、opacity、background-color 三个非布局属性。
- **② 参数**：过渡 180ms `--orbit-ease`；**按压态（active）另给 160ms scale(.97)**（见 M-04，图标格本身不缩放，避免与底色变化叠加）；`pointer:coarse` 低档提升 .75（03a 4.4）；`hover:none` 下去粘滞（03a 8.2 先例）；触屏「点按即动作本体」无新增动画（02a 第八节注）。
- **③ UISkill 出处**：emil-design-eng（`demos-motion.js:164–188`，注册段 201）——悬停变化与按压反馈分离、`me-keys` 键盘模式移除过渡（183–184）；find-animation-opportunities（`demos-audit.js:21–27`）——图标 hover 属高频面，判定：只做色/透明度过渡、不做位移，通过。
- **④ reduce 降级**：`prefers-reduced-motion: reduce` 或 `html[data-motion=off]` 下**移除全部过渡，直接切换**（比 125ms 更彻底：悬停色变是状态回执不是运动，需要 reduce 的用户更需要即时回执；与 emil 键盘模式同逻辑）。透明度档位本身不动（.70 是可见度不是动画）。
- **⑤ 片段草稿**：

### M-02 悬停提示卡 `.orbit-tip` 浮现与收回

- **① 触发与状态源**：计时逻辑归 orbit.js（03a 8.3 注「样式不含计时逻辑」）。指针悬停 350ms 意图延迟后 `data-show`；键盘 `focus` **0ms 立即**；触屏长按 450ms（`pointerdown` 起计时，移动 >8px 或抬起取消），呈现后 1s 自动消退或移指即消（03a 4.2/4.4 定稿值，落在职责给定的 300–500ms 区间内取定值）；移出/blur **立即收回**。Esc 关最上层（03a 4.2）。
- **② 参数**：出现 = 180ms 纯淡入，**无位移**（03a 4.2 定稿「无位移（克制）」——职责清单中的「位移」选项经评估后**放弃**：提示卡不是弹层，无「从触发器生长」的空间叙事需求，位移只增加噪动；理由登记第十节 2）。收回 = 同速 180ms 淡出（03a 8.3 的 `visibility` 延迟技巧保收回可中断）；触屏 1s 自动消退同 180ms。
- **③ UISkill 出处**：animate（`demos-motion.js:25–40`，注册段 191）——可中断展开/收回、反向操作从当前画面继续（`from=frame(panel)`，28 行）、键盘触发即时切换（34 行 `if(!keyboard(event))`）；emil-design-eng（`demos-motion.js:169–172`）——弹层 180ms 展开 / 125ms 收回的进出不对称先例；find-animation-opportunities 四门——悬停提示是偶发+理解型，180ms 通过；收回 faster-than-enter 的不对称取 emil 值（180/125）但保留 03a 定稿的对称 180ms 为准，125ms 收回登记为备选。
- **④ reduce 降级**：125ms 仅淡入（03a 8.3 已写 `--orbit-dur-quick`）；收回同 125ms；触屏长按计时不变（计时不属动效）。
- **⑤ 片段草稿**（orbit.js 控制器**定稿**——这是主代理点名的高价值动效面，勿再示意化，可直接落码；样式沿用 03a 8.3，仅补 reduce 收回）：

```js
// orbit.js · tip 控制器（R4 P1-3 修订定稿；主代理点名的高价值动效面，勿再示意化）
const HOLD_MOUSE = 350, HOLD_TOUCH = 450, AUTO_DISMISS = 1000, MOVE_CANCEL = 8;
let hold = 0, dismiss = 0, downX = 0, downY = 0;
function show(tip) { clearTimeout(dismiss); tip.setAttribute('data-show', ''); }
function hide(tip) { clearTimeout(hold); tip.removeAttribute('data-show'); }
icon.addEventListener('pointerenter', e => {
  if (e.pointerType === 'touch') return;                       // 触屏走长按
  hold = setTimeout(() => show(tip), HOLD_MOUSE);              // 鼠标意图延迟：仅 pointerleave 清除，微动不清（R4 P1-3）
});
icon.addEventListener('pointerleave', () => hide(tip));        // 移出立即收回（两型通用）
icon.addEventListener('focus', () => show(tip));               // 键盘 0ms
icon.addEventListener('blur', () => hide(tip));
icon.addEventListener('pointerdown', e => {                    // 触屏长按 450ms
  if (e.pointerType !== 'touch') return;
  downX = e.clientX; downY = e.clientY;
  hold = setTimeout(() => { show(tip); dismiss = setTimeout(() => hide(tip), AUTO_DISMISS); }, HOLD_TOUCH);
});
icon.addEventListener('pointermove', e => {                    // 仅触屏且位移 >8px 才取消长按（微动不清除）
  if (e.pointerType !== 'touch') return;
  if (Math.hypot(e.clientX - downX, e.clientY - downY) < MOVE_CANCEL) return;
  clearTimeout(hold);
});
['pointerup', 'pointercancel'].forEach(t =>
  icon.addEventListener(t, () => clearTimeout(hold)));         // 抬起取消：两型通用（move 不在全局清单）
```

```css
  html[data-theme=orbit] .orbit-tip { transition-duration: var(--orbit-dur-quick); }
}
```

## 二、徽标动效（高价值动效面二）：一次性强、常驻静

### M-03 dock 徽标三态：出现 / 数值变化 / 消散

适用三徽标（01 大纲 N2 簇归属）：**待确认消息**（系统簇，warn 档）、**DSH 协作未读**（系统簇 DSH 图标，warn 档）、**P1 待绑定**（工具簇，info 档）。状态源：orbit.js 从既有信号镜像（`#chat-new-attempt`/`#workers-count`/`#composer-evaluation`），徽标值与 data-tone 由 orbit.js 维护。

- **① 触发与状态源**：
  - **出现**（0→n）：一次性「双波微光 + 弹跳」——pop 220ms + 2.4s 单次微光（两波），播完由 orbit.js 移除标记，**此后常驻完全静止**（03a 3.4「允许 2.4s 微光脉冲」在本稿解释为一次性协议：催答教训=状态在场不等于持续催促，一次说清即可）。
  - **数值变化**（n→m，m>n）：只重播 pop 220ms（数字更替本身即回执，emil-design-eng：文字变化就是结果反馈），微光不再重播——用户已被「出现」告知过一次。
  - **消散**（n→0）：150ms 淡出后移除（徽标为绝对定位，淡出无布局跳动、不遮挡点击路径）；reduce 直接移除。
- **② 参数**：pop `scale(1→1.16→1)` 220ms `--orbit-ease` 1 次，`transform-origin: 70% 30%`（朝图标外缘爆开，不压图标主体）；微光 `box-shadow` 0→4px→0 两波，总时长 2400ms，色随 `data-tone`（warn `#e4c080` / info `#91b8ff`），峰值 alpha ≤0.33（「微」光的克制上限）；**双落点去重**：当前已在 P1 且页内同源提示可见（`#chat-new-attempt` 非 hidden）时，dock 徽标**只出现、不脉冲**——同一状态不双通道催促。
- **③ UISkill 出处**：find-animation-opportunities（`demos-audit.js:21–27`）——「提示不催促」= 用途门判定：注意力反馈允许，循环噪声拒绝（对照「数据图表·装饰性重绘→拒绝」候选）；animation-vocabulary（`demos-audit.js:9–16`）——本项术语为 **Press/Tap feedback 族的一次性 attention pop**，非 Stagger/非循环 pulse；emil-design-eng（`demos-motion.js:176–179`）——计数变化的文字即反馈先例。
- **④ reduce 降级**：`prefers-reduced-motion: reduce` / `data-motion=off` 下 pop 与微光一律**停帧**，只留状态色与数字（03a 3.4 门禁原文）；出现/消散即直接显隐无过渡。
- **⑤ 片段草稿**：

```js
// orbit.js · 徽标注意力控制（示意；一次性强、常驻静）
function updateBadge(badge, value, prev) {
  badge.textContent = value > 99 ? '99+' : String(value);       // 03a 3.4 上限规则
  const duplicated = document.body.dataset.orbitPage === 'p1' &&
                     !document.getElementById('chat-new-attempt')?.hidden;  // 双落点去重
  if (!prev && value) badge.setAttribute('data-attention', duplicated ? 'quiet' : '');
  else if (value > prev) retriggerPop(badge, duplicated);       // 只重播 pop，不重播微光
  else if (!value && prev) retireBadge(badge);
}
function retriggerPop(badge, quiet) {
  badge.removeAttribute('data-attention'); void badge.offsetWidth;   // 重置动画
  badge.setAttribute('data-attention', quiet ? 'quiet' : '');
}
badge.addEventListener('animationend', e => {
  if (e.animationName === 'orbit-badge-glow') badge.setAttribute('data-attention', 'done'); // 常驻静
});
function retireBadge(badge) {
  badge.setAttribute('data-fading', '');
  badge.addEventListener('transitionend', () => badge.remove(), { once: true });
}
```

## 三、状态色反馈（高价值动效面三）：操作前 / 中 / 后

### M-04 通用反馈框架（四条高频链的公共部件）

- **① 触发与状态源**：全为既有状态属性驱动，零新轮询——按压=`:active`；忙碌=03c 2.3 的 `data-busy`（qq.js / claude-gate 既有 class，orbit.js 只挂不造）；结果=`data-kind=ok|error`（result 行既有语义，discovery.js 用 `data-kind`，R3 P2-6 已核）；待保存暗示=`data-dirty`（orbit.js 监听窗内 `input/change` 挂/摘，新增钩子入还原表）。
- **② 参数**：
  - **前（前置暗示）**：表单有未保存更改时，保存钮边框 180ms 过渡到 `--accent`（「这里有一处待保存」的非文字暗示，服务收纳手段 5）；未满足前置（M6 ack 未勾）时保存钮保持 disabled .45 不动——**禁用态不给动画**（disabled 的出现/消失 180ms opacity 过渡一次）。
  - **中（点击确认）**：按压 `scale(.97)` 160ms（emil 值，`demos-motion.js:185–186` pointerdown/up/leave/cancel 四路复位）；忙碌=钮内 12px 旋转弧线 800ms/圈 linear + 钮 disabled；`progress#qq-setup-progress` 条 4px accent（03c 2.3 皮），进度增长不做补间（真实进度不表演）。

```js
// orbit.js · 步体切换（R4 P1-4 修订：stepSeq 纪元守卫；键盘/reduce 直切）
let stepSeq = 0;
function switchStep(fromEl, toEl, subEl, nextName, opts) {
  const seq = ++stepSeq;                                       // 重入守卫：每次请求取纪元号
  if (opts.reduced || opts.keyboard) {
    fromEl.hidden = true; toEl.hidden = false;
    subEl.textContent = nextName; return;
  }
  fromEl.setAttribute('data-leaving', '');
  setTimeout(() => {
    if (seq !== stepSeq) return;                               // 期间有新请求：过期回调整体丢弃
    fromEl.hidden = true; fromEl.removeAttribute('data-leaving');
    toEl.hidden = false; toEl.setAttribute('data-entering', '');
    requestAnimationFrame(() => requestAnimationFrame(() => {
      if (seq !== stepSeq) return;
      toEl.removeAttribute('data-entering');
    }));
    subEl.setAttribute('data-swap', '');
    setTimeout(() => {
      if (seq !== stepSeq) return;                             // 副行换字共用同一 seq 判断
      subEl.textContent = nextName; subEl.removeAttribute('data-swap');
    }, 120);
  }, 120);
}
```

重入守卫说明（R4 P1-4）：切换进行中（两处 120ms 未走完）的新触发使旧请求的全部回调失效，旧步体不会被过期回调误置 hidden——连点步点时「最新请求胜出」，与 ③ 所引 animate 技能「可中断、从当前画面继续」语义对齐；reduce/键盘直切分支不受守卫影响（同步路径无待决回调）。

## 六、句级揭示共存（红线防护 + 衔接设计）

### M-11 揭示节奏之上的 orbit 微观：不加动画，给约束

- **① 触发与状态源（只读核对结论）**：`revealPush` 首句 `setTimeout(…, 0)` 立即可见（app.js 2794）；句间 `revealDelay = min(520, 170 + n×14)`（2764–2767）；`revealStep` 每句经 `renderTurnBubbles(container, shown)` **整轮重渲**（render 回调传入 2864，逐句执行 2786；2886 为 done 分支的 revealSync 调用点——R4 P2-4 勘误）；done 走 `revealSync` 对齐缓冲按原节奏放完、对不上时整段立即兜底（2802–2819）；沉默在 done 且 `!revealActive` 时 `renderTurnBubbles(node, "（沉默）")` 一次成形（2889）；`is-receiving` 挂在 `#chat`（340，页级类，非 #msgs 内部）。
- **② 参数（设计决定）**：**气泡与句级入场一律不加 CSS 动画**——两道判断门拒绝：频率门（每轮对话数十句、聊天是 100+ 次/天的高频面，demos-audit.js:23 的「快捷命令」同款拒绝）；机制门（`renderTurnBubbles` 整轮重渲会让任何挂在气泡上的 animation 在每句 reveal 时**重播闪烁**，除非改 DOM 打 reveal 红线）。句的「入场」就是文字按句生长本身——这已是节奏化动效，叠加透明度动画只会延迟首句可读性。桌面 180ms 淡入上移 6px 先例**不在 web 端复制**（该先例的 DOM 每句独立节点，本机制是整轮重渲，前提不同）。
- **③ 衔接约束（交动效 A 与集成）**：
  1. A 的页容器入场转场**只做容器级**（`.orbit-page`/`#orbit-main`），不得包裹/搬移 `#msgs` 子节点（01 大纲第八节红线）；建议 A 的页入场 ≤240ms 完成，与首句 0ms 计时并行——首句在容器淡入后半程即出现，可读性不受损。
  2. reveal 计时是 `setTimeout`，**不受 rAF 暂停影响**：`document.hidden` 停 rAF（orbit-bg 门禁）不停 reveal；页面隐藏期间到达的增量由 `revealSync` 对齐兜底——orbit 侧无需也不得做「补放加速」。
  3. **「（沉默）」占位即时呈现、零动画**：它是状态事实不是新话语，动画会被读作「她说了话」；同理 `reasoning` 思考块（`el.textContent = s` 直渲，2856）不加逐字动画。
  4. `#chat.is-receiving`（页级）可供 orbit 做接收中的页级微观（如 composer 发送钮 disabled 过渡），**不得**用于给 #msgs 内部加态。
- **④ reduce**：本项为零新增动画，reduce 侧仅守上述约束（无可降级物）。
- **⑤ 片段**：无 CSS/JS 新增——红线即产出；本节全部内容为「不做清单 + 三条衔接约束」。

## 十、最主观决定登记（供主代理与 R4 复核）

1. **徽标注意力协议收紧**（M-03）：03a 3.4 的「允许 2.4s 微光脉冲」按字面可理解为常驻循环；本稿收紧为「出现/数值增加时一次性双波 2.4s，播完永久静止 + 双落点去重（P1 在场时 dock 徽标静默出现）」。依据是任务书红线原句「脉冲不得成为常驻噪音」与 11-12 反省教训；若主代理认为「出现即一次、增加不重播 pop」过冷，可放宽为「增加也重播完整双波」，但循环常驻不可接受。
2. **提示卡放弃位移**（M-02）：职责清单列了「位移+透明度」，03a 4.2 定稿为无位移淡入——本稿从 03a（上游定稿优先）；tip 不是弹层，「从触发器生长」叙事（Origin-aware，demos-audit.js:11）不适用。若 R4 认为纯淡入过淡，备选=4px 上浮，需 R3/03a 同步修订。
3. **步点 `::after` 元素化为滑移指示条**（M-09）：动 03c 1.6 既有规格（新节点 + 还原表登记 + `data-ready` 门控）。滑移的收益是分区切换方向可读；代价是 03c CSS 修订与一个新节点。若裁定不值，回退方案=保留 `::after` 静态、切换靠步点底色 180ms 过渡（无滑移）。
4. **reduce 下 hover 色变直接砍过渡**（M-01/06/07）：比「125ms 仅淡入」更激进——理由是 reduce 用户更需要即时状态回执；与 emil `me-keys` 键盘模式同构。若审查要求全稿统一 125ms，改动成本一行。
5. **「（沉默）」与句级零动画**（M-11）：拒绝了桌面 6px 上移先例在 web 端的复制，理由是整轮重渲机制不同 + 高频门拒绝；此决定同时是对动效 A 的约束移交。
