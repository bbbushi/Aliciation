## 〇、总则与门禁源

1. **两个等价的门禁源**：`html[data-motion=off]`（M3 动效开关）与 `@media (prefers-reduced-motion: reduce)`。落码用同一条覆盖规则双选择器并列，行为完全一致，本稿降级总表（第五节）按行给值，不再分叉。
2. **转场的胶水是舞台不是页面**：orbit-bg 画布常驻跨页不灭（方案 A），页面切换的视觉连续性由背景承担——这是"大页退场可以即隐"（第一节 1.4）与"球位弹簧必须比页慢半拍"（第二节 2.2）两条决定的共同前提。
3. **单 rAF 全局盘点**：orbit-bg.js 持有全主题唯一 rAF 循环（改编 room.js 293–317 结构）；orbit.js 的全部转场走 CSS animation / WAAPI 事件驱动，**零 rAF**；dock 光点、hub 印记、步点条为纯 CSS transition。每模块单 rAF 门禁由此天然满足。
4. **一切转场容器级**：动画目标只允许 `.orbit-page` / `#orbit-main` / `.orbit-window` / 步体容器 / 浮层壳；**禁止**把 `#msgs` 子节点包进任何带动画的包装层，禁止在转场动画进行中执行 DOM 搬移（orbit.js 的节点搬移只在主题切换时刻一次性完成，与转场动画不同帧——搬移完成后再挂入场类，见 1.6 顺序注）。
5. **reveal 红线的动效侧表述**：容器级入场动画不会重排 revealStates/revealSync 的 DOM 顺序与句级节奏（动画只改容器的 transform/opacity，#msgs 子树零触碰）；从他页切回 P1 时**不重播揭示**——容器动画只播一次，句子级 `.message-arrive` 动画由 app.js 驱动，orbit 域不触发、不抑制、不重放。
6. **M10 全程禁 transform**（甲-10）：`#orbit-win-workers` 入场只 opacity、退场只 opacity、拖动/固定/预览全程窗壳无 transform（原因：窗壳 transform 会成为内层 `position:fixed` 拖动/预览的包含块致错位）。本稿所有窗规格凡涉 M10 均按此例外执行。

## 一、页面切换转场（dock 切大页）

### 1.1 触发与状态源

- 触发：dock 一级簇图标点击（`#chat-nav` 等四图标；P4「去思想与探索」跨页卡、dock 待确认徽标「切至 P1」同走此转场）。
- 状态源：orbit.js 在**点击同帧**写入 `body[data-orbit-page="chat|discovery|thoughts|settings|onboarding"]`；同一帧完成旧页隐藏、新页显示与入场类挂载（时序见 1.5）。属性是全下游的唯一状态源：CSS 入场选择器、orbit-bg 球位、dock `aria-current` 都从这一帧派生。

### 1.2 编排层次（"绕行停靠"的三拍）

依 **choreograph** 技能的主角/支持/静止分层（demos-motion.js L54「主信息先到；支持信息重叠跟进；容器与操作不动」）：

| 拍 | 元素 | 角色 | 启动 | 参数 |
| --- | --- | --- | --- | --- |
| 一拍·停靠 | dock 站点光点 + 图标色/底 | 支持（操作回执） | t=0 | aria-current 即时切换（状态无动画），色/底 opacity+background-color 过渡 180ms `--orbit-ease` |
| 二拍·站台亮起 | `.orbit-page` / `#orbit-main` 容器 | **主角** | t=0 | opacity 0→1 + scale(.97)→1，240ms `--orbit-ease`，页影随容器 opacity 同步淡入（**不单独动画 box-shadow**） |
| 三拍·绕行完成 | orbit-bg 球位/镜头/视差 | 余韵（背景层） | t=0 | 弹簧插值，响应 0.9s 临界阻尼（第二节），比页晚落定 ≈600–900ms |
| 静止 | dock 本体、页头文字、页内子元素、scanlines | 不动 | — | **不给 dock 与页内子元素叠加任何入场**（choreograph 红线：不为容器与子元素叠加入场；错峰排长队=页面动得比读快） |

先后关系的读感设计：光点与页入场**同帧启动、不排人工延迟**（输入到反馈零等待），先后感由各自时长差自然形成——180ms 光点先落（"停靠"）、240ms 页安定（"站台亮起"）、0.9s 球最后归位（"镜头绕行完成"）。三拍总时长 ≈0.9s，其中用户可交互时点在 240ms。

**UISkill 出处**：choreograph（demos-motion.js L42–58：主角/支持/静止分层与重叠跟进 L51/L54；reduce 一致淡入无错峰 L51）；animate（L25–40：入场用 transform+opacity、退场不对称时长的先例 L34）。

### 1.3 入场参数

- 帧序列：`opacity: 0 → 1`；`transform: scale(.97) → scale(1)`（03a 门禁：起点禁 scale(0)；03b §七.1 锚点原文）。transform-origin：**50% 50%**（大页是"到站"，不是"从入口生长"——生长语留给召唤窗，见第三节 3.1）。
- 时长/缓动：**240ms** `--orbit-ease: cubic-bezier(.2,.7,.2,1)`。240 高于 03a 常规档 180ms 的理由：页容器是全屏级表面，180ms 会读成"闪现"；240ms 落在 choreograph 演示的总时长量级内（L194：200/190/180 错峰总计 270ms）。登记为最主观决定 2（§八）。
- 大页两形同参：整页单卡形（`.orbit-page`）与壳内原生皮形（P1 `#orbit-main`）用同一组关键帧；OB 引导容器（`#orbit-page-onboarding/#orbit-page-welcome`）亦同参（引导是特殊大页，不另设）。
- **中断语义**（animate 技能：反向操作从当前画面继续，L29/L33–34）：连续快点另一 dock 图标时——旧目标页尚在入场即被 `display:none`（动画随显示移除自动取消，无残留回调）；新目标页按全参数重新入场。不做"从中途帧续接"（页面级切换无对称反向操作，续接只用于窗，见 3.2）。

### 1.4 退场决定：切走即隐，无退场帧

**决定：旧大页在切换帧直接 `hidden`（display 切换），不做淡出。**

依据四条：

1. **背景提供连续性**（总则 2）：旧页消失的瞬间，新页恰好从 opacity:0 开始淡入，画面主体始终是常驻的背景舞台——不存在"黑帧"，也就不需要退出动画来衔接。这正是不选交叉淡化的原因：两页同位置交叉淡化会叠影（90% 透明页容器叠加时文字互透），且合成成本翻倍。
2. **隐喻一致**：orbit 的页是"绕行停靠的站"——切换读作"你已在下一站"，不是"旧站缓缓远去"。
3. **animate 技能的退场原则**（L34）：退场时长 ≤ 入场（此例为 0），偶发操作不值得为离场支付注意力；emil 技能同理（L201「没有为高频操作添加长入场」的镜像——不为高频切页添加任何退场）。
4. **reduce 一致性**：reduce 下本来就直接切换；正常态选即隐使两条路径的 DOM 时序完全相同，集成与机检分支最少。

非 dialog 大页（P1–P4/OB）无原生 close 语义，即隐不涉焦点问题；焦点在 dock 图标上（点击者），无迁移。

### 1.5 `data-orbit-page` 五档切换时机

同帧五连（orbit.js 单个点击处理器内顺序执行，全部同步 DOM 操作，同一渲染帧生效）：

```
onDockPageClick(page):
  1. body.dataset.orbitPage = page          // 状态源写入（chat/discovery/thoughts/settings/onboarding）
  2. 旧页容器.hidden = true                  // 1.4 即隐；display:none 同时取消其在途动画
  3. 新页容器.hidden = false
  4. 新页容器.classList.add('is-entering')   // 挂 240ms 入场动画（CSS 见 1.6）；animationend 移除
  5. dock: 新图标 aria-current="page"，旧图标移除；orbitBg.setPage(page)  // 球位弹簧目标更新
```

顺序注：主题切换时刻的节点搬移（orbit.js 建 dock、搬 `#chat` 入 `#orbit-main` 等）必须**先于**本流程全部完成；转场动画永不与 DOM 搬移同帧（总则 4）。首帧进入主题（room→orbit）：dock 整体 180ms 仅淡入（dock 常驻 transform 为居中 translateX，入场只动 opacity 不冲突），随后默认页走同一入场。

## 二、背景联动编排（orbit-bg.js 规格——只出规格与参数，集成归主代理）

### 2.1 五档构图目标表（值全部来自 03b §六基准，本稿补动力学参数）

| 页档 `data-orbit-page` | 球心（视口） | 半径档 | 亮度因子 dim | 房间视差 panX | 意图（03b 原文） |
| --- | --- | --- | --- | --- | --- |
| `chat`（P1） | x 72% / y 62% | 1.00（≈26vmin 基准） | 1.00 | −0.10 | 她在页后，露左上弧与光晕 |
| `discovery`（P2） | x 82% / y 24% | 0.70（≈18vmin） | 1.00 | −0.14 | 右上高挂，向外看 |
| `thoughts`（P3） | x 18% / y 20% | 0.70 | 1.00 | +0.14 | 左上高挂，内在活动在天上 |
| `settings`（P4） | x 50% / y 88% | 0.46（≈12vmin） | **0.72** | 0 | 远小托底，系统在后台 |
| `onboarding`（OB1/2） | x 50% / y 22% | 1.15 | 1.00 | 0 | 她在场，球下缘距卡顶 ≥40px |

- 视口分数 → 世界坐标换算由 orbit-bg 在 `setPage()` 时按当前投影求逆（`worldX = (fx*W − CX) / (FOVK/(SPHERE.z+CAM_DIST))` 一次解出，窗口 resize 时重解）；半径档乘 `SPHERE.r` 基准。
- **dim** 是全局 alpha 乘子：粒子/连线 alpha（room.js L233/L254）× dim，球心柔光（L277–279）强度 × dim，房间线 base（L142–161）× `0.6 + 0.4*dim`——P4"低亮度托底"不用改色相，只降能量。
- **panX** 为房间线组的水平偏移（世界单位）：球向右绕（P2），房间向左微移（−0.14），反向形成"镜头绕行"视差；幅度上限 ±0.14（≈墙宽 5%），避免网格线穿帮。
- **构图红线执行**（03b §六）：弹簧全程临界阻尼无过冲（2.2），球任何时刻不得越入文字区正后、不得与 dock 保有 <24px 空隙——目标位本身已满足间距，无过冲保证过渡态也不越线。

### 2.2 弹簧插值规格

物理内核改编自 **apple-design** 技能的 springObject（demos-motion.js L93–102：半隐式欧拉 + 4ms 子步进 + 落定阈值）与 room.js 粒子弹簧同族；参数放宽为背景尺度：

```
响应 T = 0.9s          → w = 2π/0.9 ≈ 6.98
阻尼比 z = 1.0         → 临界阻尼，无过冲（构图红线让步；springObject 的 z=0.8 仅用于手势动量，此处无手势）
子步进 h ≤ 4ms         → steps = ceil(dt/0.004)（springObject L98 同法，防单帧长任务）
状态量：球心 (x,y)、半径 r、亮度 dim、视差 panX —— 各自独立弹簧，同一 tick 内积分
落定：|Δ|<0.002(归一) 且 |v|<0.01 → 吸附到目标并停掉该量积分（rAF 保留给呼吸/躁动）
```

- 0.9s 依据：球是大面积低频背景，比页（240ms）慢 3–4 倍才读作"镜头在绕"而非"页面带着背景跳"；临界阻尼是安全选择——欠阻尼的回弹会让球瞬时越过 03b 红线位。登记为最主观决定 3。
- `setPage()` 重复调用（快速连切）：直接覆写目标值，弹簧从当前状态继续积分（apple-design「随时抓住，随时改变方向」L199 的状态连续性语义），无需取消逻辑。

### 2.3 躁动（is-receiving）与运行态衔接

room.js 先例保留：`excite += ((speaking?1:0) − excite) · min(1, dt·(speaking?3.2:1.4))`（room.js L307），呼吸/噪声力/松动区公式（L166–208）全部沿用。orbit 增量：

| 信号源（只读，不读会话内容） | excite 目标 | 其他 |
| --- | --- | --- |
| `#chat.is-receiving`（MutationObserver，room.js L331 同法；`#chat` 搬入 `#orbit-main` 后同一节点观察不受影响） | 1.0 | 沿用 room 全参 |
| P2 发现运行中（orbit.js 镜像 `#discovery-run` 的 disabled 态） | 0.35 | "她在向外找"低度躁动 |
| P3 探索运行中（orbit.js 从 `#thought-lifecycle` 只读镜像 data-state） | 0.35 | "她在想" |
| P3 睡眠待机（同上，data-state=sleeping） | **强制 0** | 自转速率 0.14→0.06（room.js L168 `ry=t*0.14` 降档）、呼吸幅度 0.022→0.012（L167）——睡眠是"安静"（03a §十.3 同语义） |
| 其余 | 0 | 房间松动区照常游走（patches，L79–104） |

多信号取 max（睡眠强制 0 优先级最高）；信号→orbit-bg 经 `setState({page, receiving, discoveryRunning, thoughtState})` 单向传入，orbit-bg 不自行查询业务 DOM（除 `#chat` class 先例）。

### 2.4 门禁与静态帧

- `hardOK = motion==='on' && !document.hidden && theme==='orbit'`（room.js L294–295 结构；**room.js 294 行 themeOK 收紧为 `=== "room"` 与本门禁同批登记**）；`hardOK` 为假 → `paintStatic()` 一帧静态后停 rAF，visibilitychange / data-theme / data-motion 变更 kick（room.js L333–337 同法）。
- **静态帧取"当前页档基准位"**：paintStatic 按 2.1 表直接摆放球位/dim/panX（不经弹簧）——reduce/停帧下构图基准即最终状态（03b §六红线原文"静态也成立"）。
- **P1 消息流滚动时球静止**（03b §七.7）：orbit-bg 不监听任何 scroll——舞台不动，滚动是页内行为。
- **停画条件补登义务**（02a 甲-11）：`.chat-atmosphere` 在 orbit 下 display:none 后，app.js 3364–3424 氛围驱动循环不会自停——集成时须把「chat-atmosphere 已隐藏（orbit）」列入其停画条件，与本节 hardOK 同批落码。

### 2.5 orbit-bg 主循环伪代码（规格级，供主代理实现）

```js
const POSE = { chat:{x:.72,y:.62,r:1.00,dim:1.00,pan:-.10},
               discovery:{x:.82,y:.24,r:.70,dim:1.00,pan:-.14},
               thoughts:{x:.18,y:.20,r:.70,dim:1.00,pan:.14},
               settings:{x:.50,y:.88,r:.46,dim:.72,pan:0},
               onboarding:{x:.50,y:.22,r:1.15,dim:1.00,pan:0} };
let cur = {...}, vel = {x:0,y:0,r:0,dim:0,pan:0}, tgt = cur;
function setPage(p){ tgt = toWorld(POSE[p]); kick(); }        // 视口分数→世界坐标
function tick(ts){
  if (!hardOK()) { paintStatic(tgt); return; }                // 静态帧=目标基准位
  const dt = Math.min(.1, last ? (ts-last)/1000 : .016); last = ts;
  integrateSpring(cur, vel, tgt, /*T=*/0.9, /*z=*/1.0, dt);   // 4ms 子步，逐量独立，落定吸附
  excite += (exciteTarget() - excite) * Math.min(1, dt * rate()); // room.js L307；rate 受睡眠降档
  draw(ts/1000, excite, false, dt);                           // room.js draw 结构不变，alpha×dim，线组×(1+pan)
  raf = requestAnimationFrame(tick);
}
```

## 三、召唤窗编排（M1–M11 与 S 族窗壳）

### 3.1 入场（180ms，03c §7.1 定值落地）

- 触发与状态源：orbit.js 调 `dialog.showModal()`（或自建窗 open）**之前**同帧完成两件事：①把 transform-origin 写到窗壳 CSS 变量；②挂 `[data-opening]` 类启动动画；`animationend` 移除。
- 参数：`opacity 0→1 + scale(.97)→1`，**180ms** `--orbit-ease`；`::backdrop` opacity 0→1 同 180ms 同帧（03c 原文"同步"）。起点禁 scale(0)（03a 门禁）。
- **transform-origin 从触发点生长**（emil-design-eng：弹层 transform-origin 靠近触发器，demos-motion.js L169/L201 `transform-origin:20px 0`）：orbit.js 计算触发元素中心相对窗矩形方位，把 origin 夹取在 20%–80% 区间写入 `--orbit-win-ox/--orbit-win-oy`。P4 hub 分区卡、dock 图标召唤的窗会从入口方向微微"长出"；键盘触发（`event.detail===0`，demos-motion.js L22 同款判定）一律回退 50% 50%（键盘用户无指针方位语义）。登记为最主观决定 4。
- **M10 例外（甲-10）**：`#orbit-win-workers` 入场只用 opacity（180ms），**无 scale 无 origin 写入**；`::backdrop` 照常淡入。
- reduce / data-motion=off：125ms 仅淡入（backdrop 同）。

### 3.2 退场 B 案落地规格（R3 轮次 6 已裁定：≤120ms 淡出后真关）

裁定原文（05 轮次 6 第 5 条）：`[data-closing]` ≤120ms 淡出后真关，退场期 `pointer-events:none`，焦点回归时机不变；reduce 下不播退场直接关。落地规格：

```
关闭请求到达（Esc / 点 backdrop / × / 返回钮，三路径视觉同源——03c §1.4）：
  1. closing 防重入旗 = true（此后 Esc/×/backdrop 点击全部忽略，不重复入队）
  2. 焦点立即移回召唤入口（与原生 close() 的回归目标同帧同目标——"时机不变"按字面执行：
     手动先移焦点，随后 close() 的原生回焦落在已聚焦元素上 = 无操作）
  3. 窗体 inert + pointer-events:none（视觉上立刻不可交互，03c §1.4 防误触原文）
  4. 挂 [data-closing]：opacity 1→0，120ms linear-in-ease-out（用 --orbit-ease 前段；只淡出，
     无 scale——退场不解释来源，emil L171 收回 125ms 同构）
  5. animationend（或 150ms setTimeout 兜底，防 animationend 因隐藏丢失）→ dialog.close()
     → 移除 [data-closing]、清除 origin 变量
reduce / data-motion=off：跳过 3–5 的动画段，直接按原生语义 close()（原生回焦时机=原语义）。
```

- 120ms 内 `::backdrop` 同步淡出（同 120ms）。
- 快速开关（关了立刻再开同一窗）：open 处理器先检查 closing 旗——若在退场中，立即 close()（跳过动画）再走入场；入场/退场不并行。中断续接（`from = frame(el)` + `animation.cancel()`）用于窗**开关往复**场景（animate L29 / emil L168 先例），本窗族退场 ≤120ms 太短，续接收益趋零，取"跳过直关"简化路径。
- **M10**：退场同规格（opacity-only，天然合规）。

### 3.3 多层堆叠（窗上开窗）的层级动效

先明确渲染事实（约束动效设计）：modal dialog 渲染于 top layer，**非后代元素任何 z-index 都盖不过它**。据此：

- **随窗子树浮层**（`.orbit-tip`、S7 卡、M10「更多」popover、窗内步点 tip）：它们是窗 DOM 后代，随窗同处 top layer，无层级问题，规格照第五节总表。
- **窗上开第二个 modal**（任一窗内触发 S1 全局确认框，最常见：M6 删除令牌、M10 popover 内管理确认外的独立确认）：后 `showModal()` 者自然压前窗。动效规格：
  - 新层入场：同 3.1 全参（180ms scale .97 + origin 朝触发方位；S1 为确认框，origin 取 50% 50%）。
  - **底层窗完全静止**（不缩、不退避、不变暗再加码——choreograph L54"容器与操作不动"的层间应用；叠两层 backdrop 的压暗叠加已是足够层级信号）。
  - **第二层 backdrop 用浅档**：提案 `--orbit-backdrop-2: #05080f66`（现窗 backdrop `#05080fd9` 的半强度）——两层全强度叠加会把舞台压到近黑，且"变暗信号独占"（03a §五.2）在双层下应读出"这是窗上的确认"而非"又一个新窗"。
  - 顶层退场：B 案同规格；底层窗原地不动等待，`animationend` 后自然恢复可交互（inert 由 top-layer 栈序自动解除）。
  - Esc 只关最上层：原生栈序，orbit.js 的 closing 旗按窗实例各自持有，不全局。
- **禁**：窗内再开同规格 `.orbit-window`（大纲防堆页红线；M2–M7 窗内切分区走步体切换，非开窗，见第四节）。

```js
// orbit.js 关闭路径草稿（三路径收敛为单一 closeWindow(dialog)）
function closeWindow(d, returnFocusEl) {
  if (d.dataset.closing) return;                          // 防重入
  const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches
              || document.documentElement.dataset.motion === 'off';
  if (reduce) { d.close(); return; }                      // 原生语义直关（含原生回焦）
  d.dataset.closing = '1';
  d.inert = true;                                         // 含 pointer-events:none（CSS 双保险）
  (returnFocusEl || d._orbitOpener)?.focus();             // 焦点回归时机 = 请求帧，与无动画时相同
  const done = () => { delete d.dataset.closing; d.inert = false; d.close(); };
  d.addEventListener('animationend', done, { once: true });
  setTimeout(done, 150);                                  // 兜底
}
```

## 四、步进与 OB 引导流编排

### 4.1 步体切换（M6/M7 窗内 + OB 共用规格，03c §7.2 定值落地）

- **触发与状态源**：步点按钮点击 / `selectSettings` 分区切换 / OB `data-wstep` 前进。状态源是宿主已有的 hidden-class 互斥（02x 状态机载体）——**动效只读它，不改它**：orbit.js 在状态翻转帧给旧步体容器挂 `[data-step-out]`、新步体挂 `[data-step-in]`。
- **参数**：旧步体 fade-out **120ms** → 新步体 fade-in **180ms**（03c 定值）。重叠关系：**串行**（旧出完新进，总 300ms）而非并行交叉——步体内含表单控件，交叉叠影会误读为两个表单同屏；300ms 内窗壳、窗头、步点条全部静止（choreograph 静止锚）。为压总时长，新步体 180ms 中前 120ms 与旧步体退场并行（旧容器在独立层叠上下文淡出，视觉不冲突时允许同帧启动——集成按实测定，默认串行）。登记为集成裁量点。
- **绝不触碰步内节点显隐类**（03c §7.2 原文）：动画类只挂步体**容器**。
- reduce / off：无出场上半段，新步体 125ms 仅淡入。

### 4.2 步点指示条与当前步名

- **指示条**（03c §1.6 `.orbit-step[aria-pressed=true]::after` 16×2px）：**推荐"单一指示条元素 + transform 滑移"**——orbit.js 在步点条内放一个绝对定位 16×2px 条，切换帧测量目标步点位置，`transform: translateX(Δ)` 过渡 180ms `--orbit-ease`（composite-only，见第六节；伪元素 ::after 方案无法跨元素测量，故改实体条）。reduce / off：跳变不滑移（03c 原文"reduce 下无位移（跳变即可）"）。若集成评估测量成本高，降级方案 = 各步点 ::after 淡切（旧 120ms 出 / 新 180ms 进），功能等价。
- **当前步名换字**（`.orbit-win-sub` / OB 步名）：内容更换归 JS（03c 原文），样式层给 180ms opacity 换字——JS 换字同帧挂 `[data-swap]`（opacity 0→1 180ms；reduce 125ms）。不做滑动换字（文字位移会引入阅读回扫）。

### 4.3 OB 首次到达与步进对勾

- **首次到达**（boot 完成 → OB1；OB1 → OB2；导入完成 → P1）：全部走第一节大页转场（240ms 容器入场 + OB 档球位弹簧 0.9s）。OB 页内**不做逐元素错峰入场**——引导期用户在"读"，页面不能动得比读快（03b §5.2 原文），卡体入场即全部内容在场。
- **步进行对勾**（03b §七.8）：`data-done` 挂上瞬间，对勾 SVG 一次性描画——`stroke-dasharray/dashoffset` 从全长到 0，**240ms** `--orbit-ease`，`fill: backwards`，只播一次；**与新步体入场同帧启动**（`animation-delay: 120ms` 恰对齐旧步体退场结束/新步体入场起点——读者注意力不被拉回已退场的旧侧，R4 P2-2 二选一定此支）。240ms 为全主题对勾族统一值：与 04b M-04 结果回执对勾同参（demos-audit.js:25「首次完成 240ms」recipe；P1-1 裁定），不与步体切换排长队（choreograph 单波内短元素）。reduce / off：不描画，对勾 125ms 淡入或直接出现。
- **OB2 已有人格卡（时刻 A 主位）**：随卡体入场在场，不单独动效；「以她开始」点击即步体切换规格。
- **拖放悬停态**（`.drop.over`）：accent-soft 底色 120ms 背景色过渡（现状反馈保留，03b §5.2 红线邻域"注意力设计不删"）；reduce 保留颜色切换（颜色不属于运动门禁，但过渡时长降为 0，直接切换）。

## 六、性能预算（转场期绘制成本控制）

对照 **animation-performance** 技能演示（mountPerformance，demos-motion.js L60–79：width 推动布局 vs scaleX 保留布局 L66–70；键盘源不动画 L74–76）：

1. **composite-only 纪律**：全部转场只动 `transform` 与 `opacity`（页/窗/步体/浮层/对勾 dashoffset 属 SVG 绘制层，量小豁免）；**禁**动画/过渡 `width/height/top/left/margin`（layout 属性）；03c §7.2"折叠不做高度动画"与本条同源。短促色彩过渡（dock 图标 40px 格、hub 卡边框）允许——paint 面积极小且非逐帧连续。微元素 paint 豁免边界（R4 P2-1 配套）：box-shadow 微光（徽标脉冲/toast 竖条/S9 点）与 SVG dashoffset（对勾描画）同属登记在案的面积极小豁免；但布局/合成之辨无豁免——指示条等位移一律 transform（translateX/scaleX），禁 width（与 04b M-09 scaleX 修法接平，demos-motion.js L66–70 结论）。
2. **页影不单独动画**：入场"页影同落"由容器 opacity 承担（阴影随元素透明度同淡）——禁 box-shadow 过渡（paint 成本大且无必要）。
3. **will-use 声明策略**：`will-change` 只在运动期存在——入场元素经 `.is-entering`/`[data-opening]`/`[data-step-out]` 类携带，`animationend` 或 400ms 兜底移除；**常驻选择器一律不写 will-change**（页容器是滚动容器，常驻提升徒增显存与层树）。
4. **单 rAF**：全主题唯一 rAF 在 orbit-bg（总则 3）；弹簧 4ms 子步上限（springObject L98）防止单帧长任务；转场期 canvas 与 CSS 动画并行——canvas 帧内预算优先（粒子 alpha 分桶绘制沿用 room.js L229–269，P4 dim=0.72 使高 alpha 桶减少）。
5. **`document.hidden`**：CSS 动画由浏览器挂起不耗帧；orbit-bg 经 hardOK 停帧 + visibilitychange kick（room.js L294–295/L337 先例）。
6. **转场与 fixed 后代的包含块风险**：入场动画进行中容器 transform ≠ none，会成为内部 `position:fixed` 后代的包含块。受影响节点：S5 gate（fixed right/bottom）、`#workers-dock-preview`（fixed）。集成约定：两节点由 orbit.js 确认注入/保持在**页容器之外**（body 级；gate 若被 claude-gate.js 注入页内，则 orbit.js 在 P1 入场 240ms 内到达的 gate 延后至 animationend 再落位——挂队列，一次性成本）。M10 窗壳全程无 transform，天然无此问题（甲-10 的第二重理由）。
7. **中断不泄漏**：页动画随 display:none 自动取消；窗退场有 150ms 兜底 timeout；WAAPI/CSS 无遗留回调（animate L13 finished/catch 清理模式同源）。

## 七、红线自查清单（R4 审查员可逐条机检）

1. 转场动画目标集合 = {`.orbit-page`, `#orbit-main`, OB 容器, `.orbit-window`, 步体容器, 浮层壳, dock 图标格, 步点条指示条}——无任何 `#msgs` 子节点、无 `.msg/.txt/.think/.message-meta`、无 revealStates 相关节点出现在 @keyframes/transition 选择器中。
2. 主题切换的节点搬移（orbit.js 还原表全部动作）与转场动画不同帧：搬移完成 → 下一帧才允许挂 `.is-entering`。
3. `#orbit-win-workers` 的任何动效规则不含 transform（grep `#orbit-win-workers` 的 animation/transform 全表核对）。
4. 每个 @keyframes/transition 均有 reduce + `html[data-motion=off]` 双分支（第五节表逐行对应）；`data-motion=off` 分支须与 reduce 分支**选择器前缀同形**（同元素属性形式 `html[data-theme=orbit][data-motion=off]`），**禁止后代组合器**（R4 P1-2：`html[data-motion=off] html[…]` 永不命中，门禁静默失效）。
5. `body[data-orbit-page]` 是唯一页档状态源；orbit-bg 只经 setPage/setState 收状态，不反向改 DOM 结构。
6. 焦点：窗退场焦点回归在请求帧（3.2 第 2 步）；切大页焦点留 dock；OB 步进焦点落当前步内容（宿主机制，动效不改）。
7. 转场不重播句级揭示（总则 5）；P1 隐藏期间 revealSync 照常运行（app.js 域，orbit 不碰）。

## 八、新增令牌提案与最主观决定登记

**新增令牌提案（2 条，登记待 03a/主代理确认）**：

| # | 提案 | 值 | 理由 |
| --- | --- | --- | --- |
| i | `--orbit-dur-page` | 240ms | 页容器级转场专用时长（区别于 `--orbit-dur` 180ms 常规档），一/三/四节三处复用 |
| ii | `--orbit-backdrop-2` | `#05080f66` | 第二层 modal（窗上 S1）浅压暗档，避免双 backdrop 全强度叠加 |

**最主观决定登记（供主代理复核）**：

1. **大页退场即隐**（1.4）——拒绝交叉淡化/淡出，依据背景常驻连续性；若真人验收觉得"太切"，加码处建议给旧页 80ms 极速淡出（上限 100ms）而非对称退场。
2. **页入场 240ms**（1.3）——超出 03a 常规档一档，为全屏表面的可读时长；审查如认为过长可回 200ms，不建议低于 180ms。
3. **球位弹簧 0.9s 临界阻尼**（2.2）——无过冲是构图红线的让步；若想要"抵达感"可用 z=0.9 轻微欠阻尼，但须先复核五档基准位与红线的间距余量。
4. **窗 transform-origin 从触发点生长**（3.1）——orbit.js 需计算方位（约 10 行）；若集成裁定成本不值，回退 50% 50% 无损其余规格。
5. **P4 dim=0.72**（2.1）——"远小托底"的亮度化表达；数值凭情绪定，真人验收可调（0.65–0.8 均安全）。
6. **步体切换默认串行**（4.1）——保守选型；集成若实测 300ms 体感拖沓，允许并行裁量（已在文内登记）。
