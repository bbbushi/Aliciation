## 公共回收与恢复

既有`ChatService.worker_tasks`与GUI同源`/api/worker-tasks`列表、`/detail`、`/events`返回task/epoch/状态/版本/取消/termination_confirmed/agent_idle，增加`recovery_basis`及`recovery_available`。`usage`含source、billing=reported_only、known（input/output token均有报告）、cost_known、reported_cost_usd（部分已知和，不是全账单）、unknown_attempts、unknown_launch_attempts及attempts列表。每attempt投影attempt_id/state/sent/launched_at/source/cost_known/cost_usd；sent=可能已发，不代表精确一次。没有完整prompt、凭据、任意终端日志。

独立Claude政策公共面：`ChatService.claude_policy(payload=None)` / 同GUI来源与workers意图的GET/POST `/api/claude-policy`。GET返回session_epoch/revision/worker_id/policy/runs_used/metering/permission_profile；POST精确字段`session_epoch, request_id, revision, enabled, native_sandbox_ack, workspace_root, max_turns, budget_usd_per_task, budget_usd_per_day`。相同参数不改版；实质变更先发布新版本，再仅取消Claude任务、撤回其正文及派生；不重派或退账。绝对既有目录与原生监督确认是启用前提，默认关闭；零预算禁止新准入。当前没有专门Claude设置面板，人工SDK使用公共service；浏览器原有GUI权限不变。

质询仍走`ChatService.worker_permissions('list'/'answer')`和同源`/api/worker-permissions/list|answer`。答案必须回传id/task_id/attempt_id/epoch/worker_id/policy_revision/expires_at/action_digest/resource_digest/decision；首答案原子发布，同答幂等，冲突拒绝。缓存也走当前宿主政策校验。gate审计不再保存完整工具输入。取消/撤权会写attempt控制目录revoked标记，gate等待中及返回allow前复核，以拒绝已发布但尚未消费的旧答案；文件写失败仍继续外层进程回收。这不是所有工具的OS原子授权机制。

人工恢复入口：GUI任务详情“人工核实后恢复”；或已获准公共service/GUI同源POST `/api/worker-tasks/recover_local`。参数：`session_epoch, task_id, request_id, revision, confirmed_stopped=true`；可选`cost_usd`及`launched_at`（Unix秒）。只允许Claude终态且无执行线程；若保留自有Job句柄，先尝试核实整树，无法证明仍拒绝恢复。重启无句柄时，只能由人先确认相关运行及子进程已停，再提交；返回`recovery_basis=human_attested, agent_idle=true, termination_confirmed=false`，清楚区别人工结论与OS证据。执行state保留unknown，不把恢复写成任务成功。已有费用/启动时间不能覆盖，缺失值可补且标人工来源。未补尾账仍阻新任务；不归还次数，不删账本，不自动重派。恢复后明确重试先前被阻止的reset/关闭/连接操作；恢复本身不替用户重做这些操作。

DSH停止仍只确认原生会话idle，不承诺外部OS树。新桥身份不能洗掉旧unknown；先按原DSH会话人工核对，未取得原会话idle证据不能放行执行槽。

## 崩溃与竞争的静态推演

| 位置 | 可证明事实 | 收口 |
|---|---|---|
| Job创建前/失败 | 尚无adapter与CLI | 启动失败，不消费；无进程可回收 |
| adapter起后、绑定前 | 固定adapter仍阻塞读首帧，没有CLI后代 | 绑定失败只终止自有Popen；wait失败则unknown |
| Job绑定后、GO前 | 仅自有等待adapter | Job回收；准入取消无需执行任务 |
| GO开始写/flush异常 | 可能已开始CLI，launched_at/sent已记 | 不能当未启动，Job整树核实；费用未知保留 |
| 父先退出/收到result | Job仍可含后代 | 查询整树，不用父poll或退出码判断；无法核实unknown |
| 取消先提交、迟到结果 | 取消事实优先，费用可以记录 | 不发布迟到正文；整树核实前不释放槽 |
| 宿主崩溃/重启 | KILL_ON_JOB_CLOSE会请求回收，但新宿主没有旧查询证据 | 账本unknown、不重派、不杀历史PID，人工核实恢复 |
| 日界前排队日界后GO | 启动日由launched_at固定 | 启动当日预算重核，取消尾账仍归启动日 |

Windows Job结构/调用仅做源码/语法审阅，未在本机运行任何API/进程树实验。Job嵌套兼容、CLI当前版本、登录/有效配置、服务退出与父退子存都必须真实人工补证。
