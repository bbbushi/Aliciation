# Alice 现状：模块分工与宿主边界

2026-11-03；按当前工作区代码梳理，包含未提交改动。本文说明代码职责，不代表全部能力已经人工验收，也不代表运行中的旧进程已加载所有新代码。

## 1. 先分清几个概念

**产品 Alice = 模型 + 人格与记忆 + 宿主程序 + 用户界面与连接器。**

| 名称 | 在这个项目里指什么 |
|---|---|
| 模型 | 经配置的模型接口生成回复、选择工具、提炼记忆或提出观点。不是某个本地 Python 文件，也不自动拥有本机权限。 |
| Alice 的持续状态 | 人格文件、对话记录、记忆、观点与相关依据；主要在 `user/data/`，不是写在模型权重里。 |
| 宿主（harness） | 加载状态、装配上下文、调用模型、执行和核准工具、保存结果、调度后台任务的本机程序。`alice/` 主要就是这套宿主。 |
| 工具 | 宿主给当前模型调用开放的有限接口。模型提出调用；宿主检查授权、额度、资料资格后执行。 |
| 协作者 Agent | DSH、Claude CLI 等独立执行者，有各自的运行环境与权限机制；Alice 宿主负责派工、监督和记账。 |
| 界面/渠道 | 浏览器 GUI、命令行聊天、本人 QQ 私聊；入口不同，但服务侧协调同一永久会话。 |

因此，人格、思辨、学习这些文件也属于宿主实现，只是其中包含让模型作判断的环节。不存在一个独立的“意识主程序”。

## 2. Python 文件分工

以下文件均在 `/Volumes/workspace/Aliciation/alice/`。按主要职责分类，同一文件可能跨越多个层次。

### A. 启动、服务与宿主基础

| 文件 | 主要职责 |
|---|---|
| `__init__.py` | 包说明。 |
| `__main__.py` | 接收 `python -m alice`，转入 CLI。 |
| `cli.py` | 命令分发；启动网页服务、终端聊天，或手动执行记忆维护、思辨等。终端路径有直接使用核心模块的部分。 |
| `server.py` | 本机 HTTP 服务、GUI API、聊天流输出、静态文件、服务关闭和连接器生命周期。 |
| `service.py` | `ChatService`：GUI/渠道共用的主要服务门面，持有数据库和模型客户端，协调请求、数据访问与各子系统。 |
| `channels.py` | GUI/QQ 请求身份、会话版本、排队与回执，避免重复请求和串线。 |
| `steps.py` | 驱动分步操作，把需持锁的数据步骤和阻塞 I/O 分开。 |
| `config.py` | 配置结构、默认值、本机路径与配置加载。 |
| `config_edit.py` | 校验版本并局部修改配置文件，避免覆盖其他配置。 |
| `llm.py` | 模型接口适配：客户端、调用、模型输出解析和错误整理；不负责 Alice 的全部业务决策。 |

最接近“宿主中枢”的是 `service.py`；`server.py` 是网络入口，`loop.py` 是对话执行中枢，三者不能互相替代。

### B. 对话运行与上下文装配

| 文件 | 主要职责 |
|---|---|
| `loop.py` | 执行一轮对话：取得人格快照、组合工具与上下文、调用模型、执行工具循环、收尾并保存回复。 |
| `retrieval.py` | 运行宪法与“存在事实”、人格/记忆/资料/历史装配，以及原有 `recall`、`remember` 工具。 |
| `context.py` | 上下文块清单、保守 token 估算、预算与完整对话往返选择；不负责长期存储。 |
| `context_memory.py` | 新的普通记忆候选目录与按需展开：`memory_search`/`memory_load`，本轮引用、读取额度及版本检查。 |
| `persona_context.py` | 读取固定人格快照，按用途和预算渲染人格与表达参考，提供指纹与样本依据。 |

当前代码保留两种普通记忆装配方式：默认 `legacy` 仍装配长期摘要、仓库索引和近期提炼；`indexed` 才使用候选目录与按需展开。`context_memory.py` 已出现在工作区并有调用接线，不能据此断言本机已切换或已验收。

### C. 人格、记忆与成长

| 文件 | 主要职责 |
|---|---|
| `store.py` | SQLite 存储门面：对话、三层记忆、技能、墓碑、元数据；组合来源、学习与协作资料扩展。 |
| `extraction.py` | 从积累的普通聊天中调用模型提炼事件、偏好和约定，记录再次提及；不是网页资料直接入库的通道。 |
| `consolidation.py` | 执行记忆分层、到期处理、晋升和容量清理。 |
| `memory_policy.py` | 生成维护计划：价值、使用情况、兴趣关联和依赖保护；预览和实际维护共用规则，不调用模型。 |
| `persona.py` | 人格生成、导入提取/适配/收养审查、安装、恢复与后续演化。 |
| `thought.py` | 从记忆形成或修订观点，并整理可用观点叙事；包含模型判断与宿主的依据检查。 |
| `skills.py` | 从记忆提炼“怎么做”的可复用技能；有存储、触发和清理逻辑，当前未作为通用对话技能工具自动加载。 |
| `learning.py` | 兴趣原话依据、已读见闻的保存/跳过与价值分级、即时初步观点、同版本复用、低价值浓缩及相关账本。 |
| `observation_memory.py` | 已保留见闻的来源依据、派生依赖、有效性、撤销、详情与遗忘传播。 |

三层记忆是同一套存储中的 `active`、`warehouse`、`longterm`，不是三个独立 Agent。`event`/`stance` 是内容类型，`high`/`normal`/`low` 是见闻价值，不能与存储层混为一谈。

### D. 网络检索、来源池与后台发现

| 文件 | 主要职责 |
|---|---|
| `discovery.py` | 发现协调器：兴趣与平台配置、前后台共用检索/读取、任务调度、预算、取消、资料发布与后台思辨监督。 |
| `dialogue_search.py` | 把一次聊天绑定到检索任务，组织公开查询、进度和实际已读材料；复用发现协调器。 |
| `discovery_worker.py` | 独立子进程执行单步搜索、读取或模型工作；父进程监督并负责正式写库。 |
| `discovery_sources.py` | 固定平台的搜索/读取入口、URL 和网络目标检查、正文与结果整理。 |
| `discovery_network.py` | 发现请求的本机代理与网络路由；不是 GUI HTTP 服务器，也不是模型接口配置。 |
| `discovery_memory.py` | 来源池、资料包、轮次附件、受众和期限等存储操作。与正式见闻记忆分开。 |
| `discovery_tieba.py` | 贴吧匿名协议映射、吧名检测、主帖/获准首页回帖的解析。 |
| `discovery_zhihu.py` | 从已取得页面中提取指定知乎问题、回答或文章，防止拿错实体。 |
| `bilibili_transport.py` | 宿主侧固定 B 站 addon 协议与进程桥接。 |
| `browser_transport.py` | 宿主侧独立浏览器组件桥接、请求核准和进程回收。 |

这里有三个不同的“网络”：GUI/QQ 接入本机服务，宿主访问模型 API，以及外部内容检索。它们共用部分服务资源，但不是同一条管线。

来源池暂存材料不等于形成长期记忆。实际读到后，模型可以决定保留什么；宿主再检查依据、范围、授权与额度，写入带来源见闻。主动聊天需要时可当轮形成初步观点，后台另有积累后的思辨路径。

### E. 外部 Agent 协作

| 文件 | 主要职责 |
|---|---|
| `collaborators.py` | `WorkerCoordinator`：GUI 协作配置、授权与各协作子模块的组合门面。 |
| `worker_tools.py` | 给主对话模型提供派工、查询、读公开消息、追问、请求停止等工具，绑定本轮目标。 |
| `worker_runtime.py` | 实际执行和监督：任务准入、执行槽、DSH 桥调用、本机 Claude 线程、状态与取消回收。 |
| `worker_transport.py` | 与 DSH 插件桥的固定回环 HTTP 通信，以及安装信息检测。 |
| `worker_credentials.py` | GUI 配置的专用桥接令牌管理，不把令牌交给模型。 |
| `worker_tasks.py` | 协作任务、执行尝试、事件、公开消息及额度等账本。 |
| `worker_context.py` | 协作资料在聊天中的引用和依赖；与普通记忆、网页来源分开。 |
| `worker_reports.py` | 任务结束后调用 Alice 做一次无工具总结，并检查发布资格；不是自动验收或继续派工。 |
| `worker_management.py` | GUI 用户归档、恢复、删除等任务整理操作；与执行授权分开。 |
| `worker_artifacts.py` | 文件导入/产物收取的路径、哈希及两阶段发布辅助；当前公共输入/产物入口仍返回未开放。 |

DSH 走插件桥；Claude 走本机 CLI 子进程和权限闸门。两者共享一部分任务账本与界面，执行传输并不相同。协作报告也不会自动变成 Alice 的普通记忆、人格或技能。

### F. 外部渠道连接与观察核查

| 文件 | 主要职责 |
|---|---|
| `local_connector.py` | 固定本机连接器的进程与 JSON 行协议宿主，目前用于 QQ 连接准备。 |
| `connector_setup.py` | 用户明确点击后安装固定 QQ addon 的锁定依赖，负责占用协调和进程处理。 |
| `observation.py` | GUI 开发者观察器的只读查询：状态、记录、记忆、上下文依据等。这里的 observation 不是“见闻记忆”。 |
| `evaluation.py` | 显式 P1 记忆主张核查的数据与材料校验。 |
| `evaluation_service.py` | 核查任务的授权、模型调用、调度与结果提交；属于评估旁路，不是正常对话的必经步骤。 |
| `metrics.py` | 对话指标记录、开关和评分辅助；指标与正式记忆不同。 |

`alice/metrics_prompts/__init__.py` 另提供核查提示材料，不是独立运行入口。以上覆盖当前 `alice/` 顶层 50 个 Python 文件。

## 4. 三条主要执行路线

**网页聊天**：`__main__.py → cli.py → server.py → ChatService`；请求经 `channels.py` 协调后由 `loop.py` 执行，`retrieval.py` 等组装材料，经 `llm.py` 调模型；工具回到宿主核准执行，最后保存回复并向 GUI 返回。

**联网学习**：聊天 `dialogue_search.py` 或后台调度进入 `discovery.py`，由受监督工作进程取得材料，进入来源池；模型提出保留或初步观点，经 `learning.py` 与来源记忆模块核准后保存；后续由 `thought.py`、`memory_policy.py`、`consolidation.py` 等参与思辨与维护。

**外部协作**：主对话工具进入 `worker_tools.py`，经协调器、准入和账本交给 `worker_runtime.py`；DSH 走桥、Claude 走 CLI 与 MCP 闸门；公开回执回到任务记录，必要时由 `worker_reports.py` 生成一次总结。

这些是执行路线，不是每个文件依次调用的固定流水线。终端聊天还有独立入口路径，不能假设享有与网页完全一致的渠道和协作能力。

## 5. 现在的结构特点与边界

- **主体是一个本机 Python 服务，内部有线程和受监督子进程**，不是按这些文件拆成的微服务；模型服务、DSH、Claude、QQ/browser addon 则在核心进程之外。
- **宿主与“认知”尚未按目录分层**：`loop.py` 同时协调对话、工具和落盘；`service.py` 管生命周期与多个业务入口；`discovery.py` 兼有调度、预算、来源与后台任务；`store.py` 通过多个 mixin 汇集存储能力。
- **模型作价值和表达判断，宿主守可执行边界**：例如模型判断某篇材料值得保留，但没有当前已读依据、有效授权或额度时，宿主仍应拒绝。宿主的字段/版本校验不等于理解内容真伪，也不等于人工验收。
- **现有分层约定与 Claude 实现有偏差**：约定核心不 import addons，但 `service.py`、`worker_runtime.py` 当前直接导入 `addons.claude_agent`。这是实际耦合点，本文只记录，不在本轮改动。
- **代码存在、接线存在、启用、正在运行和验收通过是五件事**：例如按需记忆装配有开关，产物入口未开放；平台浏览器适配和协作者权限能力需按实际环境判断。
- **本轮网络人工验收按用户决定结束**：已观察的通过结果保留，未验边界仍记未验；“低价值旁支只存名字与 URL，按需重读”的 N09 仍是待办，尚未实现。

阅读代码建议先看 `service.py → loop.py → retrieval.py → store.py`，再按需要进入人格、学习、发现或协作子系统。这样容易看清“谁决定、谁核准、谁执行、谁保存”。
