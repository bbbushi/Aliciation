# 陪伴型 Harness（Alice）设计思路

> 状态：**MVP 定稿**。原始构想与评审结论已合并，标注「决策」处为定稿取舍。

## 1. 核心理念

1. **单一永久会话**：从始至终只有一个会话，没有「新会话」的概念。工程实现为每轮上下文重组（宪法 → 人格 → 记忆 → 近期原文），主观体验是一条从未中断的时间线。
2. **经历塑造人格**：AI 不是被配置出来的，是「活出来的」。记忆、技能、人格都从真实对话中生长，不同经历的 AI 发展出完全不同的人格——常被打代码的 AI 自带严谨和技术崇拜，天天陪刷视频的 AI 爱玩梗、擅长提炼信息。
3. **真实优先**：不懂就诚实问，没学过就说不知道，忘了就承认。绝对不允许糊弄和猜测。该遗忘的就遗忘——遗忘不是话术，是真实的架构后果。

## 2. 记忆系统（三层）

| 层 | 时间窗 | 形态 | 进入上下文的方式 |
|---|---|---|---|
| 活跃层 | 0 ~ `active_days`(2) 天 | 近期原文 + 提炼条目 | 每轮自动注入 |
| 仓库层 | `active_days` ~ `survival_days`(7) 天 | 完整条目 | 只注入紧凑索引，模型按需 recall 取全文 |
| 长期层 | 生存过滤后的幸存者 | 精炼条目 | 按权重检索注入 |

**写入（批量提取）**：每累计 N 轮对话（默认 10，退出前兜底），用廉价模型从对话片段提炼记忆条目（title / content / keywords / salience），同时对照已有记忆做「再提及」计数。

**生存过滤（七日线）**：记忆跨过 7 天时——
- 被再次提及或使用过 ≥ `survival_min_uses` 次，**或**被标记重要（salience=1，豁免通道，覆盖「只说一次但永远重要」的事，如生日、过敏、重大变故）→ 晋升长期层；
- 否则**真实过期**：内容删除，仅留墓碑（标题+时间+原因）供人工审计，墓碑不进入任何上下文。

> **决策**：7 天为生存过滤线（原始构想），2 天为活跃/仓库分界。仓库层为「重要但不重复」的事提供 5 天宽限期——期间被检索命中一次即可存活。两个数字均为配置项。
>
> 仓库层的关键机制：「需要时翻出来」必须是**可见索引 + recall 工具**，否则 AI 不知道自己记得什么，仓库就是死存储。索引按天分组、只列标题，控制在约 1k token。

**权重与清理**：`score = mention_count×2 + use_count + 近期使用加成`。长期层超容量时按分数淘汰低分记忆——「重复提及、反复回忆者保留权重高」的落地方。

**诚实遗忘**：过期 = 内容真实删除（AI 侧不可恢复），所以「我忘了」是事实陈述，不是修辞。

## 3. 技能库

- 定位：**「怎么做」的可复用知识**（方法、流程、模式、技巧），与记忆（「发生了什么」）、人格（「我是谁」）划清边界。
- 提炼：从记忆库提炼，数据触发（每累计 `distill_every_memories`(30) 条新记忆自动提炼，也可手动命令）；只提炼不编造，与现有技能去重，可溯源到源记忆。
- 管理：同记忆库原则——新技能按时间权重，老技能按使用频次，超容量清理低分技能。
- MVP 只建表 + 提炼命令，对话中暂不注入技能（v2）。

## 4. 人格系统（两层）

| 层 | 内容 | 变化速度 |
|---|---|---|
| 底色层（气质） | 用户初始选择的标签（害羞/幽默/高冷…）生成的说话方式、情绪倾向、边界感 | 极慢：自改任务仅可微调，且必须引用记忆依据 |
| 生长层（性格内容） | 自我叙事、兴趣倾向、价值观、与用户的关系认知 | 随记忆自由演化 |

**种子**：首次运行时用户选 2~4 个标签 → 生成人格底色。硬性约束：**只写气质与风格，禁止编造任何经历、回忆或事实背景**（编造经历 = 谎报记忆，破坏真实性体系）。

> **决策**：人格初始全空改为「程序性种子」。全空挡不住底座模型的默认助手人格填满真空；种子只固定气质，「内容」仍全部从经历生长，保留原构想「不同经历 → 不同人格」的核心意图。

**自改护栏（数据触发）**：每累计 `evolve_every_memories`(15) 条新记忆演化一次——人格由事件塑造而非日历，安静的月份不改变人格（无时间兜底，特性而非缺陷）；密集使用则演化更频繁，成本自动正比于使用强度。输入为当前人格 + 期间新记忆；输出带 changelog；旧版本快照存 `history/`；底色层微调须标注依据；生长层自由。

> **决策（2026-10）**：过程性阶段（提取→演化→提炼）用数据量触发，状态性边界（遗忘测试）保留时间介质。理由：遗忘的语义是"一段时间内未被再次唤起"，时间是被测变量本身；数据量刻度随提取提示词的校准漂移，时间刻度稳定；且时间是唯一能表达"缺席"的信号源（用户两周没来本身是陪伴场景的经历）。容量淘汰（`longterm_capacity`）继续作为数据量的第二重遗忘压力存在。

**用进废退的自洽性**：长期记忆存活取决于被回忆次数 → AI 的注意力模式塑造留存记忆 → 记忆结构反哺人格生长。记忆机制与人格涌现是同一条因果链。

## 5. 真实性三分法

1. **我记得的**：记忆区可溯源 → 直接说；可用 recall 核查仓库。
2. **我懂的**：底座模型通用知识 → 可以使用，但当用户可能误认为亲身经历时，说明这是通用了解。
3. **我不知道的**：记忆区没有、recall 查不到 → 明确承认不记得/不知道。

配套机制：
- 上下文显式标注记忆范围：「未列出的内容一律视为你不记得」——**诚实由检索管道实现，不靠提示词祈祷**。
- 「你还记得 X 吗」→ 先 recall 查证，再按命中如实回答（记得清楚 / 有点模糊 / 确实忘了）。
- remember 工具允许 AI 主动记忆重要事项（自动 salience=1，免于七日线）。

## 6. MVP 范围

**包含**：CLI 渠道（终端对话）；被动应答（说才回，不主动找用户）；三层记忆 + 批量提取 + 生存过滤；两层人格 + 周级自改；三分法诚实 + recall/remember 工具；技能库表 + 提炼命令；SQLite 本地存储，数据不出本机。

**不包含（v2）**：主动行为、Telegram/微信渠道、语音多模态、打断处理、技能注入对话。

**成本设计**：提取/提炼/人格演化走廉价模型；上下文按「稳定前缀（宪法）→ 慢变（人格）→ 中变（记忆区）→ 易变（时间+近期原文）」排序以吃 prompt 缓存。预估 ¥1~5/天，优化后可进 ¥1/天以内。

## 7. 关键参数（config.toml）

| 参数 | 默认 | 含义 |
|---|---|---|
| `active_days` | 2 | 活跃层/仓库层分界（天） |
| `survival_days` | 7 | 生存过滤线（天） |
| `survival_min_uses` | 1 | 跨线存活所需最少（提及+使用）次数 |
| `extract_every_turns` | 10 | 每累计多少用户轮跑一次记忆提取 |
| `recent_turns` | 16 | 注入原文的最近对话轮数 |
| `warehouse_index_max_lines` | 120 | 仓库索引最大行数 |
| `longterm_top_k` | 12 | 每轮注入的长期记忆条数 |
| `longterm_capacity` | 2000 | 长期层容量上限 |
| `evolve_every_memories` | 15 | 触发人格演化所需新记忆条数 |
| `distill_every_memories` | 30 | 触发技能提炼所需新记忆条数 |

## 8. v2 路线

主动行为（分寸感控制）→ Telegram 渠道 → 技能注入对话 → 语音多模态 → 记忆重要度的模型校准。
