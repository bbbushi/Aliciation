# Alice 架构完善：人工验收清单

日期：2026-11-04。验收目标：`trial/windows-v0.2-20261028` 的 `ef99c42e59c8eea31494621b02b58c8a478b2e21`，或之后明确选定的版本。

**本文件只用于真实环境人工验收，单独记录人工结果。全部项目当前均未执行。** 仓库已更新不等于运行中的服务已加载新版，先完成 M01。

结果使用：**通过、失败、未覆盖、阻塞、不适用**。条件没出现写“未覆盖”；缺环境或入口写“阻塞”；本次不启用的可选功能写“不适用”并注明原因。一个项目只做了部分分支时，分别记录，不能把整项一并标为通过。

## 本轮先做

### M01　实际版本、启动与已有功能共存

- [ ] 由启动者确认唯一实例、实际启动目录和版本；按既有流程保存本机一致备份后启动待验版本。不能仅凭当前Git提交判断进程版本。
- [ ] 打开实际GUI，查看原有历史及当前人格，发送一条正常消息，刷新页面后确认对话仍在、没有重复发送。
- [ ] 由部署负责人确认监听回环地址；有正常重启需求时，再核对历史／人格连续性和恢复状态。正常关闭可能触发记忆提取，记录其实际新增内容，不要求数据总数完全不变。

**通过标准：** 加载版本明确，界面及原有功能可用；刷新没有重发聊天或触发新的模型调用；正常重启没有重复安装人格、错误清空历史或绕过恢复错误。

**记录：** 启动版本、实际地址、时间、异常提示；只验了启动而未重启时，重启分支记未覆盖。

### M02　真实对话、表达和改写质量

- [ ] 做一次普通闲聊，再提出一个确实需要的正式任务，最后回到普通交流。有实际工具调用时，也观察工具之后的回答。
- [ ] 给出一段含明确限制的文字，请其改写，例如保留时间、条件、否定和责任主体。逐句对照最终结果，不以“语气好听”代替内容正确。
- [ ] 观察已有长条件观点、多行表达和角色区分：不丢后半句条件，不把示例、角色背景或别人的经历当作自己的亲历。

**通过标准：** 表达符合本人预期，办事时清楚；改写保留事实与限制；界面不先展示随后又被审查否定的正文。审查拒绝未自然出现则该分支记未覆盖。

**记录：** 相关轮次／时间、期望和实际差异，必要时截取最小片段。表达锚默认保持关闭；只有本次明确试用它时，才在相近场景作开关对照，并单独记录效果。

### M03　表达编辑：取消、保存与旧页面冲突

- [ ] 打开“当前人格 → 编辑说话习惯”，修改一条后点“取消”，重新打开确认没有保存。
- [ ] 重新进入，只修改一条确实想改的表达，点“保存表达偏好”；核对目标条目，以及其他表达、关系／思想、对话和记忆是否保持。
- [ ] 两个标签页预先打开同一版编辑器：先在第一页保存，再在第二页提交旧版本。第二次应提示版本冲突，不能覆盖第一页结果。

**通过标准：** 取消不落盘；保存范围正确；旧页面不能覆盖新版本。若需要恢复，按当前版本只恢复那条内容，不整份覆盖后续修改。

**记录：** 改了哪一条、保存前后版本（界面可取时）、冲突提示。表达保存本身不应启动人格生成或模型适配。

### M04　真实模型回执与异常呈现

- [ ] 在正常对话、改写或实际任务总结后，记录对应轮次及时间，由现有公共观察入口回收该次调用记录。
- [ ] 对照实际调用的模型与用途，检查用量是完整、部分还是未知；有部分数字时不能因此声称整轮账单完整，未知也不能显示为零。
- [ ] 仅在真实失败、取消、重试或流式回退发生时，检查界面提示、最终回答及调用记录。没有发生就记未覆盖，不需要主动断网、损坏配置或反复请求。

**通过标准：** 真实接口可用，记录能对应这次操作；失败及回退没有被最后一次成功掩盖；固定错误提示不泄露接口异常正文；查看观察记录不会触发新的模型调用。

**记录：** 时间／request_id（可取时）、模型名、正常或异常现象。逐调用及聚合完整性可由取证人员核对，用户不必手算token；供应商结算准确性不凭本地数字断言。

## 相关功能已启用时做

### M05　Claude／DSH真实接入、许可与报告

**前提：** 使用已配置且已获准的工人、明确的任务目录。Claude没有专门的策略设置面板；若尚未启用，由部署负责人通过已有公共入口准备，不要求用户寻找不存在的开关。

- [ ] Claude、DSH各选一个范围明确的小任务，经现有协作入口派发；分别检查任务所属工人、内容、最终状态和实际产物。
- [ ] Claude出现质询时，核对完整动作和目标，再按需要选择“允许一次”“期限内允许相同完整文件动作”或“拒绝”。首次允许不应变成许可冲突导致整项失败。
- [ ] 同一任务确实再次出现相同动作或变更内容／文件时，分别观察是否正确复用或重新质询；没有出现的分支单独记未覆盖。
- [ ] 查看任务完成后的Alice总结及任务卡，再观察下一份真实报告：来源应明确为协作者自报，报告不反复发送、不持续卡住后续队列；工人、费用来源及未知状态显示正确。

**通过标准：** 真实CLI与协议可用，授权只覆盖显示的范围；任务卡与实际工人一致；报告清楚区分自报与核实，不把人格样本当成任务经历。

**记录：** Claude和DSH分别填写结果，附task_id／attempt（可取时）、质询选择、终态、报告现象；不为填满分支重复执行有副作用的动作。

### M06　真实取消、撤权和人工恢复

**前提：** 有本人正在运行或准备停止的任务，且归属、目录明确。

- [ ] 对自有活动任务使用现有取消入口，观察停止过程、终态和后续是否仍有活动；不能只看“父进程退出”判断整项已停。
- [ ] 确需撤权时，通过已有公共策略／任务入口操作，再观察旧质询卡和正文：旧卡不能恢复失效许可，已撤正文不能继续用于新回答。两轨都有实际任务时，分别核对只影响目标工人。
- [ ] 仅当符合恢复条件的Claude任务实际显示“人工核实后恢复”，且已人工确认任务及其子进程停止时，才使用该入口；费用只填有依据的金额。DSH沿其已有恢复流程处理，不套用Claude入口。没有这样的现场就不执行这一分支。

**通过标准：** 已停止、有待核实和人工确认三种状态如实区分；不自动重派、不误撤另一工人；人工核实不冒充宿主整树证明，也不用猜测的0费用消除未知。

**记录：** 任务身份、取消／撤权时间及最终状态；由取证人员补充停止证据、恢复依据和费用已知性。疑似任务仍在运行时保留现场，交部署负责人核实，不要求用户按旧PID杀进程。

### M07　真实人格导入与适配成品

**前提：** 本人确实要导入／替换人格，或已准备独立可处置验收环境与一致备份。明确本次是Alice格式直装，还是外部角色材料的模型适配，两者分别记录。

- [ ] 从“当前人格 → 导入新的人格”或初始化页“导入人格文档”提交本人选定的材料。界面的“预览”只是原文预览，不代表模型适配结果已经审查通过。
- [ ] 安装后查看实际人格及相关公开详情，对照原材料中的长条件、多行样本、出处和适配理由；随后用真实问题确认这些限制是否在回答中保留。
- [ ] 自然遇到准备／接口／审查失败时，核对当前人格是否仍为原有效版本；保留操作身份，不连续点击重导来掩盖第一次状态。

**通过标准：** 成品完整，捐赠经历不冒认为亲历，收养观点仍保持应有的未验证身份；无静默截断或装成缺少底色的人格。失败分支没有真实发生则记未覆盖。

**记录：** 导入类型、材料的脱敏名称、前后人格版本、op_id（可取时）及具体内容差异。不要求上交完整人格或私人材料。

### M08　正常重新初始化与再启动

**前提：仅在部署负责人准备好的独立可处置环境，或本人本来就决定重置时执行。** 仅更换`--config`不能保证数据目录隔离；未确认隔离就记阻塞，不在日常活库上试。

- [ ] 使用“当前人格 → 重新初始化”，核对确认提示。已有QQ接入时，按界面提示先处理桥接和待发送状态。
- [ ] 检查归档、空白会话及重新安装后的实际状态；在正常启动流程中核对新人格、新会话与旧归档边界。
- [ ] 如果真实中断或恢复冲突自然发生，记录提示并交部署负责人处理；不手改日志或数据库强行进入ready，也不人为制造崩溃来填表。

**通过标准：** 旧数据有明确归档，新旧会话不混用；再次启动没有重复安装、旧队列回放或覆盖后来的人格编辑。正常流程通过不代表所有故障恢复场景通过。

**记录：** 重置前后会话身份、归档标识、人格版本与启动结果；细节由已有公共操作记录回收。

### M09　真实记忆、历史与前情使用

**前提：** 只验当前实际启用的功能；以下四个分支分别填写结果。

- [ ] **普通记忆：** 询问一件真实保存过、当前页面没有直接提供的事情。核对是否确实取到材料；没取到时应说明范围，不能编造细节或声称从未发生。
- [ ] **旧往返：** 自然聊天推进后，再问较早的一段对话，核对谁说了什么、完整条件和当前渠道。无需刷固定条数；任务报告和外部资料不能冒充普通本人历史。
- [ ] **前情：** 实际产生前情后，检查它是否遗漏否定、角色或条件；自然再次谈到同段时观察复用。明确纠正一项后，观察近期回答是否优先采用纠正。没有前情生成就记未覆盖，不编造卡片。
- [ ] **工作集：** 若已启用，在真实读取材料后请求后续保留，再明确释放；后续不再固定携带该材料，但原记忆不应被删除。跨渠道及正常重启时，仅记录实际发生的范围。

**通过标准：** 回答与实际取用材料相符，角色和条件不丢，来源范围不串；撤回或失效材料不继续当作当前依据。GUI／QQ普通私人记忆的既定共享，与各自历史／工作集范围分别判断。

**记录：** 问题及差异的最小片段、对应轮次／时间、材料或卡片身份（可取时）。前情退出近期窗口后又压过纠正，应记录实际缺口；当前没有前情退休入口，不要求执行尚未实现的功能。

## 长期使用中继续观察

### M10　人格生长、思辨与长期体验

- [ ] 自然使用达到维护条件后，查看发生了哪些人格、观点或技能变化；记录对应经历和实际维护时间。无需刷消息、改阈值、造记忆或手动触发不需要的维护。
- [ ] 核对人格生长只改允许的小节，固定表达没有被覆盖；变化依据是有效经历，而非用户压力、样本或协作者自报。
- [ ] 长条件观点自然被证实、证伪或修订时，核对改的是哪一条、条件是否完整；同前缀不同条件的观点不能互相误改。
- [ ] 在闲聊、办事及之后的日常交流中，记录稳定性、自然度及纠正是否持续有效。若旧前情覆盖新纠正，单独记问题，不能以“已经演化”解释为正常。

**通过标准：** 对已经实际发生的变化，可说明依据、对象与结果，且符合本人长期使用预期。尚未触发的维护、证伪、撤回及跨重启分支继续未覆盖，不能用一次回复代替长期结论。

**记录：** 1—3个有代表性的例子、时间／request_id（可取时）、人格或观点版本，以及期望与实际差异。
