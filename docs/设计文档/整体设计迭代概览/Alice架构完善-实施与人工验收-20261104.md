## W3：统一实际边界

`retrieval.build_messages`仅一次执行目录/工作集初始化和完整往返选择。`ContextManifest.history`产出retained_ids、first_retained_id、excluded_ids、message_limit、history_token_budget、policy、recap_reserved_tokens；`loop`把同一对象传入HistoryContext和RecapContext。context_basis.history_selection、history.boundary、recap.boundary可对照。普通原文资格SQL不扩大，同epoch/同渠道/完成往返及任一侧来源/worker整对排除不变。

前情预留`recap_inject_chars + 2048`估算单位及原回复/schema/锚预算，选择历史后才生成/注入；不会为floor再次调用模型或重复调用initial。字符估算仍不是供应商token硬上限；最后守卫保留。前情仍按min_rows/span_max_rows批量、一次尝试和既有generation_key缓存，不承诺每个刚退出往返立即变成卡，但合法history可达。前情纠正/退休另交设计，不偷偷上线。

静态推导（未功能执行）：交替1—32+当前user33、N=16且预算足够时后缀为19—33，cutoff/floor均19，17/18满足assistant_id<19；紧预算更早裁出的完整对同样进入旧原文范围。当前用户过大时完整保留，最终明确预算拒绝，不切掉条件。后续工具调用/回执不删、不重放。

## W4：调用观测与公共取证

`llm.chat`内部每个真实attempt独立记录，逻辑call_id不变；请求request_id串联主调用、前情、审查、流式失败与fallback。`loop._stream_round`保存该次实际回执，缺失usage为unknown，结束前收到但未能确认为最终的usage标partial_receipt；不从全轮累计倒推单次。duration_ms使用monotonic，model优先真实回执否则标requested，错误只存固定分类。无密钥、端点原文、prompt/私人正文。

receipt先入Store持有的线程安全有界队列，不在锁外写SQLite；业务metrics记录、安全收尾和close时仅在无外层事务时flush。失败保留pending，不重试模型、不重复副作用；队列上限2000，丢弃计数pending_dropped公开，不承诺崩溃后未落盘回执仍在。`metrics.record`及meta_set只在自己拥有事务时commit，不能提交调用者事务。

公共`ChatService.observer_llm_calls(scope,limit,request_id)`和GET `/api/observer/calls`沿用GUI observer意图/来源检查。只读投影含purpose/request_id/call_id/attempt/duration_ms/model/model_source/status/error_type/fallback/usage/usage_state/ts/storage；不触发业务、计数、flush或模型。人工SDK可经公共service面接入，不能伪造浏览器头或读取内部活库。context_basis包含实际表达/锚元数据及manifest。

## reset恢复边界

`persona_reset.py`在Store打开之前读取固定DATA_DIR/reset-op.json；归档移动前记录旧/新epoch、op_id、固定目标及所有原文件摘要。moving阶段先验证全组，然后把已移且摘要吻合的文件原路恢复。archived/installing阶段先核归档，再绑定新epoch；无任何安装尝试时可从持久化plan完成，不重跑模型。已有安装日志则先recover_imports，只有数据库marker+精确成品证明提交完成才收尾。损坏日志、未知代际、后来编辑、已尝试但未能证明完成都阻ready，保留两版人工恢复，不删除后来内容或猜测重放。

恢复人工步骤：停止并确认唯一实例；正常停止可能提取记忆，先记录授权范围并备份；保留reset-op.json、archive目标、新库与persona完整副本；按旧epoch/操作摘要核对后选恢复旧版或保留新编辑。不可只拷人格文件而留下另一版先验，不删除日志伪装完成。具体操作由后续授权的人验执行，本轮不接触真实路径。

## W4逐调用覆盖与异常出口

| 实际调用 | purpose与模型依据 | 关联、失败与重试 |
|---|---|---|
| 主非流式/工具后主调用 | main；请求chat模型，回执优先 | 同主request_id，每逻辑call单独call_id；内部3次尝试各记attempt，不抹失败 |
| 主流式及异常回退 | main_stream / main_fallback；chat模型 | 同request，失败流保已报告usage/partial；回退独立call并fallback=true |
| 记忆提取/提取审查 | extraction / memory_review；cheap模型 | chat尾部传入原request_id；手动/关服独立操作ID。拒绝/解析失败不推进游标；网络失败也保尝试 |
| 前情生成/前情审查 | recap_generate / recap_review；cheap模型 | 同request，retry=false；先claim再生成一次，失败跨度不自动循环付费 |
| 改写/前情回答审查 | rewrite_review / recap_reply_review；cheap模型 | 同request；失败保原句/原摘录，无未审草稿提前流出 |
| 外卡提取/表达适配/独立成品审查/认知收养 | import_extract / expression_adapt / expression_verify / import_review | 同op_id，前三cheap、收养实际chat；所有内部attempt由llm层记录 |
| 标签生成/人格演化 | persona_seed / persona_growth；实际请求/回执模型 | 各有独立操作ID；记录失败，不能把模型成功等同安装/演化完成 |

每个主调用attempt还携带context：实际表达sample_ids、anchor开关/入选样本/字符/估算/降级、同一history_selection、blocks与当次estimated_tokens。它记录请求尝试材料，不证明供应商已处理或模型理解；取消和错误状态分别标示。只有一项token计量时usage_state=partial_receipt；缺失项不能按0相加。流式先收到部分usage、结束缺失时仍保持partial。整轮显示的累计已知值另标incomplete。

- `/api/claude-policy`沿workers来源/意图，公共service同名；未知恢复`worker_tasks('recover_local', ...)`区分owned_tree_empty与human_attested。人为补费用/时间仅明确有据输入，不覆盖已报告/实际值；保留原attempt/次数，非退款。
- `/api/observer/persona-operations`/`observer_persona_operations`复用只读public_status，给op/epoch/阶段/前后摘要/实际新增ID及reset摘要；查询不恢复。扫描有界，truncated/scan_incomplete明确；服务启动被阻时此入口不可用，需人工核日志。
- 新人格日志不自动修复历史截短主张。迁移必须先在用户选定旧op/候选范围内生成差异，保留已演化的现行观点，逐项确认完整claim/出处/先验身份后才另行写入；不能重导、清库或用新op替换历史。旧日志无法证明恢复时人工处理，不猜测跨epoch。
- 回滚先停止新任务准入并核实unknown/费用；解决未完成reset/import日志，完整备份两版。保留新增审计和列，不drop表、不退次数；关闭P1b/C1/C2/C3可退试用行为，但关闭不删除真实数据。旧代码会重现本轮缺陷，不能绕过未完日志直接起旧版；具体恢复/部署留后续授权。
