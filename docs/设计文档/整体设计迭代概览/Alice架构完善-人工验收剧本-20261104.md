## 1. 公共回收与记录格式

每个场景先填：`case_id / 执行人 / 时间(Asia/Shanghai) / HEAD / 改动快照SHA256 / 实际加载版本 / Windows与CLI版本 / 脱敏模型和接口类型 / channel / 全部相关开关 / epoch / request_id / task_id / attempt / worker_id / policy_revision / persona_revision / source_version`。无此对象填“不适用”，未能取得填“未知”，不得留空暗指通过。

结果填写：实际人工动作、最终GUI可见结果、固定返回码、`loaded/sent`、卡/记忆身份、实际调用/usage已知性、首字/总等待、取消/停止证据、恢复动作、是否付费/写数据、`passed/failed/not_observed/blocked`及其范围。记录只留必要脱敏字段；正文由真人在原界面核对，不另存私人prompt、密钥、完整聊天或原始供应商错误。

| 公开入口 | 可回收字段及用途 |
|---|---|
| GUI/公共 `ChatService.state/history/persona_view`（以现有方法签名为准） | 版本/epoch、请求和消息身份、人格当前版本与明确编辑；运行版本未公开时真人记录部署包指纹，不能由HEAD推断已加载 |
| `ChatService.observer_snapshot/observer_list/observer_detail`；`/api/observer/snapshot,list,detail` | 当前快照/普通记忆/人格及有限详情；忙时busy、换scope需刷新。读取不计检索使用、不调用模型、不执行维护 |
| `ChatService.observer_context_basis`；`GET /api/observer/context` | `history_selection`及manifest.history：`retained_ids,first_retained_id,excluded_ids,message_limit,history_token_budget,policy,recap_reserved_tokens`；history和recap的metadata.boundary应同份；人格实际选择/预算/loaded/sent见basis |
| `ChatService.observer_llm_calls(scope,limit,request_id)`；`GET /api/observer/calls` | `request_id,call_id,attempt,purpose,duration_ms,model,model_source,usage,usage_state,status,error_type,fallback,ts,storage`；storage为committed/pending，`pending_dropped`不可忽略 |
| `ChatService.observer_persona_operations(scope,limit)`；`GET /api/observer/persona-operations` | 只读脱敏journal：op_id/phase/epoch/前后hash/inserted_ids/db_marker_present/same_epoch；reset另有old/new epoch/archive。启动被恢复日志阻断时服务接口不可用，须真人停唯一实例、备份后在本机核日志，不能让SDK绕开公共面读活库 |
| 工人任务公共列表/详情、GUI质询与任务卡 | task/attempt/worker/policy、状态、termination_confirmed、agent_idle、usage的source/billing/reported_cost_usd/cost_known/unknown_attempts、recovery_basis/recovery_available |
| `ChatService.claude_policy(payload=None)`；`GET/POST /api/claude-policy` | 独立Claude策略公共入口、默认关；具体字段见W1实施细节。人工SDK不读取或改SQL来开启政策；GUI同源管理权限照旧 |
| `ChatService.worker_tasks('recover_local', payload)`；`POST /api/worker-tasks/recover_local` | Claude终态人工恢复；payload含session_epoch/task_id/request_id/revision/confirmed_stopped=true，可选cost_usd及launched_at（Unix秒）；只补缺失值不覆盖既有账本，具体规则见§3 |

HTTP观察/管理仍要求真实GUI来源和意图；人工SDK使用已授权公共service接入，不能伪造浏览器头或直接读取SQLite。SDK缺某字段时记“公共字段不可取”，交架构侧补面，不能内部SQL取证。观察端点不flush待写队列，查询本身不应使pending变committed。

usage `unknown`为未知，`partial_receipt`只证明已有部分回执；model_source=requested表示请求目标、receipt才是回执标识。主调用与审查必须逐attempt关联，不能用全轮累计猜某次。观测队列有界且未承诺断电持久，崩溃丢失应如实记缺证。

每主调用attempt的 `stage=transport_attempt`，`context={persona,history_selection,estimated_tokens,blocks}` 可核实际发送前装配；persona含实际选材/anchor，表达字段包括实际sample_ids/chars/estimated_tokens/degradation/policy_version/full_chars。这些字段只证明宿主选择和发送，不证明模型理解。

4. 按W2实施记录处理已有未完成安装/reset/growth日志后再ready；恢复不得重跑模型、跨epoch、重插先验或覆盖后来人工编辑。日志不明确/摘要冲突则停止写入并保留blocked，不手改日志phase、meta或活库伪装成功。
