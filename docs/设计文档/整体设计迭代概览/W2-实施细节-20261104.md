## 已落实的调用链

- `persona.seed_from_tags`、Alice 格式 `install_persona`、外卡 `prepare_import/commit_import_plan` 共用 `persona_transaction.install`。直装也先补齐结构、解析表达并检查完整条目预算；外卡先完成所有模型阶段与表达成品检查，再允许 reset 归档。移除原独立 `_ensure_meta_prior` 入口，先验统一在安装事务内处理。
- `ChatService` 与 CLI 启动在开放业务前恢复 reset/import/growth。归档外层由 `persona_reset.py` 处理，导入内层由 `persona_transaction.py` 处理。reset 的准备计划是 JSON，可在确定的新空库中无模型完成；没有把一次失败变成重跑导入模型。
- 非 reset 准备在模型调用前冻结人格正文与 epoch；提交再次比较。reset 在归档前比较计划与当前会话/人格。准备期间后来的编辑使旧计划失效。
- `_commit_import` 写入完整 `主张`、原候选、捐赠出处、收养/适配理由、候选ID、op_id 与未验证先验身份。标题仍只是24字符索引。`thought._field_of/_render_stances` 读取含缩进续行的完整主张，保留不确定、出处及收养说明；不再把标题当完整主张，亦取消下次回应的字符截断。legacy 上下文由 retrieval 调用此渲染；indexed 的 memory read 读取完整 content，均不会仅消费短标题。
- 收养审查强制候选与结果一一对应；缺失/重复/未知 ID、未知决定或理由类型、空理由、无效依据、adapt 无完整主张，均拒绝整次准备。输入依据名空间为 `donor:<candidate_id>`、`style:<n>`、`reaction:<n>`、`boundary:existence|honesty`；ID只是所据材料身份，不证明判断正确。超量提取列表与非法条目也明确拒绝，不静默裁掉候选。
- 导入观测按同一 op_id 关联 `import_extract`、`expression_adapt`、`expression_verify`（独立成品审查）、`import_review`；后者使用实际默认 chat 模型，不再误标 cheap。seed/growth 使用独立 request_id。失败和内部尝试由 llm 层记录。导入本身不调用旧的重复 record_llm_call；观测 flush 在业务事务外，失败不重发模型或安装。

## 数据与事务契约

新操作日志为 `persona/imports/<op_id>/op.json`，版本 `persona_import_v2`，字段：`kind/op_id/epoch/phase/before_exists/before_sha256/after_sha256/before_meta/after_meta/inserted[{id,sha256}]`。同目录 `candidate.md` 与可选 `previous_persona.md` 是该操作快照；原始捐赠/审查档案继续保留。旧 `history/` 生长记录保持原语义。

所有新增收养先验、缺少的元先验、版本/基线元信息、`meta[persona_import:<op_id>]` 在显式 `BEGIN IMMEDIATE` 内提交。写 marker 的 SQL 与先验同事务，不调用会独立提交的 meta_set；Store 的 insert_memory 内部 savepoint 位于真实外事务之内。已有外事务时安装明确失败，不接管或意外提交调用者事务。文件日志与正文使用同目录临时文件 + fsync + os.replace；SQLite 与文件并非共同事务，不承诺整机断电后的跨介质一致持久性。

DB marker 保存完整实际新增ID与行摘要。即使 DB COMMIT 后还没来得及更新文件日志，恢复仍从 marker 得到实际写集。恢复不调用模型、不重插先验、不重放旧文件、不跨 epoch 操作。版本号每次安装递增一次，包括首次安装；旧先验不自动重导或修订。

### 崩溃点静态推演（非故障注入结果）

| 位置/证据 | 启动处理 | 业务开放条件 |
|---|---|---|
| 提取/适配/审查失败，未写 op.json | 保留旧版；首次仍待安装，保留准备审计 | 旧人格可用；不自动重试付费 |
| prepared 已写、DB 未提交 | SQLite 回滚；无 marker，无新增先验；日志标回滚或后续编辑取代 | 文件仍旧版/空白，或后来显式编辑胜出 |
| 先验写入中断 | 与 marker 同真实事务回滚，不能遗留半组先验 | 同上 |
| DB 已提交、文件仍是旧摘要/首次仍无文件 | 仅撤销 marker 列出的、逐行摘要仍匹配的新增先验；恢复仍等于本操作值的元信息 | 旧版/空白与旧DB状态一致 |
| DB 已提交、文件替换成功、file_replaced/completed 日志尚未写 | 同 epoch marker + 当前新正文完整摘要证明提交完成，补完成日志 | 无模型/无重复先验；同进程若恢复证明完成按成功返回 |
| 文件与前后摘要都不符（后来手工编辑） | 不覆盖文件；精确撤销尚未使用/变更的本操作新增，标 superseded | 保留后来文件，不能把旧快照盖回 |
| 新增先验后来已变化或不明确 | 不删除该记录，阻恢复并说明需人工核对 | 未开放，保留所有证据 |
| 有新文件无原子 marker、坏日志/未知阶段/跨 epoch | 不猜测、不重放，阻启动 | 人工核对后恢复 |
| 已完成记录后发生正常编辑/演化 | 不按旧摘要回放；v2终态只核最小记录身份结构，legacy completed 保持兼容 | 让合法后来版本胜出；不是自动历史数据迁移 |
| reset 归档 moving 阶段中断 | `persona_reset.before_open` 先校验整组固定源/目标摘要，再逐项回移；冲突阻启动 | 原文件组已恢复；尚未创建Store时执行 |
| reset archived/installing，新库尚无安装尝试 | 校验旧归档、新epoch和空白状态后，用持久计划完成一次安装 | 不重跑模型；安装必须经上述事务 |
| reset 已有安装尝试 | 先 recover_imports；仅原子marker+新hash证明确已安装才收尾 | 未完成或后来编辑则保留两版并阻启动，人工恢复；不自动循环尝试 |

正常停服可能提取新记忆，恢复/部署的备份应包括停服前与停服后差异。上述自动恢复是新代码的行为契约，本轮没有对任何真实文件执行。

## 表达与 P1b

`persona_context.parse_snapshot` 读取完整多行样本，后续行一直归属于同一个显式样本ID；新导入把续行缩进，正文中的列表和标题不冒充人格结构。重复ID、空样本、无法识别的样本格式明确拒绝。GUI表达修订在写入前也调用同一解析/预算检查。受支持的样本首行为 `- 【原文摘取·s1】情境：…｜用户：…｜回应：…`（类型也可为适配生成），后续行可缩进继续。旧单行格式保持兼容；原本不受支持却被忽略的任意样本列表，须由用户明确修正格式，不静默重写旧文件。

风格/情境和样本各1200字符预算，包括标题和降级说明，按完整条目固定顺序选取。首条风格都放不下时报预算冲突；样本放不下整条省略并记 actual selected/omitted IDs，不切断条件。总结用途只渲染风格/情境与固定样本提示，总计1200字符，不输入样本正文、关系或来历。

`render_full`、`render_expression_reference`、`render_anchor` 新增可选 `metadata=dict`，原字符串返回保持兼容。元数据为实际 `sample_ids/chars/estimated_tokens/degradation/fingerprint/policy_version=3`，另含选中风格序号及未选样本ID；full 增加 `full_chars/full_estimated_tokens`。估算统一调用 context.estimate_tokens，不能冒充供应商用量。

P1b 全文含标题和必要边界最多500字符；整条风格和样本放不下就降级，不做末端字符串切片。默认开关不变，关闭时不用锚。loop负责同请求快照、每次调用前一份、manifest/预留与实际调用观测；不能用全部 snapshot.sample_ids 代表实际入模。表达预算变更不自动重导人格、不启用锚、不增加逐轮润色调用。
