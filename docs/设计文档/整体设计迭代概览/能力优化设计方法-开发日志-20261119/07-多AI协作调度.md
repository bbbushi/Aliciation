# 07 多AI协作调度

> 这条线解决「本机多个 AI（Claude/DSH/worker）如何在宿主治理下协作」：管家 Alice + 宿主权威 + 分阶段交付，身份、预算、回执全部不由 Agent 自报。

**文档**：`docs/设计文档/Agent协作者调度/` 7 篇

---

## 1. 管家 Alice 定位与三方分工

**设计方法**：

- **Alice**：理解需求、选人、写任务书、解释结果。
- **宿主**：管身份 / 政策 / 预算 / 账本 / 来源资格。
- **Agent**：在任务范围内执行。

三所有权分离：对话槽、任务执行槽、Store 短锁。

---

## 2. 有效能力 = 交集，且每次派工重核验

- 注册三态分离：安装描述 / 用户政策 / 运行事实。
- **有效能力 = 四者交集，且每次派工重新核验**——安装了 ≠ 政策允许 ≠ 当前可运行。

---

## 3. 分阶段安全交付

> P1 只给状态 + 不透明句柄 → P2 受范围来源链 → P3 多 Agent

---

## 4. claude 直调：权限闸门 + 质询卡

**设计方法**：

- 独立 claude_policy 表（DSH 零接触）；stream-json + **进程组整树回收**。
- 权限闸门三层裁决：结构禁区硬挡 → 任务内缓存 → **宿主质询文件协议**（10 分钟超时 deny）+ GUI 质询卡三按钮。

**用户裁定**：撤回「删表回退」旧建议，改为先禁用准入、排空、保留账本。

---

## 5. CLI 宿主契约（DSH 与 Claude 统一）

**设计方法**：

- 「**一次解析贯穿整条链路**」（worker_id + policy_revision）；宿主信封与任务书分开；一次提交 + 锁外启动的原子准入。
- 状态四维（执行 / 终止 / 验收 / 交付）**互不冒充**；「请求取消 ≠ 已取消」。
- 质询裁决**绑定具体动作**（epoch / task / 参数摘要 / 期限），deny 后不得换工具绕行。
- 费用三模式 recorded_only / estimated_stop / enforced_backend，**未知不算 0**；预算分 reserved / observed / settled / unknown。

**用户裁定（2026-11-06）**：DSH 与 Claude **独立执行、独立排队**，各 1 执行 + 4 待办，允许跨工具同时运行——替代原「共享总槽」约束。

---

## 6. worker-P2 最小来源链

**设计方法**：

- artifact / evidence / grant / dependency 分层身份。
- `assurance=worker_claim` 的正文**永不单独成为事实证据**；工人自报 URL / 引文 / 哈希不变成宿主证据。
- material_ref 为宿主签发的请求内引用，读取前先登记依赖；生成与发布全程复核版本；**撤权沿派生传播**。
- 见闻准入默认 `not_eligible`，只留接口。

---

## 7. 撞车裁决

两套实现撞车时：**采纳 trial 正典、撤回另一套**，契约 v1 转为 P1 人工验收标尺。
