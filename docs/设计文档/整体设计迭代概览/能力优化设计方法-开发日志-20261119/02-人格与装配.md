# 02 人格与装配

> 这条线解决「人格如何进入每轮上下文」：从整包注入演进到「常驻核心 + 薄索引 + 按需读原文」，最终用户裁定导入方式为**原文保留与轻分类**。

**演进线**：17 轮诊断 → 字段注册表 → 注册表架构 v1 → 预引导两阶段 → 薄索引 v2 → 表达采用与经验依据分离 → 体积/耗时诊断 → **原文保留与轻分类导入** → 六层理解

**文档**：`docs/设计文档/上下文组装优化/人格*.md` 等 16 篇

---

## 1. 不把全部人格换成 ID

**问题**：评估「每轮注入 persona 字段注册表、模型自选材料」是否可行。

**设计方法**：

- 核心表达习惯**常驻**；只有有语义的场景进注册表，主模型按需读取、宿主校验装配。
- 复用记忆索引的访问模式，但 persona 保持独立的数据语义、预算与版本约束。

**用户裁定**：不把全部人格换成 ID，事实边界与基本表达习惯始终常驻；先做分层与读取契约再实现。

**源文档**：人格字段注册表与按需装配-可行性评估-v1-20261107.md

---

## 2. 注册表 + 按需装配（persona-residency 合同）

**设计方法**：

- 单一 Markdown 权威 + 可选 assembly 合同，以 expression_digest 绑定表达包。
- core 常驻 + bundles 场景；模型经 `persona_load` 七态状态机（loaded / already_loaded / unknown_ref / stale_ref 等）按 nonce 引用读取完整场景。
- 宿主校验依赖闭包、用途交集与冻结额度；失效 full 回退，**不静默切换**。

**用户裁定**：QQ/worker 首版保持 full；R0–R4 真人验收决定是否默认开启。

**源文档**：人格注册表与模型按需装配-架构设计-v1-20261107.md

---

## 3. 预引导只做两阶段

**问题**：人格安装后缺少有过程、低压力的熟悉与表达尝试。

**设计方法**：

- 只做**熟悉材料 + 尝试表达**两阶段；独立准备上下文，宿主引导不伪装成用户发言。
- 幂等身份绑定安装操作/会话代际/表达摘要，同身份只跑一次。
- 准备记录与记忆提取隔离；仅 ≤800 字符准备资料带入首次后续请求，不每轮重复。
- 开关唯一且默认关，做真人 A/B 对照。

**用户裁定**：「反馈学习与偏好沉淀（三四步）不做」；不以认同宣言作完成标准。

**源文档**：人格导入后预引导-两阶段与对照开关设计-v1、人格预引导-核心流程与插件控制台-架构设计-v1

## 4. 薄索引

**问题**：v1 注册表目录冗余字段多、易超预算。

**设计方法**：

- 三层：核心常驻 → 薄索引（每行仅 [本轮引用, 场景名, 适用线索]）→ 命中才 `persona_load` 读完整场景正文。
- 严格相等字段合并、公共说明写一次、按 entry ID 去重；**不放大 1600/2200/2400 冻结额度**。

**用户裁定**：全局/条件语义分类须用户在 GUI 原文预览核对；不自动启用。

**源文档**：人格按需装配-薄索引与完整场景-设计-v2、人格按需装配-薄索引施工与人工验收-20261108

## 5. 表达采用与经验依据分离

**问题**：AI 把「采用用户选定表达」误设为「先有真实内心经历才能用」。

**设计方法**：

- 真实性只约束事实主张，**不设成长门槛**；语气、看法可直接采用。
- full 与 registry 共用采用说明；旧 AI 自述不构成新限制。
- 禁止无依据收窄 scope；场景专用表达须显式声明并被 chat 场景覆盖。

**用户裁定**：不迁移记忆、不追写历史、不自动重装；旧包修正须走原稿更新/重新分层流程，不暗中改稿。

**源文档**：表达采用与经验依据分离-设计与实施-v1-20261108

## 6. 存储表示与阅读表示分开

**问题**：澄清人格落盘文件 54408 字符与实际每轮注入量的关系。

**诊断结论**：文件 89.78% 是 Base64 存储封装；运行投影解包后仅 5449 字符——方向是**分开设计「可靠存储表示」与「模型阅读表示」**，消除 scope/trigger 重复。

**源文档**：人格文档体积-存储与运行投影诊断-20261108

## 7. 原文保留与轻分类导入（核心裁定）

**问题**：旧导入「完整拆解重建 + 双初审 + 认知收养串联」成本高，且一处失败整包作废。

> **用户要求**：简化导入、保留原文与表达细节、按需取用、只在必要处局部适配。

**设计方法**：

- **原文为权威**：本地解析原子块（字符区间），正文永远读自原文区间，不由模型填。
- **一次轻分类**只返回块 ID / 类别 / 驻留建议 / 触发线索——**宿主填正文**。
- 失败逐行/逐场景隔离，**不整包作废**。
- 表达与认知收养解耦：安装不写 stance / 经历 / 立场。
- 局部适配改为可选派生 patch；新路径灰度，不设默认。

**源文档**：人格原文保留与轻分类导入-优化设计-v1-20261110（含施工记录 §13）

## 8. 用途是常驻唯一权威

**问题**：修正 v1 的双常驻来源（勾选框与用途并存）、旧缓存失联与样例语境缺失。

**设计方法**：

- 用途成为常驻选择的唯一权威，core_block_ids 降为兼容缓存。
- 相邻「用户提问 + 角色回答」作为完整问答单元共同闭包。
- 未归入任何场景的按需块自动生成逐块引用入口（auto_ 哈希 ID），**不造无限制的「其他」大包**。

**用户裁定**：按「现在补齐」执行；不改写原稿、不新增分类调用、不扩大预算。

**源文档**：原文人格-装配合同补齐-v2-20261110

## 9. 六层理解

**问题**：外部原稿混有身份接管指令与背景经历。

**设计方法**：

- 先「理解」：标注六层（人格设定/背景经历/性格分析/表达习惯/爱好/杂项，可多选可空）。
- **唯一定位并剔除身份接管片段**（原稿不删），决定用途（expression / reference / derived / disabled）。
- 背景须经「派生倾向」提炼（≤600 字符 + 逐字依据）才可用。
- 再对剔除后表达原文做轻分类打导航标签；旧生成入口改为「恢复 Alice 文件」。

**用户裁定**：新原稿统一走原文保留路径，旧人格不自动迁移。

**源文档**：人格六层理解与轻分类导入-设计与实施-v1-20261111
