# 05 思想层与自主活动

> 这条线解决「用户不发言时 Alice 做什么、做得是否有质量」：从思想层 v1 到清醒调度，再到 v2 切断三个相互强化的假进展环节，并把主动交流改为**先邀请、接受后再展开**。

**演进线**：思想层 v1（20261114）→ 清醒睡眠三模式（20261117）→ 首夜评估 → **自主活动 v2** → 联系等待与思考价值（20261118）

**文档**：`docs/设计文档/自主探索与主动交流/` 全部 17 篇

---

## 1. 思想层 v1（疑问管理 / 自主探索 / 主动交流）

**设计方法**：

- 疑问「**收纳 / 探索 / 保留 / 联系**」四个决定分开记录理由；问题七类来源。
- 探索是**有界可恢复循环**：检查点、预算、前台让位、结果未知不重试。
- 成果按性质进见闻或思想层，并以引用关联；主动交流三类动机，联系意图与送达分开。
- 首版自动执行与主动通知**默认关闭**。

**用户裁定**：认可两区块、四决定分开、三类联系动机等 7 条方向后授权施工。

---

## 2. 清醒睡眠两态 + 三模式

**设计方法**：

- wake_state 显式两态（旧 enabled 作兼容别名）；清醒空闲时在兴趣探索 / 问题思考 / 自我迭代间按「内容分数 + 轮换债额 − 最近执行系数」加权选择。
- 事项附轻量调度元数据（importance / urgency / due_at）：**模型判断内容价值，宿主只校验类型与许可**。
- 每模式独立时长与五组读取工具，共享额度，前台优先。

> **用户裁定**：不提供基础偏好或模式权重配置——倾向由具体内容、可推进条件与执行历史形成。

---

## 3. 首夜评估 → v2 的直接动因

**问题定位**（只读核对 20 次运行 / 96 次调用）：观点 1→13 全是新增、修订 0。三个相互强化的环节——

1. 成功写入 thought_record/update/resolve 就记为进展；
2. 自己的疑问版本与观点写入改变输入戳，解除无进展冷却；
3. 部分成果只要还有 remaining，就重新写成 open。

**源文档**：清醒调度-首夜真实运行评估-20261117

## 4. v2 四方向（用户确认原文）

> 「清醒期间增加**发呆**，允许无事可做；仍保留兴趣探索、问题思考、自我迭代。
> **不提供用户可设置的基础偏好**；活动倾向由具体内容、可推进条件与执行历史形成。
> 一起优化**等待条件、进展判定、观点修订与后台成果进入聊天**的方式。
> Alice 想主动开启话题时，**先询问是否方便；用户愿意再展开**。未回复或表示没空，本次不展开，留待下一次合适机会重新发起。」

发呆时长、推演窗口数、邀请等待与再邀间隔均为**实现初值建议**，待真实使用校准。

---

## 5. 切断三环节（v2 核心机制）

| 环节 | 机制 |
| --- | --- |
| 写入≠进展 | 成功写回执只记**实际执行**；语义进展仅由 activity_finish 回执驱动 |
| 自写≠新依据 | `external_material_version`（用户证据/来源内容/行动回执）与 `working_revision`（问题/草稿/观点版本）**拆分**，自写不刷新外部依据 |
| remaining≠open | `thought_resolve` 扩 `next_status` / `wait_condition`，独立提交；保持 open 须给可执行下一步 |

**进展五分类**：新证据（可解除等待）/ 实际行动（失败也消除一种可能）/ 有意义的新推导（支持**有限**后续推演）/ 表述修订（可存版本但**不得新窗口**）/ 状态登记（不算推进）。

**同依据推演窗口**：同问题族同一外部依据初值 2 个窗口；子问题不继承新额度——「不凭『又想深一层』无限续开」。

---

## 6. 发呆（第四模式）

- 零模型 / 工具 / 记忆整理调用；宿主定时器管理，不生成空白用户轮、不定期问模型是否无聊。
- **先判断可推进，再算权重**：等待事项为 0，不能靠等待时间累积成高权重强行执行。
- `idle_score = 1 + 2×min(连续无实质进展窗口, 3) + 2×不可推进的工作模式数`。
- 界面必须区分**主动发呆**与**额度等待**——「不把额度用尽包装成 Alice 自主选择休息」。

---

## 7. 部分解决状态表

| 剩余情况 | 状态与解除条件 |
| --- | --- |
| 有具体可执行方法 | open，附下一步与所需工具 |
| 等用户回应 | waiting_user——**用户任意消息不自动唤醒**，前台模型判相关性 |
| 等资料/外部验证 | waiting_source——自己的新观点不满足条件 |
| 等工具/资格/额度 | waiting_permission / waiting_budget——恢复资格不代表结论已验证 |
| 无值得继续方向 | paused / closed |
| 缺口全部处理完 | resolved（不等于每项事实都独立验证） |

## 8. 观点当前版

- 稳定身份 + **当前指针**；多个候选解释并列于同一份当前材料，「不伪装成多条独立支持」。
- 已有 outcome 的问题**默认要求修订**，不默认新增另一条长期观点。
- 前台只投影当前版，旧版按需查阅；**传统全文装配路径同样遵守**当前版投影。
- 版本升级不把不可保存的外部材料变成可永久保存的本机观点。

---

## 9. 邀请式交流

- 联系意图（稳定）与邀请尝试（每次独立）分离；邀请只发一句「现在方便聊吗」，**不带正文**。
- 状态机：prepared → awaiting_reply → accepted → expanded / deferred / declined / withdrawn。
- **接受须绑定真实用户消息**后才展开；接受不另计一次主动联系；后台模型不能接受自己的邀请。
- 超时**静默**转延期，不发「你还在吗」；明确拒绝该话题则结束意图（不是「现在没空」）；同主题再邀至少间隔 24 小时。
- 同一时间仅保留一个待回应邀请；awaiting_reply 从**实际投递回执**起算。

---

## 10. 后台成果进入前台（§8）

- 前台只获取：相关当前观点、必要等待索引、**最多一个**待回应邀请；未接受的意图不注入展开正文。
- 问候优先回应问候，不自动附带后台反省；活动自述使用**实际运行记录**，不把适合人格的活动写成已发生的操作。
- 用户接受后再按主题载入成果正文；必要资料不可用就说明现有范围，不拿过期缓存补足。

---

## 11. 2026-11-18 增补（用户两条新方向）

> ①想联系时若用户长久没回答或表示在忙，应**自觉延后或放回问题**，先做其他事等待回应；
> ②自我思考发散过多，思考前应先回答「**这是什么、有什么价值、为什么要思考**」。

**落地**：联系等待与研究状态分开（v2_contact_holds 按会话保存等待，沉默不等于拒绝）；思考前四问入 activity_plan；inference 不再无条件记实质进展；后台新疑问默认 paused 作线索。

---

## 12. 相关机制（同线）

- **交流决定并入收尾**：每窗口在 activity_finish 一并提交 invite/later/none 及理由——不新增审核轮、不设最低联系频率。
- **材料与证据流**：thought_load 分 task/full（仅 full 绑定旧正文依赖）；证据按本轮真实 loaded 对象解析；history 拆 user_message 与 historical_ai_speech 两身份，旧 AI 自述不解除等待；工具返回宿主绑定 action_receipt。
- **测试策略**：「测试期间跳过额度、时段、间隔等限制，只保留总开关和工具权限」（TEST_CONTROLS_ONLY，可撤回，非发布策略）。
