# 08 QQ接入

> 这条线解决「把 Alice 带进 QQ 而不泄露私人记忆、不像机器人」：一个所有者两个入口、最小权限机器入口、自然分条回复。

**文档**：`docs/设计文档/QQ接入/` 4 篇

---

## 1. 一个所有者，两个入口

**设计方法**：

- 官方 QQ Bot + Node SDK WebSocket → 独立本机桥 → 最小权限机器入口 → **唯一 ChatService**。
- 限时配对短码绑定 openid；QQ 与 GUI **共享同一个 Alice 及记忆**——有意选择，不提供虚假隔离。
- 群聊默认关闭（防私人记忆出站泄露）。

**用户裁定**：2026-10-29 明确「批准，可以开工」，并选择「像参考项目一样扫码，先核清组件使用条件」。

---

## 2. 最小权限机器入口

- 仅 C2C 纯文本；**禁主动消息 / 远程管理 / 多媒体**。
- 被动回复按「5 分钟窗口、最多 4 条」保守上界设计。
- 机器鉴权、请求账本、单处理槽属核心架构改动。

---

## 3. 自然分条回复

**问题**：一轮完整回复整段发出，不像自然聊天节奏。

**设计方法**：

- **自然分条**规则：自然段优先；极短承接（「嗯」「好呀」）并入相邻内容；最多 3 条；固定最小 1 秒间隔，**不模拟随机打字**；不拆坏引号 / 链接 / 代码 / emoji。
- **只在 QQ 桥本地切分**：核心仍生成并保存一份完整回复，不增加模型调用 / 记忆提取。
- `reply-plan` / `delivery-plan` 生成**不可变计划 + 稳定 hash + 逐段身份**：重启或配置变化不重切旧计划、成功条目不重发、unknown 不补发。
- 发送前**重验来源资格**，来源失效停止未发尾段。

**用户裁定**：已批准范围并授权开工；模型输出「消息数组」与精确网页进度接口明确不在本次范围。
