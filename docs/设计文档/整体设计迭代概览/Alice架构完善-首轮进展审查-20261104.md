## 4. 主要发现

### R01 · P1 · 首次“本任务内允许”可能反而中止整个Claude任务

**类型：新增生产回归。**

[worker_permissions.py:146](D:/alice/alice/worker_permissions.py:146)先写`allow_task`答案并登记许可缓存。gate每0.5秒读答案、之后才删pending文件（[gate_server.py:151](D:/alice/addons/claude_agent/gate_server.py:151)）；宿主每0.2秒轮询，期间[缓存扫描:125](D:/alice/alice/worker_permissions.py:125)可能再次看见同一质询，并写`allow_once`。

[首答检查:114](D:/alice/alice/worker_permissions.py:114)发现同一ID的decision不同即抛`ValueError`。该异常穿透[worker_runtime.py:794](D:/alice/alice/worker_runtime.py:794)，落入执行器故障分支并回收整项任务。正常用户批准文件动作即可遇到这个竞争窗口，不需要恶意输入。

**修复要求：**已裁定请求不再由缓存改答；首答不可变、相同答复幂等。缓存许可只处理后续新质询。局部答复冲突应有明确处理，不能无条件升级为整个执行器故障。人工补验首次allow_task、同动作再次请求、同前缀异动作以及重复点击。

### R02 · P2 · 已通过保存的人格可能使协作报告队列持续阻塞

**类型：表达预算与报告事务之间的新增集成回归。**

[persona_context.py:112](D:/alice/alice/persona_context.py:112)在`worker_summary`用途且存在样本时，另从1200字符风格预算扣掉样本说明；首条风格必须完整容纳。安装和显式编辑却只按chat用途验证（例如[persona.py:268](D:/alice/alice/persona.py:268)）。因此首条风格连同header落在两种用途预算差值区间的人格，可保存并正常聊天，总结渲染却抛`ValueError`。

报告准备在[source_transaction内:225](D:/alice/alice/worker_reports.py:225)调用`_style_excerpt()`；异常使`summarizing`更新回滚成`pending`。外层[113行](D:/alice/alice/worker_reports.py:113)尚未执行`claimed=True`，异常处理不会转为状态降级。调度持续选择最早pending报告，影响该报告及排在其后的报告，直至人格或处理逻辑改变。

**修复要求：**让保存准入与各用途预算契约一致，并为报告准备阶段的表达异常提供一次性、可观察的状态降级。不能让一个不可总结的人格条目永久占住报告队头；保持不重试付费总结的约束。

### R03 · P2 · 长主张保存完整，但后续证实／证伪／修订仍按短标题查找

**类型：完整主张修复未贯通后续消费。**

[persona.py:636](D:/alice/alice/persona.py:636)将标题截为24字符，正文保存完整主张；本轮[thought.py:122](D:/alice/alice/thought.py:122)已向模型渲染完整主张，并另列短索引标题。思辨提示要求回传“主张原文”，执行端却仍使用[find_by_title:223](D:/alice/alice/thought.py:223)，替换旧观点也在[291行](D:/alice/alice/thought.py:291)按标题找。

当模型按提示返回超过24字符的完整主张时，标题查询无法命中：验证静默跳过；修订可能插入新观点而不退休原先验，留下并存冲突。模型碰巧改用短标题不能保证契约；相同前24字符的不同主张还存在歧义。

**修复要求：**给当前实际提供的观点附稳定ID／版本，验证和替换按该身份定位并重核资格。完整主张作为内容，短标题只供显示。人工补验长条件主张的证实、证伪、修订及同前缀不同条件。

### R04 · P2 · 旧版支持的缩进底色标题会静默退出入模人格

**类型：解析兼容回归与入口验证缺口。**

[persona_context.py:19](D:/alice/alice/persona_context.py:19)从对`line.strip()`匹配改成只匹配列0的`## `；原可识别的带前导空格标题不再进入sections。[直装入口:254](D:/alice/alice/persona.py:254)仍仅凭文本包含`## 底色`判格式，再将parse／render未抛异常当验证成功。

例如原有`  ## 底色 · 气质与风格`及其条目，在首个列0小节之前会被解析器丢弃。直装可以成功，主聊天渲染时却没有这段底色；升级读取旧人格也可发生。这里仅做源码推演，未生成或安装测试人格。

**修复要求：**保留原受支持标题语法，或在入口明确拒绝并提供兼容处理；检查必需底色确实被解析，不能只检查没有异常。旧文件不能被无提示地削掉人格内容。

### R05 · P2 · 历史pending文件可挤掉当前权限质询

**类型：新增活动请求筛选缺陷。**

[worker_permissions.py:67](D:/alice/alice/worker_permissions.py:67)先对所有历史pending路径排序截取128条，之后才过滤活动task、attempt、epoch和期限。gate被取消或终止时可能保留pending；其正常删除在[gate_server.py:159](D:/alice/addons/claude_agent/gate_server.py:159)，宿主没有对应清理闭环。

当当前请求排序在128个旧路径之后，GUI list和缓存扫描均看不到它，最终超时拒绝；用户不会得到明确的容量或扫描失败说明。

**修复要求：**优先按活动task／attempt定向扫描，再限制有效条数。保留总扫描预算及耗尽诊断，避免历史残留静默阻断活动请求。补验长期使用、取消残留及恢复后新质询。

### R06 · P2 · 账本字段已修，GUI仍将Claude费用与恢复状态标成DSH

**类型：W1公共面到GUI接线未完成。**

[worker-tasks.js:1293](D:/alice/web/worker-tasks.js:1293)仍硬编码DSH能力说明、DSH累计自报及“费用仍未知”；没有据新的`usage.source`、`reported_cost_usd`、`cost_known`、`recovery_basis`渲染。人工停止恢复后还可能显示“DSH会话已空闲”。

因此Claude已报告费用或人工有据补账后，页面仍可能显示未知／错误工人身份；人工确认与宿主整树证明也没有正确区分。这直接影响人工验收者判断停止和费用状态。

**修复要求：**按实际工人、计量来源、已知性和恢复依据显示，区分CLI自报、人工有据补账与供应商结算；`human_attested`不得显示成宿主已证明整树停止。覆盖DSH／Claude和已知／未知组合。

### R07 · P2 · Step1还不能覆盖真实维护和协作总结的全部调用

**类型：逐调用观测覆盖遗留，原路径未新引入重试。**

主模型、提取、多类审查及人格演化已接入新观测，但[thought.py:189](D:/alice/alice/thought.py:189)的思辨和[skills.py:46](D:/alice/alice/skills.py:46)的技能提炼仍未传`observation`；两者可由[service.py:962](D:/alice/alice/service.py:962)的维护链真实触发。[worker_reports.py:255](D:/alice/alice/worker_reports.py:255)的单次协作总结直接调用client，也未记录新attempt回执。

这些成功／失败／内部重试不会出现在新增的公共calls观察面。按该接口汇总“一次使用的全部模型次数、用量和等待”会漏计；思辨／提炼发生在维护阶段时也缺少与触发请求的关联。现有覆盖表需明确排除项，不能据当前表声称完整。

**修复要求：**给这些真实入口补统一调用身份、purpose、错误／unknown用量及触发关联；保留各自原重试策略。尤其worker_summary只能单次领取／单次发送，不因接观测改成默认三次重试。不要求为了观测恢复已取消的机器评审或测试。
