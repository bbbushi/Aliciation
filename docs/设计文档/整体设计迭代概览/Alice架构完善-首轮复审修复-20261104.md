## 补充项

- POSIX协议失联后，仅在仍持有的adapter Popen已经退出，且用户明确核实整树停止时，允许 `human_attested` 解除占槽；`termination_confirmed`保持false。存活adapter或无法核实的Windows Job仍拒绝。不会按历史PID杀进程，不退款、不重派；未知费用仍需核对。
- 旧 `run_task.py` 和 `demo_dispatch.py` 明确退役，只返回说明和退出码2。Windows `local_transport` 启动CLI前要求生产监督标记及当前进程的Job成员证明；生产宿主最终仍查询自己的Job树。未运行旧入口或进程实验。
- 每次主模型调用依据当次 `active_tools` 生成schema块、`tool_schema_count/tool_names`；无工具收尾不再携带旧schema观测。总输入估算与块清单各有语义，不把字符估算当供应商精确token。
- W3在同一次实际后缀选择中生成 `exclusions[{id,reason}]`，原因分为 `message_limit/orphan_prefix/token_budget`；另给 `minimum_retained_over_budget/current_user_over_budget`。不重新选择或改变history/recap共同边界，不截断当前用户原话。
- 收养审查明确合法的 `decision × reason_type` 组合，自相矛盾回执拒绝。结构检查不等于语义审查正确。
- 宪法“存在事实”同步说明人工恢复只解除执行槽占用，不代表宿主整树证据或供应商费用结清；P1b仍默认关闭。没有开放文件下载、跨任务传播、worker自动正式见闻、worker资料向QQ传播或W6—W9新行为。

## 调用观察覆盖及限制

| 路径 | 本轮补齐的关联与回执 | 重试与边界 |
|---|---|---|
| 普通思辨 | `purpose=thought`，触发request_id或独立thought身份；实际回执模型、耗时、成功/错误和usage已接统一calls | 原 `retry=not external_input` 不变 |
| 技能提炼 | `purpose=skill_distill`，触发request_id或独立distill身份；原cheap_model | 原llm.chat重试策略不变 |
| 人格演化与维护链 | 包装器贯穿request_id；独立service维护同一maintenance身份，正常对话沿原请求 | 没有为关联额外发模型请求 |
| 协作报告总结 | `purpose=worker_summary`，attempt=1；context含trigger、task_id、worker_attempt_id、epoch和worker_id | 仍单次直接create，client自身max_retries=0；格式不合格降状态但保留真实usage，供应商异常只记固定分类 |
| 观测保存 | 回执只进线程安全有界队列，报告收尾在Store锁内安全flush | 不提交业务外层事务、不因日志失败重发；进程崩溃前未落盘回执仍可能缺失 |

既有主调用、提取、前情、各类审查和人格导入的覆盖见首轮记录。本轮没有把独立网络discovery的受监督model_runner、手动P1核查（evaluation_service）或模型配置探测（service._probe_model_config）改成同一账本；它们各按既有调用记录或实际明确操作取证。**不能仅累加统一calls就声称全产品所有模型次数/费用。** 已取消的机器评分与功能自测没有恢复。
