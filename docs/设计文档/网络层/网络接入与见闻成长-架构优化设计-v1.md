# 网络接入与见闻成长：架构优化设计 v1

> 2026-11-02｜设计与实施基准，实际进度见执行计划。依据：[已确认待办 N01～N08](./网络接入架构优化-待办.md)。
> 本文将已确认原则整理为目标架构；分档、模块落点和实施顺序属于设计建议，具体参数另定。当前工作分支为 `ytq`。

实施入口：[AI 执行计划 v1](./网络接入与见闻成长-AI执行计划-v1.md)，包含分阶段代码范围、完成条件及人工验收清单。

## 1. 目标与现状

让 Alice 在授权范围内主动寻找材料、理解用户兴趣，自主选择值得留下的见闻，并及时形成可验证、可修订的判断。用户当前讨论优先，记忆按价值保留细节、逐步浓缩或遗忘。

当前已有来源池、见闻保存、来源依赖、平台适配、后台发现和对话检索。主要改造点是：集中且重复的调度逻辑、以数量为主的思辨触发、缺少价值分档的遗忘，以及兴趣识别与后续使用之间的闭环。

本版沿用现有记忆库、GUI/QQ 渠道、平台授权和浏览器组件，逐步改造内容接入链路。模型接口和 QQ 传输继续使用现有实现；完整 Agent 的产出仍按独立任务来源契约接入。

## 2. 整体流程与职责

材料经搜索和读取进入来源池，完成初筛后交给 Alice。Alice 对实际收到的材料判断价值、决定保留内容，再保存带来源见闻；按任务类型立即或批量思辨。兴趣与后续反馈参与下一轮寻找和记忆维护。

| 部分 | 职责 | 沿用基础 |
|---|---|---|
| 任务调度 | 前后台优先级、取消、期限、预算和阶段状态 | `discovery.py`、`dialogue_search.py` |
| 平台适配 | 搜索、读取、范围声明和规范化结果 | `discovery_sources.py`、平台 transport 与 addons |
| 来源管理 | 版本、实际读取范围、证据、受众、保留与撤销 | `discovery_memory.py`、`observation_memory.py` |
| 兴趣与价值判断 | 从聊天识别兴趣，对已读材料决定保留与优先级 | 兴趣记录、Alice 对话及受调度的模型步骤 |
| 见闻与观点维护 | 分级保存、浓缩、遗忘、思辨与观点修订 | `store.py`、`consolidation.py`、`thought.py` |

AI 决定兴趣、价值、保留意愿与初步观点；宿主核实实际输入、权限、来源、预算和落库条件。具体模块名在施工时确定，避免一次性重写。

## 3. 统一材料处理链（N01、N06、N08）

1. **取得材料**：前台检索与后台探索调用同一套平台搜索/读取接口，共用规范化结果、计账和失败规则。
2. **初筛**：排除重复、空正文、登录页、无关广告和无法确认出处的内容；保留合法的不同意见与反例。搜索摘要仅用于发现线索。
3. **实际阅读**：将获准片段及阅读范围交给 Alice，记录本次输入的来源版本。入池、抓取成功、交给模型和形成记忆分别记录。
4. **AI 判断**：输出保留意愿、价值理由、兴趣关联与必要的不确定性；允许认为材料无价值，不要求每条保存。
5. **保存见闻**：保存 Alice 选择留下的内容，绑定实际材料依赖，再交给思辨与遗忘机制。

“实际读过”以本次模型输入为依据；保留完整度以已经读取且获准保留的范围为上限。渠道、作者背景和评论可作为辅助信号；评论没有读取或尚未授权时，不能伪装为已参考，也不阻塞主要材料的处理。

## 4. 价值、浓缩与遗忘（N01、N06）

价值由用户兴趣相关性与 Alice 自主判断共同决定。兴趣外但重要的材料也可保留。价值与可信度建议分别记录：争议或错误说法也可能值得作为反例保存，热度不直接等于可信度。

初版建议采用可调整的三档，先验证行为，再确定数值权重：

| 优先级 | 保存方式 | 维护顺序 |
|---|---|---|
| 高 | 保留较完整的已读内容、关键证据、条件与判断依据 | 优先保留，必要时复核和修订 |
| 中 | 保留结构化摘要、关键条件及支持或反对的证据 | 随使用和反馈重新评估 |
| 低 | 高度浓缩为核心要点、适用条件、不确定性与出处 | 优先进一步浓缩或遗忘 |

浓缩以可核对的证据为依据，避免不断转述上一次摘要。不同表达但相同内容版本不能反复计作新知识；浓缩更新须处理版本和派生依赖，不能断开出处。

将价值排序接入统一记忆维护入口，综合近期使用、反馈和兴趣变化调整。2026-11-02 用户确认：保留来源硬期限，七天线作为复核点；高价值新见闻优先保留，中低价值结合实际使用决定去留。旧未分级记录保留原规则；高价值观点的必要依据同样受保护，容量不足时低价值先遗忘。证据保留、来源撤销和用户删除的规则始终有效。

## 5. 即时提取与分级思辨（N02）

| 材料类型 | 调度方式 |
|---|---|
| 为用户当轮明确目标开展的检索 | 读取后即可提取和初步思辨，用于当轮讨论，不等待数量或时间阈值 |
| 高价值、明显冲突、反复出现的有效材料 | 提前进入思辨队列，同一材料或同一组证据合并处理 |
| 普通后台材料 | 在空闲时积累后批量消化 |

当轮回答可以同时完成理解、提出暂时判断与择要保存，不强制每条材料额外调用模型。宿主接收结构化保存意图，验证来源和预算；没有值得保留的内容时允许跳过。

初步观点保留依据、不确定性与暂时判断状态。后续独立思辨可验证、修订或放弃它，避免同一材料在前台和后台重复消耗。保存失败不等于读取失败，不应阻塞仍有有效来源支撑的讨论，也不能声称已经记住。

## 6. 自主兴趣与防循环（N03、N04）

Alice 从自然聊天中的观点、经历和关注点自主建立或更新兴趣，无需逐条询问用户。兴趣记录保留主题、态度、置信度、依据轮次与更新时间，并允许用户查看、纠正和停用。

区分持续兴趣、一次性提及、转述，以及喜欢、关注、反对等态度。后续真实表达可增强或修订兴趣，长期缺少支持可逐渐衰减。

用户表达与 Alice 自行搜索、阅读的记录分开计权。Alice 接触某话题的次数不能直接强化用户兴趣；用户主动继续讨论或给出反馈时，才形成新的用户侧依据。兴趣识别受原渠道范围约束，私密依据不直接拼成公开搜索词；自主寻找沿用已有平台与外发许可。

## 7. 来源与观点修订（N05、N06）

见闻保存出处、内容版本、阅读覆盖范围、必要证据和受众，派生观点继承实际输入依赖。来源池的日常清理与已授权保留证据的生命周期分开管理；来源撤回或许可失效时，相关内容及派生使用资格同步处理。

新旧证据冲突时，记录双方依据和“当时的判断／当前的判断”。AI 可以维持、修订或放弃观点，保留修订理由，不将新材料自动当作更正确的结论。信息已经过时与来源已被撤销分别表达，不把失效材料继续呈现为当前有效依据。

## 8. 调度、预算与可见状态（N07）

统一任务身份贯穿检索、读取、判断、保存和思辨；每个子步骤归属原任务，记录其输入版本与处理结果。前台讨论优先，后台工作在可取消的阶段让路，并复用已经完成且仍有效的结果。

共享账本覆盖网络请求、传输量、模型调用和记忆写入。执行前预留、执行后结算，未知消耗保守保留；已计入当轮回答的模型调用只做任务归属，不重复收费记账。即时处理资格仍受用户既有权限和额度约束。

GUI 保持简洁，能够说明“读到了什么、留下了什么、为什么感兴趣、观点是否修订”。读取失败、未选择保存、额度不足和来源失效给出不同状态。

## 9. 实施顺序与人工验收

| 阶段 | 实施范围 | 人工验收重点 |
|---|---|---|
| A | 提炼统一平台接口、规范结果与任务上下文 | 前后台获取同一材料时，读取范围、授权、取消和计账一致 |
| B | 自主兴趣及价值判断，接入带来源见闻保存 | 自然聊天能形成可解释兴趣；AI 自读不自增用户兴趣；兴趣外重要材料可保留 |
| C | 用户检索即时提取、提前与批量思辨、观点修订 | 同轮角色/作品讨论能及时形成有依据的判断；冲突可修订；不重复处理 |
| D | 分档保存、证据保留与统一遗忘决策 | 低价值压缩更多，高价值保留细节；浓缩仍可核对；撤销和遗忘正确传播 |

沿用现有公共 API、短事务和锁外网络/模型调用，按阶段迁移并保留兼容入口。数据变更先备份；用户数据与授权不因改造被重新初始化。能力上线时同步存在事实清单。验收使用真实环境人工操作，设计完成不代表实现或验收通过。
