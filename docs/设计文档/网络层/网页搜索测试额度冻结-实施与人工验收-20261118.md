# 网页搜索测试额度冻结

2026-11-18。用户要求网页搜索也暂时冻结额度限制，便于人工测试。0.1.22沿用已有`autonomy_policy.TEST_CONTROLS_ONLY=True`，不另外增加隐式开关或改写真实配置。

## 原因与实现

此前`SearchSession`的测试覆盖仅在`background=True`时生效；`DiscoveryCoordinator._reserve_step`也只为`exploration_search`跳过预算。前台仍会被每日查询/网络/响应总量、每轮来源依赖与工具轮数拦截。只跳过每日额度还不够：来源保存阶段的容量校验、模型上下文的依赖上限也会在后续阶段阻断。

新增纯内存策略`search_settings()`和`search_source_limits()`，所有保存配置仍是原值。测试开关启用时临时把以下业务上限设为None：

- 每日查询、搜索模型、网络请求与响应总量；每轮搜索调用次数与自动选入资料数量。
- 候选读取数、每轮资料/来源依赖数量、候选池条数、来源内容池容量、外部来源回忆数量。
- 已获准提供搜索工具的前台对话，其工具交互轮数上限。

`SearchSession`在读到配置后应用有效策略；后台原有每次2份材料的小批量样本策略保留。搜索的每日预算预留不再因原数值超额而拒绝，但仍真实登记每次查询、网络、模型和字节使用量。手动寻找与吧名检测同样在本次运行副本里放宽相应预算；原发现后台路径的业务时段/间隔/库存等待在测试时跳过，平台与后台启用状态不改变。

来源存储通过既有`SourceStoreMixin.source_limits`返回有效限额，覆盖保存时来源池检查、前台初始来源集合、工具返回时的依赖上限。正式见闻写入额度、来源文字校验不修改；这项是网页取材测试放宽，不是给保存记忆或主动联系另开权限。

发现状态API新增`search_quota_testing`，预算和来源池字段返回当前有效限额None；设置表单仍显示保存值。页面显示“测试模式：搜索额度暂不执行，用量仍记录；设置值保留”，并取消被暂停容量值为0误导的前端寻找拦截。兴趣启用数/必要兴趣和各项实际权限仍按原逻辑处理。

## 仍执行的约束与恢复

不修改总开关、对话搜索、平台/全网开关、第三方/QQ资料共享或付费许可。取消、服务排空/更新维护、前后台互斥、会话/来源范围、来源TTL/撤回、用户显式单次limit与单批候选数量都保留；单请求/模型期限、子进程监督、响应解析体积、网页公网地址与TLS校验仍执行。并不绕过Bing/Brave/SearXNG或目标网站自身限流。

`TEST_CONTROLS_ONLY=False`后，两个策略函数返回保存值，预算预留和业务时段/间隔恢复；原后台额外放宽也按既有开关恢复。不落入人为超大配额、不清空计数、不更改user或桌面配置。测试期间的实际使用量保留，恢复后会按真实累计值判断剩余额度。正式发布前应撤回临时策略。

本轮新增的是开发包执行策略与观察字段，没有模型工具增减，注册表/宪法v9保持。沿用0.1.21全网和0.1.20防闪、0.1.19自主活动实现及其待验状态；实际恢复/中断撤销继续暂缓。
