## 4. 分阶段实施

### P0｜核对基线与数据演进

入口：`discovery.py`、`dialogue_search.py`、`discovery_memory.py`、`observation_memory.py`、`thought.py`、`consolidation.py`、`store.py`。

- 标出目前前后台平台分派、额度预留、来源发布、自动摘录保存、兴趣推断和思辨入口，区分已实现行为与缺口。
- 确定统一任务上下文、平台结果及新增兴趣/价值/思辨记录的最小字段与存储位置，复用现有表和依赖机制，不为重构复制完整数据库。
- 新字段与迁移保持向后兼容、可重复执行。旧数据缺少价值、阅读或来源依据时标为未知，不批量伪造记录。
- 起服即可能迁移活库；涉及数据库变更前备份并检查当前服务/任务，避免两个进程写同一账本。

完成条件：基线、参数处理与数据演进方案已记入实施记录，后续阶段具有明确入口。

### P1｜统一前后台材料链与计账（N07、N08）

入口：`discovery.py`、`dialogue_search.py`、`discovery_worker.py`、`discovery_sources.py`、各平台 transport；必要时提炼新的核心模块。

- 提炼共同的搜索、候选规范化、读取、初筛和来源发布服务；前台与后台仅保留各自任务目标、选材方式及调度差异。
- 任务身份、阶段、输入版本、期限、取消信号和授权快照贯穿链路；平台专有判断集中到适配层。
- 复用共享账本，子步骤只预留和结算一次，未知消耗保守保留；当轮回答已有的模型调用只关联归属，不重复计账。
- 用户讨论优先，后台在可取消阶段让路；恢复时重新核验来源与授权，复用有效成果，不自动重发可能已执行的模型/网络动作。

完成条件：两条入口调用同一处理链；保留原平台、代理、GUI/QQ 范围、停止与额度语义；无重复平台分派和重复扣账。

### P2｜自主兴趣识别与防循环（N03、N04）

入口：`discovery.py` 的兴趣与 `record_chat_locked` 逻辑、`service.py`、`loop.py`，以及对应 GUI 设置。

- 由 AI 从自然聊天提出兴趣及更新意图，宿主保存主题、态度、置信度、真实用户轮次依据和时间；不要求用户逐条确认或使用固定口令。
- 区分用户原话、转述、一次性话题、持续关注和态度。用户主动表达与反馈可以增强兴趣，Alice 自行搜索/阅读不能直接增强用户兴趣。
- 去重合并已有主题，支持修订、衰减及用户纠正/停用。混合网页引用的聊天只使用能确认属于用户表达的依据。
- 保留原渠道范围和外发许可，私密依据不直接拼入搜索词；接上现有兴趣选材与价值判断入口。

完成条件：兴趣有可追溯用户依据；无需手动标签；AI 自读不自增兴趣；新增识别不绕过原有搜索许可。

### P3｜AI 择要保存与价值元数据（N01、N06）

入口：统一材料链、`retrieval.py`、`observation_memory.py`、`discovery_memory.py`、`store.py`。

- 将初筛后的实际材料交给 Alice，记录模型输入范围与来源版本；入池不直接冒充已读。
- 接收 AI 的保留决定、价值理由、兴趣关联、压缩级别及必要的不确定性，允许跳过，也允许保留兴趣外的重要材料。
- 前台和后台都进入同一择要保存入口，替换后台按开关直接保存固定摘录的旁路；绑定实际证据、版本和受众。
- 以任务、材料内容版本和处理目的去重；重复轮询或改写标题不重复写入或刷高价值。

完成条件：保存取决于 AI 对已读材料的判断；高低价值可影响保存内容；出处、关键条件、不确定性和撤销依赖仍有效。

### P4｜即时提取与分级思辨（N02、N05）

入口：`service.py`、`loop.py`、`thought.py`、见闻和观点依赖记录。

- 用户当轮明确目标产生的检索可即时提取、形成初步观点并参与回答；不要求额外的“搜索”口令，不等待批量数量或定时窗口。
- 尽量复用当轮模型步骤的结构化输出；需要独立调用时归入原任务和预算，不强制每条生成观点。
- 高价值、冲突和反复出现的有效材料提前调度，普通材料空闲时批量处理；以已处理输入版本避免前后台重复消化。
- 核对首次思辨与人格演化共用时间锚点的问题，使用独立、可追踪的处理进度，避免新材料被其他维护任务跳过。
- 观点保留证据、不确定性和暂时判断状态。修订保存新旧关系及理由；来源变化、任务取消后重新核准，迟到结果不直接写入。

完成条件：角色/作品讨论可当轮形成有依据的判断并择要保存；普通批量路径保留；无新观点可跳过，冲突可修订且不丢旧依据。

### P5｜分档浓缩与统一遗忘（N01、N06）

入口：`consolidation.py`、`store.py`、`observation_memory.py`、来源及派生依赖维护。

- 统一价值、实际使用、反馈与兴趣变化的维护入口，使优先级同时影响保留细节及淘汰次序。
- 低价值保存核心要点，高价值保留较完整的已读材料和证据；从可核对依据生成浓缩结果，避免反复摘要造成失真。
- 浓缩保留身份、版本和来源关系，处理派生观点依赖；常规浓缩、资料池清理、来源撤销、用户删除分别处理。
- 淘汰预览与实际执行使用相同策略。保存期限及旧七天线关系落定后，再启用新淘汰规则；保留普通用户记忆、压力窗口及既有授权的约束。

完成条件：能解释为什么压缩或遗忘；低价值先压缩/淘汰，高价值不被另一条旧清理旁路提前删除；证据、派生资格与期限正确处理。

### P6｜界面、兼容与交付记录

入口：`web/discovery.js`、`web/chat-search.js`、`service.py`、`server.py`、`retrieval.py` 的存在事实清单。

- 沿用当前界面展示材料的读取/保留结果、兴趣依据与纠正入口、初步观点及修订说明；展示当前压缩级别和淘汰预览。
- 区分读取失败、未选择保留、保存失败、额度不足和来源失效；保持回答与实际保存状态一致。
- 全链路检查 GUI/QQ 的可见范围及实际发送前核准，不因摘要、兴趣或新观点扩大受众。
- 更新能力事实、设置说明和简短实施记录，清理本次替代的重复入口，保留必要兼容面；不扩大为 GUI 重做。

完成条件：用户能看懂为什么留下、为什么感兴趣及观点如何变化；原有渠道和已交付 CLI/GUI 功能没有被覆盖。

### P7｜真实环境人工验收

由人通过 GUI/公共 API 操作；AI 准备操作步骤并记录实际证据，不运行自动业务测试或模拟结果。

| 场景 | 通过条件 |
|---|---|
| 普通聊天流露兴趣，随后转述/批评另一个话题 | 能自主识别，依据准确，态度与兴趣区分，用户可纠正 |
| Alice 自主探索同一主题多次 | 不以自身阅读次数强化用户兴趣，不重复形成同一见闻/观点 |
| 用户要求查角色或作品后立即讨论 | 当轮能理解、初步判断与择要保存，不等待原 15 条阈值 |
| 高低价值材料及兴趣外重要材料 | 保存完整度不同；兴趣外可留；压缩仍有依据和关键条件 |
| 新证据与旧观点冲突 | 保留分歧和修订关系，能维持或修订判断，不机械覆盖 |
| 前台检索遇到后台探索/思辨 | 前台优先，后台正确让路，预算不双扣，取消后不复活 |
| 来源撤回、过期，或转到 QQ 询问 | 依赖和受众规则有效，派生摘要/观点不绕过限制 |
| 执行中重启、失联或额度耗尽 | 状态及未知消费可解释，不自动重复有副作用的操作 |

记录代码版本、配置摘要、任务/来源身份、实际操作和结果。不可用的平台如实待验，例如浏览器通道当前的 Windows Edge 限制；不把其他平台的结果当作该平台通过。
