## 使用入口

1. 在「发现 → 自动寻找与高级设置」保留所需平台，开启「允许内容访问」和「允许 Alice 在聊天时按需要自行查找相关资料」。只需配置一次，按兴趣自动寻找仍是独立开关。
2. 直接正常聊天，例如「最近想换把安静一点的机械键盘，大家实际用起来是什么感受？」。主对话模型可判断是否需要近期信息、具体例子、观点或谈资，自行组织公开关键词并调用工具，不要求说“搜索”、填写主题或逐次确认。已有信息足够时直接回答，不会在模型回答前强制联网。
3. 查找过程中可点「停止查找」。界面分别显示搜索返回、候选、尝试读取、读到正文、复用材料与网络请求数量。停止只针对剩余查找；已经发生的请求仍计账，当前聊天可以说明已取得的材料或停止原因。
4. 想保留见闻时，先开启「允许择要保存带出处的见闻」。Alice 可在当前对话里择要保存，也可在资料卡点「记住这份见闻」。卡片上的「查看记忆」及记忆详情中的「查看出处与相关讨论」可追溯短证据、读取范围和关联提问。
5. 「记住：我更喜欢安静的咖啡馆」这类独立、明确的本人表述可直接保存；普通第一人称表达提供「记住我的表达」。含引用或指代不清的混合表达提供「补充我的看法」，只填草稿，仍由用户自己发送，不把网页判断直接当作用户偏好。

聊天中没有独立搜索栏。仅实际调用检索时，在 Alice 的回复旁显示查询主题、进度、来源和停止入口。可以直接说「这次不要联网」，常见明确禁用表达会移除本轮工具；其余自然语言要求由主模型遵守。需要新材料时，模型可使用 `fresh` 跳过跨请求结果缓存；同一工具调用的重放仍不会重新联网。

QQ 本人私聊另需在「聊天取材与记忆」开启「允许本人 QQ 私聊搜索和使用资料」。QQ 只接收最终回答，网页与 QQ 共用平台和额度；本机网页历史可查看来源仍同时允许两处使用的 QQ 回答。修复不会自动开启许可，也不包含群聊更新。

## 执行和公共接口

- `alice/steps.py` 负责驱动短存储步骤与锁外等待；`loop / extraction / persona / thought / skills` 的阻塞公共调用保持兼容，服务使用对应步骤入口。
- `alice/dialogue_search.py` 绑定本轮网页或已绑定本人 QQ 私聊请求、会话版本、配置版本及渠道令牌。许可开启时向主对话模型提供工具，由它决定是否及何时调用；不再宿主预先查找，也不另加选题模型。
- `discovery_search(query, platform?, limit?, fresh?)` 接受模型根据话题生成的公开关键词，不接收任意 URL。平台仍由用户许可限定，额度共享；相同调用 ID 不能换参数后重放，相同条件优先复用仍有效的材料。验证、登录、拒绝访问及限流发生后，本轮不能换关键词再次访问该平台。
- 搜索提示要求将私人经历抽象为公共话题，不外发完整聊天、私密记忆或身份凭据；宿主额外拒绝链接、邮箱、常见手机号/身份证号及密钥等明显模式。这是有限格式检测，不宣称能识别所有语义上的私人信息。
- `/api/chat` 保留可选 `search_intent`：`{query, platform, interest_id?, fresh?}`，兼容旧调用方的查询提示，不再是启用检索的必要条件；网页普通发送不填写该字段。同一 `request_id` 的正文及提示必须一致。`platform` 可为 `auto / tieba / bilibili / zhihu / wikipedia`；关联兴趣仍须有效且获准外发。
- SSE 增加 `type: search`，包含请求身份、阶段、状态、实际计数和材料元信息。聊天断线不自动取消或新增请求；页面可根据活动身份查询原任务。
- `POST /api/chat/search/status`、`POST /api/chat/search/cancel` 使用 `{request_id, session_epoch}`，仅供本机 GUI。取消只设置事件，不等待 Store 锁；状态读取会重新检查来源，进程重启后的旧任务不自动重跑。
- `POST /api/discovery/memory` 使用 `{dataset_id, memory_id}`，返回当前范围内的记忆、短证据及关联提问。发现管理增加 `remember_card` 和 `remember_user` 动作，继续要求会话与配置版本。
- 公共服务方法为 `ChatService.send(..., search_intent=..., on_search_progress=...)`、`chat_search_control`、`observation_memory`；本人 QQ 私聊通过原渠道消息入口触发获准搜索，机器凭据仍不能调用 GUI 管理入口、修改许可或访问未授权来源。搜索状态/停止入口只供本机 GUI，接受原 QQ 请求身份；QQ 不接收逐步进度推送。

数据库恢复元数据只保留任务身份、来源 ID、状态、计数等；查询词只在当前任务进度中显示，不另建持久查询正文记录。结果状态不另缓存来源正文；状态展示和聊天取材都通过当前来源资格重新读取。搜索结果为空、找到候选但没读到正文、额度阻止、平台验证、部分成功等状态分别处理。仅提供工具而没有实际查找的普通聊天不产生检索运行记录，也不因此变成外部来源讨论。

## 设置与额度

| 设置 | 新安装初值 | 含义 |
| --- | --- | --- |
| `background_enabled` | `true` | 总开关允许时，是否按兴趣自动寻找；迁移不关闭既有自动发现 |
| `chat_search_enabled` | `false` | 是否允许 Alice 在网页或本人 QQ 私聊中按需要自行查找；非逐次开关 |
| `share_in_qq` | `false` | 本人 QQ 私聊搜索及引用资料的额外许可；搜索仍须开启内容访问和聊天查找 |
| `remember_observations` | `false` | 是否允许新增带来源的正式见闻及其派生观点 |
| `chat_search_calls` | `null` | 每轮搜索调用次数，不设强制次数封顶 |
| `chat_search_results` | `3` | 每次查找目标材料数，仍受用户自己的资料及依赖数量设置约束 |
| `tool_round_limit` | `4` | 聊天工具交互轮数，替代原固定轮数，可改或不限 |
| `chat_search_timeout_seconds` | `300` | 一次对话搜索等待期限，可改 |
| `observation_ttl_hours` | `null` | 新正式见闻最长保留时间；默认按普通遗忘与真实来源许可存活，可另设期限 |

可空的数量/容量设置仍按 `null=不限、0=禁止新增` 解释。等待期限须为正数；协议字段、合法地址、资源核准及来源身份校验仍存在。查询、网络、响应量、每日见闻写入及来源池与后台共用，搜索本身不再另调用选题模型；正常聊天及既有维护的模型消耗仍按原配置执行。

保留已有额度，不悄悄放宽。特别是旧 `chat_material_limit` 默认是 2，所以把搜索目标设成 3 并不覆盖用户当前的材料额度。`pool_capacity=0` 可以不建卡但保留获准的本轮附件；来源池为 0 时不会先出去读取再丢弃。临时查找卡不参与自动兴趣库存目标。

## 记忆和撤销

临时原文仍在 `source_packets`、`discovery_cards` 及来源聊天附件中，按原 TTL 和容量清理。正式见闻进入原 `memories` 表，标记 `origin=external_derived`、`lifecycle=memory`、`salience=0`，参与原分层、容量竞争和遗忘。新 `retained_evidence` 只留来源身份、版本、读取时间、短引文、覆盖与许可，不复制整页。

`memory_evidence_links` 记录必要短证据；`memory_dependencies` 记录思辨依据的实际记忆 ID 与内容版本，不能只凭模型输出的标题或较少来源解除依赖。`discussion_records` 与 `discussion_memory_links` 区分用户独立表述和提问背景：没有可独立保存的原句时，只关联轮次，不另复制混合讨论正文。

正式保存先核对本轮真实来源、资格、范围、容量和日额度。只有 URL 的旧 `save_web_seen_memory` 入口现在拒绝保存。正式见闻加上来源声称/暂时判断的说明，网页观察形成的观点从「见闻、先验」开始，不因生成一次摘要自动变成已核实事实。

原包 TTL 清理保留另有资格的短证据；显式清除、必要证据到期或收窄范围会撤销相关记忆与派生观点，并清理来源回答附件。最后一个记忆依赖消失后，持久证据只留不含正文的撤销元数据。重读时间戳和改写摘要不能重置同一版本同题记忆的年龄；被遗忘或清除的内容版本不能靠改名自动复活。独立用户表达不因背景资料删除而被抹去。

来源观点只按当前渠道参与上下文，并以参考数据提供；不会写入供所有渠道共用的无范围人格正文。人格、技能、普通提取与 P1 继续排除未完成范围传播的外部派生。旧 `source_url` 普通记忆标为 `legacy_unverified`，可人工回顾，但不继续作为自动召回或成长依据；能定位到的相关旧观点同样隔离。无法反推的历史人格变化仍需人工核对。

## 2026-11-01：QQ 本人私聊搜索修复

旧代码在工具准备和任务持有者检查中都只接受 `gui`，搜索结果的读取、复用和正文保护也固定使用该范围，因而 QQ 私聊即使已允许使用资料，也无法发起新查找。本次允许已认证的 `qq-owner` 在内容访问、对话查找及 QQ 资料许可同时开启时使用现有工具；每次请求仍核对当前许可、设置版本、原会话和处理槽，不为 QQ 增加管理权限。

搜索缓存按当前渠道分开，所有读写与引用按当前范围校验。QQ 新取得的材料可供本机查看，但不会改写旧 GUI 专属来源的许可；相同页面须真实重读后才产生另一个获准版本。GUI 历史定向展示本人 QQ 来源正文时，所有依赖必须同时允许 GUI 与 QQ，反向读取、模型上下文和普通记忆的范围规则保持原样。成功、失败和维护异常都会收尾当前搜索会话。

QQ 多次工具调用共用原消息的时间上限：按保守的 5 分钟被动回复窗口提前 60 秒停止搜索，并与用户设置的单次查找时限取较短值。桥配置的窗口可能更短，模型或网络也可能变慢，因此不保证每次都能赶上发送；沿用原桥的实际窗口、逐段来源核准和未知发送不重试规则，不转为主动消息。

本轮仅静态语法、差异及独立审查；未执行机器自测、发送真实 QQ 消息、调用模型或启停服务，未读写 `user/`。以下真实人工验证均待执行：

| 场景 | 期望行为 |
| --- | --- |
| 已绑定本人 QQ 请求查找公开主题 | 在已开放平台查找，取得正文后回答并说明出处；查询/网络额度与网页共用 |
| 缺少任一许可、额度为 0、明确说本轮不要联网 | 不发起新搜索；无法查找时不伪称已经联网 |
