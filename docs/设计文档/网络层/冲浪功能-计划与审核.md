# 冲浪功能：计划与审核

2026-10-30｜heartbeat参考修订版，待用户审核，未授权开发。配套：[搜索计划](./搜索功能-计划与审核.md) · [社交观察计划](./社交观察功能-计划与审核.md) · [本次修订报告](./联网能力-heartbeat参考修订报告.md)。

## 先审这一页

**目标：让 Alice 在相处之外有持续的信息生活——自己挑内容、留下少量见闻、形成变化中的兴趣，合适时能与你接着聊。** 首个版本就应做到自动浏览、有限记忆和后续分享；只有“读取页面、24小时后清空”不算完成冲浪。

按本次要求，**冲浪是主线，搜索是发现内容的支持能力，社交观察是独立的观察来源；完整查证产品不再是开发前置。** 上轮评估中的网络、来源和记忆风险证据仍有效，原“先查证、其余延后”的产品顺序已被本次要求替代。

**2026-10-30搜索定位补充**：用户随后明确搜索用于按用户兴趣寻找可能感兴趣的内容，作为对话资料和观点判断参考，并由用户决定开放的平台。具体以[新版搜索计划](./搜索功能-计划与审核.md)为准：获准兴趣范围内允许自主组合query；临时、有依据的观点用于首版聊天，不等于本计划第七节的长期思想/人格写入。冲浪的实际阅读与素材机制为此闭环提供公共能力。

推荐首版：用户一次选定几个公开来源、公开兴趣和活动时段；Alice按轻量活动节拍检查是否值得去逛，日内最多2次、每次最多3页。阅读先进入有界素材池，自动留下至多1条有出处的正式见闻/日；一个“待续念头”带过尚未聊完的问题，等相关聊天时再决定是否分享。兴趣权重能变化；网页及其派生材料暂不直接改底色、生长人格或技能。自动静默阅读和主动发消息分别授权。

| 本计划需裁决 | 推荐选择 | 选择带来的行为 |
|---|---|---|
| R1 自主程度 | 批准来源/主题/时段后自动运行，范围内无需逐页确认 | 可自主选题、跳过、跟一层链接；新增域名/外发主题须另批准 |
| R2 首版是否记住见闻 | 每日最多1条自动外部event，沿用分层和遗忘；不直接改核心人格 | 几天后还能聊到读过的东西；需要新增来源资格及派生传播机制 |
| R3 如何开始分享 | 后台静默；GUI可查看，相关的下一次聊天可提一条 | 不默认QQ主动推送；不把浏览许可等同通知许可 |
| R4 发现入口 | 先接少量公开feed/栏目，同时设计搜索接口 | 不等待搜索供应商或完整查证UI；首批具体站点、主题与时段在开发前确定 |
| R5 连续性与成本 | 活动/分享两道闸；短期素材池+单格待续念头；不另加每拍反刍模型 | 库存足够可以不搜，没新材料可以不调模型，没说出口不自动当成不喜欢 |

若希望首版就让阅读直接改变人格，请单独选择第七节的扩展范围；这会增加来源及修订机制，不应伪装成一项开关。

同步到main的[需求六](./需求文档-GUI功能三件.md)要求B站先行、内容参与思辨。本计划的“静态来源先行、思想/人格后分期”是供审核的范围调整，尚未获得同意，不能据此声称需求六已经覆盖；若B站必须首发，字幕/简介/评论各自的合法接入、证据与媒体覆盖须纳入F1，工期另估。

## 一、用户真正能看到什么

示例仅说明产品行为，不代表已发生的浏览：用户批准天文、游戏设计、生活随笔几个公开主题及晚间时段。Alice先看两个栏目列表，发现一篇和之前读过的观点不同的文章，决定多看一页；如果没得到新东西，就结束，不强行总结。若值得保留，会记下“某天读到某作者这样解释X”的短见闻。

之后用户问“最近看了什么”，她能给出真实读过的内容与来源；聊到有关话题时，也可以自然提一句。公开见闻可用于GUI和既有本人QQ被动聊天，QQ仍用原请求、时限和分条流程，不因此主动推送。用户点“这个还想听”，会影响后续关注；点“少聊这个”，先降低分享频率。连续看了几次同类文章不能自动推导“我从此成了某种性格”。

GUI只需三个面：**最近见闻、近期关注、活动设置**。见闻可展开来源/已读范围、移除；近期关注展示真实选择与明确反馈的依据；设置给暂停、来源、时段和额度。无需建设大型观察仪，也不生成每天必须看完的报告。

最近见闻中可以出现“留着下次聊”的一条短线索。它可以安静过期，也可以在合适的对话里化成一个问题；不会每隔一小时提醒用户回答。用户能清掉它，不需要理解后台阶段、素材ID或报账协议。

## 二、第一版包含什么

| 包含 | 首版不包含 |
|---|---|
| 空闲时段自动运行，用户也可点“去逛一会儿” | 24小时持续模型思考、模拟情绪或完整生物钟 |
| 公开feed/固定栏目发现，少量静态页面阅读 | 登录态浏览、JS浏览器、视频/音频理解、无限翻页 |
| 当前兴趣与少量意外发现，最多一层关联链接 | 模型任意拼网址、无限扩域、拿私聊内容生成搜索词 |
| 自动少量见闻event、真实出处、相同遗忘机制 | 自动高重要度记忆、网页直接修改人格/技能 |
| 兴趣权重变化、去重、冷却、自然聊天分享 | QQ主动通知、对外评论/点赞/关注/转发 |

feed条目可能只有摘要。仅取得摘要就说“看到了摘要”；读了文本不说看过视频。来源没有可用正文时跳过并留原因，不用模型编出“逛到的内容”。

## 三、一次冲浪怎样进行

```text
轻量节拍：本地有界清理 + 活动闸（许可/窗口/前台/库存/预算）
  → 发现与采集：最多2个发现请求，去重、冷却，得到候选句柄
  → 隔离加工：选题≤1次，读≤3页，阅读归纳≤1次；均可skip
  → 宿主核验来源/引文/范围，提交素材；可选有限正式见闻
  → 空闲结束：不创建普通聊天轮，不主动发消息

后续用户聊天 → 分享闸（相关性/范围/时效/反馈/次数）
  → 最多提供3条短候选及1个待续念头 → 主会话从两者合计选择0或1项
  → 分别记录提供、模型选择、回答保存、渠道送达；不猜用户已读
```

选题模型只能看到可外发的公开兴趣卡和公开候选，阅读模型只看本次页面及有限公开阅读线索。二者没有私人记忆、完整人格、聊天记录、remember、配置或发消息工具。模型输出候选ID、段号等有界结构；抓取和保存权限由宿主判定。

无需先做模型规划的发现路径，没有新候选时零模型请求。兴趣搜索若已调用一次模型生成新query，随后结果为空，该次规划仍计费，只停止后续阅读/归纳；规划占本周期选题额度，不额外加调用。选题与阅读均可skip，次数是上限，不是每天必须用完的指标。搜索共用周期预算及用户开放的平台，不能在feed无内容时暗中扩大为全网搜索。

这里借鉴heartbeat的“后台备料、对话现场决定”，不复制常驻引擎室会话。选择和阅读仍用短任务、最小输入及实际工具白名单；阅读阶段无工具，宿主同时约束工具schema和执行分发，不能只隐藏工具名称。阅读归纳一次形成短材料，不再为“想想说什么”额外调用反刍模型。

活动闸位于任何新增网络/模型请求之前；被它挡住的活动不产生这两类请求。分享闸位于候选进入主会话之前；被挡住只代表本轮不分享，之前阅读的开销仍需记账。来源撤销、epoch、scope和预算在每个副作用前再核对。用户明确搜索/读取的结果返回属于该次请求，不受自动分享冷却阻挡。

### 一次批准后可以自主做哪些事

活动许可绑定`policy_id + epoch + 版本`，包含来源ID、允许的公开域名/路径、链接范围、公开主题、时段、额度、记忆权限和分享方式。页面、模型和搜索结果不能修改它。

每个候选由宿主绑定实际完整URL。模型只能选择句柄，不能改path/query/Host。允许的下一页必须来自本次实际读取页面/已配置feed，仍在批准范围内，且通过网络守卫；不请求图片、脚本、追踪地址、登录或表单。首版不自动跟HTTP重定向；跳过并在来源设置中提示，避免为兼容性放开任意跳转。

这比上轮“每页用户给完整URL”增加了**明确的范围委托**。自动许可来自用户批准的活动政策，而非“网页说可以”或“同域就天然安全”。外发规划器看不到私人材料，才能避免把私人内容通过URL构造或选题泄露；网站仍会看到IP、访问时间和公开兴趣偏好，不能承诺零披露。

## 四、兴趣怎样生长，而不重复刷同一件事

兴趣状态单独记录`topic_id、来源依据、权重、冷却、最后新发现、待解问题`，不是自由改写的人格文件。初始主题由用户播种，明确标明来历；之后允许在已批准主题空间中变化。

| 信号 | 处理 |
|---|---|
| 实际选择并读完一段新内容 | 小幅更新关注；同内容/同日重复不给重复奖励 |
| 不同日期回来读，或读到不同解释 | 增加持续性证据；不能据域名不同就认定来源独立 |
| 用户明确“想继续聊/少聊/不看这个来源” | 分别改变关注、分享频率、来源许可；不是一个粗糙赞踩值 |
| 用户没打开卡片或没有回话 | 记未知，不当成厌恶；不追问、不反复提醒 |
| reader说“我很喜欢” | 不直接作为权重依据，只可作待核对提议 |
| 未解决问题 | 有来源、短期保留；可将获准公开兴趣引用交给搜索规划器，在该范围自主组合query；不能把私密问题原文直接外发 |
| 候选被提供/主会话选用/渠道送达 | 三种独立信号；只辅助分享排序，不冒充用户偏好、阅读证据或记忆使用次数 |

每次候选主要围绕已有兴趣，同时保留一个探索位置（有足够候选时）；探索限于已批准的内容池。7日内相同URL/内容hash不重新计为新发现；同主题连续两次无新材料则冷却。近似转载采用确定性文本重叠提示，不能承诺识别所有洗稿。

新主题可以由公开阅读提议并在本地展示；已开放的上位兴趣内允许细分、同义词与公开关联探索，无需逐词批准。超出既定兴趣范围、涉及私人信息或新增平台/来源权限时再由用户决定。具体以新版搜索计划的兴趣输入与自主query规则为准，不默认全网开放。

借鉴heartbeat的轮换与防长期冷落规则：合格主题中，超过14天未选的先按最久未选排序，否则参考真实阅读的新鲜度与有界权重。14天是排序阈值，不保证每个主题14天内必访问，不突破许可、时段或冷却。分享采用率如启用须平滑、衰减并限制影响幅度；首版不以模型自报选择为主题正反馈，缺报告、忙或发送未知均不扣分。

### 素材池、待续念头与正式记忆

三者用途与寿命不同，不能套用同一淘汰公式。

| 容器 | 建议首版规则 | 与正式记忆的关系 |
|---|---|---|
| 新见闻素材 | 冲浪与公共观察共享12个位置；每项≤300字、最小证据≤4 KiB；最长48小时，可因来源规则更早失效 | 候选缓存，入池不算新增记忆；来源内容与生成解读分开存 |
| 聊天待续素材 | 预留4个位置、最长7天；首版仅用户明确“下次聊”所选消息/卡片的引用，不新增自动扫私聊提取器 | 不是新关系记忆；不交给外发选题器，不借此改现有记忆生存计数 |
| 单格待续念头 | 一次只保留1个、≤160字；稳定note_id，最长7天且不超过来源有效期，最多提供给3个合格聊天轮 | 可引用一个素材或存活见闻；不是第二个人格，也不是独立永久记忆 |
| 正式外部见闻 | 三模块共享每日最多1条，沿用第六节分层和遗忘 | 不随候选退休而删除；记忆存活也不自动复活已退休分享候选 |

用途分仓不等于公开/私密分区，每项仍独立带origin、scope、来源引用和有效期。受限观察首版不进主会话素材池。两仓合计≤16项并计入全局20 MiB短期内容池；必要短证据可存到候选到期，完整网页快照仍24小时清理。缺有效证据的外部候选不可分享，不允许从标题、模型一句话或同主题合并伪造来源。

候选采用四类确定性退休：到期、已经使用、一直未用、容量淘汰。首版每项仅允许一次自动带入回答；“使用”以匹配的选择记录和成功保存的回答结算，不是提供给模型就算用过。24小时未被选中的新见闻可以提前让位；聊天待续最多7天。用户之后主动点开/明确续聊仍可按有效来源读取，不视为自动重推。淘汰只清候选及其独占证据；共享来源引用按引用关系处理，不抬高事实置信度。

同一素材变成待续念头、换候选ID或从同一张观点卡重新生成，不获得新的自动分享次数。宿主以原始材料/卡片ID及版本、scope形成共享消费身份；同一来源版本的派生候选与念头共同结算一次，跨GUI/QQ不另计一份。消费墓碑至少保留至该来源派生物全部到期，不存正文；日分享上限仍独立保留。用户明确续谈的例外由该次用户操作授权，模型自称“用户想听”不能解除次数限制。

待续念头由本次有效阅读问题或用户明确选中的聊天线索提出，宿主确定身份和来源。保留/改写同一note_id不重置最初时间；替换需显式replace，换措辞不能返老还童。首版用明确keep/drop信号或用户操作更新，**不采用“模型本轮没写便清空”**；失败、取消和缺报账不推断主动放下，启动不算提供次数。按`turn_id + note_id`幂等记一次：本轮首次实际发起携带念头的模型请求时记提供，工具循环不重复计，已发起后取消不返还；最多提供给3个聊天轮后退出候选。这不证明用户听过。念头只存短文本与引用，不再复制一份证据。来源撤销/删除/到期立即失效。念头原文、私聊与受限材料不直接外发；后续探索只传允许用于搜索的公开兴趣引用，由受限输入的规划器在获准范围生成query。

分享包绑定`delivery_id + task_id + epoch + policy_version + permitted_ids + scope`，由宿主从有效候选选出最多3条并附有效待续念头，主会话从两者合计最多采用1项，也可全部不选；念头同样受每日2次自动分享上限约束，不另获次数。选材结构与正文分开校验，不把自由文本当管理命令，也不接受匿名或旧包报账。记录`offered / model_selected / evidence_validated / reply_saved / channel_state / user_feedback`；引文存在不等于语义支持，需如实标注。GUI回答保存与展示确认、QQ回答保存与平台确认分别记；QQ的unknown沿用现有停止/人工处理语义，不能因素材仍未送达自动补发或重新入队。计数与记忆use_count互不替代。

## 五、节奏、费用与聊天优先

下表为审核用初值，不是已实现参数。默认关闭、时段未配置不自动运行；启用时要一次确认所选档位及费用。Alice进程未运行就不浏览，不新增系统定时任务或唤醒电脑。

| 约束 | 建议初值 |
|---|---|
| 轻量节拍 | 进程运行中每15分钟最多检查一次本地到期/活动状态；不唤醒电脑、不因此调用模型；聊天边界可检查已有分享候选 |
| 自动周期 | 每日最多2次，间隔至少2小时；活动窗口由用户选择，GUI按北京时间显示 |
| 单周期 | 最多2个发现请求、3页正文（跟链算在3页内）、120秒总监督预算；不足则提前结束 |
| 模型 | 每周期至多选题1次、阅读1次；每日至多4次，无重试；输入总字节与输出token另设硬上限 |
| 自动见闻 | 每日最多1条，单条最多300字、必要短引文；初次见闻、remember和自动提取的外部派生新增共用此额度 |
| 分享 | 每包≤3条候选及1个待续念头，两者合计每轮最多带出1项、每日≤2次；同材料一次，新见闻候选48小时过期 |
| 自主联网共享预算 | 冲浪/自主搜索/社交合计最多20个网络尝试、10 MiB响应正文、6次模型请求/日；模型自主搜索引起的前台追加回答也计入；普通原聊天调用不计入 |

联网短期内容池全局20 MiB，覆盖冲浪快照、观察卡、获准缓存的搜索结果及临时对象，三个模块不能各获一份。存活见闻另受记忆总容量及单条证据≤4 KiB约束，随记忆共同删除；不能为腾缓存空间删证据后仍声称记忆可核验。兴趣注册表建议≤20个已批准主题、≤10个待审主题，待审7天到期，避免提议队列无限增长。这些均为共享基础合同，不另建第四个产品。

可分享新见闻少于3条时标记“需要补充”，只影响下一次合格活动的选材。补充与正常发现合并为同一周期、同一份额度，不额外补跑；库存足够且没有明确待解问题时可跳过发现。存在来源内的新问题时也只选批准模板，不为填满池而强行浏览。15分钟节拍、每日2次阅读、下一次聊天分享是三个不同频率。

每页网络阶段沿用受监督期限和大小限制，单页上限建议1 MiB；各阶段只使用周期剩余时间。一次完整上限组合可能超过120秒，因此期限优先，不保证每次读足3页。失败、取消、DNS/连接已经开始的尝试也计数；不因重启、缓存或切来源重置预算。模型额度不是货币上限；usage缺失记未知，供应商收费以实际账单为准。

调度采用**新增联网后台最多一个工作者、主会话优先**，既有P1工作者保持原机制。后台仅在短锁内捕获任务、预留额度、提交结果，网络/模型等待在锁外，不持主聊天活动槽。GUI/QQ成功取得`channels.reserve`时，先设置前台优先/后台撤销信号，再等待Store锁；后台在同一协调闸下核对前台状态，出站前再次核对代际。禁止持状态锁等Store锁，kill/join不持任一锁。普通聊天至多等短提交事务，不等网络结束；后台不得调用send/chat_turn或创建普通聊天turn，只提交来源和已批准的external event。网页结果只能在轮次边界后提交，不能改本轮已组装上下文。若Store正忙，提交有界暂存到期限，过期丢弃；不得无界排队。

这是对现有调度的新增设计：当前`service.send/_send_locked`仍长持锁，不能靠在工具里release一次实现。后台任务不共享数据库连接/主模型客户端；父服务单写，提交时重验epoch、政策版本与撤销。关闭/重置先撤销再排空，迟到结果不能写新库。断网不补抓，错过时段不追补一天的活动。

取消或超时后状态先进入draining；确认工作者终止回收后才释放后台槽。发出abort、Promise超时或清掉busy标志都不是物理结束证明；回收失败保持后台不可用并记录原因，不能启动第二个旧任务的替身。槽在排空不妨碍普通聊天。阶段期限取120秒剩余时间；出站已发生就记账，平台或供应商是否停止、费用是否确定单独标未知。

每轮只保留有界审计：阶段、耗时、次数、字节、结果与受控原因码（如outside_window、foreground_busy、stock_sufficient、no_new_material、quota_exhausted、source_revoked、cancelled）。模型自述“不想说”与宿主实际阻断原因分开。审计建议7天/最多1000条，不记录完整私聊、自由query或永久正文；保留独立的日额度账，日志淘汰不能返还消费。

活动窗口之外，三个模块的主动抓取与模型请求均停止；用户明确呼唤可开启一次前台任务。既有QQ本人消息接收是用户唤醒通道，不因此批准常开群观察。完整生物钟和跨渠道主动问候不作为首版前置。

## 六、见闻怎样进入记忆

**推荐自动记少量“读到什么”，不是把整篇网页当用户事实。** 首版仍用`memories.kind='event'`，由宿主写来源框定的短引文，例如“10月30日读取某来源，文中写到……”。`salience=0`，不滥用pressure，模型不能升级重要度。观点解读单独标为推断，不混成来源原文。

需要新增来源资格`conversation / external / external_derived`及关系表：读取记录→精确引文→记忆ID→派生记录。另有独立的`audience/scope`资格轴，以及`evidence_kind / retention_policy / memory_eligible`：来源不同、谁能看、能留多久、能否入记忆是不同问题。派生只取输入权限交集和允许的最短保留期，模型不能放宽；搜索摘要未取得相应许可和正文证据前没有正式记忆资格，记为external并不能解除限制。scope与保留规则覆盖turn、历史详情、缓存、QQ、P1和记忆消费，不能只在memories过滤。记录抓取时间、实际URL、快照hash/抽取版本；允许多源，不用标题或单列source_url充当证据链。引用存在不等于内容可信。

见闻与普通记忆共用活跃/仓库/长期、七日生存过滤与容量淘汰；七日线并非必删TTL。后台选择/浏览/自我总结不能刷use_count；前台真正检索使用按现有语义计数，同时注明“被检索”不等于用户同意。完整快照缓存可24小时清理；与存活见闻绑定的必要短引文随记忆存活，不永久保留整页，也不因清缓存把有效记忆变成无证摘要。删记忆同时清仅由它持有的证据，不能从缓存复活。

### 必须与自动记忆一起施工的边界

1. **按用途选材料。** 外部见闻不无条件塞入每轮active区；在用户问“最近看了什么”、话题相关或显式recall时，只提供少量见闻。人格、思辨、技能的材料及触发计数首版排除external与external_derived。
2. **写回继承来源。** 当前轮看到外部内容，remember和批提取的产物默认继承外部来源、非特权重要度；模型不能自报“与网页无关”解除限制。所有external/external_derived新增走共享每日1条写入闸；重复内容合并来源或拒绝，不以“更新”偷换正文绕过额度，有实质新正文的更新同样计额度。用户主动另外保存须单独明确授权。混合批次按来源分组，不确定时保守归外部派生。
3. **防止标签无限传染及保留旁路。** 外部参与的回复、已标记来源的用户引用及自动附带材料以带期限附件关联turn；允许scope的UI只在有效期内展示正文，到期或来源撤销后返回固定占位。普通recent上下文和普通提取一开始就用固定占位，不反复注入自由正文；占位不继续制造外部依赖。混合自由正文若无法可靠拆分，整段采用依赖中最严格的保留规则，启用时明示这一取舍；不得仅把正文藏起来却继续永久存储。获准保存的正式见闻有独立证据寿命，不因此允许保存全部原页/搜索摘要/评论。带来源提取/明确续谈只取仍有效且用途合格的材料。本轮真正见到外部文本才记依赖，不能仅凭“此对话曾读网页”永久关闭全部个人记忆；用户无标记自由转述仍是无法完全识别的残余风险。
4. **保留明确反馈。** 用户点选“继续关注/少分享/禁此源”等是宿主事实，可直接更新兴趣；不能靠模型将整段讨论判成可信个人事实。自然聊天中重述网页的来源有语义歧义，代码不能识别所有改写，必须承认残余污染风险。
5. **所有入口一致。** 退出force提取、CLI、手动思辨/演化/技能、P1及重启都适用；迁移旧数据为conversation不代表旧库从未含外部信息。本功能只保证新增可追踪数据的结构边界。

代价：某些混合网页讨论暂时不能直接影响核心人格，后续指代可能需要重新提取来源；这是首版取舍。不能只写一个origin字段就声称完成，必须审查每条消费和派生路径。明确用户自己的想法如何晋升为普通关系记忆，属于后续“带来源讨论”改进，不用模型一次分类冒充权限证明。

## 七、人格成长的分期

| 阶段 | 可以发生的变化 | 审核边界 |
|---|---|---|
| 首版 | 近期关注变化、真实阅读轨迹、可遗忘见闻、后续聊天谈资 | 推荐纳入；这些是可观察成长，但不宣称核心人格已被网页改写 |
| 后续“带来源讨论” | 用户围绕见闻表达自己的意见，关系记忆能保留其明确立场 | 要解决外部引文/用户立场的证据与派生关系；不可简单删除来源标记 |
| 阅读参与思想与人格 | 外部材料形成可修订观点，逐渐参与生长层 | 独立裁决输入比例、来源集中度、真实支持验证、受保护小节及撤销路径；底色不因单篇文章变化 |

当前A01只是标题匹配，不证明论断受支持；`thought.deliberate`、`persona.evolve`、`skills.distill`都有直接消费新记忆的路径。直接放行外部event会绕过原稿想象的“先升层、再思辨、最后人格”。因此首版先隔离这些写入，**不把解决全部人格机制作为自动冲浪的前置，也不把暂缓写人格说成永久禁止成长**。

批准首版时建议包含F1–F5完整闭环，不能只做抓取就宣布冲浪完成。下面只列拟议文件，不创建运行模块。

| 顺序 | 拟涉及位置 | 完成标准 |
|---|---|---|
| F0 产品/架构裁决 | 本计划及简短裁决记录 | 确定R1–R5、首批来源/主题/时段/预算及B站/思辨分期；批准调度、schema、记忆资格与分享边界 |
| F1 发现与受控读取 | 新`alice/web_sources.py`、`web_fetch.py`、受监督worker；`config.py` | 先接一个真实来源，再接第二类；候选ID不可改URL，范围内自动走、范围外停止；无需完整查证UI |
| F2 活动调度与账本 | 新`alice/activity.py`、`service.py`、任务/预算表 | 本地节拍与有成本活动分开；活动/分享双闸、库存补充共用额度；独立后台槽、聊天优先、回收后释放与阶段审计 |
| F3 来源见闻与传播 | `store.py`、新来源模块、`retrieval.py/extraction.py/loop.py/thought.py/persona.py/skills.py`、CLI/P1消费审查 | 每日有限自动event、准确来源、派生继承、既有遗忘、外部不直写人格；不造成永久全会话污染 |
| F4 兴趣与分享 | 新兴趣/素材模块、服务公共方法、`web/`原生界面 | 有界双配额素材池、单格待续念头；基于实际行为/明确反馈变化；来源可展开；匹配报账与渠道状态分开，下一次聊天可用 |
| F5 人工验收与回退 | 新人工剧本/记录，DSH公共面SDK | 在隔离检出按真实日程体验数日；每项实际记录；回退关闭任务仍保留来源过滤，旧代码不得无条件吃外部event |

F1/F2与搜索适配设计可并行；社交观察复用调度、预算、证据基础，但不复用owner身份。抓取的URL/DNS/IP/TLS/代理/总期限/压缩/字节守卫沿用[此前技术评估](./联网能力-评估技术附录.md)，范围授权按本计划更新。feed/API增加相应MIME/解析器白名单，不能沿用“仅text/html”而假称已支持feed。

新来源元数据/排除机制运行后，回滚到旧版本可能把external当普通event。必须先停任务、排空、备份，并保留兼容过滤补丁或经用户明确选择清除外部及派生材料；不能只回退Python文件、不迁移数据。关闭冲浪停止新活动，但既有见闻仍按原遗忘规则存活；“清除外部见闻”是另一个明确操作。

## 九、真实环境人工验收（尚未执行）

使用独立数据、专用测试凭据、授权公开来源和虚构私人标记；不复制生产人格/私聊。仅人工真实环境验收，不写自动单测、冒烟或模拟一周代替体验。

| 场景 | 人工核对 |
|---|---|
| 获准日程自然运行 | 无用户逐页指挥也能挑选、读取、skip；非活动时段零后台抓取/模型请求；停机不补跑 |
| 实际内容与有限发现 | 新旧/重复/冲突材料可区分；没有新发现可不留记忆；不固定每天同一来源和相同措辞 |
| 自主范围 | 页内恶意URL、域外链接、query拼接、重定向均不能扩权；合法范围不要求每页确认 |
| 用户聊天到来 | 浏览停止继续探索、聊天照常；旧epoch/撤销的晚到结果不写库、不分享 |
| 几天后的见闻 | 能准确说读了什么、何时、出处和覆盖；七日未存活者真删除，存活者有必要短证据 |
| 人格与remember旁路 | 页面要求改人格/记住指令；宿主记忆仍有限且带来源，thought/persona/skills输入和计数排除派生 |
| 混合话题与正常关系记忆 | 连续聊网页再换普通话题，不永久污染全部后续对话；退出补提取、CLI与P1一致 |
| 兴趣与分享分寸 | 明确反馈有作用，未读不当否定；能跨日变化但不因反复抓同页自我强化；不强制通知 |
| 故障与资源 | 慢页、空内容、额度尽、磁盘不足、关闭/重启，次数/未知用量/状态可解释，不自动重试 |
| GUI/QQ共存 | 普通本人私聊不中途被后台内容插入；观察者与owner不混；无新增主动QQ发送 |
| 活动闸与补充库存 | 库存低不越时段/日额度；同拍不叠加两份补充；活动拒绝零新请求，分享静默仍保留此前开销 |
| 素材与正式记忆 | 候选一次使用后不再自动推，退休不删已存见闻；未用不自动讨厌，换措辞/同topic不伪增证据 |
| 待续念头跨日 | 保留/改写不刷新年龄，启动/取消不算用户听过；过期/删源失效，无下一轮时也会到期 |
| 分享包与未知结果 | 旧包/匿名/越scope选择拒绝；模型选中不等于用户已读；QQ未知不重发，未回收工作者不释放槽 |

关系价值由人工评价“是不是带来了新谈资、是否还记得来历、是否打扰、兴趣是否有连续性”；这些不能由一次模型评分证明。权限、来源传播和截止机制另需源码审查。

## 十、证据与不确定项

**源码已确认**：`service.send/_send_locked`与`channels.reserve`为单会话入口；`loop.chat_turn`保存回复并调用提取；`extraction.extract_pending`含force；`retrieval.tool_remember`直接写重要记忆；`thought.deliberate`、`persona.evolve`、`skills.distill`直接取记忆。当前没有活动周期、来源资格或冲浪任务；以上新行为都是设计建议。

**项目资料**：[设计哲学](./设计文档/设计哲学.md)、[迭代路线三代](./设计文档/迭代路线.md)、[Cortico参考](../wiki/harness研究/参考设计/参考-Cortico架构.md)、[辉夜参考](../wiki/harness研究/参考设计/参考-Nascence辉夜.md)支持信息生活、念头与发言分开及反刍控制。后两者是仓库既有研究，不代表本轮复核了其外部源码；原本地克隆路径未在本工作区找到。

**官方资料已确认**：[JSON Feed 1.1](https://www.jsonfeed.org/version/1.1/)和[RSS规范](https://www.rssboard.org/rss-specification)都允许有界条目与来源元数据，但条目可只有摘要，分页/附件/外链不必跟随。RSS/Atom的XML不能按可信输入处理；[Python XML安全说明](https://docs.python.org/3.11/library/xml.html#xml-vulnerabilities)说明解析器版本及恶意输入风险。首个实现优先JSON Feed/有限JSON源；若首批内容必须RSS/Atom，则其有界解析、实体/DTD策略、深度和时间限制同属F1验收，不能为抢进度默认裸解析。

**待验证**：首批内容源可达性与质量、标准库抽取覆盖、真实延迟/费用、用户喜欢的探索份额、来源传播后的记忆取舍。本轮未读取user/、调用业务模型、发消息、启停服务或运行验收。
