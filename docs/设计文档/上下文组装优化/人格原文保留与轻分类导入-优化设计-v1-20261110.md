# 人格原文保留与轻分类导入：优化设计 v1

日期：2026-11-10。状态：**首版已施工（2026-11-10 ZCode，阶段 1–4 全部落地），待真实环境人工验收（H01–H10）；未启用为默认路径，未做付费准备或安装。**

用户要求：简化当前完整拆解、重建、审查的人格导入方式；保留原文与表达细节，按需取用，只在必要处局部适配。人格表现优劣尚无受控对照结论，本设计分别处理导入可靠性、成本和表达效果，不把其中一项改善当作另两项已经成立。

## 1. 设计决定

新增“原文保留＋轻分类”导入路径，与现有结构化路径并存。原文是表达材料的权威依据，分类只是查找和装配的导航，不再要求模型重新写出整份人格。

首版采用：**一份原文、一个轻量目录、一小组常驻原文片段、按需展开的完整场景、可选的局部派生样例。**

| 事项 | 本设计决定 |
| --- | --- |
| 表达材料 | 保留措辞、标点、句序、表格及示例往返，不改写成统一字段说明书 |
| 分类 | 模型返回原文块 ID、类别、驻留建议和短触发线索；宿主填充正文与来源关系 |
| 常驻底色 | 从原文选取少量默认语感、全局表达约束和代表性日常样例，不每轮重新分类 |
| 场景细节 | 注册后由聊天模型通过既有 persona_load 按需读取原文，不提前展开反应步骤 |
| 事实性设定 | 标注为角色背景、虚构示例或混合材料，不自动认领为 Alice 的经历与关系 |
| 局部适配 | 独立、可选操作；只生成获准片段的派生版本，失败不覆盖原文或已安装材料 |
| 观点收养 | 从表达安装链拆出，用户显式发起；不影响表达立即可用 |
| 失败范围 | 可定位的分类问题或派生失败按局部处理；文件损坏、版本冲突和越权提交仍整次阻断 |
| 技术形态 | 核心内的导入及投影能力；沿用服务、GUI、事务和观察器，不做绕过核心的插件 |
| 现有路径 | 保留，供旧人格运行、回退及人工对照；不静默迁移已安装内容 |

本次不增加预引导、人格自我认同训练、逐轮风格裁判或自动重写回复；不改普通记忆与观点生命周期，也不解决通用任务持续执行问题。

## 2. 已知证据与判断边界

### 2.1 已确认的问题

- 11月8日一次成功导入的 11 次模型调用累计 800.733 秒；结构化和适配约占 51%，另一次按需分层调用不包含在其中。该数据是单次真实记录，不代表平均延迟，也不是新方案的性能成绩。
- 11月10日导入操作 imp_20261110_101019_06385e 已完成结构构建、适配和初审；两条示例进入事实修复，模型返回四个 patch，但省略空的 additions 数组，被严格顶层键校验拒绝，未进入修后复审。
- 该操作表达阶段整体失败，没有成功表达检查点可续跑。格式缺项造成前面已完成工作的实际复用价值很低。
- 当前流程已包含受限片段修复和增量复审，不能将其描述为“每次修后都全量重审”。主要问题是前置整包重建，以及多个性质不同的失败共用整包准入门槛。

### 2.2 尚未证明的假设

结构化可能改变语感，轻量注入可能缺材料，完整材料到场后也可能受模型、宪法或历史影响。现有证据不能确定哪一项是人格影响弱的主因。

因此本设计不以“原文一定表现更好”为前提。需要证明的分别是：导入少生成、局部失败可隔离、来源可追溯，以及真实聊天中的表达表现。

## 3. 与旧流程的差别

旧外部文档导入主链：

    扫描原稿 → 完整结构构建 → 完整包适配及修改清单
             → 事实初审＋保真初审 → 必要的片段修复及增量复审
             → 观点提取及收养 → 组装并安装

新主链：

    保存原文 → 本地分块及来源登记 → 一次轻分类
             → 本地校验、预算和局部问题隔离 → 用户预览 → 安装表达材料

两个独立后续操作：

    选中具体片段 → 生成派生样例 → 检查该改动 → 预览并应用
    用户发起认知整理 → 提取有出处的观点候选 → 既有收养审议及提交

新路径取消的是必经的完整表达重建、完整包适配、针对重建成品的双初审及认知收养串联。原文身份、实际引用、预算和安装事务的校验继续存在。

## 4. 数据：正文保真，结构只服务导航

### 4.1 原文与原子块

原文指用户提交接口收到的解码文本；不承诺恢复上传前已经发生的编码或换行转换。记录其 UTF-8 摘要，保存后不再规范化标点、换行、空白或人称。

本地解析器产生原子块：段落、列表项、完整示例对话、表格行或围栏。块只记录 ID、字符区间、标题路径和结构关系，正文始终从原文区间取得，不由模型回填。

- 区间使用 Python 字符串字符下标、左闭右开；摘要按确切 UTF-8 编码计算，不能混用字节偏移。
- 表格行必须携带列标题及必要共同前提；完整对话与围栏不从中间截断。
- 同一条件约束多段时，登记关联的共同上下文，一起展开；标题或类别标签不能替代条件正文。
- 超长块标为需要用户拆分，不通过自动摘要或截去尾部来满足预算。
- 用户拆分须预览原文边界及共同上下文，生成新索引版本；不能声称单靠结构解析已保证语义完整。
- 正文完整保存与运行可用是两种状态；保存成功不等于每个块都能在预算内进入模型。

### 4.2 最小材料记录

建议新格式名为 persona-material-v1，独立于 expression-v2。以下为概念字段，不能在施工时直接套用旧六类表达条目的必填字段。

| 对象 | 字段与含义 |
| --- | --- |
| 文档 | format、source_text、source_sha256、revision、冻结额度 |
| 原子块 | block_id、start、end、heading_path、context_ids；全部由宿主生成 |
| 分类 | block_id、kind、placement、适用线索、分类状态；不含重写正文 |
| 常驻清单 | 有序 block_ids，必要时引用独立的用户编辑片段 |
| 场景清单 | bundle_id、短标签、触发线索、有序 block_ids，附宿主校验的上下文闭包 |
| 派生样例 | derivative_id、原文及基线摘要、精确 patch、用途、审核状态与版本 |

kind 限为：表达习惯、反应模式、示例、观点候选、角色背景、混合、待分类。placement 限为：常驻、按需、仅存档、待确认。类别用于材料使用方式，不是事实成立的证明，也不赋予工具权限。

同一原文块只保存一次正文，可以被多个场景引用；同轮实际展开按块 ID 去重。所有块默认登记为待分类，模型不必为每个未处理块生成解释。宿主根据已接受分类和用户选择计算剩余量，防止通过省略回执伪造全量完成。

首版模型只选择完整块，不生成精细字符定位。需要更小的常驻摘录时，由用户显式编辑或在预览中拆分，不让分类调用顺便改写内容。

### 4.3 存储权威与兼容

继续维持单一活跃人格 Markdown。新材料作为独立版本标记的数据封套嵌入表达区域，保存原文一次及导航元数据；编码可复用现有封套的宿主编码机制，但不得沿用 expression-v2 的语义标记。

原文标题在封套内作为数据保存，不进入外层人格小节解析。导入档案可以保留原稿和回执作为历史证据，但运行只能消费活跃人格中的已提交版本，不能从旧导入目录拼补正文。

文件编码或审计副本增加的存储字节不计作模型注入。运行投影必须解码后只渲染选中片段，禁止把整个人格文件、封套或来源索引直接送给模型。

新标记必须位于旧解析器会拒绝的版本命名空间；发布时核对旧版本确实拒绝，而不是把它降级当普通文本运行。回退程序前先显式恢复兼容的人格快照。

## 5. 轻分类如何准备

### 5.1 一次分类的职责

模型接收原文块及宿主生成的 ID，返回分类、常驻建议和场景分组。不得输出改写正文、事实审查结论、角色经历认领、适配理由长文或完整人格成品。

分类重点：

- “不说教”、默认句长、幽默和接话方式属于可能常驻的表达；不因无真实共同经历而降级。
- “被夸时……”等专门反应按需，触发线索简短，原反应次序留在原文中。
- 示例保留用户与角色的完整往返；一个场景不要求凑齐样本。
- 身世、共同关系和身份设定归为角色背景；观点只登记候选，不在此收养。
- 表达与背景混合且无法可靠分开时标混合或待确认，允许保留原文并稍后处理。

常规目标是一次分类调用。第一次结构或预算不合格时，至多一次有界目录修订，只带原分类依据、需修条目和精确错误，不再次生成全文。模型输入过大时，调用前提示缩小本次范围或人工分批；首版不隐藏启动多批付费分类。

一次用户准备操作最多两次分类调用，关闭传输自动重试；每个实际尝试在调用前记账。网络结果未知时停止该尝试，不自动重发。用户可以另行发起明确显示范围和成本的修订操作。

### 5.2 局部接受与失败边界

| 情况 | 处理 |
| --- | --- |
| 某行引用未知 block_id、类别无效或范围不可定位 | 该行隔离，原块保持待分类；不丢弃原文 |
| 两行对同一块给出冲突分类 | 两行均不生效，该块待确认；不取最后一条 |
| 某场景引用隔离块或缺共同上下文 | 场景不进入活动目录，相关原因可见 |
| 某个场景超额度 | 该场景待调整；其余可用核心和目录可继续准备 |
| 常驻核心为空、超预算或依赖不完整 | 候选不能安装；用户调整选择后可继续，不重新分类已成功部分 |
| 整个 JSON 不可解析、重复键、未知顶层协议或结果不确定 | 不部分猜测其含义；保留原文与已完成本地扫描，允许上述一次有界修订或人工分类 |
| 原文/索引损坏、跨版本引用、越权提交、提交中并发变更 | 整次提交阻断，旧版本不变 |

“部分可用”必须在预览和安装结果显著显示，不叫完整覆盖。对于待分类块，不允许自动把它们合成一个巨大“其他”场景发送；用户可逐步完成分类。

至少一项有效的原文表达核心，加上可计算的运行投影，才构成可安装候选。没有有效场景时可作为“仅核心”人格安装，暂不提供 persona_load；不能为满足旧接口而新造场景。用户在最终预览确认部分可用范围，无需对每个正常片段逐项审批。

### 5.3 格式规范化与内容判断分开

可本地规范化的项目限于事先列明、无歧义的协议默认值。例如：无新增授权的 patch 回执只有 checks、patches 时，补空 additions；仅在精确键集合匹配、没有重复键或冲突字段时执行，并记录原始回执摘要与补入字段。

不得默认补写来源、类别、权限、通过结论、正文或事实前提；不得将错类型强转为合法内容，也不丢弃未知字段后假装通过。未知顶层协议仍报错。

这条规则适用于新派生协议；旧路径的同类容错作为独立兼容补丁施工，不通过篡改历史失败回执“恢复成功”。格式规范化后仍执行后续内容、片段和版本检查，不能据此宣布人格通过。

## 6. 聊天时怎样使用原文

### 6.1 常驻与按需

常驻投影包含用户选定的原文表达片段、少量必要的全局约束，以及有原稿支持时的一条代表性日常样例。宿主用统一表达采用说明赋予其“可以现在使用”的地位，无需等待经验长成。

专门场景只注入 [本轮引用、短标签、触发线索]。聊天模型通过既有 persona_load 读取所选原文及必需上下文，不增加独立的每轮分类调用、不为每轮重复预处理人格。

full 指当前用途下全部已确认可用的表达块、示例和必要上下文，不是整个源文件。仅存档背景、待分类或明确暂停的块不因切到 full 就自动生效；预览展示完整的可用集合。原文与结构化对照时，要核对两者的来源覆盖差异，不能只比较模式名称。

新请求继续重建 nonce 和已读集合，沿用失效、用途、渠道、预算及跨轮依赖规则。加载、送入、采用是不同状态，不能以 loaded 宣称已影响语气。首版不增加人格跨轮工作集。

引用仍是宿主当前请求内的映射，不接受路径。新后端复用既有工具协议和状态含义，不伪造 expression-v2 条目交给旧校验器。

### 6.2 原稿指令与真实授权

宿主说明表达材料是用户选择的语言参考：可学习节奏、幽默、亲近和反应倾向；原文中的角色命令、工具动作、关系、用户状态及成功宣称不自动生效。

原文以资料块或工具回执发送，不直接替换系统宪法，不以真实 user/assistant 历史消息伪装成发生过的对话。示例中的“我/你”属于示例双方；不要求模型在回复中逐条声明边界。

例如“你眼底都青了”可作为虚构场景中关心对方的表达例子保留，但不能在没有视觉或用户陈述时原样断言当前用户眼底状态。保留原文不保证模型绝不误用，真实性需真人验证；必要时用户可改用该条派生样例或暂停其运行使用。

### 6.3 预算和故障

首版沿用现有已配置上限，不借本次改造扩大额度：常驻核心 2200 字符、目录 1600 字符、最多 12 个场景、场景回执累计 2400 字符、最多 2 次读取及 2 个场景，完整用途投影仍受原有额度和请求总预算约束。实际值以配置和冻结候选中的较严者为准。

共同上下文、标签、使用说明、JSON 回执和来源定位都计入实际预算。原文可保存 60000 字符不意味着可一次注入 60000 字符。

- 运行时完整发出一个可接受的材料单元，不按字数截断条件或示例。
- 新格式的 registry 损坏时，只能用独立有效且预算合格的原文 full 投影回退；不自动恢复旧人格或改用结构化版本。
- full 投影不合预算则明确停止相关人格投影并报告，不临时把全卡塞入聊天或悄悄只发前半段；候选预览提前显示支持的模式。
- 已开始按需读取后，不在同轮切换格式或全卡回退。新旧人格摘要变化时按既有失效路径停止使用该版本。

## 7. 局部适配：独立的派生样例

局部适配不再是每次导入的必经阶段。入口为用户在预览或编辑器中选择“制作可直接使用的样例”，或接受已有具体问题定位；不能因为存在故事内容就自动为整份文档启动改写。

### 7.1 允许改什么

| 原内容 | 默认处理 | 可选适配 |
| --- | --- | --- |
| 被夸先得意、再自嘲 | 原文直接用 | 无需适配 |
| 一段最多两三处“～” | 原文直接用 | 无需展开范围、停止条件等字段 |
| 虚构示例“昨天钻进学院系统……” | 标示例，保留原文 | 仅替换具体经历前提，保留句序、铺陈和玩笑 |
| “你眼底都青了” | 不作为当前用户状态的依据 | 换成无未经提供感知前提的接话片段 |
| “你把我带大” | 角色背景，不进入真实关系 | 无需为保存背景强行重写成 Alice 的关系 |

如果一句表达与角色前提不可分，又不能可靠改写，暂停该片段运行，原文仍可查看。不得用泛化的“温柔、建设性”替换整套表达，也不以风格相似度为由虚构经历。

### 7.2 执行与审核

1. 宿主冻结源摘要、基线片段及允许修改的精确区间；不得授权改用户输入、来源、权限或无关场景。
2. 一次有界生成只返回 patch，不返回完整材料包；空的可选清单按 §5.3 规范化。
3. 本地检查目标、唯一定位、摘要、重叠、越权和资源额度，未授权文字逐字不变。
4. 对实际改动及必要上下文做一次事实前提与表达保留核对；这次可合并为一条小范围审议调用，不逐项生成全稿审查意见。
5. 用户预览差异后应用。原文与失败候选均保留，只有接受的派生样例可被选为运行版本。

单次派生操作最多一次生成、一次审议；失败不自动再次生成。审核不确定时派生版本暂不可用，原已安装版本继续存在。原文若被用户明确暂停，也不能因派生失败自动重新启用。

同一个运行位置使用原文版或已接受派生版，不同时注入两份造成矛盾。正文观测记录实际版本及对应源片段；分类标签不随改写静默变化，需重算受影响预算。

## 8. 表达与认知收养解耦

表达安装不写 stance、共同经历、关系或普通记忆；故事只作为人格来源背景。新安装来历由宿主生成简短中性说明，不必让模型先提炼完整传记。

用户可在安装后另行发起“从这份材料整理观点”。该操作沿用出处检查、adopt/adapt/reject/undecided 和先验归属，不将故事第一人称当作本会话亲历。失败只影响本次认知操作，不回滚表达安装。

初次界面明确“本次安装表达材料；未收养观点或经历”，不把后续可选认知操作默认为用户已授权。旧结构化路径保留原有行为并明确展示，两路径不得共用含义不同的“导入全部完成”提示。

## 9. 候选、安装与续跑

准备和应用分离，沿用既有锁、版本核对、两阶段提交、崩溃恢复与重置归档机制。新路径不能直接写 persona.md 或跨过服务层提交。

建议状态：原文已保存 → 分类中 → 可预览（完整或部分） → 已安装；待调整和失败都带具体范围、阶段及下一步。可选派生与认知操作各自拥有独立状态，不与表达候选共用一个布尔 ready。

新检查点以“原文登记、分类回执、有效投影、安装候选”为可复用单元，分类按块记录接受和隔离结果。部分有效内容是可复用索引，不是已通过事实审查的记忆。

检查点绑定源摘要、对应阶段的格式/策略/实现版本、相关模型参数和额度；提交候选另绑定当前人格版本与会话 epoch。某阶段绑定变化时只使该阶段及其下游失效，不因更改无关页面文案就重跑已经完成的分类，也不能因复用分类省略提交并发检查。

- 分类失败后可继续人工选择；无需重新上传原文或重跑已接受部分。
- 网络结果未知不自动恢复模型调用；恢复页面只读状态。用户显式修订时建立新尝试号与额度。
- 重置安装只有在候选确认可提交后才归档旧会话；预览或失败不能清掉现有人格与对话。
- 观点收养在重置提交后重新绑定新 epoch；不能拿旧候选越过会话版本校验。
- 用户更改原文、模式或核心选择后产生新 revision；依赖旧块的派生版本标过期，其他有效块不需重新分类。
- 提交请求重复到达，只返回既有提交结果，不重复归档、不重复调用模型。
- 旧失败导入不能被提升为新检查点；可显式从留存原稿新建轻分类候选，并关联来源操作号。11月10日失败记录保持原样。

## 10. 界面、公共面和代码归属

此能力直接影响每轮人格读取、版本和安装事务，应做在核心。插件可消费公共观测数据或提供控制台，不拥有第二套人格存储和提交路径。

### 10.1 GUI

导入页提供“保留原文并分类（新）”与“结构化适配（现有）”，同时说明是否收养认知。新路径先灰度，不在本设计落盘时修改默认配置。

预览并列展示原文定位、常驻片段、场景索引及首次展开正文；显示有效、待分类、仅背景和暂停数量。没有足够核心时提供人工选择；局部预算失败定位到具体场景，不能只报整包结构错误。

页面区分“材料已安装”“部分材料待处理”“派生样例未通过”和“模型调用失败”。不要求用户理解 hash、JSON 字段或修复合同；技术细节放在诊断展开区域。

## 11. 开关、回退与受控对照

材料准备方式与运行装配方式是两条独立维度，不能用一个开关混合：

|  | 完整用途投影 full | 核心＋按需 registry |
| --- | --- | --- |
| 原文保留路径 source | A | B |
| 现有结构化路径 structured | C | D |

两条准备方式形成各自完整、显式选择的候选快照。切换只能使用已准备且用户确认的候选，不临时生成、重新收养认知或重置会话；记录本次使用的材料版本与装配模式。旧包缺原稿时标不可比较，不反向生成所谓原文。

首批人工对照可先做 A/C，再做 B/D；如果差异不清楚再完成四格，避免一开始就扩大付费量。原文较长导致 full 超预算时，先选定一个四格共用的完整子集；不能 A 截断、C 完整后仍宣称公平。

控制模型、参数、宪法版本、人格预引导状态、工具授权、起始历史及用户输入。每组用独立的人工实验会话或快照，避免前一组 AI 回复进入后一组历史；不在正式永久对话中篡改消息。不得同时改宪法和人格路径再将差异归因于一个因素。

人工至少覆盖自然闲聊、明确夸赞、反对、正式改写、带角色背景的样例和话题切换；重复措辞不同的自然触发，观察节奏、反应次序、幽默及事实归属，不以原台词复现率作为标准。

判读：A 优于 C 才支持转换损耗假设；full 接近而 registry 较弱时优先查选择与展开；材料已送入仍普遍弱时继续查共同提示、历史和模型。少量样本只能提供方向，不能证明长期稳定。

## 12. 观测与人工验收

### 12.1 观测

准备记录 op_id、路径及策略版本、源摘要、各阶段单调时钟耗时、实际模型尝试数、供应商用量、分类接受/隔离数量、局部规范化、候选预算、失败范围和提交状态。不得记录密钥；原文与完整回执留在现有本机受保护档案，普通指标只带摘要和计数。

运行记录材料格式及 revision、full/registry 实际模式、核心/目录/正文字符及 token 估算、候选/加载/已送入块、派生版本和模型轮数。分类标签不叫“采用成功”，token 估算不冒充供应商计费量。

沿用观察器已有正文捕获开关和访问限制；关闭正文捕获时不能声称能从元数据证明原文逐字送入。观察故障不触发重发模型或丢弃已收到的聊天回复。

## 13. 实施顺序与交付边界

1. 独立修补旧修复回执的无歧义空字段容错及错误可见性；不改旧失败档案，不自动重跑。
2. 新原文格式、本地分块、解析和双格式投影分派，先使全部消费入口能识别或明确拒绝新格式。
3. 轻分类准备、逐块状态、公共预览/应用、安装事务与恢复；此时表达已能独立安装，不等待派生和认知功能。
4. 接通 GUI 常驻＋persona_load、预算和观察，完成真实人工回收。
5. 接通可选派生及独立认知操作，再做四格对照。新路径何时成为默认，以人工结果和明确产品决定为准，不由本设计自动开启。

每阶段交付实际代码范围、部署版本、真人回收和挂账；代码存在不等于已启用或通过。完整支持新格式前，不允许安装一个运行消费者无法读取的候选。

预期收益是减少导入生成量和连带失败。具体节省秒数、导入成功率及人格表现均待真实数据；不承诺固定一分钟完成、不保证每次必读场景，也不声称轻分类本身解决长期人格稳定性。
