# 上下文观测器“未留存正文”原因

2026-11-11，只读核查当前配置、ctx_obs事件、meta计数与正文文件；未修改采集开关、配额、日志或会话，未模型调用、发消息或重启。

当前observer_enabled与observer_body_capture均为true，但ctx_obs_body_used=10，已达到context_observation.BODY_REQUEST_LIMIT。实际是累计采集10个用户请求，然后第11次起只留hash、长度、顺序等元数据；不是滚动保留最近10次，也不因服务重启清零。

当前会话12次真实请求：第1–10次SDK消息body均stored；第10次为11月10日18:22的6110dec5fc3a4f5c90c8e9ec3e8ee81b。18:34的90f6d5f253154aac986038988c02707e及18:35的4b08944a4906488b8bc3830c3e39182f全部SDK消息body=none，分别47与50条，故页面会出现大量未留存标记。一个用户请求可有多次模型调用及重复历史消息，不等于47或50次用户请求。

正文目录605个文件，总计1104865字节，约1.05MiB，远低于50MiB。本次停止原因是十请求额度，不是容量不足或七天过期；也不是材料没有发送给模型。“未留存”仅说明观测快照未保存正文。开启采集不能补回没有采集的完整旧快照。

附带实现问题：_body_capture_allowed在采集关闭时确有清零分支，但begin_request仅在observer_body_capture为true时调用它，仓库没有其他调用或清零位置。因此body_quota对外宣称“关闭开关即重置计数”未由实际入口落实；不要建议用户反复切配置或重启即可恢复。

后续可将策略改成有界滚动留存，或提供明确的“开始下一批10请求采集”操作；界面应给出本条是“额度用尽未采集”、关闭、过期还是写入失败的原因。本轮仅记录，未改变当前约定。
