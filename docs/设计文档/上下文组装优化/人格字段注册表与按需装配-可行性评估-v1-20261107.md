# 人格字段注册表与按需装配：可行性评估 v1

日期：2026-11-07。状态：评估与拟议契约，未施工。用户提出每轮注入persona字段注册表，由AI自行选择所需材料。本轮只读源码、当前人格与真实装配记录，未改运行代码、配置、人格或服务，未调用模型或执行机器测试。

## 结论

可行，建议采用 **核心表达习惯常驻＋有语义的场景注册表＋主模型按需读取＋宿主校验装配**。复用记忆索引的访问模式，但persona保持独立的数据语义、预算与版本约束。

不建议把所有人格都替换成ID。事实边界和用户选定的基本表达习惯应始终可用；否则一次没读取人格，就可能回到用户不喜欢的通用口吻。模型选择的是本轮需要展开的表达细节，不能选择是否遵守核心习惯、权限或停止要求。

这是对此前“完整包按用途常驻”的有意调整。保留完整来源包作为权威版本，运行时分层投影；不会为了节省上下文重新概括、删除或重导入人格。

## 本机证据

当前已安装人格与早先诊断不同，不能沿用15条的旧指标。最近成功往返的 `context_basis`（用户turn #7）记录fingerprint `8183d33292f18a1a`：

| --- | --- |
| 条目 | 4取向＋5约束＋11语感＋7张力＋7反应＋3样本，共37条 |
| 表达投影 | 5362字符，估算4165 tokens |
| 完整persona渲染 | 6120字符，估算4827 tokens，包含457字符的使用说明及其他小节 |
| 整次请求估算 | 13258 tokens，persona约占36% |
| 供应商prompt回执 | 10255 tokens，与上述本机估算口径不同，不能混算占比 |
| 选择方式 | `complete_per_purpose`，所有chat条目都进入当前请求 |

人格文件本身61266字符，其中有编码元数据；不能把文件大小当作模型实际接收的persona正文。当前负担主要是每次都给出全部chat情境和语感细节，而非把整个编码文件直接发送。

三条样本所在的可读小节总共约563字符。当前仅对样本做索引化，新增目录与工具schema可能抵消节省；优先拆分条件性张力、反应和专用语汇。

## 哪些常驻，哪些提供入口

| 内容 | 建议形态 | 理由 |
| --- | --- | --- |
| 事实、能力、许可、停止边界 | 简明常驻，由宿主保护 | 不依赖模型是否读取 |
| 基本相处取向、常用句式节奏、全局负约束 | 常驻 | 让普通闲聊无需工具也有辨识度 |
| 少量日常完整示范 | 首版保留一条常驻，数量由实际预算决定 | 继续提供回应结构示范，避免只剩抽象标签 |
| 被夸、逞强、低落、深夜、食物、战斗等专门反应 | 注册表＋按需正文 | 当前话题不一定需要，适合选择性展开 |
| 条件性张力及对应转折细节 | 简短可发现说明＋按需正文 | 不每轮主动诱发内核主题，相关时仍能取得完整行为链 |
| 更多场景样本、特定意象/台词 | 随对应场景包读取 | 避免条目脱离适用范围重复出现 |
| 人格来源、审议和覆盖审计细节 | 来源资格简明常驻，详细审计走管理流程 | 不作为闲聊每轮的长背景 |
| 生长与关系材料 | 沿用既有证据有效性和渠道投影，再独立评估索引 | 不能因并入persona目录绕过依据校验 |

“先轻后重”应如何表达取决于用户安装的包；不硬编码成所有人格都必须轻快。常驻层保留当前包真实的默认取向与限制，专门场景细节再展开。

## 注册表应让模型知道什么

按完整场景包登记，比每个句子独立编号更合适。以下只是界面/协议示意，不是已存在工具或本机新条目：

```json
{
  "ref": "persona:care@<version>:<request_nonce>",
  "kind": "expression_scene",
  "when": "对方低落或表示不想展开，但仍愿意有人陪着",
  "contents": ["初始反应", "继续与停止条件", "相关样本"],
  "estimated_chars": 380,
  "detail_state": "not_loaded"
}
```

目录只用已安装条目的触发/范围生成有界语义提示，说明适用场景、内容类型与展开大小；不只给字段名和裸ID。不得将标题当成已知正文、真实经历或已获授权。摘要不能偷偷把整段正文改写后塞回目录，也不在运行时调用另一个模型生成摘要。

例如本轮只有问候，常驻语感和日常示范已经足够，可以直接回答。用户说“别一个人扛”，模型可读取对应的并肩回应与样本；用户转而问游戏，就无需继续携带上一场景的全部张力。不是每轮必先读一遍人格。

初始目标可按常驻正文约1000–1800字符、目录约400–800字符、至多两个场景包探索；这只是资源起点，不是已测收益。实际核心条目若放不下，应保留完整层或明确报告，不能悄悄截断全局约束。目录/工具schema/额外模型请求一并计入成本。

## 拟议读取与装配流程

1. 宿主读取同一个人格快照，先做用途与有效性过滤，形成核心正文和场景目录。
2. 与其他上下文一起交给当前主模型。模型可直接答，也可调用拟议只读工具 `persona_load(refs)` 批量读取。
3. 宿主验证本轮引用、会话代际、人格版本、用途、依赖与总预算，返回完整场景正文及条目ID。
4. 在同一模型工具循环的下一次请求中使用这些材料；按完整条目去重，不重复追加核心正文。
5. 记录核心、目录、请求展开、实际送入、未送入原因和最终调用；本轮结束后保持有界策略。

不增加独立逐轮选择模型，不暴露内部推理。没有必要先复用 `memory_search`：当前目录较小，可以直接列出可发现的场景包。后续目录增大时再设计分层发现。

首版不提供人格编辑/移除核心工具，也不把persona引用交给现有memory工具或工作集入口处理。读取只影响表达材料装配，不改人格、认知、记忆、工具权限或用户偏好。

## 必须补齐的实现约束

- **分层有依据。** 当前v2没有完整的常驻/按需合同；不能只按priority或GROUPS取前几条。包准备/用户表达更新时标明驻留层与关联，保留源ID和未决项。旧包未完成分层时继续完整投影，不在运行时凭关键词切包。
- **完整依赖。** 当前一些张力/反应的links为空，不能据此认定没有边界。全局约束常驻；专用规则、停止条件和样本组成完整场景依赖闭包。缺依赖时标未决，不能为了预算只取一句台词。
- **字段不等于任意正文。** 初版仅覆盖已审议表达材料；人格生长、关系和观点仍按原证据与用途处理，不把其他小节都开放成无条件读取库。
- **版本与用途。** 先过滤GUI/QQ/worker资格再生成目录，标题也不能跨用途泄漏。工具只接受本轮已签发引用，不读路径、任意ID或旧版本；人格变化后旧引用失效。
- **权限语义。** 已安装表达偏好经读取后可用于当前表达，不因此成为经历或新授权。必要宿主边界常驻；工具返回不成为可覆盖宿主协议的新指令。
- **预算与故障。** 校验完整依赖包及工具schema/回执的总成本。超限逐项返回明确状态，不截半条规则；不无限读、不强制所有回答额外一跳。无法读取仍有核心表达可用。
- **跨轮保留。** 首版可仅保留本轮加载，不引入长期人格工作集。当前原始工具回执仍可能随最近历史进入后续请求，这必须计入实际预算；若要后续移除正文，应通过宿主有界装配实现，不删除对话、不声称已经遗忘。之后再独立设计跨轮场景保留与失效，不能只改工具的“本轮”标签就宣称消除了重复。

## 收益与风险

潜在收益是减少无关正文及人物主题竞争，尤其避免普通问候也同时看见消失恐惧、战斗台词和深夜孤独。模型可按本轮需要选择细节，规模增大时不必所有字段常驻。

主要风险是模型不读或选错：人格可能更淡，也可能只读吸引注意的主题，造成场景偏移。常驻核心和日常示范提供基本保障，但不能证明该风险已解决。相关目录存在而未读，只能说明没有展开，不能据此解释成“她不需要/不喜欢这个人格”。

另一个风险是工具调用后的重复上下文与延迟。固定前缀缩短也可能改变供应商缓存收益；首轮变短不等于整轮token、费用或响应时间降低。要比较一次用户请求中所有实际调用的输入、usage、耗时和读取次数，并观察连续对话累积。

## 推进与真人验收

先在观测器里把persona拆成使用说明/核心候选/场景候选/生长材料的来源构成，记录实际大小，保持当前全量模式作为基线；再增加可回退的分层模式，不立即替换默认行为。

人工在真实环境比较：日常问候、低落、被夸、能力澄清、正式改写，以及连续数轮话题切换。分别记录语感、样本反应顺序、读取是否自然、额外延迟、总输入量和是否误引经历。不要只看注册表是否显示、字数是否下降。

复验还应包含同义问法、未读取直接回答、未知/过期引用、场景依赖超预算及渠道隔离；无法实际触发的分支记待验，不补造机器验收。保留完整模式一键配置回退，不清会话、不重导入认知、不修改已选表达偏好。

建议先做这份分层与读取契约，再决定实现。现阶段不建议把37条全部变成ID立即上线。已有架构具备大部分基础，但需要显式的驻留合同、依赖校验和独立表达读取协议，属于一项架构改造。
