# 互动习惯优化 v1

2026-11-09。范围限定为当前24轮复盘的R03/R04/R05/R06：主动接话、反问收尾、反馈后的行为、对用户动机的解释。不在本批修改记忆保存、操作回执或维护调度。

## 目标与取舍

人格决定具体语感，通用互动规则解决如何推进这一轮。用户让Alice起头时，直接提供一小段内容或发起当前可做的玩法；需要澄清时仍可以问问题。用户说少问、别分析时，让紧接着的回答体现变化，而不是又请用户确认“这样是不是好点”。

不设“永远不提问”或“每轮最多一个问题”的硬配额，不按标点删句，不自动把普通提问解释为用户厌烦。反馈的适用范围按用户原意；当前明确任务的格式和内容仍优先。

## 实现

1. 新增纯标准库、无I/O的 `alice/interaction_policy.py`。只保存一份有版本的互动指引及无正文元数据，不新建持久偏好或后台任务。
2. `retrieval.build_system_prompt` 在稳定系统前缀中加入该指引一次，完整/按需人格和无人格的聊天都适用；纳入现有上下文预算及SDK实际消息记录。不另加轮尾重复提示。
3. 同步完整/按需人格的样例使用说明：样例中的反问、关怀与收尾按当前情境选择；不能机械复用，也不能覆盖用户明确的互动反馈。已有私人表达包不重写、不重分类、不要求重新导入。
4. 在主模型调用的上下文依据和完成后的 `context_basis` 中记录互动策略版本、SHA256及字符数，区分“磁盘有修改”“本次采用哪个版本”“实际回答效果”。不把版本号当作效果通过。

不增加付费调用、回复重写或行为分类器；不新加正则去猜用户是不是反感追问，不跨越来源保护读取额外历史。本版依赖本轮实际可见的反馈；反馈离开上下文后，不宣称已永久记住。

## 指引的内容

- 先回应用户本轮内容。有具体作用才问，普通接话可以自然结束，不每轮把选择或问题交回去。
- 用户要求起头、先讲、先玩时，先给内容或可进行的一步；允许用户改变方向，主动推进不等于替用户决定。
- 收到明确的互动反馈，短暂接住后直接改变下一条行为，避免反复认错、解释心理成因或请用户监督。
- 用户反问、转题或不知道答案，不自动推断其隐瞒、逃避，也不评价其是否“更像人”。受邀猜测时保持猜测强度。
- 可以参与文字游戏、猜谜等当前能做的互动；涉及外部实际操作时按真实工具能力说明，不从身份、身体或发言不可撤回推出额外禁令。
- 语感继续用所选人格；正常闲聊无需为每次接话补一段身份与心理说明。

## 人工验收

只在真实环境人工聊天，不用模拟模型、自测或额外付费审稿。

| 场景 | 可观察结果 |
| --- | --- |
| “你先起个话头” | 直接起一小段有内容的话，不再先问想聊什么 |
| “少问我点，接着说” | 接着上一话题，不以反问要求用户评价是否改好 |
| “我们来玩个文字小游戏，你先来” | 提出简单玩法并开始第一步，不先讲身体或身份限制 |
| 用户说“不知道”，或问“为什么这么想” | 按字面回应，避免断言用户在回避或藏事 |
| 明确需要补充条件的实际任务 | 保留必要澄清，不为了少问而擅自作主 |
| 用户邀请猜测自己的想法 | 可以猜，但不把猜测当原意，也不把普通好奇读成心理防御 |
| 正式改写“只给结果” | 只给所需结果，不加入闲聊或游戏 |

验收需要同时观察是否自然、有内容、保留人格语感；没有问号不等于通过。旧历史仍保留，不把历史中的认错、旁观者叙事或追问习惯当成新的互动要求。
