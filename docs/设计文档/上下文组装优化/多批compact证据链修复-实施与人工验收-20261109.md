# 多批compact证据链修复：实施与人工验收

2026-11-09。针对b948284复核发现的R04递进缺口施工。**代码已修改，静态检查通过，真人行为未验收，服务未重启、维护开关未启用。**

## 问题与修复选择

旧实现的状态正文可以继承A批事项，但B批写入的processed_pairs只含B；到了C批只能重建B的原文，无法核对A事项。连续两批检查不足以发现该问题。

本次采用已有批次账本追溯，不修改数据库格式、不复制原文到新日志，也不将所有旧引用反复写进每个新批次。当前compact任务是单飞行、同渠道按顺序追加；最新状态的累计覆盖集合应能由该渠道、同epoch、截至本state_id的已提交批次完整解释。

## 实际改动

`alice/maintenance.py`：

1. `_rebuild_prior_evidence`读取同epoch、同渠道的历史批次，合并各批processed_pairs；检查引用冲突、完整往返及累计覆盖集合一致性。
2. 每对原文通过既有`context_history_rounds`重新核准当前资格、角色、请求完成状态及来源/协作隔离，再核对冻结版本。不能只按turn ID直读正文。
3. 从第一批开始的合格证据全部交给后续生成与审核，包含原始时间；摘要本身不能当作事实依据。
4. 旧状态存在但证据不能重建，直接返回`prior_evidence_unavailable`，在模型调用前失败。不会让模型以删除旧事项换取本批通过。
5. 生成输入将旧原文纳入原有预算检查；超限在模型调用前返回`generation_budget_exceeded`，审核输入仍有独立预算检查。
6. 最终提交前再次核对活动状态和全部旧证据；等待期间状态/资格/原文发生变化，批次以stale_input结束，不发布新状态、记忆或覆盖边界。

`alice/grounding.py`：

- 审核保留旧事项所需的原始依据；仍有效的未决事项和限制不能仅因本批未提及而省略。
- 旧证据用于接续状态核对；长期记忆候选仍只能从本批尚未常规提取的原文产生，避免回头重复提取。

不新增工具或权限，不改变宪法存在事实清单中的能力范围。

## 兼容与保守处理

- 正常b948284格式的历史批次可直接追溯，不要求用户重置人格/会话或重新压缩已覆盖的原文。
- 旧格式缺assistant_id、遗漏批次、覆盖集合不能解释、来源资格变化或原文版本变化：明确失败，保留此前已发布状态与游标，不自动迁移或补猜。
- 证据按同epoch/渠道获取，不能借全局turn ID从其他受众补证据。
- 本版保守地保留批次级证据，随着批次数增长会增加生成/审核输入。超预算时明确失败，不静默截断。进一步按状态条目裁剪必要证据，需要单独的来源映射设计；本次不以减少证据为代价掩盖预算问题。
- 回退代码不影响原批次记录。本次没有数据库迁移，也没有读写用户活库。

## 人工验收步骤

在允许的真实测试环境、保持普通原文资格的条件下执行，避免对运行中的同一活库另开CLI并发写入。

| 场景 | 需确认 |
| --- | --- |
| A批记录一个未完成任务和限制，compact | 新状态和原文依据正确 |
| B批换话题，不再提A事项，再compact | A事项保留且可由A原文核对 |
| C批继续其他话题，第三次compact | 审核仍包含A、B证据，不只B；A事项不丢失 |
| 后续明确完成/取消A事项，再compact | 允许有据更新状态，不能永远机械保留旧待办 |
| 旧原文资格/内容在任务中变化 | 提交拒绝，不发布过时产物或推进边界 |
| 历史证据缺失或版本不匹配 | 明确失败，不能以空证据让模型自行丢旧事项 |
| 证据较多、预算不足 | 明确预算失败；不截断冒充完整，不追加隐式重试 |
| 检查新增长期记忆 | 不把A/B旧证据再次提为C批新记忆 |

接续状态是否有用、模型是否遵守保留规则，仍需真实对话和实际发送正文验证；不能只看prior_pairs_verified数量。
