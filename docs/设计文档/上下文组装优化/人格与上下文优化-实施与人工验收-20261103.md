## 2. 本轮实现

### 2.1 修复已有 C0 接线

- 原 loop 在 messages 创建前追加学习/搜索/协作说明，随后又以 build_messages 覆盖。现在先收集动态说明，预留预算，组装后实际追加，避免未定义变量和说明丢失。
- 原历史只把 worker 渠道投影用于清单，实际发送仍用原始 rows；现在先投影，再选择、计量、序列化。
- 去重后按真正发送的资料重新构建清单，当前时间注入也纳入历史计量。
- messages_tokens 计入消息封装、工具调用参数与 schema，收尾说明追加后再检查预算，并预留回复空间。长度仍是启发式估算，不是精确 tokenizer 或严格上界。
- 修正记忆区残留的“未列出就不记得”及查不到就遗忘的话术。

### 2.2 C1 索引与展开

新增 alice/context_memory.py，复用标准库和现有文本匹配。普通记忆范围显式传渠道，仅取有效且未到期限、无 URL/来源证据/父链的 conversation 记录；三层均可发现。带父链的普通条目暂不支持，不用隐含 GUI 的旧查询读取 QQ 目录。

目录含标题、类型化主题提示、记录时间、未知事件时间、预计长度和本轮引用。引用带正文版本与随机请求身份，由宿主映射，旧请求/随机数字 ID 不可直接读。计数变化不改变正文版本。

初始按相关性、重要度、时间排序，补少量近期候选；最多两条相关、重要的长期锚点可完整注入（合计约 1,200 字符）。其他条目只展示目录；这仍是朴素匹配，尚未完成专门的未决事项抽取与分歧配额。

memory_search 只返回有界目录，游标绑定本轮及查询、候选版本。memory_load 最多批量四项，返回 loaded/already_loaded/stale_ref/unavailable/budget_exceeded/too_large，不截断正文。搜索展示不增加使用次数，完整展开同请求只计一次；初始自动锚点不增加检索使用计数。

每次模型调用前、调用返回后、发布前复核所有已暴露引用；材料变更时保守结束本轮，不拿旧版本继续作答。已暴露索引也参与检查。indexed 有目录/正文时缓冲流式输出，检查通过后才发布，因此首字等待可能变长。

### 2.3 来源路径兼容

indexed 的普通记忆用 memory_search/memory_load；来源见闻使用独立 recall_sources，复用原来源许可、期限及派生依赖，不进入普通目录。来源回忆也受本轮记忆调用/正文预算限制，逐条完整保留，放不下不截限定条件。

旧 recall 不重复挂到 indexed schema；兼容调用走同一普通过滤和预算。legacy 模式保留原 recall 入口。带父链的普通记忆在 indexed 暂不覆盖，不能把该模式说成对旧召回能力完全等价。

来源回忆仍保守登记所考虑的来源依赖，预算拒绝条目不增加正文使用次数；不以“模型说没采用”清除依赖。未改变来源硬期限、兴趣、价值或退款规则。
