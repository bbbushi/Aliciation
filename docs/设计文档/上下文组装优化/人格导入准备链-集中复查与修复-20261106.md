用户在多次导入同一份人格文本后遇到连续失败，要求先集中检查其他问题，避免继续靠付费重试逐个定位。本轮覆盖结构生成、局部适配、用户修订合入、完整投影、事实与保真双审、样本补位、认知提取、收养审查及安装入口；采用静态审查与既有真实回执的只读数据分析。

## 兼容与审查边界

- `entry_text()`、编辑器正文、表达包编码和锚点路径保持原表示；运行时完整投影的 metadata.policy_version 从 5 改为 6，表达格式及准备协议版本不变。
- 依赖编号按完整包固定生成，同一条目跨用途使用相同编号。完整结构校验仍先证明被引用条目在相应用途中存在，不能用编号隐藏跨用途缺失。
- 短 ID、多位编号和稀疏用途可能使数字依赖反而变长，中文标题也可能增加 token 估算。因此仅在紧凑表示字符更短、原文与 JSON 转义后的未取整 token 权重均不增加时采用它，否则沿用原表示；既有合规包不会仅因排版变化而新增字符或当前估算规则下的 token 预算失败。metadata.projection_layout 记录实际选择。
- 生成阶段的顺序、来源别名、反向索引规范化都有单独审计；用户修订合入之后不再执行这些规范化。原始模型回执不覆盖。
- 完整 JSON 差异不是宽松解析：重复键、错误 ID、缺失或额外字段、错误类型、部分对象均不能据此通过；未知差异 ID 仍仅能在单字段精确替换且唯一对应时恢复。
- 提前覆盖判断经独立复核修正：补位可能改变已有样本所关联源的去向，因此这类源缺口不提前一刀切拒绝。最终双审、覆盖核对、摘要与激活门槛继续生效。
- 保留文本预检只检查已经确定的容量和旧修订状态。它不构造占位候选、不改 baseline、不预判新源身份匹配或冲突，也不承诺最终总上下文预算通过。
- 没有增加模型调用、外部能力或权限，宪法“存在事实”清单无需增加项目；没有引入依赖或构建工具。
