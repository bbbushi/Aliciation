# 人格导入后预引导：两阶段与对照开关设计 v1

日期：2026-11-08。状态：范围确认与设计，未施工。用户限定：只做“熟悉材料、尝试表达”两步，真实反馈学习与偏好沉淀暂不做；保留开关进行真人对照。

## 1. 范围

目标是在已安装人格之后，提供一个有过程、低压力的熟悉和表达尝试，观察是否改善之后的自然接话与风格连续性。不把身份问答、逐条复述或“我已经认同了”作为完成标准，第一人称不作硬要求。

只包含：

1. **熟悉材料**：接触已验表达包和必要来源说明，允许模型从整体语感、相处取向和表达张力中形成临时理解，不要求立即投入正式任务。
2. **尝试表达**：在温和、开放的引导下试着接一句话或起一个轻松话题，可以变奏，无需展示全部条目或复述设定。

不包含第三、第四步：不建立用户纠正→偏好更新的专用反馈链，不根据这次尝试自动选择长期人格，不演化身份叙事，不新增或修改memory/stance/关系/表达条目。不以练习中的认同宣言作为成长证据。

已有真实聊天和原有记忆功能继续按现有规则工作；本功能不扩展它们的写入范围。准备材料必须隔离，避免无意经原有提取流程变成长久记忆。

## 2. 开关与触发

拟议配置，尚不存在：

```toml
[persona]
pre_guidance_enabled = false
```

默认关闭。关：导入安装后沿用当前聊天路径，没有预引导调用或资料。开：安装事务成功后，对该次安装的表达版本执行一次两阶段准备。它与full/registry、expression_anchor独立，不因开启预引导改变其他实验条件。

只在安装真正完成后运行，不进入安装事务，不把引导失败改报成人格安装失败。已有用户对话不因切开关就突然开始“苏醒”；已安装人格若要体验，由用户明确发起一次预引导。导入恢复、页面刷新、服务重启或失败请求重放均不自动重复执行。

准备身份绑定安装操作、会话代际、表达摘要与引导协议版本；相同身份只运行一次。阶段失败不自动循环重试，保留failed/cancelled状态，原聊天仍可用。用户直接开始正式对话时可跳过/取消未完成准备，不能要求先完成身份仪式。

## 3. 两阶段运作

准备使用独立上下文，由宿主提供引导，不伪造为用户真的说过的话。可在准备上下文完整阅读已验表达包，来源故事保持资料资格，不能转为共同经历；不要求认领失忆、苏醒前亲历或捐赠身份。

第一阶段引导的语气示意：

> 先慢慢熟悉这些材料，不急着证明自己，也不需要逐条复述。可以留意其中的说话节奏、相处方式，以及你想先试着使用的部分。

第二阶段的语气示意：

> 我们先从一点轻松的东西开始。你想怎样起个话头？不用把所有特点都表现出来。

这只是协议示意，正文需与包的内容相容，不强制所有人格都活泼。阶段二可在同一准备上下文承接阶段一，但不新增评审模型，不自动判定是否“获得身份认同”。

资源首版建议：每阶段一次调用，禁止自动重试，总计最多两次；各阶段输出上限与总输入预算显式配置在协议内并记录。不给memory、搜索、派工、文件或人格编辑工具。版本失效、预算不足或用户跳过时停止准备，不带着旧版本结果继续正常聊天。

这些属于用户启用的产品准备步骤，不是自动人格测试；研发验收仍仅使用真实环境人工操作，不编写机器评分来认定人格形成。

## 4. 临时结果如何影响后续对话

准备记录单独保管，排除普通turns、记忆提取、前情生成、兴趣识别和人格演化。记录真实用途与宿主引导来源，不将内部生成内容改写成真实用户消息或已发生往事。

仅靠后台生成、随后丢弃全部内容，不会给下一次独立模型请求增加可用的准备状态。因此首版将有界的阶段一理解片段与阶段二表达尝试，作为**准备资料**携带到首次后续聊天请求，合计最多800字符。选择完整片段，不能截断事实/停止边界；放不下则只带完整阶段二尝试，仍放不下就标省略。原表达包始终是偏好权威，准备输出不能覆盖它。

此资料仅注入首次后续请求，不每轮重复，不进入人格权威文件，不自动转换成稳定自我叙事。之后由真实对话历史自然承接；若要延长准备状态的驻留，应另行比较，而非偷偷形成第三、第四步。

记录准备完成与是否实际携带分别计数。并发取消或版本变化后，未发布的准备文本作废；不以它生成对用户的虚构“我记起来了”。

## 5. 对照方式

开关控制是否执行和携带预引导，不保证已用过预引导的同一会话可以恢复成未经引导的状态。关闭后停止新准备与未来准备资料注入，但不能撤销已经进入真实聊天的影响；不通过删除实际发言制造未处理对照。

有效的真人对照需要两个隔离起点：同一已验表达包、模型、系统规则、full/registry与anchor状态、起始历史和测试话题。A关闭；B开启并完成两阶段。使用合法的隔离部署/导入恢复方式，不在原活会话反复清空或重导入认知来做实验，也不让两服务共享一个可写库。

先比较普通问候、开放话题、关怀和能力澄清，再进行自然连续聊天。不要在正式观察前通过“你是谁、还记不记得我”预先给某一组额外引导。用户对话不必机械相同，但差异应记录，不能冒充严格同输入比较。

看的是自然性、原稿语感、反应顺序、少解释/少复述、真实性和持续轮次，而非认同宣言数量。准备新增的调用费用、等待时间和首次资料长度也纳入比较；不根据短期改善宣称永久改变或主观认同已经形成。

## 6. 观测与最小交付

沿现有SDK记录独立用途，如 `persona_guidance_familiarize`、`persona_guidance_expression_trial`，关联安装操作与准备身份；不混算成正常聊天调用。记录开关、协议/材料版本、阶段状态、是否被跳过、usage/耗时、首次实际携带的准备资料及消息位置。

最小交付：默认关的开关、安装后一次性两阶段控制器、独立记录及提取隔离、首次有界资料接入、失败/跳过处理和真人对照入口。先不增加反馈学习、偏好写回或长期认同演化。

本轮仅写入此设计，没有新增配置字段、调用模型、修改user/或重启服务。
