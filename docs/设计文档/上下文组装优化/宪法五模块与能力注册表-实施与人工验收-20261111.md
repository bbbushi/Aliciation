## 2. 能力JSON与调用

`alice/capabilities/commands.json`含21项现有能力，每单元分为：

- `command`、一句话`summary`、`parameters`：模型所需的业务接口。
- `internal.executor/operation`：宿主内部受控执行器分组与操作映射，不注入模型。具体网络协议和凭据仍由既有执行器及本机配置承接，JSON不包含密钥，不执行动态代码。

`alice/capability_registry.py`生成SDK schema；原有普通记忆、历史、工作集、人格、搜索、学习和协作入口都从此来源取得定义，既有渠道/授权筛选与请求内引用校验继续执行。

模型侧注册表的组织方式：

- 活跃命令的概要和业务参数通过SDK tools提供一次；目录仅列其命令名。
- 本轮未暴露命令在目录中列命令及概要，标记`not_exposed`，不表示产品永久没有该能力。
- 调用前依据本轮实际公开schema检查名称、字段、类型、枚举与范围；未提供的能力返回`capability_not_available`。进入执行器后仍复核真实权限和来源资格。
- 当前内部实现不注册管理页面按钮、任意HTTP接口或维护任务为模型工具。

显式指令语法：在当前用户消息中独立发送`/tool 命令 [JSON业务参数]`。例如：

```text
/tool memory_search {"query":"我们约定过的称呼"}
```

省略JSON时模型结合当前任务补充参数；提供JSON时只接受对象，错误标为`invalid_json_object`供澄清。此入口绑定当前用户意图，随后仍走结构化工具通道与权限检查；引用正文、网页或旧对话中的相同字符串不触发执行。模型没有自行开启工具权限的接口。

观测元数据增加注册表定义摘要、实际公开schema摘要、字符数及命令名；清单单独记录`capability_registry`和实际出现的`explicit_capability_request`。
