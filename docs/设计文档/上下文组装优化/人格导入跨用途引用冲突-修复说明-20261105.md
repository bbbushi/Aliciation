# 人格导入跨用途引用冲突：定位与修复

日期：2026-11-05。基线：`eaf2974`；本文记录后续本地修复，不改写此前审核报告或真人验收状态。

## 证据与定位边界

用户提供初始化导入界面的报错截图：`表达跨用途引用不可完整投影：c_fame`，并提供当时使用的《爱弥斯-人格提示词.md》。原稿没有 `c_fame`、`purposes` 或 `links` 字段；这些字段由表达准备链生成。

用户随后确认，问题由另一位开发者在其环境发现。本机仅查询了 `user/data/` 下相关生成回执的文件名，没有找到 `structure.json`、`adapt.json` 或 `expression_prepared.json`；没有读取配置、数据库、人格正文或修改用户数据。没有取得对方当次回执，因此不能确认 `c_fame` 对应的具体正文、引用对象和失败阶段，也不宣称本机复现。

可确定的代码条件：某条目声明的用途不是其每个依赖条目用途的子集。例如 A 可用于 `chat/qq`，A 引用的 B 只可用于 `chat`，则 QQ 投影无法同时保留 A 和 B，必须拒绝这一未经处理的包。原准备提示只列用途取值，没有说明依赖用途约束；结构生成和局部适配之后直接校验，中途遇到此冲突就终止。

## 本次修改

- `alice/expression.py`：跨用途检查移至全部条目、来源、场景及修订结构检查之后，使用专门的 `PurposeReferenceError`。错误同时给出引用方、目标和不支持的用途，其他错误保持原拒绝路径。
- 新增仅供生成阶段使用的 `restrict_prepared_purposes`：先严格验证，仅捕获上述冲突；深拷贝候选，通过反向依赖队列传播用途交集，直至稳定，再严格验证。所有合法条目必含 `chat`，因此收窄过程保留完整 GUI 表达；QQ 和 worker 可见条目可能减少。正文、ID、引用、来源、必要性和受众均不改，不能扩大依赖条目的共享资格。
- `alice/expression_prepare.py`：生成协议明确 `links` 是投影必须保留的依赖，规定用途子集关系及传递、循环引用的处理。结构生成和适配生成分别收窄，之后继续原有用户修订合入、投影预算检查、事实与保真双审及激活门槛。
- 适配差异仍以模型原始包对照实际输入核对；通过后才采用宿主收窄后的包。宿主用途变化不伪装成模型文本替换，避免误报模型遗漏 `changes`。

运行时解码、投影、应用和回退仍调用严格校验，没有跳过开关，也不会在运行时修复人格。用户修订合入之后不执行这项收窄。此次不增减公开能力或权限，既有宪法“存在事实”清单保持准确；表达格式及准备协议不变，旧候选仍需满足相同的严格用途约束与审议摘要。

## 审计与调用成本

原始 `structure.json`、`adapt.json` 保持模型回执。后续真实准备会分别写入 `structure_purposes.json`、`adapt_purposes.json`，记录政策 `restrict_to_dependencies_v1`、受影响 ID、调整前后用途和造成限制的依赖。完整准备结果另含 `purpose_changes`。这些记录留在操作私有目录，不进入人格 Markdown，也不替代双审。

本轮没有执行准备，因此没有创建上述运行期文件。修复没有新增模型调用、自动重试或替用户重跑导入。生成包若还有其他结构、预算、事实或保真问题，继续明确失败。
