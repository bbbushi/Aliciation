## 推荐分层

1. **常驻宿主规则**：身份/时间、真实能力、事实与发言/推断区分、记忆载入状态、许可/停止/渠道边界、表达资料使用规则。普通回答无需复述清单。
2. **同用途人格投影**：保留明亮外层、护短、嘴硬、报喜藏忧、完整触发/转折/停止与语气节奏。事实边界限制事实主张，不把表达倾向改成客服。
3. **本轮资料**：有资格的记忆/观点、历史前情与来源；明确为资料而非新权限。注册表只是在既有合同成立时可选，不能作为万能压缩开关。
4. **操作专用材料**：导入/修复模型自己的明确合同、额度与校验；用户操作界面负责进度和实际结果。主聊天不凭省略掉的算法细节回答精确实施问题。
5. **宿主审计**：导入原候选、适配差异、原回执、完整理由/版本等保存原处。删除聊天投影字段不等于删除证据。

### 为什么压缩导入段落不会让导入模型丢掉规则

已核对 `expression_prepare.py:88 _call_messages`：操作请求由专用 instruction、冻结解释合同和资料 JSON 构成，不消费聊天 CONSTITUTION。局部修复由 `expression_repair` 的精确片段合同及 `_apply_review_patch` 实际执行；修复次数、必修优先/可选失败回基线在 `prepare_expression` 中；JSON 恢复使用 `expression_json_recovery.INSTRUCTION/build_request/apply_patches`；续跑额度在 `persona_checkpoint.LIMITS`、版本绑定在 `persona._import_binding`。这些代码和操作专用指令未改。

因此本轮是压缩主聊天的能力说明，不把关键规则“删除后期待模型自己知道”。主聊天仍知道不能代安装/续跑，准备不等于安装，普通覆盖提示不等于硬问题，模型审议不等于真人验收。主聊天没有自动读取全部审计的承诺；不能据简写回答自己没有证据的精确操作状态。协作安装目录、版本、GUI 控件说明虽然冗长，本轮仍保留；尚未证明有可靠的相关场景注入，不能顺手移除。

## 需裁决的后续设计（提案，未实施）

### A. 协作/导入帮助按场景提供

必要性：协作六条就占样本 2,271 字符；本机路径、版本、控件步骤会老化，普通聊天常驻价值低，但错误派工与停止判断风险高。

最小方案：定义聊天观点投影包含完整主张、归因、状态、不确定、下一步和稳定 ID/版本；审计字段独立可追溯。legacy 人格只给当前观点语义提示和精确引用，正文在本轮资料中提供一次；每次先做失效/撤回/来源资格校验。不按标题或相似文本去重，不能删除理由中的重要条件。存储是否拆字段必须明确迁移契约，不能在本轮替私有库做正则迁移。

替代方案：维持现有双投影，仅省原候选（本轮采用）；采用现有 indexed 模式需用户自行裁决配置与真实体验，不能自动切换。迁移若获准，应备份原库、版本化读取器、保留原审计映射和回滚路径；表达包及用户历史不可重写。人格 donor 人称/占位符的自动转换同属待裁决，不把“爱弥斯”机械替换成“Alice”。
