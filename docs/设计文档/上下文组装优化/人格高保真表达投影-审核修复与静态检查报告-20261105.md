## 1. 决策与范围

R1 采用“默认保留当前 v1 完整三节”策略。缺少日志、日志摘要不匹配、用户自写原生人格都不能证明不存在用户后改；不再靠修订日志缺失来放行覆盖。当前三节（包括空节）作为用户配置保护，不伪造捐赠出处。保护内容与新源必要边界冲突时保留当前人格并报告缺口，不静默以原稿替换。保守保护不是用户对新源条目的删除授权；无法可靠合入的 v1 可继续原版运行，本修复不承诺每份 v1 都能直接迁移。被保护或用户修订的样本若核对失败，只显示缺口，不进入自动补位改写。

R4 对结构完整的编辑采用逐项修订记录；只有用户明确选择整节自由文本才保留整节范围。旧粗粒度 `user_overrides` 无法反推出用户曾逐项改删什么，不能自动当作新原稿条目的删除授权。跨新包条目身份不可靠时阻止激活，而非猜测相似项。

表达事务仍只改人格三节、人格版本和本操作标记；不进行认知重导、记忆重置或维护水位迁移。单一人格 Markdown 权威、标准库核心、原生 JS、回环服务和来源许可边界保持。P1b 默认关闭。原稿全文与审议正文仍只会在以后用户显式操作时进入本机私有审计。

## 3. GUI 与服务契约变化

现有 `POST /api/persona/expression-update` 六动作与本机 GUI 来源/意图闸门不变。新增或明确的返回字段：

| 字段 | 含义 |
| --- | --- |
| `baseline_policy` | 本次采用的当前表达保留策略；面向用户的说明 |
| `current_diff` | 三节 `{section,before,after,policy}`；before 为准备时的可读正文，不是刷新时实时人格，也不含 v2 base64 机器注释 |
| `token` | 当前查看的原更新/操作身份；正常回退响应不替换为 undo 身份 |
| `rollback_token` | 已证明完成的独立回退操作身份 |
| `rollback_of` | 当前记录是回退事务时，其对应原更新身份 |
| `expression.revision_modes` | 当前人格各节的修订范围模式，供编辑器显示既有整节选择与旧格式保护 |

候选页面将“准备时的表达 → 候选表达”与“原文 → 适配 → 排除或缺口”分开，前者优先展示。历史记录没有该对照时明确显示缺失，不能据此认定已保护旧修订。页面显示保留策略；模型事实/保真核对仍只称核对结果，不称真人效果认证。

三节编辑器增加显式“整节自由文本”选择。用户勾选时由 GUI 在提交内容前加入 `【整节自由文本】` 标记，不要求用户写元数据。未选时仍按结构化条目编辑，类型外字段须明确处理。已经采用整节模式的节会显示持续保留范围说明；本次未勾选不自动撤销过去的整节选择。

回退响应合并时 GUI 始终保留正在查看的原 token，单独显示回退记录，并支持原记录与回退记录互相查看。关系扫描未完成时显示“操作状态尚未完整核对”，不显示普通已应用回退按钮。准备/应用结果不明仍先查记录，没有前端自动重做准备；后台单阶段传输重试属于既有 `llm.chat` 尝试机制，不能混称整个准备流程零重试。

## 4. 回退证明与失败边界

回退关系核对两份操作日志及各自数据库提交标记，要求同代际、互为前后文件摘要、连续人格版本、`mode=rollback` 与明确 `rollback_of`。只读查询可投影已证明但原日志尚未归并的关系，不在查询中写盘；启动恢复/写操作前恢复会补结原日志状态。

关系归并只写操作状态，不回放人格文件；后续用户编辑不因补结被覆盖。重复回退只在原操作已回退且当前仍符合已完成回退版本时确认已有结果。当前已后来变化、证明不全或同一原操作出现冲突逆事务时明确拒绝并保留现场。

本轮没有用删除旧记录、清库或重新准备替代恢复。外部删除整份日志、介质损坏等原审核指出的恢复边界未宣称自动解决。
