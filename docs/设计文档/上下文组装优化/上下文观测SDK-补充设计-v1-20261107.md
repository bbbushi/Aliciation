## 决策

采用可嵌入 Python SDK。第一版在本仓库核心中落地，保持仅用标准库；通用采集模块不依赖 Alice 的 Store、人格格式、模型厂商或网页。Alice 通过适配层提供材料语义、接入现有收据和公共查询面。将来需要独立分发时再拆包，不先引入发布和插件框架。

SDK 观察上下文形成和使用过程，不负责选择记忆、裁剪消息、调用模型、改变权限、重试请求或评判人格效果。关闭观察与观察故障时，聊天仍按原有业务规则运行。

## 两种接入必须同时存在

### 组装接入

记录来源ID、版本、块类型、入选/排除及原因，以及最终消息中的位置绑定。宿主掌握这些语义；仅观察最后的 messages 无法知道“哪些记忆被考虑后排除了”。

先兼容现有 ContextManifest，逐步扩展块ID和来源绑定；现有清单作为同一记录的投影，不再产生一套无法关联的平行账本。

### 调用接入

在实际调用模型前记录最终参数投影，涵盖 messages、tools 和白名单模型选项。流式与非流式共用冻结和关联代码；显式接入，不做全局 monkey patch，也不由 SDK 接管模型请求。

提供调用方可用的独立参数副本，使本次快照与本次请求对应。未知或不可序列化的扩展参数标明未覆盖，不能丢掉业务参数后发送“简化请求”。快照是应用提交给模型客户端的参数，不声称是HTTP原始字节或远端内部上下文。

## 公共 API 草图

以下方法均为拟议接口，不能直接当现成代码执行：

```python
observer = ContextObserver(sink=alice_sink, policy=capture_policy)
trace = observer.begin_request(
    request_id=request_id, session_epoch=epoch, scope="gui"
)

# 组装阶段，由业务代码登记；登记不会向模型新增消息。
trace.block("persona", kind="expression", content=persona_text,
            source={"fingerprint": persona_fingerprint})
trace.selection("memory:10", included=False, reason="not_loaded")

# 最终调用阶段，bindings 指向消息内实际内容区间。
call = trace.prepare_call(
    call_id=call_id, purpose="main_stream", tool_round=0,
    messages=messages, tools=tools, parameters=model_parameters,
    bindings=bindings,
)
attempt = call.begin_attempt(number=1)

# Alice 继续按原有逻辑调用和消费模型；SDK 自身不发送请求。
# client.chat.completions.create(**call.request_kwargs())
# attempt.response_started(...)
# attempt.finish(status="stream_completed", usage=usage)
# trace.finish(assistant_turn_id=assistant_id)
```

SDK 支持无正文模式和空实现。调用方不能依赖它返回记忆选择、权限或生成决策。示例中的来源和状态由宿主提供；SDK 不能凭名称推断正文已读。

## 事件合同与状态

事件采用 `schema_version`、`event_id`、进程内请求序号、会话代际/渠道、request_id、call_id、attempt、工具轮次、用途、时间和数据体。保留父子关系，不把同请求多次调用合并成最后一次。重试沿用业务侧已有标识与次数，观察器不新增重试。

核心事件包括：请求开始、块登记、选择决策、调用准备、尝试开始、响应开始、尝试结束、回复后处理、请求结束、观测缺口。

进入调用、收到响应头/首个流事件、流完整结束、流中断、失败和取消分别表达。收到流对象不能立即报告完整成功；失败也不能自动推出远端未执行。未覆盖的辅助调用显示未覆盖。

hash 基于明确版本的规范化参数/文本表示，用于比较内容与定位快照，不当作网络发送证明。消息顺序与工具定义分别保存；块绑定有角色、序号、字符区间、来源版本。SDK 校验绑定不符时记录缺口，不伪造位置或修正业务消息。

## 存储与查询合同

SDK 只向 sink 提交不可变、有大小上限的事件，不直接连接活库。Alice sink 复用现有线程安全收据队列和安全落盘边界；正文使用专属本机快照存储，与默认元数据模式分开。沿用前一设计的有限轮次、期限、容量、用途和撤回规则。

队列满、磁盘失败、记录超限或进程崩溃，都可能造成证据缺失；记录可得的 dropped/partial/pending 状态。不得为补证据重新发送聊天或模型请求。观察故障的异常不会替换业务异常，也不改变已有成功回复。

公共只读面提供请求列表、调用详情、快照块与差异。沿用现有服务观察权限及来源约束；人工工具可通过允许的 ChatService/CLI读取投影，不能伪造浏览器来源访问GUI专用HTTP。若新增远程读取能力，需另定义实际公共契约，不能声称 SDK 自动获得访问权限。

只读查询不清队列、不flush、不触发维护或模型调用。过去未记录正文的调用保持“未留存”，不重新读活人格/记忆来伪造历史。测试报告保存引用与人工备注；正文导出沿用材料的实际可见范围。

## 与人工测试 SDK 的关系

人工工具负责部署、由人发送、关联 turn/request、收取观测投影、记人工判定和输出报告；采集 SDK 负责被测服务内部的事实记录。双方使用同一事件合同和请求标识，不各自重建上下文。

拿到事件后可以不打开网页，直接导出一次请求的有序输入、各次调用变化和人工备注。网页只是一个读取端；未来其他 harness 也能接入通用采集接口，但需要自行提供组装语义和 sink，不能仅套一个客户端装饰器就声称完成全链路观测。

## 交付顺序

1. 定义事件合同、空实现、采集接口和 Alice sink；兼容已有清单/收据查询。
2. 接主对话组装及流式/非流式最终调用边界，完成同一请求多次调用关联；人工核对真实输入。
3. 提供公共查询和网页展开，同时让人工工具按请求引用这些记录。
4. 后续扩辅助模型、细粒度排除原因与更多导出格式；实际未接入的路径明确标注。

真人验收仍遵守现有策略，不新增机器自测或模型自动评分。本轮只补充 SDK 化设计，不修改运行代码、配置或用户数据，也不宣称已经可 import 使用。
