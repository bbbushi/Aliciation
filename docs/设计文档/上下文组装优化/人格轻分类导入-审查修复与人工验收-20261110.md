## 3. 用户可见流程

新原稿：人格 → 导入新的人格（或初始化页 → 导入人格文档）→ 明确选择“原文保留＋轻分类”→ 上传或粘贴 → 准备轻分类（先预览）→ 核对原文并开始轻分类（必要时一次协议修订）→ 核对并人工处理原文块/核心/场景 → 保存预览 → 选择支持的装配模式 → 明确确认后安装。此路径仍归档旧会话。

分类失败：原文已登记时，页面保留待人工处理的候选；最近准备档案可以查看并显式继续。网络未知不重发。若输入在本地扫描前即不合法，则保留编辑框文字供用户修正，不声称已形成可恢复检查点。

已安装原文：人格 → 编辑原文分类（不调用模型）→ 保存并核对 → 应用分类（保留对话）。只更新表达封套，不归档现有会话，不收养观点，不覆盖生长小节。

原文块默认按完整单元处理。人工拆分位置按Python/Unicode字符计数，不按UTF-16长度；围栏和已关联派生样例的块不直接切开。无法确定示例配对或跨段共同条件时，使用完整原稿核对并编辑共同上下文；结构解析不构成语义完整性证明。

预算超限的未活动场景不在预览中重复返回庞大组合正文；原文块全文始终可见。活动场景才展示完整实际首次加载回执，未活动的场景不得标为已展开。

设计与实现：在设置/QQ连接的连接状态下方始终展示“启用QQ渠道”。它修改已保存绑定的channels.enabled与qq_owner.enabled，不允许浏览器提交新身份或令牌；保留其他渠道配置及原绑定。保存后立即发布至当前服务，不要求用户为每次切换重启。开关关闭拒绝新QQ请求，同时请求停止本页拥有的桥进程；终端或其他程序启动的桥不擅自终止，不宣称已确认停止。暂停连接仍只停止连接，两者分别显示。开启开关本身不连接、不发消息；停用时“开始QQ聊天”按钮明确标注会启用渠道并连接。

接口沿用GUI专用/api/connectors/qq，新增set_channel_enabled动作，精确字段为action/operation_id/enabled/session_epoch/config_revision。渠道状态返回只读开关、可否开启与原因、配置版本和epoch，不返回身份凭据。服务层仅在空闲时取得control槽，版本与epoch复核后用已有配置原子替换器保存；忙时返回busy，不排队等待后突然生效。连接器沿service→host锁顺序提交；关闭后作废待绑定回执，防迟到事件重新启用。渠道accept_locked在入库前再次复核授权，防最初鉴权与切换之间的竞态。旧页或其他配置更改拒绝覆盖，未知网络结果只查状态，不自动重发。

启用需已有完整本人绑定、有效已安装人格，并继续禁止原文人格与QQ共存；关闭不依赖人格或组件已准备好。无可写配置或不满足启用条件时，页面禁用相应操作并给出原因。存在事实同步retrieval与scoped prefix_policy，说明用户可操作渠道开关，Alice没有代切换工具。
