# 气质候选与人工审议契约

2026-11-04；W9具体设计、待裁决、未实现新候选流程。依据[人格设计§7](人格连续性与表达稳定-架构优化设计-v1.md)、[剩余工作§4](Alice剩余工作-详细评估与推进报告-20261103.md)。现有普通演化只写自我叙事/关系两节，用户显式编辑风格/情境/样本；两者都不等于已产出其他气质候选。

## 1. 权限边界与数据

首版建议所有新人格候选人工确认；普通两节演化保持现行规则，不扩大白名单。用户固定表达包括用户明确选定或保存的风格、情境条目、表达样本。无来源标记的旧格式表达默认受保护，不能根据“看起来像普通气质”自动归为可变。提出调整“正式任务中更克制”只能修改精确条件，不能顺带删除日常玩笑或整体人格。

| 字段 | 语义 |
|---|---|
| `candidate_id,epoch,operation_id,created_at,expires_at` | 宿主生成身份；operation幂等，过期不自动再提 |
| `persona_revision,target_section,target_entry_id,old_entry_digest,old_text_ref` | 精确目标与基版；旧正文仅引用仍存快照，不另留永久全文 |
| `new_text,change_kind,reason,expected_effect,risks` | 有界完整候选，change为新增/局部替换，不接收整份人格 |
| `touches_user_fixed,protection_basis` | 宿主依据条目来源判定；模型不能将fixed改为false |
| `evidence_refs[{id,version,purpose}],generation_call_id,rule_revision` | 真正用于本候选的独立普通对话事件；不能用样本、先验、来源见闻或worker正文作既有演化资格 |
| `state,decision_id,decision_actor,decision_at,application_op_id,result_revision` | pending/applied/rejected/expired/stale/invalid_evidence/application_failed；建议与已应用严格区分 |

候选最多8项、单项完整新文本2000字符、每项最多16依据为建议工程上限；放不下则too_large，不截尾。候选不进入运行人格、普通记忆或主聊天提示，不让“待审建议”事实上先改变表达。拒绝只记录有限原因；可选拒绝主题的抑制需单独数据期限，不默认永远记住用户拒绝。

## 2. 产生与人工入口

推荐首版只在用户显式点击“根据现有经历提出建议”时产生，界面先告知一次真实模型调用和可能的独立审查；无合格依据则免调用并返回not_enough_evidence。替代是普通演化后自主提议，但会新增频率、费用、候选积压和保留策略，当前不采用也不暗中触发。

生成前固定人格hash、epoch、合格依据版本和完整条目。请求中区分用户固定与其他条目，输出不能替宿主决定权限。生成后结构逐ID覆盖、未知/重复目标拒绝，再核依据资格、非压力来源及版本；模型理由只能辅助人工判断，不能认证证据语义。普通演化同期变化导致版本不符时标stale，不自动重新生成。

拟议公共 `ChatService.persona_candidates(action, payload)`，固定动作 `list/detail/propose/decide`；GUI同源 `/api/persona/candidates`，写入沿人格意图/epoch校验。propose带 operation_id、persona_revision、明确一次付费授权；decide带 candidate_id、expected_revision、decision=apply/reject。只有本机用户确认可以apply；聊天模型没有apply工具，QQ不获管理权限。以上API尚未实现。

界面并排显示旧条目/完整建议/固定表达提示/证据可用状态/预期影响，缺失原证据就不可应用；默认不选“全部应用”。涉及固定表达时，入口转现有显式说话习惯编辑，显示精确差异并重新保存确认，不能用批量候选审批绕开固定表达保护。样本新增需显示 `source_type=real_dialogue/adapted_generated` 和原始范围，禁止把最近回复自动当风格规范。

## 3. 应用、撤回和恢复

应用获得人格写锁，重核epoch/完整人格hash/目标摘要/全部依据版本。以唯一op_id沿W2/P2日志协议写快照、候选决定和实际新版本；失败前旧版不变，提交后中断只按证据补账，不能重跑模型。两标签同时提交首个CAS成功，另一返回409/stale且不覆盖。应用不重置会话、关系、思想、提取水位或开关。

普通证据失效：未应用候选标invalid_evidence，删除候选正文并留现行许可内的有限身份；已应用候选采用派生投影：依赖缺失时停止使用相应新条目，若旧条目来源仍合法且未被后续用户编辑则可回落；否则隐藏该派生部分并提示需修订，不能无条件恢复旧称呼。后续用户亲自明确保存形成新的用户编辑版本，应记录与旧派生版本的边界，不能继续把旧证据失效当成覆盖人类新编辑的理由。

撤销应用是新操作，展示应用后版本与当前版本差异。只有当前条目仍等于该候选结果且旧内容仍可用才可精确恢复；冲突进入人工编辑，不整文件覆盖。重启恢复不重复模型、不跨epoch；无法判定日志时阻止人格新写入并公开固定冲突状态，不默默ready矛盾版本。

候选保留建议为7天且不超过证据寿命，最多8个pending；到期物理删除候选正文，审计只留必要身份及状态并沿现行审计生命周期，不设隐藏永久副本。申请重新生成是新的显式付费操作，旧拒绝/失败仍保留其真实状态。

## 4. 迁移、分解和验收

旧人格仅在用户首次启用候选前显示条目分区预览，默认全部现存表达受保护；不自动重新导入、抽取或重写旧人格。新表为空，旧版忽略候选即可；回退前关闭propose并处理pending，已应用条目按实际人格版本保存，不把回退代码当撤销事实。只有用户选择精确回滚才应用逆变更，保留之后真实对话。

实施顺序：条目保护映射及只读预览 → 用户触发的生成/预算/观测 → 完整候选审议及CAS → 依赖投影/过期删除 → 日志恢复和精确撤销。各步不扩普通演化白名单。人工使用真实反复形成的习惯，观察候选可见但未生效、固定表达保护、旧版本拒绝、依据失效、两窗口并发、重启恢复、应用后局部回退；没有真实依据时记录“尚不具备场景”，不造记忆。

## 5. 待裁决

推荐“用户显式生成、逐项人工确认、7天且受证据期限限制的候选”；替代“普通演化后自主提议”须另定调用频率/费用/积压；替代“白名单自动应用”须先明确哪些条目不属于固定表达及误改恢复。三者影响新候选产品行为，不阻塞现有两节演化和W2/W4修复。当前没有默认选中任一方案。
