## 二、scoped 前缀计划（宪法设计 P1/P2）

`prefix_policy.build_prefix_plan` 纯函数构造，实测全块 1256 字符（本轮暴露：记忆/保存/搜索工具 + 2 份来源 + 来源依赖）：

| 块 | 实测字符 | 设计 §12 软目标 |
| --- | ---: | --- |
| 最小宪法 | 462 | 500–800（略低：语义完整为准，不为凑数扩写） |
| 能力事实（固定+本轮状态） | 328 | 数百字符以内 |
| 互动默认值 | 147 | 120–180 |
| 专项规则（激活 3 条） | 305 | 随暴露 |

- **专项条件表（§7.1）**落为 `SPECIAL_RULES` 固定代码表：memory_history / save / workspace / persona_scene / search / collaborator，`applies_when` 由宿主按请求级暴露判定（工具集、来源数、依赖、registry），模型不按话题猜。
- **生命周期（§6.2）**：工具集是请求级冻结的，计划在请求开始构造一次；工具轮收起工具时 system 前缀不变——已激活规则自然保持。轮中 `recall_sources` 新增来源依赖不影响：search 规则的触发条件含外部记忆检索许可与来源资料，依赖新增时该规则已在场。
- **预算（§10）**：计划随 system prompt 进 `build_messages` 的 `material_tokens`，历史预算重核算；最小宪法从不截断（预算不足走既有明确拒绝路径）。
- **legacy 回退（§10）**：生产 `build_messages` 调用方只有 `loop`（已接线）；`expression_update` 的静态准备预览继续 legacy（它组装人格正文预览，不是聊天请求）。未传 plan 即 legacy 行为，观测清单以块名忠实区分。
- **迁移表核对（§11）**：逐项去向已按设计表落位——身份/时间/诚实分寸/证据归属→最小宪法；身体/感知/权重→固定能力事实；QQ 渠道与连接状态→本轮状态行（连接步骤归产品帮助语义，见「挂账」）；记忆读法四分/「还记得吗」→memory_history；keep/release→workspace；人格按需→persona_scene；联网/阅读与见闻→search；协作/执行状态→collaborator；remember 永久化暗示→save；互动 451 字符 v1→INTERACTION_DEFAULTS（legacy 保留原版）。改写人称义务规则未入常驻——由既有 `transform_inputs` 轮内 system 消息承载（原本就不在宪法）。
- **观测（§12）**：scoped 拆块登记（`prefix:minimal_constitution` 等），legacy 整块登记 `constitution+persona+memory-area`（改造前的忠实记录，两处均不重复计费）；`context_basis.prefix_policy` 记 mode/version/sha/chars/激活与失活清单。

## 三、双维护流程（草案）

**状态机**：`queued → running → validating → committed`；可终 `failed / cancelled / stale`。同 kind 单飞行（排队去重）；进程重启把遗留 running/validating 置 stale（欠账由自动触发重估）。

**compact**（`compact_task_steps`）：
- 范围 = 默认窗口保护线之下、压缩游标之上的**普通完整往返**（经 `channel_requests` 资格：同 epoch/渠道/completed）；单次上限 `compact_max_span_rounds`。
- 生成（cheap_model）→ 接续状态 + 记忆候选（0~8 条，字段校验同提取器）→ **同一批 grounding 审查**（`COMPACT_POLICY`：用户限制须原话、AI「已保存」只记曾说、约定须用户同意原话）。
- 提交原子：新接续状态（旧状态 superseded）、覆盖轮次集合、游标、过审记忆、任务回执同事务；接续状态未过审→边界不推进、记忆不单独发布（同批原则）；提交前重核 epoch/游标/原文版本。
- **覆盖集合语义（非全局游标）**：来源/协作/未完成轮次无合同被跳过时**不进覆盖集合**，仍留在默认窗口按原规则使用——不假称已覆盖（草案 §3.3）。`retrieval.build_messages` 按集合过滤并写入 `selection.compact_boundary`。
- 接续状态注入：宿主（loop）取 `active_compact_state`（epoch+游标一致才生效，宁缺毋滥）组块传入；位于历史之前，带宿主信封（`request_id`/covered_turns/引用资料声明），计入材料预算。

**tidy**（`tidy_task_steps`）：
- 决策顺序（草案 §4）：`consolidation.run` 先行（硬期限/撤回/分层；兴趣衰减按表存在性显式传参，见「兼容修复」）→ 候选 = 普通事件记忆，**排除明确保护（salience=1 未施压）、有依赖/证据/来源/讨论链接、全部 stance** → 规则分组（标题归一 + text_score ≥ 阈值）→ 模型判读 merge/distinct + 浓缩 → grounding 审查 → 提交前逐条重核（存在/内容未漂移/资格未变）→ 事务提交。
- 合并：survivor 保留（取最早 created_at、最大使用计数），被并条目走 `forget_memory_tree`（墓碑可追溯）；distinct 留存计数入回执。
- 浓缩：仅零使用长正文；超比例/不合格按原文保留（不截尾、不失败整个任务）。
- **回退**：浓缩原文存 `tidy_batches.rollback_json`，窗口 `tidy_rollback_days`（默认 7 天）后清除本体——整理不留永久敏感正文日志；合并不回退（墓碑语义）。`tidy-rollback` CLI 与 HTTP 均可触发。

**触发与执行（草案 §5/§6）**：
- 命令：CLI `python -m alice compact / tidy / tidy-rollback`（先预览后同步执行）；HTTP `GET/POST /api/maintenance`（GUI 意图保护；action: status / preview_compact / preview_tidy / compact / tidy / cancel / rollback_tidy）——排队不等待，由执行器完成。
- 自动触发：`queue_due_tasks` 只做廉价阈值检查与排队（回复后路径挂点 + runner 每周期），默认关。
- 执行器：`MaintenanceRunner`（serve 进程守护线程，轮询 `runner_poll_seconds`）；`drive(steps, service._lock)` 逐段持锁——DB 步与聊天串行、模型调用期间锁空闲，聊天优先；意外中断的任务由 runner 兜底置 failed，不永久占 running。
- 模型不拥有维护工具；自然语句不触发清理（草案 §5）。

## 四、兼容修复（顺带，均不改变 serve 既有行为）

1. `consolidation.run(..., decay=True)` 新增显式参数：兴趣衰减仅在 `discovery_interests` 表存在时执行（表由 serve 侧协调器建；裸库路径无兴趣可衰减）。此前裸库 `python -m alice consolidate` 在无表库上会崩（既有潜伏问题，本次 tidy 先行维护同路径暴露，一并收口）。
2. `maintenance._has_links` 表存在性判定：缺表 = 无该类链接（此前初版按保守 True 处理会全量滤空 CLI 路径候选）。

## 七、挂账与边界

1. **QQ 连接产品帮助缺位**：scoped 宪法按 §7.2 把「QQ 连接步骤」归产品帮助，但本版未建帮助页/帮助索引；QQ 渠道用户当前建议留在 legacy（默认即 legacy），切换 scoped 前先补简短帮助入口。
2. **维护界面**：HTTP API + CLI 已交付；`web/` 维护面板（预览/排队/状态/回退的 UI）未做——草案 §5 的界面入口挂账。
3. **来源/协作段混合压缩**：首版 compact 只处理普通原文资格；「普通轮已被压缩、中间夹着未结来源讨论」的窗口形态待人工场景验证（覆盖集合语义保证来源段留在窗口，但接续状态与残留原文的接续体验需真人核对）。
4. **A02/A05 等既有挂账不变**；双维护不改 M01/C01 状态解释（草案 §1）。
5. scoped 模式下 `expression_prepare` 静态预览继续 legacy 宪法（组装预览非聊天请求）；如需对齐另行处理。
6. 参数初值（`[maintenance]` 各阈值）为工程起点，按真人使用校准（草案 §5）。
