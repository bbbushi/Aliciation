# 人格导入：独立 JSON 格式恢复

2026-11-07。用户批准将 JSON 格式恢复加入表达准备链，并在施工完成后用同份《爱弥斯-人格提示词.md》重新进行一次真实导入。本文记录本轮实现，前轮结构回执引号错误的原始证据不作改写。

## 接入位置和额度

表达准备中的 `_call` 先验证模型回执完整结束、消息角色、工具字段和资源上限，然后严格解析 JSON。只有 `JSONDecodeError` 进入格式恢复；已经可以解析但不是对象的回执，以及重复字段、非有限数字等严格校验失败，不交给格式模型“选择一个版本”。截断或未正常结束的传输也不补完。

恢复分两步：先在本地去除开头 BOM 或单个覆盖整份回执的 JSON 围栏，再严格解析；不会从说明文字中截取看起来像 JSON 的片段。若仍是语法错误，则在同次表达准备中最多调用一次格式恢复模型。结构生成、适配、初审、片段修复和限定复审共用这一份格式额度，每个阶段没有各自重新获得一次机会。

宿主在 `json_format_recovery.json` 中以独占创建方式登记 `reserved`，并在模型请求前 `flush + fsync`。失败、中断或已有账本均不重置额度。恢复调用关闭传输重试，恢复模型自己的坏 JSON 不再递归调用模型；本地 BOM/围栏处理仍不消耗模型额度。恢复成功后回到原阶段的结构、核对协议和语义检查，不跳过已有闸门。恢复失败则拒绝该回执，上层继续沿原必修停止、可选补全整包回退等规则处理，不因格式机制新增失败兜底。

| 额度 | 本轮规则 |
|---|---|
| JSON 格式恢复 | 同一次表达准备最多一次模型调用，独立账本，失败不退款 |
| 结构纠错 | 原有一次，格式恢复不占用；只处理完整 JSON 对象的结构问题 |
| 内容修复或可选补全 | 原有共用一次，格式恢复不占用 |
| 完整表达准备 | 原检查点规则保持；格式恢复是本次准备内部的一次恢复，不允许任意重开整条生成链 |
| 认知提取与审议 | 本轮没有扩展 JSON 恢复机制到认知链，也没有增加其续跑额度 |

## 格式模型可以改什么

新模块 `expression_json_recovery.py` 只负责纯文本合同和补丁校验，不调用模型或读写文件。宿主按完整原回执生成最多 32 个带重叠的定位窗口，提供 `target_id`、`base_hash`、原文和位置。模型只返回 `patches`，每条包含宿主窗口身份、唯一逐字匹配的小片段、替换片段和原因；不能返回整份新候选。片段最多 512 字符，最多 32 条补丁、64 处语法编辑，补丁不能重叠。

允许的原子操作收紧为四类：

- 为原有且应属于字符串正文的未转义双引号插入反斜杠，原引号保留。
- 将字符串内的实际换行、回车、制表符转为对应 JSON 转义。
- 在字符串外插入缺失的逗号或冒号。
- 删除紧靠闭合方括号或花括号之前的尾逗号。

不允许增删双引号或括号，不允许删除反斜杠，不改动文字、数字、正负号、小数点、布尔值、null、键名和其他空白。宿主核对原片段与窗口摘要，从右向左应用编辑；恢复后严格解析，并核对转义位置、分隔符位置及原本可识别的键、标量仍保有原角色。

这些规则不是万能 JSON 修复。缺整个字段、括号不配对或需要补造内容时仍会失败。坏 JSON 没有权威语法树，保留文字和可识别角色也不等于能证明有歧义处的原意；恢复只是得到可继续核验的对象，完整结构和语义审核仍是后续必要步骤。
