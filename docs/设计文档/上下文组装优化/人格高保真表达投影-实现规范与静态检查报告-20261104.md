## 2. expression-v2 最小规范

原稿登记为 `expression-source-v1`。登记保存完整输入文本、SHA256、行数以及所有非空原文块；每块含 `source_id`、同一原稿 hash、起止行、父标题路径、表列名、块类型、完整原文和结构未决标记。ID 为 `s_<hash前20位>_<起行>_<止行>`，由原稿版本和位置确定，不随模型排列改变。空白仍在完整原文中，不当作独立表达单元。

扫描识别标题、段落、列表及其缩进续行、表头/表行、示例围栏。围栏只登记资料，不执行；未闭合围栏、不能对应列数的表行保留并标未决。正文无法细分时完整保留为段落，不静默删去。单元或全文超限拒绝准备，不截到前 N 项。

包包含 `orientation`、`constraints`、`voice`、`tensions`、`reactions`、`examples` 六组及 `coverage`、源单元去向。公共条目字段包括 ID、完整范围、必要性、显式优先级、来源类型、源 ID、关联 ID、受众、用途、纯表达标记与锚角色。各组分别保存：

- 取向的默认互动、表层/认真层次和优先关系；限制的完整规则与例外；语感的句法和节奏。
- 张力的触发、初始倾向、转折、停止条件、边界；反应的触发、第一反应、后续变化及停止条件。
- 样本的场景、完整用户输入、完整回应、适用规则与来源类型。

每个源 ID 恰有一种去向：`retained`、`adapted`、`merged`、`background`、`excluded`、`unresolved`；用户编辑后可变为 `user_revised`。宿主核对集合、唯一性、目标存在、源/目标双向引用和跨用途关联完整性。合并保留全部来源；源账目完整不能证明语义无损。

基础五类场景为日常接话、轻微玩笑、接住低落、被拒绝或反对、能力澄清，均须登记覆盖或不适用依据。`covered` 必须引用匹配场景的样本；`not_applicable` 只容纳原稿不含或用户明确缩范围的依据，不能掩盖必需场景或审查删空。源结构未决、必需边界归档/排除、未覆盖必需场景都会形成缺口。

## 3. 单一 Markdown 权威与编辑

三个保护小节仍为“底色 · 气质与风格”“底色 · 情境反应”“底色 · 表达样本”。第一节容纳前四组，第二节容纳反应，第三节容纳样本。正文使用 `【类型·ID】` 和中文字段，专用字段续行统一使用两个空格加 `│ ` 的资料前缀，避免围栏或标题产生伪小节边界。机器元数据只在第一节顶部携带一条注释：

```text
<!-- alice-expression-v2:<base64(UTF-8 JSON {package,body_hashes})> -->
```

解码验证包结构、注释位置与唯一性、三节正文 hash、成品及用户修订基线摘要，以及正文是否精确等于该包的可编辑渲染。普通包要求已完成双审；显式用户配置使用独立未审语义和同版修订摘要。重复 JSON 键、非有限数及未完整结束的模型回执拒绝。运行时只从这一份人格 Markdown 取值；旁边 JSON 是审计资料，不作运行兜底。未知版本、损坏元数据、正文与元数据不同版会明确失败，不能降成 v1。共享小节解析器识别围栏，拒绝重复/有歧义标题和未闭合围栏；样本内容不能借标题越过三节保护边界。普通演化仍只允许原有两节生长内容。

GUI 展示可读正文并隐藏机器注释；下载 `.md` 保留完整权威版本。编辑仍是三节文本，不要求手写元数据。能解析的条目保留未变条目与 ID；改动项转为 `user_config`，原映射和受影响样本关联更新或失效。若用户自由文本改掉条目边界，整节作为用户配置保留，显示待处理关联，默认仅供 GUI 聊天。人工新增偏好不伪造原稿出处。新增及改动条目的旧跨用途审议同时失效，默认只用于 GUI；未改条目的已审用途保持，不能让改后私人文字继承旧 worker 纯表达资格。

已有明确修订在下一次原稿更新时作为基线合入；v1 仅以同代际已完成修订日志及当前正文摘要一致的条目确定受保护小节，不从摘要推造捐赠来源，先保留用户选择，再进行两类核对；不会把旧审议结论套在后来改过的成品上。v1 明示“未完成 v2 覆盖核对”。v2 用户修订后明确提示源文关联待核对，不冒称原稿保真仍已通过。

## 4. 准备链与门槛

准备调用使用当前配置的 `cheap_model`，不另建逐轮风格分类调用。阶段依次为：

1. 宿主扫描全文；模型构建完整结构，保留每个源单元去向。
2. 局部适配事实/权限冲突；保留各组条目 ID 与来源，记录冲突片段、替换片段和理由。
3. 应用既有用户修订基线。
4. 成品事实核对：只给候选成品、完整场景/用户输入及用途，不给原稿、适配理由或前次结论替成品自证。
5. 表达保真核对：给完整原稿账目、候选与去向，分别对源单元、条目、场景返回逐项结论；保留范围、转折和停止条件是独立要求。
6. 仅对事实或保真拒绝的受影响样本允许同次一次批量补位；不改变场景、用户输入、规则或源 ID，保留替换片段、原因和 `replacement` 来源类型。
7. 补位后重新进行两类核对；仍失败即结束，不循环到通过。只有结构、覆盖、审议、容量与版本门槛都满足，才得到可应用候选。

准备的 JSON 回执必须完整可解析；逐项结论的 ID 集合、重复、越界和理由由宿主核对。原稿/回执/提示超限都明确失败。结果状态区分 `prepare_failed`、`uncovered`、`candidate_inactive`；候选未应用时活人格不变。模型核对不是事实认证或表达效果验收。

| `max_source_units` | 600 | 10—2400 |
| `max_items` | 160 | 10—640 |
| `max_links` | 1200 | 10—4800 |
| `max_metadata_chars` | 120000 | 1000—480000 |
| `max_projection_chars` | 6000 | 500—24000 |

| `max_anchor_chars` | 500 | 100—2000 |
| `max_item_chars` | 2400 | 100—9600 |

2000—3500 中文字符只是方案给出的材料目标，不是代码强制最小值，更不是效果结论。当前没有实际获准的完整《爱弥斯》原稿，本轮未测它的投影成本或效果。

v2 按本次用途完整投影，不沿用 v1 的风格/样本前缀选择；必要边界和关联不得半句截断。准备及保存核对聊天、QQ、worker 投影容量。候选激活前进一步计算完整人格与宿主稳定规则的最低 token 成本；每次实际主模型调用前仍核对消息、工具 schema 和回复预留的总预算。估算成本是宿主估算，真实 usage 以调用回执为准。

为避免新增包挤掉刚发生的纠正，v2 保留配置内的近期完整往返窗口；更老历史仍受 `recent_turns` 限制。无法在总预算容纳该窗口、最新问题、来源规则和完整表达时，明确返回预算冲突，而不猜测哪条用户纠正可丢。这个保守取舍可能使长历史任务更早报预算不足，需真人验收容量；不宣称已解决任意长上下文。

GUI 使用 `chat`；本人 QQ 使用 `qq`，只可取得标为通用且许可用途包含 QQ 的条目。`worker_summary` 仅允许明确纯表达的语感/限制条目，不含样本、故事、普通聊天或真实关系；缺少合法投影时可为空。原有来源、历史、工作集授权不由表达包扩大，确定性失败/授权提示语义保持。

P1b 仍默认关闭。v2 锚从同一快照按显式优先级和用途选择停止边界、核心语感、一个示范；不能固定取前两条和首个特殊样本。放不下的角色/条目有遗漏记录，诚实边界无法容纳则省略整个锚并记录 `anchor_boundary_budget`，完整基础包继续使用。工具多轮替换同一份锚，基础完整表达包不依赖锚开启。

## 6. 公共服务与 GUI 契约

公共入口为 `ChatService.persona_expression_update(payload)`，HTTP 为 `POST /api/persona/expression-update`，沿用同源本机 GUI 的来源与 `X-Alice-Intent: gui` 校验。QQ 和模型没有激活、取消或回退工具。HTTP JSON 上限 1 MiB，服务继续按原文/审议配置检查，不截断请求。

| action | 输入字段（除 action） | 作用 |
| --- | --- | --- |
| `list` | 无 | 返回确实有 `source.md` 的审计来源与操作状态；不恢复、不调用模型 |
| `detail` | `token` | 返回当前会话候选/完成记录及私有逐项差异；不调用模型 |
| `prepare` | `revision`、`session_epoch`；`source_text`+`source_name` 或 `source_op_id` | 绑定当前人格准备表达候选 |
| `apply` | `token`、`revision`、`session_epoch` | 核对完整门槛后应用冻结候选 |
| `cancel` | `token`、`revision`、`session_epoch` | 取消未应用候选；不改活人格 |
| `rollback` | `token`、当前 `revision`、`session_epoch` | 只回退仍符合版本前提的已应用表达操作 |

候选回传包含 token、状态、ready、人格 revision、代际、原稿 hash、缺口、两类审议、投影长度、用户修订说明及逐项原文/适配/去向/理由。GUI 只有 `ready=true` 且 `candidate_inactive` 时显示应用按钮。关闭弹层不会激活，也不会撤销正在进行的准备；完成结果可从操作记录找回，再取消候选。网络结果不明时不自动重试模型。

入口为“人格 → 从原稿更新表达”。应用与完成页保留可折叠差异、核对详情和版本信息；“编辑说话习惯”显示本次变更范围及待处理关联。未知/损坏格式不提供三节编辑按钮。恢复冲突明确交代版本问题，不自动覆盖后来编辑。

## 7. 表达专用事务与恢复

私有候选与事务位于本机人格目录下 `expressions/exp_<32位hex>/`；候选令牌只接受固定格式，不接受任意路径。原稿与 JSON 审计均不进入版本库。操作保存 `source.md`、候选/前版 Markdown、准备计划、逐阶段审议、`op.json`；源文版本以原始 UTF-8 文本摘要绑定，换行不得在审计读取时静默改版。

`expression_update` 复用 `persona_transaction` 的原子写与数据库事务基础函数，但使用独立 `expression_update_v2` 日志、`expression_update:<token>` 数据库标记。写集只有人格文件、`persona_version` 和本操作标记，不更新 `persona_seeded_at`、`last_evolve_at`、认知或记忆水位。

提交前检查人格完整 hash、代际、版本号、预算配置、源文 hash、候选 hash 及两类审议绑定；三节以外内容不得变化。日志先记录前后版本，数据库标记提交后才原子替换人格文件。重复应用仅在已完成且当前文件/版本仍匹配时返回已有结果，不重复写入。

启动恢复纳入既有服务恢复顺序。可证明文件与数据库已是同一完成版本时收尾；文件仍是提交前版本且标记属于本操作时只撤回本操作元数据。文件不是提交前后任一版本、代际或元数据不符则保留现场并报恢复冲突，不重新跑模型，也不重放旧文件盖住后改内容。

回退是新的表达事务，只在当前文件/版本仍等于所选操作完成版本时成立；原快照 hash 损坏或后续编辑存在则拒绝。用户三节修订也走表达专用写集。这里描述的是实现路径及静态分析，不代表本轮已实际制造崩溃、并发或重复提交验证。
