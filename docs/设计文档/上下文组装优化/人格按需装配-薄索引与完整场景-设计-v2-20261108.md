# 人格按需装配：薄索引与完整场景（v2）

2026-11-08。用户授权：先出设计文档，再施工。本文先于本次运行代码修改落盘。

## 目标与边界

结构化完整资料继续作为权威资料。优化每次模型调用收到什么：常驻核心 + 薄场景索引；命中场景时，由同一个聊天模型使用 persona_load 读取完整正文。不会为每轮增加一个分类模型调用，也不通过删掉条件、停止要求或样本来“瘦身”。本次不迁移单Markdown存储，不改原稿/表达包、不实现预引导、不自动开启按需。

| 层 | 内容 | 运行时 |
| --- | --- | --- |
| 核心 | 默认取向、语感、全局表达约束，可选一个日常样本 | 每轮常驻 |
| 索引 | 本轮引用、短场景名、适用线索 | 每轮常驻，不含反应步骤、样本和依赖正文 |
| 场景 | 触发、第一/后续反应、转折、停止、例外、样本、必要依赖 | 明确命中时先读再组织回答；无关场景不展开 |

例：索引仅写“被夸赞｜被夸、被感谢时”，不会提前给出“先得意、再自嘲”等正文。普通闲聊只靠核心；“你今天好可爱”命中索引后读取对应完整场景。目录不是已读知识，读取失败不脑补。

## 分类合同与兼容

新增 `persona-residency-v3`，保留v2可用，v1继续提示额度未冻结。v3在已有字段上增加 `conditional_constraint_ids`：明确哪些constraints只随场景展开。其余constraints必须常驻，两个集合互斥；条件约束必须全部在可用于chat的场景闭包中出现，不能遗漏或藏在其他用途。

v3核心不能包含tensions/reactions及其依赖闭包，最多一个examples条目；orientation/voice至少一项，全局约束保留。核心必须闭合，不能以依赖把完整场景偷偷升级为常驻，也不能把所有场景塞进核心来绕过目录预算。模型负责语义分类，宿主验证结构/覆盖/依赖/用途/预算；全局与条件的语义分类必须在GUI原文预览中由用户核对，宿主不能声称纯规则已经判对。

原人格及v2合同不静默升级。新“准备分层”生成v3候选，用户核对并保存后才安装；模式启用仍是独立操作。full及QQ/协作原用途投影保持现有行为。

## 薄索引和引用

索引为一次公共说明加JSON行数组 `[ref,场景名,适用线索]`。全目录共享“尚未展开”说明，去掉逐行detail_state、contains、estimated_chars及重复字段名。场景名最多24字符，适用线索最多72字符，准备时提示并校验；不截断模型返回文字，不把反应过程塞进索引。

引用为 `persona:<本轮随机nonce>:<目录位置>`，宿主只查当前映射，不从模型字符串拼路径。表达/分类摘要、会话epoch仍在宿主校验及观察元数据中保留，不必每行重复发给模型。新请求新nonce；旧引用未知或失效。真实预算、准备预览和运行时用同一个索引渲染函数，预算校验采用等长nonce。

不放大现有1600字符目录额度、2200字符核心额度及2400字符读取回执额度；保存冻结，运行只能收紧。

## 重复说明合并

1. 同一条目的scope与各字段若文本严格相同，合并为一个带组合字段标签的值；只忽略首尾空白，不把语义近似的条件当作相同。
2. 全局读取说明与资料边界写一次，索引行和成功读取回执不重复整段共同说明。
3. 核心、场景和共享依赖按entry ID去重；第二场景只返回尚未提供的正文，回执标明已提供的ID。
4. 不用正则删除“看起来像重复”的条件，不自动改写人格包里的scope/触发/停止/边界。语义重复的改写需另走既有表达修订与保真审议，本次保证完整条件不误删。

GUI和观察元数据区分权威条目原文、实际运行投影、目录、候选/已读/已送入集合。相似但不相同的文字可能仍保留，这是保真取舍，不宣称全部自然语言冗余已消除。

## 准备失败与有限修订

一次用户点击最多两次模型调用：初次分类 + 初次结构/预算不通过时一次修订。每次retry=false。修订仅改core/场景归属、条件约束声明、场景名/线索；原表达条目不变。输入带完整条目、精确目录协议说明、实测错误及预算、首轮候选。输入超过既有限额则停止，不截断或继续调用。网络失败不自动重发。

每次准备先建立独立操作记录，完成后记录成功/失败：人格摘要、表达摘要、epoch、策略版本、配置额度、每次调用返回候选/原始输出（有明确长度上限）、实际核心/目录/场景尺寸与错误。异常保留错误类型，不落密钥、供应商敏感文本。最多保留最近10个操作；损坏/中断记录不自动续跑。失败记录与可应用暂存候选分离，失败不得被apply读取；已有暂存候选不因新失败覆盖。

分类调用接入既有无正文LLM调用回执；本机操作记录保存诊断，正常读取状态不发模型请求。页面刷新后仍能看到最近准备的结果、版本是否匹配、实际目录X/上限Y、修订次数。可应用候选继续绑定token及表达/分类摘要，禁止旧页面误应用。

## 观察与验收

观察器每次主调用记录：投影策略/版本、核心IDs/字符、目录字符、候选场景IDs、本轮引用映射、已读场景/条目、送入引用、正文字符与去重数量。预算预留与真正已注入的字符分别解释：预留不会凭空出现在请求正文里。

按AGENTS约定只做真实环境人工验收，静态编译/语法检查只作施工检查：

- H1：从当前人格准备，成功或失败都可刷新回看；失败显示精确实数；至多两次调用，无隐式重试/启用。
- H2：核对v3核心没有专门反应/张力，条件约束分类合理；索引短且不出现正文/样本。
- H3：无关闲聊实际SDK输入没有“被夸”反应正文；明确夸赞时模型先persona_load，后续主调用收到完整反应及必要条件/样本。
- H4：同轮两个场景共享依赖只注入一次；再次读取/旧引用/版本失效/超预算返回对应状态，不加载额外资料。
- H5：下一轮重建引用和已读集合，不把上轮工具回执常驻。历史里已公开的回答保留，不声称能撤回模型已见内容。
- H6：full回退、v2兼容、QQ用途、配置持久化与旧页冲突不回归；观察记录能区分候选/loaded/sent，不能以模式开关代替SDK正文证据。
- H7：风格及真实性通过自然对话对照；不要求机械复述样本，不宣称代码能保证模型每次必读。

## 施工顺序

先保存本文；再实现合同/渲染、运行时接线、准备审计与有限修订、GUI及存在事实；静态检查后加载服务，保留full默认，交付H1–H7人工验收入口和实施记录。

## 施工补充：近位提醒

代码接线时发现既有 expression_anchor 可独立从完整表达包选择样本/条目，可能绕过场景读取。registry生效时停用这条完整包提醒路径，以已有核心作表达引导；full继续原逻辑。观察记录分别保留 anchor_requested / anchor_enabled / anchor_suppressed_reason，不把配置请求值当实际已注入值。

运行投影保留每个条目的范围、内容字段和样本来源，原links转由宿主做完整闭包及ID账本，不在每条正文重复打印长依赖串。核心/场景/共有依赖的闭包资格仍不变。GUI逐项展示权威原文，另显示首次展开实际送入的正文和薄索引。
