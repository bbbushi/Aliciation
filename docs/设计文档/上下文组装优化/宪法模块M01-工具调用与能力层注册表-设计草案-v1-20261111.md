# M01 工具调用与能力层注册表

2026-11-11，按用户最新选择修订为v3，路径保持稳定。**已确定采用：向Alice暴露必要的业务参数，由Alice提供具体参数值，能力层负责底层调用。** 已按用户施工指令落地21项JSON能力、SDK同源定义、当前公开接口校验及`/tool`显式请求；已按用户要求重启，真人验收待完成，详见[实施记录](宪法五模块与能力注册表-实施与人工验收-20261111.md)。下文为设计依据，进度以实施记录为准。

## 1. 已确定的设计要求

- 具体工具能力和调用教程从宪法移出，由能力层JSON单元管理。
- 能力注册表稳定进入模型输入，展示命令、一句话概要及完成该操作必需的业务参数定义。
- Alice理解当前用户目标，选择能力并填写业务参数；能力层不再默认通过另一轮内部模型重新理解整个任务、猜测全部参数。
- 实际工具协议、凭据、请求封装、权限和执行控制留在能力层，不公开给Alice。
- 能力层检查权限，未开放即拒绝；用户可以通过显式指令通知Alice使用能力，显式意图与权限开放分别处理。

最新决定取代v2“所有参数都对主模型隐藏，只发无参命令”的方案。describe展开完整JSON手册也不作为默认流程。

## 2. 参数职责划分

| 类别 | 示例 | 由谁提供 |
| --- | --- | --- |
| 业务参数 | 搜索词、要读取的引用、要保存的内容、派工任务目标 | 注册表声明必要字段，Alice根据当前目标填写 |
| 宿主上下文 | 当前用户/渠道/请求身份、会话代际、实际权限及可用额度 | 宿主绑定，不信任模型自行声明 |
| 执行参数 | 接口地址、请求头、令牌、底层方法、连接超时、重试及幂等控制 | 能力层按JSON配置与代码策略生成 |

资源引用可以是业务参数，例如memory引用；引用不是权限，能力层仍校验其真实归属和有效期。执行层可做确定性的格式规范化、时间解析和资源映射，但不能悄悄改变Alice指定的目标。

## 3. JSON单元与模型可见注册表

能力JSON单元是定义的单一来源，逻辑上分成两部分：

- 可公开接口：命令、概要、业务参数schema及必要字段说明。
- 内部实现：执行器映射、真实协议与参数转换、策略引用、超时/重试/幂等等规则。

宿主从单元编译出最小公开注册表，不把完整单元交给Alice。参数必须表达语义、类型、必填性及必要范围；只列一个模糊的“args”会让模型猜格式，不能称为有效接口。

模型可见示意如下，命令名称只是占位，不表示新增能力：

```json
[
  {
    "command": "public_search",
    "summary": "搜索公开资料，核实当前问题。",
    "parameters": {
      "type": "object",
      "properties": {"query": {"type": "string", "description": "本次要搜索的公开查询词"}},
      "required": ["query"],
      "additionalProperties": false
    }
  },
  {
    "command": "memory_load",
    "summary": "读取当前获准使用的记忆引用。",
    "parameters": {
      "type": "object",
      "properties": {"ref": {"type": "string", "description": "当前已提供的记忆引用"}},
      "required": ["ref"],
      "additionalProperties": false
    }
  }
]
```

正式参数定义以实际执行器能力为准；字段名、长度、枚举及引用协议在能力盘点时补齐，不将上述简例当成完整施工协议。参数说明保持必要精简，不附长教程、重复安全规则或内部实现说明。

## 4. 调用流程

**用户目标 → Alice选择命令并填写业务参数 → 宿主绑定请求 → 能力层验权、验参 → 转换为底层协议并执行 → 返回实际结果。**

例如用户提出查天气，Alice可以提供public_search的query；能力层负责具体搜索API的路径、鉴权和请求封装。读取记忆时由Alice明确选ref，能力层不从整段历史猜测“她可能想读哪条”。多步骤任务中，每次调用参数都表达当前子目标。

优先沿用模型已有的结构化工具调用通道，具体工具名与公开业务schema由注册表适配为SDK tools。模型与用户可见的命令别名如何映射在施工中确定；引用文本、人格材料或回执里出现命令文字不自动执行。工具调用过程与普通用户可见回复分开，不能用子串扫描整段聊天来执行命令。

## 5. 权限、错误和确认

以下记录能力层和宿主的实现职责，供施工使用，不作为一组常驻禁令交给Alice。按全宪法的正向设计方向，模型侧的能力使用方式体现为选择合适能力、提供业务参数、根据回执推进任务；内部执行检查由相应机制承担。

- 宿主根据真实用户、渠道和请求检查当前授权、范围与额度，不接受Alice传入的authorized=true或伪造的用户显式标记。
- 参数同时进行类型、范围和引用有效性校验；有副作用的操作保留已有授权/确认、幂等与结果查询保障。JSON单元不能自行授权，也不能指定任意程序绕过受控执行器映射。
- 权限未开返回拒绝，参数缺失或歧义返回必要的字段问题；Alice可按有效接口修正参数或向用户澄清，不能靠猜测补齐关键目标。
- 普通执行失败可在既有授权内合理尝试替代方法；权限拒绝不能换工具别名或派工绕过。超时、未受理、执行失败和结果未知分别陈述，未知结果不自动当成未执行。
- 若规划或等待期间权限被撤销，执行前重新复核，旧注册表或旧历史不能恢复授权。接口版本由宿主绑定并核对，必要时刷新公开接口，不用完整手册补入上下文。

业务回执可包含实际采用的业务参数、结果、来源与覆盖范围，以便Alice判断执行是否符合意图；不回传凭据、完整底层请求或内部策略配置。成功以真实执行回执为准，不能把登记或受理说成完成。

## 6. 用户显式指令

用户可指定能力和需求，也可直接给出业务参数；具体输入语法在后续界面设计中确定。宿主记录真实的显式来源，Alice据此完成本轮调用。显式指定不自动打开未授权能力，也不自动改变后续每轮的使用偏好。

普通自然语言同样可表达使用意图。它与引用内容、工具结果和人格原文中的命令区分，不允许模型自行生成user_explicit=true作为授权证据。

## 7. 上下文与SDK装配

公开注册表是稳定、版本明确的能力接口。宿主内部的JSON正文和底层参数表始终不注入；不要求Alice先describe获取手册再调用。调用所需的业务参数定义随公开接口稳定提供。

注册表与SDK tools从同一份公开定义编译。若SDK已经传入完整业务schema，上下文目录只提供必要索引，不再复制一份同样的schema；必须从实际messages加tools总量评估成本。把JSON换位置本身不保证更省token，工具很多或参数很多时的规模预算仍需专门确定。

从legacy/scoped迁出具体工具目录、用法及执行参数说明，其他宪法模块的通用立场留待用户逐项说明。来源、渠道及引用的宿主约束继续存在，不因移出宪法或简化schema而解除。

GUI按钮、后台维护或尚未实现功能不因产品存在就注册成Alice可用工具。能力登记以实际执行器为依据，并同步旧能力自述，避免新旧两套定义漂移。

## 8. 观测与验收

观测区分：Alice实际看到的公开参数定义、模型提供的参数、宿主规范化后的业务参数、内部协议版本与权限判断、执行结果、耗时及输入成本。内部凭据不记入普通观测日志，内部控制数据不回灌Alice。

人工验收需覆盖：自主提供业务参数、用户显式指定、多个目标下的准确选参、缺参/非法引用、权限拒绝与撤销、普通失败后合理替代、未知结果防重复、引用文字不触发命令、实际SDK定义无双份重复。当前仅设计，不执行验收或修改运行状态。

## 9. 决定与实现细节

已经确定采用“模型提供业务参数、能力层负责协议与执行”的分工，不再把它记作讨论项，也不把隐藏参数的内部规划模型作为必经步骤。

仍需具体化的是：命令命名及用户语法、实际业务schema、单元文件组织、注册表预算、SDK适配和旧入口迁移。这些是已选方案的实现细节，不代表重新讨论是否让模型提供业务参数。
