# 对话压缩与记忆库整理：双维护流程设计草案 v1

2026-11-09。状态：用户提出方向后的设计补充，**已施工（compact/tidy 流程 + 命令面 + 空闲执行器；未清除历史或记忆、自动调度默认关）**——实施细节与人工验收清单见[实施记录](./前缀宪法与双维护-实施记录-v1-20261109.md)。

本稿与前缀宪法精简方案配套，分别解决治理提示和数据生命周期问题。它扩展了维护调度的设计讨论，不把既有未施工项改判为完成。

## 1. 两条独立流程

| 流程 | 输入 | 主要产物 | 对后续聊天的影响 |
| --- | --- | --- | --- |
| 对话压缩 compact | 一段完整、尚未压缩的合法对话及其依赖 | 接续状态、合格记忆/观点候选、证据引用、压缩边界 | 将已覆盖旧原文移出默认活跃上下文，保留最近完整往返 |
| 记忆库整理 tidy | 当前合法记忆、观点版本、时间/使用/保护标记与依赖 | 去重/合并/浓缩/降级/淘汰计划及实际结果 | 改善检索和长期容量，不直接改变当前对话边界 |

两者均支持显式命令和自动触发，使用相同校验、提交、审计逻辑。可以串联，但compact成功不等于tidy成功，反之亦然。

本稿建议“清除历史消息”首先定义为移出模型默认活跃上下文，原文按原资格可检索追溯。物理删除原文另行定义为清除操作，不让一次普通compact默默抹去证据。来源到期/撤回仍按原规则失效或清理，不因归档而延长访问资格。

## 2. 当前机制与差距

- extraction每轮检查，默认extract_every_turns=10；不是默认每轮都调用模型做提取。
- 达到条件后提取/审核仍在聊天请求的同步路径等待，是此前回复后卡顿的来源之一。
- 现有提取游标表示普通记忆处理进度，不表示这段原文已经具备压缩替代物。
- 现有前情是从合格普通原文抽取的带归属摘录，不是通用compact；它有自己的历史边界与证据格式。
- 已有记忆层级、时间复核、容量淘汰、来源依赖和见闻浓缩，可作为tidy的基础，不再另造一套互相冲突的遗忘政策。

所以需要分别管理“候选提取进度”“活跃历史压缩边界”和“记忆维护批次”，不能共用一个extract_cursor。

## 3. 对话压缩的输出

### 3.1 接续状态

保留当前目标、未决问题、用户明确限制、已达成/未完成事项，以及必要的说话者和时间。它是短期接续材料，不是每句话都升级成长期记忆。

正式改写中的“我/你”、确认条件、承诺主体按原文保留；旧AI声称“已保存”不等于实际保存，必要时关联宿主真实回执。证据不足的旧认错不能作为事实写入。

### 3.2 长期记忆与观点

只提取有持续价值、可依据原文审核的内容。事件、用户明确偏好、有效约定、AI当前观点分别保留归属：

- 用户观点记录用户怎么说，不自动变成AI立场。
- AI观点保留依据、适用条件和不确定性，不把“曾说过”当成已经验证。
- 更新观点要保留时间与被替代关系；矛盾内容不能仅因措辞相近就合并。
- 未生成长期记忆可以是正常结果；不为完成compact强行制造记忆。

### 3.3 发布边界

选择完整旧往返，保留最近若干完整轮次和正在进行的工具往返。未结事项通过有效接续状态保留；覆盖不充分或校验失败时不推进相应压缩边界。

原文版本、会话epoch、渠道与依赖在提交前重核。候选记忆、接续状态和边界按同一批次发布；无长期候选不阻止合法接续状态提交。外部资料不能借compact洗成独立普通记忆。

首版可只处理既有普通原文资格；来源/协作段必须有对应依赖与期限合同才能压缩，否则明确跳过、不假称已覆盖。当前大量来源保护对话的问题不能靠放宽compact准入绕过。

## 4. 记忆库整理的决策顺序

1. 先执行既有失效、撤回、硬期限和受众规则。它们不等待周期整理，也不能因价值高而延长。
2. 保留用户明确保护及仍有效的未结事项，维护必要证据依赖。保护与容量冲突时明确报告，不伪称无限保留。
3. 在同类、资格和保护程度可比较时，按事件/确认时间优先，再结合价值与真实使用排序，优先检查陈旧、重复和低价值项。
4. 重复内容合并到可追溯版本；长而重复的正文择要浓缩。改变对象、否定、期限、确认人、来源或承诺条件的内容不得直接当作重复。
5. 不能确定可合并时保留差异或形成待核对项；按既有时间与容量政策降级或淘汰，不把模糊语义判断伪装成精确事实。

AI自动读取不能反复刷新“用户最近确认”的时间；使用次数与用户再次确认分开。年代较久的稳定偏好可能仍有效，较新的重复闲聊不必因此优先保留。

普通冗余整理的历史版本可在既有资格和期限内回退；来源撤回/过期的正文不能为了回退保留无期限副本。整理与删除须保留必要的无正文审计，不另建永久敏感正文日志。

## 5. 命令与自动触发

命令名称提案，当前尚不存在本稿所述完整功能：

| 入口 | 行为 |
| --- | --- |
| `/compact` | 为已完成对话范围创建压缩任务，返回范围与状态 |
| `/memory tidy` | 创建记忆库整理任务，返回计划/结果统计 |
| 对应预览入口 | 显示拟处理范围、规则与预计调用；不提前改数据 |
| 对应状态入口 | 查询排队、运行、提交或失败及实际结果 |

GUI/CLI命令解析与自然语言聊天分开。模型可以建议操作；是否赋予模型维护工具另行规定，不能把提到“compact”的普通句子直接执行成清理。

自动compact综合活跃上下文压力、未处理完整轮次、距上次成功压缩的间隔和空闲状态。定期检查有新增合格范围才排队；无新增数据不空跑付费总结。接近硬窗口上限时，在下一次请求前完成所需压缩或减少可选材料，明确显示处理状态，不能假称所有压缩永不需要等待。

自动tidy综合周期、库容量、新增量和维护欠账，优先在空闲时处理有界批次。参数需要基于真人使用与预算确定；本稿不提前指定每10轮、每天几点作为固定新值。

所有触发入口共用既有许可与费用预算。显式请求也不恢复被撤销的来源权限；自动任务不能自己开启付费模型或见闻保存。应用关闭期间不假称仍有后台AI工作，启动后可按原许可合并处理欠账。

## 6. 调度、事务与聊天优先级

每轮正常回复后的路径只做廉价阈值检查和排队，不同步执行整套提取/审核。任务建立源范围与版本快照；模型计算不占用聊天的长时间写锁，提交进入既有受控单写者路径。

聊天优先于可延迟的维护。新消息不必使旧范围任务全部作废，但发布前必须确认源内容、权限、依赖和epoch仍匹配；被修改/撤回的材料不能提交旧产物。活跃请求不在生成中途更换历史边界或已签发引用，compact结果供后续请求使用。

相同覆盖范围的显式与自动任务去重合并；失败保留原对话与已发布状态，有限重试并说明原因。整理中的记录被使用、修改或手动保护时，需要重新核对相应版本。

建议状态：queued → running → validating → committed；可结束为failed/cancelled/stale。接续状态、记忆发布、压缩边界或整理变更都应有幂等批次标识，不能半写入后声称全部完成。

定期compact替代轮末同步提取的变更，应与退出时强制提取、已有前情生成、观点形成及维护watchers一起核对，避免启动/退出又偷偷跑另一套付费提取。硬资格失效检查保留。

## 7. 观测与人工验收

状态说明至少区分：原文已保存、压缩已排队、接续状态已发布、新增长期记忆数、观点修订数、跳过资格数、整理合并/降级/淘汰数。操作是否成功以宿主回执为准，不让AI根据任务受理猜测完成。

人工验收重点：

- 显式compact后上下文原文减少，但任务、限制、说话者与待办能正确接续，原文在有效资格内可追溯。
- 自动compact有新范围才调用；普通聊天不再轮末等待同步审核。
- 整理优先处理冗余和低价值内容，时间、保护、观点版本与依赖均正确。
- 来源关闭、到期、撤回及跨渠道条件在两条流程中保持；失败不推进错误游标或产生虚假完成说明。
- 聊天与维护交错、应用重启、同范围重复命令、预算不足时，既有状态与审计一致。

只采用真实环境人工测试和数据回收；本稿不授权改活库、执行删除、添加计划任务或调用模型。本轮只记录方向。
