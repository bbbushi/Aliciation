## 前置与记录

所有运行都由人工在已获授权的环境执行。需要中断、低预算、格式异常或旧版本样本时，由部署负责人建立真正隔离、可处置的配置/数据库/人格目录，不以只改 `--config` 冒充隔离，不操作日常活人格制造故障。保留原稿、当前人格和候选的私有证据；不把角色原文或真实对话正文提交版本库。

每组固定并记录代码版本、源稿 hash、人格 revision、session epoch、模型/接口/采样设置、总 token 与表达预算、P1b 实际值、渠道许可与历史背景。基础观察保持 P1b 关闭；本补充不自动开启 QQ、工人或模型。没有实际发生的分支记“未覆盖”，不以模拟、机器评分或静态检查代填。

## GUI 与恢复记录补充

1. 准备页先读“保留策略”，展开“准备时的表达 → 候选表达”，再读“原文 → 适配 → 排除或缺口”。比较的是准备时冻结的当前表达；准备后另页编辑应触发版本冲突，不能把该对照误认作实时当前人格。
2. 正常回退后，页面保留原更新 token，单列回退 token；“查看回退记录”和“查看原更新记录”应可追踪关系。刷新后结果相同。旧历史记录缺少差异时应明确显示缺失，不伪称已有保护证据。
3. 准备/应用/回退响应不明时先查记录，不重新准备凑通过。关闭弹层不取消已经进行的模型阶段，也不激活候选。后台单阶段传输重试与“重新准备整条链”分开记录成本。
4. 当前版本已被后改、会话代际不同、回退证明不完整时停止操作并保留记录。不要删除审计、重新初始化或重做导入来掩盖恢复冲突。

## 未改取舍与停止条件

v2 仍保护配置内完整近期往返窗口；未实现自动语义判断哪段历史可以裁剪。材料增加可能更早出现预算拒绝，需沿原 M08 记录频率与实际影响。此限制与 R6“连稳定材料都放不下时不得保存”不同。P1b、真实《爱弥斯》原稿成本/效果、长期稳定性继续按原清单执行，不据本轮静态修复宣布通过。

任一数据丢失、未授权共享、错误回退关系或版本覆盖迹象出现时，先保留私有证据并停止相关验收分支。确需回退且满足当前版本前提时使用表达专用回退；有后改则交人工核对差异，不能强制回放旧文件。
