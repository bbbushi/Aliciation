## 1. 结论

这次新版路径确实生效，人格并非没有注入。当前20轮均记录interpretation.version=1、assembly_version=4、registry生效且无fallback；核心1073字符、目录301字符。8轮调用persona_load，共读取14个场景引用（含重复场景）；场景频次：日常问候5、并肩分担2、沉重追问3、低落与逞强4、战斗英雄腔0。前面的口头进度“9轮读取”经统计更正为8轮。

真正突出的问题是表达与角色事实仍混在同一块中获准采用；另外存在空读取、反应场景混装、过度解读用户、把AI先前自述续写成现实等问题。口吻特征能看见，但不能因此宣称人格语气或真实性验收通过。

## 3. 材料采用中的具体问题

### 3.1 六层标注不等于完成了混合内容处理

身份接管原句b0001和压制身份披露的b0017片段确实被剔除。背景b0003–b0008作为参考留存，没有整段进入常驻，这些是有效改进。

但b0010被归入“性格分析/表达习惯”，作为expression直接常驻，仍包含“必须演出来”“爱人的方式是隐瞒”“把真相砸碎”等内容。b0011把口语/节奏与隧者兵装、特定角色台词和世界观关键词混装。b0016作为表达原文保留“人都不在了”“生前”“小屋、炉火、汤”等设定。b0013原样采用“半真半假…信任极深时才说真话”。

当前宿主只对标为人格设定/背景的整块禁止直接采用；其他块主要依赖理解器的语义选择。故只要一个混合块被标成表达，其内部角色事实、掩饰策略和现实行为仍会进入模型。这是本次设计落实覆盖不够，不应归因于用户分类不仔细，或简单增加完整事实审查链。

### 3.2 常驻示例在教“编一段日常”

b0019的问候样例描述“昨天钻进学院系统…改食堂菜单”，被当作纯表达示例常驻。它既示范了语气，也示范了通过虚构日常、最后反问用户来接话。

没有证据证明“酱油面”和“窗户”逐字来自该样例；合理推断是这种答复结构与样例、现有模型习惯共同作用。现有代码没有隔离样例里的事实槽位，因此不能只用“样例不是经历”的总说明期待模型自行完成全部转换。

### 3.3 目录去重正确，但目录发布范围仍有问题

日常问候scn001只有b0009和b0019，二者都已在核心。当前保留了这个目录入口。已留存的#25请求真实回执明确为status=loaded、text为空、already_present_ids列出二者；历史装配元数据表明该场景共被选择5次。

空正文是去重的正确结果，问题在发布了“没有新增材料”的可读入口，消耗选择和读取预算。不能把5次loaded计成5次新增内容注入。

### 3.4 场景选择不能控制块内其他情境

scn004“低落与逞强”引用整块b0016。实际#25请求回执除低落、逞强外，还包含被夸、死亡、战斗、独处和吃东西等全部反应。#33只说“也不是”，模型又读了“沉重追问/低落与逞强”，随后把猜错解释为用户藏着重事。

这同时暴露了分块过粗和目录触发过宽。保留原文不意味着必须把整个反应列表当作最小读取单元；需要保留共同条件，同时按真实情境拆开可独立使用的条目。

## 4. 记忆与前情侧的归属

当前记忆把相关条目写作“AI曾说报幕腔…”“AI自述窗边风大…”，前情也明确“用户曾说/AI曾说”。没有发现这批记录把煮面或风声直接认证为客观事实。

因此不能把问题主要归咎于记忆库编造。更直接的失效点是回复生成时顺着旧AI自述继续补写，未保持“历史发言”和“实际发生”的区别。已有引用归属是有效保护，但不会自动保证下一轮正确使用。

## 5. 建议优先顺序（尚未施工）

1. 所有层统一判断内容如何采用，不能仅以层名判定安全直用。对样例、爱好和反应中的具体角色事实、现实行为、自我掩饰策略做片段级处理，保留有效语气；必要时形成短派生候选，仍由用户预览，无须恢复整份重建与多轮审查。
2. 优先提供不靠虚构亲历、不固定以反问收尾的常驻日常样例。保留原稿作为依据，清楚展示派生差异，而不是默默改原文。
3. 目录只发布至少有一块核心外有效正文的场景；反应列表按情境拆分，共同条件显式关联。加载空正文如实呈现，但不把它当装配收益。
4. 对“用户明确否定/说随便问问”的互动采用朴素解释；猜错后收回猜测，不再追加隐藏心理。相关节奏优先在可采用人格习惯与示例中表达，不把宪法重新堆成细碎禁令。
5. 若需要谈论捐赠角色，另提供带来源的背景参考读取；“作为资料知道”与“作为自己身份采用”分开。当前没有该入口，不能声称AI本轮已知整份背景。

真实性优先于加大人格注入量。现有核心已经引出了明确台词和语感，继续整体增加背景或强制每轮读取，可能放大上述问题。没有受控对照证据支持“宪法太严导致这批人格无效”这一结论。
