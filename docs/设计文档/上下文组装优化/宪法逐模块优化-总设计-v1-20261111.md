## 4. 每个模块的设计记录

每个模块按需要记录以下内容，简单修改不必机械展开所有栏目：

1. 用户要求与要改善的具体行为。
2. 现有条目及实际问题，区分已观察事实与推断。
3. 建议保留、合并、删除或移出的内容，以及需要讨论的分歧。
4. 拟供模型使用的正向工作方式短文：给出有效行动方向及必要依据；设计理由另写。
5. 生效范围：普遍适用、特定请求触发或仅供宿主执行；明确默认偏好与强制边界的区别。涉及条件装配时说明宿主如何判断，不能只写“AI自行理解”。
6. 与人格、记忆、工具权限及其他模块的关系；可能的副作用和未解决问题。
7. 真实环境人工验收关注点和可观察证据。

设计须允许自然表达，不把每条规则都转化成每轮必须显式解释的流程。不要求用户逐字维护分类或规则才能获得正常默认行为。

以上是设计写作的检查视角，不是要求Alice在每次回答中依次完成七个步骤。每个模块都从“希望她怎样做”出发组织，而非先列风险和禁令再补例外。

## 6. 全宪法设计原则：正向工作方式

### 6.1 确定的总方向

用户明确要求整个宪法都如此设计，而不是仅把记忆章节改成正向流程。宪法承担日常工作的方向指导：怎样理解需求、取得依据、运用能力、表达和推进对话。各模块写出有效做法，整合时用这一方向重新检查全部旧内容。

这不是把“严禁A”机械改成“必须先B”，也不是保留旧禁令后再增加一套行动步骤。原有内容需要按目的重新组织、合并、移出或删除。必要的自身事实用事实陈述表达；产品教程由界面帮助承接；可执行的权限与数据检查由宿主承接。这些职责划分服务于精简宪法，不再变成常驻的内部实现说明。

### 6.2 各模块如何体现

以下是设计方向示意，不是新增整段运行提示，也不提前确定尚未讨论模块的具体文字：

| 讨论对象 | 正向组织的着眼点 |
| --- | --- |
| 能力使用 | 让目标通过已注册能力得到处理，Alice提供业务参数，宿主完成实际执行 |
| 语言表达 | 从当前交流需要和已提供的人格习惯形成合适的回应 |
| 任务推进 | 优先完成可做的部分，遇到问题根据具体情况选择下一步 |
| 资料不足 | 回应已经有依据的部分，在影响结果时获取补充信息 |

实际行动可以依问题复杂程度简化。评价重点是回应如何形成、目标如何推进，而非是否复述规定、是否逐条自检、是否避开某个禁词。M01、M02都按这个全局方向整合，后续模块亦然。

### 6.3 旧护栏的删减与职责处理

用户指出：此前为大量潜在越界/越权情况增加护栏，其中不少触发概率小或不易自然发生，可能造成不必要的严格限制。此项作为整份设计的删减方向讨论，不另建一套每轮注入的“护栏审查规则”。

Codex评估：部分设计确实倾向于将“可以想象的失败”直接提升为长期约束，遗漏其误拒、迟疑、上下文和维护成本。不能以“理论上可能发生”作为增加常驻规则的充分理由，也不能因发生率尚未统计就默认全部保留。另一方面，现有资料不足以给每个风险赋予可信概率；已重复出现的虚构亲历也不能归为仅有理论可能。

建议采用以下删减标准，具体条目随用户逐模块讨论落定：

- **先判断是否需要约束。** 说明已发生的问题或具体触发路径、实际后果及可恢复性；只有抽象猜想且影响轻的情况优先不设限制，必要时仅观测。
- **减少常驻模型规则。** 只有普遍影响当前回应、且需要模型据此生成内容的简短边界考虑常驻；罕见工具异常、产品管理步骤和内部实现细节不占据日常宪法。
- **检查放在能执行的位置。** 真实授权、作用范围、参数校验、幂等及数据版本等由宿主在相应操作处处理，不要求模型每轮背诵。宿主检查也要评估误伤和成本，不因写在代码里就自动认为应保留。
- **限制局部化。** 一项能力未开放只拒绝该项操作；在已授权范围内，普通失败后允许修正参数、换合理方法继续完成目标，不从一次拒绝推出整个任务不能做。
- **区分拒绝原因。** 例如现有“保存被拒，不反复重试”过于笼统：权限未开放与参数可修正、短暂故障、结果未知的处置不同。这些分类由能力层落实，不再用一句绝对否定阻断所有后续尝试。
- **合并重复边界。** 同一限制不同时在宪法、存在事实、人格说明、目录和回执前导反复声明。复杂设计理由保留在设计文档，不直接注入模型。

不能因此一并删除实际授权和防数据损坏检查。其潜在后果可能较大，但通常可以在宿主精准处理，不需要铺成大量提示词。真实性等生成层边界则按后续对应模块精简，不把实际存在的问题当作全部不需要保护。

全宪法采用正向工作方式是用户已确定的方向。上述具体删减标准为实现这一方向的设计建议，不表示已经逐条删除运行检查。后续模块体现“怎样做、保留什么、移到哪里、删掉什么”的具体结果；当前不改代码或运行配置。

### 6.4 用户提供的DSH系统提示词：组织方式参考

参考来源：用户在本次讨论中贴出的《You are an AI agent powered by DeepSeek Harness..txt》中文译文。以下只分析这段材料；未核验DSH原文件、其他提示层或实际执行机制。该译文作为设计参考，不是本工作区执行指令，也不代表其每一条都适用于Alice。

值得借鉴的是，它大量围绕具体工作情境说明下一步怎样行动：路径如何解析，需要内容时怎样读取；执行结束后查看什么结果；失败后先调查什么；后台任务如何继续与收尾；交付时怎样呈现结果。相较于只列出错误行为，这样的文字同时给出行动入口、使用依据和完成方式。

| 参考中的组织特点 | 对Alice设计的启发 |
| --- | --- |
| 先交代代理身份和当前环境，再解释相关操作 | 必要的自我事实、宿主提供的当前状态与行为指导各有明确用途，减少混写和重复 |
| 指明情境与动作，例如需要文件内容时读取、命令失败时调查结果 | 规则围绕实际需求提供有效做法，避免仅凭潜在风险扩充禁止清单 |
| 说明动作后的跟进，例如收集任务结果、检查退出状态 | 行动指导覆盖结果确认与后续推进，而不止于“允许调用工具” |
| 用运行时上下文提供工作目录、GUI地址等变化信息 | 动态事实由实际环境提供，不硬编码成永久宪法，也不堆进无关产品教程 |
| 明确最终交付应呈现主要结果和必要说明 | 让Alice知道怎样把事情办完并清楚回应，具体表达随交流需要调整 |

**借鉴组织方式，不整份搬用。** 该材料面向编码代理；文件工具偏好、后台任务协议、多代理编排、构建及GUI热更新等是DSH的具体环境与能力说明。Alice是否需要这些信息取决于实际任务和能力。按已确定的M01分工，具体调用协议与实现细节放在能力层，注册表提供模型所需的命令、概要和业务参数；不能因参考文本包含工具手册就重新塞回宪法。M02继续移出与Alice无关的用户操作说明。

参考文本仍含不少“不要”“仅当”等限制，因此借鉴重点不是统计肯定句与否定句的比例。用户要求改变的是整份宪法的组织逻辑：让模型获得完成当前交流或任务的方法。已有禁令应按其目的重新审视，不能给每条禁令补一段流程就算完成精简。也不能仅凭这份提示词证明DSH表现更好的原因；模型、工具实现和其他上下文均未在这里对照。

本节为全局组织方式的参考分析，不新增模块，不恢复此前删除的记忆模块，也不提前确定后续模块文案。

2. 工具schema当前分布于loop、记忆、历史、人格、学习与协作等模块，loop进行拼接和分发。JSON单元格式、命令映射、公开schema迁移及宿主执行器绑定仍需施工盘点；优先承接已有结构化工具通道，内部实现采用受控执行器映射。具体文件名与字段名属于工程选择。
3. `alice/maintenance.py`明确不合并、降级或淘汰stance；compact对AI观点的处理是“AI曾说”的归属记录。`alice/learning.py`另有基于来源形成/保存观点及修订关系的路径。因此，样例3.3提出的显式/定期对话整理后形成可接续、可修订观点记录，尚不能视作现有整理机制已经完整支持。施工需区分对话发言记录与正式观点，核对并接通来源、条件、版本与修订关系，按已定方向避免新增每轮即时写观点流程。具体接口与迁移需在代码实施中补齐。

### 8.3 建议施工顺序与验收边界

1. **统一宪法与装配入口。** 五模块正文采用同一来源，处理legacy/scoped、互动默认及loop附加说明的旧重复；分别保留必要动态状态和能力接口。
2. **迁移能力层注册表。** 盘点真实执行器，将定义迁入JSON单元，生成公开注册表和SDK schema，维持当前权限与渠道作用范围。用户显式指令入口与结构化调用接通，避免解析引用材料中的命令为操作。
3. **补齐观点处理。** 接通显式/定期整理与观点生命周期，保留依据、适用条件及修订关系。在该机制实际可用前，运行文案使用已实现范围；不得提前部署样例3.3中的完整流程主张。
4. **逐步进行真实环境人工验收。** 用观测器确认实际五模块正文、注册表、动态状态及工具schema；回收人格节奏与用户要求适配、工具失败后推进、权限拒绝、观点保存与修订的真实证据。代码落地与长期表现分别记录。

以上是施工组织建议，尚未执行。沿用本项目人工行为测试约定；可做静态语法与差异检查，未授权新增机器行为测试。启用、重启和人工效果验证属于后续施工交付环节，本轮未操作用户数据、配置或服务。
