# 记忆保存失败：外部来源路由与开关诊断

2026-11-08。用户要求定位Alice记忆存不上；只读真实对话/工具回执、数据库状态、相关保存代码与非秘密开关。未改配置/记忆、自动启用见闻保存、重跑模型或重启服务。

## 已核实

当前库44条turn、13条memory；其中自动提取batch1从原文1–18提炼4个候选，来源审核通过3项写入ID11/12/13，另一项因把“这轮不问”扩大为“这轮起不再问”被拒。其余10条不是本批新对话记忆。数据库不是完全无法写入。

原文19–44共26条turn都带source_turns附件标记；普通turn表存来源保护影子，正文仍在对应有资格的来源附件中。普通自动提取明确排除这些source_turns；extract_cursor已推进44，不会把外部附件在以后退出/重启时偷偷当成普通独立记忆。此路径没有产生新的普通提取batch。

最新用户#43说“压缩一下再存？”。AI#44称把要保存内容缩为用户让她慢慢寻找选择人格的理由、没有外部来源，仍返回模糊错误。实际宿主为本轮绑定7个来源packet IDs；文本没写网页链接，不等于本轮没有来源依赖。

保存设置读取discovery_config：remember_observations=false、save_memories=false；来源写入账本为空。最新request8796f45e866548c5ab48d4a7baeddc44的真实后续tool消息为：“见闻未保存：来源资格、字段或用户配置的容量不允许。”

## 路径与直接阻断点

retrieval.tool_remember发现source_context.packet_ids非空 → 调用save_learning，不走普通insert_memory。

learning.save_learning在字段/长度/容量检查之前，检查remember_observations；关闭时立即ValueError“未开启见闻保存”。tool_remember捕获ValueError/UnicodeError后统一回传上述模糊消息。故当前直接阻断是见闻保存未开启，没有证据表明是容量不足。压缩19字或删除关键词都不会改变这个先行检查。

普通用户自己的发言与外部资料被整轮同样保护，也解释了为何用户觉得“我只是让她记我们自己的事，怎么仍存不了”。不能为方便而简单解除整轮来源保护，否则会把网页/协作衍生资料洗成永久普通记忆。

## AI回复中的错误

- 把没有足够细分的工具回执推测成容量原因，建议用户调整容量，没有依据。
- 声称本轮“没有外部来源”，与宿主绑定7来源的事实不符。模型拟保存的一句话没带外链，不代表宿主来源依赖为空。
- “对话还在我就还记着”“稳存要用户手动”等说法没有精确交代检索/读取资格和窗口范围，不能保证未来可访问。

## 建议修复（本轮未施工）

先返回可区分原因：未开启见闻保存、无有效来源、来源不允许记忆、额度不足、字段无效等；不向模型泄露密钥/供应商错误。避免压缩重试的错误方向。

独立用户表达若需保存，应设计绑定用户原话与turn/epoch的独立准入，仅允许确实独立、无外部或协作依赖的内容进入普通记忆；不能由AI一句“这不是外部资料”取消宿主依赖。现有discussion_user捕获是其他受限用途，不能未经对应准入直接当成普通记忆授权。

若用户确实希望保存网页见闻，可通过原设置显式开启并受原有来源、期限和额度约束；这不应被当作保存普通聊天偏好的必要前提。本轮未自行开启。
