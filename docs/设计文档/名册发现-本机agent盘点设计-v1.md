# 名册发现：本机 CLI agent 盘点设计 v1（scan_local_agents）

> 2026-11-03。用户提出：Alice/宿主目前无法自动检查本机装了哪些 CLI agent——每次接一个新干将都要人工知道、人工核验、人工注册。本设计补上"发现"这一环，**扫描≠注册**：盘点只读无副作用，每一步放行都是用户的按钮。
> 依据：[协作者调度-设计 v2.1](./协作者调度-设计.md)（招募权在人类/"她只能表达需求"）、[claude 直调正式设计 v1](./claude直调-正式设计-v1.md)（claude_gate_v1 先例）、DSH adapter.py 的固定路径安装元数据先例（describe() 只读模式）。
> 状态：设计稿 v1，待用户评审；实施仍限 ytq（Claude 直调线内）。

## 〇、一句话

宿主提供**只读本机盘点**：扫固定位置的常见 agent CLI，对每个候选做无副作用核验（--version/--help 旗子抓取），产出候选报告——**报告之外零动作**；注册/试跑/启用仍走既有五道闸（扫描→候选→人工核验→注册→启用），全程用户的按钮。

## 一、为什么是现在、为什么这样切

1. **真实空白**：现流程里"知道装了什么"完全靠人（你告诉我装了 claude，我手动跑 --version）；DSH 的 adapter 只查固定路径的安装元数据，不扫 PATH。第二个干将（claude）进来时这个摩擦已经真实发生；
2. **原则不动**：招募权在人类（v2.1）——自动扫描+自动注册等于 Alice 自我扩权，Super-agent §8.4 的警告在此方向同样成立；注册试跑必须人工主持（astra 评审 6.3）。所以扫描（信息）与准入（权力）必须拆开；
3. **价值**：把"人类招募权"的信息负担降下来——你不用记得装了什么、在哪、什么版本；看一张清单点按钮。Alice 的角色是**转述者与建议者**，不是执行者。

## 二、五道闸（权力链全在用户）

| 闸 | 动作 | 谁触发 | 副作用 |
|---|---|---|---|
| ①扫描 | 盘点固定位置 + 无副作用核验 | 用户按钮（或 Alice 提议→用户批准） | 只读；候选 CLI 各跑一次 `--version`（限时 5s） |
| ②候选 | 报告呈现：名称/版本/无头能力/权限旗子/判定 | — | 无（只是报告） |
| ③核验 | 对选中项做完整 D0（无头试跑、权限旗子实测、输出形态） | 用户勾选→启动 | 受限试跑（同 claude 接入时的 D0，付费项须用户明示） |
| ④注册 | 写入名册（per-worker 政策表/manifest 声明） | 用户确认 | 账本写入；**默认禁用** |
| ⑤启用 | 政策行 enabled=1 + 权限档接受确认 | 用户在设置页 | 此后才挂载工具 |

Alice 在②后可读报告向你转述建议（"机器上有 claude 2.1.278，支持无头和权限质询，要不要核验后请进名册？"）——**转述不产生任何闸的推进**。

## 三、扫描范围（v1 白名单，固定+保守）

```
PATH 上找已知 CLI 名单：claude / codex / gemini / aider / cursor-agent / opencode / qwen / dify…
（名单是常量表，不在运行时可写——防"扫描器自己被改去扫任意路径"）
固定根补充：/Applications 与 ~/Applications 的 .app 内 CLI（按 bundle id 白名单）、
           ~/.local/bin、/opt/homebrew/bin（PATH 通常已含，重复无害）
每个候选：
  which 定位 → realpath（防同名脚本顶包）→ lstat 归属检查（非当前用户可写目录内的优先报"需人工"）
  --version（timeout 5s，无网络假设，stderr/stdout 有界捕获 4KiB）
  --help 抓旗子表（正则白名单：-p/--print、--output-format、--permission*、--mcp-config、--add-dir、--max-turns…）
  判定：headless_capable / needs_review / not_an_agent（退出码+输出形状启发式）
```

**不扫**：任意目录遍历、文件名内容匹配、注册表/spotlight 全盘索引、网络探测（mDNS 等）、任何形式的"执行发现"（跑 `--help` 之外的命令）。**不进** QQ 渠道（盘点是 GUI-only）。

## 四、实现落点（贴现有形态，最小增量）

| 件 | 落点 | 说明 |
|---|---|---|
| 盘点器 | `alice/worker_discovery.py`（新，纯标准库） | `scan() -> 报告 dict`；CLI 白名单+核验启发式；结果**不落库**（内存报告，GUI 会话内有效） |
| API | `GET /api/worker-inventory`（GUI-only，同 worker-permissions 的 intent 检查） | 触发扫描（服务端限时 30s 总预算，逐 CLI 5s） |
| GUI | 设置→协作者：新增"扫描本机 agent"按钮 + 候选表（名称/版本/能力/判定/【发起核验】） | 复用协作面板样式；候选行的核验按钮指向③（走既有 D0 流程，本期人工主持） |
| Alice 转述 | 事件 `inventory_ready` 落 worker_events（scope=gui，文本摘要） | 她可读可建议；不含可执行字段 |
| 名册衔接 | 核验通过→注册仍写 per-worker 政策表（claude_policy 模式：每工人一表或统一 registry 表，随 P3 泛化定） | 注册默认禁用不变 |

**安全评审点（实施前必过）**：扫描器命令全部固定 argv（版本/帮助旗子白名单），无任何用户输入拼接；候选 CLI 的 `--version/--help` 输出按不可信数据处理（截断+过 safe_text，防终端转义注入 GUI）；盘点报告不写入任何模型可直接消费的持久上下文（只事件文本摘要）。

## 五、与既有线的边界

- **不替代 D0**：扫描只回答"有什么、长什么样"；能不能派工仍是核验+注册+启用的事；
- **不碰通道协作者**：QQ daemon、桥插件不在盘点范围（它们不是本机 CLI agent）；
- **不做热加载**：扫描结果与会话内报告，不自动挂载任何工具；新 agent 进名册要重启生效（同 claude 先例）；
- **Claude 直调线内先行**：实施挂 ytq，不合 main；P3 泛化时与"注册表多行化"一起收编。

## 六、验收（人工，GUI）

| # | 场景 | 必须看到 |
|---|---|---|
| N01 | 点"扫描"→ 报告列出本机真实安装（claude 应出现，版本正确） | 只读、≤30s、无注册发生 |
| N02 | 伪造 PATH 顶包脚本（同名 claude，行为怪异）| 判定 needs_review/归因异常，不给 headless_capable |
| N03 | 扫描报告 Alice 可转述（问她"机器上有哪些 agent"） | 只述报告内容，不自行推进任何闸 |
| N04 | 全程无任何政策表/名册/工具挂载变化 | 扫描零副作用实证 |
| N05 | QQ 侧请求盘点 → 拒绝 | GUI-only 边界 |
