# QQ 自然分条回复：实施与人工验收

2026-10-30。用户已批准[精简方案](QQ自然分条回复-方案与审核.md)并授权开工。本轮在 `codex/qq-natural-replies` 实施，起点为本地 `620219d`；尚未提交、推送或合并。

## 已实现的行为

- 默认 `delivery.reply_split_mode = "natural"`，旧配置省略此项也启用。优先按自然段分条，极短承接与相邻内容合并；长段按完整句群选择边界，短回复仍是一条。
- 最多3条，单条仍不超过1000 Unicode码点及4000 UTF-8字节。先合并／重新分配相邻内容，无法容纳时保留连续安全前缀，明确提示后文未发送。代码、列表项、链接、引号和组合emoji均保护；不因超限静默删除一个字素后继续后文。
- 使用现有串行发送器，最小间隔默认1秒，不模拟随机打字。下一轮QQ输入先排队；`/cancel`仍只取消尚未提交的输入。
- 一轮只有一份完整核心回复，分条不调用模型、不新增逻辑回合、记忆提取、工具或P1任务。自然分条本身不改核心接口/schema；随后搜索来源联动增量增加原reply_hash与发送资格检查。来源仍有效时网页展示完整回复，来源失效后依原保留规则显示占位。
- 网页状态只说明已登记片段的已确认／失败／未知，明确可能是摘录或部分发送；不伪造完整送达、已读或精确n/N。用户主动发 `/status` 时，桥可用本地账本报告各段数量。

每轮在首发前固定正文、序号、hash和规则快照。已有计划不能因为重启或配置变化重新切分。每段最多3次派发预留，明确401至多刷新一次，明确429有限退避并对全部发送／通知共享冷却。回执重试不消耗派发次数，也不调用QQ。

平台成功后仅回补状态；网络不明、5xx或缺有效消息ID记unknown并停止该轮尾部。重启发现sending同样保守unknown。明确未尝试的尾段直接ready→failed，不补造sending。实际QQ请求前重新检查剩余计划的窗口预算；用户停止后不再提交新输入。已在途请求仍无法撤回，不承诺端到端恰好一次。

同日搜索来源联动已补入 `alice/channels.py`、`alice/store.py` 和桥：生成事务保存不可变原reply_hash；ready只登记hash，每次实际QQ尝试及401／429重试都强制重交sending核验来源。来源到期／清除／撤回QQ范围后，仅停止未发尾段，历史真实终态仍可按原hash落账，不能用显示占位核hash。结果增量返回reply_hash／delivery_allowed，旧请求hash兼容和有效平台消息ID要求见[技术参考第7.3节](QQ自然分条回复-技术参考.md#73-来源资格与原回复hash搜索功能联动2026-10-30)。固定计划、seq、节奏和unknown不重试规则保持。

## 生效与回退

本轮没有读写真实 `user/`，没有干预当前服务或桥。**文件已修改，不代表正在运行的桥已经加载新代码。** 由用户在QQ回复收尾后暂停桥、确认退出并在本机妥善备份账本，再启动新桥。仅需重新启动QQ桥加载这些addon模块；网页刷新后读取新的状态文案。

上段“仅重启QQ桥”适用于自然分条模块；加载后续来源联动还需要Alice核心加载更新，并与新桥配套。核心首次打开旧库时增量添加可空reply_hash列，不改既有固定分段。不能用旧桥的sending去重行为承担新来源撤销契约；本轮没有执行任何启停或数据库迁移。

首次启动新桥才实际迁移v2账本。已有分段按原text/hash/seq认领为legacy，不猜旧规则和截断情况；发送未知或失败的旧计划不会恢复成待发送。新建 `ledger.identity.json` 用于识别单独丢失的state文件；整个目录同时丢失无法自动识别，禁止删除状态目录来重置恢复。

需要恢复原有长度分条体验时，设置 `reply_split_mode = "length"` 后受控重启桥，仅影响之后的新计划。不要直接降级代码、手改账本版本或恢复发送前旧备份继续发送；旧程序不理解v2账本及新配置键，会安全拒绝。旧计划遇到更严格的泡数／窗口限制时停发，不能重切绕过。

## 验证边界与人工验收

本轮仅做静态源码交叉审查、JavaScript语法检查和Git差异检查；没有执行机器自测、冒烟、假模型、真实模型调用、QQ发送或服务启停。**真实体验与故障恢复均尚未人工验收。**

人工在隔离副本与真实QQ中重点核对：

1. 短回复保持一条；两三个自然段实际发成不同气泡，句子完整、顺序正确。
2. 多段超预算时先合并，超长有明确提示；引号、列表、代码、URL、数字、组合emoji不被拆坏。
3. 连续追问不穿插上一轮气泡；暂停期间不再提交排队输入。
4. 首条成功、后条失败或结果未知后，成功的不重发，尾部停止，网页仍有全文。
5. 受控重启及旧账本迁移沿用冻结正文／seq；sending转unknown，配置变化不重切旧计划。
6. 真实限流／鉴权错误下重试有界；过期不转主动消息，冷却与重启间隔有效。
7. 一轮仅一对用户／助手历史；分条不增加提取入口、工具调用或P1许可消费。
8. 按[搜索实施 S09](搜索功能-实施与人工验收.md#人工验收记录待执行)覆盖来源失效：已确认首段保留，冷却／已知失败重试前撤销时未发尾段停止；原文变占位后真实确认或unknown仍可补报；固定计划不重切，未知段不重发。真实401／429条件未取得时标记对应分支待验。

完整故障剧本见[技术参考第13节](QQ自然分条回复-技术参考.md#13-真实环境人工验收清单全部待执行)。未实际覆盖的场景保持待验，不以语法检查替代人工通过。
