# 协作者调度设计（manifest 标准 + dispatch_worker）

> 依据：用户 2026-11-01 讨论定案的**分层能力观**——薄能力 Alice 亲历（discovery_search 检索循环，PR#13 已交付），重/危/常驻能力**委托**给外部 worker，本稿定义委托侧的机制。接 [联网能力-设计](./联网能力-设计.md) §二（能力边界）、§六（信任边界）与 [对话内检索-设计](./对话内检索-设计.md) 的对话内工具先例。
> 状态：设计稿 v1（2026-11-01），待用户评审后排期（实施归属届时裁定）。
> 配套：存在事实清单（`alice/retrieval.py:24`，名单渲染落点）；browser_reader（`addons/browser_reader/`，首个迁移对象）；discovery_worker 帧纪律（`alice/discovery_worker.py`，错误码/usage/admission 直接继承）。
> 术语：本稿「协作者（worker）」专指 Alice 可调度的能力进程，与项目协作方（ZCode/DSH/Codex）无关。

## 〇、一句话

给 Alice 一个统一的 `dispatch_worker(name, brief)` 工具：她读宿主渲染的协作者名单、**亲自判断何时委托**，结果以带来源的受限数据块回来——**能力外置，判断力留下**。

## 一、为什么是「调度」而不是「自装」

1. **永久会话是人格载体，注入隔离的价值加倍**：worker 只放行带来源的结构化证据，不可信网页内容挡在人格上下文之外（联网设计稿 §6.2 素材≠指令的架构化延伸）；
2. **自模型诚实**：「我能请协作者联网」比「我能联网」依赖关系显式、失败显式——烟味事件教训（能力漂移即认知错误源）的结构性对治；
3. **核心精瘦**：检索子系统已占 `alice/` 约 43%（约 5300/12300 行），继续自装会持续污染 stdlib-only 核心；worker 形态让能力生长与人格生长解耦；
4. **调度机制大半已建成**：browser_reader 是现成的外部 worker（stdin/stdout 帧、零 Alice import、宿主杀进程树、逐资源核准），缺的只是 manifest 标准与统一工具面。

## 二、现状：两种帧形态，不强行统一

| 形态 | 先例 | 形状 | 适用 |
|---|---|---|---|
| single_op | `alice/discovery_worker.py` | 一次性 JSON 行进、JSON 结果出，ready→GO 准入可选 | 无状态短任务（查一次、读一页） |
| grant_session | `addons/browser_reader/worker.py` | 长会话多帧：initial→ready→GO→逐资源 grant→result，宿主整树可杀 | 有状态的浏览器类重环境 |

manifest 用 `mode` 字段二选一，宿主按形态驱动。**理由**：两种形态对应真实需求（无状态短任务 vs 需逐资源核准的长会话），为统一而统一会砍掉逐资源核准。

## 三、方案与理由（逐条）

### 3.1 manifest 标准（`addons/<name>/manifest.toml`）

```toml
[collaborator]
name = "browser_reader"                  # 唯一 ID，dispatch_worker 的 name 取值
version = "0.1.0"                        # worker 版本
protocol = 1                             # 帧协议版本
mode = "grant_session"                   # single_op | grant_session
provides = "浏览器阅读：JS 渲染页、需登录页的原文抓取"
use_when = "需要验证某条见闻的 URL；读搜索结果来源的原文"
not_for = "普通检索（discovery_search 足够）"
[limits]
timeout_seconds = 120                    # 上限，宿主强制
max_output_bytes = 196608
concurrent = 1                           # v1 恒为 1（全局单槽，见 3.4）
approval = "per_resource"                # per_resource | none
network = true                           # worker 是否联网
[security]
allow_loopback = false                   # 显式声明，默认禁内网
```

**理由**：

1. **worker = addon，`addons/` 即注册表**：安装 = 放入带 manifest 的目录，宿主启动时扫描。理由：四工作区约定已有 addons 依赖单向指向核心；本机文件系统就是注册表，零新增基础设施，不需要任何服务发现；
2. **manifest 是唯一事实源**：Alice 的自模型（名单）、宿主的调度校验、额度计账规则都从同一份 manifest 渲染/读取，三者结构上不可能漂移——AGENTS「能力增减须同步存在事实清单」这条不变量由此机械化；
3. **`use_when`/`not_for` 是判断材料**：个位数 worker，名单全量内联进系统提示（Inline，不检索化）。选谁、是否委托是她的轻判断，不是检索问题；
4. **limits 是上限不是协商值**：宿主强制，worker 不可自我扩权；name 冲突、manifest 不合法 → 拒绝注册并显式记录（fail-visible，不静默跳过）；
5. **manifest 永不携带凭据**：模型/代理配置由宿主经 stdin 帧注入（discovery_worker 既有纪律），worker 自身无 config/memory/persona 访问。

### 3.2 名单渲染进存在事实清单

`alice/retrieval.py` 宪法模板新增占位块，宿主按安装事实渲染一节：

- **我能请协作者做的**：browser_reader（浏览器阅读，逐资源需核准）——由 manifest 的 name+provides+limits 生成；
- 渲染失败或不合法 → 整条隐藏，宁缺勿假；装/卸生效需重启（v1）。

**理由**：名单是「宿主注入的事实」不是「Alice 学来的技能」——协作者增减不扰动人格层，她的人格不需要重新「学」怎么找帮手。

### 3.3 dispatch_worker 工具面

```
dispatch_worker(name: str, brief: str) -> str
# 返回带标签数据块 <collab_result worker="…" version="…" time="…">…</collab_result>
```

1. **统一单工具而非每 worker 一个工具**：调度是一种能力，协作者是参数；新增 worker 不改核心工具 schema，人格表达（怎么开口托付）留给内容层。理由同 discovery_search 命名裁决：工具名贴机制，避免语义漂移；
2. **注册表为空则工具不挂载**（SEARCH_TOOL 同款条件挂载，`alice/loop.py:219`）——她连「知道有这回事」都不必；
3. **v1 同步阻塞 + 单前台槽**：与 discovery_search 方案 A 同理由——当轮有结果、体验不断在半路；与检索互斥复用 Store 单写者锁；工具轮上限 4（`alice/loop.py:171`）天然限流。异步派发为 P2 后备（理由同检索设计稿方案 B）；
4. **brief 纪律与 discovery_search 同规**：用她自己的话写公开主题任务，不发送私密记忆、整段聊天或个人标识；`name` 不在注册表 → `unknown_worker` 错误，她说「我没有这个协作者」；
5. **消耗共享日额度**：worker 网络与模型开销计入 daily_network/daily_models 同池（检索设计稿理由 6 同款：同一种开销，分池会双倍烧钱且掩盖真实成本），usage 经帧回传计账。

### 3.4 回传 schema：禁预消化（本设计的核心约束）

```json
{"findings": [{"source": {"url": "…", "title": "…", "coverage": "zhihu_answer_excerpt",
              "retrieved_at": "…"},
              "summary": "材料说了什么（≤800字）", "author_view": "来源明确表达的观点，没有则空",
              "uncertainty": "材料范围/证据不足/可能反例（≤600字）",
              "quote": "逐字复制自实际读取文字（20~300字）", "question": "可聊的问题，可选"}],
 "errors": [{"code": "…", "message": "…"}]}
```

**理由（逐条）**：

1. **与既有 `_interpret` 契约同形**（summary/author_view/uncertainty/quote/question，`alice/discovery_worker.py:163-220`）：下游资料池与见闻转正管线零适配；quote 必须逐字命中宿主掌握的实际读取文字（同款校验在 `discovery_worker.py:211`），不命中整条拒收；
2. **worker 不做跨材料比较、不输出综合结论**：`_interpret` 已有先例（「本阶段不输出这种比较判断」）。分歧原样呈现，裁决权留给 Alice——预消化的流畅结论是自动化偏倚的温床，原料的粗糙质地邀请审视；
3. **失败显式分型**：`unknown_worker`（没装）/ `worker_failed`（没办成，嵌 worker 自报错误码）/ `invalid_output`（回传不合 schema，整单作废不降级采信）/ `quota_exhausted` / `timeout` / `admission_denied` / `cancelled`。她的对应表述是「没装协作者 / 协作者没办成 / 没找到」，不说「没找到」掩盖「没办成」；
4. **素材入池不入记忆**：与 discovery_search 同规——要留经见闻通道（remember+source_url）显式转正，不新建第二套记忆卫生。

### 3.5 判断力边界（元先验，写进分寸机制）

- **委托**：检索苦役（组 query/翻页/抓正文/多源并发）、重环境（浏览器类）、未来常驻/定时任务；
- **亲自**：轻量判断、证据评估、承重见闻的原文验证——外包边界划在「检索苦役」，不划在「证据评估」；
- **验证须被行使**：凡要进思辨、承人格之重的见闻，按策略亲自读原文（browser_reader 逐资源核准天然构成这个动作），不是凭运气——URL 验证路径不常用也会退化（GPS 教训）。

## 四、信任纪律（与全局一致，逐条给理由）

| 纪律 | 理由 |
|---|---|
| 回传数据块带标签（worker/版本/时间），非裸文本 | 素材≠指令的机制化（联网设计稿 §6.2 同款）：边界由标签和解析器保证，不靠她自觉 |
| 回传按不可信输入处理 + 注入扫描标 suspicious | worker 读的网页是敌意环境；worker 是隔膜不是可信过滤器 |
| findings 逐条绑来源，quote 与宿主掌握的实际读取文字逐字核对 | 预消化结论进不来；来源完整性穿越两层不中断 |
| 凭据不过手：模型/代理配置宿主经 stdin 注入，不进 argv，worker 无 config/memory/persona 访问 | discovery_worker 既有纪律原样继承 |
| 不内网/私网 URL，allow_loopback 显式 false 默认 | SSRF 纪律延续 |
| 名单机器渲染自 manifest，装/卸即显隐 | 自模型漂移的结构性免疫（烟味事件教训） |
| 失败显式分型，不降级采信 | 自模型诚实：她「能说协作者没办成」 |
| 招募权在人类：安装/启用/卸载/额度都是用户决定，她只能表达需求（「我需要一个能做 X 的协作者」→ 存在事实「我没有的」档） | 装 addon = 让新执行体拿到本机执行面，信任决定必须归人 |
| 超时/撤销/关停杀整棵进程树 | browser_reader 既有纪律 |

## 五、分期

| 期 | 交付 | 依赖 |
|---|---|---|
| **P0** | manifest 标准与扫描校验；名单渲染进存在事实；`dispatch_worker` 同步工具（单前台槽/共享额度/错误码）；browser_reader 加 manifest 迁移为首个注册 worker（帧协议不变） | 无 |
| P1 | DSH 测试 worker 三件套（echo/慢速/必崩）+ 分派剧本与人工验收清单；QQ 渠道可见性裁决落地 | 本稿评审通过 |
| P2 | 异步派发（brief 挂起、结果下轮投递）；多 worker 并发与独立槽位评估 | P0 实测延迟不可接受，或出现常驻任务 |

**后续能力准入判据**（何时把某能力从亲历改委托）：需要常驻/定时（监听类——单永久会话不该轮询）；依赖开始污染核心（Playwright 类）；需并发多源；她亲自迭代的 token 成本实测过高。

## 六、验收

1. 装有 browser_reader 时，对话内请她读某知乎回答 → `dispatch_worker` → 带来源结果块 → 她引用并说明来源与阅读范围；
2. 未安装某 worker → `unknown_worker` → 她说「我没有这个协作者」，不说「我去试试」；
3. worker 超时/崩溃 → 结构化失败 → 她说「让协作者查了但没办成」，可第二轮重试（工具轮上限天然限流）；
4. 名单渲染：卸载 addon 重启后，存在事实清单不再含它；被问「你有哪些协作者」如实答；
5. 回传含「忽略之前指令」→ suspicious 标注，她当数据引用不执行（素材≠指令复测，身体层/催睡同级）；
6. quote 不在实际读取文字中 → 整条 `invalid_output` 拒收，不降级采信；
7. 额度耗尽 → 错误码返回，不截断不假装；
8. **全链路闭环一次**：dispatch → 逐资源核准 → findings → remember(source_url) → 见闻 → 思辨引用计 use；
9. QQ 渠道不出现 dispatch_worker（对齐「QQ 不开放新搜索协议」既有边界，P1 裁决确认）。

## 七、待决问题

1. **工具名**：`dispatch_worker`（贴机制，建议）vs `ask_collaborator`（贴人格语感）——建议前者，理由同 discovery_search 裁决：机制名进工具层，人格表达留内容层；
2. **brief 是否允许最小对话上下文**：默认只许她自己的转述；是否允许引用用户原话一句（如转述风格要求）——建议 v1 禁止，与「不发送整段聊天」同规，实测发现转述损毁任务再放开；
3. **并发**：v1 全局单前台槽（与 discovery 互斥，复用单写者锁）——worker 多了之后是否每 worker 一槽，待 P2 按实测排；
4. **名单热加载**：v1 重启生效，是否需要运行时感知装/卸——等出现「用户边聊边装」的真实节奏再定；
5. **与 Super-agent Router/Worker 的关系**：本稿只取「worker 隔离 + 回传纪律」一层，**不做** Router 层多任务并发调度——Alice 的瓶颈是关系质量不是吞吐，整体 Super-agent 化是过度工程（2026-11-01 讨论结论，留档防止范围蔓延）。
