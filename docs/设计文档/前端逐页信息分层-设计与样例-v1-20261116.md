# 前端逐页信息分层：设计与样例 v1

2026-11-16。状态：**设计稿 + 样例，未施工**。作用域：minimal 主题（简洁 · 专注对话）；room/legacy/endfield 布局不动。

依据：[前端信息分层与窗口整理-实施-20261115](./前端信息分层与窗口整理-实施-20261115.md)（下称「实施记录」——中心原则与三条用户补充的原始出处，其 §自查仍欠 明确要求"先做一次正式的信息盘点与分层设计稿再施工"，本稿即该设计稿）；方法论取自 Emil Kowalski 设计工程 skill（`emil-design-eng`，已装全局）。本稿只设计不施工；`web/` 现有未提交改动（另一棒）不在本稿触碰范围。

## 1. 原则 → 可施工判定（翻译层）

实施记录给的是目标语汇，施工需要判定规则。映射如下：

| 实施记录原则 | Emil 方法 | 可施工判定 |
| --- | --- | --- |
| 每步信息量刚刚好 | Progressive disclosure；"信息太少会显得空" | 每屏三问：**此刻任务是什么？下一步动作是什么？卡住了吗？** 三问各有答案即"刚好"；答不出的信息进展开层，答不出的状态=缺陷 |
| 克制呈现 ≠ 删减 | Unseen details compound | 状态不可见不算简洁。删一个元素前先问：删掉后三问是否仍有答案 |
| 少量解释在需要时出现 | Tooltips（首延迟+后续即时） | 解释分两层：L1 悬停一句话；L2 按钮打开的窗口。不再有 L0 常驻说明段 |
| 更多信息按需展开 | 逐步展开 | 内容分级 L0 常驻 / L1 悬停 / L2 命名窗口 / L3 详情视图。每个 L2 入口按钮只承载"打开什么"语义 |
| 反馈三段（前/中/后） | 操作前可操作性、按压 scale(0.97)、结果可感知 | 每个可点元素必须答三题：**现在能不能点（+不能的原因）、点了收到没有、结果是什么**。三题任一无法从界面直接看出即为缺陷 |
| 秩序、条理、简单 | Cohesion（整体气质一致） | 同类操作同规格：所有"调用模型"按钮同一状态机；同一时刻同一位置只回答一个三问 |

## 2. 全局反馈语言（v1 规格，仅 minimal）

一处定义，全站复用——这是"反馈三段"能被直觉感知的前提（cohesion）。

### 2.1 状态三段的具体表达

| 段 | 表达 | 规格 |
| --- | --- | --- |
| **前馈**（能不能点） | 可用：正常态；不可用：`disabled` + `aria-describedby` 指向一行可见的原因说明（不藏在悬停里——操作前反馈要能直觉看到） | 原因说明用 `--muted` 一行小字，出现在按钮组正下方，不弹窗 |
| **接收确认**（点到了吗） | `:active { transform: scale(0.97) }`，`transition: transform 160ms var(--ease-out)`；异步操作立即进入 pending 态 | pending 态按钮保留原文案 + 转圈 12px 内联图标；**不改文案为主语**（"探索中…"可以，"正在为您探索…"不行——克制） |
| **结果**（发生了什么） | 成功且可从界面本身看到 → 静默（不加 toast）；成功但不可见 → 瞬时确认 2s 淡出；失败 → 常驻状态行直到下次操作 | 失败行 = `--danger`（新增 token）+ 一句原因 + 可选重试链接；失败不自动消失 |

预期 vs 已发生必须可区分：pending 态就是分界线——pending 前的一切只是"可以发生"，pending 后的一切是"正在发生"，终态才是"发生了"。

### 2.2 动效决策（Emil 框架逐项应用）

| 元素 | 频率 | 决策 | 规格 |
| --- | --- | --- | --- |
| 发送按钮/回车发送 | 100+ 次/天 | **无入场无退场动画**；仅按压 scale(0.97) | 160ms ease-out |
| 详情窗口（dialog） | 偶发 | 标准动画 | enter 240ms / exit 180ms，`cubic-bezier(0.23,1,0.32,1)`；`transform-origin: center`（modal 豁免） |
| Tooltip/悬停解释 | 数十次/天 | 极短 | 125ms ease-out；首个延迟 300ms，相邻悬停 0ms 直开 |
| 历史同步进度条 | 每次刷新 | 有（状态指示用途） | indeterminate 循环 `linear`；出现 150ms ease-out |
| 列表项增删（卡片/记录） | 偶发 | opacity+height 组合，exit 快于 enter | enter 240ms / exit 180ms；`@starting-style { opacity:0; transform: translateY(4px) }` |
| 全站 | — | `prefers-reduced-motion: reduce` | 保留 opacity/颜色，去位移 |

### 2.3 新增 CSS token（minimal 作用域）

```css
html[data-theme=minimal] {
  --danger: #c98a8a;        /* 失败行、不可操作原因；低饱和贴合现有色板 */
  --ok: #8fbf9f;            /* 仅用于终态确认点，不做大面积着色 */
  --ease-out: cubic-bezier(0.23, 1, 0.32, 1);
  --dur-enter: 240ms; --dur-exit: 180ms; --dur-press: 160ms;
}
```

## 3. 遗留项专项设计（三个自查欠账）

### 3.1 思想页「现在探索一轮」：前馈三态（遗留 #1）

现状：`thoughts.js` 中按钮恒为 ghost 可点样式；探索关闭时按钮可点但自动探索未开——语义正确（手动探索只查 `allow_paid`），但用户无从知道"点了会发生什么、会不会花钱"；写库期间整面板禁用但无原因。

| Before | After | Why |
| --- | --- | --- |
| 按钮永远可点样式，点击后无 pending 态 | 三态状态机：可用 / 不可用（disabled+原因行）/ 探索中（pending+转圈，面板其余禁用照旧） | 三题：能否点、收到没、结果——现状一题都答不出 |
| "（调用模型）"塞在按钮文案里 | 按钮主文案「现在探索一轮」；费用与条件移入按钮组下一行常驻原因行：「将用已配置模型，产生一次调用费用」 | 括号是绕过信息分层；费用是操作前必须可见的预期结果，且只占一行 |
| 写库期间静默禁用 | 禁用同时显示「正在保存设置…」原因行 | disabled 无原因 = 操作前反馈缺失 |

三态样例（ASCII）：

```
可用态                      不可用态                    探索中（pending）
┌────────────────────┐     ┌────────────────────┐     ┌────────────────────┐
│ ▷ 现在探索一轮      │     │ ▷ 现在探索一轮      │     │ ◌ 现在探索一轮      │
└────────────────────┘     └────────────────────┘     └────────────────────┘
 将用已配置模型，产生        未配置模型接口，先在         正在探索…可随时
 一次调用费用                设置→模型配置               「暂停当前探索」
 (muted 常驻一行)           (muted + 按钮置灰)          (paused 按钮转主色)
```

状态机接线（施工说明，非本轮代码）：可用 ⟶ 点击 pending（按钮自身 disabled，`暂停当前探索` 升为主操作）⟶ 回执成功静默（探索页自身会出现新运行条目=结果可见）⟶ 失败恢复可用态+失败原因行。暂停态的「继续（调用模型）」复用同一状态机与原因行。

### 3.2 对话历史加载指示（遗留 #2）

现状：`syncHistory()` 期间 `#msgs` 短暂空白，无任何"正在同步"表达；失败时也静默。这违背"操作时：是否正在处理"——刷新是用户主动操作，接收确认与处理中全是空白。

| Before | After | Why |
| --- | --- | --- |
| 同步期间内容区空白 | `#msgs` 顶部 2px indeterminate 细线 + 底部状态行「正在同步记录…」 | 双通道：细线是环境感知（不占认知），状态行是可读确认；不遮已有内容 |
| 同步完成无表达、失败无表达 | 完成：静默（内容出现即结果可见）；失败：状态行转「同步未完成，稍后重试」`--danger` + 重试链接 | 成功可从界面本身看到 → 静默；失败不可自行消失 |

```
同步中                          失败
┌──────────────────────┐       ┌──────────────────────┐
│ ▔▔▔▔▔▔▔▔░░░░ (2px线)  │       │ 同步未完成 · 重试      │
│ 正在同步记录… (muted)  │       │ （--danger 一行）      │
│ …已有消息原样保留…     │       │ …已有消息原样保留…     │
```

CSS 要点：细线与状态行均为独立元素，`@starting-style { opacity:0 }` 150ms 淡入；完成后 180ms 淡出（exit 快于 enter）；进度条动画 `linear` 循环。

### 3.3 发现页状态条 × 下一步引导去重（遗留 #3）

现状：`renderOverview` 已标 `data-enabled`，暂停态隐藏了 mode 行、引导在场时收起范围摘要——但两块的分工没有规则，部分状态仍重复。本稿给出**完整分工矩阵**，规则化后施工可核对：

- **状态条**只回答"系统现在处于什么状态"（不含任何动作邀请）；
- **引导卡**只回答"你下一步可以做什么"（不含状态陈述）；
- 同一事实两处都出现 = 违反"同一时刻同一位置只回答一个三问"。

| 系统状态 | 状态条显示 | 引导卡 |
| --- | --- | --- |
| 已配置·运行中 | 「自动寻找：运行中 · 时段 xx–xx」（mode 行保留） | 无（无事可做时不造引导——信息量刚刚好） |
| 已配置·暂停 | 「自动寻找：已暂停」 | 「开启自动寻找」单按钮 |
| 未配置（无平台/无兴趣） | 「内容发现：未配置」 | 「先配置平台与兴趣」→ 打开偏好窗口 |
| 额度用尽 | 「今日额度已用完」 | 无按钮，仅说明恢复时间（下一步=等待，不造按钮） |
| 引导在场时 | 自动省略与引导重复的那一项（延续二轮施工做法） | — |

样例（暂停态）：

```
┌ 状态条 ──────────────────────────────┐
│ 内容发现：已暂停 · 今日已读 3 篇      │   ← 只有状态
└─────────────────────────────────────┘
┌ 下一步 ──────────────────────────────┐
│ 自动寻找没开。 [开启自动寻找]          │   ← 只有动作
└─────────────────────────────────────┘
```

## 5. 人工验收（真实验收，未执行）

1. 思想页：正常态/断开 API/探索中三态逐一目视——按钮态、原因行、pending 图标与「暂停」主操作化，各自符合 §3.1；点击后"收到没"由按压 scale + 转圈确认。
2. 刷新聊天：同步期间细线+状态行可见且不遮内容；完成后消失；拔掉服务再刷新 → 失败行出现且不自动消失，重试可用。
3. 发现页逐状态切换（运行/暂停/未配置/额度尽）对照 §3.3 矩阵：状态条与引导无一句重复、无空态悬置按钮。
4. 悬停解释：首个 300ms 延迟、相邻即时；键盘 Tab 可达所有 L0 操作，`aria-describedby` 在读屏下报出原因行。
5. 全站快门测试：所有窗口 enter/exit 体感 ≤300ms；reduced-motion 下无位移动画。
6. 回归：实施记录 §人工验收 1–8 仍全过（本稿不回退其成果）。

## 6. 边界与施工顺序

- **不改**：room/legacy/endfield 三主题、后端 API、另一棒 `web/` 未提交区；新增 token 仅 minimal 作用域。
- **建议顺序**：§3.3 发现页矩阵（纯结构/文案，风险最小）→ §3.2 同步指示（新增元素，无状态接线）→ §3.1 思想页状态机（需要接线，最后做）。每步完成后按 §5 对应条目真人验收，再进下一步。
- 本稿为 v1：矩阵与状态机在真人使用中发现新状态时增补行，不推翻结构。
