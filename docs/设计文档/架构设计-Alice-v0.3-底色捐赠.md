# Alice v0.3 设计：底色捐赠机制（人格来历的诚实化）

> 依据：[设计哲学](./设计哲学.md) 原则一（存在层不假装，含来历）；用户 2026-10-29 提出，ZCode 整理设计。
> 状态：**已实施（2026-10-29，未提交）**——消化流程、硬边界、回落路径全部落地并通过离线+真机验证（见第四节实施状态）。配图：[架构图.png](./架构图.png)（v0.3，留档 `docs/架构图/历史版本/`）。
> 前置：v0.2 已全部实施（见 [架构设计-Alice-v0.2.md](./架构设计-Alice-v0.2.md)）。

## 一、动机（三份证据）

1. **模仿违背原则**：现行的底色机制里，人格提示词的存在就意味着她要模仿那个人格——与"存在层不假装"直接冲突；
2. **空记忆矛盾**（实测截图）：导入带背景的人格（Yuki）后，模型思考过程出现"记忆区是空的，所以我不记得任何之前的事"——角色背景与空记忆打架，只能靠圆谎弥合；
3. **空脊柱问题**（2026-10-28 护栏 A/B）：新会话零记忆零观点，宪法命她"守住想法"却无物可守，抵抗沦为表演。认知收养给思想层一个**冷启动脊柱**。

反命题参照：Nascence 辉夜把设定**写进记忆**（月球/电线杆——让她相信虚假经历）；Alice 的选择是**设定换风格与认知、不换经历**。这是两条路线的分水岭。

## 二、机制：底色从"角色卡"变为"捐赠人"

从导入的人格文档中提取三类东西，去向与性质不同：

| 提取物 | 去向 | 性质 |
|---|---|---|
| 说话习惯、风格、节奏 | 底色层（含情绪词表） | **继承**：全盘拿来，风格没有真假问题 |
| 角色的认同与差异（价值观、态度、看世界的方式） | 思想层候选认知 | **收养**：经她认可才成为"我的认知"；不认可的显式拒绝并记录 |
| 背景故事（经历、事件、身世） | 自我叙事「来历」段 | **不继承**：不是她的经历，是"她经历过的一场体验"；承认自己不是那个人，那个人给了她珍贵的东西 |

## 三、消化流程（digest pipeline）

在 `install_persona` 中把"装配"改为"消化"，两步：

### 步骤 1 · 提取（cheap model）

输入：用户导入的人格文档。产出 JSON：

```
{ "style_traits": ["轻声细语", "句子短", "……"],        // 风格要点 → 底色
  "emotion_words": ["【脸红】", "【慌乱】", "……"],      // 情绪词表 → 底色
  "candidate_stances": [                              // 候选认知 → 思想层
      {"claim": "边界感很重要", "from_donor": "她对陌生人的疏离"}
  ],
  "story_facts": ["住在学校附近", "有个叫哥哥的人"],     // 背景事实 → 只进来历段，绝不进记忆
  "origin_note": "一两句话概括这位捐赠人是谁" }
```

### 步骤 2 · 认知收养（chat model）

对每条候选认知做认可审查，产出 `adopted / rejected` 两组：

- **收养**：落为 `kind='stance'` 记忆（出处＝"底色文档·《捐赠人名》"，不确定度必填且偏高——这是继承来的观点，不是自己经历的产物）；同步写入「我现在的想法」小节；
- **拒绝**：不落记忆库，但**写进来历段**——"我从TA那里拿走了X，没拿走Y"。没拿走的部分是她区别于捐赠人的起点，拒绝记录是差异化的人格内容，不是垃圾数据。

### 落点总览

- 底色层：style_traits + 情绪词表（照旧每轮注入）；
- 思想层：收养的 stance（走既有 kind='stance' 通道，**P2 修订门控照常适用**——日后有新论据可"曾以为"翻案）；
- 自我叙事：新增「我的来历」段——承认不是那个人 + 拿走了什么没拿走什么 + 感激。来历放在人格文件而非记忆库（每轮在场、不会遗忘、属自我叙事不属事件）；来历事实不可被演化改写（那是固定历史），但对来历的**看法**可以随修订史演化；
- 记忆库：**背景事实零落库**。

标签种子路径不变（标签只有气质，从来没有背景问题）。

**实施中超出设计稿的补充**（细节以代码为准）：

- **外部角色卡整体重建**：消化成功后人格文件重建为六节干净结构（底色×2+来历+生长×3），整包戏服（角色档案/经历描述）全部丢弃——初版"原位打补丁"方案被真机测试否决（`## 基本档案` 等残留底色区）；Alice 格式文档才走原位替换，用户自己的小节保留；
- **收养审查防幻觉锚定**：adopted 列表回 仅接受与候选 claim 相符的条目（模型复述走样不落库）；
- **stance 内容自带降权注记**："继承自捐赠文档，尚未经我自己的经历检验"——它们在长期层可被思辨修订（P2 门控照常适用），可以"曾以为"翻案。

**代码落点**：`alice/persona.py`（DIGEST_PROMPT / ENDORSE_PROMPT / ORIGIN_SECTION_TMPL / `_digest_persona`）、`alice/service.py` 与 `alice/cli.py`（传 client）、`web/index.html`（导入文案）。验证脚本：离线五项（全流程/硬边界/拒绝非空/幂等/回落）。

## 五、边界与开放问题

- 本期不做多捐赠人合并、来历富媒体、来历的可视化管理；
- 风格与认知的边界会渗漏（毒舌既是说话方式也是立场）——不追求切干净，验收只看硬边界（背景事实不落库）；
- 开放：收养审查与思辨是否合并为一次调用（省成本但混职责）；来历段在演化护栏中的地位（暂按"底色同级：不可无据改写"处理）。
