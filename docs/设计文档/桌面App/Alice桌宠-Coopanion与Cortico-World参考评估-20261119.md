# Alice 桌宠的 Coopanion 与 Cortico World 参考评估

2026-11-19。基于 Coopanion 官方指南、Cortico World 契约和 Alice 当前桌面端源码。本文供方案讨论，实际施工仍需结合桌面体验、兼容性和现有会话边界完整评估。

**建议参考 Coopanion 的交互和 Cortico World 的模块边界。首版从现有 macOS 桌面气泡出发，加一个可选的 Alice 形象。** 先验证用户能否随手和 Alice 说话、感受到她的在场，同时不受桌宠打扰。

## 可以借鉴的做法

| 参考点 | Coopanion 的做法 | Alice 的建议 |
|---|---|---|
| 桌宠是聊天入口 | 角色待在屏幕边缘，按钮和气泡贴近角色。被动状态气泡可以点击穿透。 | 保留两级点击。点角色展开对话按钮，点按钮才聚焦输入。继续复用逐句气泡和被动预览。 |
| 互动有不同触发成本 | 戳、摸、拖动有不同反馈，用户可选择哪些互动唤起模型。 | 点按和拖动在桌面端立即反馈，用户提交消息时才请求模型。首版只将实际对话纳入长期会话。 |
| 状态来自真实流程 | 宿主阶段驱动思考和工作提示，聊天交互优先于状态展示。 | 用现有会话状态和允许展示的回复驱动表情。逐句气泡揭示时表现为说话，用户输入、拖动或操作菜单时保持位置稳定。 |
| 外部环境有明确接口 | World 提供事件、工具和环境描述，动作有回执，人格与记忆由各自模块管理。 | 将桌宠作为桌面端组件，通过已有公开接口接入同一个 Alice。将来有明确的自主动作需求时，再增加受控的动作与回执。 |

资料见 [Coopanion 互动指南](https://coo.palailab.org/guide/everyday/)、[桌宠 World 说明](https://github.com/Pal-AI-Lab/Coopanion/blob/main/packages/cortico-world-desktop-pet/README.md)和 [Cortico World 契约](https://github.com/Pal-AI-Lab/Cortico/blob/main/docs/worlds.md)。

## Alice 已有的基础

- Tauri 宿主已有透明悬浮入口、独立对话按钮窗、预览窗及输入窗。预览窗支持整窗鼠标穿透，位置按显示器工作区校正，主窗聚焦或服务维护时由宿主控制显隐。见 [桌面气泡宿主](../../../addons/desktop/src-tauri/src/bubble.rs)。
- 桌面聊天使用既有 `/api/chat`，逐句展示属于界面行为。桌宠形象可以替换悬浮入口的视觉呈现，复用现有请求身份、同一长期会话和服务端允许展示的内容。见 [两级入口与逐句气泡实施记录](两级入口与逐句气泡-实施与人工验收-20261116.md)和[桌面端说明](../../../addons/desktop/README.md)。
- 窗口真实体验仍需人工确认。尤其要检查放大角色后透明区域是否拦截点击、切换屏幕或缩放后角色是否越界，以及角色动作是否跟得上气泡的实际显示进度。

## 建议的首版范围

1. **一个可选的原创形象。** 从现有小窗入口开始，支持待机、点按反馈、拖动、说话和隐藏。位置、外观与开关由桌面端偏好管理。
2. **一条现有聊天路径。** 输入沿用现在的两级点击。角色从实际回复和界面状态取得展示信号。后台切换、撤销来源、维护和退出继续沿用宿主的显隐和内容投影规则。
3. **一轮真实使用验证。** 在其他应用工作时验证角色附近能否正常点选和键入。再核对主动聊天后的输入焦点、拖动与多屏位置、收起再打开后的回复节奏，以及菜单栏能否隐藏和召回角色。

语音、自由漫步、换装包、系统操作和模型主动控制桌宠可按实际使用需求分别评估。首版的判断重点是角色是否增加陪伴感，以及它对其他应用的焦点和点击有多大影响。

## 何时再考虑 World 兼容

Alice 首版复用现有会话和 Tauri 宿主即可。挂载完整 Cortico World 是另一项工程，涉及环境描述、工具回执、事件唤醒、合批和打断等宿主语义。等桌宠或其他入口确实需要共享这些能力时，再比较自有接口与兼容层的成本。见 [Cortico World 兼容等级](https://github.com/Pal-AI-Lab/Cortico/blob/main/docs/world-compatibility.md)。
