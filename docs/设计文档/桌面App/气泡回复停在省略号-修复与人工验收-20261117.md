# 气泡回复停在省略号：修复与人工验收

## 现场与定位

用户报告桌面气泡出现“…”、回复缺失或逐句显示卡住。只读核对安装版本为0.1.16；真实数据库最近两次请求均 completed、助手轮次48/50已保存；这几条均有关联资料，附件尚未到期。这排除了这两轮根本没有保存回复，不能据此判断气泡的实际渲染状态。

检查现有消息流发现三处缺口：

1. SSE done带assistant_turn_id时不把已流入的文字标记final，末尾不符合句界的文字要依赖后续历史同步才进入逐句队列。历史忙碌、失败或挂起时可能一直等不到末句。
2. 历史同步失败会清除资料正文并显示占位；恢复后，所有旧资料正文的显示进度从零开始。DesktopSpeech逐条找第一条未显示完的记录，因此旧消息重新排队可以长时间挡住新回复，留下“…”；多次失败/恢复还可能反复重置。
3. 只读同步没有超时，某次fetch或JSON正文挂起会一直占据syncing，后续自动刷新与发送都被挡住。

这些是代码确认能形成所述症状的路径，尚未捕获原生WebView控制台中的本次直接报错。原生UI只观察到入口、展开状态与设置，未发新聊天或重现模型调用；不把上述定位描述为完成真人复现。

## 修改

- done立即将已经收到的live.reply标记为final，沿用原逐句计时与动画，不一次性倒出全文。不额外使用done中的资料正文绕过历史投影。未取得流式正文时明确提示“回复已保存，正在同步正文…”。
- DesktopSpeech新增masked呈现状态。隐藏资料时仅保留已揭示句数，不保留原文、原句数组；重新得到服务端允许的投影后恢复该进度。旧消息不会因为一次资格刷新重新从头播放，尚未显示完的消息继续剩余部分。
- 只读同步统一12秒AbortController期限，覆盖活动状态、配置状态及三页历史的响应头和JSON读取；finally释放syncing，下一宿主节拍可正常重试。该期限不作用于聊天SSE，不会重发用户请求或再调模型。
- 资料到期/不可用仍立即清除；同步失败仍隐藏正文，不放宽GUI投影、来源期限、协作材料或桌面被动预览范围。主页面和原主动邀请状态机不变；桌面预览共用的Speech默认行为不变。

## 验收与交付

仅做语法、版本和包完整性核对，不创建假消息、假模型或临时Store，不执行业务机器自测。真人验收待：

1. 气泡中发送真实消息，观察正常逐句回复、最后一句和done后的收尾；包含无句末标点的实际回答时也能收尾。
2. 实际断连/恢复或遇到忙碌后，旧资料回复恢复可读但不从头播放，新回复不会长时间排在旧历史之后。
3. 同步超时后窗口可恢复刷新，原请求不重复发送；已保存但未同步正文的状态可辨识。
4. 真实撤回/到期资料仍隐藏；恢复展示只来自服务端许可投影，不能从本地恢复旧正文。
5. 收起、展开、切回主窗口、桌面被动预览、跟随/回看、减少动态效果及旧邀请接受流程一并由真人复验。
