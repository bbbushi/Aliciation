## 操作入口

菜单栏“数据与更新 → 备份与恢复”打开独立窗口。它只加载签名包内页面，禁止外部导航；固定原生命令检查窗口标识，主聊天回环页面不能调用。主聊天页未新增备份 HTTP 权限、任意路径、程序或模型工具。

- **备份并退出，准备更新**：应用内确认后关停接单、等待既有工作与 SQLite/客户端收尾，不新增退出前记忆提取。服务关闭后，在同一个持有维护锁的核心进程内创建并验证恢复点，发布成功才发出完成状态，宿主再等待真实进程退出。之后用户手动安装新版。
- **暂停 Alice，查看恢复点**：同样不新增收尾调用，停止服务，保留桌面恢复窗口。核验按钮只读检查恢复点文件摘要；确认恢复后复制到暂存区、检查 SQLite、保留当前数据再替换。
- **继续启动当前版本**：确认程序版本/兼容声明与数据格式。离线 CLI 只授权一个新的随机启动身份，后台在持有锁时消费授权，启动完成才清除维护阻断。准备失败且没有完整恢复点时，不授权启动不同版本。
- **撤销未完成的恢复**：只用于中断的文件替换；核对当前与保留副本的摘要后放回原数据。已完成恢复后不提供无条件的一键撤销，原数据和日志仍保留，不能盲目复制单个数据库覆盖。

成功备份后的重开会先显示恢复窗口，避免在备份与换包之间出现普通写入。是否替换安装包仍由用户操作；程序不能阻止 Finder 中的手动覆盖。此批没有自动取消更新、自动回滚或自动合并备份之后的对话。

## 数据与一致性

核心新增 `alice/profile_maintenance.py`，只用标准库，不构造 Store、模型客户端或网络请求。

1. `ProfileLease` 使用用户根 `.alice-profile.lock`，正常 Store、CLI 和维护操作共用；进程内可重入，Store 的 `data/.alice-instance.lock` 仍保持唯一。桌面后端从启动到服务关闭、备份结束一直保留外层锁，避免 Store 释放锁后才抢锁备份。恢复不删除、移动或替换这两个锁 inode。独立 `ChatService(db_path=...)` 仍按独立数据库目录隔离。
2. `.maintenance/state.json` 记录准备/已备份/授权/启动中/完成/失败；`.maintenance/format.json` 声明数据格式。正常 CLI/ChatService 在打开 SQLite 之前检查维护阻断。跨进程间隙由持久阻断和绑定版本/nonce 的单次授权覆盖；进程崩溃或启动失败仍留在恢复入口。
3. 恢复点覆盖配置、SQLite、人格/原稿/快照、思想与归档、重置/安装操作记录、渠道状态及其他实际用户文件。包含本机凭据，目录 0700、文件 0600（有用户执行位的文件仅保留用户权限）；不声称加密或系统密钥链。外发前不可把整个恢复点当普通日志共享。
4. 排除根 `.maintenance`、OS 锁文件、日志、缓存/下载目录、浏览器缓存、Python 缓存；浏览器其他现存数据不假装自动适配。拒绝符号链接、硬链接和特殊文件，不自动忽略它们来冒充完整备份。
5. 先清点源文件并复制，核对暂存与源前后清单。仅在私人暂存副本打开 SQLite，执行 integrity_check、foreign_key_check、WAL checkpoint；不读写活库 SQL。最终清单含每个文件的 SHA-256、大小、协议、格式、创建程序 build、已知数据来源版本和 SQLite schema 摘要。
6. 文件与目录落盘后原子发布完整恢复点；部分目录不出现在可选恢复点中。空间、权限、SQLite 或摘要不通过均不发布。所有旧恢复点保留，不自动清理最后一份恢复点。
7. 恢复先核验完整点并复制到同盘暂存，记录根目录项和 data 子项的 old/new 摘要，保留旧文件到 `.maintenance/replaced/<op>/previous/` 再逐项替换。跨多文件一致性依靠持久恢复日志及启动阻断；不是声称一次 rename 原子替换整个用户目录。各步有 fsync 和摘要检查，遇到后来改动停止，保留现场。
8. 中断撤销按实际文件位置和摘要判断已执行的移动，可在再次中断后继续撤销；不因历史 PID、文件名或旧日志就杀进程/覆盖数据。

本批声明维护协议 v1、数据格式 v1、无格式迁移（migration_from 为空）。后续 schema/跨文件格式变化必须同步维护格式和迁移合同；不支持的格式会被阻止。本批没有实现任意未来格式的自动迁移。0.1.0 旧二进制不理解这些维护标记，必须正常退出并在维护期间避免再启动它；不要把旧版绕过新协议当作受支持交接。

## 公开 CLI 与协议

源码使用 `python -m alice`，冻结包使用 `alice-backend`，其余参数相同：

```sh
# 所有命令均要求明确的绝对用户根；以下是供人工使用的示例，本轮没有执行。
alice-backend --user-dir /absolute/profile maintenance status
alice-backend --user-dir /absolute/profile maintenance backup
alice-backend --user-dir /absolute/profile maintenance verify --backup-id <32位恢复点ID>
alice-backend --user-dir /absolute/profile maintenance prepare --confirm
alice-backend --user-dir /absolute/profile maintenance restore --backup-id <32位恢复点ID> --confirm
alice-backend --user-dir /absolute/profile maintenance rollback --confirm
```

输出仅 JSON 操作/恢复点元数据，错误不输出密钥或数据库正文。CLI 遇到活实例会拒绝；`authorize --launch-nonce ... --confirm` 是宿主在继续启动时使用的固定入口，不接受可执行路径。UI 列出最近 20 个恢复点，其余文件仍保留，可按已记录 ID 使用 CLI。

私有管道仍是协议 v1，新增只读 `maintenance_status`，shutdown reason 扩展为 quit/update/recovery。shutdown 原子预留关闭门禁，防止与普通退出竞争后改变已开始的退出语义；重放 request_id 返回原结果。新事件报告备份阶段、维护阻断；宿主保持 `updates=false`。普通退出不改变既有提取许可。

此批增加的是本机管理能力，没有增减模型 SDK 工具；`commands.json` 与宪法不增加用户操作教程或原生命令权限。

## 验证与人工验收

已完成 Python/JS 语法检查、diff 检查、Rust debug/release 编译、129 个资源摘要、66 个 Mach-O 架构/动态库边界、Info.plist、codesign deep/strict 及 DMG 校验，最终构建无 WARNING/ERROR。按项目要求没有机器行为测试，没有模拟数据库、假模型或自动 HTTP 请求。

以下均待真人验收，优先在独立 macOS 用户账户的真实少量数据上操作：

1. 正常退出已安装 0.1.0，安装 0.1.1；打开后确认当前对话与人格连续，菜单可打开独立维护窗口。
2. 空闲时备份并退出；再次打开应先进入恢复窗口，继续当前版本后可聊天。人工核对恢复点时间/大小及含凭据说明。
3. 正在回复或处理任务时准备更新：等待既有工作结束，不强杀、不新增退出提取；确认失败时没有显示备份成功。
4. 真实完成第二个兼容版本 B 的构建后，走 A 备份退出 → 手动安装 B → 确认启动；此双版本升级演练尚未完成。
5. 选一个真实恢复点：核验、确认回到该时间、检查对话/人格/相关文件连续；原数据确实另存，备份后的对话没有被偷偷合并。
6. 人工制造磁盘空间/权限不足、损坏恢复点副本：拒绝发布或恢复；原恢复点与数据仍在。
7. 在隔离账户实际中断恢复、重开：不能进入聊天；明确撤销后回到原数据；后来手动改动不被无条件覆盖。
8. 构造不支持的数据格式或新版启动失败：留在恢复页，不打开不兼容 Store、不自动恢复旧数据；安装匹配程序后显式恢复。
9. 旧版本、重复实例、带空格/中文路径、第三方组件在途未知结果和干净账户另行覆盖，不因静态编译通过写成通过。
