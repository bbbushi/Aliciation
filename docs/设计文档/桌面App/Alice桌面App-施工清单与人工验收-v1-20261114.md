# Alice 桌面 App：施工清单与人工验收 v1

2026-11-14。配套：[架构与更新设计](Alice桌面App-架构与更新设计-v1-20261114.md)。当前仅设计与施工准备，以下模块、命令与安装包均未实现。

## 1. 本轮已核对

- 工作分支 `ytq`，工作区有大量其他棒未提交改动；本轮不覆盖、不暂存、不提交这些改动。
- 本机 `arm64`；PATH 有 Node 和 Python，未检测到 `cargo`/`rustc`。这不是全盘确认机器未安装，只说明当前构建环境不可直接调用。
- 已核对配置根、服务启动/来源校验/退出、默认数据与 worker 启动方式；没有读取 `user/`、重启服务、调用模型或安装依赖。
- 首期开发包支持本机 macOS arm64；Windows x64 要在 Windows 构建和人工验收。签名身份、更新密钥、托管地址留到发布批次配置，不阻塞核心路径施工。

## 2. 首批改动顺序

| 顺序 | 预期文件/区域 | 交付 | 前置/共存要求 |
|---|---|---|---|
| P0.1 | `alice/runtime_paths.py`、`config.py`、`cli.py` | `--user-dir` 在业务导入前生效，资源与数据分离 | 不改变不传参数时的源码默认路径 |
| P0.2 | 所有路径消费者、`service.py`、`persona_reset.py`、观测/渠道组件 | 数据、人格、归档、重置/导入日志完整隔离 | `--config` 不能作为隔离证明 |
| P0.3 | `alice/instance_lock.py`、CLI 与服务入口 | 同一根目录的排他锁，明确维护交接 | 涵盖不同端口、目录别名、CLI；识别旧版本不支持锁的限制 |
| P0.4 | 固定 runtime/worker 分派入口和构建资源清单 | 冻结进程不再当通用解释器用 | addon 独立入口，不逆向 import |

每批施工前重新读取 AGENTS 当前状态和目标路径 diff。`config.py/cli.py/server.py/service.py` 与其他在建功能共用，逐处保留现有自主探索、QQ、维护和 GUI 行为；不要为了桌面原型清理或回退其他棒代码。仅暂存自己碰的路径；当前未获推送指令，不推送。后续合 main 仍按 PR 与共存要求执行。

## 3. 开发环境准备步骤

1. 先实施可离线编辑的 P0 路径与进程契约；不依赖 Rust 下载即可推进。
2. 检查 Xcode Command Line Tools、Rust 工具链及目标 Tauri 2 构建条件；按官方来源准备，下载前锁定候选版本。本文档阶段不自动安装全局工具链。
3. 桌面独立环境安装冻结工具和模型 SDK，依赖带版本锁与许可证清单；不用现有混合 requirements 把 matplotlib 带进运行包。
4. 给 Rust 和桌面构建配置提交锁文件。构建输出单独忽略，不写入现有 `dist/alice-harness/`；不签发或上传现有脏工作区为正式版本。
5. 人工运行使用单独用户根；新建数据与迁移数据分开。真人输入模型配置与发送聊天，不读写当前活 `user/` 来凑验收。

开始 P1 时应记录：OS/架构、工具版本、源版本/dirty 状态、产物路径、组件支持清单。出现 Tauri/WebView 同源不兼容，先排查实际 Origin，不放宽服务鉴权；出现冻结资源/worker 阻断，停在打包批次修正，不把源码运行成功写成安装包成功。

## 4. 人工验收清单

全部初始状态为“未执行”。静态检查结果另记；不要生成自动请求、假模型或脚本化行为测试替代人工验收。

| 编号 | 人工操作/场景 | 预期与证据 |
|---|---|---|
| D01 | 干净账户安装并首次打开 | 无需 Python/终端；缺配置可进入设置；记录安装包 hash、版本与截图 |
| D02 | 配置后真实聊天，关窗，重新打开 | 已保存对话、人格、记忆连续；日志说明退出原因，无重复发送 |
| D03 | 连点图标；另起不同端口的同数据服务/CLI | 唯一写入者，重复窗口被唤醒或明确拒绝，不初始化第二份 Store |
| D04 | 另一程序占用 8800；切换为带空格/中文用户目录 | App 用 OS 分配端口，所有数据落在指定根，无源码目录写入 |
| D05 | 正在聊天/导入/维护/探索时退出或更新 | 状态可见；阻塞可解释；不强杀；更新退出不新增模型收尾请求 |
| D06 | 外链、新窗口、人格导入、下载导出、SSE、神经球 | WebView 中实际可用；外链走系统浏览器；无原生命令越权；目视动画 |
| D07 | 开关未启用、组件缺失/不支持 | 状态与实际组件一致，不自动安装或放宽用户许可 |
| D08 | 停服后迁移一份真实历史数据 | 原数据保留；完整包核验；历史/人格/原稿/观测/思想与凭据处理有记录 |
| D09 | 更新下载中断、错误签名或错误架构 | 不执行安装；原版本仍可用；不记录密钥/正文 |
| D10 | 真实 A → B 更新并重启 | 后端退出后才安装；恢复点可定位；界面/核心 build 对得上 |
| D11 | 空间不足、只读位置、备份失败 | 更新阻止在安装前；原因准确，无半份恢复点冒充成功 |
| D12 | B 数据迁移失败/程序启动失败 | 显示恢复入口，不进入业务；不自动用旧数据覆盖新对话 |
| D13 | 通过核心入口恢复匹配版本和完整恢复点 | 明确恢复时间/丢失范围；人格与数据库成套恢复；源备份保留 |
| D14 | 异常终止后重开 | 无历史 PID 误杀；未知副作用不重放；恢复状态诚实 |
| D15 | 正常卸载/覆盖安装/更新后卸载 | 默认保留用户数据；删除数据另行明确确认 |
| D16 | Windows x64 完整重复 D01～D15 | 原生构建、WebView2、进程树、文件锁/路径、安装器与更新流程证据齐全 |

真人测试时只使用用户明确提供或专门建立的隔离数据。用户要求不调用模型的阶段只做安装/路径/静态检查，不把聊天功能填为通过。架构内部新增版本/schema 字段必须通过核心公开只读投影回收，SDK/addon 不直查活库。

P1 放行：真实窗口启动、配置、真实聊天、正常退出、重开连续性、实例锁与数据隔离通过。P2 放行：干净账户无需 Python 即可运行，资源和首发功能完整，明确组件限制。P3 放行：至少两个真实构建完成更新，失败与恢复分支有人工证据。Windows 仅在 P4 完成后列为支持平台。正式发布还需可追溯提交、签名、固定更新地址和恢复说明。

本轮没有运行上述项目，没有重启当前服务；设计文档不改变思想层或此前人格/记忆问题的未通过结论。
