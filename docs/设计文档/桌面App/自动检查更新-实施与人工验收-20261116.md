# 自动检查更新：实施与人工验收

用户提出自动检测更新后，本轮在 0.1.5 实现自动获取版本清单、发现新版提示及可持久关闭的开关。正常升级到 0.1.4、对话人格保留、聊天和退出重开已由用户真人确认；本轮不把该结果迁移为自动检查通过。

## 行为

- 安装版启动约 30 秒后，在后端已就绪且没有退出/维护时检查；后端仍启动或维护中则延后，每分钟观察一次是否可以检查。
- 成功检查后约 24 小时再查；联网或清单失败静默，约 1 小时后重试。程序关闭时不运行，不注册系统后台任务。源码 debug 运行不自动联网，保留手动检查。
- 发现新版本时显示已有更新窗口，创建时不抢焦点；同一版本自动提示一次，已提示版本保存在本机。后续仍能在菜单打开更新窗口，手动检查不受提示去重限制。
- 已下载并验签的包不会被自动检查覆盖；自动任务与手动检查/下载共用互斥标志，维护/退出期间不弹窗。
- 自动任务只取清单，不下载归档、不验签归档、不关闭后端或执行备份安装。下载、安装确认及退出重启沿用已经施工的用户主动流程。
- 更新窗口新增“自动检查更新”，默认开启。关闭后下一次计划检查停止；正在进行的请求不会强行中断，但会丢弃其自动提示。手动检查继续可用。

## 实现边界

原生 `updates.rs` 复用同一个 `check_release` 来配置来源和验证版本包 URL；定时线程的网络 I/O 不阻塞窗口主线程，窗口创建通过主线程调度。公开源直读固定 GitHub `desktop-dev/latest.json`；本次进程已设置可选私有令牌时沿用授权 API，仍不持久保存令牌。

偏好由 Tauri 的 app_config_dir 定位为 macOS `~/Library/Application Support/app.aliceharness.desktop/updater.json`，与独立 Alice 记忆目录分开。文件只含 enabled 和 announced 版本，目录 0700、文件 0600，采用临时文件写入、同步后改名；拒绝符号链接路径。已存在但不可读或损坏的偏好按关闭自动检查处理，用户可手动重新开启；设置写入失败在窗口中显示错误并保留原选择。偏好不进入 Alice 数据恢复点。

设置入口与现有更新命令一样，仅允许 bundle 内 updates 窗口调用。没有新增模型能力，因此不改核心 commands.json 或宪法；`resource-manifest.json` v6 的 updater 组件声明同步为 scheduled-check-manual-install-signed-macos。数据格式 v1、签名公钥、下载大小限制、备份及安装保护不变。

本轮同时将下载 HTTP 失败与大小超限提示分开，避免把标签/附件 404 误读为安装包太大。UI 合并状态快照与下载进度，避免部分进度帧重置版本、授权或开关显示。

## 验证与交付

按项目规则不执行机器行为测试。仅执行 Python/JS 语法、diff、Rust 编译与安装材料静态检查；不启动现有 App、不读取真实配置记忆、不调用模型。0.1.5 已生成于 `addons/desktop/build/releases/20261116T011253Z-e95d3fab-dirty/`：DMG 39,105,467 字节，签名归档 32,830,352 字节，`github-release/` 包含版本附件与 `latest.json`，目标 tag 为 `v0.1.5`。Rust debug/release、Python/JS 语法、diff、129 项资源、66 项 Mach-O、codesign、DMG、更新签名、文件摘要与宿主/后端声明、清单版本/地址静态核验通过。构建来源仍为 e95d3fa 加本地改动，真人状态 pending。

工作区同期另有他人的 `web/app.js` 改动，本轮未修改它。比较冻结资源，0.1.5 相对真人通过的 0.1.4 只有 `alice/__init__.py` 版本摘要变化，冻结网页未包含同期前端变更；原生宿主和 bootstrap 则包含本轮自动检查实现。本轮用户已授权将桌面更新代码与设计验收文档随本次提交上推 origin/ytq，排除同期前端未完成改动、个人资料/数据/观察记录、构建产物及已有删除操作；代理未发布 Release。

## 真人验收（待执行）

1. 发布 0.1.5 版本附件与对应 desktop-dev 清单，通过现有 0.1.4 客户端升级；同版本不会触发更新。
2. 在 0.1.5 更新窗口关闭开关，退出重开确认仍关闭；手动检查仍可用。重新开启，重开后确认仍开启。
3. 让通道指向真实更高版本（后续另出包），启动 0.1.5 等待约 30 秒，确认自动提示、不抢聊天焦点；未点击下载时不下载、不备份或退出。
4. 关闭提示后，退出重开不重复提示同一版本；菜单仍能查看。新版本或明确手动检查仍可显示更新。
5. 在真实断网/恢复网络情况下核对没有错误弹窗、卡住聊天或退出；每日周期、失败重试、维护/退出并发、已下载包保护等待真实条件逐项验收，不由短时观察推断通过。

实际数据恢复与中断撤销仍按用户此前决定暂缓；不因本轮增加自动检查而重启这些演练。
