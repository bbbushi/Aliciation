# 桌面透明气泡聊天：设计 v1

日期：2026-11-16。状态：已按用户“施工”指令实现 macOS 0.1.6 首版，尚待真人验收；实际范围与验收见[实施记录](桌面透明气泡聊天-实施与人工验收-20261116.md)。下文保留设计依据。

用户后续要求参考 Coopanion，0.1.7 已改为两级点击入口和逐句气泡，见[最新实施记录](两级入口与逐句气泡-实施与人工验收-20261116.md)；以下保留最初设计，不作为最新交互说明。

## 目标与边界

Alice 在后台运行时，桌面边缘提供可直接交流的小入口。用户点击后能在原地输入、阅读回复；主窗口不必打开。与主窗口共用同一个永久会话、人格与记忆，不创建第二个 Alice 或第二个模型客户端。

“不影响工作”具体指：被动出现的消息不抢焦点、不占键盘、不拦鼠标；只有用户主动打开输入面板时，面板本身才接收输入。透明指窗口外壳全透明，文字气泡保留足够的底色与对比度，不对整个窗口统一降低透明度。

首批面向目前已有安装包的 macOS Apple Silicon。Windows 保持同一交互设计，但窗口层级、点击穿透、多屏缩放、输入法与全屏行为须另作原生实现及真人验收，不宣称随 macOS 一并可用。

## 使用过程

设置增加“桌面气泡”开关，首次默认关闭，用户打开后生效；首次说明“隐藏主窗口后仍在运行，可通过设置或菜单退出”。菜单栏提供打开聊天、打开主界面、暂停气泡、退出 Alice 的备用入口，防止气泡移出屏幕后无法操作。

1. 主窗口处于前台：气泡收起，继续正常使用主界面。
2. 切换去其他软件、最小化或隐藏主窗口：短暂防抖后，在屏幕右侧靠下出现约 44 × 44 逻辑像素的入口，可拖动并记住位置。
3. Alice 有已经生成的可展示消息：入口旁展示最近一条回复的节选，最多三行；约 10 秒后收回，只留未读标记。长消息不铺满屏幕，也不自动滚动桌面。
4. 点击入口：原地展开约 340 × 420 逻辑像素的聊天面板，包含近期消息、输入框、发送、收起、打开主界面；点击输入框后才能打字，不打开主窗口。
5. 点击其他应用：面板收回，草稿保留；Esc 收起，中文输入法正在组词时先交给输入法处理。提供“固定展开”，供用户边工作边聊。
6. 重新打开主窗口：恢复同一段对话，气泡面板收起。切换过程中不取消已接受的生成，不重复发送。

“后台”指 Alice 仍运行、用户正在使用其他应用；退出 Alice 后不存在继续聊天的独立进程。打开更新、恢复、配置等 Alice 自己的窗口时，不把失焦误判为用户切走而弹出气泡。

## 三种显示状态

| 状态 | 可见内容 | 焦点与鼠标 | 收起方式 |
| --- | --- | --- | --- |
| 待机入口 | 小型 Alice 标识、未读标记 | 只有小入口可点击；不自动取得键盘焦点 | 前台主窗口、暂停、退出 |
| 被动消息 | 入口旁少量消息文字 | 消息所在原生窗口完整穿透鼠标，不获取焦点 | 约 10 秒收起；未读仍保留 |
| 主动聊天 | 近期消息与输入框 | 用户点击后才激活；仅面板所在小矩形接收输入 | Esc、收起按钮、切走；可固定 |

被动消息本身不承担点击操作，回复统一点击旁边入口；需要复制、滚动、阅读全文时进入主动聊天状态。第一版以清楚可靠的点击规则优先，不依赖“鼠标悬停后才临时取消穿透”。

## 外观与反馈

- 窗口无标题栏、无整块矩形背景；消息使用圆角气泡，浅深两套颜色跟随主题。正文约 15px、行高 1.6，正文保持不透明。消息底色默认约 85%，可调，并提供高对比度实底；不以毛玻璃作为可读性的前提。
- 展开的聊天框容器全透明（11-16 用户后续要求），消息间隙透出桌面；输入、消息与操作区域分别保留淡底色。实色背景开关可恢复整块底色；首批只做文字与轻描边，不移入主界面的神经球、仪表、侧栏、设置和监测信息。
- 默认不发声音、不闪烁、不抖动、不循环呼吸。鼠标在工作区经过不会展开；快捷操作立即响应，被动消息可用约 150ms 淡入，尊重减少动态效果设置。
- 最近若干轮按需加载，长消息可在面板内滚动。用户回看旧消息时不强制滚到底；新消息只显示“有新回复”。
- 发送中显示一个简短状态；失败保留草稿并说明可重试；结果不确定时先同步原请求，不以“网络错误”作为自动重发的理由。离线或后台异常时显示“暂时无法连接”，不伪装仍在输入。
- 初次展开同步既有历史，建立基线，不将旧记录全部当成新消息。已读只随用户实际查看推进，自动收起不等于读过。

## 不打扰与隐私

桌面模式默认只提示当前 GUI 对话的后续回复；它不额外启动模型、不定时催聊、不改变 Alice 主动消息政策。以后若接入主动消息，须来自核心明确许可的投递结果；不能因历史里多了一条 QQ 消息就原样弹到桌面。

提供“只显示未读，不展示正文”和“暂停桌面气泡”。锁屏时隐藏正文与输入框，待解锁后再按用户状态恢复。全屏演示、游戏与屏幕共享不强行覆盖；跨应用全屏检测与屏幕共享自动隐藏属于平台专项，首批未验收前以菜单一键暂停和默认不跨全屏空间为可控边界，不承诺自动保密。

位置以屏幕工作区与逻辑尺寸记录，避开 Dock/任务栏；拖动吸附边缘。副屏断开、分辨率或缩放变化时，把入口夹回当前可见工作区。首批不自动出现在所有虚拟桌面、不跨全屏空间置顶；跨空间跟随留作后续可选项。

## 原生窗口方案

沿用现有 Tauri 2.12.5 宿主与单个 Python 后端，新增三个职责独立的小窗口，按需创建/显示：

| 窗口 | 职责 | 原生属性 |
| --- | --- | --- |
| `bubble-anchor` | 可点击、拖动的小入口 | 小矩形、透明外壳、无装饰；不随消息自动激活 |
| `bubble-preview` | 被动显示新回复 | 透明、无装饰、不可聚焦、整窗鼠标穿透 |
| `bubble-chat` | 直接阅读、输入、发送 | 有界小面板，用户主动打开才聚焦；隐藏后保留页面及生成连接 |

选择拆窗是为了避免一个大透明矩形挡住其他应用。CSS `pointer-events: none` 只能改变页面内事件目标，不能作为操作系统级点击穿透的保证。三窗之间的边距也不得额外创建覆盖桌面的可交互透明层。

Tauri 已有透明窗口、`set_ignore_cursor_events`、`set_focusable`、置顶等能力。当前锁定的 2.12.5 本地源码及官方 2.12.1 发布说明均表明透明不再要求开启旧 `macos-private-api` 开关。仍须在真实系统确认首次显示白闪、窗口阴影、首次点击与焦点行为。macOS 已聚焦的窗口不能仅靠 `set_focusable(false)` 立即交还焦点，因此被动预览与输入面板分开，收起输入面板时通过隐藏完成焦点交接，不假定修改属性即可完成。

普通应用之上是否置顶仅对气泡相关小窗口生效，用户可暂停。菜单栏/托盘作为稳定召回入口，不能依赖正在穿透鼠标的预览窗口来恢复交互。首批不增加全局键盘监听或辅助功能权限；全局唤出快捷键作为后续选项。

## 会话与权限

现有 `/api/chat` 流式回复、`/api/history`、`/api/chat/activity` 与会话身份/请求身份机制可以作为接入基础。新增精简同源气泡页面及静态资源路由，不复制完整 `web/app.js` 页面、不额外直接读取数据库、不接入第二个模型实例。

抽取或复用必要的聊天传输与记录归并逻辑，保留 `session_epoch`、`request_id`、服务端忙态与不确定结果处理。当前 `web/app.js` 有另一棒未提交的逐句展示修改，施工前须协调该处公共逻辑，不能覆盖或夹带其半成品。第一版不在气泡入口操作人格、模型配置、工具审批或 P1 许可，需要这些操作时明确打开对应主界面。

一次提交只有一个发送者持有流式连接；另一个窗口通过公共历史/活动投影更新，消息按 ID 归并。切换界面隐藏发送者窗口而不销毁它；独立端异常导致流中断时，沿用既有服务端请求记录核对结果，不从另一个窗口再次付费执行。跨窗口提示只是刷新线索，最终以服务端事实为准。

主窗与气泡窗的草稿分开保存，切换不覆盖另一处未发送文字。关闭面板只收起；如需跨整个应用重启保存草稿，另行加入受控的本机草稿存储，不默认把正文写进普通偏好文件。

页面由后端实际回环地址同源提供，继续遵守 GUI Origin 与 `X-Alice-Intent` 校验，不允许 `null`/任意 Origin，也不由宿主伪造浏览器身份调用 HTTP。原生命令只接受固定动作，核对调用窗口标签、当前 URL 与宿主登记的实例/地址；窗口移动、尺寸、显示、偏好各限定范围。气泡页面不获得更新安装、备份恢复、任意文件、任意外部 URL 或 shell 权限。

气泡启用状态、位置、显示正文选项等可独立保存在宿主配置目录的 `bubble.json`；只存 UI 偏好与已读游标，不保存 API 密钥或对话正文。文件采用与更新偏好同等的原子写入、权限与符号链接保护。此功能为用户界面增量，不是模型工具增量；若以后增加模型可调用的桌面投递能力，再同步能力注册表与必要自我事实。

## 后台生命周期、退出与更新

现状：`main.rs` 的主窗口 `CloseRequested` 调用 `Backend::quit`。因此只增加透明窗口还不能实现后台聊天，必须同步区分“隐藏主窗口”与“退出应用”。

- 开启桌面气泡时，主窗口关闭按钮隐藏主窗并显示入口；首次启用时说明此行为。关闭气泡功能后沿用现有正常退出规则。
- 设置的退出图标、菜单“退出 Alice”、Cmd+Q 仍走现有正常排空和退出，所有气泡随之消失，不残留第二个后端。关闭小面板永远不被解释为退出应用。
- 更新安装、备份恢复、退出排空期间统一收起气泡、禁止新发送；保持现有备份及后端停机顺序。隐藏主窗口不能阻止显式更新确认与必要的故障反馈。
- 模型/API/人格尚未准备好时，气泡显示简短说明和“打开设置”，不提供假装能发送的输入框。后端崩溃时由宿主故障入口负责召回，不能因主窗口已隐藏而丢掉错误。
- 只在显示且需要同步时轮询公开投影；后台降低频率，收起后停止动画。切换到其他应用不会结束 Python 服务或新增模型调用。

## 施工顺序与人工验收

第一步先做原生窗口骨架和后台生命周期：开关、隐藏/召回、入口拖动、穿透预览、主动输入框、正常退出。真人在浏览器、编辑器和中文输入法中确认不抢焦点、预览下方可点击、只有小面板阻挡输入。

第二步接同一会话：先历史/活动，再发送/流式回复、请求身份、草稿与已读。真人验证主窗发消息切到后台仍能收到、气泡发消息主窗记录一致、切换时不重复发、不丢尾部回复；断线、忙态、会话变化均保留可核对状态。

第三步打包检查与体验验收：按项目策略仅做静态语法/构建/资源/签名核验和真实环境人工验收，不编写或运行自动行为测试。验收覆盖浅深色桌面、长回复、中文组词、复制滚动、外接屏拔插、睡眠唤醒、锁屏、退出重开、已有更新/维护窗口共存；Windows 后续单列验收。更新失败恢复与实际数据恢复仍按原先暂缓决定，不由本功能擅自重启测试。

设计阶段仅形成设计稿，未改运行代码、未启停 App/服务、未访问用户资料、未调用模型，未提交或推送。
