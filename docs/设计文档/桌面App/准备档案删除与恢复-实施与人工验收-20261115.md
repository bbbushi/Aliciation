# 准备档案删除与恢复

2026-11-15，按用户“添加准备档案删除”施工。仅增加 GUI 管理入口，不自动选择或删除任何已有档案。

## 行为

- 材料候选预览新增“准备档案”，可进入列表；有未保存修改时先确认放弃界面修改。列表中的非活动档案有“删除”按钮，使用应用内确认框，默认取消。
- 删除将固定 token 对应 JSON 原子移动到同目录 `.deleted/`；“已删除档案”可恢复，恢复只回列表，不自动启用或安装。没有永久清除或自动清空回收区；已删除列表最多显示最近100项，超过时明确标注“最近”。近期排序按移动后的文件时间，JSON正文不改写。
- 活动候选不能直接删：先使用“取消候选（保留档案）”，再回列表删除。后端重新检查活动槽，不信任按钮状态；不可读候选槽保守拒绝操作。
- 删除/恢复携带 archive_revision，绑定档案规范化内容摘要。身份格式、固定目录、普通文件、读取上限、版本与同名冲突都由核心检查；拒绝链接，不接受网页传入任意路径。文件已移动/变化时提示刷新，不覆盖已有目标。
- 已安装人格、对话、记忆、安装日志与旧会话备份不在该操作范围。操作不调用模型、不接触 API Key。已有最近准备档案的自动留存策略保持原逻辑。

## 接口与边界

`ChatService.material_import` / 本机 GUI `/api/persona/material` 新增 `delete_preparation`、`restore_preparation`，参数为 action/token/archive_revision；沿用 GUI 来源/意图、渠道控制与服务锁。status 返回每条准备档案的 can_delete、delete_issue、archive_revision，以及 deleted_preparations 与截断标记。

实现放在新标准库模块 `alice/persona_material_archives.py`，不修改四份参与人格准备实现摘要的文件，避免仅增加档案管理就使已有候选失效。模型没有获得删除人格材料的工具；这是用户 GUI 管理操作，无模型工具注册表或宪法事实增量，公共面已同步工作区约定。
