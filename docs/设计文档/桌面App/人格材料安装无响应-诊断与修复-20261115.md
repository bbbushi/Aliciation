# 人格材料安装无响应：诊断与修复

2026-11-15。用户反馈桌面“安装并归档旧会话”按钮能点，但没有反应或确认弹窗。诊断和前端修复；没有替用户安装、恢复、取消候选或重新调用模型。

## 真实候选证据

桌面实例为回环55142/PID5227。通过同一服务的正常浏览器 GUI，只读打开“查看／继续原文准备”，当前活动候选 `mat_bf586af977ee4977902b0135f6cac0df` 第1版：原稿1840字符、21块；理解/分类两阶段均为 received，分别19.8秒/16.4秒，模型 deepseek-flash。当前预览核心851/2200字符，有效表达658字符；full、registry 均可用，安装按钮可点击。9块确认、2块待分类、10块仅存档；两条设定/背景提示未阻止其他合格表达安装。未据此宣称所有人格内容均采用或通过聊天体验验收。

候选绑定的四份实现文件摘要与磁盘当前源码一致，候选未绑定已有人格、当前也尚无已安装人格。此前另一份已取消候选曾在理解阶段失败，不能把那条旧错误当成这次候选的结果。

## 原因与修复

安装回调在发请求之前同步调用 window.confirm。桌面原型没有接入 dialog 插件或原生 JS 确认框适配，而用户明确反馈没有弹窗；浏览器同源预览可安装，结合代码路径定位到桌面确认步骤。WKWebView 的确认框依赖宿主提供对应委托，见 [Apple WKUIDelegate](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:runjavascriptconfirmpanelwithmessage:initiatedbyframe:completionhandler:))；本次没有把浏览器显示正常等同于桌面确认已经验收。

改为原生 HTML dialog 的应用内异步确认，独立于材料预览弹层，默认焦点为取消；Escape 只取消确认，不关闭底下候选。文本通过 textContent 插入；并发确认拒绝第二次打开，显示失败时保守返回取消。只在用户明确点击“确认继续”后提交原有 apply 请求，版本、权限、预算、QQ、归档与后端安装校验不变；取消不写候选或数据库，并提示“安装未提交，已有候选保留”。

同一 app.js 中的重新准备、重新理解、初始化、QQ重置确认、重复发送与关服也替换为 await confirmAction，避免同一同步原生对话框问题。没有覆盖浏览器 window.confirm、没有授予网页原生 IPC/文件权限或自动接受确认。其他独立 addon 的确认调用不在本轮改动范围。
