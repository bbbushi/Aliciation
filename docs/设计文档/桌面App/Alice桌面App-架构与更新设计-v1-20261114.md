# Alice 桌面 App：架构与更新设计 v1

日期：2026-11-14。状态：设计完成，待按施工清单实施；本文件不表示已有安装包或通过真人验收。

用户要求：先出设计文档，再准备施工。采用本地桌面路线，macOS Apple Silicon 首发，Windows x64 后续同架构适配；保留源码运行方式。首版提供应用内更新并安全重启，不做运行中的 Python 代码替换。配套：[施工清单与人工验收](Alice桌面App-施工清单与人工验收-v1-20261114.md)。

## 1. 产品边界与技术选择

用户安装 Alice 后，点击图标即可进入现有聊天界面，无需自行安装 Python、打开终端或启动网页服务。记忆、人格、配置留在本机；模型仍使用用户配置的接口，不因桌面化获得离线模型能力。

确定采用 **Tauri 2 原生宿主 + 原有 web 页面 + 独立 Alice Python 后端**。宿主负责窗口、进程、系统目录和更新，业务仍由核心负责。Tauri 与 Rust 依赖仅进入 `addons/desktop/`；`alice/` 保持标准库约束和现有惰性 OpenAI 导入，`web/` 保持原生 JS，不增加前端框架或构建链。打包工具属于构建依赖。

后端优先评估 PyInstaller `onedir`：分发冻结解释器与依赖目录；不以单文件自解压为首选。原型必须先证明资源、动态导入、子进程分派及签名能工作，再锁定工具版本。冻结程序不是通用 Python，不能继续假设 `sys.executable -m …` 或 `sys.executable addon.py` 可运行。

Tauri 官方提供外部二进制和更新插件；本项目仍须实现后端停机、备份和恢复协调，插件本身不保证 Alice 数据安全。[外部二进制](https://v2.tauri.app/develop/sidecar/)、[更新插件](https://v2.tauri.app/plugin/updater/)。PyInstaller 需要按目标系统分别构建，不能在 Mac 上完成 Windows 后端产物。[打包原理](https://pyinstaller.org/en/stable/operating-mode.html)。

首发包括聊天、人格、记忆、设置和既有观测界面；思想层沿用原有许可和默认关闭状态。QQ、独立浏览器、Claude/DSH 等外部组件分别列出兼容状态，未适配的桌面入口应解释缺少什么，不沿用源码环境的“可用”判断。桌面首发不默认安装 Node、浏览器或外部 CLI，不自动启用任何已有开关。

首版不包含手机端、跨设备同步、常驻托盘、登录启动、系统通知、应用商店发行、增量补丁和远程下发代码。关闭主窗口即进入退出流程；最小化保持运行。日后如支持关窗常驻，必须单独定义后台执行和费用提示。

## 2. 现状与必须先拆开的耦合

本次只读检查基于 `ytq` 当前工作区，包括已有未提交改动；不是只针对 Git HEAD 的设计。

| 当前源码事实 | 桌面化影响 | 施工要求 |
|---|---|---|
| `alice/config.py` 的 USER_DIR、DATA_DIR 从 PROJECT_ROOT 派生 | 安装目录可能不可写，升级可能覆盖数据 | 统一解析资源目录和用户目录 |
| `--config` 只指定配置文件，未隔离默认数据库/人格路径 | 仅换 config 不能隔离桌面与源码实例 | 新增独立用户根目录入口 |
| `alice/server.py` 在构造 ChatService 前绑定端口 | 已防同端口重复启动，但随机端口仍可共写数据 | 新增按数据根目录持有的实例锁 |
| Host、Origin、X-Alice-Intent 校验限制 GUI 请求 | 自定义协议页面直接请求 HTTP 可能不兼容 | 主窗口直接加载实际回环 URL，保留同源 |
| `/api/shutdown` 是 GUI 专用；`ChatService.close()` 可能提取记忆 | 宿主不能伪造浏览器来源关服；退出可能调用模型 | 增加独立宿主控制通道，显式退出原因 |
| `discovery.py` 用 `sys.executable -m alice.discovery_worker` | 冻结后可能错误启动服务或失败 | 固定后端 worker 分派入口 |
| B站/Claude/DSH 等通过 Python 脚本子进程接入 | 冻结解释器不能直接解释任意脚本 | addon 独立可执行入口或声明未适配 |
| 宪法、能力 JSON、网页、人格实现摘要依赖文件路径 | Python 分析器不会自动收齐所有资源 | 维护显式资源清单和实现摘要材料 |
| `requirements.txt` 同时列 openai、matplotlib | 直接全装会带入出图依赖 | 桌面构建依赖独立锁定，运行包不含 matplotlib |

当前退出和任务恢复语义必须先盘点。尤其不可把取消本地等待写成远端付费调用已取消，也不可重放不确定的外部副作用。

## 3. 模块与依赖方向

```text
addons/desktop/（Tauri / Rust）
  ├─ 窗口、原生菜单、实例唤醒、更新编排
  ├─ 启动固定的 alice-backend 可执行文件
  └─ 私有继承管道 ↔ 核心公开 desktop-host 协议
                          ↓
web/ ← 同源 HTTP/SSE → alice/server.py → ChatService
                                           ↓
                               本机配置 / 记忆 / 人格
```

计划目录：`addons/desktop/src-tauri/` 放宿主和配置，`addons/desktop/packaging/` 放冻结入口与资源清单，构建产物进入独立且忽略的目录，避免覆盖现有 `dist/`。核心提供 `alice/runtime_paths.py`、`alice/instance_lock.py`、`alice/desktop_host.py` 等标准库模块；具体命名可在施工时微调。

addon 只执行公开 CLI、消费公开协议及网页接口，不导入 Store、内部调度器或直接读写活库。备份、迁移、完整性检查和恢复属于核心公开维护能力。不能把 `tools/` 变成 App 运行依赖。新增公共面须同步工作区约定；用户或模型可见能力变化按实际范围同步注册表和必要自我事实，原生更新不是默认授予模型的工具。

## 4. 文件布局与实例所有权

| 用途 | macOS | Windows |
|---|---|---|
| 可替换程序资源 | Alice.app 内 | 每用户安装目录内 |
| 默认用户根目录 | `~/Library/Application Support/Alice/` | `%LOCALAPPDATA%/Alice/` |
| 配置/记忆 | 根目录下 `config.toml`、`data/` | 相同结构 |
| 日志/更新缓存/恢复点 | 根目录下 `logs/`、`updates/`、`backups/` | 相同结构 |

这里的 App 用户根目录与源码检出的 `user/` 独立，不违反每检出专属数据的约束。首发不共享可写目录，不自动扫描或复制源码检出。暂定稳定 App 标识 `app.aliceharness.desktop`，首次签名发布前固定；后续变更标识必须附迁移方案。初始只承诺 macOS arm64 和 Windows x64；Intel Mac、Windows ARM 后续单列构建和验收。

新增全局 CLI 参数 `--user-dir ABSOLUTE_PATH`，源码模式不传时仍使用当前 `user/`。入口在导入会缓存路径常量的业务模块之前解析；显式参数优先，其次受控启动环境，最后源码默认值。资源根目录由打包位置解析，不允许网页或普通配置字段指定可执行资源路径。不得用启动后的 monkey patch 改几项常量冒充完整隔离。

所有数据库、人格、归档、观测正文、安装日志和渠道凭据的路径消费者都要审计；`--config` 不隐式改变用户根。桌面模式固定配置位于选定用户根，拒绝其逃逸到安装资源目录。外部 CLI 如访问 App 数据，必须显式指定同一用户根。

核心在打开默认活库前，按规范化数据根获取跨进程排他锁，持有到所有资源关闭。覆盖 serve、普通 CLI 写操作和维护入口；以 OS 锁而非 PID 文件存在与否判定占用，处理符号链接/Windows 路径大小写，禁止两个不同别名绕过锁。Rust 单实例插件仅用于重复点击唤醒窗口，不能替代核心数据锁。被占用时不打开第二份 Store，不自行附着陌生服务，也不终止来源不明 PID。旧版源码进程不认识新锁，因此首次迁移必须明确停服；锁不能替旧版本保证互斥。

## 5. 启动、身份与控制协议

建议新增公开 CLI `alice-backend --user-dir <root> desktop-host --port 0`。这表示未来契约，当前不可执行。服务直接绑定 `127.0.0.1:0`，由 OS 分配端口；禁止先探测空闲端口再启动的竞争窗口。源码 `serve` 保持 8800 默认值。

状态：`stopped → starting → ready → quiescing → closed`；启动或恢复失败进入 `failed`。壳先显示随包启动页；获取核心锁、配置和恢复状态，正常构造服务后才公布 ready。缺少模型配置仍可进入配置界面；禁止为了 ready 自动生成新的人格、清空数据或发测试聊天。

宿主使用独占继承的 stdin/stdout 管道交换有界 JSON 行；日志移至 stderr。进程句柄和管道标识实例，不从端口开放或可预测 PID 推断身份。启动 nonce、随机 instance_id、request_id 用于防串线；不把密钥放 URL、进程参数或普通日志。

协议 v1 最小字段示意：

```json
{"protocol":1,"event":"ready","instance_id":"<random>","nonce":"<launch>","url":"http://127.0.0.1:<bound-port>","build_id":"<build>","schema_version":1}
{"protocol":1,"request_id":"<id>","op":"prepare_exit","reason":"update","target_version":"<version>"}
{"protocol":1,"request_id":"<id>","status":"blocked","blockers":["persona_import_in_progress"]}
```

固定操作仅含 `status`、`prepare_exit`、`commit_exit`、`abort_exit`；明确状态前置条件、幂等 request_id 和超时结果。`status` 只读，不续租任务或调用模型。`prepare_exit` 关停接单并排空任务，可返回 blocked/ready_to_exit；成功后不接新业务，防止备份与退出之间又有写入。`abort_exit` 仅允许在未提交退出时恢复接单。`commit_exit` 走原有服务所有者的关闭路径，关闭结束输出 closed；随后必须观察到进程真正退出。

管道断开：服务停止新接单并进入安全收尾；壳重启不能仅凭历史 PID 杀进程。无法收尾则显示恢复状态，不开启共享数据的新实例。控制协议不给文件路径、任意命令或 Python 表达式入口。主窗口只加载 ready 指定且经解析验证的 `127.0.0.1` URL，后续导航仅允许该精确 origin；拒绝非 HTTP 或越界 URL。

主窗口 HTTP 页面保留现有 GUI 权限检查。原生菜单通过 Rust 和管道退出/更新，不伪造 Origin 调用 `/api/shutdown`。主聊天页不获得 Tauri shell、文件系统、更新安装或通用 IPC 权限。Tauri 默认仅向随包代码开放 API，动态回环页面不额外授予远程命令权限。[权限边界](https://v2.tauri.app/security/capabilities/)。系统浏览器打开外链只允许用户手势触发的 http/https；拦截新窗口、下载和自定义协议，防止导航后继续拥有原生权限。

## 6. 安全退出与后台任务

当前 `begin_shutdown()` 同时停止多个协调器；需拆出可观察的排空状态，不能在 UI 线程同步等待。原生退出界面显示聊天、人格导入、维护、搜索、worker 等阻塞原因；等待期间保持进度可见。业务超时先提示等待/取消更新，不自动强杀。系统强制终止或断电走已有恢复纪律，不承诺零损失。

增加明确退出原因：普通退出保留当前配置允许的收尾行为；**更新和迁移退出不启动新的记忆提取、人格演化或付费模型调用**，原始已保存对话交由下次正常启动按原许可处理。已有模型调用等待结束或按既有可取消语义处理。后台探索停止新任务，区分 queued、completed、unknown；QQ 投递和外部 worker 的未知副作用不能自动重做。

正常关窗进入退出流程，确认完成才退出壳。用户请求更新时也走同一状态机。Windows 更新器可能在安装前退出宿主，因此所有排空、备份和日志落盘都必须在调用 install 之前完成；退出 hook 仅做短收尾，不能承担异步备份。[Windows 更新退出说明](https://v2.tauri.app/plugin/updater/#windows-before-exit-hook)。

## 7. 备份、迁移与恢复

首版先做**离线一致恢复点**：核心完全关闭且已确认无写入后，宿主保持维护锁，通过核心公开离线 CLI 创建恢复包。维护锁到下次接管之间无无锁间隙；跨进程交接需带所有权凭证/接管确认，不能放锁后再抢锁碰运气。实现过重时可先由宿主持有全程锁并只向指定后端授权，所有 CLI 都必须理解这一协议。

恢复包包含配置、SQLite（包括必要 WAL 状态）、人格/原稿/快照、思想与记忆依赖文件、重置与安装日志、渠道状态，以及实际存在的其他用户数据。凭据包含与否明确标记；本机更新恢复点含凭据并限制权限，对外导出默认排除凭据。日志和下载缓存不递归进入备份，历史恢复点也不互相嵌套。索引记录文件清单、hash、schema、来源 build、恢复协议版本，不记录正文摘要或密钥。

离线核心负责 SQLite 一致性和引用完整性核查，不让 addon 直接读 SQL。恢复包先写临时目录，完成验证后原子发布。空间不足、备份不完整、权限异常均阻止安装。首版不自动删除最后一个已确认可恢复点。

从源码迁移：用户显式选来源 → 确认旧服务停止 → 核心离线导出 → App 用户根旁暂存与核验 → 原子安装 → 首次正常打开。源 `user/` 保留；目标非空时拒绝直接覆盖，必须先保存目标恢复点并确认替换。首次迁移不同时启动新旧 Alice，不合并两份人格或数据库。

更新新增统一数据格式版本和迁移账本；启动前检查可读/可写范围，不允许旧程序先打开新库再报错。每次迁移记录开始/完成/失败，尽量事务化；跨文件操作用恢复日志。失败留在恢复页，不继续聊天。不能只靠 SQLite user_version 覆盖现有业务代际和安装日志。

回退分两类：未更改数据格式且旧版本声明兼容时可退程序；已迁移时需恢复程序与匹配的完整数据恢复点。恢复旧数据会丢失备份后的新对话，必须展示恢复时间和影响并由用户明确选择。绝不自动用旧备份覆盖已有新对话。Tauri updater 不替项目完成此回退流程，首版允许走有说明的手动重装与核心恢复入口，不宣称自动回滚。

## 8. 更新与发布

统一更新壳、网页、Python 核心和随包资源，避免接口/宪法/注册表版本混用。首版整包下载，用户在原生菜单“检查更新”查看版本与说明，选择“下载”，下载完成再选择“更新并重启”。默认仅手动检查；可选自动检查，关闭后不联网查更新。无自动强制安装，也无远程脚本执行。

状态：`idle → checking → available → downloading → verified → preparing → backed_up → installing → verifying → complete`；每阶段记录恢复日志。断网/下载失败留在原版本；签名失败直接拒绝安装；排空或备份失败保留已下载包并给出重试。调用安装器前必须验证运行目标匹配、完整性及当前实例身份。

更新源采用固定 HTTPS 端点，先独立测试通道，再稳定通道。托管位置待发布时选择（可用静态托管或 Releases），设计不依赖专用更新服务器。Tauri 使用自身标准更新清单和签名，不自造不兼容字段；额外兼容信息放入被签名安装包内的 `release.json`。清单可显示说明，真正启动前再以签名包内兼容信息为准。

`release.json` 至少包含 app_version、build_id、源代码修订和 dirty 标记、target、host_protocol、resource_revision、schema 可读/可写范围、migration_from、component_status 和恢复协议版本。正式产物从可追溯提交构建；当前脏工作区只能产内部开发包。版本与架构不匹配时不能安装后再猜。

更新包签名与 macOS 开发者签名/公证、Windows 代码签名分别配置。更新验证公钥随程序固定，私钥留在受控发布环境，不进仓库和用户配置；记录密钥备份与轮换步骤。没有证书、更新密钥或托管地址时可继续做本地原型，不得把未配置更新的包标为正式可自动更新。[Tauri 签名与更新格式](https://v2.tauri.app/plugin/updater/)。

macOS 先提供 `.app`/DMG；Windows 先选每用户 NSIS 安装，避免默认管理员权限。最终支持的最低系统版本要以选定工具链、WebView 与目标真机验收结果固定，不能以“能编译”当作系统支持。Windows WebView2 的检测/安装策略也属于安装验收。

## 9. 冻结资源与外部组件

资源清单至少含：`web/` 全部实际引用资源、`constitution.json`、`capabilities/commands.json`、配置模板、观测 addon 的网页与 manifest，以及人格流水线计算实现摘要所需材料。使用构建时稳定摘要或只读附带源码材料，不因冻结导致摘要变化而偷偷重新处理人格。

主后端冻结入口分派固定 `serve/desktop-host/discovery-worker` 等公开模式，参数白名单化，worker 不得误开主数据库。现有源码模式仍使用原 Python 调用；冻结模式选固定可执行入口，禁止任意 `-m` 或脚本路径。包含懒导入的 OpenAI 依赖及证书资源，冻结清单锁定实际版本；出图依赖不打入。

addon Python 工作者需要各自独立构建入口，保留核心不 import addon 的单向边界；Node/浏览器组件用受控路径与单独安装目录，不能向签名包内部写 node_modules 或安装产物。首发组件 manifest 必须诚实区分“支持/未安装/此包未适配”，对话可用与可选能力可用分别验收；不修改用户原配置来隐藏不兼容。

API key 首发兼容当前本机 TOML 保存方式，配合每用户权限和日志脱敏；不能在未接通读写/迁移之前宣称已用系统密钥链。系统凭据存储作为独立后续阶段，需核心标准库与宿主的固定凭据桥，网页不能读回明文。任何更新都不能把 key 写入更新 URL、遥测或崩溃报告。

## 10. 实施批次与完成口径

1. P0：路径/实例锁/固定进程模式设计落地，确认所有路径消费者；不操作活库。
2. P1：源码后端与 Tauri 原型，通过真实窗口完成启动、配置、聊天、退出和独立数据目录验收。
3. P2：冻结后端与 macOS 安装包，在无 Python 环境的干净用户账户人工安装、重启和迁移。
4. P3：备份恢复与双版本升级，在独立真实数据上演练下载、排空、安装、迁移失败和恢复。
5. P4：Windows 原生构建与人工验收，覆盖进程树、路径、锁、WebView2、安装/更新与数据恢复。
6. P5：签名、托管、版本通道和发布记录齐备后再正式分发。

按项目规则仅做真实环境人工测试；静态语法、编译和 diff 检查不替代功能验收，不新增机器行为自测或冒烟测试。当前本机服务和既有未验收项不因桌面设计而改变状态。详细文件计划、阻塞条件与记录模板见配套施工清单。
