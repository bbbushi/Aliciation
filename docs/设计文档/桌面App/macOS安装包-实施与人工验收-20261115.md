## 实施

- `packaging/backend_entry.py` 只启动公开 `alice` 模块 CLI；固定 `desktop-host`、`discovery-worker` 分派沿用核心实现，不将冻结后端当作脚本解释器。
- `alice-backend.spec` 显式收集核心模块、SDK 模块和发行元数据，保留人格准备校验所需 `.py` 源文件。SDK 模块名从发行文件清单读取，避免为枚举而执行未使用的 agents 子模块。
- `requirements-macos-arm64-py314.lock.txt` 锁定 20 个构建/运行依赖及 wheel SHA-256，隔离到 `packaging/.venv/`；未安装绘图库，不改变项目现有 `.venv`。
- `resource-manifest.json` v2 精确包含核心 Python/JSON、web、上下文观测插件和配置模板，禁止用户目录、缓存、Git 内容和资源符号链接；实际收集 128 个文件，每个记录 SHA-256。
- `build_macos.py` 静态核对核心与宿主版本，构建 PyInstaller onedir 与 Cargo release/custom-protocol，组装 `Contents/MacOS` 与 `Contents/Resources/backend`、Info.plist、ICNS 图标和依赖许可目录。构建记录写入源提交、dirty 状态、依赖锁摘要、平台/组件与验收状态。
- Python 与 Rust 依赖的发行许可进入 `ThirdPartyNotices`；Cargo 清单包含全部锁定平台/可选组件，不能据此推断全部进入运行包。
- 先签宿主和应用外层，保留 PyInstaller 对后端的签名，再做 deep/strict 校验；DMG 内为 Alice.app、“应用程序”快捷方式和安装说明。

采用 [PyInstaller onedir](https://pyinstaller.org/en/stable/operating-mode.html) 收集解释器与依赖；目录布局与 [Tauri macOS bundle](https://v2.tauri.app/distribute/macos-application-bundle/) 一致。当前由本项目构建脚本组装和签名，没有引入另一个 Tauri CLI 工具链。

## 真人安装验收

1. 先正常退出源码桌面原型；双击 DMG，将 Alice 拖入“应用程序”。
2. 从“应用程序”打开 Alice，确认随机端口启动，并沿用独立桌面数据；若是新账户，应先配置模型 API，再导入人格。
3. 在没有检出目录、没有本机 Python 的干净账户重复打开，验证无需开发环境。带空格/中文路径另行覆盖。
4. 人工确认模型列表、一次真实聊天、人格材料准备/安装与观测界面；对话/人格内容只由用户选择，不以脚本代发。
5. 点击设置下方退出图标，确认正常收尾、窗口关闭且无 Python 异常提示；再打开核对对话/人格连续性。
6. 检查第二次打开能唤起唯一实例；缺失组件提示与实际范围一致。
7. 覆盖安装前退出旧版；删除 Alice.app 后用户数据仍保留，不在本批执行数据删除或自动迁移。
