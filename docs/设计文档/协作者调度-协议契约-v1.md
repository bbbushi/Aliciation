## 一、帧协议（宿主 ↔ adapter，stdin/stdout JSON 行）

- 每帧首行一个 UTF-8 JSON 对象，字段 `protocol_version`（恒 1）+ 帧名 + 载荷；每帧 ≤ 256 KiB，结果清单 ≤ 1 MiB，待处理事件队列 ≤ 128 项。过限 → 宿主按协议违规终止尝试（`protocol_violation`），不假装读完。
- 宿主 → adapter：`start`（一次性，进程启动参数之外的第一帧）→ `go`（预算预留与政策复核完成后才发）→ `cancel{reason}`（任意时刻可发）。
- adapter → 宿主：`ready{adapter_version, cli_version, effective_capabilities}` → `progress{phase, counters}`（有界枚举+数值，限频合并）→ `usage{sequence, cumulative, confidence}`（seq 单调，宿主不重复累加）→ `result{status, artifacts[], report_ref?, usage_final, errors[]}`（每尝试恰一个终态）→ 收到 cancel 后 `stopped{local_confirmed, remote_state}`。
- **ready 前禁止付费与业务副作用**；做不到的 CLI 由 adapter 在 GO 后才启动（adapter 是 CLI 的监督壳）。
- stderr：有界缓冲（各 64 KiB），只进诊断，不进 UI、不进模型。
- 状态码（宿主判给任务的终态，worker_failed 嵌套 adapter 自报 code）：`succeeded / failed / cancelled / interrupted / unknown`；宿主侧违规另设 `protocol_violation`。

## 二、任务状态机（worker_tasks 表，全部迁移由宿主短锁内执行）

- 执行主态：`queued → starting → running → collecting → succeeded`；失败分支 `failed / cancelled / interrupted / unknown`。
- 取消是独立意图字段：请求取消 ≠ 已取消；确认回收前不进 `cancelled`；资源未回收保留 `draining` 标记并阻塞同资源组新任务。
- 三条验收线互不冒充：`validation_state`（宿主结构检查：路径/格式/大小）、`review_state`（人工：unreviewed/accepted/rejected）、`delivery_state`（available/presented/withdrawn）。
- 幂等键：`(epoch, originating_request_id, tool_call_id)` 唯一 + 参数哈希；相同 → 返回原 task_id，不同 → `request_conflict`。
- 代际绑定：任务绑定 `session_epoch` + `policy_revision`；重启后 queued 且从未建尝试的任务先挂起，等用户显式恢复时重核输入/政策/额度；不自动重跑。
- 启动间隙崩溃 → `interrupted/unknown`；不承诺 exactly-once。

## 三、名册与有效能力（collaborators.py）

- 三态分离：安装描述（注册项）/ 用户政策（enabled、许可输入范围、额度、并发）/ 运行事实（版本匹配、依赖、最近阻塞）。
- **有效能力 = 已认可安装 ∩ 用户政策 ∩ 当前渠道范围 ∩ 运行条件**；模型名单、工具挂载、实际执行三处读同一视图；每次派工重新核验。
- 失败分话术（对 Alice 的错误码）：`unknown_worker`（不在名册）/ `worker_disabled`（政策禁用）/ `worker_unverified`（未过人工注册验收）/ `channel_forbidden`（渠道不开放）/ `quota_exhausted` / `request_conflict`——都 ≠「没找到」。
- 注册项字段冻结：`name, kind(agent|tool|channel), adapter_id, adapter_version, protocol_version, task_schema, result_schema, provides, use_when, not_for, permission_profile, requirements{isolated_session, owned_process}, budget{unit, per_task_cap, per_day_cap}, enabled, verified_at, revision`。manifest 永不含可执行命令与凭据；`adapter_id` 由核心固定映射到已审核 addon 入口（映射表在 `collaborators.py` 常量，本期仅 testbed）。

## 四、输入与产物（worker_artifacts.py）

- 目录布局：`user/worker_tasks/<epoch>/<task_id>/<attempt_id>/{input,work,output,collected}`；输入先入暂存 `user/worker_tasks/<epoch>/inputs/<input_id>/`，派工时宿主复制获准子集进任务 `input/`。
- 输入：宿主生成最终文件名（用户文件名仅展示），记 SHA-256/大小/媒体类型/许可/有效期；模型只引用 `input_id`，不接收路径。
- 产物收取：先停写入并确认进程回收 → 校验 worker 回传的**相对路径清单**（拒绝绝对路径、父目录逃逸、符号链接/重解析点、越界类型；包含性按 realpath 判定，不做字符串前缀比较）→ 复制进 `collected/` → 宿主计算 SHA-256 → 两阶段发布（暂存 + manifest 哈希）。孤立文件不交付，可重复校验不重启 agent。
- 首期检查器 = 宿主固定非执行性检查（存在/大小/扩展名/文本可解码），**无任意 verify 命令**；任务内容正确性归人工（review_state）。

## 五、预算（worker_budget_entries，本期最小实现）

- 记录四类：`reserved / observed / settled / unknown`；字段含计量单位（token|calls|currency 分列）、资源组、尝试 ID、幂等键。
- adapter 能力声明决定表述：有事前上限+途中用量 → 硬预算；只能事后报 → 软预算/费用记录（UI 如实标示，用户显式接受才可启用）；中断 → `unknown` 保留，不记零。
- 本期无真实 adapter，预算表与预留/结算 API 先落地，计量能力随 D0 核验填。

## 六、D1 机制层人工验收清单（交 DSH；零成本 testbed worker 承载，不涉付费/外发）

1. 名册：注册 testbed → 默认禁用 → 启用后出现在有效视图；禁用后派工得 `worker_disabled`；未验收注册派工得 `worker_unverified`；QQ scope 派工得 `channel_forbidden`。
2. 幂等：同 `(epoch, request, tool_call)` 重复派工返回同一 task_id；改参数同键 → `request_conflict`。
3. 协议：testbed 正常走 start→ready→go→progress→usage→result；宿主不发 go 则无副作用；重复 seq 幂等；超限帧 → `protocol_violation` 终态。
4. 取消：running 中请求取消 → intent 置位 → 进程树回收 → `stopped.local_confirmed` 后才进 `cancelled`；结果与取消竞争按宿主终态提交顺序裁决。
5. 产物：testbed 产 1 合法文件 + 1 越界路径（`../`）+ 1 绝对路径 → 仅合法者入 collected；collected 哈希与暂存一致；孤立文件不交付。
6. 重启：running 中杀宿主 → 尝试标 `interrupted/unknown`；queued 未启动任务重启后挂起待显式恢复。
7. 代际：政策 revision 变更后，在途任务按「先阻新准入再取消」处理；旧 epoch 任务结果对新 epoch 不可见。

## 七、本期明确不做（防蔓延）

无网络、无模型调用、无凭据接触；不接真实 agent CLI（D0 待核验）；不做 HTTP 回调（P2+）；不做多任务并行（全局运行数 1 是本期实施范围）；不做 GUI 结果卡样式（D3）；Windows 进程树回收沿用 browser_transport.ProcessTree 思路，另包提交。
