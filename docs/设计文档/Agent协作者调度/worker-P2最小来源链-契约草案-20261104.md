# worker P2 最小来源链契约

2026-11-04；具体设计待裁决，未开放新正文用途。依据[协议契约](协作者调度-协议契约-v1.md)、[CLI宿主契约](CLI协作-宿主契约补充设计-v1.md)、[任务书 W8](../整体设计迭代概览/Alice架构完善-开发任务书-20261104.md)。本期建议只接 GUI 一种有界文字报告，前置为 W1 双轨可信边界及本机人工证据。既有 GUI 单次无工具总结保持，不能退回早期“只显示元数据”，也不能把它等同完整 P2。

## 1. 材料身份及事实等级

| 对象 | 必需字段／约束 |
|---|---|
| task | `epoch,task_id,attempt_id,worker_id,policy_revision,request_id,dispatch_identity,execution_state`；共享队列不共享授权 |
| artifact | `artifact_id,artifact_version,task_id,attempt_id,kind=report_text,host_acquisition=protocol_message,message_id,body_digest,body_chars,created_at`；宿主从固定进程协议接收并登记的完整有界文字，模型不能自填取得方式 |
| evidence | `evidence_id,artifact_id,artifact_version,scope=full_report,assurance=worker_claim,host_observed_fields,input_dependencies`；不是网页 packet，不支持伪造 source_packet_id |
| grant | `epoch,worker_id,policy_revision,scope_channels=[gui],allowed_purposes=[chat_analysis],expires_at,revoked_at,grant_revision`；到期取政策/输入/材料最短期限 |
| dependency | `consumer_type,consumer_id,consumer_version,parent_type,parent_id,parent_version,purpose,channel,registered_at`；复合唯一键；保守继承所有已暴露依赖 |

`host_observed_fields` 仅包括宿主实际观察的启动/消息接收/结果/停止证据及其未知状态。`assurance=worker_claim` 的正文可以是分析、建议或自称执行结果；退出码和 result 不证明业务正确。工人自报 URL、引文、哈希和“已核实”不变成宿主取得的证据。未来若宿主独立受控重读网页，应另建真实 packet 并关联该 claim；同源重抓只能验证取得内容，不能自称独立佐证。

首版文本建议上限16000字符（包括必要条件及来源标注）；超限返回 `too_large` 不先取半段。摘要不能替代原材料。输入依赖为本次 task 真实获准输入清单及其版本，不能让工人用自报“没用过”解除。不存在的文件ID、下载、跨任务转发均保持unavailable，不接testbed作生产入口。

## 2. 工具和管理契约

拟在既有 worker 公开读面下增加 `worker_material_search(task_ref)` 和 `worker_material_load(material_ref)`；同请求不重复暴露两个能绕过对方预算的正文工具。若现有 `worker_task_read` 已覆盖同样完整文字，扩展其规范回执而非另开工具。是否增加名称由实施时单一工具集合决定。

`material_ref` 是宿主签发的请求内引用，绑定 task/attempt/artifact_version/grant_revision/epoch/channel/request_nonce；裸artifact_id和旧任务ref不能直接展开。目录仅给当前GUI可见材料的类型、时间、长度、状态、`assurance=worker_claim`，不凭目录支持事实回答。正文一次最多1条，共用现有工具总轮数、总上下文预算及 worker 预算。返回 `loaded/already_loaded/unavailable/stale_ref/too_large/budget_exceeded`，分别标记 `loaded`（已交付到装配）和 `sent`（已随实际模型请求发送），不声称模型理解。

拟新增 `ChatService.worker_materials(action, payload)`，固定动作 `list/detail/revoke`，接同源 worker 管理 API，继续目标工人政策及GUI意图校验。只读观察字段：`task_id,attempt_id,worker_id,policy_revision,artifact_id/version,acquisition,assurance,grant_revision,scope,purposes,expires_at,state,dependency_ids,loaded/sent,publish_check`。SDK只能经公共service/HTTP/CLI获取，不import Store或读SQL。本文接口尚未实现，最终名称须在实施记录明确。

## 3. 正文暴露、派生与撤回

1. 读取前检查工人政策、代际、任务和材料版本、用途、渠道、输入依赖、期限及预算，不能用另一工人授权补齐。
2. 在业务事务内先登记本请求所有必要依赖，再取得完整正文；登记失败不给正文，不把观测日志当依赖账本。
3. 每次模型调用前、工具之间、生成完成后、最终发布事务内复核版本。任一依赖失效就拒绝发布有关派生正文；不发未审流式草稿。
4. 回答及历史正文继承全部已暴露依赖；释放上下文或模型自称未使用不解绑。任一侧绑定worker的历史往返仍整体排除普通C3，不能绕过专用政策重读。
5. 撤权先阻止新准入，再按工人及政策版本取消/回收/撤销材料与派生。撤销正文资格和停止执行是两个状态；unknown占槽不阻止撤销正文。DSH撤权不碰Claude材料，除非明确全局epoch重置。

状态：`received → available → expired/revoked/deleted`；只有通过宿主完整接收/校验才available。`archive`只改变列表归档状态，不延长期限/重授用途；`cancel`不自动抹掉已发生账本，也不意味着工人确已停止；明确删除或撤权不因晚到result复活。后续新授权必须新grant，不修改旧账本或退还次数。

派生失效传播覆盖聊天、任务总结、可回放历史、目录、观察器正文、提取、思辨、人格/技能维护、渠道发送。本期后三类写入仍禁止消费worker材料；GUI分析不因总结进入普通记忆。QQ无此正文用途，原任务内容也不得作为下一任务输入自动转发。

## 4. 见闻准入的保留接口

首版不自动入正式见闻。拟设 `admission_state=not_eligible/pending_evidence/eligible/rejected`，默认not_eligible；`worker_claim`永不单独使eligible。未来若要正式见闻，至少必须有：宿主实际取得且当前有效的证据身份、覆盖主张的范围与完整限制、用途与保留授权、可继承依赖、独立准入决定、原claim与核验结果区别、去重/撤回/维护路径。缺一项仍是有标签建议。

观点也不能用“仅个人看法”绕开来源许可，派生输入失效则观点当前资格失效。worker自报成功与用户验收结果分开记录；用户确认“文件可用”不等于批准所有报告事实或长期保存。

## 5. 去重、恢复、迁移和回退

接收幂等键 `(epoch,task_id,attempt_id,message_id,artifact_kind)`；同键同digest返回既有身份，不重复总结/入模计数；同键异digest为protocol_conflict并封该材料，不能覆盖已登记版本。每次实际发送记录attempt，观察失败不重派。

重启不重跑任务、不自动恢复旧grant、不补旧总结；接收中断的材料标unknown/incomplete，不拼凑尾部。已入库材料需全部输入仍有效才可再次申请新请求ref。操作日志只存身份/摘要/阶段，正文已有单一受控存储，不再复制审计全文。

新schema为空且功能默认关。旧报告缺input_dependencies或acquisition证据时保持 `legacy_restricted`，继续原有受限显示但不得自动升级P2。迁移只做用户选定任务的预览与版本化登记；不回扫全部旧任务、不让旧产物取得新授权。schema迁移在未来启动前先备份并取得授权，本轮未运行。

关闭P2后取消新ref签发并保留所有已发生的依赖过滤；已撤回派生不得因旧版不识别新表重新显示。回滚兼容版本必须仍能过滤 `worker_material` 依赖；否则停止正文显示保留元数据，不能简单删新表后启动旧版。旧GUI单次总结不变，除非对应原来源已失效。

## 6. 分包及裁决

最小分包：①schema/身份/公共只读投影；②协议文字取得、严格幂等和输入依赖；③请求内ref/预算/完整读取；④生成和发布复核、全链撤回；⑤受限GUI入口与人工验收。见闻准入仅留拒绝态，下载/跨任务/QQ各另包。

待裁决：推荐允许一种有标签的GUI文字分析材料，仍禁止自动正式见闻；替代为继续只用现有单次总结，不新增持久材料。若采用前者，需确认正文保留期限（推荐不超过任务既有正文许可和最短输入期限，不额外延长）及用户删除时派生同步退出。这里没有批准新权限，W1修复不被该选择阻塞。

人工门槛：真实协议报告完整；工人身份/同版本幂等；自报URL不能变宿主证据；生成期间撤回不发布；恶意正文不改权限；GUI→QQ拒绝；重启不重派/不退款；来源过期后目录及正文都不可用。未发生真实场景就保持待验。
