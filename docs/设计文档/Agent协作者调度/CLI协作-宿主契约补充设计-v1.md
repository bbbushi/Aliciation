# Alice 调用 CLI Agent：宿主契约补充设计 v1

> 2026-11-02｜设计补充，待分项实施与真实环境人工验收。本文不代表相关能力已经接入或验收通过。
> 分支：当前工作在 `ytq`；Claude 直调只在 `ytq` 实施与验收，不合 main。沿用 main 的 DSH 插件桥正典，不恢复已撤回的另一套 D1，也不借统一契约重建现有数据库。

## 1. 结论与边界

继续采用“管家 Alice 协调本机完整 Agent”的方向。近期交付目标是：用户可以在 GUI 授权一个任务，Alice 派给已启用的 CLI Agent，期间继续聊天，最后拿到可追溯的结果，并能知道失败在哪里、取消是否生效、费用是否已结算。先把这一个闭环做可靠，再增加任务类型和并行度。

统一的中心是**宿主任务契约**，不能只把两个工人的名字加进同一个工具枚举。派工、权限、上下文、取消、报告读取和恢复必须识别同一个任务及同一个工人。

| 层 | 负责 | 权限边界 |
|---|---|---|
| Alice | 理解目标与偏好、选择工人、整理任务书、提出澄清或拆分、解释结果 | 可以建议授权，不能授予授权；不能把 worker 自述提升为宿主事实 |
| 宿主 | 身份与准入、队列、政策、预算、生命周期、结果和来源资格、审计 | 不依赖模型自觉来执行权限或状态规则 |
| CLI Agent | 专业规划、工具执行、产物、证据、建议与不确定性 | 不能自授更多输入或副作用权限，不能写 Alice 人格和记忆 |

完整 Agent 可以承担分析和综合建议，不必降格成只会回传原始片段的工具。Alice 也不必重做全部专业推理；她需要围绕任务标准解释交付、辨认证据缺口，必要时建议人工或独立复核。系统能力取决于任务表达、专业能力、上下文、证据与验收，不能保证“上限等于集群上限”，也不预设轻量路由模型一定足够。

人格和长期关系留在 Alice。外部 Agent 本身可能有会话、配置、插件和历史；隔离依赖明确的运行档案，不能用“协作者天然无记忆”代替约束。近期不做任意 CLI 插件市场、多机调度、自动组队或自动退休现有工具。

## 2. 工人身份、政策与适配边界

### 2.1 一次解析，贯穿整条链路

宿主提供统一的工人解析结果，至少包含下表；名称仅作展示，稳定 `worker_id` 才是关联键。

| 类别 | 需要保留的事实 |
|---|---|
| 身份 | `worker_id`、`adapter_id`、transport 类型；桥实例与 CLI 会话句柄是各自 transport 的可选字段 |
| 能力快照 | adapter/CLI/协议版本、支持的任务及结果类型、取消与回收能力、权限档、计量模式、运行档案摘要 |
| 政策 | 工人所属政策标识与版本、启用和认可状态、输入/输出/外发许可、额度与时限 |
| 资源 | 账号、共享配置或可写目录对应的资源组；不在模型上下文保存凭据 |
| 就绪状态 | ready/disabled/unavailable/incompatible 及有界原因；注册、授权、当前可用分别记录 |

工具名单、派工准入、`worker_target`、任务正文读取、历史展开、完成报告和撤销均调用同一个解析入口。先确定目标工人，再读取它的政策：Claude 可用不以 DSH 启用或桥在线为前提；Claude 的目标不能被强制校验 DSH 桥实例。

政策比较键至少为 `(worker_id, policy_revision)`，不能拿两个表中恰好相等的数字版本当同一授权。多工人上下文保存按工人索引的版本快照，不复用单个 DSH 版本字段。已创建任务保留快照用于解释历史，但每次实际执行、读取和交付还要检查当前许可、epoch 与来源有效性；历史快照不是永久授权。

过渡期保留 `worker_policy` 与 `claude_policy`，由解析层封装差异。政策版本表示相关授权变化；同参恢复/短时断开不凭空改版，明确撤销或变更范围按既有规则处理。禁止起服时偷偷重建对方任务表。

### 2.2 最小 adapter 契约

以下是职责，不要求立即新增同名类或方法：

| 操作 | 输入与输出约束 |
|---|---|
| probe / prepare | 检查版本、能力和运行档案，准备任务资源；不隐式运行付费模型任务 |
| start | 接受宿主批准的 task/attempt 和任务书，返回可回收句柄；不得私自生成另一个任务身份 |
| events | 把私有 CLI/桥消息转换成有界、可去重的标准事件；原始 stderr 留内部诊断 |
| cancel / reap | 取消是请求，回收是事实；分别报告送达、退出/整树回收证据或 unknown |
| normalize result | 将文本、产物声明、用量和原生失败类型转换为公共结果；保留原生类型供诊断 |

核心保留通用准入、账本、调度与监督，只使用标准库。CLI 专有参数、stream-json 和 MCP 语义留在 addon/adapter，经公开的进程协议或已有公共 API 与宿主交互；核心不 import `addons`，addon 不 import `alice` 内部或直接操作 Store。入口由受控注册映射确定，不接受模型、网页或 worker 提交的任意启动命令。

DSH 桥和本地 CLI 共用语义，不要求两者采用同一种底层传输。启动可先准备一个不执行任务的 adapter，但真正给 CLI 提交任务书/启动模型前必须已完成宿主准入；仅在日志里写一个 GO 事件不构成门控。

## 3. 任务契约与原子派工

### 3.1 任务书与身份分开

| 宿主信封，不由模型授予 | 任务书，可以由 Alice 整理 |
|---|---|
| `epoch`、`task_id`、`attempt_id`、原始对话 `request_id`、工具调用 ID、幂等键 | 目标、必要背景与已知条件 |
| `worker_id`、政策/能力快照、GUI 渠道范围、获准输入引用 | 输入各自用途、约束与禁止副作用 |
| 输出目录/类型、时间/费用上限、资源组、授权依据 | 交付物、完成标准、遇到缺口时的处理方式 |

原始对话请求 ID、派工回执 ID、attempt ID 各有用途，不能互相替代。用户消息、worker 回复和事件要真实落到账本并保留关联；不能用随机 message ID 代替未创建的消息行，再期望结果读取器找到正文。

首个可验任务可以是：在已获准的独立任务目录内，依据任务书生成一份文本方案，列明假设、证据缺口和待人工确认项。不得为了演示 CSV 场景默认开放尚未接线的文件 ID 导入；文件导入、下载、跨任务转交仍按各自门槛实施。

最小必要上下文由任务目的决定。不要默认导出完整聊天、人格、记忆库或凭据；用户选定的材料要带来源、用途、范围及撤销依赖。资料中的命令或 worker 自述不能扩大授权。

### 3.2 一次提交、锁外启动

准入事务须一起完成：当前政策校验、幂等检查、任务与初始 attempt 登记、真实输入消息登记、额度预留、排队记录和回执。失败则整体回滚，不留“有任务无正文”或“扣了额度无回执”的半成品。

幂等键绑定 epoch、原请求、工具调用和 worker；参数摘要覆盖有效任务书、输入与执行约束。同键同参返回原回执，同键异参报冲突。用户主动重试创建新 attempt，并重新准入；它与传输层重送是两回事。回执明确 `queued`，只有监督器确认启动后才能显示 `running`。

事务提交后再唤醒调度器；调度器以原子领取避免双启动。数据库提交与进程实际接收任务无法组成一个本地事务，所以不承诺 exactly-once。启动窗口崩溃后须核实原 attempt，不自动重发有副作用的任务。

## 4. 生命周期、并发与恢复

### 4.1 状态至少分四个维度

这里描述语义，实施时可映射现有字段，不要求破坏性换表。

| 维度 | 示例状态 | 解释 |
|---|---|---|
| 执行 | queued / starting / running / waiting_permission / collecting / succeeded / failed / cancelled / interrupted / unknown | `succeeded` 只表示协议层任务成功，不证明内容正确 |
| 终止 | not_started / active / cancel_requested / confirmed_stopped / unknown | 请求取消不等于 CLI 或其子进程已停止 |
| 验收 | not_checked / structure_checked / needs_review / accepted / rejected | 结构检查与人工内容验收分别记录 |
| 交付 | unavailable / available / presented / withdrawn | 展示过不等于验收过；撤销资格不能抹去发生过的事实 |

执行报错但仍有未回收进程时，占用资源保持 draining，不能立刻启动下一项。确认没有执行主体存活后才能释放执行槽；无法确认则保留占用并显示需人工处理。不能把 `failed`、`cancelled` 字符串本身当作释放资源的证据。

### 4.2 三种槽与锁

保留对话槽；执行槽独立；Store 只做短事务。初期 DSH 与 Claude 共享宿主总上限 **1 执行 + 4 待办**，并按资源组收紧。费用帽不能代替并发上限，也不能每条 transport 自己开线程绕过总队列。等待质询的任务仍占执行槽，GUI 显示等待用户。

监督器登记每个 attempt 的进程/连接句柄和线程。外部消息先转换为不可变事件，由宿主在短锁内写账；spawn、网络等待、stdout/stderr 读取、质询等待、取消信号和 join 均在锁外。禁止在 Store 锁内等待依赖该锁才能收尾的线程。

总时限用独立的单调时钟监督，不能靠“下一行 stdout 到来”才检查；质询时限与任务总时限分别记录，质询默认 600 秒且不延长总期限。超过时限要明确 deny/停止及回收状态。stdout 使用有界字节读取/帧累计，不能先无界 `readline` 再检查；stderr 有界并脱敏，用户收到原因码和诊断 ID。

启动失败、协议异常、断连、超时、预算触发、用户取消都要有 phase、原因、可确认的回收状态和费用状态。原生结果中的错误必须归一化，不能把“收到 result 事件”或退出码 0 直接等同成功。

### 4.3 取消、迟到事件与重启

取消 API 先提交意图，再由监督器送达并回收。用户立即看到“正在取消”；收到符合该 transport 能力的停止证据后才显示“已停止”。CLI 本地轨须核验进程树；平台不支持的回收方式如实标记，不把 macOS 方案直接宣称适用于 Windows。

取消与结果发布由宿主事务顺序裁决：取消先提交，迟到结果只用于诊断与费用结算，不自动发布正文/产物；交付先提交，后来的取消不能伪称撤回已完成动作，用户可以另行撤销结果资格。撤销授权立即停止新访问和新派工，再锁外取消活动任务；政策撤销、执行停止和结果撤回分别可见。

退出/归档/重置顺序：停止接单 → 锁外取消、回收与等待 → 结算并持久化状态 → 关闭旧 Store 或切换 epoch。旧事件以 epoch/task/attempt 校验，不能通过读取“当前 Store”写进新会话。

重启不把未知 attempt 改回 queued。持久队列也须重新验证许可，先展示待恢复，再按明确恢复策略推进。可能仍存活的旧进程/桥任务先核实，禁止仅凭陈旧 PID 终止进程；无法可靠识别或回收则保留 unknown 和相关资源占用，交由人工处理。重试前先处理旧 attempt 的副作用与消费，防止双重执行。

## 5. 权限档与质询协议

### 5.1 如实描述实际约束

近期可以采用用户知情接受的原生权限监督档，如 `claude_gate_v1`；它不等于 OS 隔离。不同权限档必须标明实际限制哪些工具、进程和路径。`task_files_v1` 所要求的强隔离若尚未满足，不能借同名配置宣称已实现，也不能静默降级。

Claude 的 `--add-dir` 增加可操作目录，不是可见目录上限；权限模式和既有规则决定何时质询，不能保证每个工具调用都经过 MCP 质询。官方内置沙箱的覆盖范围也不等于整个 CLI 的所有工具、MCP 与 hooks。[CLI 参数](https://code.claude.com/docs/en/cli-reference)、[权限机制](https://code.claude.com/docs/en/permissions)、[沙箱范围](https://code.claude.com/docs/en/sandboxing)（核对日期：2026-11-02）。

每个 attempt 固定运行档案：工作目录、可读取的配置来源、模型/后端身份、权限模式、工具集合、MCP、hooks/插件、会话持久化及历史继承方式。采用新会话，不附着用户正在使用的交互会话。配置合并可能保留未显式覆盖的值，因此必须核验有效配置，不能只展示命令行字符串。可用控制参数以本机版本人工核验为准，版本或相关配置变化后使旧就绪认可失效；重新认可前不启动任务。

目录分为任务工作区与宿主控制区；策略、质询答案、回收句柄和凭据不应放进约定的输出范围。每个 attempt 使用独立 MCP 配置与 gate 通道，不能共写一个全局 `gate/mcp.json`。不过同 UID 的非隔离 CLI 仍可能有更广访问能力：目录分离、路径黑名单和随机文件名都不提供对抗性安全边界。能力说明必须保留这一限制。

### 5.2 裁决绑定具体动作

质询至少绑定 `epoch/task_id/attempt_id/worker_id/policy_revision/request_id`、工具名、完整参数的规范化摘要、期限与当前状态。GUI 使用宿主提供的结构化目标与影响，worker 提供的 reason 标为自述；Alice 可以解释，但不能代用户点击许可。

答案提交时，宿主重验活动 attempt、当前政策、请求摘要与期限。第一个有效答案原子落定，同答案重送幂等，冲突答案拒绝；已过期、已取消、跨任务或旧版本答案不能复用。文件中转使用不透明 ID、临时写入后原子替换并检查完整绑定；这些措施解决串线和竞争，不承诺抵御拥有相同系统权限的恶意进程。

“本任务内允许”是有界能力：工具、具体动作、获准资源范围、外部目的地、attempt 与到期时间共同决定。路径按规范化后的真实目标及目录包含关系检查，处理符号链接；禁止字符串前缀匹配授权相邻目录。Shell 不能用命令前 24 字符或任意前缀复用授权；无法可靠解析作用范围时只允许当前完整动作一次，或要求用户预授明确的操作类别。

持续授权范围内无需反复询问；新增输入、目标、副作用或额度才产生新的决策。deny 后不得自动换工具绕过同一被拒动作。缓存、黑名单与质询均只覆盖实际经过它们的动作，不能在能力清单中写成全进程强隔离。

## 6. 费用记录与预算控制

费用、token、任务次数、并发数是不同量；CLI 工具轮数也不等于宿主派工次数。工人声明计量能力，GUI 同时展示数值和依据。

| 模式 | 可以承诺 | 不能承诺 |
|---|---|---|
| `recorded_only` | 记录已报告用量，达到已知阈值后拒绝新任务 | 当前任务一定不超支 |
| `estimated_stop` | 根据 CLI/宿主估算尝试停止，显示可能存在超额与未知尾账 | 最终账单硬上限 |
| `enforced_backend` | 在已验证的后端额度机制和覆盖范围内限制消费 | 覆盖别的账号、手动 CLI 或未纳入的调用 |

`total_cost_usd` 是 CLI 报告值，尤其使用第三方模型/代理时不能称为供应商精确结算。官方 `--max-budget-usd` 按客户端估算消费触发停止，也不能直接解释成绝不超支的账单硬帽。[Claude CLI 参数说明](https://code.claude.com/docs/en/cli-reference)。本机版本和后端是否支持、如何计量仍需真实人工核验。

账本区分 `reserved`、`observed`、`settled`、`unknown`。任务准入原子预留次数与费用估算额度；同资源组的在途预留计入可用余额。没有可靠消费上界的任务，预留值只是准入依据，不能改变其软预算性质。

累计用量按事件序列更新，不能把重复 result 再加一次；结算至多一次，终态已知后释放未用预留，未知尾账保留待核对金额。跨日按原预留所属账期结算，不在新旧两天重复扣费。缺失/非法用量不是 0，取消、失联、启动异常都要明确是否可能发生消费。

配置中 `0`、未配置与无限制分别定义，不用真假值回退偷偷把 0 变成默认额度。预算不能通过改名 worker 或重启清零；同账号的不同 worker 归同资源组。宿主之外的手工 CLI 消费不在本账本覆盖范围内，GUI 明示覆盖范围。

## 7. 结果、产物与记忆

### 7.1 统一结果读取链

adapter 输出标准的 assistant 正文、状态、用量与产物声明，宿主将它们关联到真实 task/attempt/message 及原始对话请求。actor/worker_id 来自任务身份，不能固定写成 DSH。事件流供进度和审计，正文读取器有明确的持久来源；只写 `claude_completed` 事件不能自动保证 `read_worker_task` 有正文可读。

Agent 可以提交完整专业建议，同时给出完成项、未完成项、证据引用、假设、风险和建议复核步骤。宿主区分“worker 声称成功”“协议成功且已停止”“产物已收取”“结构已检查”“人工已接受”；输出卡和 Alice 文案使用对应事实，不压缩成一个绿色成功标记。

### 7.2 文件交付另有准入

worker 产物清单只是声明。开放收取时由宿主核验归属、真实路径、符号链接、类型、大小与摘要，形成不可变 artifact ID；不接受任意本机路径下载。宿主执行固定的非执行性格式检查，不运行 manifest 或 worker 给出的任意 `verify` 命令，也不把语法通过当内容验收。

当前文件 ID 导入、产物下载与跨任务来源转发尚未开放，`worker_artifacts.py` 的存在不等于接线完成。未收取的输出只能显示“worker 报告文件已生成/待收取”，不能声称已有可下载成果。未来通过独立的输入/产物公共契约接线，再增加 CSV、图表等完整场景。

### 7.3 沿用既有 GUI 摘要边界

沿用 PR19 已交付的持久领取、GUI 内单次无工具总结及来源依赖隔离，不退回旧开发稿“只显示元数据”的历史默认。补齐 Claude 时要求同一套身份、领取幂等和依赖规则生效；一次任务结果不应因轮询/重连反复插入总结，也不因总结触发新的派工。

任务正文、标题、证据和派生摘要保留 GUI/epoch/工人政策及实际输入依赖。撤销、必要来源失效和跨渠道读取按同一规则处理；报告摘要不能洗成普通记忆或通过 QQ 泄露。任务事实先留账本，不自动进入人格成长、普通 recall、观察器或见闻。未来纳入记忆须单独设计来源资格和传播规则。

同参重连与显式撤销分开：前者不得随意清除仍有效的正文，后者必须使有关读取及派生资格失效。对外交付、发布和向其他人发消息不由“任务成功”自动授权。

## 8. 实施顺序与完成条件

本轮只补设计；下表是后续施工建议。同步交接记录：`f748e55` 已提交政策/目标分流、工具构造时序、消息与原请求账本、取消句柄及 Row 访问修复，`d6e041b` 记录了对方的真实 CLI 链路验证，用户 GUI 人工项仍待验。这是提交与交接记录，不是本轮独立复验；实施者先核对最新 commit 与下表的剩余差距，保留已完成接线，不能把早期静态发现当作最新代码仍有缺陷的证明。

| 包 | 先做什么 | 完成证据 |
|---|---|---|
| H1 身份与可读闭环 | 统一 worker/policy resolver；工具名单、target、真实消息、原请求、报告归一化 | DSH 禁用且 Claude 启用时，真实派工与结果读取同一任务，无跨政策串线 |
| H2 生命周期 | 原子登记/预留、共享 1+4 队列、监督器、独立期限、取消与重启 | 取消可确认；未知不重派；对话可继续；资源占用和费用状态可解释 |
| H3 权限与费用 | 运行档案、逐 attempt gate、绑定裁决、缓存范围、预算模式与结算 | 真实质询不串线；软预算如实显示；失联不归零；重复事件不双扣 |
| H4 交付闭环 | 标准正文、GUI 领取/总结、来源与撤销传播；文件能力按独立门槛接线 | 用户能核对实际交付，正文/摘要不越渠道，未接线能力不出现在存在事实中 |

H1～H4 的相关要求共同构成首个正式任务闭环，不能只完成 H1 就宣称正式可用。随后再做第二类任务；只有单任务故障闭环与资源组规则通过人工验收后，才提议放开独立任务并行。不提前做通用 DAG、队列服务或全库迁移。

本分支回退路径为：禁用新准入 → 取消/排空或明确标记无法回收 → 保留日志、任务、未知费用与授权审计 → 停用相应挂载。删除 addon 或 DROP 政策表不是运行中回退步骤，不能先毁掉回收和解释旧任务所需资料。

## 10. 对旧设计的明确修订

| 旧表述 | 本文约束 |
|---|---|
| 协作者无记忆；注册即授权；Alice 上限等于集群 | 外部会话/配置显式约束；注册、授权、就绪分离；能力受任务与验收制约 |

| result 费用精确；接上线即有硬预算 | 报告、估算与供应商结算区分；模式、预留、未知尾账分别可见 |
