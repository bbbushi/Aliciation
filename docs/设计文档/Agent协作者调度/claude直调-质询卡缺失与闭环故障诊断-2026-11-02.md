## 修复顺序

1. **A：恢复质询卡**——补固定静态路由，显示加载或读取失败状态。
2. **B：打通结果读取与通知**——按工人统一政策、任务引用、原请求关联和消息身份。
3. **C：修正执行收尾**——规范 CLI 结果判定、等待状态、独立超时和锁外取消。
4. **D：真实 GUI 验收**——由用户实际操作，同一任务完整走通授权、执行、读取和通知，再验证拒绝、取消与超时。

范围限于本次接线修复，Claude 继续仅限 `ytq`。沿用现有权限和来源校验，历史任务不自动重跑；总体设计见 [宿主契约补充设计](./CLI协作-宿主契约补充设计-v1.md)。
