## 1. 产品定位

Alice TUI 是 Alice 的可选终端客户端。用户可以从网页或桌面接着聊，发送中文多行消息，查看回复进度，也能翻看近期对话。各入口共用当前档案的永久会话、记忆、人格和工具权限。退出 TUI 只关闭终端界面，宿主继续负责已经接单的任务和后台活动。

首版采用单列主界面。启动时可直接输入，消息进入当前对话。聊天常驻内容为对话、输入框，以及需要时显示的一行状态。具体工具进度按需展开，高级设置与人格导入在网页或桌面完成，完整上下文和后台调度记录在 Alice Lab 查看。

## 3. Alice TUI 视觉与交互规格（前两阶段已施工，待真机验收）

### 3.1 启动和页面构成

新版样稿采用终端本身的浅色画布。蓝紫色集中在 Alice 像素头像、点阵字标和输入焦点。正文、工具摘要和辅助状态共用等宽网格，通过缩进与间距区分。

- **启动。** 像素头像、`ALICE` 字标和窄输入框居中构成首屏。输入框直接获焦，首条消息接到当前会话。终端较窄或较矮时先减小图形，再缩为一行名称与可用输入。 [启动效果图](./assets/Alice-TUI-视觉二稿-启动.png)
- **进入聊天。** 头像与字标缩小后排在左上，下面接对话正文，输入框移到底部。品牌区可随消息滚出，到较长会话的底部时将空间留给对话。工具进度跟随对应消息，默认以一行缩进摘要呈现。 [聊天效果图](./assets/Alice-TUI-视觉二稿-聊天.png)

头像使用 Alice 首次引导形象的低分辨率采样。连接中显示短状态，档案尚未就绪时在输入区附近给出处理说明。两张图是待确认的静态样稿，以下线框补充窄屏、命令菜单和断线状态。 [Alice 像素形象](../../web/assets/alice-wizard-avatar-v1.png)

### 3.2 网格、窗口和渲染模式

| 终端空间 | 主视图 | 详情与优先级 |
| --- | --- | --- |
| 参考基准 80 × 24 | 单列。每侧默认 2 列留白，顶部用紧凑标题，输入区与状态行留在底部。 | 详情使用临时视图，面板标题、焦点行、返回提示可见。 |
| 小于 64 列或 20 行 | 每侧 1 列，收起头像与长键位提示。输入框可见行数随高度缩减，光标所在行始终可见。 | 状态收成一行，失败或待确认优先于快捷键。菜单超高时内部滚动。 |
| 约 40 列或 12 行以下 | 退到紧凑的一行标题、一行输入附近状态，继续保留至少一行可编辑输入。对于连这些内容都无法容纳的极小窗口，提示放大。 | 详情接管临时屏幕，优先保留选中项和返回键。 |
| 宽屏试验，内容宽度至少 96 列 | 仍默认单列，主对话每行约 72–84 个显示列作为初始目标。 | 用户展开时才尝试分栏，聊天至少 64 列、面板至少 28 列。收窄时用同一临时详情视图接续。 |

以上数字是 Alice 的首轮设计值，依据 macOS「终端」及其他实际终端中的中文换行和可用高度校准。布局按终端显示列计宽，检查中文宽字、组合字符和 emoji。全屏可用于实现稳定的滚动锚点、输入区和分栏。先用现有单列 inline 方式实现基础视觉，随后比较全屏版在键盘、选择和复制上的表现。若启用两种方式，使用同一套角色、状态文案和颜色。窗口缩小时依次让位的是装饰、额外提示、预览，然后压缩正文区。

### 3.3 颜色、字形与可识别性

| 颜色或形状角色 | 使用规则 |
| --- | --- |
| 正文 | 优先用终端默认前景与背景。用户和 Alice 通过角色名、块间距和局部字重区分，正文不需要整段高饱和彩色。 |
| 品牌与焦点 | 用同一低饱和紫色表现 Alice 名称和当前焦点。窄屏或单色模式使用短标签和反显焦点。 |
| 输入与工具表面 | 输入有细边界或低对比衬底，焦点用边界强弱区分。工具摘要通过缩进和展开符号辨认，工具卡衬底随深浅主题变化。 |
| 状态 | 接单、处理中、断线与失败用不同短标签，可配合符号和语义颜色。色彩关闭后仍可辨认。可用 Unicode 绘图字符时用细线，字符能力有限时退回 ASCII。 |
| 弱化 | 仅用于辅助信息和非当前项。正文、焦点、错误原因和下一步动作保持清楚。 |

色板规格先确定语义，再定具体色值。浅、深、16 色和无彩色模式的同类元素保持相同位置、符号与标签。若以后增加自动背景检测，读取超时、能力未知或使用透明终端时退回终端默认前景和背景。主题预览以真实的消息、工具摘要、选中行和错误四类样本判断可读性，避免用单独色块做决定。

### 3.4 正文、输入、折叠与位置恢复

- 消息块的角色名单独成行，正文至少保留自然段、列表、引用和代码缩进。流式渲染与正式消息以同一版式呈现，完成时按宿主消息 ID 确认和合并，阅读位置保持稳定。向上翻看时留在原消息附近，新消息通过底部提示可达。
- 输入框一直保留光标附近的行。Enter 发送，Ctrl+J 换行，多行粘贴完整进入草稿。直接输入 `/` 时在输入上方打开同宽菜单，最初只列历史、状态和帮助。选中项以箭头和反显或强调色标明。↑/↓ 选择，Tab 补全，Enter 执行选中项，Esc 仅关闭当前菜单。临时视图退出后恢复草稿、光标与上一阅读位置。
- 工具卡默认只占一行，含类型、当前进度或结果摘要。多条同类动作可合并为一个可展开组。一处焦点只展开一项，Ctrl+O 仍可从输入区打开本轮工具详情。工具名和具体参数的显示服从宿主可见字段。来源正文继续使用当前有效的临时历史投影。
- 主动邀请作为对话中的 Alice 消息，用小标签区分。用户在同一个输入框中回复，终端沿用宿主已经投递的邀请与接续状态。
- 不熟悉的快捷键能通过 `/help` 按需查看。普通消息的选择与复制优先沿用终端行为。鼠标可用于展开、切换或复制，所有日常操作都有键盘路径。
- 模型或外部工具返回的文本按字面清洗后展示。终端控制序列由客户端生成，正文里的链接由用户主动选择或复制。

### 3.5 状态栏与反馈

| 情况 | 状态区文字示例 | 此时用户可做什么 |
| --- | --- | --- |
| 已连接且草稿可发 | `● 可以发送` | Enter 发送，Ctrl+J 换行。 |
| 已提交，等待宿主接单 | `○ 正在提交` | 继续编辑下一条草稿，等待接单回执。 |
| 接单、回复或工具读取中 | `◌ Alice 正在回复` 或 `◌ 正在读取资料` | Ctrl+O 打开对应的工具详情。 |
| 正式回复已同步 | 对话新增正式消息，状态区恢复输入提示 | 继续输入。 |
| 宿主忙或连接中断 | `! Alice 正忙 · 草稿已保留` 或 `! 连接中断 · 草稿已保留` | 继续编辑，等待恢复。 |
| 原请求结果未知 | `! 等待确认上一条 · /status` | 核对原请求。能否重试由宿主回执决定。 |

前台的这轮操作优先出现在状态区。清醒或睡眠等后台状态在空闲时可作一项短提示，其原因与详情通过 `/status` 打开。字号固定的终端里，反馈主要依靠稳定位置、短符号和标签。高频操作即时更新。需要动效时只刷新头像或单个状态符号，空闲或失焦时优先停画。

### 3.6 施工范围与验收

1. **视觉基础。** 建立统一网格、居中启动页、聊天首屏的紧凑品牌区、消息块、输入边界和统一状态栏。用现有单列模式交付第一版。此阶段改动集中在 TUI 客户端绘制和键盘层。
2. **按需查看。** 加上输入区命令菜单、折叠工具摘要，以及历史与状态临时视图的一致样式。验证 Esc、草稿恢复、断线和流式回执。
3. **宽屏与进阶能力。** 验证全屏滚动锚点和可选侧栏，再评估实时主题预览、更完整的 Markdown、终端图片、头像动效。选择这些功能前先看日常使用价值。编码工作区、Git、子代理看板和底层计量放在它们对应的产品入口。

| 视觉验收 | 通过标准 |
| --- | --- |
| 有历史与空会话分别启动 | 两种画面都能立刻输入，发送后进入当前会话。启动和聊天阶段可辨认同一套 Alice 字标与头像，输入在切换后仍可达。 |
| 80 × 24、窄窗口、宽窗口连续调整 | 聊天和输入边界可辨，焦点与长中文换行正确。菜单焦点行、状态与退出提示在可见范围内。 |
| 深色、浅色、16 色、无色 | 正文、焦点、工具折叠与断线提示无需依赖同一种颜色区分。 |
| 中文输入、粘贴、打开菜单和详情 | 选词与粘贴只进入草稿。临时界面关闭后能在原光标位置继续输入。 |
| 回复流式、工具展开、翻看旧消息、新消息抵达 | 状态更新不打断阅读。正文、工具和状态各自易找，最终消息只出现一次。 |
| 连接中断、恢复、原请求待核对 | 三种画面在同一个状态区清楚区分，能读到现有草稿或查询入口。 |

## 4. 接入现有 Alice

### 4.1 客户端与授权

客户端在 `addons/alice_tui/`，通过 Unix domain socket 上的 HTTP/SSE 连接已运行的档案。默认使用源码档案，`--desktop` 选中 macOS 桌面默认档案，`--user-dir` 可指定另一档案。服务未就绪时提示打开选定档案。 [启动与路径格式](../../addons/alice_tui/README.md)

按需启动宿主、桌面加入同一实例和退出语义的后续方案，见 [TUI 与 GUI 独立启动说明](./Alice-TUI与GUI独立启动-说明-v1-20261122.md)。

宿主使用当前用户私有目录下的档案专属 socket。目录权限为 `0700`，socket 权限为 `0600`。macOS 用 `getpeereid()`，Linux 用 `SO_PEERCRED`，在每个连接进入 HTTP 处理前核对对端的有效 UID。取不到凭据或 UID 不同则断开。socket 按档案独立注册和清理。宿主退出时停止接入，排空两个监听器已经接受的请求，然后关闭 Store。

同账号程序可使用终端接口，业务权限仍由同一个 Alice 宿主执行。终端监听器只挂聊天、原请求核对、历史与状态四项。网页继续通过本机 HTTP 提供服务，并沿用自己的来源校验。QQ 和 Alice Lab 沿用各自的授权。 [工作区约定](../工作约束/工作区约定.md)

### 4.2 服务契约

下表为 Unix socket 上的 `/api/tui/v1` 接口。

| 接口 | 首版返回或行为 | 可复用部分 |
| --- | --- | --- |
| `GET /status` | 返回 Alice 名称、会话代次、档案就绪情况、前台忙闲和有效清醒／睡眠状态。 | `state()` 与活动／生命周期的只读投影。先取用户需要的最小字段。 |
| `GET /history` | 首次取最近一页，`after_id` 用于增量追更，`before_id` 用于向前翻页。支持复核已经显示的来源轮次。 | 复用 `history_page()` 和用户可见的正文投影。向前分页是新增能力，且须和增量游标互斥。 |
| `POST /chat` | 提交 `text`、`request_id`、`session_epoch`，返回接单、增量文本、用户可见的工具进度、完成结果或错误。 | 同一个 `ChatService.send()` 与持久化链。`reasoning`、内部 `meta` 和记忆写入细节留在既有观测面。 |
| `POST /chat/status` | 按提交时的正文、请求 ID 和会话代次核对，返回状态与已入库的消息 ID。 | 复用已有的请求账本与身份核对，由服务端绑定当前档案与请求身份。 |

TUI 是本机所有者的对话入口。服务端在校验系统账户后，沿用本机所有者的业务范围，使主动邀请、来源可见性和工具许可沿同一套规则运行。

终端请求先明确接单，再显示回复过程。消息以 `session_epoch` 与正式消息 ID 合并。连接中断后，用原请求标识核对并从历史补齐。宿主仍在处理或暂时无法确认时显示等待，保留草稿和核对入口。确认未接单后才允许用户重试。重复提交、重连与切换客户端不得把一条消息写成两条。会话代次变化时清理旧缓存和游标，旧草稿留给用户确认后再发。

主聊天区按消息 ID 增量同步网页、桌面写入及主动邀请，重连仍使用当前档案。终端原生回滚会保留历史输出，来源绑定正文放在临时历史视图内，按当前档案与宿主投影周期刷新。客户端收到失效结果或无法及时取得新页面时，更新或隐藏界面上的正文。 [历史投影、消息标识与请求账本](../../alice/service.py)

## 5. 接入与跨端人工验收

1. 先接通本机授权、状态、历史、聊天流和原请求核对，确认它们都走同一个宿主。
2. 完成单列对话、输入、历史和工具进度，先用 macOS 自带的「终端」人工验收。
3. 再验证其他终端的输入表现，逐步扩大发行范围。视觉施工顺序和画面验收见 [第 3.6 节](#36-施工范围与验收)。

| 人工场景 | 通过标准 |
| --- | --- |
| 网页发一句，切到 TUI 回复，再回桌面查看 | 两端同时看到同一组消息，刷新和重连后顺序一致、每条只出现一次。 |
| 中文输入法选词、多行粘贴、调整窗口、滞留在历史处阅读 | 选词与粘贴可先预览，发送需要明确动作；草稿、阅读位置和中文排版稳定。 |
| 发出一轮慢回复，在流式期间断开，再用原请求恢复 | 界面区分「处理中」「结果待核对」与「已完成」，聊天历史只有一次提交。 |
| 终端与网页同时发送或网页切换会话，再恢复终端 | 繁忙提示可理解，旧请求不会写入新会话，未送出的草稿可继续编辑。 |
| 查看 `/status`、收到主动邀请并关闭终端 | 状态与宿主一致，邀请在各界面出现一次，关闭或重开 TUI 不触发额外邀请；后台按原设置运行。 |
| 查看检索进度、翻历史、等待来源过期 | 折叠状态可理解，展开只显示可见摘要；历史与搜索结果里旧来源内容按宿主投影更新。 |
| 用同账户和另一个普通系统账户连接 | 同账户直接进入选定档案，另一个系统账户无法通过文件权限和 UID 检查进入。旧 TCP 路径不可访问。 |
| 并行打开两个档案，再关闭其中一个宿主 | TUI 始终指向选定档案。剩余实例仍能连接。正常关闭会排空已接单轮次，再清理本档案 socket。 |
