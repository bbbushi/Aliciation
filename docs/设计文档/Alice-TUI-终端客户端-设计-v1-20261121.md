# Alice TUI 终端客户端设计 v1

2026-11-21 · 已实现本机 socket 方案，待真实终端验收

## 1. 产品定位

Alice TUI 是 Alice 的可选终端客户端。用户可以从网页或桌面接着聊，发送中文多行消息，查看回复进度，也能翻看近期对话。各入口共用当前档案的永久会话、记忆、人格和工具权限。退出 TUI 只关闭终端界面，宿主继续负责已经接单的任务和后台活动。

首版采用单列主界面。打开即进入当前对话，常驻内容只有对话、输入框，以及需要时显示的一行状态。具体工具进度按需展开，高级设置与人格导入在网页或桌面完成，完整上下文和后台调度记录在 Alice Lab 查看。

## 3. 交互规格

```text
Alice

你     说回刚才那个问题，晚上有空再聊。
Alice  好。晚上方便的时候，我再接着说。

       正在查找相关记忆…  Ctrl+O 查看进度
────────────────────────────────────────────
> 我补一下刚才的条件。
  这次只看我们聊过的内容。
  Enter 发送  ·  Ctrl+J 换行  ·  / 命令
```

- **输入与粘贴**　`Enter` 提交，`Ctrl+J` 换行。中文输入法候选态由系统处理，终端收到的确认文本先进入草稿。多行粘贴整体进草稿，等待显式发送。历史、详情与帮助关闭后恢复原草稿和光标。快捷键冲突时以目标终端的真人测验为准。
- **流式与滚动**　停在底部时跟随回复，翻看旧消息时保留阅读位置，并提示有新内容。调整窗口大小后按消息 ID 保持阅读位置。长回复仅更新可见区域，保持输入可用。中文、emoji、引用和代码段按终端宽度换行，保留正文中的空行与代码缩进。
- **状态反馈**　有草稿时可发送。发出后先显示「正在提交」，收到宿主接单才显示「Alice 正在回复」。收到最终结果时由对话本身呈现成功。忙碌、断开、授权到期或结果待核对时，各自显示一句说明与可执行的下一步，颜色用于辅助辨识。
- **主动交流**　显示当前会话里宿主已经投递的邀请，按消息 ID 与网页、桌面同步。用户可以像平常一样回答「现在可以」「晚一点」。终端负责呈现，等待、延后、再次询问由现有宿主策略决定。
- **终端内容**　模型正文、历史、工具提示均作为文本渲染。由客户端生成样式，过滤正文里的 ANSI/OSC 等控制序列，保留普通换行。文本里的地址以可阅读形式显示，交由用户选择或复制。

| 命令 | 行为 |
| --- | --- |
| `/history` | 进入历史浏览，从最近一页向前翻。可用关键词筛选已加载的历史，界面显示搜索覆盖范围，空结果显示「已加载的对话中未找到」。 |
| `/status` | 显示连接情况和宿主报告的有效清醒／睡眠状态。无法取得宿主状态时显示「暂不可确认」。 |
| `/help` | 显示当前终端下可用的命令和快捷键。 |

命令在客户端处理，无模型请求。仅首行匹配内置命令并经用户提交时执行；未知斜杠输入保留在草稿，用户可以选择按普通消息发送。关闭详情或取消命令选择只影响相应的界面。

## 4. 接入现有 Alice

### 4.1 客户端与授权

客户端在 `addons/alice_tui/`，通过 Unix domain socket 上的 HTTP/SSE 连接已运行的档案。默认使用源码档案，`--desktop` 选中 macOS 桌面默认档案，`--user-dir` 可指定另一档案。服务未就绪时提示打开选定档案。 [启动与路径格式](../../addons/alice_tui/README.md)

宿主使用当前用户私有目录下的档案专属 socket。目录权限为 `0700`，socket 权限为 `0600`。macOS 用 `getpeereid()`，Linux 用 `SO_PEERCRED`，在每个连接进入 HTTP 处理前核对对端的有效 UID。取不到凭据或 UID 不同则断开。socket 按档案独立注册和清理。宿主退出时停止接入，排空两个监听器已经接受的请求，然后关闭 Store。

同账号程序可使用终端接口，业务权限仍由同一个 Alice 宿主执行。终端监听器只挂聊天、原请求核对、历史与状态四项。网页继续通过本机 HTTP 提供服务，并沿用自己的来源校验。QQ 和 Alice Lab 沿用各自的授权。 [工作区约定](../工作约束/工作区约定.md)

### 4.2 服务契约

下表为 Unix socket 上的 `/api/tui/v1` 接口。

| 接口 | 首版返回或行为 | 可复用部分 |
| --- | --- | --- |
| `GET /status` | 返回 Alice 名称、会话代次、档案就绪情况、前台忙闲和有效清醒／睡眠状态。 | `state()` 与活动／生命周期的只读投影。先取用户需要的最小字段。 |
| `GET /history` | 首次取最近一页，`after_id` 用于增量追更，`before_id` 用于向前翻页。支持复核已经显示的来源轮次。 | 复用 `history_page()` 和用户可见的正文投影。向前分页是新增能力，且须和增量游标互斥。 |
| `POST /chat` | 提交 `text`、`request_id`、`session_epoch`，返回接单、增量文本、用户可见的工具进度、完成结果或错误。 | 同一个 `ChatService.send()` 与持久化链。`reasoning`、内部 `meta` 和记忆写入细节留在既有观测面。 |
| `POST /chat/status` | 按提交时的正文、请求 ID 和会话代次核对，返回状态与已入库的消息 ID。 | 复用已有的请求账本与身份核对，由服务端绑定当前档案与请求身份。 |

TUI 是本机所有者的对话入口。服务端在校验系统账户后，沿用本机所有者的业务范围，使主动邀请、来源可见性和工具许可沿同一套规则运行。

终端请求先明确接单，再显示回复过程。消息以 `session_epoch` 与正式消息 ID 合并。连接中断后，用原请求标识核对并从历史补齐。宿主仍在处理或暂时无法确认时显示等待，保留草稿和核对入口。确认未接单后才允许用户重试。重复提交、重连与切换客户端不得把一条消息写成两条。会话代次变化时清理旧缓存和游标，旧草稿留给用户确认后再发。

主聊天区按消息 ID 增量同步网页、桌面写入及主动邀请，重连仍使用当前档案。终端原生回滚会保留历史输出，来源绑定正文放在临时历史视图内，按当前档案与宿主投影周期刷新。客户端收到失效结果或无法及时取得新页面时，更新或隐藏界面上的正文。 [历史投影、消息标识与请求账本](../../alice/service.py)

## 5. 施工与人工验收

1. 先接通本机授权、状态、历史、聊天流和原请求核对，确认它们都走同一个宿主。
2. 完成单列对话、输入、历史和工具进度，先用 macOS 自带的「终端」人工验收。
3. 再验证其他终端的输入表现，逐步扩大发行范围。宽屏侧栏、全会话关键词检索和更完整的终端 Markdown 由首版实际使用决定。

| 人工场景 | 通过标准 |
| --- | --- |
| 网页发一句，切到 TUI 回复，再回桌面查看 | 两端同时看到同一组消息，刷新和重连后顺序一致、每条只出现一次。 |
| 中文输入法选词、多行粘贴、调整窗口、滞留在历史处阅读 | 选词与粘贴可先预览，发送需要明确动作；草稿、阅读位置和中文排版稳定。 |
| 发出一轮慢回复，在流式期间断开，再用原请求恢复 | 界面区分「处理中」「结果待核对」与「已完成」，聊天历史只有一次提交。 |
| 终端与网页同时发送或网页切换会话，再恢复终端 | 繁忙提示可理解，旧请求不会写入新会话，未送出的草稿可继续编辑。 |
| 查看 `/status`、收到主动邀请并关闭终端 | 状态与宿主一致，邀请在各界面出现一次，关闭或重开 TUI 不触发额外邀请；后台按原设置运行。 |
| 查看检索进度、翻历史、等待来源过期 | 折叠状态可理解，展开只显示可见摘要；历史与搜索结果里旧来源内容按宿主投影更新。 |
| 用同账户和另一个普通系统账户连接 | 同账户直接进入选定档案，另一个系统账户无法通过文件权限和 UID 检查进入。旧 TCP 路径不可访问。 |
| 并行打开两个档案，再关闭其中一个宿主 | TUI 始终指向选定档案。剩余实例仍能连接。正常关闭会排空已接单轮次，再清理本档案 socket。 |
