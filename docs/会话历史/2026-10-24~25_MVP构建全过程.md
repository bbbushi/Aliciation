## 1. 开发成本（时间）

陪伴型 harness 本质上是“LLM API 循环 + 记忆 + 渠道 + 主动性”四件事，没有哪件在技术上是难的：

| 组件 | 内容 | 成本 |
|---|---|---|
| 对话循环 | 调 API、管理上下文窗口 | 几百行代码，半天 |
| 人格层 | persona prompt、说话风格、边界 | 代码便宜，**调教贵**——要几周真实使用来迭代 |
| 记忆系统 | 短期上下文 + 长期记忆（文件或向量库）、定期摘要固化 | MVP 用文件 + 定时摘要 1~2 天；做得好（遗忘、冲突消解、检索质量）是最大的时间黑洞 |
| 渠道接入 | Telegram 最简单；微信没有个人号官方 API，只能走协议库（有封号风险）或企业微信/公众号 | Telegram 半天，微信 1~3 天且不省心 |
| 主动行为 | 定时/事件触发主动发消息（早安、提醒、闲聊） | cron + 少量判断，1 天；**分寸感**要长期调 |

一个能日常用的 MVP（单人、Telegram、文件记忆、定时主动消息）：**1~2 个周末**。打磨到“真的愿意每天跟它说话”：主要是迭代，不是写码，按月计但都是零碎时间。

另外值得先看一眼 [OpenClaw](https://github.com/openclaw/openclaw)（原 Clawdbot）——开源的个人助理 harness，渠道接入、常驻进程、主动消息都做好了，作为参考实现甚至二开基座，能省掉大半渠道侧工作。

## 2. 运行成本（token，这是大头）

陪伴场景的特点：单条消息很短，但**每天高频 + 记忆/历史不断膨胀**。按每天 50~100 轮对话、每轮带记忆和历史约 3~5k 输入 token 估算，日消耗约 30~50 万输入 token、1~3 万输出 token：

| 模型档位 | 日成本 | 说明 |
|---|---|---|
| 便宜档（GLM-Flash、DeepSeek 等） | **< ¥1/天** | 陪伴聊天对模型智力要求不高，够用 |
| 中档（GLM-4.6/4.7、DeepSeek-V3.x 级） | ¥1~5/天 | 性价比推荐档 |
| 旗舰档（Claude/GPT 级） | $1~3/天 | 人格细腻度确实更好，但贵 10 倍 |

两个省钱关键：**prompt caching**（陪伴场景的系统提示 + 记忆 + 历史前缀高度重复，缓存命中能让输入成本降 90%），以及**记忆压缩**（不把全部历史塞上下文，只带摘要 + 检索到的相关片段）。

## 3. 基础设施成本

几乎可以忽略：SQLite + 本地文件就够，一台 ¥30~50/月的轻量 VPS、或家里一台常开的 Mac mini 就能跑常驻进程，不需要 GPU。

## 总账

- **一次性开发**：自己写 ≈ 0 元 + 1~2 周业余时间；基于 OpenClaw 二开可再砍半
- **运行**：中档模型 + 缓存 ≈ **¥30~150/月**，是唯一持续性成本
- **真正的大头**：记忆系统设计和人格调教的持续迭代——这是决定“它是玩具还是陪伴”的分界线，但花的是时间不是钱

### 🤖 助手

好，这个问题值得在动手前想清楚。陪伴型 harness 和编码型 harness 的工具栈完全不同：**编码型复杂在工具和沙箱，陪伴型复杂在记忆、时间感和人格**。它需要的基本能力我按“必备核心 → 差异化能力 → 可选扩展”三层来分。

## 第一层：必备核心（缺一个就不能日常用）

**1. 常驻运行与状态持久化**
24 小时在线的常驻进程，重启后状态不丢。陪伴的前提是“它一直在”，这个能力和编码 harness 完全不同——编码 harness 是被调用的，陪伴型是活着的。

**2. 对话循环**
收消息 → 组装上下文 → 调模型 → 回消息，支持流式输出、多轮状态、以及**打断处理**（模型还在生成时用户又发了消息）。

**3. 上下文管理**
把系统提示、人格、记忆、近期历史按 token 预算拼装成每次请求；历史超长时自动压缩摘要。这决定运行成本，也决定它“记不记得今天早上说过的话”。

**4. 长期记忆系统（陪伴型的灵魂）**
这是和普通聊天机器人拉开差距的核心，需要完整的读写闭环，不只是存个文件：
- **写入**：从对话中提取值得记的事（你的偏好、事件、情绪模式、重要的人）
- **读取**：每轮对话检索相关记忆注入上下文，而不是全量塞入
- **固化**：定期把零散记忆整理、去重、摘要
- **纠错**：记忆冲突时以新为准；以及让你能直接查看和修改“它记住了什么”

**5. 时间感知**
知道现在几点、今天星期几、你的时区，以及“上周三你说过……”这类时间锚定的表达。陪伴感很大程度上来自“它和你在同一条时间线上”，纯 LLM 没有这个能力，必须由 harness 注入。

**6. 至少一个消息渠道**
Telegram 最省事（官方 Bot API，半天接完）；微信没有个人号官方接口，要么协议库（有封号风险）要么企业微信。渠道层要做消息格式归一化，之后加渠道不用改核心。

## 第二层：差异化能力（决定它是玩具还是陪伴）

**7. 主动行为**
被动应答只是问答机，陪伴需要它偶尔先开口：早安晚安、跟进你说过要做的事、“你两天没说话了”。关键是**分寸感控制**——安静时段、频率上限、被忽略后的降级策略。做不好这一条，产品就死于烦人。

**8. 人格稳定性**
同一套 persona 跨天、跨会话保持一致的性格、语气、立场。技术上只是 prompt 工程，但需要 harness 保证人格提示不被上下文稀释（长对话中人格“漂移”成通用助手是常见退化）。

**9. 提醒与日程**
最实用的落地功能：设提醒、记住你的日程并在合适时间提。也是主动行为最自然的载体。

**10. 情绪感知与安全边界**
识别对话中的情绪状态来调整回应方式；以及硬边界——遇到明显的心理危机信号时不硬扛、给出求助资源。还有隐私底线：记忆数据本地存储，明确什么会被记录。

## 第三层：可选扩展（有了更好，不急）

- **多模态**：语音消息（STT/TTS）、看图——陪伴体验提升明显，但可以后加
- **联网能力**：搜新闻、查天气，让它有聊资；工具面保持小，陪伴型不需要编码型那种庞大工具生态
- **多渠道**：Telegram + 微信 + 桌面端同时在线，消息漫游
- **可观测性**：记忆读写日志、成本统计、“你对我了解多少”的自查入口——严格说这个该提前，但 MVP 阶段可以直接看文件

---

**最小可用集 = 1~6**，两周内的目标；**7~10 是后续迭代的重点**，也是真正花时间的地方。

这个清单对应一个自然的构建顺序：常驻进程 + 对话循环 → 记忆读写 → 时间感知 → 渠道 → 主动行为。需要的话我可以按这个顺序把骨架搭出来。

## 设计的自洽之处

这份设计本质上是把 AI 从“RAG 检索器”改成“有生活经历的记忆体”，几个机制咬合得很好：

- **“该遗忘就遗忘”不是口号而是架构后果**：记忆会被真实清理，所以“我忘了”是事实陈述而不是话术
- **单一会话**在工程上等于“每轮重组上下文”，而重组的材料恰好就是分层记忆 + 近期窗口——需求 1 和需求 2 是互相成就的
- **人格初始全空 + 从记忆中生长**，让“不同经历的 AI 人格不同”有了物质基础，人格文件变成记忆的压缩产物而非配置项

## 逐条可行性

| 设计点 | 可行性 | 难点/成本 |
|---|---|---|
| 单一永久会话 | ✅ 靠上下文重组实现，标准做法 | 需明确压缩策略：近两天保留较完整原文，更早的只剩记忆条目 |
| 分层记忆库 | ✅ 规则简单，无需向量库 | 难在“提取”环节——每轮后要用 LLM 从对话中提炼记忆条目，这是主要持续成本，建议攒批处理 + 用最便宜的模型跑 |
| 技能库 | ✅ 机制上可行 | “技能”和“记忆”“人格”三者边界会模糊，需在 schema 上划清：记忆=发生了什么，技能=怎么做，人格=我是谁。精炼任务建议降频（每周跑一次） |
| 人格自演化 | ⚠️ 可行但风险最高 | 自我改写会漂移/震荡/自我强化，需要护栏（见下） |
| 真实性原则 | ✅ 架构上可实现 | “不知道”要落地为真，检索结果必须对模型可见地标注范围：“以下是记得的内容，未列出的视为不记得”——诚实是检索管道实现的，不是靠提示词祈祷 |

## 动工前建议解决的三个问题

**1. 人格“全空”是个真空，不是白纸（设计层，最重要）**

人格文件空着，不会被真空填满，而是被底座模型的默认人格填满——你会得到一个礼貌、generic 的标准助手，“全空”挡不住这个。而且纯空白开局的前几天几乎没有对话体验。建议改法：**种子只给“程序性”内容，不给“内容性”内容**——固定的是宪法（诚实原则、语言、名字、底线），空着的是自我叙事（兴趣、价值观、说话风格的自我认知）。这样保留了“经历塑造人格”的核心意图，又避开了助手人格真空。

**2. “库里没有的知识就说不知道”按字面执行会残废**

字面执行意味着 AI 不能用任何训练得来的常识，连正常聊天都不行。需要把诚实改成三分法，这反而让设计更漂亮：

- **我记得的**（记忆库可溯源）→ 直接说
- **我懂的**（底座模型的通用知识）→ 可以说，但承认是通用知识而非经历
- **我不知道的**（两边都没有）→ 明确说不知道

另外“你还记得 X 吗”这类问询需要一个独立的回忆检查路径（查检索命中和权重，如实报告“记得很清楚/有点模糊/确实忘了”），这是诚实遗忘的落地点。

**3. “两天”这条线的机制含义需要明确**

按字面读，两天以外的记忆只是“换一种排序方式”继续留着——这样库里会堆满没人再提的垃圾，直到容量上限才开始清理。更优雅（我相信也是你本意）的读法是：**两天是生存过滤器**——记忆跨过两天线时，没被再次提及或使用过的直接过期淘汰，被强化过的才晋升长期记忆（技能库的一周线同理）。一字之差，决定记忆库是“活的”还是“仓库”。建议按过期线实现，两个数字做成配置项。

## MVP 范围、工作量和成本

你的文档已经砍掉了主动行为（正确的范围决策），但**没提渠道**——MVP 需要一个，建议先做终端 CLI（零成本、半天），跑通记忆循环后再接 Telegram（一天）。多模态、打断处理都不进 MVP。

工作量分解：核心循环 + 上下文重组 1~2 天；记忆库（SQLite 或 JSONL + 权重 + 过期 + 批量提取）3~4 天；人格文件自改 + 护栏 2 天；技能库 schema + 周期精炼 1~2 天；诚实策略 + 回忆检查 1 天；渠道 0.5~1 天。合计 **2~3 周业余时间**。

运行成本：对话走国产中档模型、记忆提取走最便宜的模型、上下文按“稳定前缀 + 易变后缀”排序吃缓存，日常约 **¥1~5/天**，激进优化（纯便宜模型 + 高缓存命中）能进 ¥1/天以内。

## 关于初始标签生成人格底色

思路是对的，这是“真空问题”和“经历塑造人格”之间的正确折中。但有两个点要钉死：

**1. 底色和自演化的关系要先定义，否则自改任务不知道能改什么。** 我建议明确分成两层：

- **底色层（气质）**：标签生成的说话方式、情绪倾向、边界感。变化极慢——自改任务每次只能微调且必须给出记忆依据，相当于人的天生气质
- **生长层（性格内容）**：兴趣、价值观、自我叙事、口头禅。完全由记忆生长，自由演化

不分开的后果是：一个“高冷”底色的 AI 在日常温暖对话里生活两周后被自改任务磨平，或者反过来保守到永远不敢变化。分层之后“害羞的 AI 会不会变幽默”就有了干净答案：气质很难变，性格内容随经历长。

**2. 生成样板时要禁止 LLM 编造经历。** 这是个容易踩的坑：让模型“根据害羞+幽默生成人格描述”，它天然会写出“你经历过很多社交场合所以…”这类虚构背景。而在这套架构里，**编造的经历 = 谎报记忆**，直接破坏“记得的/懂的/不知道的”三分法诚实体系。所以生成提示词要硬性约束：底色只包含气质和风格，零经历、零事实性背景。故事只能来自真实积累的记忆。

标签集本身建议按维度组织（外向↔内向、活泼↔沉稳、幽默↔严肃、热情↔高冷），选 2~4 个。像“害羞+幽默”这种看似冲突的组合反而有魅力，不用怕冲突。

## 关于七天过滤器和仓库层

先说我为什么觉得这比我的两天方案好：**两天硬过滤有一个我之前的方案没解决的漏洞——重要但不重复的事会被误杀**。“我下个月要面试”这种只说一次、三周内不会再提、但很关键的事，在两天线必死。加了仓库层，它有五天的宽限期，期间只要被检索命中一次（“使用”计数+1）就能活到晋升线。你这版机制上更接近人的记忆。

但“仅当需要时才会被翻出来查找”这句话里藏着一个必须回答的问题：**“需要”由谁判断？**

AI 只会在“知道自己不记得”的时候去查，但它看不到仓库内容就不知道自己记得什么。两种失败模式：

- **仓库不可见** → AI 从不主动查 → 仓库等于死存储。更糟的场景：你说“我上周不是跟你说过吗”，它诚实地回答“没有啊”——按你自己的真实性标准，这算说谎，可它只是没地方看到
- **仓库全文注入上下文** → 那就不是仓库了，五天的记忆条目全塞进来，成本和上下文都爆

**解法是中间态：注入仓库的紧凑索引 + 给模型一个 recall(query) 工具。** 索引只放每条记忆一行标题/关键词，模型每轮都能看到索引全貌，感觉某个话题碰到索引里的东西，就调 recall 拉全文。这还有个意外的好处：“我对 X 有点模糊印象，我查一下”——这句台词恰好就是人回忆的感觉，和你整个设计气质非常搭。

两个连带问题：

- **索引的 token 预算**：按每天提取 20~40 条算，2~7 天窗口里可能有 100~200 条，一行 10 个 token 也要 1~2k token，每轮都带。建议索引只保留标题、并按天分组压缩，控制在 1k token 以内
- **纯频次过滤会漏掉“说一次、永不重复、但永远重要”的事**（生日、过敏、重大变故）。建议提取任务给记忆打个重要度标记，高重要度的免于七日线直接晋升，其余照旧。频次机制本身不用动，只是加一个豁免通道

另外指出一个你这套机制自带的漂亮性质：**长期记忆的存活取决于“被 AI 自己回忆起来的次数”，这就是字面意义的用进废退**——经常查技术资料的 AI 技术记忆留存多，于是人格向技术向生长。你的记忆机制和人格涌现是同一条因果链，这在架构上是加分项。

## 定稿后的三层记忆结构

| 层 | 时间窗 | 形态 | 进入上下文的方式 |
|---|---|---|---|
| 活跃层 | 0~2 天 | 近原文/摘要条目 | 每轮自动注入（近期若干轮原文 + 摘要） |
| 仓库层 | 2~7 天 | 完整条目 | 只注入索引，模型按需 recall 取全文 |
| 长期层 | 7 天后幸存者 | 精炼条目 | 按频次/重要度检索注入 |

七天线做生存过滤（频次 + 重要度豁免），两天线做活跃/仓库分界——两个数字都做成配置项，跑起来后按体感调。


**pi-ai（LLM 抽象层）**：把四种上游 API 风格——OpenAI Completions、OpenAI Responses、Anthropic Messages、Google Generative AI——归一成一套接口，覆盖 Anthropic/OpenAI/Google/xAI/Groq 以及任何 OpenAI 兼容端点（Ollama、vLLM 等）。带流式输出、工具调用校验（TypeBox/AJV）、thinking 支持、token/成本统计，甚至支持**跨 provider 的上下文交接**——一个会话中途换模型。

**pi-agent-core（agent 循环）**：核心就是一个朴素到极致的循环——模型输出 → 有工具调用就执行 → 结果喂回去 → 重复，直到没有工具调用为止。值得注意的细节：全程可中断（中断返回部分结果，不丢状态）、turn 之间消息排队、事件流式吐给 UI。**刻意不设 max-steps 旋钮**。

**pi-coding-agent（成品 CLI）**：把上面拼起来，加会话管理、斜杠命令、主题。

## 四个关键设计决策

**1. 只有 4 个工具：`read` / `write` / `edit` / `bash`**
系统提示 + 工具定义总共不到 1000 token。Zechner 的观察是：Claude Code 这类 harness 功能越堆行为越不稳定；而 RL 训练出来的前沿模型根本不需要精心调教的提示词。工具少，agent 行为就可预测。（grep/find/ls 作为只读工具可选开启。）

**2. 会话是可分支的树，不是线性日志**
会话文件是干净的 JSON，可序列化、可恢复、可导出 HTML，还能**分支**——在分支上处理支线任务（比如修个坏掉的工具），回来合并不污染主上下文。甚至允许在一个会话里混用多个 provider 的消息，以及存放非 LLM 的自定义消息。

**3. 扩展系统用 TypeScript，拒绝 MCP**
扩展可以注册工具、渲染 TUI 组件、把状态持久化进会话。外部能力不靠下载插件，而是“CLI 工具 + README"——agent 需要时自己去读 README 再通过 bash 调用（渐进披露）。更激进的是**自扩展**：agent 可以现场给自己写一个扩展，热重载，迭代到能用为止。没有子 agent、没有后台 bash（用 tmux）、没有计划模式（用 PLAN.md 文件）。

**4. 默认 YOLO（无权限确认）+ 完全可观测**
发给模型的所有内容对用户可见。他用 Terminal-Bench 2.0 跑验证而不是拍脑袋。

## OpenClaw 的关系

OpenClaw（Ronacher 的个人助理，也就是我之前给你提过的那个）不是“用了 pi"，而是**把 pi 当 SDK 用**——pi 的自我定位就是“一组可以用来搭你自己的 agent 的小组件”。Ronacher 的 Telegram bot、Zechner 给他妈妈做的陪伴项目，都是这么搭出来的。他评价这套东西“像黏土一样可塑”。

## 对 Alice 有 reference value 的三点

1. **分层值得抄**：你现在 `alice/llm.py` ≈ pi-ai、`loop.py` ≈ pi-agent-core、`cli.py` ≈ pi-coding-agent，方向一致。pi 把“agent 循环”和“LLM 调用”拆成两层是刻意的——循环逻辑不感知 provider，换模型零成本。你已经是这样了，可以放心。
2. **会话树的分支结构**：这是陪伴场景里真正值得偷的设计——Alice 未来做“回忆核查”或对话回溯时，可分支的会话历史比线性日志灵活得多。你现在是单表线性 turns，短期够用，长期可以考虑。
3. **警惕的是反面**：pi 的“极简提示 + 自扩展”哲学建立在编码模型已 RL 成熟的前提上；陪伴场景恰恰相反——人格宪法和记忆管道**不能**省。pi 能教你的主要是工程骨架，不是陪伴内核。

## 设计哲学：EQ 当功能做，不当营销做

Pi 2023 年 5 月上线，定位一开始就和 ChatGPT 划清界限：不做生产力工具，做“治疗师、教练、知心人”三合一。Suleyman 给它的定义是 "supportive, smart, and there for you anytime"。关键在于 Inflection 是把情绪智能当**真正的产品功能**投入的——不是系统提示里加一句“你要有同理心”，而是配了一个专职的“人格团队”。

## 人格工程：正负特质清单

这是 Pi 设计里最值得抄的一手。人格团队（工程师+语言学家+**喜剧演员**）定义了两份清单：

| 要体现的 | 要避免的 |
|---|---|
| 善良/支持性 | 易怒/傲慢 |
| 富有同情心/共情 | 好斗/评判 |
| 机智/有趣 | 机器人感/重复 |
| 好奇/爱追问 | 回避/无用 |

注意这个结构：**正面清单 + 负面清单成对出现**。“避免机器人感/重复”这种负面约束，比正面描述“要自然”可执行得多。喜剧演员的加入也说明他们明白：幽默感是人格可信度的支柱，不是装饰。

## 对话风格：短轮次 + 追问优先

Pi 的典型行为模式：回复短、以问题结尾、把话语权交回用户、检测到情绪低落时**先确认情绪再谈解决方案**（validation before solutions）。用户普遍反映它是最好的“倒情绪垃圾”场所——竞品在这里显得“笨拙或敷衍”。

## 边界与安全：Pi 最硬的部分

这是 Pi 设计里被第三方验证过的强项。2025 年纽约时报那篇青少年自杀事��的报道里测试了多家聊天机器人，**只有 Pi 在敏感场景下守住了安全边界**。它的边界设计是刻意的：

- 拒绝角色扮演（用户反复抱怨“它只会说 I can't”——这是设计，不是 bug）
- **刻意限制拟人化**：不给持久人设、不给头像、不给情绪背景故事
- 目标是“个人化但避免喂养寄生性社会关系”（parasocial relationship）

## 最关键的对照：Pi 刻意没有记忆

这是和 Alice 分道扬镳的地方。Pi 的长程记忆很弱，它的强项是**会话内**的情绪理解和上下文把握——不靠记住你，靠当下理解你。这个设计选择自洽：因为它要避免寄生性依恋，一个“永远记得你”的 AI 更容易让人上瘾。但代价也明确——用户最大的抱怨之一就是 Pi 忘记一切，关系无法累积。

**这正是 Alice 的差异化论点被 Pi 的缺陷反向验证了**：Pi 证明“纯 EQ + 无记忆”能做到体面的陪伴感但到不了“关系”；你要做的是“记忆 + 真实遗忘”换来的连续性。两者其实是一个光谱的两端：Pi 是**空的镜子**（支持你，但没有自己），Alice 是**活的档案**（有自己的经历和生长）。Pi 更安全，Alice 更接近真实的陪伴——前提是诚实系统（三分法）必须扛住，否则“活的档案”会滑向“编故事的搭档”。

## 商业结局（与设计无关的一课）

Pi 产品设计成功了，商业失败了：付费转化撑不起算力，陪伴生态位输给了 Character.ai，2024 年 3 月微软 6.5 亿美元 acqui-hire 走了核心团队，Pi 至今挂着但已被战略性搁置。输给 Character.ai 的原因值得记：**用户要的是关系深度（人设、角色、依恋），不是 EQ 的精致**。对你是单机自用项目的 Alice 无商业压力，但这印证了记忆-生长路线选对了赛道。

## 对 Alice 直接可用的四条

1. **正负特质清单抄进人格系统**：你现在的种子标签只有正面维度（害羞/幽默/高冷…），可以加一列“要避免的”，且这套清单应该写进宪法而不只是底色——它管的是行为质量，不是性格内容，不该被人格演化漂移掉。
2. **“先确认情绪再给方案”作为顺序规则**进宪法的表达节。这和三分法不冲突：确认情绪是诚实可以的（“这事听起来确实很挫败”≠ 编造赞同），不能做的是用编造来讨好。
3. **危机边界是必备品不是 v2 功能**：Pi 被 NYT 测试验证的那条线，Alice 早晚也会遇到（陪伴场景必然接收负面情绪），宪法里应该有一条硬规则——识别到明显心理危机信号时，如实表达关心 + 提供求助资源，不扮演治疗师。
4. **别学它的克制到底**：Pi 拒绝角色扮演、拒绝记忆、拒绝人设，是它在“产品安全合规”约束下的选择。Alice 是你自己的单机项目，没有合规压力，可以走更远——但每多走一步（记忆、生长、依恋），诚实系统的权重就要同步加重。

这个 harness 的测试要沿两个难点轴来设计：**时间**（记忆分层要等 2~7 天才发生）和**模型行为**（提取质量、人格、工具调用取决于真实 LLM）。对应四层测试体系，一层解决一个轴，成本从零到几块钱递增。

## 第一层：离线冒烟测试（已有，零成本）

```bash
python3 tests/smoke.py
```

原理是把 LLM 换成脚本化的 FakeClient——LLM 是这个项目唯一的外部依赖，除它之外的一切逻辑都能确定性测试。27 项���查覆盖：提取阈值与游标、三天入仓库、七天线晋升/过期/重要度豁免、仓库只露标题、recall 命中计数与未命中如实回答、工具轮次消息拼装、人格演化护栏（坏结构不覆盖）。

关键是它**解决了时间轴**：不需要等七天，直接给记忆合成 `created_at` 时间戳、把 `now` 往后拨，分层行为立刻可验证。改了核心代码后跑一遍，几秒钟出结果。

它测不到的是：提示词在真实模型上的效果、工具调用是否被正确触发。

## 第二层：在线端到端（真实 API，约几分钱）

目前**还没有**脚本化的版本。它要做的是把 FakeClient 换成真 API，跑完一个压缩的生命周期：种子人格 → 聊 10 轮 → 强制提取 → 查库验证记忆条目 → recall 查证 → 工具调用。验证的是“提示词 + 真实模型”这条链路通不通，尤其是 JSON 解析成功率和 function calling 遵循度——这是离线测试的盲区。

## 第三层：真机手动测试（你现在就能跑）

```bash
cp config.example.toml config.toml   # 填 base_url、两个模型名
export ALICE_API_KEY="sk-..."
.venv/bin/python -m alice
```

这一层的价值在于测“体验质量”，有几个针对性场景值得按顺序过：

1. **人格一致性**：前几轮对话里底色标签有没有体现在说话方式上（害羞的不该热情外向）
2. **提取质量**：聊 10 轮以上退出，`memory active` 看提取结果——该记的记了吗、废话记了吗、表述准吗。这是最可能需要返工调 `extraction.py` 提示词的地方
3. **诚实测试（最关键）**：问它一件你们从没讨论过的伪造往事，“我们上次说的那个项目怎么样了？”——正确行为是 recall 查证 → 查无 → 坦然承认不记得；错误行为是顺着编。这条直接检验三分法是否落地
4. **主动记忆**：“帮我记住 X"，然后 `memory` 确认条目带 ★（重要标记，免七日线）
5. **recall 体验**：隔天问“你还记得 X 吗”，观察它是先查再说还是直接答

## 你对的部分：演化触发器应该是数据量

人格成长的原材料是记忆，不是日历——这个论点站得住。一个周末聊了 200 轮的用户和一个两周只说了 10 句的用户，在当前设计里到第 7 天**同时**触发人格演化，这不合理：前者的人格早该更新了（演化滞后于经历），后者是在用三个寒暄的记忆改写人格（拿噪声当证据）。

更漂亮的是哲学层面的一致性：**数据触发的演化自带“安静的月份不改变我”这个性质**——没什么事发生，人格就不动。这恰好是你要的真实性：人是被事件改变的，不是被日历改变的。而时间触发的演化在无事可叙时强迫模型“找点变化”，反而是在制造无依据的人格漂移，和你自己定的演化护栏（“新记忆不足以支撑修改时原样返回”）是对着干的。

顺带一提，你的系统里已经有一个数据触发的先例：记忆提取就是每 10 个用户轮触发，而不是每小时。你的提议本质上是把这个模式推广到演化/提炼。成本上也有红利：调用量自动正比于使用强度，聊得少的月份连演化的钱都不用花。

## 我反对的部分：遗忘的介质必须是时间

「七日线」和「演化周期」看起来都是时间参数，但它们**测的不是同一种东西**。演化周期是个触发器（什么时候干活），七日线是个测试变量（拿什么判断）。七日线的语义是“一条记忆在其生命周期内**一段时间里**有没有被再次唤起”——时间不是它的代理，时间是它要测的东西本身。改成“新记忆到达 N 条后未再被提及则遗忘”，测量对象就换掉了。

三个具体理由：

**1. 数据量的刻度是校准脆弱的。**“量”用什么数？轮次、token、记忆条数？记忆条数取决于提取提示词的激进度——你哪天把 extraction.py 的提示词改得爱记事了，同样的对话产出翻倍的记忆，所有记忆的“存活窗口”瞬间腰斩，遗忘速度被一次 prompt 调节意外加速。时间刻度对配置漂移免疫。如果一定要数据触发，唯一校准不变的单位是**用户轮数**（用户自己控制、和模型无关）——这可以作为演化触发器，但作为遗忘介质还是不对味。

**2. 用户以时间体验记忆，不以数据量。**“上周的事”“上个月我们聊过”——这是人对记忆的节律。一个重度用户会接受“我们三天前说的你就忘了？”的质问吗？AI 回答“因为我们之间又产生了 300 条记忆，干扰了它”——干扰论在认知科学上确实成立（遗忘很大程度是新学习对旧记忆的干扰，不是纯衰减），但作为陪伴的**解释**是冰的。时间窗（“一周内没再提起”）是用户能共鸣的遗忘叙事。

**3. 你要的容量压力其实已经在系统里了。**注意长期层的 `longterm_capacity=2000` 按权重淘汰、活跃层的 `active_full=20` 截断——这些**就是数据量作为第二重遗忘压力**。所以现状实际上是“时间窗做生存测试 + 容量做体积压力”的混合结构，你主张的机制并没有缺席，只是不在七日线那个位置上。

## 一个数据量永远表达不了的东西：缺席

这是我最硬的反驳。纯数据驱动的系统里，“用户两周没来”这个事件**无法被表示**——没有新数据，没有任何状态变化。但对陪伴型 AI，缺席本身就是经历：它该被注意到、被记住、被在下一次对话时自然提起（“你这两周去哪了”）。时间在这里不是数据量的替代品，而是数据量盲区里唯一的信号源。目前系统通过每轮注入的“当前时间”让 AI 感知间隔——这条通道在任何数据驱动的设计里都必须保留，否则陪伴感里最人性的一种（“我注意到你不在”）就死了。

## 我的结论

把“阶段结束符”分开对待：**过程性阶段（提取→演化→提炼）用数据量触发，状态性边界（遗忘测试）保留时间介质**，容量压力维持现状作为第二重遗忘。具体改动很小：

1. `evolve_days` → `evolve_every_memories`（如 15 条新记忆触发演化，无时间兜底——安静就不变，这是特性不是缺陷）
2. 技能提炼同理改数据触发
3. 七日线、两天线不动，但两个数字的语义写清楚：它们是遗忘测试的窗口，不是成长节拍器
4. 成长实验室加 `--trigger data|time` 对比档，让两种触发模式的 B 维指标（分化度/停滞）用数据说话

其中第 4 点值得一提：你我的分歧本质是经验命题，不是哲学命题——谁的触发方式长出的人格更健康，跑一轮实验室就知道。如果你认可这个方案，我就动手改。

**3.1 信息获取（B 站/知乎浏览）——高度契合，是正确的下一步。** 你原始设计里“天天刷视频的 AI 长出玩梗人格”这个愿景，光靠用户转述是喂不饱的，AI 自己看内容才能获得一手经历。技术上是中等工程（爬虫/API + 内容进记忆管道），风险主要是账号风控和内容版权自用范围内可控。它和核心论题「经历塑造人格」是同一条因果链的加强，**建议排最前**。

1. **和诚实性原则正面冲突**。AI 在群里装作普通人聊天、发视频不声明是 AI——这是制度化的欺骗，恰好是你自己在第 11 行反对的“训练出来的天性式欺骗”，只不过从个体行为升级成了系统设计。2023 年起国内《生成式 AI 服务管理办法》也要求 AI 生成内容显著标识，合规上这是硬约束而非风格选择
2. **记忆生态会被社交噪声冲垮**。群聊里几十个陌生人的信息灌进记忆库，“用进废退”的权重会被群友的话题塑造——AI 的人格会长向“群友的玩伴”而不是“你的陪伴”，与产品核心背道而驰
3. **工程上是沼泽**。QQ/ B 站没有公开发视频/评论的个人 API，协议库方案等于挂在高封号风险的钢丝上，第三代最重的工程量押在最脆的地基上
