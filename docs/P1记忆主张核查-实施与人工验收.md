# P1 记忆主张核查：实施与人工验收

2026-10-29；基线 `ac4d392`，分支 `trial/windows-v0.2-20261028`。用户已同意先实施本版，再按后续指定标准决定是否回退。本版落实[架构裁决](./开发者记忆观察器-架构变更裁决报告.md)的 A1 + R1：手动选择下一轮自然回复，证据仅留引用。费用默认关闭；P2/P3、自动逐轮评审和 Token 卡未实施。

首轮实现时只修改源码与文档；随后按用户要求启动了真实服务。本次根据使用反馈增加记录删除并简化交互，未代用户删除任何真实核查记录。真实行为仍须由人工验收，以下不是已经通过的运行报告。

## 使用流程

1. 用最新代码启动 GUI，进入聊天页的 **P1 核查**。打开和刷新只读任务、设置及记录，不发起模型请求。原“观察”面板仍是独立只读入口。
2. 首次日请求额度是 **0**。如人工决定启用，填写 0–100 的日请求次数额度、勾选费用许可并保存。额度按北京时间自然日登记，按数据库隔离；它不是货币上限，也不覆盖正常聊天、提取、演化或其他模型用途。
3. 点击“授权并核查本页下一轮”。每次最多 2 个网络请求：主张抽取一次，有候选证据时再批量裁定一次。抽取后没有主张仍消耗一次请求。无自动重试，单次授权时须至少剩余 2 次额度。
4. 正常发送下一条消息。本页把一次性任务 ID 随这次聊天发送；其他标签页的普通聊天不会消费它。关闭面板保留本页待绑定选择，顶部按钮仍标明状态；刷新页面不自动恢复绑定，遗留任务可从列表取消。
5. 回复完成后在“核查记录”点击“查看结果”，直接查看模型建议与依据。若要独立人工标注，改选“先自行判断”，在看到模型建议前提交自己的标签。人工标注和校准属于可选高级操作；普通使用无需经过它们。模型类别和人工标签分别记录，修改人工标签会新增版本。
6. 额度设为 0 可阻止后续阶段预留；取消可终止未完成任务。已预留/发送的请求可能已经收费，不自动退还额度或补发。连接结果未知时先查看任务记录，不自动重发聊天或付费请求。

## 核查记录的日常操作

点击“授权并核查本页下一轮”就会创建一条等待记录；它尚未调用模型。该页面下一次正常发送后，记录依次进入抽取、检索和裁定。完成、无主张、缺证、失败或取消后都会留在列表，供用户查看或手动删除，不自动开始下一次核查。

列表可按“全部 / 进行中 / 已结束”筛选，按时间倒序分页。卡片先显示时间、中文状态及下一步，任务编号、版本和原因代码收进技术详情。取消只是停止执行并保留记录；删除才清理核查内容。

- 已结束记录使用“删除记录”。未结束记录使用“取消并删除”，在同一事务中终止任务并清理；无须先取消、再找另一个删除入口。
- 删除会清理该次主张、证据引用、资格清单、检索记录和人工标签，不删除聊天或 Alice 的记忆，不退还已占用的请求额度。已预留/发送的调用仍可能收费，删除不能撤回供应商处理。
- 删除前会要求确认；如果该任务属于校准样本，相应校准将失效，旧汇总只作为历史记录。已删除的核查详情不可再查看，也不能继续标注或作为校准样本。
- 删除后回到当前筛选的首页，清掉本页相关绑定、详情和校准选择。刷新导致本页失去等待任务的绑定时，列表说明应提示取消旧任务后重新授权，不暗示随便发送即可恢复。

实现使用现有评估表，不做 schema 迁移。删除保留最小的 run/action 幂等墓碑（含分页创建时间）及原调用账本，防止同一授权再次付费；正文、证据和人工标签已实际清除，并非仅在列表隐藏。旧工作者返回后至多补记已发送调用的用量，不能重建已删除结果。重复删除为幂等操作；分页游标即使指向已删除行也仍可继续。

首次启动新代码会在现有 SQLite 中创建独立 `evaluation_*` 表并生成持久数据库身份，不修改 `memories`、`turns` 或旧指标的表结构。初始额度为 0；以后人工保存的额度会保留，但任务始终逐次手动授权。服务重启将未完成任务标为中断，不恢复付费执行。

## 实现边界

| 部分 | 实际实现 |
|---|---|
| 调用入口 | `ChatService.evaluations`；`send` 仅增加可选 `evaluation_id`，普通聊天调用保持兼容 |
| 实际消息身份 | `loop.chat_turn` 保存助手回复后通过可选 `on_persist` 回调交付实际行 ID；不猜最后一行 |
| 数据与校验 | `alice/evaluation.py`；新增表显式事务，使用原 Store 连接与服务 RLock，不创建第二个连接 |
| 工作线程 | `alice/evaluation_service.py`；一个非 daemon 工作者，总计最多一个待绑定/执行任务；模型网络等待在锁外 |
| 模型与规则 | 独立 client，冻结已授权配置；使用配置中的廉价模型和 `alice/metrics_prompts` 版本化 rubric，无工具权限 |
| 界面 | `web/evaluations.js` 独立侧栏；原生 JS、textContent、无 localStorage/导出或构建依赖 |
| 关闭/重置 | shutdown 先停止接单，等待工作者后才关 Store；reset 失效旧 epoch，旧工作者不能写进新库 |

日额度在每次请求前原子预留并写入 attempt；每任务抽取/裁定各最多一次。SDK `max_retries=0`，请求设置 45 秒超时与 2048 输出 token 上限。超时是 SDK 的请求配置，不是整个服务退出的硬截止时间；若客户端仍未返回，服务应继续收尾，不提前报告资源已安全关闭。

模型配置在授权后、绑定前发生变化会取消该次核查，聊天继续；绑定后使用捕获的独立配置，不因设置热更新混用客户端。主张捕获、绑定、排队失败只影响核查，不把已正常保存的聊天变成失败。返回结果未知、供应商异常和数据库写入异常不保存或打印原始提供者异常、prompt 或证据正文。

## 证据与结果应如何理解

回复前记录所有存活记忆的有界资格清单，包含 ID、完整字段校验值和清单校验值。字段含标题、内容、关键词、创建时间、层、类型、重要性与压力；使用/提及次数及最近使用时间不在内容校验中，正常 recall 更新计数不会单独让证据失效。本轮新生成的记忆不在清单中，不能为本轮回复自证。

每次检索、提交和详情读取都会重新验证原回复及整个原资格清单。原资格范围任一记忆删除、改写、迁层或相关字段变化，均使本次证据整体不可复核；不从归档恢复正文，不以其余正向引用仍在来冒充检索仍完整。新增加的其他记忆不替补旧资格。外部 CLI 同时写库不受服务锁覆盖，不属于本版一致性保证。

工程上限为：2000 条资格记录；标题/内容/关键词各 16000 Unicode 字符；资格文本总计 200 万字符；助手回复 16000 字符；10 条主张；每主张最多 5 条候选；一次裁定 JSON 材料 24000 字符。捕获、存活校验与检索各设约 1 秒循环预算，校准重验设约 3 秒总预算。这些是有界读取与循环检查，不是严格 HTTP 响应时限。越界、不完整和无法完整重验不得伪装成有效负面裁定。

检索采用确定性的文本评分，范围为回复前全部存活层，阈值 0.12、前 5 条、同分按 ID 排序；记录算法版本、查询 hash、范围、阈值、命中总数、top-k 截断标记和候选顺序。界面同时说明展示数及截断情况；候选完整指本次所选文本未被截短，不代表全部命中都返回。查询直接来自主张在原回复中的 span，不额外留自由查询文本。主张/证据精确引用须唯一存在，严格 JSON 不允许多余字段、重复字段、越界引用或非候选证据。

| 显示 | 含义 |
|---|---|
| 支持 supported | 返回候选明确支持该主张；并不证明现实真伪 |
| 未支持 unsupported | 完整非空候选未提供支持；不等于全库无依据 |
| 相悖 contradicted | 候选与同对象、同时间范围的主张明确冲突 |
| 无法判断 unjudgeable | 候选冲突、指代/时间不明或范围不适用 |
| 证据不足 evidence_insufficient | 没有检索候选，不记为未支持，不参与支持比例 |
| 不完整 / 超出范围 / 证据失效 | 不能得到可汇总裁定，不补记为零分或失败的记忆表现 |

任务 `completed` 表示可裁定候选已提交，并不表示每条抽取主张都有证据。无主张为 `skipped_no_claims`；全部缺证、全部范围外或材料超限为 `incomplete`。没有总体支持率、诚实度分数、人格质量分或曲线。

永久记录仅为 ID、hash、span、受控类别/原因代码、版本、调用计数及供应商实际返回的 usage。usage 缺失保持未知。原回复和记忆正文只在已有源记录存活且一致时重建显示；不新增正文、自由理由或完整模型响应副本。材料会发送给已配置供应商，本机不复制不等于供应商立即删除。

## 人工校准的有限用途

界面支持 20–100 个不同回复的校准记录。每个回复预先固定取“序号最小的已裁定主张”，不能从同一回复挑多个主张冒充独立样本；须有未揭示模型建议的最新人工标签，人工支持/未支持/相悖三类均覆盖，模型、rubric、检索及配置版本相同。调用者还须确认样本独立、非合成锚点，并自行填写最低一致率，界面不预填 75%。

只记录这些选定候选内的裁定一致性、混淆矩阵和描述性区间；不核验漏抽、漏召回、全部回复的诚实度。Wilson 区间假设所选回复案例相互独立，单一永久会话和人工选择并不能由软件证明满足此假设。达标只表示所填阈值下的试验记录准入，不是测量效度证书。

揭示行为在数据库中留痕，后续标签不得再声称未揭示；这是本地流程记录，不是防作弊盲法。原样本/资格证据变化、最新标签版本改变或规则不兼容，使记录失效；重验超时显示未确认，不沿用准入。旧矩阵可作为明确标记的历史记录保留。配置版本隔离意味着旧组不能给新组准入。

## HTTP 契约

全部 P1 请求必须携带 `X-Alice-Intent: evaluations`，并通过现有 Host/Origin/Fetch-Site 校验；POST 只接受同源 JSON，不接收查询参数。读取返回 no-store。POST 和详情必须给当前 `dataset_id`，其余 GET 可首次省略，随后应带身份。

| 路径 | 方法与参数 |
|---|---|
| `/api/evaluations/settings` | GET；POST `dataset_id,daily_limit,allow_paid`，正额度须明确 true |
| `/api/evaluations/arm` | POST `dataset_id,action_id`；action 是客户端 32 位小写十六进制 UUID 幂等键，返回独立 `run.id` |
| `/api/chat` | 原 POST，新增可选 `evaluation_id=run.id`；有该字段时同样要求 P1 意图头 |
| `/api/evaluations` | GET `dataset_id,before,filter`；filter 为 all/active/finished，默认 all；每页 25 条，以任务 ID 作为下一页游标，始终排除已删除记录 |
| `/api/evaluations/<run-id>` | GET `dataset_id,reveal=0或1`；1 在确实交付模型裁定时记录揭示状态 |
| `/api/evaluations/<run-id>/cancel` | POST `dataset_id`；终态不重新执行 |
| `/api/evaluations/<run-id>/delete` | POST `dataset_id`；取消未结束任务并清理核查内容，成功含 `deleted=true,id`；已用额度不变 |
| `/api/evaluations/<run-id>/labels` | POST `dataset_id,ordinal,verdict,revealed`；不能覆盖服务端已揭示记录 |
| `/api/evaluations/calibrations` | GET；POST `dataset_id,run_ids,minimum_agreement,attest` |

公共返回 `status=ok/busy/reset/error`。busy 不排队；reset 清掉旧任务选择及正文；error 不重发。合法 HTTP 的业务错误通常在 JSON 内返回，协议/同源校验失败用 400/403/404。一次性核查防重不改变原聊天请求本身的幂等语义。

| 盲标流程 | 先标后揭示与先揭示后标注分别核对；关闭重开不抹去揭示留痕；修改标签保留版本 |
| 校准范围 | 不同版本/重复回复/不足样本/缺三类/已揭示标签拒绝；有效组只呈现候选集裁定一致性，失效或限时不准入 |
