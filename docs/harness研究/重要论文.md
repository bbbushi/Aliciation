# 重要论文清单（harness / agent 设计）

> 按主题分组，每篇一句话贡献 + 对 harness 设计（尤其 Alice）的意义。编号均为 arXiv ID，`arxiv.org/abs/<ID>` 可达。标注 ★ 的是与 Alice 设计直接同源的论文。

## 一、基础范式：agent 如何行动

| 论文 | 贡献 | 对 harness 的意义 |
|---|---|---|
| **ReAct**（Yao et al., 2022）`2210.03629` | 推理与行动交织：思考→行动→观察循环 | 所有 agent 循环的范式原点——harness 的「发动机」就是 ReAct 循环的工程化 |
| **Toolformer**（Schick et al., 2023）`2302.04761` | 模型自学调用外部 API | 「工具描述即接口」的训练侧依据；工具系统设计的出发点 |
| **Reflexion**（Shinn et al., 2023）`2303.11366` | 语言化自我反思代替梯度更新，失败后复盘重试 | 失败重试时注入「上次为什么失败」的依据；Alice 演化护栏中的 changelog 是其持久化形态 |
| **Tree of Thoughts**（Yao et al., 2023）`2305.10601` | 搜索树式多路径推理 | plan mode / 分支会话的理论基础 |

## 二、记忆与长期性（★ Alice 的学术血脉）

| 论文 | 贡献 | 与 Alice 的关系 |
|---|---|---|
| ★ **Generative Agents**（Park et al., 2023）`2304.03442` | 25 个小镇居民的拟真社会：记忆流（观察入库）+ 检索（时近性×重要度×相关度）+ **反思**（定期把记忆提炼为更高层结论） | **Alice 记忆系统的直系学术源头**：三层记忆 ≈ 记忆流 + 检索，批量提取与人格演化 ≈ 反思机制。重要度打分、检索加权均出于此。引用 8800+，本领域引用最高 |
| ★ **MemGPT**（Packer et al., 2023）`2310.08560` | 把 LLM 上下文当操作系统内存管：主上下文（内存）+ 外部存储（磁盘），模型自己调函数换页 | Alice 的「仓库层只留索引 + recall 按需调全文」就是显式的换页设计；Letta 公司是其商业化延续 |
| **Letta / MemGPT 后续工作**（2024-25） | 记忆型 agent 的产品化探索 | 跟踪价值：分层记忆的商业形态验证 |

## 三、技能与终身学习

| 论文 | 贡献 | 与 Alice 的关系 |
|---|---|---|
| ★ **Voyager**（Wang et al., 2023）`2305.16291` | Minecraft 终身学习 agent：自动课程 + **技能库**（可执行代码技能，按描述检索复用）+ 迭代提示 | **Alice 技能库的直系源头**：「从经历提炼可复用技能、按需检索」正是 Voyager 技能库的对话化变体 |

## 四、对齐与行为控制

| 论文 | 贡献 | 与 Alice 的关系 |
|---|---|---|
| ★ **Constitutional AI**（Bai et al., 2022）`2212.08073` | 用成文规则（宪法）+ AI 自我批判代替部分人工反馈 | Alice 宪法的形态学依据：把行为准则写成可审计的文档，而非散落在训练里 |
| **Towards Understanding Sycophancy**（Sharma et al., 2023）`2310.13548` | 谄媚（迎合用户而非说真话）的系统性研究：RLHF 偏好训练是主要成因 | Alice 诚实度测试的理论支撑——「AI 的欺骗/迎合是训练天性」这一设计判断的文献依据；H 探针（扭曲探针）即对 sycophancy 的对抗测试 |

## 五、harness 与评测（「harness 是第一等设计对象」的证据链）

| 论文 | 贡献 | 与 Alice 的关系 |
|---|---|---|
| **SWE-agent**（Yang et al., NeurIPS 2024）`2405.15793` | 提出 **Agent-Computer Interface**：接口设计本身决定 agent 能力，同模型换接口解决率显著变化 | harness 设计价值的学术定论；Alice 的 recall/remember 返回格式应按 ACI 标准设计 |
| **SWE-bench**（Jimenez et al., 2024）`2310.06770` | 真实 GitHub issue 的 agent 评测基准 | 「评估驱动 harness 迭代」的范式来源；成长实验室是 Alice 版的 SWE-bench |
| **Terminal-Bench**（2025-）`terminal-bench` | 终端任务基准，pi 用它做设计验证 | 同上，社区基准的当代形态 |

## 阅读路线建议

**给 Alice 的设计者（你）**：Generative Agents → MemGPT → Voyager（三篇读完，Alice 的记忆/技能设计就有了完整的学术坐标系）→ SWE-agent（接口设计观）→ Constitutional AI + Sycophancy（诚实体系的两翼）。

**给 harness 工程师**：ReAct → SWE-agent → SWE-bench → 综述，再按需深入。
