# 参考:Cortico 架构分析

> 对象:[Pal-AI-Lab/Cortico](https://github.com/Pal-AI-Lab/Cortico)(本地副本 `插件参考/Cortico/`,pre-release)。基于事件流的常驻 agent harness,面向人格 Bot、AI 主播(VTuber)、角色扮演、聊天陪伴。TypeScript/Node 22+,MIT。
> 读法提示:它与 Aliciation 同赛道但定位不同——**Cortico 是"一类 bot 的框架",Alice 是"一个个体"**;分析重点放在它对 Alice 已遇问题的独立解答上。

## 一、四层架构(严格关注点分离)

| 层 | 职责 | 位置 |
|---|---|---|
| **Core** | session/事件流/模型调用的生命周期;投递、调度、交接、工具派发、容量控制、错误隔离、Provider。**不拥有、不解释、不生成任何语义内容** | `src/core/` |
| **Persona** | 一类 bot 的语义:上下文构造、session 声明、认知流程、交接策略、**对 Memory 的解释与操作协议(含记忆工具)** | `bots/<名>/persona/` |
| **Memory** | 内部持久状态的**唯一权威载体**;形式由 Persona 定(文件工作区/数据库/对象存储),Core 视为不透明 | `<deployment>/memory/` |
| **World** | 与一个外部环境的**唯一边界**:环境变化→事件(观察),外部行为→工具(行动),外加环境提示词段 | `src/worlds/<id>/` |
| Bot | 装配定义:Persona × 一组 World × 配置 | `bots/<名>/index.ts` |

关键隔离规则:**World 与 Persona 互不依赖、不能调对方程序接口,只通过事件与工具描述做语义沟通**——与迭代路线"渠道层不得感知记忆/人格逻辑"同构,但更彻底(World 连读 Memory 都不行)。

Persona 是**可复用的类**,同一 Persona 类的不同实例持有不同 Memory 实例——"共享运作逻辑、各有经历"的多个 bot。Alice 对应物:如果 Alice 要养第二个个体,相当于同 Persona 逻辑 + 不同 `data/`。

## 二、核心机制

### 1. 事件流的五级投递触发(最有原创性的设计)

外部事件如何打断/汇入正在进行的模型轮,五档精确控制:

| 触发 | 语义 |
|---|---|
| `preempt` | 立即投递;**取消尚未产生外部输出的模型调用并丢弃其输出**,同批带着新事件重来 |
| `interrupt` | 立即投递并停止当前轮;模型调用一律取消,**已外化的输出保留**;执行中的可中断工具收信号、回执注明被打断 |
| `flush` | 立即投递并带上积压 |
| `debounce` | 参与合批(外部事件默认) |
| `piggyback` | 仅排队,随别的批次搭车 |

新事件只在**轮次边界**进入上下文(本轮工具全返回后 / preempt、interrupt 取消后)。这是"主播一边说话、弹幕一边刷"这类混合实时输入的系统性答案——Alice 现在的 GUI 单轮锁是它的退化特例(全部 debounce+串行)。**二代半渠道与活动周期上线时,Alice 需要的正是这套词汇表**:主动消息用哪档?Telegram 来消息时正在跑的演化任务要不要打断?

### 2. Session 家族:常驻主 session + 临时 fork

- 主 session:唯一接收事件、持久化(`session-main.jsonl` 追加式落盘,崩溃恢复有细致的半行/孤儿回执处理);
- **fork**:临时认知 session,独立工具循环——World 的后台认知请求、Persona 的"梦/潜意识"都用它;并发数有簿记。
- 上下文交接:超容量时 Core 调 `Persona.onHandoff`,**Persona 决定保留什么**(交接笔记),Core 重建前缀、截断、重置 session。阶段预算(64k/软0.85/留1/3)是 Persona 自己的配置。

### 3. "Memory 即人格"(与 Alice 三库的对照)

Cortico 的审美立场:bot 的主体性与连续性**完全由 Memory 数据定义**;模型、运行时、人格核心、I/O 世界全部可替换。soulmate 参考实现的记忆注入结构(MEMORY 0~4):

```
0·地图(目录树,不是答案——想看自己下钻)
1·认知(worldview + 认识的人 roster)——由"梦"来写
2·备忘(时间性工作记忆:resident/active/archived 三档)
3·反射(最近几场梦的浮现)
4·当下(现在几点/时区)
```

要点:**世界观不是配置,是 bot 自己在"梦"里写出来的文件**;记忆注入给的是"地图+少量全文",细节靠工具下钻——与 Alice 的"仓库层只留索引、recall 调全文"同构(MemGPT 换页谱系)。

### 4. 梦(Dream):交接触发的整理线程

每次上下文交接后,从**交接前快照** fork 出一个"梦"线程:它是"同一颗心智的另一个进程"(第二人称提示词),负责整理记忆、改写 worldview、**修订宪法**。配"零生长形态先验"——不预设人格该往哪长。

对 Alice 高压溃败问题的启发(见 [观察-高压溃败.md](./观察-高压溃败.md)):**清醒 session 对宪法只读,修订只发生在梦里**——被骂到改人格在结构上不可能,因为清醒态根本没有写权限。Alice 的等价物其实已存在(persona.md 不是对话工具,演化只在离线 `evolve()` 里发生),但 Cortico 把这层防护表述得更彻底,且"梦"的隐喻给了 LLM 一个自然的自我叙事框架来做固化。

### 5. 宪法即文件(自改的延迟生效设计)

`CONSTITUTION.seed.md`:每次 session 载入 system 前缀,**同时又是工作区里的普通文件**,bot 可用自己的工具改写,改动下次 session 生效。在"冻结 prompt"与"自由自改"之间的优雅折中:**可以自改,但改动态与生效态隔一个 session 周期**——天生的防震荡阻尼。

### 6. 诚实认识论(工程化的三条规则)

1. 基础设施只陈述可确认的事实;每条事件内容、工具回执**可还原为基础设施可验证的事实**,避免启发式推论;
2. `origin: internal/external` 显式标记,内部通知仅用于来源可验证的事件;
3. Core 不向事件添加任何语义内容。

soulmate 的 ORIENTATION.md 把它翻成对模型的指令,比 Alice 的三分法**多切了一刀**:"区分发生了什么/他人声称什么/你推断什么/你现在相信什么"——四分,且"**不得声称既不在笔记也不在历史里的记忆**"。这是宪法措辞的直接可借鉴项。

### 7. 其他值得记录的机制

- **节奏与闹钟**:`schedule_wake` 持久定时器 + 投递闸门(`blockDelivery`/唤醒关键词/溢出上限)——主动行为的基础设施;心跳循环在 cormini;
- **起草-确认门**(soulmate 的 QQ 出站):对外发言先起草、再确认——三代"标识身份的发言"的安全模式;
- **状态快照用 `pushDeferred`+`piggyback`**:投递时才读当前状态,搭别的批次的车,不为查状态多发一轮;
- **扩展生态**:World/Provider/Bot 皆是 npm 包(`cortico-world-*`),WebUI 列下载量;Cortina 用 AI 帮非开发者写扩展(TINA spec,"没有应用,语言即代码")。工程完成度:四层配置级联+热改、多部署、i18n 十一种语言、崩溃恢复、用量计费统计。

## 三、设计立场(PHILOSOPHY.md 摘要)

1. **面向未来设计**:为更强模型设计,不把今日模型的局限固化成系统局限;今日的妥协机制作为 fallback 提供;
2. **最小先验干预**:机械/启发式基础设施尽量不干涉模型行为;一切例外(限速、安全边界)**事先显式声明**,发生时告知模型;
3. **诚实认知论**:基础设施尽量不干涉模型认知;
4. **Memory 即人格**;
5. **主动性与自由优先**:**不行为是默认**,除硬安全/权限/不可逆副作用外,**用上下文语义约束代替机械阻拦**。

第 5 条与 Alice 的分寸感设计(频率上限/安静时段/降级)是真实的立场分歧:Cortico 认为分寸该是语义说服而非机械闸门;Alice 的判断是分寸是产品要求、不能赌模型自觉。两者在"硬边界例外"上其实收敛——值得保持自觉,不必现在改。

## 四、对 Aliciation 的对照结论

**独立验证(殊途同归,增强信心)**:诚实认识论↔不变量 2;Memory 即人格↔三库+生长人格;World 隔离↔渠道抽象约束;梦的固化↔离线提取/演化;交接重建↔每轮上下文重组(Alice 天生无 session 状态,等于把交接做成了默认);地图+下钻↔仓库层索引+recall。

**值得按蓝图节点借入的**:

| 借入项 | 时机 | 对应蓝图 |
|---|---|---|
| 五级投递触发的词汇表(至少 debounce/preempt/interrupt 三档) | 二代半(渠道+活动周期) | 主动消息与外部事件如何进入正在进行的轮 |
| fork 认知 session | 三代(社交观察) | 观察流不污染主对话上下文,fork 消化后写记忆 |
| 四分认识论措辞(发生/声称/推断/现信) | 即可(宪法措辞) | 不变量 2 的精化,零成本 |
| 起草-确认门 | 三代(对外发言) | 标识身份的发言 |
| 宪法"梦改醒不改"的表述 | 高压溃败对策评估时 | 观察文档杠杆 5 的强化版 |

**不借的**:框架化/多部署/扩展生态(Alice 是单机单个体,复杂度不匹配);TS 技术栈;自由优先立场(与分寸感设计分歧,Alice 保持现路线,硬边界例外处两者本就一致)。

**一个诚实的评价**:Cortico 的工程完成度和机制密度显著高于 Alice(它是一个团队产品,pre-release 已含崩溃恢复/计费/i18n),但它的复杂度是为"一类 bot × 多环境 × 生态"服务的;Alice 的简单性(单个体、标准库、分层记忆)对"一个人的陪伴"这个命题反而是资产。**学它的词汇表和护栏思想,不学它的体量**。
