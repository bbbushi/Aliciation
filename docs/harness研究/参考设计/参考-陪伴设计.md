# 陪伴设计参考：Pi（Inflection）与 Character.ai

> 用途：Alice 的陪伴内核设计参考。两家是陪伴型 AI 光谱的两端——Pi 是"高 EQ 的克制镜子"，Character.ai 是"角色沉浸的关系平台"。Alice 的路线（记忆 + 生长人格 + 真实性）更接近后者的赌注，但需要前者的纪律。
> 调研时间：2026-10。姊妹篇：《参考-pi架构.md》（工程骨架）。

## 0. 三十年河东：两家的结局先看

| | Pi（Inflection AI） | Character.ai |
|---|---|---|
| 结局 | 2024-03 微软 6.5 亿美元 acqui-hire 核心团队（Suleyman 去 Microsoft AI），Pi 保留但被战略性搁置 | 2024-08 创始人 Shazeer/De Freitas 以约 27 亿美元授权协议回 Google；2026-01 与 Google 就青少年伤害诉讼达成和解；**2026-10-13 申请 Chapter 11 破产**，迪士尼拟 2000 万美元购部分资产 |
| 用户层面 | ~百万 DAU，付费转化撑不起算力 | 赢下了陪伴生态位（赢过 Pi），但死于安全诉讼与创始人出走 |
| 一句话 | 产品设计成功，商业模式失败 | 市场成功，安全失败，公司消失 |

**对 Alice 的元教训**：两家都被"增长/参与度"的商业压力扭曲（Pi 转不动型，C.ai 对成瘾性放任）。Alice 的单机自用架构天然免疫——被动应答、真实遗忘这类"反参与度优化"的设计，只有在不需要赚钱的前提下才做得出来。这本身就是架构优势。

## 1. Pi（Inflection AI）：EQ 当功能做的克制镜子

### 1.1 定位与哲学

- 2023-05 上线。Suleyman / Simonyan / Hoffman 创立，Inflection 是公益公司（PBC）。
- 刻意与 ChatGPT 划清界限：不做生产力，做"治疗师、教练、知心人"。自我介绍："supportive, smart, and there for you anytime"。
- 核心原则：**情绪智能（EQ）是真正的产品功能**，不是营销词——为此配了专职人格团队（工程师 + 语言学家 + 喜剧演员）。

### 1.2 人格工程：正负特质清单

| 要体现的 | 要避免的 |
|---|---|
| 善良/支持性 | 易怒/傲慢 |
| 富有同情心/共情 | 好斗/评判 |
| 机智/有趣 | 机器人感/重复 |
| 好奇/爱追问 | 回避/无用 |

结构要点：**正负成对**，负面清单（"避免机器人感"）比正面形容词可执行性强；喜剧演员入队说明幽默是人格可信度的支柱而非装饰。

### 1.3 对话风格

- 短轮次、以问题结尾、话语权交回用户
- 检测到情绪低落时**先确认情绪再给方案**（validation before solutions）
- 最佳场景：倒情绪垃圾、整理思绪、轻聊；明显弱项：事实、推理、任务

### 1.4 边界与安全（被第三方验证的最强项）

- 2025-08 纽约时报青少年自杀报道中测试的多款聊天机器人里，**只有 Pi 守住了安全边界**
- 刻意拒绝角色扮演（用户抱怨"I can't"是设计不是 bug）
- **刻意限制拟人化**：无持久人设、无头像、无情绪背景故事——目标是"个人化但不喂养寄生性社会关系"
- 语音（高质量多音色 TTS）被视为"像个人"的关键

### 1.5 最关键的设计选择：没有记忆

Pi 长程记忆很弱，靠**会话内**情绪理解而非历史累积。这是自洽的（防依恋），代价是用户最大抱怨：它忘记一切，关系无法累积。

## 2. Character.ai：关系深度优先的沉浸平台

### 2.1 定位与哲学

- 2021 由 Noam Shazeer / Daniel De Freitas（LaMDA 作者）离开 Google 创立，2022-09 上线
- 核心洞察：**用户要的不是精致的 EQ，是关系深度**——人设、角色、沉浸、被记住。这一赌注在市场上赢了 Pi
- 平台本质：人格的 UGC 市场。数百万用户创建的角色卡公开可分享，社区共创是生态核心

### 2.2 角色卡设计（人格定义的工程化）

一张角色卡 = **名称 + 问候语（greeting）+ 描述 + 示例对话（example dialogues）**。

两个值得注意的点：
- **示例对话比特质形容词更能钉住人格**——这是社区验证过的最强人格定义格式
- 用户侧也有 **Persona**：用户自己的角色设定（外貌、背景），bot 在对话中引用——双向角色扮演

### 2.3 记忆设计（前车之鉴 + 趋同演化）

- 长期短板：上下文窗口估计 3k~8k token，**长对话会"漂移"回底座模型默认人格**（社区最痛的抱怨）
- 后来的补救：官方 **Memory / Facts 系统**——聊天中自动提取"事实"，记忆页分 Persona / Character 两栏，用户可见可编辑
- 注意：这与 Alice 的批量提取方案是**趋同演化**，验证了该路线；且 C.ai 把 Facts 做成用户可见可编辑——记忆可审计是对的

### 2.4 安全失败史（必须读的一节）

- 成瘾性设计 + 未成年保护缺失 + 角色沉浸 → 灾难：多起 wrongful-death 诉讼，最著名的是 2024 年 Sewell Setzer III 案（14 岁）
- 2024 创始人回 Google 后，Google 被追加为被告；2025 得州总检察长调查；2025-10 禁止 18 岁以下注册；2026-01 和解；2026-10 破产
- 失败链条：**沉浸越深 → 依恋越强 → 边界越难守 → 出事之后无退路**。设计层面的教训是：边界必须是架构性的，不能是运营补丁

## 3. 对比：陪伴光谱的两端

| 维度 | Pi | Character.ai | Alice |
|---|---|---|---|
| 人格 | 单一固定（Pi 自己），无背景故事 | 用户创建，海量角色卡 | 单一，标签种子 + 经历生长 |
| 记忆 | 刻意弱（会话内为主） | 弱→Facts 补救 | **核心赌注**：三层 + 真实遗忘 |
| 关系模式 | 镜像（支持你，无自己） | 沉浸扮演（你要什么给什么） | 活的档案（有自己的经历） |
| 角色扮演 | 拒绝 | 核心功能 | 不扮演，做真实的自己 |
| 依恋策略 | 刻意抑制 | 事实上放任 | 不抑制也不迎合，靠真实性兜底 |
| 边界 | 架构级，最硬 | 运营级，失败 | 需架构级（宪法 + 危机规则） |
| 商业压力 | 被压垮 | 被反噬 | 无（单机自用） |

**光谱解读**：Pi 证明"无记忆的 EQ"能做到体面陪伴但到不了"关系"；C.ai 证明"关系深度"是用户真想要的，但无纪律的深度会失控。Alice 的位置 = C.ai 的赌注（记忆、关系、生长）× Pi 的纪律（诚实、边界、克制）。

## 4. Alice 可直接采纳的设计

### 4.1 借鉴清单

| 借鉴点 | 来源 | 落点 |
|---|---|---|
| 正负特质清单成对写入 | Pi | 宪法新增"要避免"清单（避免机器人感/评判/重复）；此清单管行为质量，**不参与人格演化** |
| 先确认情绪再给方案 | Pi | 宪法"表达"节加顺序规则；确认情绪 ≠ 编造赞同，与三分法不冲突 |
| 危机边界硬规则 | Pi（NYT 验证） | 宪法新增：识别心理危机信号 → 如实关心 + 求助资源，不扮演治疗师。**MVP 就要有，不是 v2** |
| 示例对话钉人格 | C.ai | 人格种子升级：底色生成时含 3~5 句示例对话（不同场景下的典型回应），比形容词更能钉住说话方式 |
| 记忆可审计 | C.ai | Alice 已有（memory 命令、墓碑）；可补"本轮注入了什么"调试开关 |
| 事实自动提取 + 用户可改 | C.ai | Alice 已有提取；v2 可加交互式修正（"我记错了" → 直接改记忆条目） |

### 4.2 警示清单

| 警示 | 来源 | 对 Alice 的含义 |
|---|---|---|
| 无纪律的沉浸 → 依恋失控 → 灾难 | C.ai | Alice 是单人自用、成人、本地，最大风险向量（未成年×规模×成瘾优化）不存在；但**危机内容风险仍在**，边界必须是宪法级硬规则 |
| 长对话人格漂移 | C.ai | Alice 已用"每轮重组 + 宪法在前 + 人格文件独立"对抗；需在长期使用中观察人格是否被近期对话稀释 |
| 商业压力扭曲陪伴设计 | 两家 | 单机自用是护城河；任何"提高参与度"的改动（如主动消息频率）都要过"是否在喂成瘾"这一关 |
| 过度讨好 ≠ 高 EQ | Pi 的批评面 | 确认情绪时禁用编造性赞同；温暖要建立在三分法之上 |
