# 论文导读 · Tree of Thoughts:搜索树式推理

> 原文:[Tree of Thoughts: Deliberate Problem Solving with Large Language Models](https://arxiv.org/abs/2305.10601)(Yao et al., 2023,Princeton & DeepMind,NeurIPS 2023)
> 量级:把 CoT 从"链"推广成"树"的代表作;Yao 是 ReAct 与 ToT 的共同作者,一脉相承

## 一句话

把中间推理步骤(Thought)组织成一棵树:每步生成多个候选、用模型自己给状态打分、按搜索算法(BFS/DFS)探索与回溯——让 LLM 会"想了再想、不行重来"。

## 它要解决的问题

CoT 是单链推理:一路向前,错了无法回头;采样多数投票(self-consistency)只是重复尝试,彼此不通信。ToT 的观点:难题需要**深思熟虑**——探索分支、评估中间状态、必要时放弃换路。这是人类问题求解的标准形态,但 LLM 推理当时没有。

## 核心机制

四个组件把推理变成显式搜索问题:

1. **思维分解**:定义"一个 Thought"是什么——一句话、一段计划、一行算式(24 点游戏里是一步运算)
2. **Thought 生成**:每步让模型采样 k 个候选(或独立采样,或按序提案)
3. **状态评估**:LLM 自己当评估器,对每个中间状态打分("确定不行/可能不行/可能行/肯定行")或在候选间做 pairwise 比较
4. **搜索算法**:BFS(每层保留最优 b 个)或 DFS(深入到底,不好就剪枝回溯)

本质是:**生成器 + 评估器 + 搜索框架**三件套,全部由同一个 LLM 通过不同的 prompt 扮演。

## 关键结果

- **24 点游戏(强约束组合问题)**:GPT-4 用 CoT 解出率约 4%,ToT 达到 **74%**——这是论文最著名的对比,说明"更多推理时间换正确率"在难问题上收益巨大
- **创意写作**:先列五个候选大纲、打分选优再成文,人评显著好于直接 CoT 一次成文
- **填字游戏**:ToT 能利用"字母级约束"回溯排除,CoT 一次性输出后无法自我修正
- 代价:ToT 的 LM 调用次数是 CoT 的数十倍——**算力换正确率**是明码标价的

## 局限

- 成本高:简单任务上 CoT 已够,ToT 是杀鸡用牛刀
- 评估器自身的可靠性决定搜索质量;评估器系统性偏差会导致整棵树长歪
- 对话/陪伴这种开放连续任务,没有可枚举的中间状态与终止判定,难以直接套用

## 对 Alice 的启示

- **人格演化的"生成-评估-选择"结构**:Alice 演化人格时可以借鉴 ToT 三件套——生成若干演化候选 persona、用固定标准(宪法、诚实度)评估、择优采纳。比"一步生成新 persona"多一层护栏,对抗人格漂移
- **分寸感决策的树形模拟**:主动行为(要不要主动发消息)天然是决策分支;离线模拟"说了这句之后对话可能怎么走"(反事实推演)可以放进成长实验室当主动行为的预检
- **算力预算意识**:ToT 证明了深思的价值也标出了价格——Alice 的日常对话应走单链(便宜档模型),演化/固化等低频高价值环节才值得上树形搜索(多候选+评估)
- **评估器独立性**:ToT 的评估器与生成器同源时偏差会叠加——Alice 演化评估时用不同 prompt 角色(甚至不同模型档)做评估,可降低自我强化
