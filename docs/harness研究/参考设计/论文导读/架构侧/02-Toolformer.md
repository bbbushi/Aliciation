# 论文导读 · Toolformer:模型自学调用工具

> 原文:[Toolformer: Language Models Can Teach Themselves to Use Tools](https://arxiv.org/abs/2302.04761)(Schick et al., 2023,Meta AI)
> 量级:训练侧工具使用的代表作;当时引发了"工具调用应该训练进模型还是写在 prompt 里"的路线之争

## 一句话

不用人工标注,让模型自己学会在文本的什么位置、调用什么 API、把结果插回哪里——筛选标准完全自监督:**调用 API 后,模型预测后文的能力是否变强**。

## 它要解决的问题

GPT-3 时代的模型不会用工具:计算靠心算(错)、日期靠猜、事实靠记忆(幻觉)。已有的注入式方法(如把 API 结果拼进 prompt)需要人工决定何时调用、结果放哪。Toolformer 的问题是:**调用决策本身能否从数据里学出来?**

## 核心机制

三步流水线,全部自动:

1. **采样候选**:用少样本提示让模型在文本各处尝试插入 API 调用(如 `Q: ... weather in ... → weather()`),每个位置采样多个调用
2. **自监督过滤**(全文最优雅的设计):把「调用+返回结果」插入原文后,比较模型在**结果之后的 token** 上的对数似然:
   - 有结果时预测更准(损失下降超过阈值 ε)→ 这个调用"有用",保留
   - 没变好 → 剔除
   - 换句话说:**一个 API 调用值不值得存在,由它对后文预测的信息增益决定**
3. **微调**:用过滤后的自标注数据微调 GPT-J(6.7B),得到 Toolformer

覆盖五类 API:计算器、问答检索、日历、机器翻译、维基检索。

## 关键结果

- 6.7B 的 Toolformer 在知识问答(LAMA 零样本子集)上**超过 GPT-3 davinci(175B)**——工具补上了小模型没有的知识
- 数学任务上追平 GPT-3,而参数量只有其 1/25
- 学会的调用位置符合直觉:问到日期才查日历,而不是每句话都调

## 局限

- 训练侧方案:对 Alice 这种基于 API 的 harness 不可复刻(我们不能微调基座),但其**接口哲学**完全可借用
- 只学了"单点插值"式调用,没有多步工具链(ReAct 式的循环它做不了)
- 过滤标准偏爱"后文可预测性",不等于"对用户有用"

## 对 Alice 的启示

- **「工具描述即接口」**:Toolformer 证明模型靠阅读 API 的自然语言描述就能学会调用——Alice 的记忆工具(recall/remember)给模型的说明文档就是接口本身,写得越清楚、返回格式越规整,模型用得越准(与 SWE-agent 的 ACI 观点互证)
- **信息增益思想可用于提取环节**:哪些对话值得提取成记忆?Toolformer 的筛子是"对预测后文是否有增益"——Alice 的 `extraction.py` 用的是 LLM 判断"值得记",两者可以在设计上互相校准(重要度打分来自 Generative Agents,见 05 导读)
- **少即是多**:五个 API 就够了。Alice 的工具面同样应该克制——陪伴场景的工具生态不需要编码 harness 那么大
