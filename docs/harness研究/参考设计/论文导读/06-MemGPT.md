# 论文导读 · MemGPT:把上下文当操作系统内存管

> 原文:[MemGPT: Towards LLMs as Operating Systems](https://arxiv.org/abs/2310.08560)(Packer et al., 2023,UC Berkeley)
> 量级:上下文管理的标志性论文;**Alice「仓库层只留索引 + recall 按需调取」的直系源头**。作者 Packer 与 Qiao 后来创立 Letta 公司做商业化(文末附后续)

## 一句话

借用操作系统「内存/磁盘分层 + 换页」的隐喻:上下文窗口是内存,窗口外的存储是磁盘,**模型自己通过函数调用把信息在两者之间搬运**——从而突破固定上下文的限制。

## 它要解决的问题

固定上下文窗口的 LLM 有两个死穴:

1. **长文档**:文档比窗口大,关键信息放不进去
2. **多会话对话**:跨会话没有记忆,每次重开都失忆;硬塞历史摘要又会挤压当前对话空间

已有方案(截断、RAG 检索)由**外部代码**决定保留什么;MemGPT 的主张:**让模型自己管理自己的内存**,就像 OS 进程自己决定换页。

## 核心机制

### 分层结构

```
┌─────────────── 上下文窗口内(主上下文 = "内存")───────────────┐
│ 系统指令(常驻,不可变)                                          │
│ 工作上下文(常驻块:自我/用户画像——模型可自我编辑)               │
│ FIFO 消息队列(滚动窗口,满了溢出)                               │
└──────────────────────────────────────────────────────────┘
┌─────────────── 上下文窗口外("磁盘")───────────────┐
│ recall storage:全部历史消息(可检索)                      │
│ archival storage:事实性长期记忆(向量库,可插入/检索)      │
└──────────────────────────────────────────────────────┘
```

### 模型自己换页(函数调用)

模型拥有一组内存管理原语:

- `core_memory_append / core_memory_replace`——把"用户名叫 Tom、在学驾照"写进常驻画像块
- `archival_memory_insert / archival_memory_search`——向长期库写/检索
- `conversation_search`——回搜早期对话

用户说"记住我喜欢爬山",模型**主动发起** `core_memory_append`;上下文将满时,系统注入**溢出中断**(interrupt):暂停、提示"该换页了",模型自己决定把哪些旧消息移出、是否摘要。

### 自我编辑与心跳机制

对话轮末尾附加"心跳"信号,允许模型在回复用户后继续执行内存整理——**内存整理与对话响应解耦**。

## 关键结果

- **长文档问答**:MemGPT(GPT-3.5 底座)在深度记忆类问题上超过固定上下文的 GPT-3.5 和 GPT-4——大窗口不如会管理的小窗口
- **多会话对话(MSC 数据集)**:32 个会话的连续对话中,基线模型随会话数增加记忆准确率线性衰减,MemGPT 保持稳定——**分层自管理的记忆有耐久性**
- 失败模式也诚实:模型偶尔过度调用检索工具导致对话迟滞(与 SWE-agent 的"接口设计决定行为"互证)

## 局限

- 管理开销:每轮多次工具调用,延迟与 token 成本上升
- 依赖模型的自我管理能力——弱模型换页决策很差,会把关键信息换出去
- 评价基准较窄(文档 QA + 合成多会话),真实长期陪伴场景未验证

## 对 Alice 的启示

- **仓库层 = archival storage,Alice 的索引 = MemGPT 的换页表**:2~7 天记忆只留索引(标题)、recall 时调全文——这正是"仓库层只留索引"的显式换页设计;区别是 Alice 的换页策略由 harness 代码规则 + 模型检索双轨完成,比纯自管理更稳
- **工作上下文的自画像块 ≈ persona 注入**:MemGPT 的常驻"自我画像块"由模型自我编辑——Alice 的 persona 由演化流程离线改写,更可控(护栏),但可以借鉴"常驻块"思想:persona 摘要永远钉在上下文头部,防止长对话人格漂移
- **心跳/中断思想 = 固化与对话解耦**:Alice 的提取、固化、演化全部离线批量跑(数据量触发),对应 MemGPT"对话轮结束后整理内存"的设计——**陪伴体验不被记忆整理打断**
- **MSC 衰减曲线是成长实验室的直接参照**:把"第 N 个会话时的记忆准确率"画成曲线,基线衰减 vs Alice 稳定——这就是 Alice 版的耐久性证明图

## 附:Letta 后续跟踪(2024-25)

Packer 与 Qiao 创立 [Letta](https://www.letta.com/)(原 MemGPT 团队),把论文产品化,值得跟踪的三个演化:

1. **Memory blocks**:画像块产品化为结构化分块(如 user block / persona block,可标记只读或自编辑)——验证了"常驻自画像块"路线
2. **Sleep-time compute**:空闲时由后台 agent 离线重组、摘要记忆——与 Alice 的固化/演化流程同构,是"记忆离线整理"的商业形态验证
3. **Agent server**:agent 作为常驻服务、状态持久化、消息驱动——正是 Alice 常驻进程形态的行业化

[GitHub: cpacker/MemGPT](https://github.com/cpacker/MemGPT)(研究代码)与 Letta 产品线并行演进。
