# 论文导读 · Voyager:技能库与终身学习

> 原文:[Voyager: An Open-Ended Embodied Agent with Large Language Models](https://arxiv.org/abs/2305.16291)(Wang et al., 2023,NVIDIA / Caltech / UT Austin / UIUC 等,2023)
> 量级:**Alice 技能库的直系源头**——"从经历提炼可复用技能、按需检索复用"这一机制的出处

## 一句话

在 Minecraft 里永不停止学习的 agent:自动给自己出任务、把学会的本事写成**可执行的代码技能**存进技能库,新任务来了先检索旧技能复用——技能越攒越多,学新东西越来越快(复利式终身学习)。

## 它要解决的问题

此前的 LLM agent(AutoGPT、BabyAGI 一类)在开放世界里要么漫无目的(任务列表靠人工),要么学了就忘(每次从零开始)。Voyager 问:**怎么让 agent 在没有终点的环境里持续变强,并且过去的经验能复用?**

## 核心机制(三件套)

### 1. 自动课程(Automatic Curriculum)

GPT-3.5 根据当前状态(背包物品、附近方块、已会技能、上次失败原因)提出"下一个合适的任务"——难度自动匹配当前能力,像健身计划一样渐进:

> "你现在有一把木镐 → 下一个任务:挖 3 块石头做一个石镐"

没有人为的课程表,**探索欲由模型对自己状态的感知驱动**。

### 2. 技能库(Skill Library)——对 Alice 最重要的部分

每学会一个技能,存的是**可执行代码 + 描述**:

```javascript
// craftItem.js —— 描述:制作指定物品,需要靠近工作台……
async function craftItem(bot, itemName, numItem) { ... }
```

- 技能描述向量化;新任务来时按相似度检索 top-k 旧技能,作为"已有工具"拼进代码生成 prompt
- **检索复用 = 复利**:做"石剑"时检索到"木剑"的代码,只改材料参数——新技能站在旧技能上
- 技能可组合:高级技能(建造房屋)调用低级技能(挖矿、合成)

### 3. 迭代提示(Iterative Prompting)

生成的代码在环境里执行,拿三样东西回来做修正:环境报错(编译/执行错误)、执行轨迹、自我验证(GPT-4 按检查单验证产出物)。循环修到通过,技能才入库——**入库门槛是验证,不是生成**。

## 关键结果

- 获得的**独特物品数约为基线(AutoGPT、ReAct、Reflexion 变体)的 3.3 倍**;科技树进度(从木头到铁器)快 60% 以上
- **技能复用证据**:解锁同一条科技树上后续物品所需的尝试次数显著下降——学得越多学得越快,这是"终身学习"的直接证据
- 消融:去掉技能库,物品获取腰斩;去掉自动课程,任务完成杂乱无章

## 局限

- 技能有环境绑定(Minecraft Bot API);迁移到新环境需要重写
- 代码技能的正确性靠执行验证,对话场景没有这种"跑一遍就知道对不对"的验证器
- 技能库只增不减,坏技能(偶尔通过验证但不可靠)会污染后续组合

## 对 Alice 的启示

- **`skills.py` 的三件套对应**:Alice 技能库 = 描述(供检索)+ 内容(怎么做的知识);提炼入口是"从成功经历中总结可复用的做法";检索时机是遇到相似情境。Voyager 证明了这条链路在 agent 上成立
- **技能 = 记忆 + 人格之外的第三种沉淀**:记忆回答"发生了什么",人格回答"我是谁",技能回答"我学会了怎么做"——三者 schema 必须分清,这也是设计评估里反复强调的边界
- **入库门槛 = 验证**:Voyager 技能入库前必须通过执行验证;Alice 的对话技能无法执行验证,替代方案是成长实验室的探针(提炼出的技能在模拟情境里测试有效才固化)——**没有验证器的技能库会变成偏见库**
- **自动课程 ≈ 成长驱动**:Voyager 根据自身状态给自己出任务;Alice 的"想要"(演化出的偏好)与主动性可以借鉴——不是完成任务清单,而是基于"我现在是什么、还不会什么"生长
- **检索复用对抗重复学习**:用户反复教 Alice 同一件事的记忆碎片,应通过技能提炼收敛为一条可复用知识,而不是每次都从记忆里重新拼——这是固化环节的收敛性指标
