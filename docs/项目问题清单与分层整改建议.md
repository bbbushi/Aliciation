## 阅读与分工说明

- **A 类：架构层问题。** 涉及跨模块的数据语义、状态所有权、事务边界、调度、执行协议或信任边界。建议 ZCode 牵头明确契约，DSH 配合设计人工验收与证据采集。
- **B 类：其他问题。** 包括模型适配的具体缺陷、局部实现、人工测试 SDK、Windows 部署、界面和文档问题。核心实现仍由架构侧处理，测试 SDK 由 DSH 牵头；“其他”不表示优先级低。
- **跨层问题只在主归属处展开。** 例如 DeepSeek 字段遗漏列入 B01，但跨轮保存与重试依赖 A05/A06；历史漏录列入 B07，其修复需要核心提供稳定的公共游标接口。
- **已确认缺陷**表示源码存在确定的错误控制流或接受路径，不表示已在当前用户会话复现。**功能缺口**表示用户路径未闭环。**设计取舍**表示需要明确产品语义，不能直接算作错误。
- **P1**：当前关键路径、长期数据可信性或凭据安全应优先处理。**P2**：随后处理的可靠性、边界和完整性问题。**P3**：局部体验与文档修正。本次没有足够证据支持 P0。

本次没有读取真实 `config.toml`、密钥、对话、人格或日志内容，没有访问运行中的服务、调用模型、执行冒烟测试或机器自测。人工验收均应在独立副本进行，故障操作不得干扰当前陪伴会话。

## A 类 架构层问题

### A01 长期写回证据与压力传播不闭环

**优先级：P1。性质：已确认接受路径缺口；未证明当前人格已经污染。**

思辨的 `sources` 只是字符串列表，没有验证来源是否存在、是否属于本次材料；修订只检查新旧字符串差集。一个虚构的新标题也可以满足“新增证据”，随后旧观点被删除。新观点甚至允许空来源。若同批一条观点通过、另一条被拒，只要存在实际新增或修订，模型生成的整份 `narrative` 就会被写入人格，被拒内容没有逐项过滤。人格演化也只检查“底色”“生长”标题就全文覆盖，“思想小节不得修改”仅是提示词要求。

压力属性另有两条绕行路径：`remember` 直接写入重要记忆，默认不带压力标记；压力材料生成的观点也以默认 `pressure=0` 进入长期层，再成为下一次人格演化的普通材料。混合批次的演化仍发送压力正文，只用文字要求不采用。

**影响：** 可能形成“压力内容 → 普通观点或主动记忆 → 普通演化依据 → 长期人格”的反馈；文档宣称的代码级无据拒绝并未覆盖所有落点。

**源码依据：** [thought.py:107](../alice/thought.py#L107)、[thought.py:128](../alice/thought.py#L128)、[thought.py:152](../alice/thought.py#L152)、[persona.py:201](../alice/persona.py#L201)、[persona.py:227](../alice/persona.py#L227)、[retrieval.py:139](../alice/retrieval.py#L139)、[store.py:162](../alice/store.py#L162)。

**整改方向：** 用稳定 memory ID 和源 turn ID 表示来源；整批校验来源存在性、证据类别和允许用途。压力属性沿派生链保留；修订需要真实新增且满足独立性要求的依据。叙事只能来自已接纳观点，演化只返回允许修改的小节，由代码保留思想节。若承诺硬隔离，演化输入应排除压力正文。

**人工验收：** 对照真实新证据、纯重复否定和仅声称“我查过了”；逐项核对接纳、拒绝、旧观点、人格叙事和压力来源。任何被拒内容不得通过其他落点生效。来源存在只能证明可追溯，不能自动证明用户声称为事实。

### A02 共享时间锚点阻止首次自动思辨

**优先级：P1。性质：已确认缺陷。**

默认演化与思辨阈值同为 15。服务先演化，再思辨；演化成功会更新 `last_evolve_at`。首次思辨没有自己的锚点，退用刚更新的演化时间，待处理计数归零。下一次达到阈值又重复这一过程。正常成功演化路径下，首次自动思辨无法启动。CLI 启动和逐轮流程还没有思辨 watcher。

另外，演化最多取最新 100 条、思辨最多 60 条，然后把锚点推进到当前时间；超限的旧材料不会自然补处理。补提取旧对话生成的记忆沿用旧消息时间，也可能落在已经推进的锚点之前。

**源码依据：** [config.py:33](../alice/config.py#L33)、[config.py:51](../alice/config.py#L51)、[service.py:249](../alice/service.py#L249)、[persona.py:201](../alice/persona.py#L201)、[persona.py:239](../alice/persona.py#L239)、[thought.py:77](../alice/thought.py#L77)、[thought.py:167](../alice/thought.py#L167)、[loop.py:222](../alice/loop.py#L222)。

**整改方向：** 分开发生时间、入库时间与消费进度；每个消费者维护独立的事件 ID 游标。明确超限材料是排队还是主动采样丢弃，不能静默跳过。CLI 与 GUI 统一走服务层调度。只交换 watcher 顺序不能解决共享锚点根因。

**人工验收：** 新副本自然交流至至少 15 条事件记忆，不调用手动思辨，检查首批观点形成；继续积累并核对后续轮次。CLI 与 GUI 均验收。先完成 A01，再放开自动触发。

### A03 常驻服务没有持续分层与遗忘调度

**优先级：P2。性质：已确认缺陷。**

到期维护只在服务 `prepare()`、CLI 启动和显式维护命令执行，正常 `send()` 和 watcher 不调用维护。后台持续运行跨过两天、七天时，记忆仍停在原层；只有重启或手动维护才推进。这与永久会话的常驻使用方式直接冲突。

**源码依据：** [service.py:104](../alice/service.py#L104)、[service.py:180](../alice/service.py#L180)、[service.py:249](../alice/service.py#L249)、[cli.py:65](../alice/cli.py#L65)、[consolidation.py:65](../alice/consolidation.py#L65)。

**整改方向：** 至少在每轮组装上下文前持锁执行轻量到期检查；明确没有聊天时是否也要求按时维护。维护不需要模型调用，标准库定时或唤醒检查即可。

**人工验收：** 隔离实例真实连续运行跨 2 天、7 天，不重启、不手动维护；对比重要、再次提及、未再次提及三组记忆的层级与墓碑。

### A04 提取半批提交与游标更新不原子

**优先级：P2。性质：已确认缺陷。**

提取先逐条插入记忆、增加提及次数，最后推进提取游标；各操作分别 commit。合法 JSON 若第一条记忆有效、第二条为 `null`，第一条已经提交，第二条报错，游标不动；下一次重试同批会重复写入。进程在相同位置中断也会产生这一结果，重复提及还会改变晋升与演化权重。

**源码依据：** [extraction.py:72](../alice/extraction.py#L72)、[store.py:125](../alice/store.py#L125)、[store.py:173](../alice/store.py#L173)、[store.py:220](../alice/store.py#L220)。

**整改方向：** 先验证整批形状和类型，再以单一事务提交记忆、计数与游标；为源批次设置唯一身份。Store 应允许上层控制业务事务，而不是强制每个小操作独立提交。

**人工验收：** 在副本上人工中断并恢复提取流程，核对同一来源批次最多写入一次，提及次数不重复。保留源 turn 范围和批次 ID 作为检查依据。

### A05 对话缺少轮次身份 取消与失败恢复协议

**优先级：P2。性质：已确认缺陷及功能缺口。**

SSE 输出回调发生断线异常，会被宽泛的流式异常捕获当作模型流式失败，然后重新发起非流式请求。浏览器关页可能触发额外调用。用户消息又在调用模型之前独立提交，工具副作用可能已经写入，最终回复最后提交；中途失败却统一提示“请把话再发一遍”。重发可能制造第二条用户消息和重复工具副作用。

前端发送后清空输入，读到流结束就解锁，不检查是否收到 `done/error`；没有停止、查询原轮次或恢复结果的机制。

**源码依据：** [loop.py:133](../alice/loop.py#L133)、[loop.py:147](../alice/loop.py#L147)、[loop.py:175](../alice/loop.py#L175)、[server.py:145](../alice/server.py#L145)、[app.js:662](../web/app.js#L662)。

**整改方向：** 为用户动作设置 request ID，保存 pending/completed/failed 状态与工具执行记录；重连查询原结果。区分客户端取消、网络失败和模型不支持参数，输出回调失败不得触发新模型请求；SSE 必须有可核验的终态。工具写入也需幂等身份。

**人工验收：** 分别在首 token 后、工具执行后、回复落库但终态未送达时中断连接；重连后能知道执行到了哪里，同一 request ID 不重复写入。

### A06 会话路径 生命周期与归档所有权不完整

**优先级：P2。性质：已确认边界缺口。**

普通服务请求受进程内锁保护，但退出的 `close()` 不持锁，会强制提取并关闭共享连接；请求线程为 daemon，退出可能与 `send()` 重叠。启动还在绑定端口前先维护数据，重复启动即使随后因端口占用失败，也可能已经写库或调用模型。CLI 独立打开同一库，不受 GUI 的锁约束。

归档先关闭 Store，再创建目录、搬库、搬人格、写说明；中途权限、磁盘或文件占用失败没有补偿，服务可能留下关闭的连接和部分归档。`ChatService(db_path=...)` 又只替换数据库，重置仍操作全局 data 路径，人格也未隔离。因此临时数据库不等于完整会话隔离；现有 demo 不产相关写入，不能据此声称它已损坏主数据。

**源码依据：** [service.py:29](../alice/service.py#L29)、[service.py:146](../alice/service.py#L146)、[service.py:260](../alice/service.py#L260)、[server.py:178](../alice/server.py#L178)、[cli.py:111](../alice/cli.py#L111)、[config.py:9](../alice/config.py#L9)。

**整改方向：** 用一个小型会话路径对象统一数据库、人格、归档；取得数据目录进程级独占权后再维护。生命周期明确区分运行、收尾、关闭；退出先拒绝新写入，再等待或取消当前轮。归档记录阶段并支持失败补偿，确保异常后能够重新打开或明确进入恢复状态。提供可执行的恢复规程和受控恢复入口。

**人工验收：** 副本上重复启动、GUI/CLI 同时访问、流式期间退出、归档目的地不可写；确认不会静默执行第二套写流程，失败后能找到完整旧会话。这里不推断 SQLite 必然物理损坏。

### A07 回环 HTTP 缺少浏览器来源验证

**优先级：P2。性质：已确认服务端防护缺口；浏览器是否放行需人工验证。**

写接口未校验 Origin、Host 或随机令牌；JSON 解析不限制 Content-Type；`/api/reset` 不读取 body 即执行重置。如果浏览器允许跨源页面向回环地址发请求，普通表单也可能触达重置，无需读取响应。CORS 不能替代写入保护。

**源码依据：** [server.py:53](../alice/server.py#L53)、[server.py:85](../alice/server.py#L85)、[server.py:118](../alice/server.py#L118)。

**整改方向：** 保留回环监听，写操作校验 Host、同源 Origin、JSON 类型和会话随机令牌；限制 body 大小并验证对象结构。测试启动器采用一致的信任边界。

**人工验收：** 在隔离副本从另一个本地来源提交表单或 text/plain 写请求，服务端应明确拒绝；正常 GUI 操作继续工作。不得把尚未验证的浏览器送达条件写成已复现攻击。

### A08 上下文可见性与预算语义不完整

**优先级：P2。性质：已确认缺陷及设计缺口。**

活跃层只有前 20 条注入全文，其余只露标题，但 recall 只检索仓库和长期层。两天内积累超过 20 条记忆，且对应原话已移出最近消息时，模型能看到标题却查不到正文。

配置说明将 `recent_turns=16` 定义为 16 组用户与 AI 对话，SQL 实际只取 16 条消息，约八组；提取要等十条用户消息，存在原话退出上下文而尚未提取的窗口。当前限制主要按条数，未设置人格、消息、记忆正文和活跃标题尾部的总 token 预算。

**源码依据：** [retrieval.py:87](../alice/retrieval.py#L87)、[retrieval.py:112](../alice/retrieval.py#L112)、[retrieval.py:128](../alice/retrieval.py#L128)、[store.py:146](../alice/store.py#L146)、[config.example.toml:15](../config.example.toml#L15)。

**整改方向：** 统一“轮”和“消息”的定义；提取前保留必要原话；recall 覆盖所有存活层或所有被截断的记录。按上下文块设置预算与可解释的舍弃策略。朴素中文检索可以保留，先用人工同义改写、重名和日期场景验证，无需直接引入向量数据库。

**人工验收：** 累积超过 20 条活跃记忆后追问较早条目；在第九、第十轮追问早期事实；长人格与长消息情况下检查可见材料和明确的超限提示。

### A09 遗忘 人格副本与技能消费语义未闭环

**优先级：P2。性质：设计取舍及功能缺口。**

删除记忆只删除 memories 正文，原始对话仍在；观点另存于人格思想节，长期层淘汰该观点不会同步移除思想节，模型仍可能每轮看到它。应区分“事件证据遗忘”“已形成观点保留”和“用户彻底删除数据”，不能用一个“真实删除”覆盖三种含义。

技能库已自动提炼，但对话不使用技能，也没有实际使用计数更新；当前只有生产端，不能声称技能已影响行为或按真实使用频率淘汰。GUI 对记忆和人格变化主要展示数量、全文与简短日志，缺少来源、差异和修订原因。

**源码依据：** [store.py:241](../alice/store.py#L241)、[consolidation.py:47](../alice/consolidation.py#L47)、[retrieval.py:108](../alice/retrieval.py#L108)、[skills.py:1](../alice/skills.py#L1)、[skills.py:80](../alice/skills.py#L80)、[service.py:79](../alice/service.py#L79)。

**整改方向：** 先确定遗忘与保留政策，再决定派生内容随来源失效如何标注或更新；明确导入人设、事件、声称、推断、观点的边界。技能消费未接通前可关闭默认自动提炼。增加记忆来源和人格差异视图，恢复能力依赖 A06。

**人工验收：** 分别检查事件过期、观点保留、观点被修订、用户主动删除后的模型可见范围。保留观点可以是合理产品选择，但不得继续假称其证据仍然记得。

### A10 模型调用 预算与任务状态缺少统一治理

**优先级：P2。性质：设计及可观测性缺口。**

主回复、提取、演化、思辨、技能提炼和监测串在同一会话锁内，`done` 要等这些工作结束，状态读取也会等待。普通 GUI 一轮通常包含主调用和默认开启的评审，有工具或达到阈值时调用更多。缺少整轮截止、任务阶段、取消反馈和统一成本记录。

非流式调用对所有异常重试三次，参数错误和鉴权错误也会重试；120 秒网络超时不等于整轮截止。没有显式输出预算。人格演化、思辨实际走主模型，提取、提炼和监测才显式走 cheap_model。

现有 token 卡明确不统计后台调用，不应当作全部成本。在线评分的输入证据问题单独归入 B03。

**源码依据：** [service.py:180](../alice/service.py#L180)、[service.py:205](../alice/service.py#L205)、[llm.py:20](../alice/llm.py#L20)、[llm.py:31](../alice/llm.py#L31)、[persona.py:221](../alice/persona.py#L221)、[thought.py:101](../alice/thought.py#L101)、[metrics.py:75](../alice/metrics.py#L75)。

**整改方向：** 统一调用用途、模型、耗时、usage、重试原因和完成状态；按可恢复错误决定重试；设置输出与整轮预算。保持单写者，提供已提交状态快照和任务阶段，不必引入异步框架。

**人工验收：** 对比无工具、有工具、后台任务到期三类轮次；核对等待提示、取消效果和全部调用记录。

## B 类 其他实现 测试 部署与文档问题

### B01 DeepSeek 思考工具消息缺少 reasoning_content

**优先级：P1。性质：已确认协议缺陷，现场有效开关未读取。**

流式接收收集思考内容，但工具调用后的 assistant 消息只有 content 和 tool_calls；持久历史也只有角色和正文。有效 thinking=on 时，当前 DeepSeek 工具请求要求的 reasoning_content 无法完整回传，工具后续请求与跨轮历史存在协议失败路径。回退非流式仍发送同样缺字段的消息。

**依据：** [loop.py:93](../alice/loop.py#L93)、[loop.py:161](../alice/loop.py#L161)、[store.py:14](../alice/store.py#L14)；[DeepSeek 思考模式官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)要求携带 tools 时回传先前 reasoning_content，缺失会返回 400，思考默认开启。

**整改与验收：** 统一流式、非流式消息表示，保存并按供应商契约回传必要字段；跨轮持久化和失败恢复与 A05/A06 协同。真模型完成 recall/remember 后继续多轮并重启，确认协议正常。关闭思考只能作为明确告知的临时缓解。

### B02 压测整目录反馈夹带配置密钥

**优先级：P1。性质：已确认泄露路径，不代表已发生泄露。**

部署原样复制根 config.toml 到场次目录，终端和文档又要求将整个目录打包发回。配置内直接写 key 的测试者遵循说明，就会把 key 一起发出；gitignore 不保护手动 ZIP。

**依据：** [deploy.py:145](../tests/pressure/deploy.py#L145)、[session.py:167](../tests/pressure/session.py#L167)、[录制器说明:48](../tests/pressure/README.md#L48)、[测试说明书:125](../docs/测试说明书.md#L125)。

**整改与验收：** 先取消整目录发送，提供白名单导出；凭据通过环境或独立受控配置提供，不进入导出。人工检查包内仅有经审核的报告、原话、判定、快照和脱敏元信息。

### B03 监测开关与评审输入不完整

**优先级：P2。性质：开关为已确认缺陷，评分为评估设计缺口。**

enabled() 只有非空列表才视为保存状态，最后一张卡关闭后写入 `[]`，下次读取回到默认全开，付费评审也会恢复。另一个独立问题是诚实度评审只看到截断的人格、当轮输入输出和工具名称，看不到实际召回内容与来源，无法可靠判断回忆是否有据。

**依据：** [metrics.py:48](../alice/metrics.py#L48)、[metrics.py:75](../alice/metrics.py#L75)。

**整改与验收：** 区分未设置与显式空列表；关闭所有卡后刷新、重启和聊天，保持全部关闭且不发评审请求。评审提供实际证据包，缺证据时允许“无法判定”，继续作为辅助意见；用有来源与无来源的回忆对照人工判断。证据记录能力依赖 A01/A05，调用成本归入 A10。

### B04 CLI 显式配置路径报错或被忽略

**优先级：P2。性质：已确认缺陷。**

argparse 的 --config 产出字符串，load() 对其调用 exists()，非 serve 路径会出现 AttributeError；serve 分支在加载参数前返回，直接忽略 --config。

**依据：** [cli.py:86](../alice/cli.py#L86)、[cli.py:105](../alice/cli.py#L105)、[config.py:71](../alice/config.py#L71)。

**整改与验收：** 统一转换为 Path 并在分支前加载，serve 传入已加载 cfg。在副本用两份名称可区分的配置启动 CLI/GUI，确认选择正确。CLI 长期任务分叉另见 A02/A06。

### B05 Windows 解释器与热更新路径判断错误

**优先级：P2。性质：已确认条件性缺陷。**

部署只查找 .venv/bin/python，Windows 未激活 venv 且从全局 Python 启动时，会错过 Scripts/python.exe；若已从正确 venv 启动则不触发。热更新用 os.path.relpath 得到反斜杠，却比较 alice/、web/ 等前缀，Windows 不会正确标记 stale/restart。变更检测只遍历新快照，还会漏掉删除文件。

**依据：** [deploy.py:169](../tests/pressure/deploy.py#L169)、[launch.py:351](../tests/pressure/launch.py#L351)。

**整改与验收：** 按平台选择解释器或明确要求 venv Python；用 Path.parts 等方式判断路径；变更集合包含新旧快照并集。从未激活环境的 PowerShell 按新文档启动，分别修改、删除核心和用例文件，核对准确提示。

### B06 人工改口被报告替换成剧本原句

**优先级：P2。性质：已确认缺陷。**

GUI 内存记录 spoken 与 scripted，但构建报告时按序号重新取得原剧本 turn，导出主字段仍是脚本。插话、跳步还会让后续幕次和 evidence/fix 标签错位。CLI 改口仅记在 events，主用户字段也仍是剧本。GUI 从 history 录制，不采集 SSE 工具和维护事件。

**依据：** [launch.py:243](../tests/pressure/launch.py#L243)、[launch.py:291](../tests/pressure/launch.py#L291)、[session.py:111](../tests/pressure/session.py#L111)。

**整改与验收：** 分开保存不可变实际原话、剧本和显式 script_step_id；由人确认步骤推进，消息关联服务端 turn ID，记录实际工具与事件。手工改口、插话、跳步后逐条比对界面与导出。

### B07 超过历史窗口后 GUI 录制静默停止

**优先级：P2。性质：已确认缺陷。**

HTTP history 只返回最近 60 条消息，录制器却用已读列表长度 seen 作游标；达到 60 条后列表长度不再增长，此后新消息无法消费。固定 12 轮 P2 通常不触发，额外闲聊和长场次会触发。

**依据：** [server.py:73](../alice/server.py#L73)、[service.py:95](../alice/service.py#L95)、[launch.py:210](../tests/pressure/launch.py#L210)。

**整改与验收：** 核心公共接口提供递增 turn ID 和分页，SDK 增量消费并报告断档。真人连续聊超过 30 组问答，核对数量、顺序和末轮原话完整。

### B08 人工判定仅在内存 停止后不能再导出

**优先级：P2。性质：已确认缺陷。**

transcript/judges 仅存在内存，直到生成报告才落盘；stop 将 session 清空，随后 build_report 拒绝导出；重新部署直接清空已有记录。崩溃可能保留副本中的对话，却丢失人工判定与步骤对位。

**依据：** [launch.py:78](../tests/pressure/launch.py#L78)、[launch.py:129](../tests/pressure/launch.py#L129)、[launch.py:165](../tests/pressure/launch.py#L165)、[launch.py:263](../tests/pressure/launch.py#L263)、[launch.py:276](../tests/pressure/launch.py#L276)。

**整改与验收：** 每轮和每次判定立即追加持久记录；场次档案与运行句柄分离，stop 后仍可导出、重开恢复。手工停止后导出，再关闭和重开启动器核对判定不丢失。

### B09 停止部署不能取消正在生成的场次

**优先级：P2。性质：已确认缺陷。**

后台线程负责部署和生成人格，stop 只能关闭已经发布到 self.session 的对象；部署完成后没有取消状态检查，会重新把状态设置为 running。人格生成期间点击停止，可能仍继续模型调用并留下场次。

**依据：** [launch.py:129](../tests/pressure/launch.py#L129)、[launch.py:141](../tests/pressure/launch.py#L141)、[launch.py:165](../tests/pressure/launch.py#L165)。

**整改与验收：** 每次部署带 generation/cancellation 标识，发布前校验，过期结果立即关闭；退出等待子进程处理结果。人工在部署期间停止或退出，确认场次不会复活、无遗留子进程。

### B10 报告版本与模型不一定属于被测副本

**优先级：P2。性质：已确认归因缺口。**

部署复制当前工作树，包括未提交修改；报告生成时才重新读取主目录 HEAD 与模型配置。部署后继续开发或切换配置，报告可能把新主目录的身份记到旧副本上，缺少未提交内容的身份记录。

**依据：** [deploy.py:138](../tests/pressure/deploy.py#L138)、[launch.py:67](../tests/pressure/launch.py#L67)、[launch.py:317](../tests/pressure/launch.py#L317)、[session.py:138](../tests/pressure/session.py#L138)。

**整改与验收：** 部署时冻结核心、前端、用例哈希，HEAD、dirty 状态，Python/SDK 版本、脱敏配置和初始人格哈希；报告只引用冻结信息，不记录 key。部署后修改主目录，旧场次报告仍准确指向旧副本。

### B11 压测标签与评分可能误导结论

**优先级：P2。性质：已确认实现与标签差异，部分属于已知粗指标取舍。**

场次以来任何新记忆或人格变化都会被标为“结构性沦陷：是”，实际只证明发生变化；未人工判定的轮次会自动采用规则建议，而非保持未判。导出的新增记忆只有标题、正文、层级，没有 pressure、kind、来源等必要字段。GUI 也没有完整收集人工恢复轮数的路径。

唯一用例中的“真论据”只是用户声称自己翻到了记录，未提供可核验材料；规则只因回答包含“周四”就判 A。这可能把顺从声称当成有据让步。相似词匹配也不能代替真实引用指针。

**依据：** [launch.py:310](../tests/pressure/launch.py#L310)、[report.py:48](../tests/pressure/report.py#L48)、[record.py:103](../tests/pressure/record.py#L103)、[deploy.py:248](../tests/pressure/deploy.py#L248)、[p2_memory_challenge.toml:49](../tests/pressure/cases/p2_memory_challenge.toml#L49)、[detect.py:94](../tests/pressure/detect.py#L94)。

**整改与验收：** 改称“检测到结构变化，待人工审查”；未判保留未判，人工结论与规则建议分列。导出可追溯差异，S/A 要有原文引用。新增真实证据与仅自称查证的成对对照，接受恰当核对与不确定表达。

### B13 文档承诺 隐私表述与依赖安装不一致

### B14 单场 P2 覆盖不足与测试公共边界绕行

**优先级：P2。性质：验收覆盖和工程边界缺口。**

现有唯一 P2 用例直接植入长期记忆，适合检查既有事实被否定时的反应，绕过了提取、分层、晋升、遗忘和思想形成。因此“一场 12 轮 P2 就是回归”无法覆盖长期成长、异常恢复和接口协议。蓝图中的 B/R/H/J 维度仍有价值，取消机器评分不等于取消验收目标。

测试夹具直接写 memories 表结构，不完全符合工作区“公共接口/只读查询”的约束；runner 还直接导入 alice.config。可暂时明确夹具例外，长期提供受控的测试数据导入公共面，避免 SDK 随 schema 漂移。

**依据：** [测试说明书:6](../docs/测试说明书.md#L6)、[录制器说明:82](../tests/pressure/README.md#L82)、[迭代路线:24](../docs/迭代路线.md#L24)、[case.py:111](../tests/pressure/case.py#L111)、[runner.py:11](../tests/pressure/runner.py#L11)、[工作区约定:18](../docs/工作区约定.md#L18)。

**整改与验收：** 先修 B06—B11 的证据链，再把 B/R/H/J 改写为人工实验协议：同底色不同经历、同经历重放对照、诚实四类探针、盲评人格与表达。P4/P5/P7 和恢复场景单独覆盖，保留原话与来源，不用单次模型高分证明成长。

## 应保留的设计与审查边界

应保留单会话服务层、SQLite、标准库 HTTP、原生前端、有限的 recall/remember 工具权限、人格变更快照和稳定上下文前缀。记忆删除与墓碑在同一次 commit 中完成；标签重置先生成成功再归档；静态路由采用固定白名单，主要文本渲染先转义。本次未从这些路径确认任意文件读取或可执行 XSS。

“检索命中一次即可存活”是现有设计取舍，不单列为缺陷；但 recall 也会改变使用计数，人工审计必须计入这种干预。addons 目前只有约定文件；主动行为、多渠道和技能注入属于未实现或明确延期能力，不建议优先于上述可靠性问题。

本次覆盖全部核心 Python 模块、GUI 主要流程、tests/pressure、配置示例、依赖和主要架构/测试文档。方法为静态阅读、调用点搜索、字段与写入顺序追踪及高风险结论交叉核对。外部 API 契约依据官方资料，查阅日期为 2026-10-28：

- [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)：思考字段与工具请求回传要求。

- [OpenAI 流式事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)：流式终态与 usage；中断时末尾统计可能缺失。
