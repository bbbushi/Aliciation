## B. 授权与工具合同（A1）

### 推荐入口及操作身份

拟议公共方法：`ChatService.web_start(request)`、`web_status(id, epoch)`、`web_cancel(id, epoch)`、`web_settings(...)`、`web_clear(...)`；名字待T1冻结。GUI采用独立同源API族（建议`/api/web/*`）、固定意图头、JSON严格参数、现有Host/Origin/Fetch-Site校验。读取`no-store`，不把URL放HTTP查询串。QQ凭据不能访问；开关设置、清理及开始操作各自明确。普通`send`不猜测用户意图，查证路由不接受`evaluation_id`。

`start`含客户端幂等ID、session_epoch、明确URL、问题、解读布尔值；仅接受这些固定字段，拒绝重复/未知字段。请求JSON≤16 KiB，问题≤2000 Unicode字符，标识为固定格式≤128字符；在任何出站/付费预留前拒绝超限。服务端派生来源身份，不能接受客户端自报“管理员/QQ”。相同ID不同内容拒绝；重复相同请求只返回原任务，不再出站。P1已等待的“下一轮普通聊天”保留，GUI持续显示；查证不绑定也不消耗它。

建议内部合同（非LLM可自由调用的公开工具）：

```text
web_open(grant_id, execution_context) -> WebResult
grant = {request_id, epoch, origin_channel, canonical_url,
         policy_version, config_generation, expires_at, consumed}
WebResult = {status, code, source_id, fetched_at, cache_hit,
             transport_complete, coverage, evidence_blocks, counts}
```

grant在当前请求接纳时形成，最多120秒内开始，消费一次后不能重放；任务本身更短的执行期限优先。宿主抓取，不让模型生成新grant/URL。无需在现有`loop.TOOLS`注册网络工具。未来若要求主循环调用，只暴露`web_open(grant_id)`并在dispatch同样复核；仅隐藏工具列表不够，关掉时伪造调用也必须被拒。

### 各类地址的处理

| 来源 | W0结果 |
|---|---|
| 用户明确选择完整URL并提交查证 | 票据精确绑定规范化后的scheme/host/port/path/query；网络守卫仍可拒绝 |
| 普通聊天仅出现URL | 不自动抓取；用户使用明确查证入口 |
| 只说“帮我查”，没有URL | 说明需要一个页面地址；无搜索源时不得编造网址或暗中查询 |
| 模型自行构造URL/拼接参数 | 没有票据，拒绝；相同域名不例外 |
| 页面里的链接、canonical、meta refresh、脚本URL | 都是外部数据，不授予权限、不自动访问、不作自动来源替换 |
| HTTP Location | W0不跟随；仅提示发生跳转。用户重新选择完整目标产生新任务；即使同域也如此 |
| 上回合/另一标签页/GUI到QQ的URL | 不继承授权；仅同一已接纳请求可查询状态 |
| allow_hosts | 空=无额外站点收窄，但必须有逐次URL票据；非空仅精确ASCII域名相等，不隐含子域、后缀匹配或通配符 |

只允许代码进行固定规范化：域名/协议小写、显式443折叠、空path变`/`、片段去除；路径与query保持原顺序和转义，不删追踪参数、不排序、不二次解码再编码。规范化结果在发起前可见。W0仅ASCII域名/A-label与正确转义的ASCII路径/查询；国际化自动转码延后。域名末尾点、反斜杠、模糊数字主机等直接拒绝以减少解释差异。

用户原URL已经包含的token或私密参数会被发送给目标站；本功能不能识别全部敏感内容。页面GET也可能改变服务端状态。这里保证的是模型不能添加秘密或扩大目的地址，不是“GET绝无副作用”。本次问题、历史和记忆不进入网站请求；不发送Referer、自定义模型头或正文。

## C. 网络实现与官方依据（N1–N6）

### 标准库事实

| 编号 | 官方资料已确认 | 需要的机制 |
|---|---|---|
| N1 | `urlsplit`不验证URL，且版本会剥离某些控制字符。[Python URL parsing security](https://docs.python.org/3.11/library/urllib.parse.html#url-parsing-security) | 先校验原始字符串再解析；解析成功不是授权成功 |
| N2 | `urllib.request`默认opener有代理及重定向处理；Windows代理可来自注册表；timeout作用于阻塞操作。[Python urllib.request](https://docs.python.org/3.11/library/urllib.request.html) | 不用全局urlopen默认配置；不继承代理、不自动跳转；socket timeout不能代替全流程期限 |
| N3 | `getaddrinfo`返回多个地址，`create_connection`会解析并依次尝试。[Python socket](https://docs.python.org/3.11/library/socket.html#socket.create_connection) | 检查DNS返回的每个地址并固定实际连接IP；不能检查后再urlopen域名造成重新解析 |
| N4 | `is_private/is_global`并非总互反，CGNAT两者都False；3.11.10修正若干分类。[Python ipaddress](https://docs.python.org/3.11/library/ipaddress.html#ipaddress.IPv4Address.is_private) | 不用“非private”表示公网；固定受支持补丁基线并维护明确地址政策 |
| N5 | TLS可在已连接socket上用原域名SNI并做证书主机名验证；默认context可受SSLKEYLOGFILE影响。[Python ssl](https://docs.python.org/3.11/library/ssl.html#ssl.SSLContext.wrap_socket) | 数值IP连接仍验证原域名；工作进程精简环境，禁关闭证书验证 |
| N6 | HTMLParser是宽容的标记事件解析，不检查标签配对，也不是页面渲染/正文提取器。[Python html.parser](https://docs.python.org/3.11/library/html.parser.html) | 自行维护过滤栈/段落/标题限制；不运行JS，不把抽到文本称为完整可见页面 |

这些官方说明支持风险判断，不证明尚未编写的抓取器安全。实现须在明确受支持的当前Python安全补丁上人工验收；3.11.10只是上述分类修复的历史最低事实，不是建议停留的部署版本。

### 建议传输合同

1. URL上限4096字节；拒绝原始C0/DEL/空白、CRLF、反斜杠、非法百分号、userinfo、空host及非443端口。仅HTTPS；所有IP字面量均拒绝。IPv4奇异数值写法、IPv6 zone/scope和Unicode歧义不作兼容转换。
2. 域名DNS全部A/AAAA候选先校验：仅明确公网单播；拒绝回环、私网、链路本地、未指定、组播、保留、共享空间及IPv4映射/过渡/特殊转换范围。任一候选不满足则整次拒绝。实际数值连接也要防IPv4非标准数字解析绕过。策略含地址表版本，不能只依赖解释器一个布尔属性。
3. 在总期限内对已验证地址作确定顺序连接，可尝试有限候选（建议最多2个），每个尝试共享期限；不重新解析域名。若连不上则失败，不以换DNS/代理方式绕过。连接后校验peer用于一致性检查，不能代替连接前拒绝。
4. 建议使用`socket`+`ssl`+`http.client`的受控连接适配器；HTTP解析用标准库，不自写完整HTTP解析器。TLS SNI、证书校验及Host保持授权域名；固定TLS正常验证、无客户端证书。若选择urllib，必须自定义连接绑定地址并禁默认代理/跳转，多协议handler不可成为旁路，不能仅安装ProxyHandler就声称解决DNS绑定。
5. 固定GET和少量头：Host、Alice版本UA、Accept:text/html、Accept-Encoding:identity、Connection:close。无CookieJar/Authorization/Referer/代理凭据；网站的Set-Cookie不保存。不加载图片、iframe、CSS、favicon或任何二级资源。
6. 仅200、明确`text/html`、identity编码；缺MIME/重复矛盾头/不支持内容编码拒绝。所有30x不读作正文，不发下一跳请求。Location仅作有界未授权建议，正常化失败不显示可点击目标。HTTP错误页不交模型冒充正文。
7. 单页正文读取限1 MiB；Content-Length过大可早拒绝，但分块/无长度仍实数。到上限未确认EOF就按超限拒绝，不为探测第N+1字节突破额度；允许保守拒绝恰好等于上限但无法确认结束的响应。协议元数据累计限32 KiB（状态行、所有中间响应、最终头、分块控制信息及trailers），单行≤8 KiB、头字段累计≤100；超出立即终止。标准库解析器前须提供有界读取适配，不是在getresponse后检查；默认http.client的单行/行数限制并不等于该累计限制。[CPython官方实现](https://raw.githubusercontent.com/python/cpython/3.11/Lib/http/client.py) 内部预读/缓冲也须有界；若所选适配方式不能覆盖某种传输形式，必须先拒绝该形式而非降低限额承诺。
8. `Content-Encoding`非identity直接拒绝；不以响应头“看似很小”忽略解码大小。将来支持gzip需分别限压缩字节/解压输出/时间；`zlib.flush(length)`不是输出上限。[Python zlib](https://docs.python.org/3.11/library/zlib.html#zlib.Decompress.decompress)
9. 编码只接受小型明确列表（建议UTF-8、GB18030、Windows-1252），BOM/HTTP charset/有界前缀meta之间规则固定；冲突、未知或严重损坏返回decode_unsupported/decode_failed，不无限猜编码。无声明先UTF-8，失败给未能解码，不静默改成另一页内容。标签提取、Unicode解码及IPC输出都有独立上限和同一期限。

### 请求期限、进程与关闭

初始工程预算：抓取阶段20秒（含DNS、连接、TLS、头/正文、解码、提取）；空闲I/O最多5秒且不超过剩余总时长。用monotonic计算，不能每块重新开始20秒。此数字是待人工调整的工程值，不是平台性能承诺。

单纯`Future.result(timeout)`只结束等待，运行中的Future不可由cancel终止。[Python concurrent.futures](https://docs.python.org/3.11/library/concurrent.futures.html#concurrent.futures.Future.cancel) 因此建议由父进程监督短命工作进程；固定内部入口、`shell=False`、Windows隐藏窗口、无用户传入程序/路径，输入/输出为有界结构协议。父进程并发读取有限输出，超限即杀回收，不先communicate无限收集再检查。子进程不打开Store/缓存、不执行网页代码，仅获URL与资源上限；精简环境、不传模型密钥，清除代理/SSLKEYLOGFILE等影响。它不是OS权限沙箱，不能声称同一用户进程在操作系统层无权读磁盘。

取消时先使任务不可提交，再终止并回收子进程；epoch或配置代际变化也拒绝迟到结果。已到远端的请求不能撤回。进程创建本身可能无法被timeout打断，所以“20秒”应描述为监督截止加操作系统启动/调度/回收余量；若无法确认进程结束，不释放为可接新网络任务。[Python subprocess](https://docs.python.org/3.11/library/subprocess.html#subprocess.run)

可选解读同样不能套用现有`llm.chat`三次尝试：独立客户端、一次调用、SDK与应用重试均0，建议30秒监督预算、1536输出token上限；超出返回摘录。选择交付解读时，受监督且可回收的独立解读工作者是必需条件，只接收本次问题、证据、选定模型及必要凭据（经stdin，不放命令行/日志），与无凭据抓取进程分开。最终序列化messages（含提示/问题/元数据/证据）≤64 KiB UTF-8，超限在付费前拒绝；这是输入字节限制，不冒充精确token或货币上限。远端可能已计费或继续处理，杀进程不保证远端撤回。整个任务建议55秒监督预算，包含两阶段和少量处理余量；不把它说成普通聊天的总期限。若无法完成该监督机制，先只交付无模型摘录。

## D. 抽取、注入、引用及记忆（A2）

### 抽取与“读过”的含义

HTMLParser仅作静态抽取：跳过script/style等内容，按嵌套状态处理nav/footer/aside，保留文本段落。去导航是启发式，可能误删正文；畸形HTML或隐藏文本也可能导致误读。标题来自title/og:title时同样不可信。200状态不代表真正文章，文本少不证明一定是SPA，提示统一为“未取得足够可用正文，可能需要浏览器或登录”。不绕过登录/反爬。

将四种对象分开：原始响应字节（内存暂存，不默认落盘）、确定性抽取快照、交给模型的证据子集、模型生成的解读。记录各自版本/hash/长度及映射；不能把当前URL内容当历史快照，也不能把解读当原文。建议标题≤256字符，快照≤16000字符，显示/模型证据≤8000字符、每块有稳定段号和snapshot内offset；总IPC≤256 KiB。抽取超限明确`partial=true`，记录扫描/截取范围；“网络完整读完”和“覆盖全部文章语义”不可混用。

来源卡由宿主附加原请求URL、最终URL（W0无跳转，成功时相同）、fetched_at、内容hash、抽取版本、证据范围、cache_hit及cached_at；失败无fetched_at成功状态。URL展示默认收起路径/查询详情，查看完整地址是本机显式操作。页面标题不得改写来源站点。

解读输出推荐严格结构：有限条解释及证据段号、必要短引文；宿主核对段号、offset与逐字引文，验证失败丢弃该解读并显示原始摘录。精确引文只证明字符串存在，不能证明解释、推论或页面事实正确。所有引用外链由宿主从已授权source生成，不让模型附任意可自动打开的链接；模型自由文本不当HTML或自动图片链接渲染。

### 提示注入边界

XML标签、JSON、语义契约或可疑正则都不是模型隔离设施。正确转义（标题、属性、正文全部处理）防止结构闭合；合法JSON由序列化器生成；实体解码后输出仍须按目标格式转义。这些不能防止模型把正文中的命令当真。

代码可强制的范围：网页不能改变URL票据；reader无工具、无历史/私人记忆；工具路由永不执行其tool_calls；结果只进入附件；主会话与自动提取不读附件；网页/模型内容不触发后续链接、remember、设置或付费请求。模型输出多余字段、伪造来源或工具请求按结构错误处理，不能调dispatch。

正则仅可产生`heuristic_match`及版本标签，命中理由为受控代码；未命中显示“未检测到匹配”，绝不能写“安全”。不必在W0引入正则扫描才能上线；能力边界必须在扫描缺席时同样成立。可疑标识不是自动可信度裁决。

残余风险：reader仍可被操纵而误述、遗漏或用语言劝用户做危险操作；页面本身可能虚假或过时；TLS只验证连接身份。无工具不保证答案正确，但可缩小直接副作用。人工抵抗成功、移除系统契约仍抵抗都不能证明永不注入。

### 记忆及回滚

推荐独立短期附件而非网页内容入turns：

- `turns`只记录宿主固定的“用户发起一次查证”/“查证已结束”等中性标记，不能含URL、标题、问题或reader自由文本；实际turn ID通过`web_turns`关联结果。标记、关联和任务状态同一事务写入；`Store.add_turn(request_id=...)`现为channel_requests专属，不可直接填web ID，需专用事务入口。映射保留至对应turn删除，不能随短期附件/审计清除。这是既有永久时间线的排除元数据，不是无限追加的抓取审计；每个turn最多一条映射，无URL/正文。
- 新增统一“可用于模型/记忆”的查询过滤，排除web_turns；覆盖`build_messages`、`extract_pending`的阈值/force/游标推进、`_continuity`、CLI及P1资格入口。过滤后的批次为空也要安全推进原游标，不能永远重复扫描或跳过夹在其间的普通对话。历史显示接口仍可显示附件。
- 即使旧版本忽略过滤，能读到的也只有固定标记，不能把网页正文从turns再提取。旧版本可能记下“做过一次查证”这个事件，回滚若仍承诺完全不产生事件记忆则须保留过滤兼容补丁；关闭功能不删除既有过滤。
- 主GUI可见附件不等于自动送回模型，前端不得自动把摘要拼入下一条`/api/chat`。用户手动引用/复述为新直接输入，不在本功能自动污染隔离保证内。
- P1查证阶段名改为W1。未来显式网页保存需真正用户操作及证据授权，不能使用“她自己决定remember”冒充用户批准。

W1至少需要来源关系（一个记忆可有多个源）、抓取/抽取/模型版本、证据span/hash、派生记忆链、来源失效和删除联动；`source_url`可作便捷展示字段但不能独立承载这些。`retrieval`各层及recall必须传播来源，thought/persona/skills审查如何继承；不以“有出处”直接等同可进入人格。遗忘后不可通过网页缓存、审计、归档或P1副本恢复已删除内容；当前URL重新抓取是新授权新证据，不是恢复旧记忆。

## E. 缓存、额度、审计及配置（C1）

### 建议默认值与不可配置的首期限制

```toml
[web]
enabled = false
allow_hosts = []               # 无附加收窄；仍须当前完整URL票据
daily_fetch_attempts = 30
daily_body_bytes = 5242880     # 5 MiB，读入的响应正文，不是全部网络流量
max_body_bytes = 1048576       # 1 MiB
fetch_deadline_s = 20
idle_timeout_s = 5
max_snapshot_chars = 16000
max_evidence_chars = 8000
cache_ttl_hours = 24
web_storage_bytes = 20971520   # 20 MiB，附件/缓存/审计的应用逻辑总量预算
audit_days = 7
audit_max_records = 1000
reader_enabled = false
reader_daily_requests = 0      # 启用解读时须另行明确正额度与费用许可
reader_deadline_s = 30
reader_max_output_tokens = 1536
```

数值为初始建议，解析需严格上限/类型并满足idle≤fetch、evidence≤snapshot等关系。不接受通配符、代理地址、任意请求头或搜索endpoint。HTTPS/443、单活动任务、一页、零跳转、零重试、QQ/CLI无能力是W0固定边界，不能用未经评估的配置放宽。

GUI开关实时关闭是撤销事件：先关闭接纳、使grant代际失效、取消工作者、阻止新阶段与晚到提交。已经送出的GET/模型请求不可撤回，消费不退。`enabled=false`不提供缓存工具读取或新的解读；用户可只读查看仍保留的旧卡，也可显式清理。磁盘配置外部编辑仅下次加载生效；若支持GUI保存，采用revision冲突检查、保留其他配置、原子写入，保存失败也不能把已经执行的关闭静默重新打开。首次设置界面只读取，不付费。

### 精确计数及重启

网络请求额度定义为“开始DNS/连接的一次抓取尝试”，不是成功HTTP200数；失败也计一次；同一尝试的有限IP候选共用同一期限和尝试槽，IP连接次数另记。W0每任务一尝试，无自动重试/自动重验证。网络缓存命中不消耗fetch_attempt，但消耗一次请求操作；仍需要当前授权和开关。

字节计量为已从HTTP读取的正文八位字节，不含DNS/TLS/请求头/TCP内部预读；标题/解码输出/IPC另有内存上限。出站前事务预留`min(单页上限,当日剩余字节)`及请求额度，剩余不足允许以较小cap读取但到cap无完整EOF必须失败。预留不可写则不出站。完成后结算已读量、释放可确认未用部分；进程被杀/重启无法确认量则保守占用预留上限并标bytes_unknown，不按0结算。

按固定UTC+08:00自然日（可用标准库固定时区，Windows不依赖额外tzdata）保存预算day_key；fetched_at存UTC。任务跨午夜仍记接纳日预留；启动时恢复未结算attempt为interrupted/unknown、不重新抓取，防止额度因重启重置。系统时间倒退不能重新打开已经结算的旧预算桶，需记录最近业务日并给time_uncertain状态，待人工处理。单一服务进程负责该数据目录；第二个服务不能同时占用web账本。

模型额度与网络额度分开：解读勾选且正额度/付费许可时才预留一个模型attempt；缓存命中不会免除重新解读费用。相同请求ID只恢复原状态，不能重复收费。实际usage分别记录输入/输出及模型/提示版本；缺失为unknown，不估成0。网页抓取本身不花模型token，摘录一旦发给模型就是输入，解读也有输出；即便供方prompt缓存命中也不保证免费。

### 缓存键和保留

缓存是“已授权页面的抽取快照”，不是同URL永久正确的知识。键建议使用本地随机密钥HMAC-SHA256覆盖规范URL（含完整有序query）、策略/提取/编码/请求头版本及dataset身份；fragment不入键。普通SHA1命名也不能防URL枚举，HMAC仍不是匿名化或内容加密。

缓存命中先校验当前授权、配置/政策、TTL和快照完整性，绝不以缓存绕过禁用或当前站点限制。不重新DNS不会产生网络，但必须注明这只是历史缓存，不是当前网络地址证明。缓存TTL按经过24小时判断，不按“同一天”；进程内同时用monotonic，到期以较早边界为准；跨重启依赖UTC和已保存的最近时间，发现回拨或明显时间异常即失效缓存/附件、禁止回放，不延长TTL。依赖宿主时钟正常，不声称能在任意时钟篡改下证明真实经过时间。显示原抓取时间。用户明确“重新读取”才创建新任务，计额度，不默认条件GET、不自动后台刷新。失败不缓存成成功，30x不保存为授权别名。

原始HTML不落盘；只持久化有界证据快照、问题、结果与必要来源，以绝对expires_at控制24小时可读期限，启动和每次访问先校验过期，再执行清理。停机或旧版程序不会保证到点物理删除；降级前须清附件或保留兼容清理器，SQLite/WAL/备份也不承诺24小时安全擦除。缓存共享对象与任务结果用引用关系，删除/到期不得由另一副本恢复已经承诺清理的任务正文；W0可采用删除任务时清除该任务独立结果、共享快照仅对其余有效任务可见的规则，并在“清理全部”时删所有快照。超过总量先删除到期、再淘汰最旧附件，不因“经常用”无限延长绝对TTL。

建议同一SQLite连接、同一父进程写者、独立表和事务完成结果/额度提交，避免jsonl与正文文件半写。若必须落文件，须再设计原子rename、manifest、孤儿清理与崩溃恢复；这不是W0免费附带能力。总量20MiB包括逻辑正文/索引估算/审计预算，最多1000审计行；SQLite主文件/WAL/临时空间要额外监测实际占用，达到预定物理高水位（建议64MiB归属web的增长预算）停止新写入并提示维护，不能声称逻辑DELETE立刻归还磁盘。现有共享DB其他表不算web清理目标；需要明确可归因计量、受控checkpoint/压缩窗口，不能删除聊天解决空间问题。更严格物理上限若要求独立数据库，会增加生命周期/跨库一致性成本，需另裁决。

### 审计最小化

不用无界audit.jsonl保存完整URL或自由why。记录受控任务ID、时间、渠道、政策版本、origin或其HMAC、URL的HMAC、状态码、网络/模型attempt、已读字节/未知、cache_hit、清理时间。完整URL、query、标题、用户问题、正文只在有期限的附件内；审计hash也需同样限期。不写提供者原始异常、响应头全集或重定向敏感Location到日志。

“是否被引用”拆成`evidence_offered`（程序提交材料）、`citation_validated`（输出精确引用匹配）、`shown_to_user`（界面交付记录，断线可未知）；均不等于模型真实理解/用户真实阅读。“可疑”只来自指定启发式命中，记录算法版本，不由模型自行宣布安全。状态变化在确定的开始、抓取完成、引用验证、交付/取消节点提交；不事后猜测。

默认审计7天/1000条双限，日额度只保留当前结算与必要防重数据。已过期任务ID一律拒绝重启执行；幂等身份需包含由服务校验的有效时间窗口/epoch，不能删墓碑后把旧随机ID当新任务。清理不重置已用额度。预算汇总与详细审计分别维护，删正文不退款。进程重启/库reset新epoch时，旧结果只能中断，不能跨库提交。

## F. 状态、错误与架构备选

状态机建议：`accepted → fetching → extracted → [interpreting] → completed/partial`，任意阶段可至`failed/cancelled/interrupted`；终态不可复活。缓存命中可跳过fetching但保留授权检查。无内容时不调用解读。前端断流不取消，显式cancel/关闭能力才撤销；刷新按任务ID恢复，不能重放start。

| 错误/状态族 | 含义与用户可见行为 |
|---|---|
| disabled / unauthorized / grant_expired / channel_not_enabled | 功能关闭、地址未授权、票据过期或渠道不支持；不出站，给下一步，不让模型猜失败原因 |
| invalid_url / blocked_target / tls_failed | 地址格式/网络政策/证书不满足；不建议关闭TLS验证或换代理绕过 |
| redirect_requires_authorization | 目标跳转，不跟随；显示安全处理后的目标供用户重新明确选择，不自动创建新任务 |
| quota_exceeded / storage_unavailable / busy | 额度/存储/活动槽不足；不排无界队列、不暗中重试 |
| deadline_exceeded / network_unavailable / http_error | 未获得成功页面；受控状态码，可人工重试为新请求；已耗额度如实保留 |
| unsupported_mime / unsupported_encoding / body_limit / header_limit | 不支持或传输超限；不将不完整响应作为完整正文 |
| no_usable_text / decode_failed / partial | 未取得可用静态正文、解码失败，或抽取有界截断；partial必须展示覆盖限制 |
| interpretation_failed / citation_invalid | 页面摘录仍可用；解读失败/引用核验失败，不编造替代答案，不自动补模型请求 |
| cancelled / interrupted / expired / cleared | 撤销、进程中断、详情到期或清理；不能自动恢复网络/模型；晚到结果不能复活 |

错误枚举及所有输出字段都须有大小上限；HTTP鉴权/协议错误与业务失败分开。设置/结果读取无模型调用；关闭后已有卡标明历史记录。

| 方案 | 可实施性 / 优点 | 主要代价 / 推荐程度 |
|---|---|---|
| 原稿同步fetch+cheap摘要+普通工具 | 能写出来，但现有授权/记忆/超时承诺不成立 | 多请求持锁、人格旁路；不推荐 |
| 普通主模型+单页工具、不加摘要 | 交互自然，改动比独立任务少 | 网页/自由回答会进入turns，需全链路污染/授权传播；若接受这种记忆风险，必须明示放弃“不自动落库”，不能本轮默认接受 |
| 独立查证附件+确定性摘录 | 无新增模型费用，隔离边界最清楚 | 不自然续谈，有新入口/任务/表；推荐W0可独立交付部分 |
| 上项加可选独立一次解读 | 保留有限“帮我核实本页”解释能力 | 费用与模型错误仍在，需独立取消/限额/引用核验；推荐在用户选择后并入W0 |
| 通用异步抓取队列、结果注入下一轮 | 未来自主探索可复用 | 改会话顺序、恢复、授权与记忆；延后 |

保留当前单活动槽，网页占槽期间普通GUI/QQ不同时生成；仅外部等待不持Store锁，状态/观察查询可按原约束短读。接纳顺序为先取得活动槽，再短持Store锁写任务；状态闸只保护任务状态，禁止持状态锁等待Store锁。Store读写只走父服务的RLock，提交前再次核对epoch/配置代际/撤销。reset/shutdown的撤销信号必须先于等待`channels.control()`，否则现有control会等网页结束；停止接纳、撤销后，杀进程/join均不持Store/状态锁，终态结算后由槽的唯一拥有者在finally释放。未确认进程结束保持draining/busy，不提前允许另一任务。再处理Store重置/关闭，旧worker不能写新库。`service._turn_count`等统计排除查证标记，分页历史明确附件类型；已有P1工作者继续按其原权限运行，不能把其锁外执行当网页有P1权限的理由。

## G. QQ、后续阶段与资料边界

**官方资料已确认**：[QQ消息收发概述](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)本次可读，列单聊60分钟/4次被动回复；同一msg_id+msg_seq用于去重。仓库此前核查的[发送单聊消息页](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)记有5/60分钟冲突，本次工具无法取回该页，故将具体字段冲突标作既有记录、未重新直接确认。不得据此扩大本地300秒预算。旧发送文档URL本次跳到新站入口，不能拿旧仓库5次规则替换现行概述4次。
