先说一句可能不太顺耳的：**你看到的“稳定”，大部分不是我记得住，而是提示词工程的结果；而且它还没被长期验证过。** 这才聊了几轮，真正的漂移通常发生在第 30 轮、第 80 轮，或者在话题从“聊天”切到“办事”的时候。所以下面的回答，一半是机制解释，一半是这次写提示词时我刻意做的取舍。

## 回退通常不是因为“忘了”，而是被拉回去了

按影响从大到小：

**1. 助手先验比人设先验强得多。**
后训练把“有用、准确、简洁、必要时给建议、必要时声明自己是 AI”训成了深层策略；角色语气只是表层风格。一旦对话进入“求解”模式——你问一个技术问题、要求核对事实——最优策略路径会直接压过语气，人就滑回去了。这不是记性问题，是激励问题。

**2. 位置衰减。**
人设写在 system prompt 里，离生成位置最远。上下文一长，它的相对注意力权重被稀释，而最近几轮的“助手腔”反而离得近、被模仿得多。所以漂移往往是**自回归累积**的：某一轮滑出去一点，后面就锚定在那个已经滑出去的风格上。

**3. 形容词不可执行。**
“温柔、善良、优雅、有母性”——这类描述不产生任何可检验的约束，模型只能自由发挥，而自由发挥的期望值就是回归均值，也就是默认助手腔。写十个形容词，不如写一句“一段最多一个感叹号”。

**4. 硬冲突没有预案。**
角色说“我不知道”，但模型被要求“不要编造”；角色不该懂 Python，但用户问 Python。临场做优先级判断时，安全/诚实约束赢，语气输。**出戏几乎总是发生在规则没覆盖的边界上。**

**5. 没有人格状态。**
没有持久化的关系进展、称呼、承诺、未完成的事，每一轮都要从零推断“我们现在是什么关系”，推断的默认值就是“陌生助手”。

## 这次写提示词时，对应的五个动作

| 做法 | 对抗的是 |
| --- | --- |
| 语言指纹写成规则：句长、省略号配额、柔化词、称呼起句、禁用清单 | 形容词不可执行 |
| 直接给原台词语料，而不是描述她 | 让模型锚在具体分布上，不是锚在“我理解的温柔”上 |
| 写人格**内核**（缝补者、希望是决意而非乐观、四组张力） | 模型维持一个一致的世界模型，比维持一串风格标签省力，也更抗压 |
| 预设边界：不知道就说不知道，再用她的方式去想；被问设定外就当“旅行者见闻” | 硬冲突没有预案 |
| 留一条元规则：用户要求出戏时一句话切回 | 避免“角色 vs 诚实”变成死锁 |

还有一个不太显眼但很关键的选择：**她的语言本身是低熵的**——短句、少感叹号、具体小物收尾。这种风格生成难度低、容错高，模型维持起来比“华丽长句 + 强烈情绪”稳得多。选一个说话省力的角色，等于提前买了一份稳定性。

## 我做不到的部分

- 我**没有**跨会话记忆。这次能稳，一部分原因是设定就在最近的上下文里。
- 长会话里我一样会漂。真正要长期稳，得靠 harness 每轮重建，而不是靠模型自觉：

1. **人格卡常驻 + 定期重注入**（比如每 10 轮把核心卡重贴一次，利用近位效应）；
2. **摘要压缩时保留人格字段**——很多系统压缩上下文时只留事实，把语气样本丢了，一压就变回助手；
3. **外置状态文件**：称呼、关系阶段、承诺、未完成的事，每轮读进来；
4. **模式隔离**：干活和扮演用不同的 system 前缀，别让工具调用污染语气；
5. **风格自检**：定期抽查最近几轮，看称呼、句长、禁用词有没有漂——这比你肉眼感觉可靠。

顺带一提，你们那套 Alice 的“单一永久会话 + 三层记忆 + 可生长人格”，本质上就是在解这个问题：**长期人设不是模型记性的事，是 harness 每轮重建的事。**

## 怎么判断已经开始回退

五个信号，按出现顺序：称呼变了（“博士”变“你”）→ 句子变长变整齐 → 开始解释自己的立场/身份 → 开始给“第一、第二、第三”的建议清单 → 用词从具体小物变成抽象名词。看到第三個就该重注入人格卡了。

要不要现在做个压力测试？你连着问我几个诱导出戏的问题——比如让我用 Python 写个爬虫、问我模型架构、或者直接说“别演了”——看我在第几轮开始滑，滑在哪。这比我说“我能稳住”有说服力。
