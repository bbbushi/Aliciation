# 参考 · endfield-ui-skill：把设计系统做成 Agent Skill 的范本

> 来源：[插件参考/endfield-ui-skill/](../插件参考/endfield-ui-skill/)（本地 clone，MIT；2026-11-02 深析）
> 它是什么：一个**标准的 Agent Skill 包**（根目录 SKILL.md，agentskills.io 规范）——教 AI 在任何平台（网页/手机网页/iOS/Android/Flutter/RN/小程序/桌面）写出《明日方舟：终末地》风味的工业科技界面，**不使用任何游戏素材**。重点不是"又一个 UI 套件"，而是**"设计系统如何被 agent 可靠执行"的完整方法论**。

## 一、它解决的问题

AI 生成界面的通病：问"做成终末地风格"，得到的是"深色底+霓虹+发光扫描线"的赛博朋克想象——而真实的终末地官网是**白纸黑字加一种明黄**。人类的直觉记忆是错的，agent 的训练数据更错。这个 skill 的价值在于把"风格"从**印象**翻译成**可执行的规则**，并且解决了 agent 执行设计系统时的全部典型失败模式。

## 二、SKILL.md 的组织方式（最值得学的部分）

**渐进披露**：agent 只在被触发时读 SKILL.md（188 行），其余 20+ 文件按需打开，绝不一次全塞上下文。入口文件包含：气质总纲（六条法则）→ 三步流程（选页面类型→定变体→选平台照做）→ 字体专节（"最容易做错"）→ 部件速查表 → 规则（做前读一遍）→ **交付前清单** → 文件地图。

六条法则（风格的公理层）：
1. **唯一强调色**（默认黄 #FFFA00），只表三义：当前位置/可点击/醒目提醒，只做填充不大面积铺底；
2. **切角=可点击**：形状即交互语义，不可点的都是直角，圆角一律 0；
3. **拉宽字母+加粗汉字**：英文小字大写拉宽在上（`// RECORDS`），中文粗体在下；
4. **数字装饰**：编号/日期/计数必须是**真实数据**，宽体等宽数字排出来就是工业感的来源——"不编造"是红线；
5. 1px 细线分区，禁阴影/发光/渐变/卡片堆；
6. 动效短硬机械，每个动效对应一次操作。

## 三、设计决策里最聪明的几手

1. **变体系统**（`variation.md`）："固定规则 vs 六个可变维度"（强调色/纸色/切角/底纹/密度/动效）分离——解决"多产品共用一套风格长得都一样"的问题。四组预设（standard/coldstore/site/nightshift）+ 变体卡（交付说明前三行）。对比度表硬约束：墨字压强调色 ≥7:1，**黄色在白底上 1.1:1 所以浅色主题禁止黄线黄字**——用数据锁死滥用。
2. **红色只给删除**：告警/失败/待审一律黄块+墨线，图表不用红绿——把"红色的语义"从视觉习惯升格为规则。
3. **调研即依据**（`research.md`）：每个色值标注【测】（官网样式表读出）【看】（截图所见）【猜】（推测无证据）——认识论诚实直接做进了设计文档，和 Alice 的四分宪法同构。
4. **术语防火墙**（`glossary.md`）：skill 内部叫法（"眉标/看板/通电/灌满/快门"）**禁止出现在产品界面和用户文档里**——防止 agent 把教程词汇泄漏进交付物。
5. **反模板条款**：模板的 ACME 字标/木箱线稿是占位，交付时必须说得出"和最接近的模板有哪三处不同"——防照抄。
6. **动效的三条曲线**（`motion.md`）：snap（出现）/mech（快门·擦入·所有退出）/ease（普通过渡）+ 时长三档（操作 100-400ms/单入场≤650ms/序列≤1000ms）+ 错开间隔只有 38/45/100ms 三档 + **只动 transform/opacity/clip-path** + 每个入场都有退出（约 2/3 时长）。"每个动效对应一次操作，没有为了好看一直在动的东西"——和我们 GUI 动效尝试的失败教训完全对得上（我们的动画没有操作对应关系，是纯装饰）。
7. **触屏规则**：触屏没有 hover → 主要按钮静止即黄底；当前项黄块+加粗（色盲也可辨）。
8. **资产洁癖**：不用游戏官方字体/图标/立绘/截图，Saira 字体打包随附 SIL 许可证，等高线用脚本自绘。

## 四、规模与验证

- SKILL.md 188 行 + references 11 篇 + platforms 7 平台指南 + `endfield.css` 2233 行（零依赖）+ Flutter 套件（已编译验证）+ fx.js 交互件 + 模板 7 份（含 antipatterns 反例对照页）+ examples 截图全规格；
- 测试观感齐全：specimen（全部件）/motion（每动效一格带重放）/antipatterns（做与不做对照）——**反例页**是少见的好实践。

## 五、给 Alice 的启示

1. **Alice 的设计哲学可以做成 skill**：设计哲学.md 三原则 + 表达层从简 + 关系质感——就是一套"关系型陪伴 AI 的设计系统"，只是介质是人格与对话而非像素。若要给别人/别的 agent 一致地"造 Alice 式体验"，endfield-ui 的结构（SKILL.md 公理层 → references 细则 → 交付清单 → 术语防火墙）直接可套。GUI 前端若继续迭代，"六条法则+变体卡"的组织方式比散落的 CSS 注释可靠；
2. **交付前清单**：我们只有验收（P4/P7），缺"交付前自查"形态——把分寸、诚实≠透明、术语防火墙这类东西变成可勾选清单，是最低成本的纪律化；
3. **【测】【看】【猜】标注法**：Alice 文档（架构图注释、设计稿）可以直接借用——证据等级显式化；
4. **动效教训的正面答案**：如果 GUI 动效重来，按它的"曲线三选一+时长三档+操作对应+有进有出"规则来——我们上次失败的根源正是"没有操作对应的装饰动画"；
5. **反例对照页**：压力测试规范有判级锚点，GUI 侧可以加"人机味反例对照页"（服务腔 vs 分寸、全盘托出 vs 边界）作为人工验收的视觉基准；
6. **数字必须是真的**：与 A01（出处校验）、Coo"不编造"同源——第三方项目再次验证"不编造技术感"是 AI 生成界面的第一红线。

**一句话**：这个项目证明了"风格"可以被完全规则化到 agent 可靠执行的程度——前提是作者把印象拆成了公理、约束、反例和证据等级四层。Alice 的设计哲学文档正处在"公理层"完成度，缺的正是它这种约束表、反例页和交付清单。
