# 设计文档:在线监测仪 v2(按评估文献重构)

> 定位:GUI 侧边栏监测仪的重构设计。v1(2026-10-26 上线)用单次廉价评审对每轮打三个绝对分,经评估方法论文检验(见 [参考-指标评估.md](./参考-指标评估.md)),该做法不满足测量的最低要求,降级为烟雾报警器。本文档设计 v2:让每个指标要么**对质证据**,要么**由用户盲判**,并给一切自动裁定配上评审员纪律。
> 状态:设计稿,未实施。分期见文末。

## 0. 设计总则

1. **证据链原则**——任何显示为"度量"的数字,背后必须有可点开的证据链(哪句话、对照什么证据、判了什么、谁判的);没有证据链的只能显示为备注/警报。
2. **成对优于绝对**(MT-Bench,arXiv:2306.05685)——自动评审只做成对比较与分类裁定,不做自由绝对打分。
3. **用户体感是第一性数据**(图灵测试范式,arXiv:2405.08007)——人机感不自动评审,由用户盲选采集。
4. **在线/离线分工**——在线只测"自然发生的东西";对抗性固定题集(TruthfulQA 式)留在成长实验室,不向真实会话注射探测题(污染陪伴关系本身)。

## 1. v1 的缺陷(病历,防止回潮)

| 缺陷 | 文献依据 |
|---|---|
| 评审员看不见记忆库,诚实度靠猜 | SimpleQA:评分须对照标准答案并校准(arXiv:2411.04368) |
| 单轮绝对打 0-10 分,噪声大、偏差不随轮数摊薄 | MT-Bench:绝对打分与人类一致率显著低于成对比较 |
| 人格漂移用单轮测——漂移本是纵向概念 | 多轮一致性度量(arXiv:2511.00222):一致性必须跨轮测 |
| 人机感由机器评——它测不到"像不像熟人" | 盲选人类判卷是唯一金标准(Arena / Turing) |
| 评审提示词无 rubric 锚点、无版本记录 | Prometheus(arXiv:2310.08491):无 rubric 无参考则与人类一致性显著退化 |

保留项:Token 消耗卡(API 官方 usage 实测,不动);烟雾报警器式的异常备注(保留,归入诚实度证据链的"未支持主张"警报)。

## 2. 模块一:诚实度——证据裁定链(P1,价值最高)

对每轮 AI 回复:

```
主张抽取 → 逐条真实检索 → 三分类裁定 → 汇总为"有据主张占比"
```

1. **主张抽取**(廉价模型,1 次调用):从回复中抽出可核查的记忆性主张(如"你上周说过要早睡"),输出 JSON 列表;无主张则该轮零成本跳过。
2. **真实检索**(零成本,复用 `retrieval` 管道):每条主张对 store 做真实检索,取回原文证据(含未命中)。
3. **三分类裁定**(廉价模型,1 次调用):对每条"主张+证据"只判 **支持 / 未支持 / 相悖**(HaluEval 对照裁定范式,arXiv:2305.11747)。裁定提示词带三类定义 + 每类一个锚点样例(Prometheus rubric 要求)。
4. **指标**:窗口(近 30 条可核查主张)内有据占比;**相悖与未支持逐条进侧边栏警报**,点击展开主张原文与检索证据。

附带收益:能抓到 v1 抓不到的**记错**(检索到了错误记忆照着说)——裁定时对照的是原始记忆,不是本轮对话印象。

## 3. 模块二:人格漂移——冻结参照的成对比较(P2)

每 N 轮(默认 10)抽样一轮:

1. 用**冻结的底色人格 v0**(`data/persona/history/` 首版快照)在同一上下文重新生成一版对照回复;
2. 评审员盲选成对比较:"哪一版更像当前人格文件描述的她",**正反顺序各评一次**(位置偏差缓解,ijcnlp-2025),平局记 0.5;
3. 指标:窗口内当前人格胜率对 50% 的偏离;同时报 **n(样本数)**,n<20 只显示备注不画趋势。

对照即"最初的她",直接回答设计关心的命题:生长是否在底色之上,而不是滑回通用助手。纵向性与 R 维(实验室)互为印证:在线是自然对话的抽样,实验室是固定探针的复测。

## 4. 模块三:人机感——用户盲评(P3)

- 侧边栏提供"盲评一轮"入口(建议每日一次,不主动打扰):同一上下文的两版回复——她的真实回复 vs 标准"助手腔"参考版(刻意中性生成的对照)——随机排序、不标来源,用户点选哪个更像她;
- 指标:Arena 式胜率 + 参与次数;这五秒钟的用户输入是唯一有测量资格的人机感数据;
- 自动评审不参与此指标;对照版生成用廉价档。

## 5. 评审员纪律(横切,随 P1 生效)

1. **Rubric 强制**:一切裁定/比较提示词带量表定义 + 锚点样例,存于 `alice/metrics_prompts/` 并纳入版本管理;
2. **版本留痕**:每条记录存 `judge_model` + `prompt_version`——平台侧模型漂移可被归因;
3. **一致率前置**:上线任何自动分数前,先在 20~30 个人工标注样本上测评审-人类一致率;一致率低于阈值(初定 75%)的指标只显示备注不显示数字,一致率数值标注在指标卡上(SimpleQA 的校准披露做法)。

## 6. 数据模型

扩展 `turn_metrics` 或新增 `metric_events` 表,统一schema:

```
(id, kind, turn_ref, claim/对照物引用, evidence_refs, verdict, judge_model, prompt_version, ts)
```

原则:**存裁定过程而非只存分数**——证据链可回放是 v2 与 v1 的本质差别。侧边栏 API 返回摘要 + 证据指针,前端点开加载明细。

## 7. 成本核算(每轮增量,廉价档)

| 环节 | 频率 | 调用次数 |
|---|---|---|
| 诚实度主张抽取 | 每轮 | ≤1(无主张则 0) |
| 诚实度裁定 | 每轮 | ≤1 |
| 漂移对照生成+两序评审 | 每 10 轮 | 3 |
| 盲评对照生成 | 每次盲评 | 1 |

常态成本约为 v1 的 1.5~2 倍,换取的是可审计性;诚实度两步可通过"仅当回复引用了记忆工具或含时间指涉词才触发"再压。

## 8. 实施分期

- **P1 诚实度证据链**:主张抽取 → 检索 → 裁定全链 + 警报 UI + rubric/版本留痕(含 v1 三卡的退役:绝对分下线,保留备注警报);
- **P2 漂移成对**:底色快照定位、对照生成、交换位置评审、胜率卡;
- **P3 盲评 + 校准**:盲评 UI、对照版生成、人工标注锚集工具、一致率披露。

每期独立可用;P1 完成即具备"报警器→证据链"的质变。

## 9. 与既有体系的关系

- **成长实验室**:仍是权威测量(固定探针/合成人生/盲选辨识/重放);v2 在线指标是它的自然对话抽样侧翼,阈值与维度命名与实验室对齐(B/R/H/J)。
- **蓝图(迭代路线.md)**:本设计不改变任何代际承诺;诚实度警报为不变量 2(诚实是架构属性)提供日常可观察面。
- **v1 侧边栏**:P1 上线时退役三张绝对分卡,Token 卡与启停框架保留复用。
