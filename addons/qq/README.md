# Alice QQ 桥

首期仅官方 QQ 机器人、一个已确认的所有者、C2C 纯文字。QQ 与 GUI 共用同一个 Alice。群、陌生人、附件、引用、主动消息、QQ管理模型/人格/P1均关闭。实现尚待真实环境人工验收；本轮没有启动桥、扫码或向QQ发送消息。

## 推荐：从 Alice 网页连接

更新代码后重新启动 Alice，点击网页右上角的 **连接 QQ**（欢迎页和设置中也有入口）：

1. 首次使用若提示缺少组件，点击 **安装 QQ 组件**，等待页面提示准备完成。已安装的电脑会直接显示连接按钮。
2. 点击 **扫码连接**，用手机 QQ 扫描页面中的二维码。
3. 扫码后在页面确认这是你本人的账号。如果扫码没有返回身份，页面会引导你给机器人发一条配对口令，再确认本人。
4. 点击 **开始 QQ 聊天**。页面显示连接成功后，即可在 QQ 中私聊机器人。
5. 暂时不用时，在同一处点击停止。关闭设置面板不会停止已经开启的聊天。

如果提示需要 Node.js，先通过页面的 **下载 Node.js** 链接安装官方版本（22.19 或更新版本，保留安装程序中的 npm 组件），再回到页面点 **重新检测**。仍未找到时，关闭并重新启动 Alice 后再试。安装位置是运行 Alice 的那台电脑。QQ 组件安装成功后可直接扫码，无需为此再次重启 Alice；安装失败可按页面提示处理后重试。

网页会保存连接资料并让配置生效，无需手工复制配置片段或再次重启 Alice。首次进入页面不会自动扫码、连接 QQ 或调用模型；保存身份也不会自动开始聊天。Alice 下次启动后，仍需到这里点击开始，可使用原来保存的连接，不必重复扫码。

网页只展示二维码、本人确认信息和连接状态，不展示密钥。二维码与待确认资料只在内存短暂保存；可点击取消，授权总时限为5分钟。现有连接不会被新扫码覆盖。若之前已在终端启动桥，请先在终端停止，再改用网页；网页不会强停或接管另一个进程。

网页暂停先等待当前连接收尾；若网络长时间无响应，宿主会结束自己启动的连接器进程，并提示中途发送结果可能未知，恢复后不会自动重发。这个收尾范围不包含终端或其他程序启动的连接。

首次安装只在点击按钮后下载本目录所需的固定组件，不会随打开页面自动下载，也不会自动扫码或开始聊天。安装期间可以关闭连接面板后再回来查看，请保持 Alice 运行；已有 QQ 连接运行时须先停止。Node.js 本身通过官方安装程序安装，终端备用步骤仍见下节。QQ本身的权限和真实收发尚待人工确认。

升级到首次安装功能这一版前，请先停止旧版网页和终端启动的 QQ 连接，再重新启动 Alice。旧进程还未使用新的安装占用标记，尤其是自定义配置的终端桥，不能仅凭新页面判断它已经退出。

若页面提示“占用状态无法确认”，先正常停止相关 QQ 连接并重新检测；安装器只会自动清理已确认进程退出的旧标记。损坏或缺失的占用记录需要人工核对，不能直接删除标记后同时启动安装和 QQ。若安装失败，检查网络和项目目录是否可写；使用了自定义 `.npmrc` 的电脑请改用下方终端步骤，网页安装只采用固定安装设置。

## 使用前准备

- Node.js >=22.19；本次依赖安装工具为 Node 24.16.0/npm 11.10.1，未做运行验收。Alice继续用原Python环境。
- 先在独立Alice副本人工验收，QQ账号需有官方C2C/WS权限。换 `--config` 不会自动隔离Alice数据目录，须用完整独立检出副本。
- 电脑需保持在线。桥只连接本机Alice和腾讯官方服务，不监听公网端口。
- 以下命令由用户在仓库目录的PowerShell中执行；它们不会自动启动/重启Alice，不修改 `user/config.toml`。

下面是**终端备用方式**；已通过网页连接时，不要再同时启动终端桥。

```powershell
Set-Location D:\alice\addons\qq
npm.cmd ci --ignore-scripts --no-audit --no-fund
.\qq.ps1 init
.\qq.ps1 scan
```

`init` 创建 `user/qq/config.json` 和独立随机机器凭据，不覆盖已有配置。`scan` 是推荐接入方式：手机QQ扫描前台终端二维码，官方授权页显示“第三方机器人”；不伪装平台名称。5分钟总时限，Ctrl+C取消。二维码不写日志；不得把截图或链接分享给别人。它只连接官方授权服务，不调用Alice或模型，不自动开启QQ聊天。

扫码成功后，仅在本机显示AppID和可能的所有者OpenID候选；输入 `YES` 才确认该身份。AppSecret写入配置指定的凭据文件，不打印原值。若没有候选/没有确认，运行：

```powershell
.\qq.ps1 pair
```

`pair` 产生一次性80位随机码，5分钟内从你本人QQ私聊发给机器人；随后本机再输入 `YES` 确认。配对消息不交给Alice，桥不发QQ回复。已有AppSecret时 `scan` 拒绝覆盖：重新绑定请使用新的配置目录并停用旧桥，不能把旧发件转到新身份。

手工备选：在 `user/qq/config.json` 填官方AppID；把AppSecret以单行文本存入 `user/qq/credentials/app-secret.txt`，再执行 `pair`。凭据必须放在当前用户私有目录中。Windows创建目录会用icacls关闭继承并仅授予当前用户和SYSTEM；已有额外显式ACL应由用户核对。Git忽略不代表加密，备份也须保护。

确认后 `config` 命令输出不含秘密原值的核心配置片段：

```powershell
.\qq.ps1 config
```

把片段合并入 **该副本** `user/config.toml`，保留原模型配置；不要出现重复 `[channels]` 节。核心只存机器token的SHA256、AppID与绑定OpenID，不读取QQ AppSecret。用户受控重启Alice后，再运行桥：

```powershell
.\qq.ps1 run
# 前台人工确认后，可选隐藏后台：
.\qq.ps1 run -Background
# 请求停止桥，不停止Alice：
.\qq.ps1 stop
```

任意命令可用 `-Config '绝对路径\config.json'`；所有配置内相对路径按该文件目录解析。`run` 会先检查核心机器接口就绪，失败不会连接QQ。停止写入stop.request，由桥处理当前网络尝试后退出，不能把“停止请求已写入”当完成。等待日志 `bridge_stopped` 或 `bridge.lock` 消失；退出不保证QQ已读。强停导致残留锁时确认进程退出后运行 `unlock`，工具仅在PID已不存在时移除锁，不强杀进程。

停止没有严格30秒的保证：SDK 1.0.4 的HTTP超时计时在收到响应头后即清除，随后读取响应正文没有完整时限，极端半开连接可能拖长当前发送与退出。此时不要启动第二个桥或重发原请求；若人工确认需要强停，重启会把已记录的sending保守标为send_unknown，先到QQ核对再处理。启动/扫码过程也可能等待已发出的官方网络请求结束；本机“已取消”不能撤销平台已经完成的授权。

可以在人工验收后自行将 `qq.ps1 run -Background` 配置为Windows任务计划“用户登录时运行”；不需要管理员或系统服务。本项目不自动创建计划任务。

## 聊天规则

- 所有者纯文字才交给Alice；Unicode emoji和URL仅作为文字，不下载/执行链接。图片、语音、文件、平台引用、结构化表情及混合媒体整条拒绝。
- 入站正文最多4000 Unicode字符、12000 UTF-8字节；来源与正文JSON序列化后最多14000字节，为核心16KiB请求限制预留空间。超限提示缩短，不截掉一半后交给模型。
- `/status` 查看本人最近请求状态；`/cancel` 只取消最后一条尚未提交的等待消息。其它斜杠命令提示在GUI操作；`//` 开头可输入字面的斜杠文本。
- 一个处理槽与GUI共用；桥最多3条等待消息，等待不超过120秒。已提交不承诺取消或退款。
- 回复聚合完成后按自然段和完整句群，依次发送1～3条真实QQ消息；短回复和极短承接句尽量合并，不逢句号就拆。相邻发送至少间隔1秒，不随机模拟打字；后续追问先排队，上一轮发完或停止后再处理。不发送思考过程、工具日志或维护事件。
- 每条最多1000 Unicode码点且最多4000 UTF-8字节，保护引号、链接、数字、列表、代码和emoji边界。超过3条先合并相邻内容，仍放不下时明确提示后文未发送，完整回复在本机网页。以上是工程保守值，不是已确认的QQ官方长度上限。
- `delivery.reply_split_mode` 只接受 `natural` 或 `length`，新配置及旧配置缺少此项时均为 `natural`。切到 `length` 可让新回复只按长度分条，仍保留新账本、边界保护和明确截断；已冻结的投递不会重切。网页仍显示一份完整回复，分气泡不会新增逻辑回合、记忆提取、工具调用或P1核查。
- 首期不开输入中提示。按原消息5分钟被动窗口保守处理；超过窗口只在本机查看，不自动转主动消息。消息长度/额度/窗口存在平台和账号差异，须人工确认。
- 生成成功但发送失败不会再次生成。发送结果未知时停止本轮后续自动发送，请先到QQ核对；当前首期没有QQ远程“补发”命令，可在GUI取回。用户新发一条普通聊天仍是新生成，不能用它当无费用补发。网页的“平台确认”只表示已登记片段获平台确认，可能是长回复摘录，不代表全文送达或已读；失败也可能已经送出前几条。

## 数据与恢复

桥只保存自己的 `user/data/qq-bridge/state.json`，不打开Alice数据库。入队先原子写盘，失败停止接单。稳定事件键包含app、真实sender、原始d.id，核心另做来源唯一约束。入站文本在核心确认接收后从桥删除；发送正文成功后删除，未确认正文最长24小时；去重墓碑保留30天，10000条上限触发停止，绝不丢掉进行中记录继续运行。

每段发送前记录sending，响应丢失/崩溃恢复为send_unknown；重连不自动重发。明确401仅刷新一次、429有限退避且保持同一msg_seq；网络错误和5xx保守视为未知。SDK不会代桥对生成请求重试。此机制不保证端到端exactly-once，也不能保证掉线期间所有QQ消息补齐。

自然分条使用v2桥账本：首条发送前固定整轮计划、正文摘要、每条内容与序号。配置变化或进程重启后使用原计划；已经确认的片段不重发，未知结果不自动重发，已经送出的消息不自动撤回。旧账本已有分段按原内容与序号冻结迁移，不用新规则重新切分；旧sending按未知恢复，旧失败或未知项不自动续发剩余片段。缺失必要正文或账本校验失败时停止对应投递或停止接单，不凭当前配置猜测恢复。

首次启动新桥时才会实际迁移账本，并在同目录保存不含聊天正文的 `ledger.identity.json`。身份文件仍在但 `state.json` 丢失时拒绝重新初始化，防止忘记旧投递；如果整个目录都被删除，程序无法凭空识别原账本，所以不要删除状态目录来恢复聊天。发送时钟和429冷却也会持久化，重启不绕过间隔；明显系统时间回拨时停止，待本机核对。

升级须先由用户受控暂停桥、确认退出，并在本机妥善保留含聊天内容的账本备份，再启用新代码；不要把备份放入git。建议回退方式是将 `reply_split_mode` 改为 `length` 后受控重启桥，只影响之后新建的计划。旧代码会拒绝v2账本，也会拒绝新增的配置键，这是安全停止；不要把账本版本手改为1、删除账本，或恢复发送前备份继续发。确需降级旧代码，应先排空或隔离未完成／未知投递，另行审核保留去重证据的迁移；无安全迁移时关闭QQ入口，网页仍可使用。

恢复时重新核对所有者、应用与Alice的session_epoch，变化则隔离旧队列和发件。重置/归档之前先停桥并核对未发/未知项；已经交给平台的在途消息无法撤回。模型热更新不要求桥重启；QQ身份、密钥或机器token改变则先停桥排空，再改配置/受控重启。

日志只写固定错误类别、时间与散列引用号，位于 `user/data/logs/qq/`，最多7天、每天2MiB；不保存原始SDK异常、聊天、授权URL或密钥。bridge_waiting_for_service表示待查询原请求，不证明请求未执行。损坏账本不自动清空，保留原件并停止。目录权限或磁盘异常需先处理，不要删除账本“解决”重复发送问题。

| @tencent-connect/qqbot-nodejs | 1.0.4 | MIT；实际发布包src/QQBot.ts、event-dispatcher.ts、gateway-connection/reconnect、api-client/messages/token已静态阅读 |
| @tencent-connect/qqbot-connector | 1.2.0 | UNLICENSED；官方公开README明确提供第三方npm接入方式，此处仅作为外部安装依赖使用，不复制/改编/再分发其源码 |
| qrcode-terminal | 0.12.0 | Apache-2.0；前台绘制经过域名检查的二维码，不输出认证URL |

扫码组件依据：[官方发布README](https://registry.npmjs.org/@tencent-connect%2Fqqbot-connector)、[腾讯openclaw-qqbot依赖声明](https://github.com/tencent-connect/openclaw-qqbot/blob/main/package.json)。第三方默认显示“第三方机器人”；自定义平台名称/商务需求按官方README另联系，不把公开安装说明扩大解释为开源复制授权。源码发布、打包分发或商业部署时应再次核对条件。

发布包的qr-connect.d.ts/qqbot-session.d.ts及压缩JS已静态核对：默认HTTPS `q.qq.com/lite/create_bind_task`、`poll_bind_result`，二维码为 `q.qq.com/qqbot/openclaw/connect.html`；本地随机密钥解密返回的AppSecret。回调模式、AbortSignal、总时限由本桥包装。未实际授权扫码，账号是否可用未验证。

SDK 1.0.4默认API仍为旧域名，本桥明确覆盖为 `https://api.bot.qq.com`。其sendText会在内存递增msg_seq，因此本桥用**公开的** `bot.api.post` 发送固定的持久seq，无格式回退或主动发送。SDK无默认聊天回复中间件，本桥也不注册typing/媒体/命令中间件。日志全部替换为固定类别。

SDK处理网关消息时先推进游标再调用业务监听，不能把它当业务落盘确认。本桥没有持久化SDK会话游标，仅依赖进程内心跳/Resume；跨进程重启可能漏收尚未进入桥账本的事件。持久化业务请求恢复只保证已经记录的事件，真实人工验收必须覆盖重连与进程中断。

## 人工验收入口

按 [主方案](../../docs/QQ接入-方案与审核.md) 的人工矩阵执行，额外检查：扫码超时/取消不写凭据；多用户扫码候选需本机确认；配对不调用模型；拒绝陌生人/群与媒体；GUI并发/重复平台事件；发送响应丢失保守unknown；账本不可写停止；重置隔离旧epoch；模型热切换；Windows休眠/恢复/退出。**尚未运行这些验收，不以语法检查代替验收通过。**

自然分条另按[技术参考中的人工验收清单](../../docs/QQ自然分条回复-技术参考.md)核对短回复、多段回复、长文本和特殊文本、连续追问、部分成功、限流／结果未知、重启与旧账本迁移，以及核心历史和记忆只处理一轮。**这些真实环境人工验收仍待执行，配置和语法检查不等于体验已验收。**
