# 上下文观测插件（context-inspector）

固定同源独立页：从一条 Alice 回复进入，查清这轮人格、记忆、前情、历史、工具结果如何进入模型请求，以及哪些材料没有进入、调用后回复有没有被替换。只提供实际记录，不自动评判人格、不猜测模型内部原因。

## 启用

在主界面“设置 → 上下文观测”可以分别启用查看入口和完整正文留存。保存到当前实例配置；入口立即更新，新请求使用新采集策略，在途请求沿用原策略，无需重启。桌面版在应用内窗口打开观测器，普通浏览器使用独立页。

也可手工修改当前实例的 `config.toml` 后重启：

```toml
[plugins]
context_inspector_enabled = true   # 固定页面开关，默认关
```

采集开关独立在 `[context]`：`observer_enabled`（元数据，默认开）、
`observer_body_capture`（正文快照，默认关；开启后持续采集，滚动保留最近10个采集请求，另受7天和50MiB限制。快照及请求引用清单留在本机 `user/data/observation/`，不回灌聊天）。重启延续窗口，旧累计额度不再阻止新请求；关闭采集不清除已留证据。

界面开启正文留存会同时确保元数据采集开启；关闭正文留存保留原有元数据设置。关闭插件查看入口不会自动停止正文留存。新增GUI控制接口 `GET/POST /api/observer/settings` 使用独立的 `observer-settings` 意图，已有插件查询接口仍只读。

## 访问

- 页面：`/addons/context-inspector/`
- 从聊天回复旁「查看本轮上下文」进入（携带该回复的 request_id）
- 无 request_id 时只能进入请求列表，不按时间猜测归属

顶部“查看完整上下文”打开大窗口，可切换同请求中的模型调用，按实际消息顺序查看正文、工具调用字段、SDK工具定义和模型参数，支持目录跳转、搜索、复制。内置记忆观察器的“调用轨迹”也有相同入口，两者复用核心公开窗口资源与只读查询。

0.1.27 起，新请求的「回复三栏」记录格式校验结论。失败时显示原因，可附缺失字段、JSON 错误行列、供应商结束原因和交付结果。元数据采集开启即可查看。模型原始输出、过程和反省正文不进入这条记录，旧请求也没有可补采的校验细节。

0.1.28 改用纯文本分栏。观测器标明普通正文或含旁栏标记的输出，并显示重复标记、同行标记等处理结果。历史 JSON 诊断继续显示已有字段。

0.1.29 改用逐行注释。观测器显示过程、反省注释数量，以及是否实际进入短期缓存。此前版本的诊断仍按原语义展示。

0.1.30 起，在有入缓存记录的回复上点「查看缓存注释」，可只读查看该轮仍有效的过程与反省。查看即时核对会话、原回复和来源。注释保留在内存，无需启用输入正文留存，查阅不延长期限。

新增完整输入快照沿用正文采集开关和留存窗口。旧记录仍可集中查看已经留存的消息正文；旧工具定义或工具调用参数未采集时明确标为“部分留存”，不从当前配置补造。完整快照超过单条200000字符上限时也如实降为逐消息查看。查询入口为插件公共HTTP的`call?request_id=…&call_id=…`，保留插件开关、scope和观察来源校验。

页面与查询只读：读取不触发模型调用、记忆读取、维护或水位变化。
正文只有开启 `observer_body_capture` 后的新请求才留存；更早的调用如实显示「未留存」，
不用当前数据补画历史。来源失效、会话代际变化或撤回后，旧页面停止展示对应正文。
