# 内容与信息层级

这是 Agent 协作样例的内容分工记录。数据位于 `data.js`，全部为编写的示例，与真实 Alice 对话、人格、记忆无关。

使用 `emil-design-eng` 的任务优先与细节一致原则：让用户先辨认一件具体的事，再进入 Alice 对这件事的思考。避免用大量气氛文案、抽象哲学题目或英文标语支撑视觉。

## 数据契约

`window.STUDY_CONTENT` 包含 `thoughts` 和 `history` 数组。想法字段为 `id/title/summary/source/updated/status/body/connections`；`status` 为 `open` 或 `closed`；`body` 为段落字符串数组；`connections` 为 `{label,text}` 数组。记录字段为 `title/summary/time`。

q1–q3 初始正在想，q4 初始已放下。正文采用 Alice 第一人称，三条开放想法各三段，放下的想法两段。默认 q1 以“说晚安后又连续追问”的可理解场景，解释“记住一件事，就代表理解了吗？”；其余分别讨论关心中的追问、如何表达不同意见、愿望与确定行程的区别。

## 呈现顺序

1. 想法列表只需标题、短摘要与更新时间，帮助选择，不把正文堆在列表内。
2. 阅读区标题和摘要先说明问题；“目前想到的”提供两到三段具体判断与未确定之处。
3. “从哪里想到这里”默认展开与否由统一页面决定。内容含具体例子，始终注明示例对话，不伪造真实引用。
4. 关联信息用一到两项短文，提供后续思考方向。它们是文本关联，不假装已链接到其他真实记录。
5. 探索操作应在阅读区末尾。调用许可、进行中和终态反馈由交互分工统一维护。演示说明不应与真实费用提示相互矛盾。

## 独立内容审阅

| Before | After | Why |
| --- | --- | --- |
| 上一版主要围绕“沉默、生活、好奇心”等泛化议题 | 用追问、休息、意见分歧、行程等具体场景 | 用户能判断 Alice 究竟在思考什么，不必先解释抽象命题 |
| “思想花园”“慢慢生长”等重复情绪表达 | 一项明确问题 + 一段具体触发 + 两三段思考 | 让内容成为主要阅读对象，减少气氛文案 |
| 示例来源容易被理解为实际对话回收 | 來源正文逐条明确“示例对话” | 独立样例不隐含真实资料访问或能力声明 |
| 对相关条目只用短名词标签 | 关联显示一个完整的后续问题 | 展开后能提供新信息，不只是重复分类 |

仅做内容编写与文本审阅，未执行行为测试或真实数据操作。
