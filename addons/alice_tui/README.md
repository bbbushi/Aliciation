# Alice TUI 终端客户端

Alice TUI 连接已运行的本机档案，和同档案的网页或桌面共用对话、人格和记忆。客户端与宿主均使用标准库。 [设计和人工验收](../../docs/设计文档/Alice-TUI-终端客户端-设计-v1-20261121.md)

## 打开终端

```sh
alice                                # 源码默认档案，或 ALICE_USER_DIR
alice tui --desktop                  # macOS 桌面默认档案
alice tui --user-dir /absolute/path  # 指定另一个正在运行的档案
```

也可以用仓库内的 `addons/alice_tui/alice` 启动，或直接运行 `python3 addons/alice_tui`。宿主和客户端需要使用本版协议。关闭终端后，已接单的回复和宿主后台活动继续运行。

## 按需启动与停止（独立启动说明 §6.1 第一阶段）

- 宿主缺席时，`alice` 显示「正在启动 Alice」并从当前源码环境启动后台宿主
  （`serve --no-open`，日志在 `~/.alice/host-<档案>.log`），就绪握手通过后直接进入对话。
  宿主在线但忙碌（503）视为已在线，轮询等待状态可用；已有实例不会被重复启动。
- 权限不符或协议不兼容会显示实际档案与原因，不尝试启动。并发启动同一档案时
  只有一个启动者创建宿主，其余客户端等待就绪。
- `alice stop` 显式停止宿主：停止接单、排空已准入的对话与后台任务、保存后清理
  socket 与档案锁，命令等待同一份停止结果。启动期间的 Ctrl+C 只退出等待，
  宿主继续启动。
- 当前一个宿主绑定 GUI 端口 8800；另一档案并行启动会失败，终端与日志给出提示。

## 视觉与交互（设计 §3 前两阶段）

- 启动页居中显示像素头像与 ALICE 点阵字标（头像为向导形象的 24×24 主色采样，
  见 `tools/tui_avatar_sample.py`）；窗口不足时先减图形再缩为一行名称。
- 消息块：用户消息用 `›` 引导行，Alice 消息用 `• Alice` 名牌；角色名单独成行，
  正文保持终端默认色，块间空行分隔。主动邀请带小标签。
- 工具进度折叠为消息下方一行摘要（`▸ 查找记忆 · 2 次  Ctrl+O 查看`），
  `Ctrl+O` 展开本轮明细；流式回复以同一版式呈现在输入盒上方，完成后并入历史。
- 输入固定在底部圆角盒内：多行草稿、粘贴整体进草稿、光标行始终可见。
  状态行在盒下方：`● 可以发送` / `○ 正在提交` / `◌ 处理中` / `! 异常 · 草稿已保留`。
- 输入 `/` 在输入盒上方展开命令菜单（history / status / help）：
  ↑/↓ 选择，Tab 补全，Enter 执行选中项，Esc 仅关闭菜单并保留草稿。
- `/history [关键词]` 打开临时历史视图：方向键或 PgUp/PgDn 滚动，Enter 翻向更早一页，
  关键词只筛当前页；带限时来源的历史按宿主当前投影显示，到期资料标注"已到期"。
- 窗口收窄时依次让位：装饰 → 键位提示 → 流式预览 → 压缩草稿；
  `NO_COLOR` 关闭配色（靠符号与标签辨认），`ALICE_TUI_ASCII=1` 退回 ASCII 边框。

## 本机接入

macOS 使用 `getpeereid()`，Linux 使用 `SO_PEERCRED`。宿主在每条连接进入 HTTP 处理前核对对端的有效 UID。同一操作系统账户内的程序可访问档案的终端接口。

Socket 路径格式为 `~/.alice/tui-<profile-id>.sock`，目录权限为 `0700`，socket 权限为 `0600`。档案 ID 是档案规范绝对路径按文件系统编码后，取 SHA-256 的前 24 个十六进制字符。每个档案只提供自己的端点。遇到权限异常或档案服务未运行时，终端显示连接错误。隔离 Lab 宿主使用自己的私有通道。

`/api/tui/v1` 在 Unix socket 上提供四种操作。现行网页、QQ 和 Lab 走各自的入口。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /status` | 查看会话代次、档案是否就绪、前台忙闲和有效清醒／睡眠状态。 |
| `GET /history` | 读取历史和邀请，支持 `after_id` 增量与 `before_id` 向前分页，两种游标互斥。 |
| `POST /chat` | 提交 `text`、`request_id`、`session_epoch` 并流式接收进度。 |
| `POST /chat/status` | 按原始的三个字段核对同一请求。确认未接单时沿用原 ID 重试。 |
