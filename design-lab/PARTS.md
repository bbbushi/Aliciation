# PARTS.md — Alice 聊天消息流 demo · 任务拆分总纲

> 本目录是**内容与信息架构规格**：只回答"出现什么信息、有哪些状态、发什么信号、用什么文案"。
> 颜色/字号/间距/动效一律不出现——"顺序、完整性、可见性判定、状态归属"属本层，"多快、多平滑、长什么样"属下游角色。

## 0. 全局约束（所有部分共同遵守）

- 零依赖单文件 HTML，离线运行；任何操作不得发起网络请求。
- 界面语言中文；所有界面文案以各部分文案表为唯一来源，禁止 lorem。
- 本页为演示：数据全部虚构，页面常驻假数据声明（归 08）。
- 会话模型沿用真实产品：单一永久会话、双向消息（用户/Alice）、Alice 回复**逐句揭示**。
- 用户称呼是字段（`userName`，缺省"阿澈"），不是硬编码文案。

## 1. 部分清单（8 个）

| # | 部分 | 一句话职责 |
|---|------|-----------|
| 01 | 会话头栏 | 标明在与谁、哪个会话说话，链路是否活着 |
| 02 | 消息列表容器 | 唯一滚动面：顺序、分组、日期行、滚动语义、空/载状态的宿主判定 |
| 03 | 单条消息 | 一轮发言的静态结构：方向、句单元、元信息、占位与沉默 |
| 04 | 逐句揭示流 | Alice 回复的内容时序：按序、完整、可跳过、可对齐 |
| 05 | composer 输入区 | 起草与发出用户消息，草稿的终身保管者 |
| 06 | 空状态 | 零消息时的第一句话引导，把用户送进输入框 |
| 07 | 回到最新 pill | 离底时的回底入口与未读句计数 |
| 08 | 演示控制器 | 唯一数据源：档位、剧本、重置与假数据声明 |

## 2. 共享契约

### 2.1 Turn（一轮发言，用户或 Alice 各算一轮）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 会话内唯一；重放、对齐、重试都以它为键 |
| role | 'user' \| 'assistant' | 方向与归属的唯一依据 |
| text | string | 完整原文（揭示完成后页面所见必须等于它） |
| shownText | string | 当前应可见部分；非揭示态恒等于 text |
| channel | 'web' \| 'qq' | 缺省 web |
| status | 'ok' \| 'sending' \| 'failed' \| 'silent' | 缺省 ok；silent=assistant 空白回复 |
| time | 合法时间 \| null | null 时一切时间呈现整体隐藏，不出占位错误 |

### 2.2 页面状态（总线，单一真源）

| 字段 | 取值 | 显示归属（谁消费） |
|------|------|--------------------|
| sessionTitle | string（缺省 "Alice"） | 01 |
| userName | string（缺省 "阿澈"） | 06 |
| linkState | 'up' \| 'closing' | 01 显示；05 消费锁定 |
| busy | boolean | 05 显示提示；02/07 间接受影响 |
| listState | 'loading' \| 'ready' \| 'empty' | 02 宿主；06 显示条件 |
| atLatest | boolean | 02 判定；07 显示条件 |
| unreadSentences | number | 02 累积；07 显示 |
| demo.dataset | 'normal'\|'worst'\|'single'\|'empty'\|'flood' | 08 独占 |
| demo.playing | boolean（剧本运行中） | 08 独占 |

### 2.3 信号（谁发 → 谁收）

| 信号 | 发出 → 接收 | 语义 |
|------|-------------|------|
| demo:dataset(name) / demo:replay() / demo:reset() | 08 → 总线 | 切档 / 重播 / 清空（reset 不清草稿） |
| turn:append(Turn) / turn:update(id, patch) | 08 → 02 | 消息入列 / 修正（含揭示中对齐） |
| reveal:progress(id, shownText) / reveal:done(id) | 04 → 02（03 承载内容） | 逐句可见 / 揭示完成 |
| submit:text(string) | 05 → 总线（08 执行剧本） | 发送已 trim 的非空草稿 |
| send:failed(text) | 08 → 05 | 失败回执，05 回填草稿 |
| retry:send(id) / retry:load() | 03 / 02 → 总线 | 重发失败消息 / 重试载入 |
| follow:change(boolean) | 02 → 总线（07 显示） | 用户离开/回到最新区；回底时 unread 清零 |
| jump:latest() | 07 → 02 | 用户主动回底请求；**该次"用户主动回底"同时是 04 的跳过触发** |
| focus:composer() | 06 → 05 | 空状态引导聚焦输入区 |
| link:change / busy:change | 08 → 总线 | 链路与处理状态变更 |

### 2.4 边界判例（易混归属速查）

- 连接类状态（服务关闭）归 01；处理类提示（busy/发送失败）归 05——一个状态两个场景，各自文案，都从总线读。
- 时间戳归 03；日期行归 02（由相邻 Turn 的 time 推导）。
- 滚动位置与"最新区"判定归 02；回底入口与计数显示归 07。
- "这是假数据"的一切声明归 08，其他部分不得复述。
- 揭示的顺序/完整性/可跳过/可对齐归 04；每句间隔毫秒与过渡方式归动效角色，本层不规定数值。
- 草稿属于用户不属于会话数据：重置会话、切档都不清草稿。
- 句单元不带可见序号（"台账变体"的编号是历史呈现选择，不进通用规格）。

## 3. 页面组装顺序（自外而内，先承重后浮层）

1. 08 演示控制器——逻辑上最先立（数据与剧本），界面最后接入
2. 01 会话头栏
3. 02 消息列表容器（内挂 03 单条消息）
4. 04 逐句揭示流接到 03
5. 05 composer 输入区
6. 06 空状态（02 的空判定就绪后挂载）
7. 07 回到最新 pill（02 的滚动语义就绪后挂载）

## 4. 并行设计分组

- 第 0 步：冻结本文件契约（Turn / 状态 / 信号 / 边界判例）。
- 第一波（契约冻结后即可全并行）：01 / 02 / 03 / 05 / 06 / 07——彼此只通过契约交流。
- 第二波：04——需要 03 的句单元结构与占位定稿。
- 收口：08——把各部分状态矩阵里的最坏数据（超长、纯 emoji、单字符、洪流 50 条、空、缺字段）汇总成数据集与剧本。

## 5. 契约变更规则

任何部分规格需要新增字段/信号，先改本文件 2.1–2.3，再改受影响部分；禁止在部分规格里私设跨部分字段。
