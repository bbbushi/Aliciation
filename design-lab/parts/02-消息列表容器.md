# 02 · 消息列表容器

> 上游契约见 ../PARTS.md（消费：Turn 序列、listState、reveal:progress；产出：atLatest、unreadSentences、follow:change）。本文件只含内容与信息规格。

## 1. 用途与边界

**用途**：页面主体与**唯一滚动面**。负责消息的顺序、同侧分组语义、跨日日期行、滚动位置语义（在底/离底、未读句计数），并作为加载态与空态的宿主（提供判定与挂载点，不定义其内容）。

**不含**：单条消息内部结构（03）、揭示时序（04）、空状态内容（06）、pill 本体（07，仅产状态）、输入（05）。

## 2. 内容清单（字段级）

| 元素 | 来源 | 说明 |
|------|------|------|
| 消息序列 | Turn 列表 | 按 time 升序；time=null 的排队尾并保持到达序；按 id 去重（同 id 重复注入视为更新，不新增） |
| 日期行 | 相邻 Turn 的 time 推导 | 仅当相邻两条跨自然日时插入一条；任一侧 time=null 则不插；文案见 §5 |
| 同侧分组关系 | 相邻 role 推导 | 相邻同 role 属同组；组边界=日期行或对侧消息。是否视觉合并归视觉层，但**组关系数据必须可编程取得**（供测试与读屏） |
| 加载态内容 | listState=loading | 载入文案；出现于首次载入与每次切档/重置后的注入期 |
| 载入失败内容 | 注入失败剧本 | 失败文案 + 重试入口（发出 retry:load） |
| 滚动语义 | 容器判定 | atLatest（用户是否在最新区）；unreadSentences（离底期间新可见的句单元数） |

## 3. 状态矩阵

| 场景 | 行为 |
|------|------|
| 常规 | 序列 + 日期行；atLatest 时新内容到达必须跟随（新句进入可视范围，这是内容义务不是动效） |
| 空 | listState=empty → 挂载 06；atLatest 恒为 true；unread 恒为 0 |
| 加载 | listState=loading → 载入文案在场；**loading 期间不算空**（与 06 互斥） |
| 错误 | 载入失败 → 失败文案 + 重试；重试期间回 loading；Turn 含非法 role → 该条丢弃并保持列表其余部分完好（演示数据 bug 不拖垮整页） |
| 最坏 · 洪流 50 条 | 全量入序，不丢条不重条；在底则逐批跟随；离底则 unread 按新句累加 |
| 最坏 · 超长单条 | 2000 字消息可滚动完整阅读，不截断信息，不影响其余消息的序 |
| 最坏 · 时间同值/乱序 | 相同 time 保持到达序（稳定排序，不互换）；乱序 time 按值排序 |
| 最坏 · 切档（flood→empty→worst） | 清空彻底：无残留消息、无幽灵日期行；atLatest 复位 true、unread 清零、空态随即出现 |

## 4. 交互清单

| 用户行为 | 结果 / 对外信号 |
|----------|----------------|
| 上滚离开最新区 | 广播 follow:change(false)——判定须有滞回（离底与回底的判定点不同），不得在边缘反复翻转 |
| 滚回底部 | 广播 follow:change(true)，unreadSentences 清零 |
| 离底期间新句到达 | 不打断阅读（不强制改滚动位置），仅累加 unread |
| 点击载入失败区的"重试" | 发出 retry:load()（08 收） |
| 接收 | turn:append / turn:update（重排序或更新对应 Turn）；reveal:progress（atLatest 时跟随） |

## 6. 验收要点（break-ui 攻击面）

- **空态判定边界（本部分最高危）**：发送第一条消息的瞬间空态必须消失——空态条件必须是"Turn 数=0"，不得把"用户消息已上屏但 Alice 未回"误判为空；同理揭示中的轮次存在时绝不出空态。
- 洪流 + 揭示并发：unread 计数与实际新到句数一致，不重复计、不漏计。
- 50 条中混入 time=null 与相同 time：顺序稳定、无异常输出、无日期行误插。
- 快速连切三档：无残留消息、无重复 id 节点、无日期行残影。
- loading 与 empty 同屏=失败；loading 与旧消息同屏=失败（loading 是整面替换）。
- 2000 字消息在场时其余短消息仍完整在场且可滚到。
- 非法 role 注入：单条丢弃，列表与滚动语义不崩。
