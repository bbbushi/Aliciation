# 01 · 会话头栏

> 上游契约见 ../PARTS.md（消费：sessionTitle、linkState）。本文件只含内容与信息规格。

## 1. 用途与边界

**用途**：页面最上方的身份区，一次回答三个问题——我在和谁说话（Alice）、这是哪个会话（单一永久会话）、链路是否活着（连接状态）。

**不含**：消息计数、搜索、设置/返回按钮、会话切换、"正在处理"提示（归 05）、假数据徽标（归 08）、任何日期信息（归 02）。

## 2. 内容清单（字段级）

| 元素 | 来源 | 说明 |
|------|------|------|
| 对方标识 | 固定值 "Alice" | 文本；是否有头像归视觉层，头像不携带额外信息 |
| 会话性质副题 | 固定文案 | 表达"唯一且持续的会话"这一产品事实 |
| 链路状态行 | linkState | up → 常态文案；closing → 关闭文案 |
| 状态语义标记 | 派生 | 状态行需可编程识别"是否异常"（如 closing 时），供读屏与测试断言 |

## 3. 状态矩阵

| 场景 | 行为 |
|------|------|
| 常规 | 三元素齐全：标识、副题、"本机已连接" |
| 空 | 不随列表空态变化：0 条消息时头栏原样在场（页面永远有头） |
| 加载 | 不参与加载态：listState 不影响头栏任何元素 |
| 错误 | linkState=closing → 状态行换成关闭文案，副题保留；linkState 缺失/非法 → 状态行整体隐藏，不得显示占位符或原始值 |
| 最坏 | sessionTitle 超长（2000 字注入）→ 允许截断为单行，全文经元素的标准悬浮提示属性仍然可得（信息可达，呈现归视觉）；状态文案较长时不得把标识或状态挤出可读范围 |

## 4. 交互清单

- 无主动交互，无对外信号。
- 头栏为纯信息区：整体不进入 Tab 焦点序。
- 超长标题的完整文本通过平台默认的悬浮提示机制获得，不算交互设计。

## 5. 文案表

| 键 | 文案 |
|----|------|
| 对方标识 | Alice |
| 副题 | 单一会话 · 记忆持续 |
| 状态 · 已连接（up） | 本机已连接 |
| 状态 · 关闭中（closing） | 服务正在关闭 |

## 6. 验收要点（break-ui 攻击面）

- 注入 2000 字 sessionTitle：不撑破页面结构、不推走链路状态；截断后完整文本仍可达。
- linkState 传非法值/undefined：状态行消失，页面无 "undefined" 字样。
- 快速翻转 linkState（演示剧本 up↔closing 连发）：以最后一次为准，文案不错位、不叠字。
- 空会话档（demo empty）：头栏必须照常在场——"空页面只剩空态"是失败。
- 副题与状态行同时为最长文案：两行信息互不吞并。
