# 08 · 演示控制器

> 上游契约见 ../PARTS.md（产出：全部数据与剧本信号；消费：submit:text、retry:send、retry:load）。本文件只含内容与信息规格。它是 break-ui 切换器的宿主，收口角色：各部分状态矩阵里的最坏数据在此汇总成可注入的数据集。

## 1. 用途与边界

**用途**：demo 的**唯一数据源与剧本引擎**——档位切换（喂不同数据集）、重播、清空、故障模拟，以及页面级假数据声明。

**不含**：任何聊天界面本体；其他部分状态文案的副本（各部分文案表唯一，控制器只发数据不发文案）；滚动与揭示逻辑（02/04）。

**信息分区**：演示控制区与聊天区是两个并列的区域，读屏与测试可区分"这是演示装置"还是"这是被演示的界面"。

## 2. 档位（5 个数据集，字段级）

| 档位 | 内容 |
|------|------|
| normal 日常对话 | 3–5 轮有真实感的双向对话（句长 1–4 句/轮），含一条 channel=qq 的 Alice 主动消息（验证渠道标记）与一条跨自然日的相邻对（验证日期行） |
| worst 最坏数据 | 一轮一个极端，按序覆盖：2000 字长文（含句界）；无句界长串（连续字母/URL 200 字）；纯 emoji 回复（含 ZWJ 组合）；单字符回复（"嗯"）；空白回复（沉默）；一条 failed 用户轮；一条 time=null；一条超长标题注入给 01 |
| single 单条 | 仅 1 条 assistant 消息（最简反例，验证 0/1/N 边界） |
| empty 空会话 | 0 条（06 的数据源） |
| flood 洪流 | 50 条混合双向消息（超长与单字符混杂、time 有同值有 null），分批到达（模拟流式注入，检验 02 的跟随/计数与 08 自身的可取消性） |

## 3. 剧本（事件序列，字段级）

| 剧本 | 序列 |
|------|------|
| send（默认） | submit:text → 立即回执用户 Turn（sending→ok）→ busy=true → assistant Turn 建立（"…"等待首句）→ reveal:progress 逐句 → reveal:done → busy=false |
| error（开关触发） | submit:text → 用户 Turn 置 failed + 发 send:failed(原文本)（05 回填草稿） |
| closing（开关触发） | linkState=closing → 停留至重置或再次切换恢复 up |
| 主动消息（随档位/重播） | 无 submit 触发，直接注入 channel=qq 的 assistant Turn 走揭示（验证用户未发消息时列表也会增长） |

## 4. 内容清单（字段级）

| 元素 | 说明 |
|------|------|
| 档位组 | 5 个档位名 + 当前档位指示（当前项可编程识别，如 aria-current 语义） |
| 动作 · 重播 | 重跑当前档位剧本（从 loading 开始） |
| 动作 · 清空 | 等价切到 empty 并停止一切剧本；**不清草稿**（草稿属于用户） |
| 开关 · 模拟发送失败 | 置位后下一次 submit 走 error 剧本，成功一次后自动复位 |
| 开关 · 模拟服务关闭 | 置位 → linkState=closing；复位 → up |
| 假数据声明 | 常驻一行，所有档位不变 |

## 5. 状态矩阵

| 场景 | 行为 |
|------|------|
| 常规 | 当前档位可识别；剧本空闲 |
| 空 | empty 档即空态数据源；控制器自身恒有内容（档位与声明永在） |
| 加载 | 切档后：listState=loading → 注入 → ready/empty；注入期间档位指示即时更新 |
| 错误 | 载入失败仅由"重播"或首载模拟触发一次（走 02 的失败+重试路径）；控制器自身操作无失败形态 |
| 最坏 · 快速连点切档 | 以最后选中档为准；**中间档的注入必须可取消**——晚到的旧档数据不得覆盖新档（竞态是本部分最高危攻击面） |
| 最坏 · 切档与揭示并发 | 揭示中的轮随旧档数据一并清除，无残尸（与 04 联测） |
| 最坏 · 注入中途清空 | 干净回到 empty：无半套数据、无进行中的 reveal 信号 |
| 最坏 · 剧本运行中重播 | 旧剧本立即停止，新剧本从头发（无两份剧本并发发信号） |

## 6. 交互清单

| 用户行为 | 结果 / 对外信号 |
|----------|----------------|
| 点档位 | demo:dataset(name)：停旧剧本 → listState=loading → 注入 → ready/empty |
| 点重播 | demo:replay()：当前档从头跑（含 loading） |
| 点清空 | demo:reset()：停一切剧本与揭示，列表清空，empty 态 |
| 拨"模拟发送失败" | 置位/复位剧本标志（无即时信号） |
| 拨"模拟服务关闭" | link:change(closing/up) |
| 接收 | submit:text（执行 send/error 剧本）、retry:send（重发走 send 剧本）、retry:load（重新注入当前档） |

## 8. 验收要点（break-ui 攻击面）

- 连点三档竞态：最终列表与最后选中档一致，无旧档消息混入、无乱序 reveal 信号到达。
- flood 注入中途点清空：列表空、pill 无、空态在、无进行中信号。
- 揭示中切档：无"正在回复…"残尸、无半截正文（与 04 联测）。
- 剧本中重播：同一时刻只有一份剧本在发信号（计数不双倍增加）。
- 假数据声明在全部 5 档 + 空态 + 失败态下常驻可查。
- **离线硬约束**：切档/重播/清空/开关的任何操作不得发出任何网络请求（断网环境全功能可用）。
- 档位指示与实际注入内容一致（指示先行更新但内容以注入完成为准，二者最终不得矛盾）。
