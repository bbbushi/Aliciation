# 04 · 逐句揭示流

> 上游契约见 ../PARTS.md（消费：assistant Turn 的 text、turn:update；产出：reveal:progress / reveal:done）。依赖 03 的句单元结构。本文件只含内容规格——句子间隔毫秒与过渡方式归动效角色，本规格只锁四条不变量。

## 1. 用途与边界

**用途**：定义 Alice 回复从"发出请求"到"完整在场"之间的**内容时序**——本 demo 的旗舰概念。全文一次到位（模拟模型已返回），可见部分（shownText）按句逐步增长。

**不含**：句单元结构与占位样式（03）、列表跟随与未读计数（02）、节奏数值与过渡呈现（动效角色）、跳过入口的显示（pill 归 07）。

## 2. 揭示三态与四条不变量

三态：`idle`（非 assistant / 未开始）、`revealing`（shownText ⊂ text 且未完成）、`done`（shownText === text）。

**不变量（任何实现不得违反）：**

1. **按序**：句单元按原文顺序可见，不跳序、不重复；任意时刻页面显示的是 text 的**连续前缀**。
2. **完整**：进入 done 的唯一条件是全部句单元可见。done 路径上禁止"丢弃缓冲、整段重渲、一次性倒出"——即使揭示被打断收尾，也必须以"补全前缀"的方式到达完整，而不是推倒重来（真实产品踩过的坑，最高危复现点）。
3. **可跳过**：用户主动操作（点击揭示中的 assistant 消息，或经 jump:latest 的**用户主动**回底）→ shownText 直接等于 text，状态置 done。跳过=立即完整，不是取消；跳过不可撤销（完整即终点）。**自动跟随**（atLatest 的滚动跟随）不构成跳过触发。
4. **可对齐**：revealing 中收到 turn:update（全文修正/增长）→ 新文本对齐进缓冲：已显示前缀保持，差异部分继续按序揭示；若新全文与已显示前缀**对不上**（重写）→ 立即整段显示新全文并置 done（兜底：宁可一次性，也要页面与数据一致）。

## 3. 内容清单（字段级）

| 元素 | 说明 |
|------|------|
| 揭示中状态行 | revealing 时挂在该消息 meta 区，文案"正在回复…"；done 后移除（挂载点归 03，时序归本部分） |
| 等待首句形态 | assistant 轮已建立、首句未进入揭示：正文为"…"占位 + "正在回复…"状态（两者同时在场） |
| 沉默终点 | 揭示完成时全文空白 → 正文"（沉默）"，状态行移除，done |
| shownText | 每句可见后发 reveal:progress(id, shownText)；全部可见发 reveal:done(id)——跳过与兜底路径同样必须发 |

## 4. 状态矩阵

| 场景 | 行为 |
|------|------|
| 常规 | 3–6 句逐句可见；atLatest 时请求 02 跟随 |
| 空 | 全文空白 → 不进逐句流程：直接沉默占位 + done（不留"…"，不留状态行） |
| 加载 | "等待首句"即本部分的加载形态："…" + "正在回复…"，直到首句进入前缀或沉默终点 |
| 错误（剧本中断） | demo:reset / demo:replay / 切档打断揭示 → 该轮要么按不变量 3 补全后随旧档清除，要么随重置直接移除；**不得停留在半截"正在回复…"** |
| 最坏 · 无句界 2000 字 | 切句结果=1 句 → 揭示退化为"一段即一句"：整段可见即 done，不伪装节奏 |
| 最坏 · 超多句（400+ 单元） | 按切句上限收尾后照常走完，全文完整 |
| 最坏 · 纯 emoji | 句规则同 03，逐句可见不拆坏组合序列 |
| 最坏 · 揭示中洪流 | 其他 50 条并发注入：本轮揭示不中断、不丢进度、前缀不回退 |
| 最坏 · 揭示中对齐冲突 | turn:update 前缀一致 → 不从头再来；前缀不一致 → 不变量 4 兜底 |

## 5. 交互清单

| 用户行为 | 结果 / 对外信号 |
|----------|----------------|
| 点击揭示中的 assistant 消息本体 | 跳过（不变量 3） |
| 点击"回到最新"（07 发来 jump:latest，且属用户主动回底） | 该次回底同时触发揭示中轮次的跳过 |
| 自动跟随回底（02 的跟随滚动） | 不触发跳过——揭示继续 |
| 对外信号 | reveal:progress(id, shownText)（每句一次）；reveal:done(id)（自然完成/跳过/兜底三条路径都必须发） |

## 7. 验收要点（break-ui 攻击面）

- **done 补全攻击**：揭示中途外部置 done（最坏档注入修正）→ 不得整段倒出（不变量 2 的字面复测：显示连续前缀直至完整）。
- **对齐攻击**：revealing 中 turn:update 先给前缀一致的增长、再给前缀不一致的重写 → 前者不重头，后者立即一致；两 cases 终态都 done 且页面内容===text。
- **跳过竞争**：跳过与正在进行的句显示同时发生 → 终态完整全文，无重复句、无丢失句。
- **切档中断**：flood/worst 切入瞬间有轮在 revealing → 无"正在回复…"残尸、无半截正文残留。
- **全空白回复**：无"…"滞留、无状态行滞留，直达沉默。
- **无句界长文**：不得出现"永远在揭示中"的假节奏（一段即一句，直接完整）。
- **并发洪流**：揭示进度与洪流注入交错 → 前缀单调增长，不回退。
